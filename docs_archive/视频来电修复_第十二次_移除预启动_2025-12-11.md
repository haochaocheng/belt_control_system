# 视频来电修复 - 第十二次：移除预启动，让 PJSIP 自主初始化

**日期**: 2025-12-11
**问题**: 前 11 次尝试都失败，包括 183 Session Progress 方案
**关键发现**: 第十一次测试显示 **PJSIP 根本没有尝试打开设备**
**新假设**: 预启动设备（即使后来停止）可能让 PJSIP 处于错误状态

---

## 📊 第十一次测试的关键发现

### PJSIP 没有尝试打开设备

**183 阶段的日志**（09:51:42.039-09:51:42.080）：
```
09:51:42.075  pjsua_media.c  ....Call 0: stream #1 (video) unchanged.
09:51:42.080  pjsua_media.c  ....Video updated, stream #1:  (inactive)
```

**完全没有设备打开的日志**！正常应该看到：
```
vid_port.c  Opening device Integrated Webcam [dshow] for capture  ← 缺失！
vid_port.c  Device Integrated Webcam [dshow] opened  ← 缺失！
```

**对比**：通话建立后 LocalVideoManager 成功打开设备：
```
09:51:43.301  vid_port.c  ..Opening device Integrated Webcam [dshow] for capture
09:51:43.336  vid_port.c  ..Device Integrated Webcam [dshow] opened
```

**结论**：设备**可以**打开，但 PJSIP 在 183 阶段**决定不尝试打开**。

### Media 状态检查

**[8] Call Info AFTER 183 (Early Media)**：
```
Media 1 (video):
  Dir: 0          ← 应该是 3
  Status: 0        ← 应该是 1
  Video cap_dev: -3  ← 应该是 0
```

`cap_dev: -3` = `PJMEDIA_VID_INVALID_DEV`，说明 PJSIP 认为没有有效的视频设备。

### SDP Answer

```
m=video 0 RTP/AVP 125
c=IN IP4 192.168.10.243  ← 远端 IP，不是本机 IP
```

这意味着 PJSIP 在 SDP negotiation 时就决定拒绝视频了。

## 💡 新假设

经过 11 次尝试，我意识到：

**问题可能不是"设备初始化时间不够"，而是"预启动设备干扰了 PJSIP 的正常流程"**

### 时间线回顾

```
t=0ms    INVITE 到达
t=50ms   检测到视频
t=60ms   📹 [尝试 8-11] 预启动设备
         └─ 启动 preview（1920x1080 或指定格式）
t=200ms  设备打开完成
t=2000ms 用户点击接听
t=2001ms 📹 [尝试 9-11] 停止 preview
t=2101ms 183 Session Progress (vid_cnt=1)
         ├─ PJSIP 检查：能否打开视频设备？
         ├─ 结果：❌ 失败（原因未知）
         └─ 决定：直接标记视频为 "unchanged" (inactive)
```

### 可能的干扰

预启动 preview 可能导致：

1. **设备驱动状态问题**：即使停止了 preview，DirectShow 驱动可能保留某些状态
2. **PJSIP 内部状态**：PJSIP 可能记住了设备已被使用，认为不可用
3. **资源锁定**：某些 Windows 资源（句柄、互斥锁）未完全释放
4. **格式冲突**：preview 的格式（1920x1080）与编码器期望（720x480）冲突

## 💡 第十二次修复方案

### 核心思路：完全不预启动设备

**反直觉的决定**：经过 11 次尝试都试图"帮助" PJSIP，现在反其道而行之：

```
旧方案（尝试 8-11）：
1. 检测到视频来电
2. 立即预启动设备（"帮助" PJSIP）
3. 用户接听时停止 preview
4. 让 PJSIP 重新打开设备
→ 结果：失败，PJSIP 认为设备不可用

新方案（尝试 12）：
1. 检测到视频来电
2. **不做任何事**（不预启动）
3. 用户接听时让 PJSIP 从头初始化
4. 使用 183 + 2秒等待给予充分时间
→ 期望：PJSIP 处理干净的状态，成功初始化
```

### 为什么这次可能成功？

1. **干净的状态**：PJSIP 看到的是完全未使用的设备
2. **充分的时间**：2秒足够设备从冷启动初始化
3. **无干扰**：没有 preview 留下的任何痕迹
4. **PJSIP 自主**：让 PJSIP 按照自己的逻辑处理一切

## 🛠️ 实现代码

### 修改 1：禁用预启动

**文件**: `src/sip_phone/SipPhoneManager.cpp` (行 2375-2385)

```cpp
void SipPhoneManager::setIsIncomingVideoCall(bool isVideoCall)
{
    if (d->isIncomingVideoCall != isVideoCall) {
        d->isIncomingVideoCall = isVideoCall;
        emit isIncomingVideoCallChanged(isVideoCall);
        qDebug() << "✅ Incoming call detected: Video =" << isVideoCall;

        // ✅ ATTEMPT 12: DISABLE pre-start completely
        // Hypothesis: Pre-starting device (even if stopped later) leaves PJSIP in a bad state
        // Let PJSIP handle device initialization completely on its own
        qDebug() << "📹 [ATTEMPT 12] Video call detected, but NOT pre-starting device";
        qDebug() << "   Let PJSIP initialize device from scratch during answer";

        // Do NOT pre-start device
        // Do NOT set d->videoPreviewActive = true
        //
        // This is counter-intuitive after 11 attempts trying to "help" PJSIP,
        // but maybe PJSIP works better when we don't interfere at all
    }
}
```

**关键改变**：
- ❌ 不调用 `pjsua_vid_preview_start()`
- ❌ 不设置任何格式参数
- ❌ 不设置 `d->videoPreviewActive = true`
- ✅ 让 PJSIP 处理完全干净的状态

### 修改 2：增加等待时间到 2 秒

**文件**: `src/sip_phone/SipPhoneManager.cpp` (行 1615-1642)

```cpp
// ✅ ATTEMPT 12: No pre-start, let PJSIP do everything
// Use 183 Session Progress with VERY long wait time (2 seconds)
// to give PJSIP maximum time to initialize device from cold start
qDebug() << "📹 [5] ATTEMPT 12: Answering with 183 + 2 second wait (no pre-start)";
qDebug() << "   Let PJSIP initialize device completely on its own";

call_opt.vid_cnt = 1;
call_opt.aud_cnt = 1;
call_opt.flag = 0;

// Send 183 Session Progress to establish early media with video
status = pjsua_call_answer2(call_ids[i], &call_opt, 183, NULL, NULL);

if (status == PJ_SUCCESS) {
    // Wait VERY long for PJSIP to initialize video from complete cold start
    qDebug() << "📹 [7] Waiting 2000ms (2 seconds) for PJSIP cold start initialization...";
    QThread::msleep(2000);

    // ... 检查 early media 状态
}
```

**关键改变**：
- 增加等待时间：500ms → **2000ms（2秒）**
- 给予 PJSIP 充分时间从冷启动初始化设备
- 移除了所有预启动相关的停止逻辑

PJSIP 设计为自主管理设备。我们的"预启动"可能干扰了它的内部逻辑。

用户说"早期测试时可以工作"，说明 PJSIP + miniSIPServer 的组合是兼容的。
