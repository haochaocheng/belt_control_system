# 视频编码器启动修复 - 对方能看到本机视频

## 🎯 问题根本原因

虽然 SDL2 渲染器成功工作，视频接收正常，但**对方客户端看不到本机视频**。

### 关键证据

从日志中发现的问题：

```
15:31:32.320 vstenc000001ef342c9388  .......Encoder stream paused  ← 编码器被暂停！
```

**通话统计数据**：
```
TX pt=100, size=720x480, fps=15.00
   total 0pkt 0B (0B +IP hdr) @avg=0bps/0bps  ← 发送了 0 包，0 字节！
```

**结论**: 视频编码器被暂停，导致**没有发送任何视频数据**给对方。

---

## 🔍 根本原因分析

### 问题链条

1. **配置层修复（不完整）**:
   ```cpp
   // risipaccountconfiguration.cpp:346
   m_data->accountConfig.videoConfig.autoTransmitOutgoing = true;
   ```
   修改了 PJSUA2 的 `AccountConfig`，但没有正确传递到 PJSIP C API 层。

2. **PJSIP 仍然暂停编码器**:
   ```c
   // pjsua_vid.c:1313-1318
   if (!acc->cfg.vid_out_auto_transmit && call_med->strm.v.stream) {
       status = pjmedia_vid_stream_pause(call_med->strm.v.stream,
                                         PJMEDIA_DIR_ENCODING);  ← 暂停编码器
   }
   ```
   运行时检查 `acc->cfg.vid_out_auto_transmit` 仍然为 false。

3. **日志证据**:
   ```
   15:31:32.098 vstenc .......Encoder stream started  ← 最初启动
   15:31:32.320 vstenc .......Encoder stream paused   ← 然后被暂停
   ```
   编码器在 "Setting up TX" 后被暂停。

### 为什么 autoTransmitOutgoing 修改无效？

PJSUA2 的 `AccountConfig.videoConfig.autoTransmitOutgoing` 可能没有正确映射到 PJSIP C API 的 `pjsua_acc_config.vid_out_auto_transmit`。

这是一个**映射层问题**，需要更深入的 PJSUA2 代码修改，或者绕过配置直接控制编码器。

## ✅ 最终解决方案

### 直接启动视频编码器

在通话确认（CallConfirmed）后，使用 **PJSIP C API 直接启动视频编码器**，绕过配置问题。

**文件**: [SipPhoneManager.cpp:1102-1140](E:\2025\3_gongkongji\belt_control_system\src\sip_phone\SipPhoneManager.cpp#L1102-L1140)

**修改位置**: `handleCallStatusChange()` 函数中的 `CallConfirmed` 分支

**添加的代码**:
```cpp
// ✅ CRITICAL FIX: For video calls, manually start video encoder
// PJSIP may have paused the encoder even if autoTransmitOutgoing=true
// This ensures video is actually transmitted to the remote party
if (isVideoCall && d->currentCall) {
    qDebug() << "✅ Manually starting video encoder for call ID:" << d->currentCall->callId();

    pjsua_call_id pjCall_id = d->currentCall->callId();

    // Get call info to access media streams
    pjsua_call_info callInfo;
    pj_status_t status = pjsua_call_get_info(pjCall_id, &callInfo);

    if (status == PJ_SUCCESS) {
        // Find video media stream
        for (unsigned i = 0; i < callInfo.media_cnt; ++i) {
            if (callInfo.media[i].type == PJMEDIA_TYPE_VIDEO) {
                // Resume video stream encoding (direction = PJMEDIA_DIR_ENCODING)
                pjsua_call_set_vid_strm(pjCall_id, PJSUA_CALL_VID_STRM_START_TRANSMIT, NULL);
                qDebug() << "✅ Video encoder started for media stream" << i;
                break;
            }
        }
    } else {
        qWarning() << "⚠️ Failed to get call info for starting video encoder";
    }
}
```

### 工作原理

1. **等待通话确认**: 在 `CallConfirmed` 状态触发
2. **检查视频通话**: `if (isVideoCall && d->currentCall)`
3. **获取通话信息**: `pjsua_call_get_info()` 获取媒体流信息
4. **查找视频流**: 遍历 `media[]` 查找 `PJMEDIA_TYPE_VIDEO`
5. **启动编码器**: 调用 `pjsua_call_set_vid_strm(PJSUA_CALL_VID_STRM_START_TRANSMIT)`

### 关键 API

**`pjsua_call_set_vid_strm()`**:
- 功能: 控制视频流的传输
- 参数:
  - `call_id`: 通话 ID
  - `op`: `PJSUA_CALL_VID_STRM_START_TRANSMIT` (启动发送)
  - `param`: NULL (使用默认参数)
- 效果: **立即启动视频编码器并开始发送视频数据**

## 📌 技术要点

### 为什么需要手动启动？

1. **配置映射层问题**: PJSUA2 的 `AccountConfig` 到 PJSIP C API 的映射可能不完整
2. **时序问题**: 配置可能在通话建立前已经确定，无法动态生效
3. **默认行为**: PJSIP 默认暂停编码器以节省带宽，除非明确启动

### 为什么在 CallConfirmed 启动？

- **CallConfirmed** 是通话完全建立的状态
- 此时所有媒体流已经协商完成
- 视频流和编码器已经创建，只需要启动
- 太早启动可能无效（媒体流未创建）

### 为什么使用 START_TRANSMIT？

- `PJSUA_CALL_VID_STRM_START_TRANSMIT`: 明确启动视频发送
- 相对于 `pjmedia_vid_stream_resume()` 更高级的 API
- 自动处理摄像头启动和视频流连接
