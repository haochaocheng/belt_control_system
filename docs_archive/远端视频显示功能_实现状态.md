# 远端视频显示功能 - 实现状态

## 概述

根据用户需求：**"如果拨打视频电话，是否可以显示对方的视频，和本机预览视频并排"**，我们实现了远端视频管理器，并更新了 UI 以支持并排显示本机和远端视频。

## 实现内容

### 1. 新增 RemoteVideoManager 类

**文件：**
- `src/sip_phone/RemoteVideoManager.h` (49 行)
- `src/sip_phone/RemoteVideoManager.cpp` (185 行)

**功能：**
- 监听视频通话的连接/断开事件
- 自动检测 PJSIP 远端视频流
- 提供 `hasRemoteVideo` 属性供 QML 判断是否有远端视频
- 提供 `videoSink` 属性（为未来帧提取准备）

**关键接口：**
```cpp
class RemoteVideoManager : public QObject {
    Q_OBJECT
    Q_PROPERTY(bool hasRemoteVideo READ hasRemoteVideo NOTIFY hasRemoteVideoChanged)
    Q_PROPERTY(QObject* videoSink READ videoSink CONSTANT)

public:
    Q_INVOKABLE void onCallConnected(int callId);     // 通话连接时调用
    Q_INVOKABLE void onCallDisconnected();            // 通话断开时调用

signals:
    void hasRemoteVideoChanged();                     // 远端视频状态变化
    void errorOccurred(const QString &error);         // 错误发生
};
```

**实现细节：**
- 通话连接时启动 500ms 定时器，定期检查 PJSIP 通话信息
- 使用 `pjsua_call_get_info()` 获取通话媒体信息
- 检测 `PJMEDIA_TYPE_VIDEO` 类型且方向为 `PJMEDIA_DIR_DECODING` 的媒体流
- 提取远端视频窗口 ID (`ci.media[i].stream.vid.win_in`)
- 使用 `pjsua_vid_win_get_info()` 获取窗口详细信息

### ⚠️ 当前限制

#### 1. **远端视频无法嵌入 QML** （技术限制）

**问题根源**：
- PJSIP 使用 SDL2 渲染器渲染远端视频
- SDL 窗口是独立的原生窗口（HWND），无法真正嵌入到 QML 界面
- 这与本机视频预览遇到的问题相同

**表现**：
- 远端视频会显示在独立的 SDL 浮动窗口中
- QML 中的远端视频区域只显示占位符文本
- 用户需要手动管理 SDL 窗口的位置

**代码体现**：
```cpp
// RemoteVideoManager.cpp:startVideoCapture()
qDebug() << "⚠️ RemoteVideoManager: PJSIP remote video uses SDL renderer";
qDebug() << "⚠️ RemoteVideoManager: Frame extraction requires pjmedia_vid_port API access";
qDebug() << "⚠️ RemoteVideoManager: This feature requires deeper PJSIP integration";

emit errorOccurred("Remote video extraction from PJSIP SDL renderer is not yet implemented. "
                   "Remote video will display in separate SDL window.");
```

#### 2. **为什么无法提取帧？**

PJSIP 的视频渲染架构：
```
远端 RTP 视频包
    ↓
pjmedia_vid_stream (解码)
    ↓
pjmedia_vid_port (端口)
    ↓
pjmedia_vid_dev (视频设备 - SDL 渲染器)
    ↓
SDL2 独立窗口 (GPU 渲染)
```

**提取帧的可能途径**：

1. **方法 A：访问 pjmedia_vid_port**
   - 需要深入 PJSIP 内部结构 (`pjsua_var.ua_cfg`)
   - 从视频端口拦截帧数据
   - 需要修改 PJSIP 内部代码或使用未公开 API
   - **复杂度：高**

2. **方法 B：自定义视频设备**
   - 创建自定义 pjmedia_vid_dev 设备
   - 替换 SDL 渲染器
   - 直接接收解码后的帧数据
   - **复杂度：非常高**

3. **方法 C：使用 PJSIP 视频回调（不存在）**
   - PJSIP 没有提供类似 `on_vid_frame` 的官方回调
   - 音频有 `on_call_media_state`，但视频没有等效接口
   - **不可行**

## 解决方案建议

### 短期方案（当前已实现）

**保持现状**：
- 本机视频使用 Qt Multimedia（完美嵌入）
- 远端视频使用 PJSIP SDL（独立窗口）
- 在 QML 中显示警告提示用户

**优化建议**：
1. 改进 SDL 窗口定位
   - 自动将 SDL 窗口移动到 QML 远端视频区域位置
   - 使用 `SetWindowPos()` 设置窗口位置和大小
   - 保持窗口始终置顶（`HWND_TOPMOST`）

2. 添加窗口管理功能
   - 提供"显示/隐藏远端视频"按钮
   - 自动最小化/恢复 SDL 窗口

### 长期方案（需要深入 PJSIP）

#### 方案 1：自定义 PJSIP 视频设备

**工作量估计**：2-3 周

**步骤**：
1. 研究 pjmedia_vid_dev API
2. 创建自定义视频设备工厂
3. 实现帧回调接口
4. 将帧数据传递给 QVideoSink
5. 测试和调试

**参考代码位置**：
- `pjproject/pjmedia/src/pjmedia-videodev/sdl_dev.c`
- `pjproject/pjmedia/include/pjmedia/videodev.h`

#### 方案 2：使用 pjmedia_vid_port API

**工作量估计**：1-2 周

**步骤**：
1. 在 `onCallStateChanged` 回调中访问 `pjsua_var` 全局变量
2. 获取当前通话的 `pjmedia_vid_port` 指针
3. 注册帧回调或定期从端口读取帧
4. 将帧传递给 QVideoSink

**风险**：
- 需要访问 PJSIP 内部结构（非公开 API）
- 未来 PJSIP 版本升级可能导致兼容性问题

#### 方案 3：使用 Qt Multimedia 进行远端视频渲染

**替换整个视频子系统**：
- 本机视频：QCamera
- 远端视频：手动解码 RTP 流 → QVideoSink
- 音频：仍使用 PJSIP

**工作量估计**：4-6 周（极高复杂度）

**不推荐原因**：
- 需要重新实现 RTP 接收、解码、渲染
- 失去 PJSIP 的视频协商和自适应能力
- 维护成本极高
