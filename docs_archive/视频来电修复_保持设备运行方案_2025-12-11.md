# 视频来电修复 - 保持设备运行方案（第二次修复）

**日期**: 2025-12-11
**问题**: 即使初始化编码器后应答，SDP answer 中视频端口仍为 0
**根本原因**: 停止 preview 后设备被释放，PJSIP 应答时无法重新打开

---

## 第一次修复的问题

### 第一次修复方案（失败）

```cpp
// 启动preview初始化编码器
pjsua_vid_preview_start(cap_dev, NULL);
QThread::msleep(100);
// ❌ 停止preview
pjsua_vid_preview_stop(cap_dev);  // 这里释放了设备！

// 应答
call_opt.vid_cnt = 1;
pjsua_call_answer2(call_id, &call_opt, 200, NULL, NULL);
```

### 测试结果（失败）

**SDP Answer**:
```sdp
m=audio 4000 RTP/AVP 0 101  ✅
m=video 0 RTP/AVP 125       ❌ 端口为 0！
c=IN IP4 127.0.0.1          ❌ 127.0.0.1 表示拒绝
```

**媒体状态**:
```
Media 1 : type= 2 (video) dir= 0 status= 0
Video stream 1 is INACTIVE  ❌
```

### 失败原因分析

1. **设备释放时机问题**:
   - `pjsua_vid_preview_stop()` 会关闭视频设备
   - 设备关闭需要时间（约 1 秒，参见日志中的 dshow 停止过程）
   - 100ms 后设备还没完全释放

2. **PJSIP 应答时重新打开失败**:
   - `pjsua_call_answer2()` 时，PJSIP 尝试打开视频设备
   - 设备处于"正在关闭"状态，无法立即重新打开
   - PJSIP 打开失败 → 生成 `m=video 0` 拒绝视频

3. **日志证据**:
   ```
   08:27:26.886 Stopping preview for cap_dev=0
   ...
   08:27:27.176 Stopping dshow video stream  ← 设备还在关闭
   ...
   08:27:27.255 Answering call 0: code=200   ← 此时设备未就绪
   ...
   m=video 0 RTP/AVP 125                     ← 结果：拒绝视频
   ```

## 第二次修复方案（当前）

### 核心思路

**保持 preview 运行，不要停止！**

PJSIP 会：
1. 检测到设备已打开（preview 正在运行）
2. 复用这个已打开的设备用于通话
3. 自动停止 preview，将设备转移给通话使用

### 实现代码

**文件**: `src/sip_phone/SipPhoneManager.cpp` (行 1559-1600)

```cpp
// ✅ Step 1: Start and KEEP video preview running
qDebug() << "📹 Step 1: Starting video preview (will keep it running)...";
pjmedia_vid_dev_index cap_dev = d->videoCallManager->captureDevId();

// Use specific preview parameters to avoid window popup
pjsua_vid_preview_param preview_param;
pjsua_vid_preview_param_default(&preview_param);
preview_param.show = PJ_FALSE;  // Don't show window, just open device

pj_status_t preview_status = pjsua_vid_preview_start(cap_dev, &preview_param);
if (preview_status == PJ_SUCCESS) {
    qDebug() << "✅ Video preview started on device" << cap_dev << "(hidden window)";
    qDebug() << "   Device is now open and ready for call";
    QThread::msleep(200);  // Give device time to stabilize
    qDebug() << "✅ Device stabilized, ready to answer with vid_cnt=1";
    // ❌ DO NOT STOP! Keep device open for call to use
    // The bug was here: pjsua_vid_preview_stop(cap_dev) released the device!
    // PJSIP will stop the preview automatically when call starts
}

// ✅ Step 2: Answer with video if preview succeeded
if (preview_status == PJ_SUCCESS) {
    call_opt.vid_cnt = 1;  // Enable video
    qDebug() << "📹 Step 2: Answering call with vid_cnt=1 (video enabled)...";
} else {
    call_opt.vid_cnt = 0;  // Fallback to audio-only
    qDebug() << "📹 Step 2: Answering call with vid_cnt=0 (audio-only fallback)...";
}

status = pjsua_call_answer2(call_ids[i], &call_opt, 200, NULL, NULL);
```

### 关键改进

1. **不调用 `pjsua_vid_preview_stop()`**
   - 设备保持打开状态
   - PJSIP 可以立即使用

2. **使用 `preview_param.show = PJ_FALSE`**
   - 隐藏 SDL 预览窗口
   - 只打开设备，不显示画面

3. **增加稳定时间到 200ms**
   - 确保设备完全初始化
   - 避免竞态条件

4. **添加错误处理**
   - Preview 失败时回退到 audio-only
   - 不会导致应答失败

## 技术原理

### PJSIP 设备复用机制

1. **Preview 状态检测**:
   - PJSIP 维护每个设备的使用状态
   - Preview 运行时，设备标记为"已打开"

2. **应答时的设备复用**:
   - `pjsua_call_answer2(vid_cnt=1)` 检查设备状态
   - 如果设备已打开（preview），直接复用
   - 如果设备未打开，尝试打开（可能失败）

3. **Preview 自动停止**:
   - 通话开始时，PJSIP 自动停止 preview
   - 设备所有权转移到通话
   - 无需手动调用 `pjsua_vid_preview_stop()`

### 为什么 show=PJ_FALSE 重要？

1. **避免窗口闪现**:
   - Preview 窗口会弹出 SDL 渲染窗口
   - show=FALSE 只打开设备，不显示窗口

2. **资源优化**:
   - 不创建渲染管道
   - 减少内存和 CPU 开销
   - 只初始化捕获和编码器

3. **用户体验**:
   - 接听时不会看到额外窗口
   - 通话界面更干净
