## 关键检查点

### 1. 视频设备可用性
```
📹 [1] Video Devices: Total [N] devices
```

**期望**:
- 至少有 2 个设备
- 设备 0 可能是 colorbar（Dir=2，仅渲染）
- 设备 1 应该是摄像头（Dir=1 或 3，支持捕获）

**如果设备数为 0 或没有捕获设备**:
- 视频设备未正确初始化
- PJSIP 无法打开视频通道
- 会导致 `m=video 0`

### 2. 视频编解码器配置
```
📹 [2] Video Codecs: [N] available
   H264/... Priority: [priority]
```

**期望**:
- H264 编解码器可用
- Priority > 0（已启用）

**如果 H264 不可用或 Priority=0**:
- 视频编解码器未正确配置
- 会导致 `m=video 0`

### 3. 账户视频配置
```
📹 [3] Account ID: [acc_id]
```

**重要信息**:
- 账户 ID 应该是有效的（不是 -1）
- 后续会打印 vid_cap_dev, vid_rend_dev, vid_in_auto_show, vid_out_auto_transmit

**期望**:
- vid_cap_dev: 1（或实际的摄像头设备 ID）
- vid_out_auto_transmit: 1（PJ_TRUE）

**如果配置错误**:
- vid_cap_dev = 0（colorbar）→ 无法捕获
- vid_out_auto_transmit = 0 → 编码器不会自动启动

### 4. 应答前的通话状态
```
📹 [4] Call Info BEFORE Answer:
   State: [INCOMING/...]
   Media count: [N]
   Media status: [status]
```

**期望**:
- State: INCOMING 或 EARLY
- Media count: 可能是 0 或 2（取决于 PJSIP 内部状态）

### 5. 应答操作
```
📹 [5] Answering with vid_cnt=1...
   Settings: vid_cnt=1 aud_cnt=1 flag=0

📹 [6] Answer status: SUCCESS
```

**如果失败**:
- 会显示 "FAILED" 和错误信息
- 这是明确的失败点

### 6. 应答后的媒体状态（关键）
```
📹 [7] Call Info AFTER Answer:
   Media count: 2
   Media 0:
     Type: 0 (audio)
     Dir: 3
     Status: 1 (ACTIVE)
   Media 1:
     Type: 2 (video)  ← 应该是 2
     Dir: 3           ← 应该是 3（sendrecv）或 1（sendonly）
     Status: 1        ← 应该是 1（ACTIVE）
     Video stream index: [X]
     Video cap_dev: [device_id]  ← 应该是实际的捕获设备（不是 -1）
```

**正常情况**（视频正常激活）:
- Media count: 2
- Media 1:
  - Type: 2 (PJMEDIA_TYPE_VIDEO)
  - Dir: 3 (PJMEDIA_DIR_ENCODING_DECODING，即 sendrecv)
  - Status: 1 (ACTIVE)
  - cap_dev: 1 或其他有效设备 ID

**异常情况 A**（视频被拒绝）:
- Media count: 2
- Media 1:
  - Type: 2 (video)
  - **Dir: 0** (PJMEDIA_DIR_NONE，即禁用)  ← 问题！
  - **Status: 0** (INACTIVE)  ← 问题！

**异常情况 B**（视频设备未配置）:
- Media count: 2
- Media 1:
  - Type: 2 (video)
  - Dir: 3
  - Status: 1
  - **cap_dev: -1** 或 **cap_dev: PJSUA_INVALID_ID**  ← 问题！

## 根据日志定位问题

### 场景 1: 视频设备不可用
**症状**:
```
📹 [1] Video Devices: Total 0 devices
或
📹 [1] Video Devices: Total 1 devices
   Device 0: colorbar | Dir: 2
```

**原因**: VideoCallManager 未正确初始化视频子系统

**解决方案**: 检查 `initializeEndpoint()` 中的视频初始化逻辑

---

### 场景 2: 编解码器未配置
**症状**:
```
📹 [2] Video Codecs: 0 available
或
   H264/... Priority: 0
```

**原因**: H264 编解码器被禁用或未加载

**解决方案**: 检查 risipendpoint.cpp 中的编解码器配置

---

### 场景 3: 账户视频设备配置错误
**症状**:
```
   vid_cap_dev: 0 或 -1
   vid_out_auto_transmit: 0
```

**原因**:
- vid_cap_dev = 0 → 指向 colorbar（不能捕获）
- vid_out_auto_transmit = 0 → 编码器不会自动启动

**解决方案**:
- 修改 `configureAccountVideoDevice()` 确保设置正确的捕获设备
- 确保 vid_out_auto_transmit = PJ_TRUE

---

### 场景 4: 应答成功但视频流被禁用
**症状**:
```
📹 [6] Answer status: SUCCESS
📹 [7] Call Info AFTER Answer:
   Media 1:
     Type: 2 (video)
     Dir: 0  ← 禁用！
     Status: 0  ← 不活动！
```

**原因**: PJSIP 在生成 SDP answer 时发现无法创建视频流，将方向设为 0

**可能的具体原因**:
1. 视频捕获设备打开失败
2. 编码器初始化失败
3. RTP 端口分配失败
4. 格式协商失败

**解决方案**: 需要更深入的 PJSIP 内部日志（可能需要修改 PJSIP 源码）

---

### 场景 5: cap_dev 无效
**症状**:
```
📹 [7] Call Info AFTER Answer:
   Media 1:
     Video cap_dev: -1 或 PJSUA_INVALID_ID
```

**原因**: PJSIP 没有为视频流分配捕获设备

**解决方案**: 账户配置问题，vid_cap_dev 未正确设置
