# 视频来电三按钮修复 - 真正的解决方案

## 📋 问题回顾

**用户报告**: "还是不行" - 视频来电仍然只显示2个按钮，而不是3个按钮

## 🔍 问题诊断 - 时序分析

### 日志证据

从用户提供的日志中发现了关键信息：

```
[DEBUG] 📞 [RISIP INCOMING] RisipCall callId: 0
[DEBUG] 📞 [RISIP INCOMING] pjsua_call_get_info status: 0 media_cnt: 0  ❌
[DEBUG] 📞 [RISIP INCOMING] Checking 0 media streams...
[DEBUG] 📞 [RISIP INCOMING] Final result: hasVideo = false  ❌
```

**问题**: 在 Risip 的 `incomingCall` 信号触发时，`media_cnt = 0`！

但是紧接着看到：
```
[DEBUG] ✅ [CALL STATE] Call 0 state: INCOMING  ← 这个时候 SDP 已解析
```

### 根本原因

**PJSIP 呼叫状态时序**:

```
1. INVITE 请求到达
   ↓
2. Risip incomingCall 信号触发  ← 我们在这里检测（太早！）
   ↓                                 media_cnt = 0 ❌
3. PJSIP 解析 SDP
   ↓
4. 呼叫状态变为 INCOMING         ← 正确的检测时机！
   ↓                                 media_cnt > 0 ✅
5. call_state_callback_wrapper 触发
```

**结论**: 我们在**步骤2**检测视频（太早），应该在**步骤5**检测！

## ✅ 正确的解决方案

### 修改的文件: `src/risip/core/risipendpoint.cpp`

**位置**: Lines 144-168（在 `call_state_callback_wrapper` 函数中）

**修改前**（被注释掉的代码）:
```cpp
qDebug() << "✅ [CALL STATE] Call" << call_id << "state:" << ci.state_text.ptr;

// ✅ Video detection is now handled in incoming_call_callback_wrapper
// where media_cnt is already populated
```

**修改后**（恢复视频检测，这才是正确时机）:
```cpp
qDebug() << "✅ [CALL STATE] Call" << call_id << "state:" << ci.state_text.ptr;

// ✅ Detect video in incoming calls (CORRECT TIMING - after SDP has been parsed)
// This is the right place because when state becomes INCOMING, SDP is already parsed
if (ci.state == PJSIP_INV_STATE_INCOMING) {
    bool hasVideo = false;
    qDebug() << "📞 [VIDEO DETECTION] Call state INCOMING, checking media (media_cnt:" << ci.media_cnt << ")";

    for (unsigned i = 0; i < ci.media_cnt; ++i) {
        qDebug() << "📞 [VIDEO DETECTION] Media" << i << ": type=" << ci.media[i].type
                 << "dir=" << ci.media[i].dir
                 << "(AUDIO=" << PJMEDIA_TYPE_AUDIO << ", VIDEO=" << PJMEDIA_TYPE_VIDEO << ")";

        if (ci.media[i].type == PJMEDIA_TYPE_VIDEO &&
            ci.media[i].dir != PJMEDIA_DIR_NONE) {
            hasVideo = true;
            qDebug() << "✅ Detected video media in incoming call at index" << i;
        }
    }

    qDebug() << "📞 [VIDEO DETECTION] Final result: hasVideo =" << hasVideo;

    // Update SipPhoneManager's incoming video flag
    if (SipPhoneManager::instance()) {
        SipPhoneManager::instance()->setIsIncomingVideoCall(hasVideo);
    }
}
```

### 关键点

1. ✅ 在 `call_state_callback_wrapper` 中检测视频
2. ✅ 当 `ci.state == PJSIP_INV_STATE_INCOMING` 时才检测
3. ✅ 此时 `media_cnt` 已填充（不再为 0）
4. ✅ 通过 `SipPhoneManager::instance()->setIsIncomingVideoCall()` 更新 UI

## 📝 关键经验

1. **不要假设回调会被触发**
   - `incoming_call_callback_wrapper` 被 PJSUA2 拦截
   - 需要通过日志验证每个回调是否真的被调用

2. **时序很重要**
   - Risip 信号触发时 SDP 尚未解析（media_cnt = 0）
   - 需要等到呼叫状态变为 INCOMING（SDP 已解析）

3. **使用正确的 PJSIP 状态**
   - `PJSIP_INV_STATE_INCOMING` 是检测来电视频的正确时机
   - 此时 `pjsua_call_info` 的 `media_cnt` 和 `media[]` 已填充完整

4. **详细的日志是关键**
   - 通过对比预期日志和实际日志，我们发现了 `media_cnt = 0` 的问题
   - 日志显示了正确的时序：`[RISIP INCOMING]` → `[CALL STATE] INCOMING`
