# 视频性能优化 - 测试指南

**日期**: 2025-12-10
**优化内容**: 修改默认视频格式从 1920x1080 → **640x360 @ 30fps**
**目标**: 消除 PJSIP bridge 不必要的缩放，提升 FPS 到 30+

---

## 🔍 问题分析总结

### 第一次测试发现的问题

**实际情况**：
- 解码器输出：**640x360 @ 60fps**（真实视频格式）
- 我们的 port：**720x480 @ 90fps**（查询到的是 bridge 调整后的格式）
- PJSIP bridge 自动缩放：640x360 → 720x480 → 推送给我们

**性能损失**：
- 处理帧大小：720x480 = **518400 bytes**
- 实际需要：640x360 = **345600 bytes**
- **浪费 50% CPU 处理多余数据** ❌

**第一次测试日志**：
```
🎬 [FIRST FRAME] Port format: 720 x 480 @ 90 / 1 fps | Frame buffer size: 518400 bytes
Decoding format changed: 640x360 I420<- 60/1(~60)fps
📊 [REMOTE VIDEO PUSH] Received FPS: "14.7" | Avg interval: "67.9" ms
```

---

## ✅ 实施的优化

### 修改内容

**RemoteVideoManager.h**:
```cpp
// 之前
bool createCustomPort(int width = 1920, int height = 1080, int fps_num = 60, int fps_denum = 1);

// 优化后
bool createCustomPort(int width = 640, int height = 360, int fps_num = 30, int fps_denum = 1);
```

### 优化原理

1. **匹配实际格式**：大多数 SIP 视频通话使用 640x360 分辨率
2. **消除不必要缩放**：实际 640x360 → 我们的 port 640x360 → **无需 bridge 缩放** ✅
3. **减少数据处理量**：345600 bytes（vs 之前 518400 bytes）→ **减少 33%**
4. **提升帧率**：消除缩放瓶颈 → **预期 FPS 翻倍**

## 🚨 如果性能没有提升

### 可能的原因

1. **实际视频格式不是 640x360**
   - 检查 PJSIP 日志中的 `Decoding format changed`
   - 如果是其他分辨率，可能需要进一步调整

2. **网络带宽限制**
   - 检查 PJSIP 统计中的丢包率
   - 查看实际接收的比特率

3. **编解码器瓶颈**
   - H264 解码器性能可能是瓶颈
   - 检查 CPU 使用率

### 调试步骤

1. 提供完整的控制台日志
2. 截图视频通话界面（如果可能）
3. 记录系统资源占用（CPU、内存）
