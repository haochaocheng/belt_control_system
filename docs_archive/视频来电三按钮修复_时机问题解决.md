# 视频来电三按钮修复 - 时机问题解决

## 📋 问题描述

**症状**: 当对方打来视频通话时，本机只显示2个按钮（接听、挂断），而不是3个按钮（视频接听、语音接听、挂断）

**预期行为**:
- 视频来电：显示3个按钮（📹 视频接听、📞 语音接听、✗ 挂断）
- 音频来电：显示2个按钮（✓ 接听、✗ 挂断）

**日志证据**（问题诊断）:
```
[DEBUG] 📞 [VIDEO DETECTION] RisipCall callId: 0
[DEBUG] 📞 [VIDEO DETECTION] pjsua_call_get_info status: 0 media_cnt: 0
[DEBUG] 📞 [VIDEO DETECTION] Checking 0 media streams...
[DEBUG] 📞 [VIDEO DETECTION] Final result: hasVideo = false
```

**根本原因**: **视频检测时机太早，SDP尚未解析完成**

1. 旧代码在 Risip 的 `incomingCall` 信号处理器中检测视频（`SipPhoneManager.cpp:508-543`）
2. 这个信号在 PJSIP 完成 SDP 解析**之前**触发
3. 此时调用 `pjsua_call_get_info()` 会返回 `media_cnt = 0`（媒体信息尚未填充）
4. 结果：所有来电都被识别为音频来电，视频标志始终为 `false`

---

## ✅ 解决方案：在正确的时机检测视频

**核心思路**:
- 不再在 Risip 的 `incomingCall` 信号中检测视频
- 改为在 PJSIP 的 `call_state_callback_wrapper` 中检测，当呼叫状态变为 `PJSIP_INV_STATE_INCOMING` 时
- 此时 PJSIP 已完成 SDP 解析，`media_cnt` 和 `media[]` 数组已填充完整

**时序对比**:

```
旧方案（太早，SDP 未解析）:
┌─────────────────────────────────────────┐
│  1. PJSIP 收到 INVITE 请求              │
│  2. Risip incomingCall 信号触发 ⚠️       │  ← 旧代码在这里检测（太早！）
│  3. PJSIP 解析 SDP                      │
│  4. PJSIP 呼叫状态变为 INCOMING         │
│  5. media_cnt 填充完成 ✅               │
└─────────────────────────────────────────┘

新方案（正确时机，SDP 已解析）:
┌─────────────────────────────────────────┐
│  1. PJSIP 收到 INVITE 请求              │
│  2. Risip incomingCall 信号触发         │
│  3. PJSIP 解析 SDP                      │
│  4. PJSIP 呼叫状态变为 INCOMING         │
│  5. media_cnt 填充完成 ✅               │
│  6. call_state_callback_wrapper 触发 ✅ │  ← 新代码在这里检测（正确！）
└─────────────────────────────────────────┘
```

```cpp
// ✅ Detect video in incoming calls (after SDP has been parsed)
if (ci.state == PJSIP_INV_STATE_INCOMING) {
    bool hasVideo = false;
    qDebug() << "📞 [VIDEO DETECTION] Call state INCOMING, checking media (media_cnt:" << ci.media_cnt << ")";

    for (unsigned i = 0; i < ci.media_cnt; ++i) {
        qDebug() << "📞 [VIDEO DETECTION] Media" << i << ": type=" << ci.media[i].type
                 << "dir=" << ci.media[i].dir
                 << "(AUDIO=" << PJMEDIA_TYPE_AUDIO << ", VIDEO=" << PJMEDIA_TYPE_VIDEO << ")";

        if (ci.media[i].type == PJMEDIA_TYPE_VIDEO &&
            ci.media[i].dir != PJMEDIA_DIR_NONE) {
            hasVideo = true;
            qDebug() << "✅ Detected video media in incoming call at index" << i;
        }
    }

    qDebug() << "📞 [VIDEO DETECTION] Final result: hasVideo =" << hasVideo;

    // Update SipPhoneManager's incoming video flag
    if (SipPhoneManager::instance()) {
        SipPhoneManager::instance()->setIsIncomingVideoCall(hasVideo);
    }
}
```

- ✅ 此时 `media_cnt` 已填充（不再为 0）
- ✅ 遍历 `ci.media[]` 数组查找 `PJMEDIA_TYPE_VIDEO`
- ✅ 通过 `SipPhoneManager::instance()` 更新 UI 标志

## 🔍 技术要点

### 1. PJSIP 呼叫状态机

```
NULL → INCOMING → EARLY → CONNECTING → CONFIRMED → DISCONNECTED
            ↑
      SDP 已解析，media_cnt 已填充
      在这里检测视频 ✅
```

### 2. PJSIP 媒体类型枚举

```cpp
typedef enum pjmedia_type {
    PJMEDIA_TYPE_NONE = 0,    // None (无)
    PJMEDIA_TYPE_AUDIO,        // Audio (音频) = 0
    PJMEDIA_TYPE_VIDEO,        // Video (视频) = 1
    PJMEDIA_TYPE_APPLICATION,  // Application (应用数据)
    PJMEDIA_TYPE_UNKNOWN       // Unknown (未知)
} pjmedia_type;
```

### 3. SDP 解析时序

1. PJSIP 收到 INVITE 请求
2. **Risip `incomingCall` 信号触发**（此时 SDP 尚未解析 ⚠️）
3. PJSIP 在后台异步解析 SDP
4. **呼叫状态变为 `INCOMING`**（SDP 解析完成 ✅）
5. `call_state_callback_wrapper` 触发（此时 `media_cnt` 已填充）

### 4. 线程安全

- PJSIP 回调在 PJSIP 的工作线程中运行
- `SipPhoneManager::instance()->setIsIncomingVideoCall()` 使用 Qt 信号机制，自动跨线程通知 UI
- Qt 信号是线程安全的，会自动切换到 UI 线程更新界面

## 📝 总结

**问题**: 视频检测在 SDP 解析完成前执行，导致 `media_cnt = 0`，所有来电都被误判为音频

**解决**: 将视频检测移到 PJSIP 呼叫状态变为 `INCOMING` 时（SDP 已解析），此时 `media_cnt` 已填充

**核心改变**:
- ❌ 移除：Risip `incomingCall` 信号中的过早视频检测
- ✅ 新增：PJSIP `call_state_callback_wrapper` 中的正确时机视频检测
- ✅ 效果：视频来电正确显示 3 个按钮，音频来电显示 2 个按钮

```cpp
static void call_state_callback_wrapper(pjsua_call_id call_id, pjsip_event *e) {
    pjsua_call_info ci;
    pjsua_call_get_info(call_id, &ci);
```
