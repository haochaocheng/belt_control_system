# 视频来电修复 - 格式匹配方案（第三次修复）

**日期**: 2025-12-11
**问题**: Preview 成功启动但视频端口仍为 0
**根本原因**: Preview 格式与 H.264 编码器配置不匹配

---

- 启动 preview → 停止 preview → 应答
- **问题**: 设备被释放，无法重新打开
- **结果**: `m=video 0`

### 第二次修复（失败）
- 启动 preview → **不停止** → 应答
- **问题**: Preview 格式不匹配编码器配置
- **结果**: `m=video 0`（即使设备保持运行）

## 根本原因

### PJSIP 的设备复用逻辑

1. **Preview 启动**:
   - 打开设备，使用默认格式 (1920x1080 @ 5fps)
   - 设备标记为"已打开"

2. **应答时检查**:
   ```cpp
   if (device_is_open) {
       if (device_format matches encoder_format) {
           // 复用设备 ✅
           return success;
       } else {
           // 格式不匹配，无法复用 ❌
           return port=0;  // 拒绝视频
       }
   }
   ```

3. **格式不匹配的后果**:
   - PJSIP 无法复用 preview 设备
   - 无法重新打开设备（已被 preview 占用）
   - 生成 `m=video 0` 拒绝视频

### H.264 编码器配置

**文件**: `src/risip/core/risipendpoint.cpp` (行 641-646)

```cpp
// ✅ Set encoder to 25 fps for smooth video (was 15fps by default)
h264_param.enc_fmt.det.vid.fps.num = 25;
h264_param.enc_fmt.det.vid.fps.denum = 1;

// Keep resolution at 720x480 (good balance of quality and performance)
h264_param.enc_fmt.det.vid.size.w = 720;
h264_param.enc_fmt.det.vid.size.h = 480;
```

编码器期望: **720x480 @ 25fps**

### Preview 默认格式

如果不指定格式，PJSIP 使用设备默认格式：
- **1920x1080 @ 5fps**（摄像头的默认高分辨率模式）
- 或其他设备默认值

**结果**: 格式不匹配 → 无法复用 → `m=video 0`

## 第三次修复方案（当前）

### 核心思路

**启动 preview 时指定与编码器相同的格式（720x480 @ 25fps）**

### 实现代码

**文件**: `src/sip_phone/SipPhoneManager.cpp` (行 1562-1581)

```cpp
qDebug() << "📹 Step 1: Starting video preview with correct format (720x480 @ 25fps)...";
pjmedia_vid_dev_index cap_dev = d->videoCallManager->captureDevId();

// ✅ CRITICAL: Set preview format to match H.264 encoder configuration
pjsua_vid_preview_param preview_param;
pjsua_vid_preview_param_default(&preview_param);
preview_param.show = PJ_FALSE;  // Don't show window

// Set video format to match encoder (720x480 @ 25fps)
preview_param.format.id = PJMEDIA_FORMAT_YUY2;  // YUV 4:2:2
preview_param.format.det.vid.size.w = 720;      // Width
preview_param.format.det.vid.size.h = 480;      // Height
preview_param.format.det.vid.fps.num = 25;      // FPS numerator
preview_param.format.det.vid.fps.denum = 1;     // FPS denominator

qDebug() << "   Using format: 720x480 @ 25fps YUY2";

pj_status_t preview_status = pjsua_vid_preview_start(cap_dev, &preview_param);
if (preview_status == PJ_SUCCESS) {
    qDebug() << "✅ Video preview started with correct format";
    QThread::msleep(200);
    // Don't stop preview - PJSIP will reuse it
}

// Answer with video
call_opt.vid_cnt = 1;
pjsua_call_answer2(call_id, &call_opt, 200, NULL, NULL);
```

### 关键改进

1. **显式指定格式**:
   ```cpp
   preview_param.format.det.vid.size.w = 720;
   preview_param.format.det.vid.size.h = 480;
   preview_param.format.det.vid.fps.num = 25;
   ```

2. **格式与编码器完全匹配**:
   - Preview: 720x480 @ 25fps
   - Encoder: 720x480 @ 25fps
   - ✅ 完全一致！

3. **PJSIP 可以复用设备**:
   - 检测到 preview 运行
   - 检查格式 → 匹配！
   - 复用设备用于通话
   - 生成有效 SDP（端口 > 0）

## 技术细节

### 为什么格式必须匹配？

PJSIP 的视频流创建逻辑（简化）：

```cpp
// 伪代码
pj_status_t answer_call_with_video(call_id, vid_cnt=1) {
    // 1. 查找可用的视频设备
    vid_dev = find_video_device();

    // 2. 检查设备是否已打开（preview）
    if (vid_dev.is_open) {
        // 3. 检查格式是否匹配编码器要求
        if (vid_dev.format == encoder.format) {
            // 复用设备
            reuse_device_for_call(vid_dev);
            return SUCCESS;  // m=video <port>
        } else {
            // 格式不匹配，无法复用
            // 也无法重新打开（已被占用）
            return FAIL;  // m=video 0
        }
    } else {
        // 设备未打开，尝试打开
        open_device_with_encoder_format();
    }
}
```

**关键点**：
- 如果设备已打开（preview），PJSIP **必须**检查格式
- 格式不匹配时，PJSIP **不会**尝试重新配置设备
- 也**不会**关闭 preview 重新打开（设计限制）
- 唯一选择：拒绝视频 (`m=video 0`)

### 为什么之前没想到这个问题？

1. **PJSIP 文档不完善**:
   - 文档说"可以复用设备"
   - 但没说"格式必须匹配"

2. **设备默认格式不确定**:
   - 不同摄像头默认格式不同
   - 有的是 640x480，有的是 1920x1080
   - 我们的摄像头默认是高分辨率

3. **编码器配置在另一个文件**:
   - 编码器配置在 `risipendpoint.cpp`
   - Preview 启动在 `SipPhoneManager.cpp`
   - 容易忽略格式一致性
