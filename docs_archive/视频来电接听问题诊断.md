# 视频来电接听问题诊断

## 问题描述

对方打视频电话到本机，本机点击"视频接听"后：
- ❌ 本机看不到对方视频
- ❌ 对方看不到本机视频
- ✅ 但双方音频正常
- ✅ 三按钮UI显示正确

## 关键日志分析

### 成功部分
```
✅ Answering incoming VIDEO call with PJSIP C API (vid_cnt=1)...
✅ Video call answered successfully (with video, vid_cnt=1)
```

### 失败部分
发送给对方的SDP：
```sdp
m=video 0 RTP/AVP 125    ← 端口是0，拒绝视频！
c=IN IP4 127.0.0.1
```

PJSIP媒体状态：
```
Video updated, stream #1:  (inactive)
[MEDIA STATE] Media 1 : type= 2 dir= 0 status= 0
```

`dir=0` 表示 `PJMEDIA_DIR_NONE`，视频被拒绝。

## 根本原因

即使我们调用了 `pjsua_call_answer2(vid_cnt=1)`，PJSIP 在生成应答 SDP 时还是拒绝了视频流。

可能的原因：
1. **账户视频配置未正确应用** - 在接听时，`vid_cap_dev` 或 `vid_out_auto_transmit` 可能不正确
2. **视频编解码器未正确协商** - PJSIP 可能找不到双方都支持的视频编解码器
3. **SDP 协商时机问题** - `pjsua_call_answer2()` 调用时可能已经太晚

## 对比：本机主叫视频通话（正常工作）

本机拨打对方时，我们使用：
```cpp
pjsua_call_make_call(acc_id, &uri, &call_opt, NULL, NULL, &call_id);
call_opt.vid_cnt = 1;
```

关键区别：
- 主叫时，在 `makeCall()` 之前调用 `configureAccountVideoDevice()` 刷新账户配置
- 被叫时，账户配置可能在登录时设置后就没有更新过

## 尝试的修复

### 修复1：在接听前刷新账户视频配置
```cpp
if (d->currentAccount && d->currentAccount->configuration()) {
    QString accountUri = d->currentAccount->configuration()->uri();
    configureAccountVideoDevice(accountUri);  // 刷新配置
}
```

### 修复2：添加 INCLUDE_DISABLED_MEDIA 标志
```cpp
call_opt.flag = PJSUA_CALL_INCLUDE_DISABLED_MEDIA;
```

## 下一步调试

如果上述修复无效，需要检查：

1. **视频编解码器列表**
   - 检查 `pjsua_codec_get_prio()` 查看 H264/VP8 的优先级
   - 确认双方都支持相同的视频编解码器

2. **PJSIP 详细日志**
   - 启用更详细的 PJSIP 日志级别
   - 查看 SDP 协商过程中的详细错误

3. **账户配置检查**
   - 在接听前后打印 `acc_cfg.vid_cap_dev` 的值
   - 确认 `vid_out_auto_transmit` 是 `PJ_TRUE`

4. **替代方案：使用 re-INVITE**
   - 先用 `vid_cnt=0` 接听（仅音频）
   - 接听后立即发送 re-INVITE 添加视频
   - 但这会导致用户体验延迟
