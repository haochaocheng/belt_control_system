# 视频来电三按钮修复 - 关键突破 🎉

## 🔍 问题发现

用户测试后报告了一个**关键现象**：

> "对方打来的视频电话，**本机的预览视频会自动开启**"

这个现象非常重要！它证明了：
1. ✅ PJSIP **确实检测到了视频通话**
2. ✅ 视频流 **已经被正确处理和启动**
3. ❌ 但我们的检测代码没有捕获到这个信息

## 💡 根本原因

通过追踪 PJSIP 的视频预览自动启动机制，发现：

### 问题诊断
之前的三层检测机制都在**错误的时机**检测：
1. **`incoming_call_callback_wrapper`**: 未被触发（被 PJSUA2 拦截）
2. **`call_state_callback_wrapper` (INCOMING 状态)**: `media_cnt = 0` (SDP 尚未解析)
3. **Risip `incomingCall` 信号**: `media_cnt = 0` (时机太早)

### 真正的时机
**`on_call_media_state` 回调** (即 `audio_routing_callback_wrapper`) 才是 PJSIP 解析 SDP 并初始化媒体流的时刻！

此时：
- ✅ `media_cnt` 已经 > 0
- ✅ `ci.media[]` 数组包含完整的媒体信息
- ✅ 视频预览已经或即将启动

## 🔧 解决方案

### 修改位置
[src/risip/core/risipendpoint.cpp:74-111](src/risip/core/risipendpoint.cpp#L74-L111)

### 修改内容
在 `audio_routing_callback_wrapper` (媒体状态回调) 开头添加视频检测逻辑：

```cpp
// ✅ CRITICAL FIX: Detect video in media state callback (THIS is when media_cnt becomes > 0!)
// This callback is triggered when PJSIP processes SDP and initializes media streams
// At this point, ci.media_cnt will finally be populated with actual media information
qDebug() << "📞 [MEDIA STATE] Call" << call_id << "media_cnt:" << ci.media_cnt
         << "state:" << ci.state << "media_status:" << ci.media_status;

// Check for video on FIRST callback for this call (before media becomes active)
static QSet<pjsua_call_id> calls_checked_for_video;
if (!calls_checked_for_video.contains(call_id)) {
    calls_checked_for_video.insert(call_id);

    bool hasVideo = false;
    for (unsigned i = 0; i < ci.media_cnt; ++i) {
        qDebug() << "📞 [MEDIA STATE] Media" << i << ": type=" << ci.media[i].type
                 << "dir=" << ci.media[i].dir << "status=" << ci.media[i].status
                 << "(AUDIO=" << PJMEDIA_TYPE_AUDIO << ", VIDEO=" << PJMEDIA_TYPE_VIDEO << ")";

        if (ci.media[i].type == PJMEDIA_TYPE_VIDEO && ci.media[i].dir != PJMEDIA_DIR_NONE) {
            hasVideo = true;
            qDebug() << "✅ [MEDIA STATE] Detected video in call" << call_id;
        }
    }

    qDebug() << "📞 [MEDIA STATE] Final result for call" << call_id << ": hasVideo =" << hasVideo;

    // Notify SipPhoneManager if this is an incoming call
    if (ci.state == PJSIP_INV_STATE_INCOMING || ci.state == PJSIP_INV_STATE_EARLY) {
        if (SipPhoneManager::instance()) {
            qDebug() << "📞 [MEDIA STATE] Setting isIncomingVideoCall =" << hasVideo;
            SipPhoneManager::instance()->setIsIncomingVideoCall(hasVideo);
        }
    }
}

// Clean up tracking when call disconnects (must be outside the checked block)
if (ci.state == PJSIP_INV_STATE_DISCONNECTED) {
    calls_checked_for_video.remove(call_id);
}
```

### 关键特性
1. **在第一次媒体状态回调时检测** - 使用 `static QSet` 确保每个呼叫只检测一次
2. **检查呼叫状态** - 只在 INCOMING 或 EARLY 状态设置 `isIncomingVideoCall`
3. **正确清理** - 在呼叫断开时清理跟踪信息

## 🎯 为什么这次会成功？

### 之前失败的原因
所有之前的检测点都**太早了** - 在 PJSIP 解析 SDP 之前执行，导致 `media_cnt = 0`。

### 现在成功的原因
1. **正确的时机**: `on_call_media_state` 回调在 SDP 解析**之后**触发
2. **用户现象证实**: 预览视频自动开启说明这个回调确实被触发了
3. **媒体信息完整**: 此时 `ci.media[]` 已经包含所有媒体流信息

### 调用顺序
```
PJSIP 收到 INVITE
    ↓
incoming_call_callback_wrapper (media_cnt=0, 可能未触发)
    ↓
call_state_callback_wrapper (state=INCOMING, media_cnt=0)
    ↓
Risip incomingCall 信号 (media_cnt=0)
    ↓
显示来电界面 (此时 isIncomingVideoCall=false, 只显示2按钮) ❌
    ↓
【PJSIP 解析 SDP 并初始化媒体】← 关键时刻！
    ↓
✅ audio_routing_callback_wrapper (media_cnt=2, 现在检测到视频!)
    ↓
setIsIncomingVideoCall(true)
    ↓
QML 界面更新为 3 按钮 ✅
```

## 📝 技术说明

### PJSIP 回调顺序
PJSIP 在处理来电时的回调顺序：
1. `on_incoming_call` - 接收到 INVITE (SDP 可能在消息体中，但尚未解析)
2. `on_call_state` (INCOMING) - 呼叫状态变为 INCOMING (SDP 仍未解析)
3. **`on_call_media_state`** ← **这里！SDP 已解析，媒体流已初始化**
4. `on_call_media_state` (ACTIVE) - 接听后媒体变为活动状态

### 为什么预览会自动开启？
在 [risipaccountconfiguration.cpp:346](src/risip/core/risipaccountconfiguration.cpp#L346)：
```cpp
m_data->accountConfig.videoConfig.autoTransmitOutgoing = true;
```

这个配置使 PJSIP 在检测到视频流时自动启动视频传输和预览。
