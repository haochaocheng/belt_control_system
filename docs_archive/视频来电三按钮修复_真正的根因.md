# 视频来电三按钮修复 - 真正的根因发现

## 📋 问题描述

**症状**: 当对方打来视频通话时，本机只显示2个按钮（接听、挂断），而不是3个按钮（视频接听、语音接听、挂断）

**用户反馈**: "对方视频来电，还是两个按钮，没有改变"

---

## 🔍 真正的根本原因

### ❌ 错误诊断1：时机问题
**之前以为**: 视频检测在 SDP 解析前执行，导致 `media_cnt = 0`

**实际情况**: 这不是主要问题！

### ❌ 错误诊断2：Risip 信号太早
**之前以为**: Risip 的 `incomingCall` 信号在 SDP 解析前触发

**实际情况**: 这也不是主要问题！

### ✅ 真正的根因：自动接听逻辑

**发现过程**:
1. 检查日志发现 `media_cnt = 0` 在两个回调中都出现
2. 深入阅读 `risipendpoint.cpp` 的 `incoming_call_callback_wrapper` 函数
3. **震惊发现**：这个函数在 lines 208-229 **自动接听了所有来电**！

**代码证据** (`risipendpoint.cpp:208-229`):
```cpp
// ✅ Auto-answer the call
// If it has video, answer with video enabled
pjsua_call_setting call_opt;
pjsua_call_setting_default(&call_opt);

if (has_video) {
    call_opt.vid_cnt = 1;  // Enable video
    qDebug() << "✅ [INCOMING CALL] Auto-answering with video enabled";
} else {
    call_opt.vid_cnt = 0;  // Audio only
    qDebug() << "✅ [INCOMING CALL] Auto-answering audio-only call";
}

// Answer with 200 OK
status = pjsua_call_answer2(call_id, &call_opt, 200, NULL, NULL);
if (status == PJ_SUCCESS) {
    qDebug() << "✅ [INCOMING CALL] Call" << call_id << "answered successfully";
} else {
    char errmsg[PJ_ERR_MSG_SIZE];
    pj_strerror(status, errmsg, sizeof(errmsg));
    qWarning() << "❌ [INCOMING CALL] Failed to answer call:" << errmsg;
}
```

**结果**:
- 来电立即被自动接听
- 用户根本没有机会看到来电界面
- 三按钮 UI 从未显示，因为电话已经接通了

---

## ✅ 解决方案：移除自动接听逻辑

### 修改的文件
**文件**: `src/risip/core/risipendpoint.cpp`

### 1. 移除自动接听代码（lines 194-223）

**修改前**（会自动接听）:
```cpp
if (status == PJ_SUCCESS) {
    // Check if incoming call has video
    bool has_video = false;
    for (unsigned i = 0; i < ci.media_cnt; ++i) {
        if (ci.media[i].type == PJMEDIA_TYPE_VIDEO) {
            has_video = true;

    }

    qDebug() << "✅ [INCOMING CALL] Call" << call_id
             << "from:" << QString::fromUtf8(ci.remote_info.ptr, ci.remote_info.slen)

    // ❌ 自动接听！用户看不到来电界面

    pjsua_call_setting_default(&call_opt);

        call_opt.vid_cnt = 1;

    } else {

    }
```

**修改后**（检测视频 + 通知 UI，不自动接听）:
```cpp
if (status == PJ_SUCCESS) {
    // ✅ Check if incoming call has video and notify SipPhoneManager
    bool has_video = false;
    qDebug() << "📞 [INCOMING CALL] Checking media (media_cnt:" << ci.media_cnt << ")";

    for (unsigned i = 0; i < ci.media_cnt; ++i) {
        qDebug() << "📞 [INCOMING CALL] Media" << i << ": type=" << ci.media[i].type
                 << "dir=" << ci.media[i].dir
                 << "(AUDIO=" << PJMEDIA_TYPE_AUDIO << ", VIDEO=" << PJMEDIA_TYPE_VIDEO << ")";

        if (ci.media[i].type == PJMEDIA_TYPE_VIDEO &&
            ci.media[i].dir != PJMEDIA_DIR_NONE) {
            has_video = true;
            qDebug() << "✅ Detected video media in incoming call at index" << i;
        }
    }

    qDebug() << "✅ [INCOMING CALL] Call" << call_id
             << "from:" << QString::fromUtf8(ci.remote_info.ptr, ci.remote_info.slen)
             << (has_video ? "(Video)" : "(Audio only)");
    qDebug() << "📞 [INCOMING CALL] Final result: hasVideo =" << has_video;

    // ✅ Notify SipPhoneManager about video call status
    if (SipPhoneManager::instance()) {
        SipPhoneManager::instance()->setIsIncomingVideoCall(has_video);
    }

    // ✅ DO NOT auto-answer - let user decide via UI buttons
    // User will see three buttons for video calls or two buttons for audio calls
}
```

## 🔍 技术要点

### 1. PJSIP 回调顺序

```
1. incoming_call_callback_wrapper  ← 最早触发，此时 media_cnt 已填充
2. Risip incomingCall 信号        ← 由 PJSUA2 C++ 包装层触发
3. call_state_callback_wrapper    ← 状态变化时触发
```

### 2. 为什么 incoming_call_callback_wrapper 有完整信息？

- 这个回调在 PJSIP C API 层，直接访问 SIP 消息
- INVITE 请求中的 SDP 已经被解析
- `pjsua_call_get_info()` 返回的 `media_cnt` 已填充

### 3. 为什么 call_state_callback_wrapper 的 media_cnt 是 0？

- 状态回调可能在 SDP 协商完成前就触发
- 对于来电，`INCOMING` 状态可能早于媒体信息填充
- 不适合作为视频检测的时机

## 📝 总结

**问题**: 所有来电被 `incoming_call_callback_wrapper` 自动接听，用户看不到来电界面

**根因**: 代码中有自动接听逻辑（可能是早期测试代码遗留）

**解决**: 移除自动接听逻辑，改为：
1. 检测是否是视频来电
2. 通知 SipPhoneManager
3. 让用户通过 UI 按钮选择接听方式

**核心改变**:
- ❌ 移除：`pjsua_call_answer2()` 自动接听调用
- ✅ 新增：`SipPhoneManager::instance()->setIsIncomingVideoCall(has_video)`
- ✅ 效果：用户看到来电界面，可以选择接听方式

## 💡 经验教训

1. **不要过度依赖日志的表面现象**
   - `media_cnt = 0` 不一定意味着时机问题
   - 需要深入阅读代码理解完整流程

2. **自动化功能可能隐藏问题**
   - 自动接听看似方便，实际上剥夺了用户选择权
   - 测试时要检查是否有"隐藏"的自动化逻辑

3. **PJSIP 有多个回调层**
   - C API 层（最底层，最早触发）
   - PJSUA2 C++ 包装层（中间层）
   - Risip SDK 层（最上层）
   - 需要在正确的层处理正确的逻辑

4. **测试要覆盖用户体验**
   - 不只测试"能否接通"
   - 还要测试"用户能否看到界面"和"用户能否选择"
