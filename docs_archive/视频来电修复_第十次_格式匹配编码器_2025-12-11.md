# 视频来电修复 - 第十次：格式匹配编码器

**日期**: 2025-12-11
**问题**: Preview 停止后视频流仍无法创建
**根本原因**: Preview 使用默认格式（1920x1080），与编码器配置（720x480 @ 25fps）不匹配

---

## 📊 第九次测试的关键发现

### Preview 格式不匹配

从测试日志：

```
09:32:18.467  vid_port.c  Opening device ... format=YUY2, size=1920x1080 @10000000:2000000 fps
09:32:18.520  vid_port.c  Device ... opened: format=YUY2, size=1920x1080 @10000000:2000000 fps
```

Preview 打开为 **1920x1080**，但编码器配置（risipendpoint.cpp:641-646）为：

```cpp
h264_param.enc_fmt.det.vid.fps.num = 25;
h264_param.enc_fmt.det.vid.fps.denum = 1;
h264_param.enc_fmt.det.vid.size.w = 720;
h264_param.enc_fmt.det.vid.size.h = 480;
```

**编码器期望: 720x480 @ 25fps**

### 停止后仍然失败

即使停止了 preview 并等待 100ms：

```
[DEBUG] ✅ [PRE-START] Preview stopped successfully
[DEBUG] ✅ [PRE-START] Device is warmed up and ready to reopen for call
...
09:32:21.547  pjsua_media.c  ....Call 0: stream #1 (video) unchanged.
09:32:21.550  pjsua_media.c  ....Video updated, stream #1:  (inactive)
```

**还是失败**：
- SDP: `m=video 0`
- Media 1: `Dir: 0 Status: 0 cap_dev: -3`

### 通话建立后的成功

通话建立后，LocalVideoManager 成功打开了设备：

```
09:32:22.215  vid_port.c  Opening device ... format=YUY2, size=720x480 @60:1 fps
09:32:22.253  vid_port.c  Device ... opened: format=YUY2, size=640x480 @60:1 fps  ← 接近 720x480
```

这证明：
1. ✅ 设备**可以**以接近 720x480 的格式打开
2. ✅ 编码器配置是有效的
3. ❌ 但应答时无法以正确格式打开

## 💡 问题根因

### 为什么格式不匹配导致失败？

**时间线分析**：

```
t=0ms    INVITE 到达
t=50ms   检测到视频
t=60ms   📹 启动 preview（默认格式 = 1920x1080）
         ├─ 设备以 1920x1080 @ 5fps 打开
         └─ 驱动"记住"这个配置
t=2000ms 用户点击接听
t=2001ms 📹 停止 preview
t=2101ms 应答 vid_cnt=1
         ├─ PJSIP 尝试以编码器格式（720x480）打开设备
         ├─ 但设备驱动可能还"记住"上次的格式
         ├─ 或者 100ms 不够设备完全重置状态
         └─ 打开失败 → m=video 0
```

### DirectShow 设备状态

**DirectShow 驱动的行为**：

1. **首次打开**：设备初始化，选择默认格式（通常是最高分辨率）
2. **关闭**：设备释放，但驱动可能缓存配置
3. **重新打开**：
   - 如果很快重新打开（<500ms），可能复用上次的配置
   - 如果等待足够长（>1s），会重新初始化

### PJSIP 的格式协商

```cpp
// 伪代码
pj_status_t answer_call_with_video(call_id, vid_cnt=1) {
    // 1. 获取编码器配置的格式
    encoder_format = get_encoder_format();  // 720x480 @ 25fps

    // 2. 尝试打开设备
    status = open_device_with_format(encoder_format);
    if (status != SUCCESS) {
        // 如果无法以指定格式打开，拒绝视频
        return m=video 0;
    }

    // 3. 创建视频流
    create_video_stream();
    return m=video [port];
}
```

**关键点**：PJSIP 必须以编码器配置的格式打开设备，否则无法创建视频流。

## 💡 第十次修复方案（当前）

### 核心思路

**在预启动 preview 时，显式指定格式匹配编码器配置（720x480 @ 25fps）**

这样：
1. ✅ 设备以正确格式初始化
2. ✅ 驱动"记住"正确的格式
3. ✅ 停止后重新打开时，更容易匹配编码器格式

### 实现代码

**文件**: `src/sip_phone/SipPhoneManager.cpp` (行 2332-2369)

```cpp
// ✅ ATTEMPT 10: Specify format matching H.264 encoder config (720x480 @ 25fps)
if (isVideoCall && d->videoCallManager) {
    qDebug() << "📹 [PRE-START] Video call detected, pre-starting device...";
    pjmedia_vid_dev_index cap_dev = d->videoCallManager->getCaptureDeviceId();

    // ✅ CRITICAL: Specify format matching H.264 encoder config
    pjsua_vid_preview_param preview_param;
    pjsua_vid_preview_param_default(&preview_param);
    preview_param.show = PJ_FALSE;  // Don't show window

    // Set video format to match encoder (from risipendpoint.cpp:641-646)
    preview_param.wnd_flags = PJMEDIA_VID_DEV_WND_BORDER;  // Required for format to take effect
    preview_param.format.type = PJMEDIA_TYPE_VIDEO;
    preview_param.format.id = PJMEDIA_FORMAT_YUY2;  // YUV 4:2:2
    preview_param.format.det.vid.size.w = 720;      // Width (matches encoder)
    preview_param.format.det.vid.size.h = 480;      // Height (matches encoder)
    preview_param.format.det.vid.fps.num = 25;      // FPS numerator (matches encoder)
    preview_param.format.det.vid.fps.denum = 1;     // FPS denominator

    qDebug() << "   Using format: 720x480 @ 25fps YUY2 (matching encoder config)";

    pj_status_t status = pjsua_vid_preview_start(cap_dev, &preview_param);
    if (status == PJ_SUCCESS) {
        qDebug() << "✅ [PRE-START] Device" << cap_dev << "pre-started successfully (hidden)";
        qDebug() << "   Device opened with encoder-compatible format";
        d->videoPreviewActive = true;
    }
}
```

**修改 2**: 增加等待时间（行 1632-1634）

```cpp
// Wait for preview to fully release resources (window, port, driver state)
// Increased from 100ms to 200ms to ensure device is fully ready
QThread::msleep(200);
```

### 关键改进

1. **显式指定格式**：
   ```cpp
   preview_param.format.det.vid.size.w = 720;   // 匹配编码器
   preview_param.format.det.vid.size.h = 480;
   preview_param.format.det.vid.fps.num = 25;
   ```

2. **wnd_flags 设置**：
   ```cpp
   preview_param.wnd_flags = PJMEDIA_VID_DEV_WND_BORDER;
   ```
   这个标志可能帮助 PJSIP 正确应用格式参数（经验值）

3. **增加等待时间**：
   - 从 100ms 增加到 200ms
   - 给予设备更多时间完全释放和重置状态

### 解决的核心问题

1. **格式匹配**：设备以编码器需要的格式初始化
2. **驱动缓存**：驱动"记住"正确的格式配置
3. **快速重启**：停止后重新打开时更容易匹配格式

### 技术原理

**DirectShow 格式"记忆"**：

```
首次打开（默认格式）：
Device → DirectShow Driver → 选择最高分辨率（1920x1080）
         └─ 缓存配置

重新打开（无指定格式）：
Device → DirectShow Driver → 尝试复用缓存配置（1920x1080）
         └─ 与编码器不匹配 → 失败

首次打开（指定格式）：
Device → DirectShow Driver → 使用指定格式（720x480）✅
         └─ 缓存配置（720x480）

重新打开（编码器格式）：
Device → DirectShow Driver → 尝试复用缓存配置（720x480）✅
         └─ 与编码器匹配 → 成功！
```

## 🔄 如果仍有问题

### 场景 A: 格式参数被忽略

**症状**:
```
Opening device ... format=YUY2, size=1920x1080  ← 还是 1920x1080
```

**原因**: PJSIP 可能忽略格式参数（某些版本的 bug）

**解决**: 修改 risipendpoint.cpp 的编码器配置，改为 1920x1080 @ 5fps

### 场景 B: 设备不支持 720x480

**症状**:
```
⚠️ [PRE-START] Failed to pre-start device: [error message]
```

**原因**: 摄像头不支持 720x480 分辨率

**解决**: 尝试其他分辨率（640x480, 800x600）

### 场景 C: 仍然 m=video 0

**症状**:
- 格式正确（720x480）
- 但应答后还是 `m=video 0`

**可能原因**:
1. 200ms 仍不够（增加到 300ms）
2. PJSIP 内部状态问题（需要深入源码调试）
3. miniSIPServer 的特殊要求

## 🎓 修复历程总结

### 10 次尝试的演进

| 尝试 | 方案 | 问题 | 发现 |
|------|------|------|------|
| 1 | 直接 vid_cnt=1 | m=video 0 | 设备未初始化 |
| 2 | Audio + re-INVITE | PT不匹配 | 重新协商改变PT |
| 3 | Preview → 停止 → 应答 | m=video 0 | 设备释放未完成 |
| 4 | Preview保持运行 | m=video 0 | 格式不匹配 |
| 5 | 指定格式 → 应答 | m=video 0 | PJSIP忽略参数 |
| 6 | 立即 re-INVITE ADD | 挂断 | 双m=video线 |
| 7 | 深度调试 | 找到根因 | 设备来不及初始化 |
| 8 | 预启动设备 | 窗口/端口占用 | Preview占用资源 |
| 9 | 停止Preview释放资源 | 仍m=video 0 | **格式不匹配** |
| 10 | **指定格式 + 停止 + 200ms** | **应该成功** | **格式匹配** |

### 关键洞察

1. **设备初始化时间**: 需要提前预热（~200ms）
2. **资源独占**: Preview 和 Call 不能共享窗口/端口
3. **格式匹配**: 设备格式必须匹配编码器配置
4. **驱动缓存**: DirectShow 驱动会"记住"上次的格式
