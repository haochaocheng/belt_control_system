## 💡 问题根因：非标准分辨率

### 用户提供的关键信息

PortSIP UC Client 视频设置支持：

**分辨率**:
- **CIF**: 352×288
- **720P**: 1280×720
- **1080P**: 1920×1080

**码流**: 128, 256, 512, 1024, 2048 Kbps

### 我们发送的参数（不匹配）

- **分辨率**: 720×480 ← **不在支持列表中！**
- **码流**: 约 220 Kbps ← **不在预设列表中！**

### 分析

**720×480 不是标准视频分辨率**：
- 不是 ITU-T 标准（CIF, QCIF, 4CIF）
- 不是 HD 标准（720P, 1080P）
- 是老式 DVD/NTSC 分辨率，现代视频会议软件通常不支持

**PortSIP UC Client 可能**：
- 收到 RTP 包但无法解码（分辨率不匹配）
- 或者拒绝不在支持列表中的分辨率
- 解码器期望 1280×720 但收到 720×480，导致解码失败

---

## 🛠️ 第十四次修复方案

### 核心思路：改为 720P 标准分辨率

将编码器输出从 **720×480** 改为 **1280×720 (720P)**。

### 为什么选择 720P？

| 选项 | 分辨率 | 优势 | 劣势 |
|------|--------|------|------|
| **CIF** | 352×288 | 带宽低，兼容性最好 | 画质较差 |
| **720P** | 1280×720 | 画质好，现代标准 | 带宽需求中等 |
| **1080P** | 1920×1080 | 画质最好 | 带宽需求高 |

**选择 720P 理由**：
1. ✅ 是现代视频会议的主流标准
2. ✅ 画质与带宽的良好平衡
3. ✅ 摄像头通常原生支持 1280×720
4. ✅ PortSIP UC Client 明确支持

---

## 🛠️ 实现代码

**文件**: `src/risip/core/risipendpoint.cpp` (行 644-648)

### 修改前（720×480）
```cpp
// Keep resolution at 720x480 (good balance of quality and performance)
h264_param.enc_fmt.det.vid.size.w = 720;
h264_param.enc_fmt.det.vid.size.h = 480;
```

### 修改后（1280×720）
```cpp
// ✅ ATTEMPT 14: Change to 720P (1280x720) - standard resolution supported by PortSIP UC Client
// PortSIP UC Client supports: CIF (352×288), 720P (1280×720), 1080P (1920×1080)
// Our previous 720x480 is not a standard resolution and was rejected
h264_param.enc_fmt.det.vid.size.w = 1280;  // 720P width
h264_param.enc_fmt.det.vid.size.h = 720;   // 720P height
```

同时更新日志输出：
```cpp
qDebug() << "✅ H264 video codec configured: 1280x720 (720P) @ 25fps (TX), up to 30fps (RX)";
```

### 场景 A: 摄像头不支持 1280×720

**症状**:
```
vid_port.c  Opening device ... size=1280x720
vid_port.c  Device opened: size=640x480  ← 降级到 VGA
```

**原因**: 摄像头硬件不支持 720P

**解决**: 改为 **CIF (352×288)**，虽然画质较差但兼容性最好
```cpp
h264_param.enc_fmt.det.vid.size.w = 352;   // CIF width
h264_param.enc_fmt.det.vid.size.h = 288;   // CIF height
```

---

### 场景 B: 带宽不足

**症状**:
- 视频卡顿
- 对方看到马赛克或延迟严重
- 网络拥塞

**原因**: 720P 需要约 400-600 Kbps，网络带宽不足

**解决**:
1. 降低帧率到 15fps:
   ```cpp
   h264_param.enc_fmt.det.vid.fps.num = 15;
   ```
2. 或改用 CIF 分辨率

### 关键技术点

1. **来电视频激活的正确方法**:
   - 不能在应答时设置 `vid_cnt=1`（会被忽略）
   - 应该先应答音频，再用 API 激活视频
   - 使用 `pjsua_call_set_vid_strm()` + `CHANGE_DIR` 操作

2. **视频参数的重要性**:
   - 必须使用标准分辨率（CIF/720P/1080P）
   - 非标准分辨率可能被对方拒绝或无法解码
   - 720P 是现代视频会议的最佳选择

3. **re-INVITE 的标准流程**:
   - 先建立基础通话（音频）
   - 再通过 re-INVITE 添加或修改媒体流
   - 这是 RFC 3261 标准 SIP 流程
