# 视频来电修复历程 - 第七次尝试：深度调试

**日期**: 2025-12-11
**问题**: 接听 miniSIPServer 视频来电时，对方（PortSIP UC Client）看不到本机视频
**用户关键反馈**: "早期测试时，使用 miniSIPServer 是可以的，都能拨打视频电话"

---

## 修复历程回顾

### 第一次尝试: 直接用 vid_cnt=1 应答
```cpp
call_opt.vid_cnt = 1;
pjsua_call_answer2(call_id, &call_opt, 200, NULL, NULL);
```
**结果**: `m=video 0 RTP/AVP 125` (端口为 0，视频被拒绝)
**原因**: 视频编码器未初始化

---

### 第二次尝试: Audio-only + CHANGE_DIR
```cpp
// Step 1: 先用 audio-only 应答
call_opt.vid_cnt = 0;
pjsua_call_answer2(call_id, &call_opt, 200, NULL, NULL);

// Step 2: 延迟500ms后激活视频
QTimer::singleShot(500, [=]() {
    pjsua_call_vid_strm_op_param param;
    param.med_idx = 1;
    param.dir = PJMEDIA_DIR_ENCODING_DECODING;
    pjsua_call_set_vid_strm(call_id, PJSUA_CALL_VID_STRM_CHANGE_DIR, &param);
});
```
**结果**:
- 呼叫持续 29 秒
- 本机接收对方视频正常（~12 FPS）
- 对方看不到本机视频

**问题**: Payload type 不匹配
- 远端 offer: pt=125
- Audio-only answer: 拒绝视频
- re-INVITE: 本机 offer pt=100
- 导致编码/解码 payload type 不一致

---

### 第三次尝试: 启动 preview 初始化编码器
```cpp
// 启动 preview 初始化编码器
pjsua_vid_preview_start(cap_dev, NULL);
QThread::msleep(100);
// 停止 preview
pjsua_vid_preview_stop(cap_dev);

// 应答
call_opt.vid_cnt = 1;
pjsua_call_answer2(call_id, &call_opt, 200, NULL, NULL);
```
**结果**: 仍然 `m=video 0`

**问题**: 停止 preview 后，设备需要时间关闭，应答时设备未就绪

---

### 第四次尝试: 保持 preview 运行（不停止）
```cpp
// 启动 preview（不停止）
pjsua_vid_preview_param preview_param;
pjsua_vid_preview_param_default(&preview_param);
preview_param.show = PJ_FALSE;  // 隐藏窗口
pjsua_vid_preview_start(cap_dev, &preview_param);
QThread::msleep(200);
// ❌ 不调用 pjsua_vid_preview_stop()

// 应答
call_opt.vid_cnt = 1;
pjsua_call_answer2(call_id, &call_opt, 200, NULL, NULL);
```
**结果**: 仍然 `m=video 0`

**发现**: Preview 打开的格式与编码器不匹配
- Preview: 1920x1080 @ 5fps（设备默认格式）
- Encoder: 720x480 @ 25fps（risipendpoint.cpp 配置）
- PJSIP 无法复用格式不匹配的设备

---

### 第五次尝试: 指定 preview 格式匹配编码器
```cpp
pjsua_vid_preview_param preview_param;
pjsua_vid_preview_param_default(&preview_param);
preview_param.show = PJ_FALSE;

// 显式指定格式
preview_param.format.id = PJMEDIA_FORMAT_YUY2;
preview_param.format.det.vid.size.w = 720;
preview_param.format.det.vid.size.h = 480;
preview_param.format.det.vid.fps.num = 25;
preview_param.format.det.vid.fps.denum = 1;

pjsua_vid_preview_start(cap_dev, &preview_param);
```
**结果**: PJSIP 忽略了格式参数，仍打开为 1920x1080 @ 5fps

**问题**: PJSIP 的 preview 参数设置可能有问题或不生效

---

### 第六次尝试: Audio-only + 立即发送 re-INVITE ADD
```cpp
// Step 1: Audio-only 应答
call_opt.vid_cnt = 0;
pjsua_call_answer2(call_id, &call_opt, 200, NULL, NULL);

// Step 2: 立即发送 re-INVITE 添加视频
pjsua_call_vid_strm_op_param param;
param.med_idx = -1;  // Auto
param.dir = PJMEDIA_DIR_ENCODING_DECODING;
pjsua_call_set_vid_strm(call_id, PJSUA_CALL_VID_STRM_ADD, &param);
```
**结果**: miniSIPServer 发送 BYE 立即挂断

**问题**: SDP 中出现两条 m=video 线
```sdp
m=video 0 RTP/AVP 125        ← 第一条（audio-only answer 产生）
m=video 4002 RTP/AVP 100 96  ← 第二条（ADD 操作产生）
```
miniSIPServer 无法处理这种 SDP 格式

## 第七次尝试: 深度调试方案（当前）

### 用户的关键反馈

> "最好能做到兼容，因为早期测试时，使用 miniSIPServer 是可以的，都能拨打视频电话。你最好深入查找，应该不是 PJSIP 源码修改，你打印更多信息，看看到底是为什么"

### 核心思路

**不再尝试新方案，而是深入调试第一种方案（vid_cnt=1），找出为什么会失败**

理由：
1. ✅ 这是最直接、最标准的方法
2. ✅ 用户确认早期测试时这种方法是可行的
3. ✅ 不是根本性的不兼容问题，而是某个配置或初始化问题
4. ✅ 其他方案都是绕过问题，不是真正的解决方案

### 实现：添加详细调试日志

**文件**: `src/sip_phone/SipPhoneManager.cpp` (行 1559-1653)

添加了 7 个调试检查点：

1. **视频设备枚举**
   - 检查有哪些视频设备可用
   - 设备的方向（捕获/渲染）
   - 目的：确认摄像头是否被正确识别

2. **视频编解码器检查**
   - 检查 H264 等编解码器是否可用
   - 编解码器的优先级
   - 目的：确认编解码器配置正确

3. **账户配置检查**
   - 账户 ID
   - vid_cap_dev（视频捕获设备）
   - vid_rend_dev（视频渲染设备）
   - vid_out_auto_transmit（自动发送视频）
   - 目的：确认账户的视频配置正确

4. **应答前的通话状态**
   - 通话状态（INCOMING/EARLY等）
   - 媒体数量
   - 媒体状态
   - 目的：了解应答前的初始状态

5. **应答操作详情**
   - vid_cnt, aud_cnt, flag 参数
   - 应答是否成功
   - 目的：确认参数传递正确

6. **应答后的通话状态**
   - 媒体数量
   - 每个媒体流的类型/方向/状态
   - 视频流的捕获设备 ID
   - 目的：**关键**确定视频流是否被正确激活

7. **媒体流详细信息**
   - 视频流索引
   - 捕获设备 ID
   - 目的：定位设备分配问题

## 预期诊断场景

### 场景 A: 视频设备未初始化
**症状**:
```
📹 [1] Video Devices: Total 0 devices
```
**根因**: VideoCallManager 的 `initVideoSubsystem()` 未成功执行

---

### 场景 B: 编解码器未配置
**症状**:
```
📹 [2] Video Codecs: 0 available
```
**根因**: risipendpoint.cpp 中的 H264 编解码器配置问题

---

### 场景 C: 账户视频设备配置错误
**症状**:
```
📹 [3] Account ID: 0
   vid_cap_dev: 0 或 -1  ← 错误！
   vid_out_auto_transmit: 0  ← 错误！
```
**根因**: `configureAccountVideoDevice()` 未正确设置或未被调用

---

### 场景 D: 应答成功但视频流被禁用（关键场景）
**症状**:
```
📹 [6] Answer status: SUCCESS
📹 [7] Call Info AFTER Answer:
   Media 1:
     Type: 2 (video)
     Dir: 0  ← 应该是 3！
     Status: 0  ← 应该是 1！
```
**根因**: PJSIP 在生成 SDP answer 时无法创建视频流，可能原因：
- 设备打开失败
- 编码器初始化失败
- 格式协商失败

---

### 场景 E: 视频设备未分配
**症状**:
```
📹 [7] Call Info AFTER Answer:
   Media 1:
     Video cap_dev: -1  ← 无效！
```
**根因**: PJSIP 没有为视频流分配捕获设备
