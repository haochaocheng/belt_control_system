# 视频性能优化 - 默认格式优化方案

**日期**: 2025-12-10
**当前状态**: ✅ 方案实施完成，待测试验证性能提升

---

## 优化目标

**当前性能**: 14-16 FPS
**目标性能**: 50-60 FPS
**性能瓶颈**: PJSIP video conference bridge 自动缩放 640x360 → 720x480

---

## 问题分析

### 1. 已发现的性能瓶颈

从最近的测试日志发现：

```
📐 Actual video format from decoder: 720 x 480 @ 90 /1 fps
✅ Custom port created for Qt video sink: 720 x 480 @ 90 /1 fps
```

但 PJSIP 内部日志显示：
```
Decoding format changed to 640x360, bitrate=0bps
```

**问题**：
- 解码器实际输出: 640x360 @ 60fps
- 我们的 custom port 声明: 720x480 @ 90fps
- PJSIP conference bridge 自动缩放: 640x360 → 720x480
- 缩放浪费 CPU，处理 2.25 倍的数据量

### 2. 为什么之前的智能检测没生效？

在 `convertPjFrameToQt` 中添加的智能检测代码：

```cpp
// 根据 frame->size 推断实际分辨率
if (frame->size != expected_size_yuv420) {
    // 查找匹配的分辨率...
}
```

**没生效的原因**：PJSIP bridge 已经将帧缩放到 720x480，所以 `frame->size` 确实匹配 720x480 的预期大小，检测不到不匹配。

---

## 解决方案：动态格式检测与重建

### 核心思路

在**第一帧到达时**检测实际格式，如果与 port 声明不匹配，记录标志并警告。

### 实现的基础设施

#### 1. 新增成员变量

```cpp
// RemoteVideoManager.h
private:
    int m_customSlot;           // Custom port 在 vid_conf 中的 slot ID
    bool m_formatMismatch;      // 标记是否检测到格式不匹配
```

#### 2. 构造函数初始化

```cpp
RemoteVideoManager::RemoteVideoManager(QObject *parent)
    : ...
    , m_customSlot(PJSUA_INVALID_ID)
    , m_formatMismatch(false)
{
    // ...
}
```

#### 3. 存储 custom slot ID

在 `detectAndConnectToVideoBridge()` 中：

```cpp
// 添加 custom port 到 video conference
int custom_slot = PJSUA_INVALID_ID;
pjsua_vid_conf_add_port(m_pool, m_customPort, NULL, &custom_slot);

// ✅ 存储 slot ID
m_customSlot = custom_slot;

// 连接到 bridge
pjsua_vid_conf_connect(call_vid_slot, custom_slot, NULL);
```

#### 4. 增强的断开连接处理

```cpp
void RemoteVideoManager::disconnectFromVideoBridge()
{
    if (m_customSlot != PJSUA_INVALID_ID) {
        qDebug() << "🔌 RemoteVideoManager: Removing custom port, slot:" << m_customSlot;
        pjsua_vid_conf_remove_port(m_customSlot);
        m_customSlot = PJSUA_INVALID_ID;
    }
}
```

#### 5. 第一帧格式检测

在 `onFrameReceived()` 中：

```cpp
// ✅ 在第一帧到达时,检测实际格式
static int frameCount = 0;

if (frameCount == 0 && fmt) {
    pjmedia_video_format_detail *vfd = pjmedia_format_get_video_format_detail(fmt, PJ_TRUE);
    if (vfd) {
        qDebug() << "🎬 [FIRST FRAME] Port format:" << vfd->size.w << "x" << vfd->size.h
                 << "@" << vfd->fps.num << "/" << vfd->fps.denum << "fps"
                 << "| Frame buffer size:" << frame->size << "bytes"
                 << "| Format ID:" << Qt::hex << fmt->id;

        // 检测格式不匹配
        size_t expected_size = vfd->size.w * vfd->size.h * 3 / 2;
        if (frame->size != expected_size) {
            qWarning() << "⚠️ [FORMAT MISMATCH] Expected buffer size:" << expected_size
                       << "but got:" << frame->size;
            m_formatMismatch = true;
        }
    }
}
```

#### 6. 增强的性能日志

```cpp
// 每秒统计时显示格式不匹配警告
QString mismatchWarning = m_formatMismatch ? " ⚠️ FORMAT MISMATCH DETECTED" : "";
qDebug() << "📊 [REMOTE VIDEO PUSH]"
         << "Received FPS:" << actualFps
         << "| Avg interval:" << avgInterval << "ms"
         << "| Size:" << videoFrame.size()
         << mismatchWarning;
```

## 🎯 实施的优化方案

经过测试分析，我们发现：
1. **首帧格式检测无法触发**：因为 PJSIP bridge 在推送给我们之前已经缩放了帧
2. **实际视频格式**：640x360 @ 60fps（从 PJSIP 日志确认）
3. **我们之前的 port 声明**：720x480 @ 90fps（查询到的是 bridge 调整后的格式）
4. **性能损失**：处理 50% 多余的数据（720x480 vs 640x360）

### ✅ 选择的方案：优化默认格式（方案 B）

**实施内容**：
修改 `RemoteVideoManager.h` 中的默认参数：

```cpp
// 之前（导致 bridge 放大 640x360 → 720x480）
bool createCustomPort(int width = 1920, int height = 1080, int fps_num = 60, int fps_denum = 1);

// 优化后（匹配最常见的 SIP 视频格式）
bool createCustomPort(int width = 640, int height = 360, int fps_num = 30, int fps_denum = 1);
```

**为什么选择这个方案**：

1. **简单有效** ✅
   - 无需复杂的重建逻辑
   - 一行代码修改
   - 无需运行时检测

2. **符合实际使用场景** ✅
   - 大多数 SIP 视频通话：640x360 或更小
   - FreeSWITCH 默认格式：640x360 @ 60fps（测试日志确认）
   - 即使实际格式不同，bridge 也能正确处理

3. **性能优化明显** ✅
   - 如果实际是 640x360（最常见）：**无缩放损失，性能最优**
   - 如果实际是 352x288（更小）：bridge 放大，但仍比之前高效
   - 如果实际是 720p（罕见）：bridge 放大，但这种情况很少

4. **兼容性好** ✅
   - PJSIP bridge 自动处理格式转换
   - 不会导致兼容性问题
   - 向上向下缩放都支持

### ❌ 未选择的其他方案

**方案 A: 动态端口重建**
- 太复杂，需要在 PJSIP 线程中重建连接
- 可能导致短暂黑屏
- 收益不明确（因为无法准确检测真实格式）

**方案 C: 查询 SDP 协商结果**
- API 不直接暴露视频尺寸
- 需要深入解析 PJSIP 内部结构
- 开发成本高

## 技术要点

### 1. 为什么要存储 m_customSlot？

- PJSIP video conference 需要 slot ID 来断开连接和移除 port
- 存储 slot ID 使得我们可以在未来实现动态重建

### 2. 第一帧检测的时机

- 使用 static 变量 `frameCount` 追踪帧计数
- 只在 `frameCount == 0` 时执行格式检测，避免重复开销
- PJSIP 线程调用，检测代码必须快速完成

### 3. 格式不匹配的定义

当 port 声明的格式与实际帧大小不符时：

```cpp
size_t expected_size = width * height * 3 / 2;  // YUV420
if (frame->size != expected_size) {
    // 不匹配！
}
```

但注意：由于 PJSIP bridge 会预先缩放，这个检测可能在当前实现中不会触发。
