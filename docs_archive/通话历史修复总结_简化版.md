# 通话历史修复总结 - 简化版

## 核心问题

根据日志分析，问题的根源是：
**`addCallRecord` 被调用的时机太早，导致 callDirection 和 callDuration 数据不正确。**

从日志看：
```
[DEBUG] ✅ [CALL STATE] Call 0 state: CALLING
[DEBUG] 📝 [HISTORY] Adding call record:
[DEBUG]    Direction: 2 (Unknown)  ← 应该是 0 (Outgoing)
[DEBUG]    Duration: 0 ms          ← 应该在通话结束时捕获
```

## 最简单的修复方案

**方案**: 延迟 `addCallRecord` 的调用时机，从通话开始延迟到通话结束。

### 修改位置

**Risip CallManager** (src/risip/core/risipcallmanager.cpp)

当前代码：
```cpp
call->call();
emit outgoingCall(call);
qobject_cast<RisipCallHistoryModel *>(m_data->m_activeCallHistoryModel)->addCallRecord(call); // ← 太早了
```

修改为：
```cpp
call->call();
emit outgoingCall(call);
// ❌ 不要在这里调用 addCallRecord
// ✅ 改为在通话结束时调用（通过连接信号）
```

在 RisipCallManager 构造函数中连接信号：
```cpp
// 监听所有通话的状态变化
connect(this, &RisipCallManager::outgoingCall, this, [this](RisipCall *call) {
    connect(call, &RisipCall::statusChanged, this, [this, call]() {
        int status = call->status();
        if (status == RisipCall::CallDisconnected || status == RisipCall::Null) {
            // ✅ 通话结束时才添加历史记录
            qobject_cast<RisipCallHistoryModel *>(m_data->m_activeCallHistoryModel)->addCallRecord(call);
            disconnect(call, &RisipCall::statusChanged, this, nullptr);  // 断开连接避免重复添加
        }
    });
});
```

类似地修改 `incomingCall` 信号的处理。

## 问题 2: 历史记录顺序

Model 的 `addCallRecord` 应该插入到**开头**而不是末尾。

修改 risipcallhistorymodel.cpp 的 addCallRecord():
```cpp
// 之前
beginInsertRows(QModelIndex(), rowCount(), rowCount());
m_snapshots.append(snapshot);  // 追加到末尾

// 之后
beginInsertRows(QModelIndex(), 0, 0);  // 插入到开头
m_snapshots.prepend(snapshot);  // 添加到开头
```

## 问题 3: 语音通话不应启动视频预览

检查 SipPhoneManager.cpp，查找所有启动视频预览的代码，添加 `enableVideo` 条件判断。

关键位置：
- handleCallStatusChange() 中的视频预览启动逻辑
- 确保只有 enableVideo == true 时才启动预览

## 快速修复步骤

1. 修改 RisipCallManager，移除立即调用 `addCallRecord`
2. 添加信号连接，在 DISCONNECTED 状态时调用 `addCallRecord`
3. 修改 Model 的 `addCallRecord`，改为 prepend 而不是 append
4. 修复视频预览条件判断

这样可以同时解决：
- ✅ callDirection 正确（通话结束时 direction 已经确定）
- ✅ callDuration 正确（通话结束时有实际时长）
- ✅ 最新记录在最上面
- ✅ 语音通话不启动视频预览

---

**注意**: 这个方案比双阶段更新更简单，但缺点是**历史记录只在通话结束后才出现**，不能实时显示正在进行的通话。如果需要实时显示，还是需要双阶段方案。
