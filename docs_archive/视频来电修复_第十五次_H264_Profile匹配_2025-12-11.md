# 视频来电修复 - 第十五次：H.264 Profile匹配（miniSIPServer兼容性）

**日期**: 2025-12-11
**问题**: miniSIPServer场景下对方看不到本机视频（但miniSIP直连和FreeSWITCH正常）
**根本原因**: H.264 profile-level-id不匹配导致miniSIPServer无法正确转发
**解决方案**: 修改PJSIP源码，将profile-level-id从`42e01e`改为`42001f`

---

## 🎯 问题分析

### 三种场景测试结果

| 场景 | SIP服务器 | 本机→对方 | 对方→本机 | 结果 |
|------|-----------|-----------|-----------|------|
| **场景1** | **miniSIP直连** | ✅ 看到 | ✅ 看到 | **完全正常** |
| **场景2** | **FreeSWITCH** | ✅ 看到 | ✅ 看到 | **完全正常** |
| **场景3** | **miniSIPServer** | ✅ 看到 | ❌ 看不到 | **来电失败** |

### 关键发现

**不是PortSIP UC Client的问题**，而是miniSIPServer特定问题！

### 根本原因：H.264 Profile不匹配

**PortSIP UC Client INVITE SDP中的参数**：
```
a=fmtp:125 profile-level-id=42001f; packetization-mode=1
```
- `42001f` = Baseline Profile (42) + Level 3.1 (001f)

**本机应答的参数（修改前）**：
```
a=fmtp:125 profile-level-id=42e01e; packetization-mode=1
```
- `42e01e` = Baseline Profile (42) + Level 3.0 (e01e)

### 为什么miniSIP和FreeSWITCH可以但miniSIPServer不行？

#### miniSIP（点对点直连）
- 双方直接SDP协商，能够灵活协商profile差异
- ✅ 工作正常

#### FreeSWITCH（媒体服务器）
- B2BUA架构，完全重新生成SDP
- 具有视频转码功能，可以适配格式差异
- ✅ 工作正常

#### miniSIPServer（轻量级代理）
- 只转发SIP信令，不处理媒体
- SDP可能被简单修改，导致profile信息不匹配
- ❌ profile差异导致对方无法解码

## 🛠️ 第十五次修复方案

### 核心思路

**修改PJSIP源码，将H.264的默认profile-level-id改为与PortSIP UC Client一致的`42001f`**

### 修改的文件

**文件**: `F:\0\pjproject-2.15.1\pjproject-2.15.1\pjmedia\src\pjmedia-codec\ffmpeg_vid_codecs.c`

**位置**: 行302-308

### 修改内容

**修改前**：
```c
        /* Leading space for better compatibility (strange indeed!) */
        {2, { {{"profile-level-id",16},    {"42e01e",6}},  // ← Level 3.0
              {{" packetization-mode",19},  {"1",1}}, } },
```

**修改后**：
```c
        /* Leading space for better compatibility (strange indeed!) */
        /* ✅ ATTEMPT 15: Change profile-level-id to 42001f to match PortSIP UC Client
         * PortSIP UC Client sends: profile-level-id=42001f (Baseline Profile, Level 3.1)
         * Previous value: 42e01e (Baseline Profile, Level 3.0)
         * This should fix miniSIPServer compatibility issue
         */
        {2, { {{"profile-level-id",16},    {"42001f",6}},  // ← Level 3.1 ✅
              {{" packetization-mode",19},  {"1",1}}, } },
```

### 技术细节

**H.264 Profile-Level-ID格式**：
```
42001f = [42] [00] [1f]
         ↓     ↓    ↓
      Profile  Constraint  Level
      Baseline    0x00      3.1
```

**Profile**:
- `42` = Baseline Profile（基准配置）
- 最基础的H.264配置，兼容性最好

**Constraint Bits**:
- `00` = 无约束

**Level**:
- `1f` (十六进制) = 31 (十进制) = Level 3.1
- `e0` (修改前) = 30 (十进制) = Level 3.0

**Level 3.1 vs 3.0**:
- Level 3.1: 最大分辨率1280×720 @ 30fps（720P标准）✅
- Level 3.0: 最大分辨率720×576 @ 30fps（较低）
