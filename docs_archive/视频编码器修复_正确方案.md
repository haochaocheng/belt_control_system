## ✅ 正确的修复方案（第五次）

### 根本原因分析

在 `SipPhoneManager` 中发现了**两处**代码设置 `vid_out_auto_transmit = PJ_FALSE`，导致编码器被暂停：

**第一处**: [SipPhoneManager.cpp:304](E:\2025\3_gongkongji\belt_control_system\src\sip_phone\SipPhoneManager.cpp#L304) - 应用启动时调用

```cpp
// ❌ 问题代码（修复前）
acc_cfg.vid_in_auto_show = PJ_FALSE;
acc_cfg.vid_out_auto_transmit = PJ_FALSE;  // ← 应用启动时设置为 FALSE
```

**第二处**: [SipPhoneManager.cpp:1431](E:\2025\3_gongkongji\belt_control_system\src\sip_phone\SipPhoneManager.cpp#L1431) - 拨打视频通话前调用

```cpp
// ❌ 问题代码（修复前）
acc_cfg.vid_in_auto_show = PJ_FALSE;
acc_cfg.vid_out_auto_transmit = PJ_FALSE;  // ← 拨打通话前又设置为 FALSE！
```

**问题分析**:
1. 第一处在应用启动时调用 `configureAccountVideoDevice()`，但此时账户尚未创建，配置无效
2. 账户创建后，第二处在拨打通话前调用 `configureAccountVideoDevice(QString)`
3. **第二处的代码覆盖了第一处的配置**，重新设置为 `PJ_FALSE`
4. PJSIP 在 "Setting up TX" 阶段检查 `vid_out_auto_transmit`，发现是 `false`，暂停编码器

这解释了为什么：
- 第一次修复（只修复第一处）无效 - 被第二处覆盖
- 编码器总是被暂停 - 拨打通话前被重新设置为 `false`

**PJSIP 源码路径**:
`F:\0\pjproject-2.15.1\pjproject-2.15.1\pjsip\src\pjsua-lib\pjsua_vid.c:1313-1318`

```c

    status = pjmedia_vid_stream_pause(call_med->strm.v.stream,
                                      PJMEDIA_DIR_ENCODING);  // ← 暂停编码器
}
```

### 正确的修复

需要修复**两处**代码：

**第一处修复**: [SipPhoneManager.cpp:302-305](E:\2025\3_gongkongji\belt_control_system\src\sip_phone\SipPhoneManager.cpp#L302-L305)

```cpp
// ✅ 正确配置（修复后）

acc_cfg.vid_out_auto_transmit = PJ_TRUE;  // ✅ Changed from PJ_FALSE
```

**第二处修复**: [SipPhoneManager.cpp:1429-1432](E:\2025\3_gongkongji\belt_control_system\src\sip_phone\SipPhoneManager.cpp#L1429-L1432)

```cpp
// ✅ 正确配置（修复后）
acc_cfg.vid_in_auto_show = PJ_FALSE;
acc_cfg.vid_out_auto_transmit = PJ_TRUE;  // ✅ Changed from PJ_FALSE - CRITICAL!
```

**关键变更**: 两处都从 `PJ_FALSE` → `PJ_TRUE`

**为什么需要修复两处**:
- **第一处**: 为已存在的账户设置默认配置
- **第二处**: 在拨打视频通话前刷新账户配置 ← **这是关键！**

**调用流程**:
1. 应用启动 → 账户创建 → 第一处配置生效
2. 点击"视频通话" → `makeCall()` → 调用第二处 `configureAccountVideoDevice(QString)`
3. **第二处覆盖第一处的配置** ← 如果第二处仍是 `FALSE`，前功尽弃！
4. `pjsua_call_make_call()` → PJSIP 检查 `vid_out_auto_transmit`
5. 如果是 `TRUE` → 编码器自动启动 ✅
6. 如果是 `FALSE` → 编码器被暂停 ❌

## 💡 关键技术洞察

### 为什么官方例程不需要定时器？

官方 PJSIP 例程直接使用 **PJSIP C API** 创建账户，并在创建时就正确设置：

```c
// 官方例程的做法
pjsua_acc_config acc_cfg;
pjsua_acc_config_default(&acc_cfg);
acc_cfg.vid_out_auto_transmit = PJ_TRUE;  // ← 从一开始就设置正确
pjsua_acc_add(&acc_cfg, ...);
```

### 我们的代码为什么需要修复？

我们的代码混合使用了 **PJSUA2 C++ API** 和 **PJSIP C API**:

1. **账户创建**: 使用 PJSUA2 C++ API（`PjsipAccount::create()`）
2. **账户配置修改**: 使用 PJSIP C API（`pjsua_acc_modify()`）在 `configureAccountVideoDevice()`
3. **通话创建**: 使用 PJSIP C API（`pjsua_call_make_call()`）

这种混合使用导致：
- PJSUA2 C++ 配置 (`autoTransmitOutgoing = true`) **无效**
- PJSIP C API 配置 (`vid_out_auto_transmit = PJ_FALSE`) **生效**

**修复方法**: 在 C API 层直接设置正确的配置，绕过 PJSUA2 配置传递问题。

## 🎯 技术总结

### 配置层次关系

```
应用程序代码 (Qt/C++)
    ↓
PJSUA2 C++ API (AccountConfig.videoConfig.autoTransmitOutgoing)
    ↓ [传递不完整！]
PJSIP C API (pjsua_acc_config.vid_out_auto_transmit)
    ↓ [这里才是真正生效的配置]
PJMEDIA 视频子系统 (检查此配置决定是否暂停编码器)
```

### 修复原则

1. **直接在生效的层修复** - 在 PJSIP C API 层设置，不要依赖 PJSUA2 传递
2. **使用官方例程的做法** - 设置 `vid_out_auto_transmit = PJ_TRUE`
3. **删除所有 workaround** - 定时器、手动启动编码器等都不再需要
