## 💡 FreeSWITCH vs miniSIPServer

### 用户问题

用户问："为什么 FreeSWITCH 当作服务器的时候就可以，miniSIPServer 就不行？"

### 答案

**FreeSWITCH**（全功能媒体服务器）：
- ✅ 内置视频转码功能
- ✅ 可以接受非标准分辨率（720×480, 576×384 等）
- ✅ 自动转换为客户端支持的格式
- ✅ 充当两端之间的媒体网关

工作原理：
```
本机 (720×480)  →  FreeSWITCH  →  PortSIP UC Client
              [接收]         [转码]           [标准分辨率]
              720×480    → 1280×720 →        1280×720 ✅
```

**miniSIPServer**（轻量级 SIP 代理）：
- ❌ 无视频转码功能
- ❌ 只转发 RTP 包，不处理内容
- ❌ 两端必须协商兼容的格式
- ✅ 性能高、资源占用低

工作原理：
```
本机 (720×480)  →  miniSIPServer  →  PortSIP UC Client
              [转发]              [转发]           [无法解码]
              720×480       →     720×480 ×      拒绝 ❌
```

### 解决方案

**使用 miniSIPServer 时**，必须确保：
1. ✅ 本机发送的分辨率是对方支持的**标准分辨率**
2. ✅ PortSIP UC Client 支持：CIF (352×288), 720P (1280×720), 1080P (1920×1080)
3. ✅ 我们选择 720P (1280×720) - 画质和带宽的最佳平衡

**这就是为什么需要修复配置的原因**：让本机直接发送 PortSIP UC Client 可以解码的标准分辨率。

### 关键技术点

1. **来电视频激活的正确方法**:
   - 不能在应答时设置 `vid_cnt=1`（会被忽略）
   - 应该先应答音频，再用 API 激活视频
   - 使用 `pjsua_call_set_vid_strm()` + `CHANGE_DIR` 操作
   - 这是 RFC 3261 标准 SIP 流程

2. **视频参数的重要性**:
   - 必须使用标准分辨率（CIF/720P/1080P）
   - 非标准分辨率可能被对方拒绝或无法解码
   - 720P 是现代视频会议的最佳选择

3. **配置管理的重要性**:
   - 多个配置点必须协调一致
   - 后运行的配置会覆盖前面的配置
   - 必须检查整个初始化流程
   - 日志是诊断配置冲突的关键工具
