**问题**: 修复了两个H.264配置后，发现还有第三个设备格式配置点
**根本原因**: LocalVideoManager在preview时指定了720×480，影响了设备打开格式

## 💡 根本原因分析

### PJSIP视频流程

```
1. 打开视频设备（DirectShow）
   ├─ 请求格式：根据某个配置
   └─ 实际格式：设备支持的最接近格式（如640×480）

2. 设备输出 → 编码器

3. 编码器编码
   ├─ 使用设备的实际格式
   └─ 而不是 enc_fmt 配置的"期望"格式

4. 发送 RTP
   └─ 发送的是编码后的实际格式
```

**关键发现**：H.264编码器的`enc_fmt`配置只是**期望格式**，实际编码格式取决于**设备打开时的实际格式**。

### 三个配置点

经过深入分析，发现有**三个地方**设置了视频格式参数：

#### 配置点1：RisipEndpoint::start()
**文件**: `src/risip/core/risipendpoint.cpp` (行647-648)
**时机**: SIP Endpoint初始化（应用启动早期）
**作用**: 设置H.264编码器的"期望"格式

```cpp
h264_param.enc_fmt.det.vid.size.w = 1280;  // 720P width
h264_param.enc_fmt.det.vid.size.h = 720;   // 720P height
```

**状态**: ✅ 已修复（Attempt 14 初版）

#### 配置点2：VideoCallManager::initVideoSubsystem()
**文件**: `src/sip_phone/VideoCallManager.cpp` (行92-93)
**时机**: VideoCallManager初始化（在RisipEndpoint之后）
**作用**: 重新设置H.264编码器配置（覆盖第一个）

```cpp
h264_param.enc_fmt.det.vid.size.w = 1280;  // 720P width
h264_param.enc_fmt.det.vid.size.h = 720;   // 720P height
```

**状态**: ✅ 已修复（Attempt 14 初版）

#### 配置点3：LocalVideoManager::startPreview()
**文件**: `src/sip_phone/LocalVideoManager.cpp` (行51)
**时机**: 视频通话建立后启动本地preview
**作用**: **实际指定设备打开的格式** ← **这是最关键的！**

```cpp
// ❌ 修复前（问题所在）
pjmedia_format_init_video(&param.format, PJMEDIA_FORMAT_YUY2, 720, 480, 60, 1);
```

**状态**: ❌ 这是第二次测试发现的问题

### 为什么配置点3最关键？

配置点1和2设置的是编码器"期望"格式，但：
- 设备打开时，PJSIP会尝试用preview的format参数打开设备
- 设备以实际支持的格式打开（可能是640×480）
- 编码器使用**设备实际格式**，忽略"期望"格式

**因此，preview的format参数决定了最终编码的分辨率！**

### 关键技术点

1. **来电视频激活的正确方法**:
   - 不能在应答时设置`vid_cnt=1`（会被忽略）
   - 应该先应答音频，再用API激活视频
   - 使用`pjsua_call_set_vid_strm()` + `CHANGE_DIR`操作
   - 这是RFC 3261标准SIP流程

2. **视频参数的重要性**:
   - 必须使用标准分辨率（CIF/720P/1080P）
   - 非标准分辨率可能被对方拒绝或无法解码
   - 720P是现代视频会议的最佳选择

3. **配置管理的重要性**:
   - 多个配置点必须协调一致
   - 后运行的配置会覆盖前面的配置
   - 必须检查整个初始化流程

4. **设备格式vs编码器格式**:
   - **H.264编码器的enc_fmt只是"期望"格式**
   - **设备实际打开格式决定了最终编码分辨率**
   - **preview的format参数最关键**
   - 这是最隐蔽也是最重要的发现

### PJSIP视频格式优先级

```
优先级（从高到低）：

1. pjsua_vid_preview_start() 的 format 参数  ← 最高优先级！
   └─ LocalVideoManager::startPreview()

2. pjsua_vid_codec_set_param() 的 enc_fmt   ← 只是"期望"
   ├─ VideoCallManager::initVideoSubsystem()
   └─ RisipEndpoint::start()

实际流程：
1. Preview以format参数请求打开设备
2. 设备以支持的最接近格式打开
3. 编码器使用设备实际格式
4. 忽略enc_fmt的"期望"格式
```
