# 闪退问题分析与解决方案

## 问题现象

应用在关闭时闪退，日志显示：

```
[WARNING] Qt has caught an exception thrown from an event handler. Throwing
exceptions from an event handler is not supported in Qt.
You must not let any exception whatsoever propagate through Qt code.
...
UNKNOWN EXCEPTION CAUGHT!
```

## 闪退发生的时序

从日志分析闪退的时序：

1. **13:14:56** - 用户挂断通话
2. **13:14:57** - 通话正常结束，资源清理完成
3. **13:14:58** - 用户切换到历史页面（Tab 2）
4. **13:14:58.415** - **关键错误**：
   ```
   call.cpp !pjsua_call_get_info(id, &pj_ci) error:
   INVITE session already terminated (PJSIP_ESESSIONTERMINATED) (status=171140)
   ```
5. **13:14:58** - 用户关闭应用
6. **闪退发生**

## 根本原因

### 原因 1: 访问已终止的通话对象 ⚠️ **主要原因**

在切换到历史页面后，代码尝试访问刚刚结束的通话对象（Call ID 0）获取信息，但此时 PJSIP 的 INVITE session 已经被销毁。

**问题代码位置**（可能）:
- `SipPhoneManager::getCallHistoryModel()` 中可能调用了 `pjsua_call_get_info()`
- Risip SDK 的 `RisipCall` 对象可能在通话结束后仍然尝试访问 PJSIP 资源

### 原因 2: Qt 对象生命周期问题

```
[WARNING] "There are still \"1\" items in the process of being created at engine destruction."
```

这说明在 QML 引擎销毁时，还有 1 个 QML 对象正在创建过程中（可能是历史页面的某个 delegate 或组件）。

### 原因 3: 事件处理中的异常未捕获

异常从事件处理器中抛出，违反了 Qt 的规则。可能的源头：
- QML ListView delegate 的 `Component.onCompleted` 中访问了无效数据
- Model 的 `rowCount()` 或 `data()` 方法抛出异常

## 解决方案

### 方案 1: 修复 Call Info 访问（推荐）✅

在访问通话信息之前检查通话是否仍然有效：

**文件**: 可能在 `SipPhoneManager.cpp` 或 Risip SDK 中

```cpp
// 在访问 pjsua_call_get_info 之前检查
pjsua_call_info ci;
pj_status_t status = pjsua_call_get_info(call_id, &ci);

if (status == PJSIP_ESESSIONTERMINATED) {
    qWarning() << "Call" << call_id << "session already terminated, skipping...";
    return nullptr;  // 或返回空/默认值
}

if (status != PJ_SUCCESS) {
    qWarning() << "Failed to get call info:" << status;
    return nullptr;
}

// 继续处理...
```

### 方案 2: 延迟历史页面刷新

不要在通话刚结束时立即访问通话对象，而是等待一段时间：

**文件**: `SipHistoryPage.qml`

```qml
Connections {
    target: SipPhoneManager
    function onIsRegisteredChanged() {
        if (SipPhoneManager.isRegistered) {
            // 延迟 500ms 刷新，确保通话资源已完全清理
            refreshTimer.start()
        }
    }
}

Timer {
    id: refreshTimer
    interval: 500
    repeat: false
    onTriggered: {
        console.log("📝 Refreshing call history model...")
        historyList.model = null
        historyList.model = SipPhoneManager.getCallHistoryModel()
    }
}
```

### 方案 3: 添加异常捕获（保底方案）

在可能抛出异常的地方添加 try-catch：

**文件**: `SipPhoneManager.cpp`

```cpp
QObject* SipPhoneManager::getCallHistoryModel()
{
    try {
        risip::RisipCallManager *callManager = risip::RisipCallManager::instance();
        if (!callManager) {
            qWarning() << "Call manager not available";
            return nullptr;
        }

        if (!d->currentAccount) {
            qWarning() << "No active account - cannot get call history";
            return nullptr;
        }

        QString accountUri = d->currentAccount->configuration()->uri();
        QAbstractItemModel *historyModel = callManager->historyCallModelForAccount(accountUri);

        if (historyModel) {
            qDebug() << "Retrieved call history model for account:" << accountUri;
        } else {
            qWarning() << "No call history model found for account:" << accountUri;
        }

        return historyModel;
    } catch (const std::exception& e) {
        qCritical() << "Exception in getCallHistoryModel():" << e.what();
        return nullptr;
    } catch (...) {
        qCritical() << "Unknown exception in getCallHistoryModel()";
        return nullptr;
    }
}
```

### 方案 4: 修复 QML 对象创建时机

确保 QML 组件在引擎销毁前完成创建：

**文件**: 应用退出逻辑

```cpp
// 在应用退出时，先清理 QML 引擎
void MainWindow::closeEvent(QCloseEvent *event)
{
    // 1. 先注销 SIP 账户
    SipPhoneManager::instance()->logout();

    // 2. 给 Qt 事件循环时间处理所有待处理事件
    QApplication::processEvents();

    // 3. 延迟一小段时间让所有 QML 对象完成创建
    QThread::msleep(100);

    // 4. 继续关闭
    event->accept();
}
```

## 临时解决方案（快速修复）

### 快速修复 1: 在 QML 中捕获异常

```qml
// SipHistoryPage.qml
Connections {
    target: SipPhoneManager
    function onIsRegisteredChanged() {
        if (SipPhoneManager.isRegistered) {
            try {
                console.log("📝 Account registered, refreshing call history model...")
                historyList.model = null
                var newModel = SipPhoneManager.getCallHistoryModel()

                if (newModel) {
                    console.log("   New model:", newModel)
                    console.log("   Model rowCount:", newModel.rowCount())
                    historyList.model = newModel
                } else {
                    console.log("   ⚠️ Model is null, skipping...")
                }
            } catch (e) {
                console.error("❌ Error refreshing call history:", e)
            }
        }
    }
}
```

**注意**: QML 的 try-catch 只能捕获 JavaScript 异常，无法捕获 C++ 异常。

## 预防措施

1. **在 PJSIP 回调中检查对象有效性**:
   - 所有 `pjsua_call_*` API 调用前检查 call_id 是否有效
   - 检查返回值是否为 `PJSIP_ESESSIONTERMINATED`

2. **正确的对象生命周期管理**:
   - 确保 RisipCall 对象在 PJSIP session 销毁后不再被访问
   - 使用智能指针管理对象生命周期

3. **延迟敏感操作**:
   - 通话结束后不要立即访问通话对象
   - 使用 QTimer 延迟执行需要访问已结束通话的操作

4. **异常安全**:
   - 所有可能抛出异常的 C++ 代码都应该捕获异常
   - 不让异常传播到 Qt 事件循环
