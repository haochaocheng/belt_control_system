# 视频来电修复 - 第八次：来电时预启动设备

**日期**: 2025-12-11
**问题**: 应答时 PJSIP 无法立即打开视频设备，导致 `m=video 0`
**根本原因**: 设备初始化需要时间，应答的瞬间设备未就绪

---

## 📊 第七次测试（深度调试）的关键发现

### 问题确认

从 `📹 [7] Call Info AFTER Answer:` 日志：

```
Media 1 :
  Type: 2 (1=audio, 2=video)  ✓ 类型正确
  Dir: 0                       ✗ 应该是 3 (sendrecv)
```

SDP answer 中：


### 但是配置都正确

1. **视频设备可用** ✓
   ```
   Device 0 : Integrated Webcam | Dir: 1  ← 捕获设备
   ```

2. **H264 编解码器可用** ✓
   ```
   "H264/100" Priority: 200  ← 优先级高
   ```

3. **账户配置正确** ✓
   ```
   vid_cap_dev: 0              ← 指向正确设备
   vid_out_auto_transmit: 1    ← 自动发送启用
   ```

### 真正的问题

从 PJSIP 日志：
```
09:12:37.337  pjsua_media.c  ....Call 0: stream #1 (video) unchanged.
09:12:37.340  pjsua_media.c  ....Video updated, stream #1:  (inactive)
```

**"unchanged" 和 "inactive"** 说明：

**结论**: 设备**可以打开**，只是应答的瞬间来不及初始化。

## 💡 第八次修复方案

### 核心思路

**在检测到视频来电时立即预启动设备，而不是在接听时才启动**

时间线：
```
1. INVITE 到达 (t=0ms)
2. 检测到视频 (t=50ms)
3. 📹 [PRE-START] 启动设备 (t=60ms)  ← 新增
4. 设备初始化... (t=60-200ms)
5. 用户点击接听 (t=2000ms)  ← 设备已就绪！
6. pjsua_call_answer2(vid_cnt=1) (t=2001ms)
7. PJSIP 检测到设备已打开，复用 ✅
8. 生成 SDP: m=video 4002 ✅
```

### 实现代码

**修改 1**: 在检测到视频来电时启动设备

**文件**: `src/sip_phone/SipPhoneManager.cpp` (行 2290-2322)

```cpp
void SipPhoneManager::setIsIncomingVideoCall(bool isVideoCall)
{
    if (d->isIncomingVideoCall != isVideoCall) {
        d->isIncomingVideoCall = isVideoCall;
        emit isIncomingVideoCallChanged(isVideoCall);
        qDebug() << "✅ Incoming call detected: Video =" << isVideoCall;

        // ✅ CRITICAL: Pre-start video preview when video call is detected
        // This gives the device time to fully initialize BEFORE answerCall() is called
        // PJSIP will then reuse the already-open device
        if (isVideoCall && d->videoCallManager) {
            qDebug() << "📹 [PRE-START] Video call detected, pre-starting device...";
            pjmedia_vid_dev_index cap_dev = d->videoCallManager->getCaptureDeviceId();

            // Start preview with default parameters (let device choose format)
            pjsua_vid_preview_param preview_param;
            pjsua_vid_preview_param_default(&preview_param);
            preview_param.show = PJ_FALSE;  // Don't show window, just open device

            pj_status_t status = pjsua_vid_preview_start(cap_dev, &preview_param);
            if (status == PJ_SUCCESS) {
                qDebug() << "✅ [PRE-START] Device" << cap_dev << "pre-started successfully (hidden)";
                qDebug() << "   Device will be reused when answering call";
                // DO NOT stop preview - keep it running until answer
                d->videoPreviewActive = true;
            } else {
                char errmsg[PJ_ERR_MSG_SIZE];
                pj_strerror(status, errmsg, sizeof(errmsg));
                qWarning() << "⚠️ [PRE-START] Failed to pre-start device:" << errmsg;
            }
        }
    }
}
```

**修改 2**: 在通话结束/拒绝时停止预启动的设备

**文件**: `src/sip_phone/SipPhoneManager.cpp` (行 618-625, 638-645)

```cpp
// 在 CallDisconnected 处理中
if (d->videoPreviewActive && d->videoCallManager) {
    qDebug() << "📹 [PRE-START] Stopping pre-started device (call disconnected)";
    pjmedia_vid_dev_index cap_dev = d->videoCallManager->getCaptureDeviceId();
    pjsua_vid_preview_stop(cap_dev);
    d->videoPreviewActive = false;
}
setIsIncomingVideoCall(false);

// 同样在 Null 状态处理中
if (d->videoPreviewActive && d->videoCallManager) {
    qDebug() << "📹 [PRE-START] Stopping pre-started device (call returned to Null)";
    pjmedia_vid_dev_index cap_dev = d->videoCallManager->getCaptureDeviceId();
    pjsua_vid_preview_stop(cap_dev);
    d->videoPreviewActive = false;
}
setIsIncomingVideoCall(false);
```

## 🎯 为什么这次会成功

### 1. 设备有足够时间初始化

| 事件 | 旧方案（第七次） | 新方案（第八次） |
|------|---------------|---------------|
| 检测到视频 | t=50ms | t=50ms |
| 启动设备 | ❌ 在接听时 (t=2000ms) | ✅ 检测后立即 (t=60ms) |
| 用户接听 | t=2000ms | t=2000ms |
| 设备状态 | ❌ 未就绪（刚启动） | ✅ 已就绪（运行中 1940ms） |
| PJSIP 应答 | 尝试打开设备 → 失败 | 检测到设备已打开 → 复用 ✅ |

用户从看到来电到点击接听，通常需要 1-3 秒，足够设备完全初始化。

### 2. PJSIP 的设备复用机制

PJSIP 在应答时的逻辑：
```cpp
// 伪代码
pj_status_t answer_call_with_video(call_id, vid_cnt=1) {
    // 检查设备是否已打开（preview）
    if (device_is_open) {
        // ✅ 复用已打开的设备
        reuse_device_for_call();
        return SUCCESS;  // m=video <port>
    } else {
        // ❌ 尝试打开设备（可能来不及）
        if (open_device_now() == SUCCESS) {
            return SUCCESS;
        } else {
            return FAIL;  // m=video 0
        }
    }
}
```

**旧方案**: 设备未打开 → 应答时尝试打开 → 来不及 → `m=video 0`
**新方案**: 设备已打开 → 应答时直接复用 → 成功 → `m=video 4002` ✅

### 3. 格式问题已解决

之前担心格式不匹配的问题：
- 第四次尝试：Preview 打开为 1920x1080@5fps → 格式不匹配 → 失败
- 第五次尝试：指定格式 720x480@25fps → PJSIP 忽略 → 失败

但是从第七次测试日志看，LocalVideoManager 成功打开设备：
```
09:12:38.028  vid_port.c  ..Opening device Integrated Webcam [dshow] for capture: format=YUY2, size=720x480 @60:1 fps
09:12:38.063  vid_port.c  ..Device Integrated Webcam [dshow] opened: format=YUY2, size=640x480 @60:1 fps
```

说明：
1. PJSIP **可以**成功打开设备（不是设备问题）
2. 设备支持多种格式（640x480, 720x480, 1920x1080）
3. PJSIP 会自动协商合适的格式

**结论**: 只要设备提前打开，PJSIP 会处理格式问题。

### 4. 不影响用户体验

- `preview_param.show = PJ_FALSE` → 不显示预览窗口
- 设备在后台运行，用户无感知
- 如果用户拒绝来电，会自动停止设备
- 资源消耗极小（只打开设备，不渲染画面）

## 🎓 技术要点

### 为什么之前的方案都失败了？

| 方案 | 问题 | 原因 |
|------|------|------|
| 直接 vid_cnt=1 | m=video 0 | 设备未初始化 |
| Audio + re-INVITE | Payload type 不匹配 | 重新协商改变了 PT |
| 预览 → 停止 → 应答 | m=video 0 | 设备释放未完成 |
| 预览不停止 → 应答 | m=video 0 | 格式不匹配 |
| 指定格式 → 应答 | m=video 0 | PJSIP 忽略格式参数 |
| 立即 re-INVITE ADD | 双 m=video 线 | miniSIPServer 不接受 |
| **深度调试** | **找到根因** | **应答时设备来不及初始化** |
| **来电时预启动** | **应该成功** | **设备有足够时间准备** |

### PJSIP 设备管理逻辑

1. **Preview 状态**:
   - 启动 preview → 设备标记为"已打开"
   - PJSIP 维护设备使用状态表

2. **应答时检查**:
   - 检查设备是否已打开
   - 如果已打开 → 复用（快速）
   - 如果未打开 → 尝试打开（慢，可能失败）

3. **自动转移**:
   - 通话开始时，PJSIP 自动停止 preview
   - 设备所有权转移给通话
   - 无需手动干预
