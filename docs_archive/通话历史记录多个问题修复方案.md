# 通话历史记录多个问题修复方案

## 日期
2025-12-09 16:00

## 用户报告的问题

1. ❌ **拨打电话显示接入** - callDirection = 2 (Unknown)，应该是 0 (Outgoing)
2. ❌ **时长显示 --:--** - callDuration = 0，无论通话多长时间
3. ❌ **拨打语音时不需要展示本机预览视频** - 语音通话时启动了视频预览
4. ❌ **最后通话记录应该放在最上面** - 目前是旧记录在上
5. ❌ **对方拨打本机，只有时间，还是没有时长显示** - Incoming call 也没有 duration
6. ❌ **时间和时长列表与下面实际时间不再一列，错位了** - QML 布局问题

## 问题分析

### 问题 1 & 2: callDirection 和 callDuration 都是错误的

**根本原因**：snapshot 捕获时机太早！

当前流程：
```
1. RisipCall *call = new RisipCall() - callDirection = 2 (Unknown, 默认值)
2. call->call() 内部:
   - setCallDirection(Outgoing) - callDirection = 0
   - setPjsipCall(...) - 触发 statusChanged 信号
   - makeCall(...) - 发起调用
3. addCallRecord(call) 被调用 - 捕获 snapshot
```

**但是**，从日志看：
```
[DEBUG] ✅ [CALL STATE] Call 0 state: CALLING
[DEBUG] 📝 [HISTORY] Adding call record:
[DEBUG]    Direction: 2 (0=Outgoing, 1=Incoming, 2=Unknown)
```

`addCallRecord` 是在 CALLING 状态时被调用的，说明它是通过某个**信号处理**被调用的，而不是在 `RisipCallManager::callBuddyWithVideo()` 中直接调用的！

可能的原因：
- SipPhoneManager 连接了 `statusChanged` 信号
- 在信号处理中可能触发了某些操作，间接调用了 `addCallRecord`
- 或者有其他代码路径调用了 `addCallRecord`

**关键问题**：
1. callDirection 在 `call()` 方法中设置为 0
2. 但是 `addCallRecord` 可能在 `call()` 完全执行之前就被调用了（通过信号）
3. 导致捕获的 snapshot 中 callDirection = 2

### 问题 3: 语音通话时启动视频预览

日志显示：
```
[DEBUG] ✅ Call initiated via unified Risip API, video = false
...
[DEBUG] ✅ Video call started - auto-starting PJSIP local video preview
15:35:22.480            pjsua_vid.c !Starting preview for cap_dev=-1, show=0
```

这说明即使 `video = false`，视频预览仍然被启动了。

问题位置：SipPhoneManager 中的某个地方无条件启动了视频预览。

### 问题 4: 历史记录顺序

目前 `addCallRecord` 使用：
```cpp
beginInsertRows(QModelIndex(), rowCount(), rowCount());
m_snapshots.append(snapshot);  // 追加到末尾
endInsertRows();
```

应该改为：
```cpp
beginInsertRows(QModelIndex(), 0, 0);  // 插入到开头
m_snapshots.prepend(snapshot);  // 添加到开头
endInsertRows();
```

### 问题 5 & 6: QML 布局问题

需要检查 SipHistoryPage.qml 的布局。

## 解决方案

### 方案 A: 延迟 Snapshot 捕获（推荐）⭐

**核心思想**：不要在 `addCallRecord` 时立即捕获 snapshot，而是：
1. `addCallRecord` 时只添加 RisipCall 指针引用
2. 连接 `statusChanged` 信号，监听通话状态变化
3. 当通话结束（DISCONNECTED）时，捕获最终的 snapshot
4. 或者在通话建立（CONFIRMED）时，更新 direction 和 timestamp
5. 在通话结束时，更新 duration

**优点**：
- ✅ 保证 callDirection 正确（通话建立时捕获）
- ✅ 保证 callDuration 正确（通话结束时捕获）
- ✅ 数据持久化（snapshot 独立于 RisipCall 对象生命周期）

**缺点**：
- 需要修改 Model 的逻辑，增加信号连接
- 需要处理 RisipCall 对象被提前销毁的情况

### 方案 B: 强制同步捕获（简单但有风险）

**核心思想**：
1. 在 `RisipCall::call()` 方法的最后，主动 emit 一个 `callInitialized` 信号
2. RisipCallManager 连接这个信号，然后才调用 `addCallRecord`
3. 通话结束时，emit `callFinalized` 信号，更新 duration

**优点**：
- 简单，只需要添加一个新信号
- 逻辑清晰

**缺点**：
- 需要修改 Risip SDK（添加新信号）
- 仍然无法保证 duration 正确

### 方案 C: 双阶段 Snapshot（折中方案）⭐⭐

**核心思想**：
1. `addCallRecord` 时捕获初步 snapshot（contact, timestamp）
2. 连接 RisipCall 的 `statusChanged` 信号
3. 当状态变为 CONFIRMED 时，更新 direction
4. 当状态变为 DISCONNECTED 时，更新 duration
5. 使用 QHash<RisipCall*, int> 存储 call 到 snapshot index 的映射

**优点**：
- ✅ 不需要修改 Risip SDK
- ✅ 可以正确捕获 direction 和 duration
- ✅ 支持实时更新（通话进行中可以看到变化）

**缺点**：
- 需要管理 call 指针到 index 的映射
- 需要处理 Model 的 dataChanged 信号

## 推荐方案：方案 C

实施步骤：

### 步骤 1: 修改 RisipCallHistoryModel.h

添加：
1. `QHash<RisipCall*, int> m_callIndexMap;` - 存储 call 到 index 的映射
2. `void updateCallRecord(RisipCall *call);` - 公开方法，用于更新记录
3. 私有槽 `void onCallStatusChanged()`

### 步骤 2: 修改 RisipCallHistoryModel.cpp

修改 `addCallRecord()`：
1. 捕获初步 snapshot（contact, timestamp, direction=Unknown, duration=0）
2. 插入到**开头**（prepend）而不是末尾（append）
3. 连接 call 的 `statusChanged` 信号到 `onCallStatusChanged()`
4. 将 call 指针和 index 存入 m_callIndexMap

添加 `onCallStatusChanged()` 槽：
1. 获取发送信号的 RisipCall 对象
2. 根据 status 决定是否更新 snapshot
3. 如果 status == CONFIRMED：更新 direction
4. 如果 status == DISCONNECTED：更新 duration，断开信号连接，从 map 中移除

### 步骤 3: 修复视频预览问题

在 SipPhoneManager.cpp 中，检查所有启动视频预览的地方，添加 `enableVideo` 条件判断。

### 步骤 4: 修复 QML 布局问题

检查 SipHistoryPage.qml 的列对齐设置。
