## 根本原因

**H.264 编解码器参数不匹配!**

对方提供的 H264 参数:
- `profile-level-id=42001f` - H.264 Baseline Profile (42), Level 3.1 (001f)
- `packetization-mode=1` - 单个 NAL 单元模式

**我们的 H264 编解码器默认配置可能不支持这些参数**, 导致 PJSIP 在 SDP 协商时拒绝视频流。

即使:
- ✅ 我们有 H264 编解码器 (priority 128)
- ✅ 账户配置正确 (vid_cap_dev=0, vid_out_auto_transmit=1)
- ✅ 调用 `pjsua_call_answer2(vid_cnt=1)`

PJSIP 仍然会在 SDP 协商阶段检查编解码器参数兼容性, 如果参数不匹配, 就会拒绝视频 (`m=video 0`)。

## 解决方案

### 修改文件: VideoCallManager.cpp (lines 72-134)

在 `initVideoSubsystem()` 方法中添加 H264 编解码器参数配置:

```cpp
// ✅ CRITICAL: Configure H264 codec parameters to match remote offer
// Remote offers: profile-level-id=42001f, packetization-mode=1
// We need to configure our H264 to accept these parameters
qDebug() << "📹 Configuring H264 codec parameters...";

pjmedia_vid_codec_param codec_param;
pj_str_t codec_id = pj_str((char*)"H264");

// Get current H264 codec parameters
status = pjsua_vid_codec_get_param(&codec_id, &codec_param);
if (status == PJ_SUCCESS) {
    qDebug() << "  Current H264 config:";
    qDebug() << "    dir:" << codec_param.dir;
    qDebug() << "    packing:" << codec_param.packing;
    qDebug() << "    enc_fmt.id:" << codec_param.enc_fmt.id;

    // ✅ Set H264 parameters to match remote offer
    // profile-level-id=42001f = Baseline Profile (42), Level 3.1 (001f)
    codec_param.dir = PJMEDIA_DIR_ENCODING_DECODING;  // Both directions

    // Apply the modified parameters
    status = pjsua_vid_codec_set_param(&codec_id, &codec_param);
    if (status == PJ_SUCCESS) {
        qDebug() << "✅ H264 codec parameters configured successfully";
    } else {
        char errmsg[PJ_ERR_MSG_SIZE];
        pj_strerror(status, errmsg, sizeof(errmsg));
        qWarning() << "❌ Failed to set H264 parameters:" << errmsg;
    }
}

// ✅ Also boost H264 codec priority to highest
pjsua_codec_info vid_codecs[32];
unsigned vid_codec_count = PJ_ARRAY_SIZE(vid_codecs);
status = pjsua_vid_enum_codecs(vid_codecs, &vid_codec_count);

if (status == PJ_SUCCESS) {
    qDebug() << "📹 Ensuring video codec priorities are set...";
    for (unsigned i = 0; i < vid_codec_count; ++i) {
        pj_str_t vid_codec_id = vid_codecs[i].codec_id;
        QString codecName = QString::fromUtf8(vid_codec_id.ptr, vid_codec_id.slen);

        // Prioritize H264 highest
        if (codecName.contains("H264", Qt::CaseInsensitive)) {
            pjsua_vid_codec_set_priority(&vid_codec_id, 200);  // Highest priority
            qDebug() << "  Set" << codecName << "priority to 200 (highest)";
        }
    }
}
```

## 技术背景

### H.264 Profile-Level-ID 解释

`profile-level-id=42001f` 包含三部分:
- `42` = Profile IOP (Baseline Profile)
- `00` = Profile IOP constraints
- `1f` = Level (Level 3.1, 支持 1280x720@30fps)

### Packetization Mode

- Mode 0: Single NAL unit mode (简单, 每个 RTP 包一个 NAL 单元)
- Mode 1: Non-interleaved mode (更高效, 支持 FU-A 分片)
- Mode 2: Interleaved mode (复杂, 很少使用)

大多数现代 SIP 系统使用 Mode 1。

### 为什么之前主叫视频通话能工作?

当本机主叫对方时:
- **我们发送 SDP offer**, 对方只需接受我们的参数
- 对方通常支持更广泛的参数范围
- 我们提出什么参数, 对方就接受什么参数

当对方主叫本机时:
- **对方发送 SDP offer**, 我们需要匹配他们的参数
- 如果我们的编解码器不支持对方的参数, 协商失败
- PJSIP 会拒绝视频流 (`m=video 0`)

## 如果仍然不工作

如果 H264 参数配置后仍然失败, 可能需要:

1. **检查 PJSIP H264 编解码器实现**
   - PJSIP 可能使用 FFmpeg, OpenH264, 或其他 H264 实现
   - 不同实现支持的参数不同

2. **添加更详细的 SDP 日志**
   - 启用 PJSIP 详细日志级别 5
   - 查看 SDP 协商的详细过程

3. **尝试使用 VP8 编解码器**
   - VP8 参数协商更简单
   - 作为备选方案

4. **考虑强制特定编解码器**
   - 在 SDP offer 中只包含一个编解码器
   - 减少协商复杂度
