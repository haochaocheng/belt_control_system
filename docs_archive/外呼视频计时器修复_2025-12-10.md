# 外呼视频通话计时器显示修复

**日期**: 2025-12-10
**问题**: 外呼视频通话接通后，界面不显示通话计时器（来电和语音通话正常）
**状态**: ✅ 已修复

---

## 问题描述

用户反馈：
- ✅ **来电（音频/视频）**: 计时器显示正常
- ✅ **外呼语音通话**: 计时器显示正常
- ❌ **外呼视频通话**: 计时器不显示（但后台计时器正常运行）

---

## 根本原因

### 问题定位

通过日志分析发现，后台计时器实际上**已经启动**：

```
✅ [CALL STATE] Call 0 state: CONFIRMED
✅ [UI] Call timer started
```

但 QML 界面不显示时间，说明问题出在**UI 可见性条件**。

### 代码分析

#### QML 界面条件 (SipDialPage.qml:444)

```qml
Text {
    text: formatDuration(SipPhoneManager.callDuration)
    font.pixelSize: 32
    font.bold: true
    color: "#ffffff"
    Layout.alignment: Qt.AlignHCenter
    visible: SipPhoneManager.callStatus.indexOf("通话中") >= 0  // ← 关键条件
}
```

**可见性条件**: 只有当 `callStatus` **包含"通话中"**时才显示。

#### C++ 状态字符串 (SipPhoneManager.cpp:1318-1321)

```cpp
QString statusText = isVideoCall ?
    QString("视频通话: %1").arg(d->callerDisplayName) :      // ❌ 不包含"通话中"
    QString("与 %1 通话中").arg(d->callerDisplayName);       // ✅ 包含"通话中"
updateCallStatus(statusText);
```

**问题**：外呼视频通话的状态设置为 **"视频通话: XXX"**，不包含"通话中"字样。

## 解决方案

### 修改内容

需要修改**两个位置**的状态字符串：

#### 修改 1: PJSIP 回调函数（所有通话）

修改 [SipPhoneManager.cpp:131](src/sip_phone/SipPhoneManager.cpp#L131)：

```cpp
// 修复前（PJSIP 回调 - 来电和外呼都经过这里）
statusText = isVideoCall ?
    QString("视频通话: %1").arg(displayName) :
    QString("与 %1 通话中").arg(displayName);

// 修复后
statusText = isVideoCall ?
    QString("视频通话中: %1").arg(displayName) :  // ✅ 添加"通话中"
    QString("与 %1 通话中").arg(displayName);
```

#### 修改 2: 外呼视频通话处理函数

修改 [SipPhoneManager.cpp:1319](src/sip_phone/SipPhoneManager.cpp#L1319)：

```cpp
// 修复前（外呼视频通话的特殊处理）
QString statusText = isVideoCall ?
    QString("视频通话: %1").arg(d->callerDisplayName) :
    QString("与 %1 通话中").arg(d->callerDisplayName);

// 修复后
QString statusText = isVideoCall ?
    QString("视频通话中: %1").arg(d->callerDisplayName) :  // ✅ 添加"通话中"
    QString("与 %1 通话中").arg(d->callerDisplayName);
```

### 修改原理

将 **"视频通话:"** 改为 **"视频通话中:"**，使其包含"通话中"字样，满足 QML 的可见性条件。

**为什么需要修改两处**：
1. **Line 131**: PJSIP 状态回调函数（`onCallStateCallback`），处理所有通话类型
2. **Line 1319**: Risip SDK 状态回调函数（`handleCallStatusChange`），外呼通话的特殊处理

两个路径都会设置状态，需要统一修改。
