# 批量生产部署指南

## 📋 概述

本指南提供完整的批量生产部署方案,适用于:
- ✅ 生产环境批量安装
- ✅ 多台工控机快速部署
- ✅ 一键式操作,员工易用
- ✅ 所有依赖打包在Docker镜像中

---

## 🚀 快速开始

### 方案A: 一键批量部署(推荐)

**适用场景**: 有多台工控机需要部署

1. **配置设备列表**
   - 打开文件: `batch-deploy.ps1`
   - 找到 `$DeviceList` 配置
   - 填入所有工控机的IP地址:

   ```powershell
   $DeviceList = @(
       "192.168.10.170",
       "192.168.10.171",
       "192.168.10.172",
       "192.168.10.173",
       "192.168.10.174"
       # 添加更多IP...
   )
   ```

2. **运行部署**
   - 双击: `一键部署.bat`
   - 或运行: `powershell -ExecutionPolicy Bypass -File batch-deploy.ps1`

3. **等待完成**
   - 脚本会自动完成所有步骤
   - 显示部署结果统计

---

### 方案B: 单台部署

**适用场景**: 部署单台工控机或测试

1. **修改目标IP**(如果需要)
   - 打开文件: `deploy-on-device.ps1`
   - 找到: `$RemoteHost = "192.168.10.170"`
   - 改为目标设备IP

2. **运行部署**
   ```powershell
   powershell -ExecutionPolicy Bypass -File deploy-on-device.ps1
   ```

## 📊 部署流程说明

### 批量部署流程 (batch-deploy.ps1)

```
Step 1: 在第一台设备上构建Docker镜像
   └─ 传输二进制文件 + 106个共享库
   └─ 在设备上构建镜像(3-5分钟)
   └─ 启动容器

Step 2: 导出Docker镜像
   └─ 保存为 tar 文件
   └─ 下载到本地(~150 MB)

Step 3: 批量部署到其他设备
   └─ 逐个传输镜像文件
   └─ 加载镜像
   └─ 启动容器
```

**优点**:
- ✅ 只需构建一次镜像
- ✅ 其他设备直接加载,速度快
- ✅ 确保所有设备运行相同版本
- ✅ 适合大规模生产部署

---

### 单台部署流程 (deploy-on-device.ps1)

```
Phase 1: 准备构建文件
   └─ 复制二进制文件(8.14 MB)
   └─ 复制共享库(52.33 MB)
   └─ 复制 Dockerfile

Phase 2: 传输到工控机
   └─ 通过 SCP 传输所有文件

Phase 3: 构建Docker镜像
   └─ 在工控机上执行 docker build
   └─ 安装系统依赖
   └─ 打包应用和库文件

Phase 4: 启动容器
   └─ 停止旧容器
   └─ 启动新容器
   └─ 验证状态
```

## 🛠️ 员工操作手册

### 日常操作

#### 1. 批量部署新版本

```bash
# Step 1: 开发人员编译新版本
cd e:\2025\3_gongkongji\belt_control_system

# Step 2: 生产人员批量部署
```



```powershell
# 停止
ssh pi@192.168.10.170 "docker stop belt_control"

# 启动
ssh pi@192.168.10.170 "docker start belt_control"
```

## 🔧 故障排查

### 问题1: SSH连接失败

**错误**: `Connection refused` 或 `No route to host`

**解决**:
1. 检查IP地址是否正确
2. 检查网络连接
3. 确认工控机已开机
4. 测试连接: `ping 192.168.10.170`

---

### 问题2: Docker镜像构建失败

**错误**: `docker build failed`

**解决**:
1. SSH到设备检查日志:
   ```bash
   ssh pi@192.168.10.170
   cd /tmp/belt-control-build
   docker build -t belt-control-rk3588:runtime .
   ```

2. 检查网络连接(需要下载Debian包)
3. 检查磁盘空间: `df -h`

---

### 问题3: 容器无法启动

**错误**: 容器启动后立即退出

**解决**:
1. 查看容器日志:
   ```bash
   ssh pi@192.168.10.170 "docker logs belt_control"
   ```

2. 检查错误信息
3. 常见问题:
   - 缺少库文件 → 重新构建镜像
   - 配置文件错误 → 检查挂载的配置
   - 显示问题 → 检查DISPLAY环境变量

---

### 问题4: 批量部署部分失败

**现象**: 部分设备部署成功,部分失败

**解决**:
1. 查看失败的设备IP
2. 单独对失败设备运行 `deploy-on-device.ps1`
3. 检查失败原因:
   - 网络问题
   - 磁盘空间不足
   - Docker未安装或未启动

## 📈 性能参数

### 部署时间估算

| 步骤 | 单台时间 | 批量时间(10台) |
|------|----------|----------------|
| 构建镜像 | 3-5分钟 | 3-5分钟(只需一次) |
| 传输镜像 | 1-2分钟 | 10-20分钟(并行可更快) |
| 加载镜像 | 1分钟 | 1分钟/台 |
| 启动容器 | 10秒 | 10秒/台 |
| **总计** | **5-8分钟** | **15-30分钟** |

### 网络要求

- **下载**: 构建时需下载Debian包(约50-100 MB)
- **传输**: 镜像文件约150 MB
- **带宽**: 建议100Mbps以上局域网

### 磁盘空间

- **开发机**: 需要200 MB临时空间
- **工控机**: 每台需要300-500 MB空间

## 🎯 最佳实践

### 1. 新设备初始化

```bash
# 在新设备上执行
ssh pi@新设备IP

# 安装Docker(如果未安装)
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker pi
```

### 2. 版本管理

```bash
# 给镜像打标签
docker tag belt-control-rk3588:runtime belt-control-rk3588:v1.0.0

# 保存特定版本
docker save belt-control-rk3588:v1.0.0 -o belt-control-v1.0.0.tar
```

### 3. 回滚操作

```bash
# 加载旧版本镜像
docker load -i belt-control-v1.0.0.tar

# 停止当前容器
docker stop belt_control
docker rm belt_control

# 启动旧版本
docker run -d --name belt_control ... belt-control-rk3588:v1.0.0
```

### 4. 批量执行命令

创建 `batch-command.ps1`:
```powershell
$DeviceList = @("192.168.10.170", "192.168.10.171", "192.168.10.172")
$Command = "docker ps | grep belt_control"

foreach ($device in $DeviceList) {
    Write-Host "Device: $device" -ForegroundColor Cyan
    ssh pi@$device $Command
    Write-Host ""
}
```
