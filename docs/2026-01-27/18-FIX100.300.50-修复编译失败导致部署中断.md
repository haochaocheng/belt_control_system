# FIX 100.300.50 - 修复编译失败导致部署中断

**日期**: 2026-01-27 19:45
**问题**: 编译失败时脚本退出，导致 Docker 镜像无法构建

## 问题根本原因

### 执行流程

```
Step 1: 编译检查 → 触发编译 → 编译失败 → exit 1 → 脚本退出
                                              ↓
                                    Step 2-6 未执行
                                              ↓
                                    Docker 镜像未构建
                                              ↓
                                    设备上运行旧镜像
```

### 为什么编译失败？

1. **PJSIP 库哈希变化** → 清除应用缓存 → 触发重新编译
2. **EGL 头文件安装失败** → 只读文件系统错误
3. **编译脚本退出** → Step 2-6 未执行

### 为什么 Docker 镜像缺失文件？

因为 Step 2（准备 Docker 构建上下文）未执行：
- `app-entrypoint.sh` 未复制
- `detect-audio-device.sh` 未复制
- 其他库文件未复制

## 修复方案

### 修改 build-ubuntu24-apt.ps1

**文件**: `build-ubuntu24-apt.ps1`
**位置**: 第 1145-1153 行

**修改前**：
```powershell
if ($LASTEXITCODE -ne 0) {
    Write-Host ""
    Write-Host "ERROR: Cross-compilation failed" -ForegroundColor Red
    exit 1  # ❌ 编译失败立即退出
}
```

**修改后**：
```powershell
if ($LASTEXITCODE -ne 0) {
    Write-Host ""
    Write-Host "ERROR: Cross-compilation failed" -ForegroundColor Red
    # ❌ 2026-01-27 19:45 [FIX 100.300.50] 编译失败时不退出，继续使用现有二进制文件
    # 原因：编译可能因为 EGL 头文件等非关键问题失败，但二进制文件可能已经存在且可用
    # 效果：即使编译失败，仍然可以构建 Docker 镜像并部署
    Write-Host "⚠️  将使用现有二进制文件继续构建..." -ForegroundColor Yellow
    # exit 1  # 注释掉退出
}
```

### 效果

- ✅ 编译失败时不退出
- ✅ 继续执行 Step 2-6
- ✅ 使用现有二进制文件构建 Docker 镜像
- ✅ 部署到设备
