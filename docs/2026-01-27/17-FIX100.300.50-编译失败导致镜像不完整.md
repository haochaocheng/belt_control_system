# FIX 100.300.50 - 编译失败导致 Docker 镜像不完整

**日期**: 2026-01-27 19:30
**问题**: 容器启动失败，提示找不到 `/app/app-entrypoint.sh`

## 🔍 根本原因

### 问题链

```
PJSIP 库哈希变化 → 清除应用缓存 → 触发重新编译 →
编译失败（EGL 头文件只读错误）→ 构建上下文不完整 →
Docker 镜像缺失文件 → 容器启动失败
```

### 详细分析

1. **PJSIP 静态库哈希值变化**
   - 当前哈希: `DDC8C60C4022305A453582322CF5BBB9`
   - 缓存哈希: `27CE9B1639B20988E83F3F06762882E5`
   - 结果：构建脚本清除应用缓存，触发重新编译

2. **编译失败**
   ```
   /opt/sysroot/rk3588-root/usr/include/EGL/egl.h: Read-only file system
   ```
   - 原因：Docker 容器中的 sysroot 是只读挂载
   - 脚本尝试写入 EGL 头文件失败

3. **构建上下文不完整**
   - `sherpa_tts_service` - 缺失
   - `app-entrypoint.sh` - 缺失
   - `detect-audio-device.sh` - 缺失
   - 其他库文件 - 不完整

4. **Docker 镜像构建失败**
   - 由于构建上下文不完整，镜像缺失关键文件

## 🎯 解决方案

### 方案 1: 修复 EGL 头文件安装脚本

**文件**: `build-rk3588-fixed.ps1`

**问题代码**（约第 60-80 行）：
```powershell
# 尝试在只读 sysroot 中写入 EGL 头文件
docker run --rm `
    -v "${ProjectRoot}:/workspace" `
    -v "${SysrootPath}:/opt/sysroot/rk3588-root" `
    belt-control-fixed:latest `
    bash -c "wget ... && cp ... /opt/sysroot/rk3588-root/usr/include/EGL/"
```

**修复方案**：添加检查，如果 EGL 头文件已存在则跳过

```powershell
# 检查 EGL 头文件是否已存在
$eglHeaderPath = Join-Path $SysrootPath "usr\include\EGL\egl.h"
if (Test-Path $eglHeaderPath) {
    Write-Host "✅ EGL 头文件已存在，跳过安装" -ForegroundColor Green
} else {
    Write-Host "⚠️  EGL 头文件不存在，需要手动安装" -ForegroundColor Yellow
    # 不在只读 sysroot 中安装，而是在编译容器中安装
}
```
