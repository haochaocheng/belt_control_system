# FIX 100.300.50 - Docker 镜像缺失启动脚本

**日期**: 2026-01-27 19:15
**问题**: 容器启动失败，提示找不到 `/app/app-entrypoint.sh`

## 问题描述

设备上运行容器时出现错误：

```
exec /app/app-entrypoint.sh: no such file or directory
Application exited with code: 255
```

## 根本原因

**Docker 镜像是旧的**，不包含 `app-entrypoint.sh` 文件。

### 为什么会这样？

1. **从 J 盘恢复源码后**，本地文件已更新
2. **但 Docker 镜像没有重新构建**
3. 设备上运行的是旧镜像（不包含启动脚本）

## 技术要点

### 1. Docker 镜像构建流程

```
源码文件 → Docker 构建上下文 → Docker 镜像 → 设备
```

**关键点**：
- Docker 构建上下文是临时目录（`docker_build_context/`）
- 构建脚本会复制所需文件到这个目录
- Docker 从这个目录构建镜像
- 如果源文件更新，必须重新构建镜像

### 2. Dockerfile COPY 指令

```dockerfile
COPY app-entrypoint.sh /app/app-entrypoint.sh
```

**工作原理**：
- 从 Docker 构建上下文复制文件
- 不是从项目根目录复制
- 如果构建上下文中没有文件，COPY 会失败

### 3. 构建脚本的文件复制

**文件**: `build-ubuntu24-apt.ps1`

**关键代码**（第 1439-1440 行）：
```powershell
Copy-Item "$ProjectRoot\docker\rk3588\detect-audio-device.sh" "$DockerContextDir\detect-audio-device.sh" -Force
Copy-Item "$ProjectRoot\docker\rk3588\app-entrypoint.sh" "$DockerContextDir\app-entrypoint.sh" -Force
```

**说明**：
- 这两行代码将启动脚本复制到 Docker 构建上下文
- 如果这两行没有执行，镜像中就不会有启动脚本

### 4. 为什么设备上的镜像是旧的？

**可能原因**：
1. **编译失败**：从 J 盘恢复源码后，编译可能失败了
2. **未重新部署**：即使编译成功，可能没有部署到设备
3. **缓存问题**：Docker 使用了缓存的旧镜像

**解决**：
- 重新运行完整的编译和部署流程
- 确保编译成功
- 确保镜像已传输到设备
