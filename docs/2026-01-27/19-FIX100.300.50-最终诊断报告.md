## 💡 可能的原因

### 原因 1: 文件权限问题

**可能性**：文件被复制但没有执行权限

**验证方法**：
```bash
ssh pi@192.168.1.8 "docker run --rm --entrypoint sh belt-control:v3.5-apt -c 'ls -la /app/app-entrypoint.sh'"
```

### 原因 2: 文件格式问题

**可能性**：文件是 Windows 格式（CRLF），Linux 无法执行

**验证方法**：
```bash
file docker/rk3588/app-entrypoint.sh
```

**修复方法**：
```bash
dos2unix docker/rk3588/app-entrypoint.sh
```

### 原因 3: Shebang 问题

**可能性**：文件的 shebang 行不正确

**检查**：
```bash
head -1 docker/rk3588/app-entrypoint.sh
```

**应该是**：
```bash
#!/bin/bash
```

### 原因 4: Docker 缓存问题

**可能性**：即使使用 `--no-cache`，某些层仍然被缓存

**修复方法**：
```bash
# 删除所有相关镜像
docker rmi belt-control:v3.5-apt
docker rmi belt-control-base:ubuntu24

# 重新构建基础镜像
docker build --platform linux/arm64 --no-cache -f Dockerfile.ubuntu24-base -t belt-control-base:ubuntu24 .

# 重新构建应用镜像
cd docker_build_context
docker build --platform linux/arm64 --no-cache -t belt-control:v3.5-apt .
```

### 原因 5: 文件实际上不存在

**可能性**：COPY 命令失败但没有报错

**验证方法**：
```bash
# 在本地检查文件是否存在
ls -la docker_build_context/app-entrypoint.sh

# 检查文件内容
cat docker_build_context/app-entrypoint.sh
```
