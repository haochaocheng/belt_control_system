## 根本原因

### 1. Git 操作导致文件回退

**触发事件**：用户执行了 `.\push-commits-one-by-one.ps1` 脚本

**问题代码**（第 49 行）：
```powershell
git reset --hard origin/feature/hardware-video-codec
```

**影响**：
- 这个命令在每次循环中强制重置工作目录到远程分支状态
- 如果远程分支落后于本地，会导致本地修改丢失
- 即使后续 `git cherry-pick` 恢复了部分提交，某些文件可能未被完全恢复

### 2. 文件版本不一致

**证据**：
- 备份文件（J:\belt_control_system）包含完整的函数声明
- 当前工作目录文件缺失这些声明
- 备份文件的修改日期更新（包含 FIX 100.252.3、FIX 100.249 v3 等）

**推测**：
- 备份是在执行 `push-commits-one-by-one.ps1` 之前创建的
- 脚本执行后，某些提交未被正确 cherry-pick
- 导致头文件回退到旧版本

### 3. 远程分支状态

需要检查：
- 远程分支 `origin/feature/hardware-video-codec` 是否包含这些声明
- 本地是否有未推送的提交
- 是否存在提交丢失

## 预防措施

### 1. 禁用 push-commits-one-by-one.ps1

**问题脚本**：`push-commits-one-by-one.ps1`

**危险操作**：
```powershell
# Line 49: 强制重置工作目录
git reset --hard origin/feature/hardware-video-codec
```

**建议**：
- ❌ 不再使用此脚本
- ✅ 使用标准 `git push` 推送所有提交
- ✅ 如需逐个推送，使用 `git push origin <commit-hash>:feature/hardware-video-codec`

### 2. 定期备份

```powershell
# 每天工作结束前备份
$backupDir = "J:\belt_control_system_backup_$(Get-Date -Format 'yyyy-MM-dd')"

```

### 3. 使用 Git Stash

```powershell
# 推送前保存工作状态
git stash push -m "工作进度保存"

# 推送提交
git push origin feature/hardware-video-codec

# 恢复工作状态
git stash pop
```

## 技术要点

1. **Git Reset --hard 的危险性**：
   - 会丢弃所有未提交的修改
   - 会强制覆盖工作目录文件
   - 无法撤销（除非使用 reflog）

2. **Cherry-pick 的局限性**：
   - 只恢复指定的提交
   - 不会恢复未提交的修改
   - 可能遗漏某些文件

3. **文件版本管理**：
   - 重要修改应立即提交
   - 定期推送到远程仓库
   - 保持本地和远程同步
