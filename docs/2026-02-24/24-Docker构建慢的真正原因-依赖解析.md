## 二、真正的瓶颈分析

### 2.1 依赖解析（最大瓶颈）

**pip install 的实际过程**：
```
1. 读取 requirements.txt
2. 解析每个包的依赖关系
3. 构建依赖树
4. 检查版本冲突
5. 下载包
6. 安装包
```

**关键问题**：
- PaddleSpeech 有 **100+ 个依赖**
- 每个依赖又有自己的依赖（递归）
- 总依赖数：**300-500 个包**
- 依赖解析是**串行**的，无法并行

**时间分配**：
```
依赖解析: 60-90 分钟 ⭐⭐⭐⭐⭐ (最大瓶颈)
下载: 5-10 分钟
安装: 40-60 分钟 ⭐⭐⭐⭐
```

### 2.2 QEMU 模拟慢（第二瓶颈）

**影响的操作**：
```
1. 依赖解析（Python 代码执行）: 慢 10-20 倍 ⭐⭐⭐⭐⭐
2. 编译 .pyc 字节码: 慢 10-20 倍 ⭐⭐⭐⭐
3. 文件 I/O（解压、复制）: 慢 2-3 倍 ⭐⭐
4. 网络 I/O（下载）: 影响小 ⭐
```

**为什么依赖解析这么慢？**：
- pip 需要执行大量 Python 代码
- 读取每个包的 metadata
- 解析版本约束
- 构建依赖图
- 所有这些都在 QEMU 模拟下运行

**实际影响**：
```
原生 ARM64: 依赖解析 5-10 分钟
QEMU 模拟: 依赖解析 60-90 分钟 (慢 10-15 倍)
```

## 五、为什么依赖解析这么慢？

### 5.1 pip 的依赖解析算法

**pip 的工作流程**：
```python
# 伪代码
def resolve_dependencies(package):
    # 1. 下载包的 metadata
    metadata = download_metadata(package)

    # 2. 解析依赖列表
    deps = parse_dependencies(metadata)

    # 3. 递归解析每个依赖
    for dep in deps:
        resolve_dependencies(dep)  # 递归

    # 4. 检查版本冲突
    check_conflicts()

    # 5. 构建安装顺序
    build_install_order()
```

**问题**：
- 每个包都要下载 metadata
- 递归解析（深度优先）
- 版本冲突检查（回溯）
- 所有操作都是串行的

### 5.2 QEMU 的影响

**Python 代码执行**：
```
原生 ARM64: 1000 次函数调用/秒
QEMU 模拟: 50-100 次函数调用/秒 (慢 10-20 倍)
```

**依赖解析需要**：
- 数百万次函数调用
- 大量字符串操作
- 文件 I/O
- JSON 解析

**结果**：
- 原生：5-10 分钟
- QEMU：60-90 分钟
