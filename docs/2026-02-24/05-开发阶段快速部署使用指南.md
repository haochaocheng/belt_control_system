## 二、使用场景


## 三、命令参数说明

### 3.1 基本语法

```powershell
.\scripts\2026-02-24\02-quick-deploy.ps1 <设备> [-Type <类型>]
```

### 3.2 参数说明

| 参数 | 说明 | 可选值 | 默认值 |
|------|------|--------|--------|
| `<设备>` | 目标设备 IP 或编号 | `185`, `188`, `192.168.10.x` | `185` |
| `-Type` | 部署类型 | `auto`, `cpp`, `qml`, `python`, `all` | `auto` |

### 3.3 部署类型说明

| 类型 | 说明 | 适用场景 | 耗时 |
|------|------|---------|------|
| `auto` | 自动检测（推荐） | 自动识别最近修改的文件类型 | 根据检测结果 |
| `cpp` | 仅编译 C++ | 只修改了 C++ 源码 | 5-8 分钟 |
| `qml` | 仅复制 QML | 只修改了 QML 界面 | 30 秒 |
| `python` | 仅复制 Python | 只修改了 Python 脚本 | 1-2 分钟 |
| `all` | 全量更新 | 修改了多种文件 | 8-10 分钟 |

## 四、工作原理

### 4.1 自动检测机制

脚本会检查最近 30 分钟内修改的文件：

```powershell
# 检测 C++ 文件
Get-ChildItem -Path "src" -Recurse -Include *.cpp,*.h |
    Where-Object { $_.LastWriteTime -gt (Get-Date).AddMinutes(-30) }

# 检测 QML 文件
Get-ChildItem -Path "src/qml" -Recurse -Include *.qml |
    Where-Object { $_.LastWriteTime -gt (Get-Date).AddMinutes(-30) }

# 检测 Python 文件
Get-ChildItem -Path "docker/rk3588/tts_engines" -Recurse -Include *.py |
    Where-Object { $_.LastWriteTime -gt (Get-Date).AddMinutes(-30) }
```

### 4.2 部署流程

```
[1/6] 检测修改类型
      ├─ 扫描最近修改的文件
      └─ 自动选择部署方案

[2/6] 检查设备连接
      └─ Ping 测试设备可达性

[3/6] 检查容器状态
      └─ 确认容器正在运行

[4/6] 交叉编译应用程序（如需要）
      ├─ 使用交叉编译容器
      └─ 生成 ARM64 二进制文件

[5/6] 复制文件到设备
      ├─ 创建临时目录
      ├─ 上传文件
      └─ 复制到容器内

[6/6] 重启服务
      ├─ 重启应用进程（QML/Python）
      └─ 重启容器（C++）
```

## 五、常见问题

**错误信息**：
```

```

### 5.2 交叉编译容器不存在

**错误信息**：
```
❌ 交叉编译容器不存在: belt-control-cross-compiler:latest
```

**解决方案**：
```powershell

```

---

### 5.3 设备连接失败

**错误信息**：
```
❌ 无法连接到设备 192.168.10.185
```

**解决方案**：
1. 检查设备是否开机
2. 检查网络连接
3. 检查 IP 地址是否正确
4. 尝试手动 SSH 连接：`ssh linaro@192.168.10.185`

---

### 5.4 文件复制失败

**错误信息**：
```
❌ 复制文件失败
```

**解决方案**：
1. 检查 SSH 密钥配置
2. 检查设备磁盘空间：`ssh linaro@192.168.10.185 "df -h"`
3. 检查文件权限

## 八、故障排查

### 8.1 部署失败

**步骤**：
1. 检查错误信息
2. 查看容器日志：`ssh linaro@192.168.10.185 "docker logs belt-control-app"`
3. 检查容器状态：`ssh linaro@192.168.10.185 "docker ps -a"`
4. 尝试重启容器：`ssh linaro@192.168.10.185 "docker restart belt-control-app"`

### 8.2 应用崩溃

**步骤**：
1. 查看崩溃日志：`ssh linaro@192.168.10.185 "docker logs belt-control-app | tail -100"`
2. 检查 Core Dump：`ssh linaro@192.168.10.185 "ls -lh /tmp/core.*"`
3. 使用 GDB 调试：`.\scripts\2026-01-09\07-analyze-core-dump.ps1 185`

### 8.3 依赖库缺失

**步骤**：
1. 检查库依赖：`ssh linaro@192.168.10.185 "docker exec belt-control-app ldd /app/bin/belt_control_system"`
2. 查找缺失库：`ssh linaro@192.168.10.185 "docker exec belt-control-app ldd /app/bin/belt_control_system | grep 'not found'"`
3. 使用完整构建重新部署：`.\build-ubuntu24-apt.ps1 185`
