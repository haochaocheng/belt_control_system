## 一、完整构建流程分析

### 1.1 `build-ubuntu24-apt.ps1` 完整步骤

```
[Step -1] 检测 PJSIP 源码变化 → 重新编译 PJSIP 静态库（如需要）
          ├─ 比较源码和库文件时间戳
          └─ Docker 编译 PJSIP（约 15-20 分钟）

[Step -0.5] 监控 PJSIP 静态库哈希 → 清除应用缓存（如库更新）
            └─ 强制重新链接

[Step 1] 交叉编译应用程序
         ├─ CMake 配置
         ├─ 编译 C++ 源码
         ├─ 链接 PJSIP 静态库
         └─ 生成二进制文件（约 5-10 分钟）

[Step 2] 构建基础 Docker 镜像（ubuntu24-base）
         ├─ 安装系统依赖
         ├─ 安装 Python 依赖
         └─ 安装 TTS 引擎（约 10-15 分钟）

[Step 3] 构建运行时 Docker 镜像（ubuntu24-runtime）
         ├─ 复制二进制文件
         ├─ 复制 QML 文件
         ├─ 复制配置文件
         └─ 设置环境变量（约 1-2 分钟）

[Step 4] 保存 Docker 镜像为 tar.gz
         └─ 压缩镜像（约 2-3 分钟）

[Step 5] 上传镜像到设备
         └─ SCP 传输（约 3-5 分钟）

[Step 6] 在设备上加载并运行
         ├─ 解压镜像
         ├─ 加载到 Docker
         ├─ 停止旧容器
         └─ 启动新容器（约 2-3 分钟）
```

**总耗时**: 约 30-40 分钟

## 二、开发阶段可省略的步骤

### 2.1 不同修改类型的部署需求

| 修改类型 | 需要重新编译 | 需要重新构建镜像 | 需要重启容器 | 最快方案 |
|---------|------------|----------------|------------|---------|
| **QML 文件修改** | ❌ | ❌ | ❌ | 直接复制到容器 |
| **C++ 源码修改** | ✅ | ❌ | ✅ | 编译+复制二进制 |
| **PJSIP 源码修改** | ✅ | ❌ | ✅ | 重新编译+复制 |
| **Python TTS 脚本** | ❌ | ❌ | ✅ | 直接复制+重启服务 |
| **配置文件修改** | ❌ | ❌ | ✅ | 直接复制+重启容器 |
| **系统依赖变化** | ✅ | ✅ | ✅ | 完整构建 |

### 2.2 可省略步骤（90% 开发场景）

**前提条件**：
- ✅ 设备上已有基础镜像（ubuntu24-base）
- ✅ 设备上 Docker 容器常驻运行
- ✅ 只修改应用代码（C++/QML/Python）

**可省略**：
- ❌ Step -1: PJSIP 重新编译（除非修改 PJSIP 源码）
- ❌ Step 2: 基础镜像构建（系统依赖不变）
- ❌ Step 3: 运行时镜像构建（直接复制文件到容器）
- ❌ Step 4: 镜像打包（不需要镜像）
- ❌ Step 5: 镜像上传（不需要镜像）
- ❌ Step 6: 镜像加载（不需要镜像）

**保留**：
- ✅ Step 1: 交叉编译应用程序（如修改 C++ 代码）
- ✅ 直接复制文件到运行中的容器
- ✅ 重启容器或服务

## 三、快速部署方案

### 3.1 方案一：QML 文件修改（最快，30秒）

**适用场景**：只修改 QML 界面文件

**步骤**：
```powershell
# 1. 直接复制 QML 文件到容器
scp -r src/qml/* linaro@192.168.10.185:/home/linaro/belt-control-app/qml/

# 2. 重启应用（容器内）
ssh linaro@192.168.10.185 "docker exec belt-control-app pkill -f belt_control_system"
```

**耗时**: 约 30 秒

---

### 3.2 方案二：C++ 代码修改（快速，5-8分钟）

**适用场景**：修改 C++ 源码，不涉及 PJSIP 库

**步骤**：
```powershell
# 1. 交叉编译应用程序（本地 Windows）
docker run --rm -v ${PWD}:/workspace -w /workspace \
  belt-control-cross-compiler:latest \
  bash -c "cd build_rk3588 && cmake .. && make -j8"

# 2. 复制二进制文件到设备
scp build_rk3588/bin_arm64/belt_control_system \
  linaro@192.168.10.185:/home/linaro/belt-control-app/bin/

# 3. 重启容器
ssh linaro@192.168.10.185 "docker restart belt-control-app"
```

**耗时**: 约 5-8 分钟（编译 5 分钟 + 传输 1 分钟 + 重启 30 秒）

---

### 3.3 方案三：Python TTS 脚本修改（快速，1分钟）

**适用场景**：修改 TTS 服务脚本

**步骤**：
```powershell
# 1. 复制 Python 脚本到容器
scp docker/rk3588/tts_engines/paddlespeech/*.py \
  linaro@192.168.10.185:/home/linaro/belt-control-app/tts_engines/paddlespeech/

# 2. 重启 TTS 服务（容器内）
ssh linaro@192.168.10.185 "docker exec belt-control-app supervisorctl restart paddle_tts"
```

**耗时**: 约 1 分钟

---

### 3.4 方案四：混合修改（中等，8-10分钟）

**适用场景**：同时修改 C++、QML、Python

**步骤**：
```powershell
# 1. 交叉编译应用程序
docker run --rm -v ${PWD}:/workspace -w /workspace \
  belt-control-cross-compiler:latest \
  bash -c "cd build_rk3588 && cmake .. && make -j8"

# 2. 批量复制所有文件
scp build_rk3588/bin_arm64/belt_control_system \
  linaro@192.168.10.185:/home/linaro/belt-control-app/bin/

scp -r src/qml/* \
  linaro@192.168.10.185:/home/linaro/belt-control-app/qml/

scp docker/rk3588/tts_engines/paddlespeech/*.py \
  linaro@192.168.10.185:/home/linaro/belt-control-app/tts_engines/paddlespeech/

# 3. 重启容器
ssh linaro@192.168.10.185 "docker restart belt-control-app"
```

**耗时**: 约 8-10 分钟

## 四、容器常驻运行方案

### 4.1 容器目录结构

设备上容器内的目录结构：

```
/app/                                    # 应用根目录
├── bin/
│   └── belt_control_system              # 二进制文件（可热更新）
├── qml/                                 # QML 文件（可热更新）
│   ├── main.qml
│   ├── pages/
│   └── components/
├── tts_engines/                         # TTS 引擎（可热更新）
│   ├── paddlespeech/
│   │   ├── paddle_tts_service.py
│   │   └── requirements.txt
│   └── melotts/
├── lib/                                 # 运行时库（不可热更新）
│   ├── libpjsua2.so
│   └── ...
└── config/                              # 配置文件（可热更新）
    └── pjsip_config_site.h
```

### 4.2 容器挂载方案

**方案 A：直接挂载宿主机目录（推荐开发阶段）**

```bash
docker run -d \
  --name belt-control-app \
  -v /home/linaro/belt-control-app/bin:/app/bin \
  -v /home/linaro/belt-control-app/qml:/app/qml \
  -v /home/linaro/belt-control-app/tts_engines:/app/tts_engines \
  belt-control-ubuntu24-runtime:latest
```

**优点**：
- ✅ 修改文件后无需复制到容器
- ✅ 直接在宿主机修改，容器内立即生效
- ✅ 重启容器即可加载新文件

**缺点**：
- ❌ 需要提前在宿主机准备好目录结构

---

**方案 B：复制文件到容器（推荐生产阶段）**

```bash
docker run -d \
  --name belt-control-app \
  belt-control-ubuntu24-runtime:latest
```

**优点**：
- ✅ 容器独立，不依赖宿主机目录
- ✅ 适合生产环境

**缺点**：
- ❌ 每次修改需要复制文件到容器

## 五、快速部署脚本

### 5.1 脚本功能

创建 `quick-deploy.ps1` 脚本，支持：

1. **自动检测修改类型**（C++/QML/Python）
2. **智能选择部署方案**（编译/复制/重启）
3. **并行传输文件**（加速部署）
4. **自动重启服务**（无需手动操作）

### 5.2 使用方法

```powershell
# 快速部署到设备 185
.\quick-deploy.ps1 185

# 指定修改类型
.\quick-deploy.ps1 185 -Type cpp      # 只编译 C++ 代码
.\quick-deploy.ps1 185 -Type qml      # 只复制 QML 文件
.\quick-deploy.ps1 185 -Type python   # 只复制 Python 脚本
.\quick-deploy.ps1 185 -Type all      # 全部更新
```

## 六、依赖库完整性保证

### 6.1 运行时库检查

**问题**：如何确保容器内有所有必需的库？

**解决方案**：

1. **基础镜像包含所有系统库**
   - PJSIP 运行时库（`libpjsua2.so`）
   - FFmpeg 库（`libavcodec.so`、`libavformat.so`）
   - Qt 库（`libQt6Core.so`、`libQt6Qml.so`）
   - 音频库（`libasound.so`、`libopus.so`）

2. **应用二进制静态链接 PJSIP**
   - PJSIP 静态库（`.a` 文件）已链接到二进制
   - 无需在容器内提供 PJSIP 静态库

3. **Python 依赖在基础镜像中**
   - PaddleSpeech、MeloTTS 已安装
   - 无需每次重新安装

### 6.2 库依赖检查命令

```bash
# 检查二进制文件依赖
ssh linaro@192.168.10.185 \
  "docker exec belt-control-app ldd /app/bin/belt_control_system"

# 检查缺失的库
ssh linaro@192.168.10.185 \
  "docker exec belt-control-app ldd /app/bin/belt_control_system | grep 'not found'"
```

## 八、注意事项

### 8.1 何时需要完整构建

以下情况必须使用完整构建流程：

1. **系统依赖变化**
   - 添加新的 apt 包
   - 修改 Dockerfile.ubuntu24-base

2. **PJSIP 库更新**
   - 修改 PJSIP 源码
   - 更新 PJSIP 版本

3. **Python 依赖变化**
   - 添加新的 pip 包
   - 修改 requirements.txt

4. **新设备部署**
   - 首次部署到新设备
   - 设备上没有基础镜像

### 8.2 快速部署的前提条件

1. ✅ 设备上已有基础镜像（`belt-control-ubuntu24-base:latest`）
2. ✅ 设备上容器常驻运行（`belt-control-app`）
3. ✅ 只修改应用层代码（C++/QML/Python）
4. ✅ 系统依赖和 PJSIP 库未变化
