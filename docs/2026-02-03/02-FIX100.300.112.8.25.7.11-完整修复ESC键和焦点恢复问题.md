## 🔍 问题分析

### 问题1分析：ESC键事件传递

**根本原因**：
- InputPanel的Shortcut确实被触发（日志显示"ESC键被按下"）
- 但Shortcut没有完全消费掉ESC事件
- 事件继续传递到DeviceSettingsDialog的`Keys.onEscapePressed`
- 导致对话框也关闭

**Qt事件传递机制**：
```
ESC键按下
  ↓
InputPanel Shortcut 触发（调用 Qt.inputMethod.hide()）
  ↓
事件继续传递（Shortcut没有阻止）
  ↓
DeviceSettingsDialog Keys.onEscapePressed 触发
  ↓
对话框关闭 ❌
```

**解决方案**：
在DeviceSettingsDialog的`Keys.onEscapePressed`中添加条件判断：
- 如果`Qt.inputMethod.visible`为true，说明虚拟键盘激活中
- 直接return，不关闭对话框
- 让InputPanel的Shortcut处理ESC键

### 问题2分析：焦点恢复

**根本原因**：
- 虚拟键盘关闭时，焦点仍然在CustomSpinBox的TextInput上
- Qt.inputMethod.hide()只是隐藏虚拟键盘，不会自动恢复焦点
- 导航系统需要焦点在父容器上才能正常工作

**焦点状态**：
```
虚拟键盘打开前：
  焦点在 CurrentProtectionTab（参数区域）
  ↓
按回车键 → 调用 activateVirtualKeyboard()
  ↓
焦点转移到 TextInput
  ↓
虚拟键盘显示
  ↓
按ESC键 → Qt.inputMethod.hide()
  ↓
虚拟键盘关闭，但焦点仍在 TextInput ❌
  ↓
按上下键 → TextInput接收事件，增加减少数字
```

**解决方案**：
在CustomSpinBox中添加Connections监听`Qt.inputMethod.visible`变化：
- 当虚拟键盘关闭（visible变为false）且TextInput有焦点时
- 主动恢复焦点到父容器（参数区域）
- 这样导航系统就能正常工作

### 2. 修复焦点恢复问题

**修改文件**: `src/qml/components/device_info/CustomSpinBox.qml`

**修改位置**: Line 125-155

**问题发现**：
- 第一次修复后，焦点恢复到了`QQuickGridLayout`，而不是`CurrentProtectionTab`
- 日志显示：`焦点已恢复到: QQuickGridLayout(0x23a1d4a0f20)`
- 原因：`root.parent.parent`指向GridLayout，不是Tab

**组件层级结构**：
```
CurrentProtectionTab (root, 有 focusParamIndex 属性)
  ↓
ScrollView
  ↓
GridLayout
  ↓
Item (容器)
  ↓
CustomSpinBox (root)
```

**修改内容**：
```qml
// ✅ 2026-02-03 [FIX 100.300.112.8.25.7.11.1]: 修复焦点恢复到GridLayout而不是Tab
Connections {
    target: Qt.inputMethod
    function onVisibleChanged() {
        if (!Qt.inputMethod.visible && textInput.activeFocus) {
            console.log("⌨️ [CustomSpinBox] 虚拟键盘关闭，恢复焦点到父容器")
            // 恢复焦点到参数区域（Tab），而不是GridLayout
            // 组件层级：CustomSpinBox → Item → GridLayout → ScrollView → Tab
            // 需要向上找到Tab（通常是4-5层）
            var container = root.parent
            var depth = 0
            while (container && depth < 10) {
                console.log("   - 层级", depth, ":", container)
                // 查找包含 focusParamIndex 属性的容器（通常是Tab）
                if (container.hasOwnProperty("focusParamIndex")) {
                    console.log("   - 找到参数区域容器，恢复焦点")
                    container.forceActiveFocus()
                    return
                }
                container = container.parent
                depth++
            }
            console.log("⚠️ [CustomSpinBox] 未找到参数区域容器，使用默认恢复")
            // 如果没找到，使用默认的parent.parent
            if (root.parent && root.parent.parent) {
                root.parent.parent.forceActiveFocus()
            }
        }
    }
}
```

**工作原理**：
1. 监听`Qt.inputMethod.visible`变化
2. 当虚拟键盘关闭（visible变为false）
3. 且TextInput有焦点（textInput.activeFocus为true）
4. **向上遍历父容器**，查找包含`focusParamIndex`属性的容器
5. 找到后调用`forceActiveFocus()`恢复焦点
6. 如果没找到（最多遍历10层），使用默认的`parent.parent`

**为什么使用hasOwnProperty("focusParamIndex")？**
- 所有Tab（BasicConfigTab、CurrentProtectionTab等）都有`focusParamIndex`属性
- 这是导航系统的标志属性
- 通过这个属性可以准确找到参数区域容器

## 💡 关键知识点

### 1. Qt事件传递顺序

**Shortcut vs Keys.onEscapePressed**：
- Shortcut优先级高于Keys事件
- 但Shortcut不会自动阻止事件传递
- 需要在父组件中添加条件判断

**正确做法**：
```qml
// 子组件（InputPanel）
Shortcut {
    enabled: virtualKeyboard.active
    sequence: "Esc"
    onActivated: {
        Qt.inputMethod.hide()
    }
}

// 父组件（DeviceSettingsDialog）
Keys.onEscapePressed: {
    if (Qt.inputMethod.visible) {
        return  // 让子组件处理
    }
    // 父组件的处理逻辑
}
```

### 2. Qt.inputMethod.visible vs InputPanel.active

**Qt.inputMethod.visible**：
- Qt输入法系统的状态
- 虚拟键盘显示时为true
- 虚拟键盘关闭时为false

**InputPanel.active**：
- InputPanel组件的状态
- 绑定到Qt.inputMethod.visible
- 用于控制InputPanel的显示/隐藏动画

**使用场景**：
- 检查虚拟键盘是否激活：使用`Qt.inputMethod.visible`
- 控制InputPanel动画：使用`InputPanel.active`

### 3. 焦点恢复机制

**Qt官方InputPanel**：
- 关闭时不会自动恢复焦点
- 需要手动处理焦点恢复

**正确做法**：
```qml
Connections {
    target: Qt.inputMethod
    function onVisibleChanged() {
        if (!Qt.inputMethod.visible && textInput.activeFocus) {
            // 恢复焦点到父容器
            root.parent.parent.forceActiveFocus()
        }
    }
}
```

### 4. 为什么不在CurrentProtectionTab中处理焦点恢复？

**原因**：
- CustomSpinBox是可复用组件
- 焦点恢复逻辑应该在组件内部处理
- 这样所有使用CustomSpinBox的地方都能自动获得焦点恢复功能

**好处**：
- 代码复用性高
- 维护成本低
- 行为一致性好
