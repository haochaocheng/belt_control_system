## 🔍 根本原因分析

### 问题1：InputPanel绑定方式错误

**之前的实现**：
```qml
InputPanel {
    visible: Qt.inputMethod.visible  // ❌ 错误
}
```

**Qt官方示例**：
```qml
InputPanel {
    states: State {
        name: "visible"
        when: inputPanel.active  // ✅ 正确
    }
}
```

**原因**：
- `Qt.inputMethod.visible`是只读属性，由Qt输入法系统自动管理
- **鼠标点击**会触发Qt.inputMethod，但**键盘导航**不会
- Qt官方示例使用`inputPanel.active`，这是InputPanel自己的属性

### 问题2：键盘导航不会自动触发Qt.inputMethod

**鼠标点击流程**：
1. 用户点击TextField
2. TextField接收点击事件
3. Qt.inputMethod自动触发
4. InputPanel自动显示

**键盘导航流程**：
1. 用户按回车键
2. 调用`textInput.forceActiveFocus()`
3. TextInput获得焦点
4. ❌ Qt.inputMethod**不会**自动触发
5. ❌ InputPanel不显示

**解决方案**：
- 手动调用`Qt.inputMethod.show()`

## 💡 关键知识点

### 1. inputPanel.active vs Qt.inputMethod.visible

**inputPanel.active**：
- ✅ InputPanel自己的属性
- ✅ 会自动管理（鼠标点击时）
- ✅ 可以手动触发（调用Qt.inputMethod.show()）
- ✅ Qt官方推荐方式

**Qt.inputMethod.visible**：
- ❌ 只读属性，不能直接设置
- ❌ 只在鼠标点击时自动变化
- ❌ 键盘导航不会自动变化
- ❌ 不是Qt官方推荐方式

### 2. 鼠标点击 vs 键盘导航

**鼠标点击**：
- Qt自动触发Qt.inputMethod
- InputPanel.active自动变为true
- 不需要手动调用show()

**键盘导航**：
- Qt不会自动触发Qt.inputMethod
- 需要手动调用`Qt.inputMethod.show()`
- InputPanel.active才会变为true

### 3. Qt官方示例的设计思路

**为什么使用inputPanel.active？**
1. 更灵活：可以手动控制
2. 更可靠：不依赖Qt.inputMethod的自动触发
3. 更通用：支持鼠标和键盘两种方式

**为什么使用State和Transition？**
1. 动画效果：虚拟键盘滑入/滑出
2. 状态管理：清晰的显示/隐藏状态
3. 可扩展：可以添加更多状态和动画

## 📦 总结

### 问题根本原因

1. **InputPanel绑定方式错误**：
   - 使用`Qt.inputMethod.visible`（只读，键盘导航不会触发）
   - 应该使用`inputPanel.active`（Qt官方方式）

2. **键盘导航不会自动触发Qt.inputMethod**：
   - 鼠标点击会自动触发
   - 键盘导航需要手动调用`Qt.inputMethod.show()`

### 解决方案

1. **参考Qt官方示例**：
   - 使用`inputPanel.active`绑定
   - 使用State和Transition实现动画

2. **手动触发Qt.inputMethod**：
   - 在`activateVirtualKeyboard()`中调用`Qt.inputMethod.show()`
   - 这是键盘导航场景的必需操作
