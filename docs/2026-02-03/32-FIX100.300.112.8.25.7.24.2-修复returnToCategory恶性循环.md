## 🎯 问题描述

### 用户反馈

测试完成，从电机列表按左键无法将焦点移动到电机控制大类，又修复恶性循环了。

### 日志分析

```

Line -9: MotorControlPage 焦点变化: false

Line -5: NavigationManager 方向键: Left

Line -3: MotorControlPage 接收键盘事件: Left  ❌ 又接收到了！
Line -2: NavigationManager 方向键: Left
Line -1: MotorControlPage 接收到 returnToCategory 信号，释放焦点  ❌ 又释放了！
```

### 根本原因

**键盘事件队列导致的恶性循环！**

**问题流程**：
```
1. 用户按左键
2. MotorControlPage 接收键盘事件
3. 调用 NavigationManager.handleDirectionKey("Left")
4. NavigationManager 触发 returnToCategory 信号
5. MotorControlPage 释放焦点（root.focus = false）
6. ❌ 但是键盘事件还在队列中，又被 MotorControlPage 接收
7. 重复步骤 2-6，形成死循环
```

**为什么会有键盘事件队列？**
- Qt 的事件系统是异步的
- 当用户按下左键时，可能会产生多个键盘事件（keyPress, keyRelease等）
- 即使释放了焦点，队列中的事件仍然会被处理

---

## 🔧 解决方案

### 方案：添加标志位，防止重复处理

**核心思想**：
- 添加一个标志位 `isReturningToCategory`
- 当触发 `returnToCategory` 时，设置标志为 `true`
- 在键盘事件处理器中，检查标志，如果为 `true` 则忽略事件
- 当焦点丢失后，重置标志为 `false`

**用户按左键返回大类**：
```

5. NavigationManager 触发 returnToCategory 信号
6. MotorControlPage 设置 isReturningToCategory = true ✅
7. MotorControlPage 释放焦点（root.focus = false）
8. 焦点丢失，触发 onActiveFocusChanged
9. 重置 isReturningToCategory = false ✅
10. 队列中的键盘事件到达
```

**关键点**：
- 步骤 6：设置标志，防止后续事件被处理
- 步骤 9：焦点丢失后重置标志，为下次操作做准备
- 步骤 12：即使标志被重置，焦点已经不在 MotorControlPage，所以不会再触发恶性循环
