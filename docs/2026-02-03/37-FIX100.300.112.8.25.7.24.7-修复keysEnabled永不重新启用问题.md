## 🎯 问题描述

### 用户反馈

上下键也不能导航了。

### 日志分析

```

Line -28: 接收到 returnToCategory 信号，释放焦点
Line -27: DeviceSettingsDialog 接收到 requestDialogFocus 信号

Line -22 到 -1: 键盘事件已禁用，忽略键盘事件  ✅ 工作正常！
```

**关键发现**：
- `keysEnabled` 被设置为 `false` 后，所有键盘事件都被忽略
- 包括在大类列表中的上下键（应该切换类别）
- 包括重新进入电机控制后的上下键（应该切换电机）
- `keysEnabled` 永远不会被重新设置为 `true`

### 根本原因

**`keysEnabled` 重新启用的时机不对！**

在 FIX .24.6 中，我在 DeviceSettingsDialog 的 `onCurrentCategoryChanged` 中添加了重新启用的代码：

```qml
onCurrentCategoryChanged: {
    if (currentCategory === 3 && motorControlPageLoader.item) {
        motorControlPageLoader.item.keysEnabled = true
    }
}
```

**问题流程**：
```
1. 用户在电机控制页面（currentCategory = 3）
2. 用户按左键返回大类
3. keysEnabled 被设置为 false ✅
4. 焦点转移到 DeviceSettingsDialog
5. 但是 currentCategory 仍然是 3（电机控制）❌
6. onCurrentCategoryChanged 不会触发 ❌
7. keysEnabled 永远不会被重新设置为 true ❌
8. 所有键盘事件都被忽略 ❌
```

**为什么 `currentCategory` 不变？**
- 用户按左键返回大类后，只是焦点转移到了大类列表
- 但是右侧的内容区域仍然显示电机控制页面
- 所以 `currentCategory` 仍然是 3

---

## 🔧 解决方案

### 方案：在焦点恢复时重新启用 keysEnabled

**核心思想**：
- 不在 `onCurrentCategoryChanged` 中重新启用
- 在 `onActiveFocusChanged` 中，当焦点恢复时重新启用
- 这样无论用户如何操作，只要焦点回到 MotorControlPage，就会重新启用

## 📊 为什么这个方案有效？

### 焦点管理的关键

**问题的本质**：
- `keysEnabled` 被设置为 `false` 后，需要在合适的时机重新设置为 `true`
- 之前的方案依赖 `onCurrentCategoryChanged`，但这个事件不会在返回大类时触发
- 因为 `currentCategory` 没有改变（仍然是 3）

**解决方案的本质**：
- 使用 `onActiveFocusChanged` 监听焦点变化
- 当焦点恢复时（`activeFocus = true`），重新启用键盘事件
- 这样无论用户如何操作，只要焦点回到 MotorControlPage，就会重新启用

### 为什么不会影响返回大类的功能？

- 当用户按左键返回大类时，`keysEnabled` 被设置为 `false`
- 焦点转移到 DeviceSettingsDialog
- `onActiveFocusChanged` 触发，但 `activeFocus = false`，不会重新启用
- 所以键盘事件仍然被禁用，DeviceSettingsDialog 可以接收键盘事件
