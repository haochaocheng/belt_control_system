## 🔍 问题分析

### 问题2分析：ESC键事件传递

**Qt官方InputPanel的行为**：
- InputPanel没有内置的ESC键处理
- ESC键事件会传递到父组件
- DeviceSettingsDialog接收到ESC键，关闭对话框

**自定义虚拟键盘的处理**（参考）：
```qml
Shortcut {
    enabled: root.visible
    sequence: "Esc"
    onActivated: {
        console.log("✅ [QtVirtualKeyboard] Shortcut ESC 键被按下，关闭虚拟键盘")
        root.close()
    }
}
```

**解决方案**：
- 在InputPanel中添加Shortcut
- 捕获ESC键，调用`Qt.inputMethod.hide()`
- 阻止事件传递到DeviceSettingsDialog

### 问题3分析：焦点恢复

**Qt官方InputPanel的行为**：
- InputPanel关闭时应该自动恢复焦点
- 如果焦点没有恢复，可能是因为：
  1. InputPanel的焦点管理有问题
  2. 需要手动恢复焦点到参数区域

**需要测试**：
- 修复ESC键问题后，测试焦点是否正常恢复
- 如果还有问题，参考BasicConfigTab的处理方式

## 💡 关键知识点

### 1. Shortcut vs Keys.onEscapePressed

**Shortcut的优势**：
- 不需要焦点
- 可以设置`enabled`条件
- 优先级高于Keys事件

**Keys.onEscapePressed的问题**：
- 需要组件有焦点
- InputPanel可能没有焦点
- 事件会传递到父组件

### 2. Qt.inputMethod.hide() vs InputPanel.close()

**Qt.inputMethod.hide()**：
- Qt官方API
- 关闭Qt输入法系统
- InputPanel.active自动变为false

**InputPanel.close()**：
- 不存在这个方法
- InputPanel不是Popup，不能调用close()

### 3. 焦点恢复机制

**Qt官方InputPanel**：
- 关闭时应该自动恢复焦点到之前的输入框
- 如果焦点没有恢复，可能需要手动处理

**自定义虚拟键盘**：
- 保存`parentPage`引用
- 关闭时调用`parentPage.forceActiveFocus()`
