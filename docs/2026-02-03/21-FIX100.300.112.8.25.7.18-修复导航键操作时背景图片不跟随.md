## 🎯 问题描述

### 用户报告的新问题

在修复了 FIX 100.300.112.8.25.7.17 后：
1. 鼠标点击5号电机 → ✅ 蓝色边框和背景图片都切换到5号电机（修复成功）
2. 继续使用导航键 → ❌ **只有蓝色边框移动，背景图片停留在5号电机**

### 问题分析

**根本原因**：`MyMotorListPanel.qml` 中保留了旧的键盘事件处理器，与 `NavigationManager` 的导航逻辑冲突。

**代码分析**：

在 `MyMotorListPanel.qml` (Line 30-42)：
```qml
Keys.onUpPressed: {
    if (root.currentMotorIndex > 0) {
        root.currentMotorIndex--
        motorSelected(root.currentMotorIndex)
    }
}

Keys.onDownPressed: {
    if (root.currentMotorIndex < 7) {
        root.currentMotorIndex++
        motorSelected(root.currentMotorIndex)
    }
}
```

**问题**：
- 这些键盘事件处理器是旧的导航逻辑
- 现在导航由 `NavigationManager` 统一管理
- 但这些旧的处理器还在工作，可能会干扰导航

**正确的导航流程**：
```
用户按导航键
  ↓
NavigationManager 处理导航
  ↓
NavigationManager.motorListIndex 变化
  ↓
MotorControlPage.onMotorListIndexChanged
  ↓
同时更新：currentMotorIndex + focusItemIndex
  ↓
MyMotorListPanel 同时更新：背景图片 + 蓝色边框 ✅
```

## 🔍 技术说明

### 为什么要注释掉这些代码？

1. **导航架构变更**：
   - 旧架构：每个组件自己处理键盘事件
   - 新架构：`NavigationManager` 统一管理所有导航

2. **避免冲突**：
   - 旧的键盘事件处理器会与 `NavigationManager` 冲突
   - 导致状态不同步

3. **统一管理的优势**：
   - 焦点状态统一管理
   - 跨区域导航更流畅
   - 状态同步更可靠

### NavigationManager 的工作流程

```
用户按导航键
  ↓
DeviceSettingsDialog 捕获键盘事件
  ↓
调用 NavigationManager.handleKey()
  ↓
NavigationManager 更新 motorListIndex
  ↓
触发 onMotorListIndexChanged 信号
  ↓
MotorControlPage 同步更新所有状态变量
  ↓
MyMotorListPanel 响应状态变化，更新UI
```
