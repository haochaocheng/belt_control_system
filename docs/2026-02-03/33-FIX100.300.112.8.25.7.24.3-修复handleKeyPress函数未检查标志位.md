## 🎯 问题描述

### 用户反馈

测试完成，按左键返回到电机控制，出现一个警告，然后无法返回。

### 日志分析

```
Line -11: 按左键
Line -10: MotorControlPage 接收到 returnToCategory 信号，释放焦点
Line -9: MotorControlPage 焦点变化: false
Line -7: Warning: Parameter "event" is not declared  ⚠️ 警告
Line -6: MotorControlPage 接收键盘事件: Left  ❌ 又接收到了！
Line -5: NavigationManager 方向键: Left
Line -4: MotorControlPage 接收到 returnToCategory 信号，释放焦点  ❌ 又释放了！
```

**关键发现**：
- Line -6: "MotorControlPage 接收键盘事件: Left"
- 这不是 `Keys.onLeftPressed` 的日志（应该是 "接收到 Left 键"）
- 这是 `handleKeyPress` 函数的日志！

### 根本原因

**还有另一个键盘事件处理器！**

在 MotorControlPage.qml Line 658-661，有一个 `handleKeyPress` 函数：

```qml
function handleKeyPress(direction) {
    console.log("✅ [MotorControlPage] 接收键盘事件:", direction)
    navigationManager.handleDirectionKey(direction)
}
```

这个函数被 DeviceSettingsDialog 调用，用于转发键盘事件给 NavigationManager。

**问题流程**：
```
1. 用户按左键
2. Keys.onLeftPressed 检查 isReturningToCategory = false ✅
3. 调用 NavigationManager.handleDirectionKey("Left")
4. NavigationManager 触发 returnToCategory 信号
5. MotorControlPage 设置 isReturningToCategory = true ✅
6. MotorControlPage 释放焦点
7. 焦点丢失，DeviceSettingsDialog 接收键盘事件
8. DeviceSettingsDialog 调用 MotorControlPage.handleKeyPress("Left")  ❌
9. handleKeyPress 没有检查 isReturningToCategory  ❌
10. 再次调用 NavigationManager.handleDirectionKey("Left")
11. 重复步骤 4-10，形成死循环
```

---

## 🔧 解决方案

### 方案：在 handleKeyPress 函数中也添加标志位检查

**核心思想**：
- `handleKeyPress` 函数也会触发 NavigationManager
- 需要在这个函数中也检查 `isReturningToCategory` 标志
- 如果标志为 `true`，则忽略事件

### 修改内容

#### 修改文件：MotorControlPage.qml（Line 656-667）

```qml
// 修改前
function handleKeyPress(direction) {
    console.log("✅ [MotorControlPage] 接收键盘事件:", direction)
    navigationManager.handleDirectionKey(direction)
}

// 修改后
// ✅ 2026-02-03 [FIX 100.300.112.8.25.7.24.3]: 添加标志位检查，防止恶性循环
function handleKeyPress(direction) {
    // ✅ 2026-02-03 [FIX 100.300.112.8.25.7.24.3]: 防止恶性循环
    if (isReturningToCategory) {
        console.log("⚠️ [DEBUG] 正在返回大类，忽略键盘事件:", direction)
        return
    }
    console.log("✅ [MotorControlPage] 接收键盘事件:", direction)
    navigationManager.handleDirectionKey(direction)
}
```

### 修复后的完整流程

**用户按左键返回大类**：
```
1. 用户按左键
2. Keys.onLeftPressed 检查 isReturningToCategory = false ✅
3. 调用 NavigationManager.handleDirectionKey("Left")
4. NavigationManager 触发 returnToCategory 信号
5. MotorControlPage 设置 isReturningToCategory = true ✅
6. MotorControlPage 释放焦点
7. 焦点丢失，DeviceSettingsDialog 接收键盘事件
8. DeviceSettingsDialog 调用 MotorControlPage.handleKeyPress("Left")
9. handleKeyPress 检查 isReturningToCategory = true ✅
10. 忽略事件，输出 "正在返回大类，忽略键盘事件: Left" ✅
11. 不再触发 NavigationManager，恶性循环被打破 ✅
12. DeviceSettingsDialog 切换类别 ✅
```

## 📊 为什么之前的修复不完整？

### FIX .24.2 的修复

在 FIX .24.2 中，我们添加了标志位检查，但只在 `Keys.onLeftPressed` 等键盘事件处理器中检查：

```qml
Keys.onLeftPressed: {
    if (isReturningToCategory) {  // ✅ 检查了
        console.log("⚠️ [DEBUG] 正在返回大类，忽略 Left 键")
        return
    }
    navigationManager.handleDirectionKey("Left")
}
```

**但是忽略了 `handleKeyPress` 函数！**

### 为什么会有两个键盘事件处理器？

1. **Keys.onLeftPressed**：
   - 当 MotorControlPage 有焦点时，直接接收键盘事件
   - 用于电机列表内部的导航

2. **handleKeyPress**：
   - 当 DeviceSettingsDialog 有焦点时，DeviceSettingsDialog 接收键盘事件
   - DeviceSettingsDialog 调用 MotorControlPage.handleKeyPress 转发事件
   - 用于从外部控制电机列表的导航

**问题**：
- 当用户按左键返回大类时，焦点从 MotorControlPage 转移到 DeviceSettingsDialog
- DeviceSettingsDialog 接收到键盘事件，调用 handleKeyPress
- handleKeyPress 没有检查标志位，再次触发 NavigationManager
- 形成恶性循环
