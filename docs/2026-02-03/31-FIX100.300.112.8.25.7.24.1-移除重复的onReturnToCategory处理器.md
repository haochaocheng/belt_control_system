# FIX 100.300.112.8.25.7.24.1 - 移除重复的 onReturnToCategory 处理器

**任务编号**: FIX 100.300.112.8.25.7.24.1
**状态**: ✅ 已完成

## 🎯 问题描述

### 用户反馈

日志中显示：`MotorControlPage.qml:192: 有错位`

### 问题分析

在 MotorControlPage.qml 中存在**两个** `onReturnToCategory` 处理器：

1. **新的处理器**（Line 136-140）：
   ```qml
   // ✅ 2026-02-03 [FIX 100.300.112.8.25.7.24]: 监听 returnToCategory 信号，释放焦点
   onReturnToCategory: {
       console.log("✅ [MotorControlPage] 接收到 returnToCategory 信号，释放焦点")
       root.focus = false
   }
   ```

2. **旧的处理器**（Line 192-196）：
   ```qml
   // ✅ 2026-01-30 [FIX 100.300.109 Phase 2.8]: 监听返回到类别信号
   onReturnToCategory: {
       console.log("✅ [MotorControlPage] 返回到左侧类别")
       root.requestReturnToCategory()
   }
   ```

### 根本原因

**QML 不允许同一个信号有多个处理器！**

当存在重复的信号处理器时，QML 会报错：
- `MotorControlPage.qml:192:` 表示第192行有问题
- 这是因为第192行的 `onReturnToCategory` 与第136行的重复了

---

## 🔧 解决方案

### 方案：注释掉旧的处理器，保留新的

**核心思想**：
- 旧的处理器（Line 192-196）只是发出信号，没有实际作用
- 新的处理器（Line 136-140）会释放焦点，这是我们需要的功能
- 注释掉旧的处理器，避免重复定义

### 修改内容

#### 修改文件：MotorControlPage.qml（Line 191-197）

```qml
// 修改前
// ✅ 2026-01-30 [FIX 100.300.109 Phase 2.8]: 监听返回到类别信号
onReturnToCategory: {
    console.log("✅ [MotorControlPage] 返回到左侧类别")
    // 发出信号通知 DeviceSettingsDialog 返回到左侧类别
    root.requestReturnToCategory()
}

// 修改后
// ✅ 2026-01-30 [FIX 100.300.109 Phase 2.8]: 监听返回到类别信号
// ✅ 2026-02-03 [FIX 100.300.112.8.25.7.24]: 移除旧的处理器，已在 Line 136 重新实现
// onReturnToCategory: {
//     console.log("✅ [MotorControlPage] 返回到左侧类别")
//     // 发出信号通知 DeviceSettingsDialog 返回到左侧类别
//     root.requestReturnToCategory()
// }
```

### 为什么保留新的处理器？

**新的处理器（Line 136-140）的功能**：
```qml
onReturnToCategory: {
    console.log("✅ [MotorControlPage] 接收到 returnToCategory 信号，释放焦点")
    root.focus = false  // ✅ 释放焦点，让 DeviceSettingsDialog 接管键盘事件
}
```

**旧的处理器（Line 192-196）的功能**：
```qml
onReturnToCategory: {
    console.log("✅ [MotorControlPage] 返回到左侧类别")
    root.requestReturnToCategory()  // ❌ 只是发出信号，没有实际作用
}
```

**对比**：
- 新的处理器：释放焦点，解决了用户反馈的问题 ✅
- 旧的处理器：只是发出信号，没有实际效果 ❌
