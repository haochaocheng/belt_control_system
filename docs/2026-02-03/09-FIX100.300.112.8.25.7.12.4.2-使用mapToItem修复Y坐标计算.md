### 问题根源

**之前的getScreenY()函数**：
```qml
function getScreenY(item) {
    var y = 0
    var current = item
    while (current && depth < 20) {
        y += current.y  // ❌ 直接累加所有父元素的Y
        current = current.parent
    }
    return y
}
```

**问题**：
1. 层级2的Y=360是输入框在GridLayout中的Y坐标
2. 这个360是相对于ScrollView的**内容区域**（contentItem），不是相对于**可见区域**（viewport）
3. 直接累加所有Y值，**没有减去ScrollView的contentY**
4. 即使当前contentY=0，这个计算方式在ScrollView滚动后也会出错

**组件层级结构**：
```
CustomSpinBox (Y=0)
  ↓
Row (Y=0)
  ↓
Item (Y=360)  ← 这个360是相对于GridLayout的
  ↓
GridLayout (Y=0)
  ↓
Item (Y=0)
  ↓
Flickable (Y=0, contentY=0)  ← ScrollView的内部实现
  ↓
ScrollView (Y=0)
  ↓
...
```

**错误的计算**：
```
inputScreenY = 0 + 0 + 360 + 0 + ... = 541
```

**正确的计算应该是**：
```
inputYInContent = 360  // 输入框在ScrollView内容中的Y
currentContentY = 0    // 当前滚动位置
inputYInViewport = inputYInContent - currentContentY = 360 - 0 = 360
scrollViewScreenY = 460  // ScrollView在屏幕中的Y
inputScreenY = scrollViewScreenY + inputYInViewport = 460 + 360 = 820
```

---

## 🔧 解决方案：使用mapToItem()

### QML的mapToItem()函数

QML提供了`mapToItem()`函数，可以将一个Item的坐标映射到另一个Item的坐标系：

```qml
// 将item的坐标(0,0)映射到targetItem的坐标系
var mappedPos = item.mapToItem(targetItem, 0, 0)
var x = mappedPos.x
var y = mappedPos.y
```

**优点**：
1. **自动处理所有坐标转换**：包括ScrollView的contentY偏移
2. **自动处理变换**：包括rotation、scale等
3. **代码简洁**：一行代码搞定
4. **更可靠**：QML内部实现，经过充分测试

### 修改内容

**修改文件**: `src/qml/components/device_info/CustomSpinBox.qml`

**修改位置**: Line 270-304

**修改内容**：
```qml
// ✅ 2026-02-03 [FIX 100.300.112.8.25.7.12.4.2]: 使用mapToItem()计算屏幕Y坐标
// 原因：之前的累加方式没有考虑ScrollView的contentY偏移
// mapToItem()会自动处理所有坐标转换，包括滚动偏移
function getScreenY(item) {
    console.log("   📍 开始计算屏幕Y坐标，从:", item)

    // 获取Window的contentItem
    var windowItem = item.Window.window ? item.Window.window.contentItem : null
    if (!windowItem) {
        console.log("   ⚠️ 无法获取Window.contentItem，回退到累加方式")
        // 回退到累加方式（虽然不准确，但总比没有好）
        var y = 0
        var current = item
        var depth = 0
        while (current && depth < 20) {
            y += current.y
            current = current.parent
            depth++
            if (current && current.toString().indexOf("Window") !== -1) {
                break
            }
        }
        console.log("   📍 屏幕Y坐标（累加方式）:", y)
        return y
    }

    // 使用mapToItem将item的坐标(0,0)映射到Window.contentItem
    var mappedPos = item.mapToItem(windowItem, 0, 0)
    console.log("   📍 屏幕Y坐标（mapToItem）:", mappedPos.y)
    console.log("      - 输入框对象:", item)
    console.log("      - Window.contentItem:", windowItem)
    console.log("      - 映射后坐标: (", mappedPos.x, ",", mappedPos.y, ")")

    return mappedPos.y
}
```

**关键改进**：
1. 使用`item.mapToItem(windowItem, 0, 0)`直接映射坐标
2. 自动处理ScrollView的contentY偏移
3. 添加回退机制：如果无法获取Window.contentItem，使用累加方式
4. 添加详细日志，显示映射后的坐标

## 💡 关键知识点

### 1. mapToItem() vs 手动累加

**mapToItem()**：
```qml
var mappedPos = item.mapToItem(targetItem, 0, 0)
var y = mappedPos.y
```

**优点**：
- ✅ 自动处理ScrollView的contentY偏移
- ✅ 自动处理所有变换（rotation、scale等）
- ✅ 代码简洁，一行搞定
- ✅ QML内部实现，更可靠

**手动累加**：
```qml
var y = 0
var current = item
while (current) {
    y += current.y
    current = current.parent
}
```

**缺点**：
- ❌ 需要手动处理ScrollView的contentY
- ❌ 需要手动处理变换
- ❌ 代码复杂，容易出错
- ❌ 需要自己测试所有边界情况

### 2. 为什么之前的累加方式错误？

**问题场景**：
```
CustomSpinBox (Y=0)
  ↓
Item (Y=360)  ← 这个360是相对于GridLayout的
  ↓
GridLayout (Y=0)
  ↓
Flickable (Y=0, contentY=0)  ← ScrollView的内部实现
```

**累加方式**：
```
y = 0 + 360 + 0 + 0 = 360
```

**问题**：
- 这个360是相对于GridLayout的顶部
- GridLayout在Flickable的contentItem中
- 当Flickable滚动时（contentY > 0），这个360就不准确了
- 需要减去contentY：`y = 360 - contentY`

**mapToItem方式**：
```qml
var mappedPos = item.mapToItem(windowItem, 0, 0)
// QML内部会自动处理：
// 1. 计算item在GridLayout中的Y（360）
// 2. 减去Flickable的contentY（0）
// 3. 加上Flickable在Window中的Y（460）
// 4. 返回最终的屏幕Y（820）
```

### 3. Window.contentItem vs Window

**Window.contentItem**：
- Window的内容区域
- 所有可见元素都在这个区域内
- 坐标系的原点（0,0）

**Window**：
- 整个窗口，包括标题栏、边框等
- 不适合作为坐标映射的目标

**正确用法**：
```qml
var windowItem = item.Window.window.contentItem  // ✅ 正确
var mappedPos = item.mapToItem(windowItem, 0, 0)
```

**错误用法**：
```qml
var window = item.Window.window  // ❌ 错误
var mappedPos = item.mapToItem(window, 0, 0)  // 无法编译
```

### 4. 为什么需要回退机制？

**回退机制**：
```qml
if (!windowItem) {
    // 回退到累加方式
    var y = 0
    var current = item
    while (current) {
        y += current.y
        current = current.parent
    }
    return y
}
```

**原因**：
1. **健壮性**：如果无法获取Window.contentItem，至少有一个备用方案
2. **兼容性**：某些特殊情况下，Window.window可能为null
3. **调试**：可以通过日志看到使用了哪种方式

**实际情况**：
- 正常情况下，Window.window总是存在
- 回退机制主要是为了防御性编程
- 在实际测试中，应该总是使用mapToItem方式
