## 🎯 问题描述

### 用户反馈

测试后，背景图片还是不动。

### 日志分析

从日志来看：
- ✅ 焦点恢复成功
- ✅ 导航键正常接收
- ✅ `currentMotorIndex` 正确更新（4 → 3 → 2 → 1）
- ❌ 但背景图片没有跟随移动

### 根本原因

**`State` 绑定没有正确响应 `currentMotorIndex` 的变化。**

在 `MyMotorListPanel.qml` 中，背景图片使用了 `State` 绑定：

```qml
Image {
    id: backgroundImage
    source: "../../../images/bhNameBK.png"

    states: [
        State {
            name: "selected"
            when: root.currentMotorIndex === index
            PropertyChanges {
                target: backgroundImage
                source: "../../../images/bhNameBK1.png"
            }
        },
        State {
            name: "normal"
            when: root.currentMotorIndex !== index
            PropertyChanges {
                target: backgroundImage
                source: "../../../images/bhNameBK.png"
            }
        }
    ]
}
```

**问题**：
- `State` 的 `when` 条件依赖于 `root.currentMotorIndex === index`
- 当 `currentMotorIndex` 通过 `Qt.binding()` 传递时，`State` 可能不会正确响应变化
- 这是 QML 的一个已知问题：`State` 绑定在某些情况下不如直接属性绑定可靠

---

## 🔧 解决方案

### 方案：将 State 绑定改为直接属性绑定

**核心思想**：不使用 `State` 机制，直接将 `source` 属性绑定到条件表达式。

### 修改内容

#### 修改文件：MyMotorListPanel.qml（Line 105-121）

```qml
// 修改前（使用 State）
Image {
    id: backgroundImage
    anchors.fill: parent
    fillMode: Image.Stretch
    z: -1

    source: "../../../images/bhNameBK.png"

    states: [
        State {
            name: "selected"
            when: root.currentMotorIndex === index
            PropertyChanges {
                target: backgroundImage
                source: "../../../images/bhNameBK1.png"
            }
        },
        State {
            name: "normal"
            when: root.currentMotorIndex !== index
            PropertyChanges {
                target: backgroundImage
                source: "../../../images/bhNameBK.png"
            }
        }
    ]
}

// 修改后（直接绑定）
// ✅ 2026-02-03 [FIX 100.300.112.8.25.7.21]: 改用直接绑定替代 State
Image {
    id: backgroundImage
    anchors.fill: parent
    fillMode: Image.Stretch
    z: -1

    // ✅ 2026-02-03 [FIX 100.300.112.8.25.7.21]: 直接绑定 source，不使用 State
    source: root.currentMotorIndex === index ? "../../../images/bhNameBK1.png" : "../../../images/bhNameBK.png"

    // ✅ 2026-02-03 [FIX 100.300.112.8.25.7.21]: 添加调试日志
    onSourceChanged: {
        console.log("🔍 [DEBUG] 背景图片切换 - 电机", index + 1, "source:", source)
    }
}
```

### 关键改进

1. **直接属性绑定**：
   ```qml
   source: root.currentMotorIndex === index ? "../../../images/bhNameBK1.png" : "../../../images/bhNameBK.png"
   ```
   - 使用三元运算符直接绑定
   - 当 `currentMotorIndex` 变化时，表达式立即重新计算
   - 不依赖 `State` 机制

2. **添加调试日志**：
   ```qml
   onSourceChanged: {
       console.log("🔍 [DEBUG] 背景图片切换 - 电机", index + 1, "source:", source)
   }
   ```
   - 每次 `source` 变化时输出日志
   - 可以确认背景图片是否真的切换了

## 📊 为什么 State 绑定失效？

### QML State 机制的限制

1. **State 绑定的工作原理**：
   - `State` 的 `when` 条件会监听表达式中的属性变化
   - 当条件变为 `true` 时，应用 `PropertyChanges`
   - 当条件变为 `false` 时，恢复原始值

2. **可能的失效原因**：
   - **绑定传递问题**：`currentMotorIndex` 通过 `Qt.binding()` 传递，可能导致 `State` 的 `when` 条件无法正确监听变化
   - **State 优先级问题**：多个 `State` 的 `when` 条件可能冲突，导致状态切换不正确
   - **PropertyChanges 延迟**：`PropertyChanges` 可能在下一帧才应用，导致视觉上的延迟

3. **直接绑定的优势**：
   - **立即响应**：属性绑定在表达式变化时立即重新计算
   - **无中间层**：不依赖 `State` 机制，减少出错可能
   - **更简洁**：代码更简单，更易理解
