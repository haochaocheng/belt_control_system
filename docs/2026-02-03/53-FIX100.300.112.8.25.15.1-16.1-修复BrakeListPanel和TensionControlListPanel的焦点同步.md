# FIX 100.300.112.8.25.15.1-16.1 - 修复 BrakeListPanel 和 TensionControlListPanel 的焦点同步

**日期**: 2026-02-03
**任务编号**: FIX 100.300.112.8.25.15.1-16.1

## 🎯 问题描述

### 用户反馈

用户测试后报告：

> "制动器控制，问题还是没有得到解决，我用鼠标点击8号制动器，向上建时，只有蓝色方框跟随，背景图片不跟随"

### 问题分析

**现象**：
1. 鼠标点击8号制动器
2. 蓝色边框和背景图片都显示在8号 ✅
3. 按上键
4. 蓝色边框向上移动 ✅
5. **但是背景图片不跟随** ❌

**之前的修复（FIX 25.15）**：
- 在 BrakeControlPage.qml 的 `brakeSelected` 信号处理中添加了 `focusItemIndex` 更新
- 但是问题仍然存在

### 根本原因

**问题出在 BrakeListPanel.qml 的 MouseArea 中**（Line 178-181）：

```qml
MouseArea {
    anchors.fill: parent
    onClicked: {
        root.currentBrakeIndex = index  // ✅ 更新了
        root.brakeSelected(index)       // ✅ 发射信号
        root.focus = true
        // ❌ 但是没有更新 root.focusItemIndex ❌
    }
}
```

**问题流程**：
```
1. 鼠标点击8号 → MouseArea.onClicked 触发
2. 更新 currentBrakeIndex = 7 ✅
3. 发射 brakeSelected(7) 信号 ✅
4. BrakeControlPage 接收信号 → 更新 focusItemIndex = 7 ✅
5. ❌ 但是 BrakeListPanel 的 focusItemIndex 没有被更新 ❌
6. 因为 focusItemIndex 是通过 Qt.binding() 绑定的
7. 绑定可能在某些情况下不会立即生效
8. 按上键 → focusItemIndex-- → 从旧值开始递减 ❌
9. 蓝色边框移动（绑定到 focusItemIndex）❌
10. 背景图片不动（绑定到 currentBrakeIndex）❌
```

**为什么之前的修复不够**：

虽然在 BrakeControlPage.qml 中更新了 `focusItemIndex`，但是：
1. BrakeListPanel 的 `focusItemIndex` 是通过 `Qt.binding()` 绑定的
2. 绑定的更新可能有延迟
3. 在 MouseArea 中直接更新 `focusItemIndex` 更可靠

---

## 🔧 解决方案

### 方案：在 MouseArea 中直接更新 focusItemIndex

**核心思想**：
- 在 BrakeListPanel.qml 和 TensionControlListPanel.qml 的 MouseArea 中
- 不仅更新 `currentBrakeIndex` / `currentControlIndex`
- 还要直接更新 `focusItemIndex`
- 确保两个状态立即同步

### 修改内容

#### 1. BrakeListPanel.qml - 修改 MouseArea（Line 178-184）

```qml
MouseArea {
    anchors.fill: parent
    onClicked: {
        // ✅ 2026-02-03 [FIX 100.300.112.8.25.15.1]: 鼠标点击时同步更新所有焦点状态
        console.log("🔍 [BrakeListPanel] 鼠标点击制动器:", index)
        root.currentBrakeIndex = index
        root.focusItemIndex = index  // ← 添加这一行，确保焦点索引同步
        root.brakeSelected(index)
        root.focus = true  // 获取焦点以支持键盘操作
    }
}
```

#### 2. TensionControlListPanel.qml - 修改 MouseArea（Line 181-188）

```qml
MouseArea {
    anchors.fill: parent
    onClicked: {
        // ✅ 2026-02-03 [FIX 100.300.112.8.25.16.1]: 鼠标点击时同步更新所有焦点状态
        console.log("🔍 [TensionControlListPanel] 鼠标点击控制:", index)
        root.currentControlIndex = index
        root.focusItemIndex = index  // ← 添加这一行，确保焦点索引同步
        root.controlSelected(index)
        root.focus = true  // 获取焦点以支持键盘操作
    }
}
```

### 修复后的完整流程

**场景：鼠标点击列表项后按上下键**

#### 修复前（focusItemIndex 没有立即同步）：

```
1. 鼠标点击8号 → currentBrakeIndex = 7 ✅
2. 发射 brakeSelected(7) → BrakeControlPage 更新 focusItemIndex = 7 ✅
3. ❌ 但是 BrakeListPanel 的 focusItemIndex 可能没有立即更新 ❌
4. 按上键 → focusItemIndex-- → 从旧值开始 ❌
5. 蓝色边框移动到错误位置 ❌
6. 背景图片不跟随 ❌
```

#### 修复后（focusItemIndex 立即同步）：

```
1. 鼠标点击8号 → currentBrakeIndex = 7, focusItemIndex = 7 ✅
2. 发射 brakeSelected(7) → BrakeControlPage 也更新 focusItemIndex = 7 ✅
3. 按上键 → focusItemIndex-- → focusItemIndex = 6 ✅
4. onFocusItemIndexChanged 触发 → currentBrakeIndex = 6 ✅
5. 蓝色边框移动到7号 ✅
6. 背景图片也移动到7号 ✅
```

---

## 📊 为什么这个方案有效？

### 问题的本质

**Qt.binding() 的延迟更新**：
- BrakeListPanel 的 `focusItemIndex` 通过 `Qt.binding()` 绑定到 BrakeControlPage 的 `focusItemIndex`
- 当 BrakeControlPage 更新 `focusItemIndex` 时，绑定的更新可能有延迟
- 在 MouseArea 中直接更新 `focusItemIndex` 更可靠

### 解决方案的本质

**双重保险**：
- 在 BrakeListPanel 的 MouseArea 中直接更新 `focusItemIndex`（立即生效）
- 在 BrakeControlPage 的 `brakeSelected` 信号处理中也更新 `focusItemIndex`（通过绑定同步）
- 两个地方都更新，确保状态一定同步

### 焦点同步链

```
鼠标点击
    ↓
BrakeListPanel.MouseArea:
- currentBrakeIndex = index
- focusItemIndex = index  ← 立即更新
    ↓
发射 brakeSelected(index) 信号
    ↓
BrakeControlPage 接收:
- currentBrakeIndex = index
- focusItemIndex = index  ← 再次确认
- focusSubArea = 0
- navigationManager.brakeListIndex = index
    ↓
所有状态完全同步 ✅
```
