## 🎯 问题描述

### 用户反馈

用户测试 FIX .25.4 后，报告新问题：

"测试完成，左右导航正常时，焦点在电机列表后，用鼠标电机列表任意电机时，左键蓝色边框在电机控制按钮上，再次按右键，焦点直接跳过电机列表，直接在基本配置上，在按左键，焦点回到电机列表，再按左键焦点无法回到电机控制，只能在上下电机列表切换，朝右是正常，向左用于无法回到电机控制"

### 测试步骤分解

1. 焦点在电机列表
2. 鼠标点击电机列表任意电机
3. 按左键 → 蓝色边框在"电机控制"按钮上（左侧大类）✅
4. 再按右键 → 焦点直接跳过电机列表，直接在"基本配置"上 ❌
5. 按左键 → 焦点回到电机列表 ✅
6. 再按左键 → 焦点无法回到"电机控制"，只能在电机列表上下切换 ❌
7. 向右是正常，向左永远无法回到电机控制 ❌

### 根本原因

**NavigationManager.currentArea 没有被正确重置**

**问题流程**：
```
1. 用户在电机列表，按左键返回大类
2. DeviceSettingsDialog 接收 requestReturnToCategory 信号
3. 重置 NavigationManager.currentArea = areaMotorList ✅
4. 设置 currentFocusArea = 1（左侧类别）✅
5. 用户在大类列表，按右键进入电机控制
6. DeviceSettingsDialog 设置 currentFocusArea = 2（右侧内容区域）✅
7. ❌ 但是 NavigationManager.currentArea 没有被重置为 areaMotorList ❌
8. 用户再按右键
9. NavigationManager 认为还在上次的区域（可能是 B 或 C）
10. 直接切换到下一个区域（Tab 区域 B）❌
11. 跳过了电机列表区域 ❌
```

**为什么会这样？**

在 DeviceSettingsDialog 的 `onCurrentFocusAreaChanged` 中（Line 1399-1410），当焦点进入内容区域时：
- 设置了 `focusSubArea = 0` ✅
- 设置了 `focusItemIndex` ✅
- **但是没有设置 NavigationManager.currentArea** ❌

---

## 🔧 解决方案

### 方案：在焦点进入内容区域时，重置 NavigationManager.currentArea

**核心思想**：
- 当 `currentFocusArea` 变为 2（右侧内容区域）且 `currentCategory` 为 3（电机控制）时
- 重置 `NavigationManager.currentArea = areaMotorList`
- 确保下次按右键时，从电机列表区域开始

### 修改内容

#### 修改 DeviceSettingsDialog.qml 的 onCurrentFocusAreaChanged（Line 1399-1415）

```qml
// 修改前
function onCurrentFocusAreaChanged() {
    if (motorControlPageLoader.item && root.currentCategory === 3) {
        if (root.currentFocusArea === 2) {
            // 焦点进入内容区域，默认在电机列表区域
            motorControlPageLoader.item.focusSubArea = 0
            motorControlPageLoader.item.focusItemIndex = root.currentContentItemIndex
        } else {
            // 焦点离开内容区域，清除焦点
            motorControlPageLoader.item.focusItemIndex = -1
        }
    }
}

// 修改后
function onCurrentFocusAreaChanged() {
    if (motorControlPageLoader.item && root.currentCategory === 3) {
        if (root.currentFocusArea === 2) {
            // ✅ 2026-02-03 [FIX 100.300.112.8.25.7.25.5]: 焦点进入内容区域，重置 NavigationManager 到电机列表区域
            console.log("✅ [DeviceSettingsDialog] 焦点进入电机控制内容区域，重置 NavigationManager.currentArea 到电机列表")
            if (motorControlPageLoader.item.navigationManager) {
                motorControlPageLoader.item.navigationManager.currentArea = motorControlPageLoader.item.navigationManager.areaMotorList
            }
            // 焦点进入内容区域，默认在电机列表区域
            motorControlPageLoader.item.focusSubArea = 0
            motorControlPageLoader.item.focusItemIndex = root.currentContentItemIndex
        } else {
            // 焦点离开内容区域，清除焦点
            motorControlPageLoader.item.focusItemIndex = -1
        }
    }
}
```

## 📊 为什么这个方案有效？

### 问题的本质

**NavigationManager 状态不同步**：
- DeviceSettingsDialog 使用 `currentFocusArea` 管理焦点区域（0: 顶部, 1: 左侧, 2: 右侧, 3: 底部）
- MotorControlPage 使用 `NavigationManager.currentArea` 管理导航区域（A: 电机列表, B: Tab, C: 参数, D: 按钮）
- 两个状态需要保持同步，但是之前只在 `requestReturnToCategory` 信号处理中同步
- 当用户从大类进入电机控制时，`currentFocusArea` 变化了，但 `NavigationManager.currentArea` 没有变化

### 解决方案的本质

**在焦点进入内容区域时同步状态**：
- 监听 `currentFocusArea` 变化
- 当 `currentFocusArea` 变为 2（右侧内容区域）且 `currentCategory` 为 3（电机控制）时
- 重置 `NavigationManager.currentArea = areaMotorList`
- 确保两个状态保持同步

### 为什么之前没有这个问题？

之前的复杂逻辑（FIX .17 到 .24.7）可能通过其他方式间接解决了这个问题，但是简化后（FIX .25）暴露了这个根本问题。
