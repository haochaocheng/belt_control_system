## 🎯 问题概述

### 用户反馈

用户报告了两个相关的问题：

1. **电机控制页面**："正常情况下左右导航一切使用都正常，从使用鼠标点击点击列表任意按钮，就不正常了，你的排查重点是鼠标点击点列表任意按钮的影响，都改十几版本了，问题反复出现"

2. **开关量输入页面**："导航键从开关量输入切换到急停时，鼠标点击堆煤，蓝色边框和背景图片同时出现在堆煤，但是此时，如果按上键，没有响应（默认焦点还是在急停），按向下键，焦点出现在跑偏。因此鼠标点击事件没有更新内部焦点。"

### 根本原因

**两个独立但相关的问题**：

1. **焦点转移问题**：鼠标点击后，焦点转移到了页面，但是 DeviceSettingsDialog 没有恢复焦点
2. **反向焦点同步问题**：鼠标点击时，`focusItemIndex` 被更新了，但是 `currentContentItemIndex` 没有被同步更新

---

## 🔧 解决方案

### 方案 1：焦点转移修复（forceActiveFocus）

**问题**：鼠标点击后，按左键无法返回到左侧类别列表。

**原因**：
- 鼠标点击后，焦点转移到了页面
- DeviceSettingsDialog 失去了焦点
- 按左键时，DeviceSettingsDialog 无法接收到键盘事件

**解决方案**：
- 在左键返回处理中，添加 `root.forceActiveFocus()` 调用
- 确保焦点真正转移回 DeviceSettingsDialog

### 方案 2：反向焦点同步（currentContentItemIndex ↔ focusItemIndex）

**问题**：鼠标点击后，按上下键无法正确导航，焦点跳到错误的位置。

**原因**：
- DeviceSettingsDialog 使用 `currentContentItemIndex` 管理导航
- 页面使用 `focusItemIndex` 管理焦点
- 之前只有单向绑定：`currentContentItemIndex` → `focusItemIndex`
- 缺少反向绑定：`focusItemIndex` → `currentContentItemIndex`

**解决方案**：
- 添加反向焦点同步 Connections
- 监听 `focusItemIndex` 的变化
- 同步更新 `currentContentItemIndex`

## 🎓 核心原则

### 原则 1：显式焦点转移

**鼠标点击破坏焦点状态 → 需要显式调用 forceActiveFocus() 来恢复**

```qml
// ❌ 错误：只设置状态，不转移焦点
currentFocusArea = 1

// ✅ 正确：设置状态后，强制转移焦点
currentFocusArea = 1
root.forceActiveFocus()
```

### 原则 2：双向焦点同步

**currentContentItemIndex ↔ focusItemIndex**

```qml
// 单向绑定：Dialog → Page
Connections {
    target: root
    function onCurrentContentItemIndexChanged() {
        page.focusItemIndex = root.currentContentItemIndex
    }
}

// 反向绑定：Page → Dialog
Connections {
    target: page
    function onFocusItemIndexChanged() {
        root.currentContentItemIndex = page.focusItemIndex
    }
}
```
