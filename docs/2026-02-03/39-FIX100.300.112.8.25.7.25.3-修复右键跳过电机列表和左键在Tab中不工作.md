### 用户反馈

用户测试 FIX .25 简化方案后，报告两个新问题：

1. **右键跳过电机列表**："再次按右键时，直接跳过电机列表，进入参数区域"
2. **左键在Tab中不工作**："而且在基本配置和电流保护，只能按右键，焦点向右移动，按左键无法返回左侧"

### 日志分析

```
Line -14: 按左键，请求返回到左侧类别
Line -13: DeviceSettingsDialog 接收到返回类别请求  ✅
Line -12: Warning: Parameter "event" is not declared  ⚠️
Line -11: NavigationManager 方向键: Right 当前区域: A 当前索引: 0  ❌
Line -10: 切换区域: A → B  ❌ 直接跳过电机列表！
```

**关键发现**：
1. 用户按左键从电机列表返回大类 ✅
2. DeviceSettingsDialog 正确接收到请求 ✅
3. **但是 NavigationManager.currentArea 仍然是 A（电机列表）** ❌
4. 用户再按右键时，NavigationManager 认为还在电机列表区域，所以直接切换到 B（Tab区域）❌

**另外还有一个警告**：
```
Parameter "event" is not declared. Injection of parameters into signal handlers is deprecated.
```

### 根本原因

#### 问题1：右键跳过电机列表

**原因**：当用户从大类按右键进入电机控制时，只有 `currentFocusArea` 变化（1 → 2），但 `NavigationManager.currentArea` 没有被重置。

**流程**：
```
1. 用户在大类列表，按右键
2. DeviceSettingsDialog 设置 currentFocusArea = 2 ✅
3. MotorControlPage 获得焦点 ✅
4. 但是 NavigationManager.currentArea 仍然是上次的值（可能是 B 或 C）❌
5. 用户再按右键
6. NavigationManager 认为还在电机列表区域（A），直接切换到 Tab 区域（B）❌
```

#### 问题2：左键在Tab中不工作

**原因**：简化后的 `Keys.onLeftPressed` 总是发出 `requestReturnToCategory()` 信号，即使在 Tab/Parameter 区域也是如此。

**流程**：
```
1. 用户在 Tab 区域（基本配置），按左键
2. Keys.onLeftPressed 发出 requestReturnToCategory() 信号 ❌
3. DeviceSettingsDialog 切换到大类列表 ❌
4. 应该由 NavigationManager 处理，返回到电机列表区域（A）✅
```

#### 问题3：QML 警告

**原因**：在 `Keys.onLeftPressed: { }` 中使用了 `event.accepted = true`，但没有声明 `event` 参数。

**正确写法**：
```qml
Keys.onLeftPressed: function(event) {
    // 现在可以使用 event 参数了
}
```

## 🔧 解决方案

### 方案1：修复 QML 警告

**修改 Keys.onLeftPressed 为函数形式**：

```qml
// 修改前
Keys.onLeftPressed: {
    if (navigationManager.currentArea === navigationManager.areaMotorList) {
        // ...
        event.accepted = true  // ❌ event 未声明
    }
}

// 修改后
Keys.onLeftPressed: function(event) {
    if (navigationManager.currentArea === navigationManager.areaMotorList) {
        // ...
        event.accepted = true  // ✅ event 已声明
    }
}
```

### 方案2：重置 NavigationManager.currentArea

**在 DeviceSettingsDialog 中，当接收到 requestReturnToCategory 信号时，重置 NavigationManager 状态**：

```qml
// 修改前
item.requestReturnToCategory.connect(function() {
    console.log("✅ [DeviceSettingsDialog] 接收到返回类别请求")
    root.currentFocusArea = 1  // 切换到左侧类别区域
})

// 修改后
item.requestReturnToCategory.connect(function() {
    console.log("✅ [DeviceSettingsDialog] 接收到返回类别请求")
    // 重置 NavigationManager 到电机列表区域，这样下次按右键时会从电机列表开始
    if (item.navigationManager) {
        console.log("✅ [DeviceSettingsDialog] 重置 NavigationManager.currentArea 到电机列表区域")
        item.navigationManager.currentArea = item.navigationManager.areaMotorList
    }
    root.currentFocusArea = 1  // 切换到左侧类别区域
})
```

### 方案3：修改 Keys.onLeftPressed 检查 currentArea

**只在电机列表区域时才发出 requestReturnToCategory() 信号，其他区域让 NavigationManager 处理**：

```qml
// 修改前
Keys.onLeftPressed: {
    console.log("✅ [MotorControlPage] 按左键，请求返回到左侧类别")
    root.requestReturnToCategory()
    event.accepted = true
}

// 修改后
Keys.onLeftPressed: function(event) {
    // ✅ 2026-02-03 [FIX 100.300.112.8.25.7.25.3]: 只在电机列表区域时返回大类
    if (navigationManager.currentArea === navigationManager.areaMotorList) {
        console.log("✅ [MotorControlPage] 电机列表区域按左键，请求返回到左侧类别")
        root.requestReturnToCategory()
        event.accepted = true
    } else {
        // 其他区域由 NavigationManager 处理
        console.log("✅ [MotorControlPage] 其他区域按左键，由 NavigationManager 处理")
        navigationManager.handleDirectionKey("Left")
        event.accepted = true
    }
}
```

### 方案4：修改 handleKeyPress() 函数

**应用相同的逻辑到 handleKeyPress() 函数**：

```qml
// 修改前
function handleKeyPress(direction) {
    if (direction === "Left") {
        console.log("✅ [MotorControlPage] handleKeyPress 接收 Left 键，请求返回到左侧类别")
        root.requestReturnToCategory()
        return
    }
    // ...
}

// 修改后
function handleKeyPress(direction) {
    // 左键：检查当前区域
    if (direction === "Left") {
        if (navigationManager.currentArea === navigationManager.areaMotorList) {
            console.log("✅ [MotorControlPage] handleKeyPress 电机列表区域按左键，请求返回到左侧类别")
            root.requestReturnToCategory()
            return
        } else {
            // 其他区域由 NavigationManager 处理
            console.log("✅ [MotorControlPage] handleKeyPress 其他区域按左键，由 NavigationManager 处理")
            navigationManager.handleDirectionKey("Left")
            return
        }
    }
    // ...
}
```

## 📊 为什么这个方案有效？

### 问题1：右键跳过电机列表

**问题的本质**：
- 当用户从电机列表返回大类时，只有 `currentFocusArea` 变化，`NavigationManager.currentArea` 没有重置
- 导致下次按右键时，NavigationManager 认为还在电机列表区域，直接切换到 Tab 区域

**解决方案的本质**：
- 在 `requestReturnToCategory` 信号处理中，重置 `NavigationManager.currentArea = areaMotorList`
- 确保下次按右键时，NavigationManager 从电机列表区域开始

### 问题2：左键在Tab中不工作

**问题的本质**：
- 简化后的 `Keys.onLeftPressed` 总是发出 `requestReturnToCategory()` 信号
- 即使在 Tab/Parameter 区域也是如此，导致左键总是返回大类

**解决方案的本质**：
- 检查 `navigationManager.currentArea`
- 只在电机列表区域时才发出 `requestReturnToCategory()` 信号
- 其他区域让 NavigationManager 处理

### 问题3：QML 警告

**问题的本质**：
- 在 `Keys.onLeftPressed: { }` 中使用了 `event` 参数，但没有声明
- Qt 5.15+ 不再自动注入参数到信号处理器

**解决方案的本质**：
- 使用函数形式 `Keys.onLeftPressed: function(event) { }`
- 显式声明 `event` 参数
