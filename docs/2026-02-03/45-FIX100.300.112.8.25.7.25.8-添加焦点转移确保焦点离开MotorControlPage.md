**关键发现**：
- 用户按了**三次**左键

### 根本原因

**焦点没有转移！**

在 `requestReturnToCategory` 信号处理中（Line 1376），我们只设置了：
```qml
root.currentFocusArea = 1  // 切换到左侧类别区域
```

**但是没有调用 `forceActiveFocus()`！**

`currentFocusArea` 只是一个状态变量，改变它不会自动转移焦点。我们需要显式地调用 `root.forceActiveFocus()` 来强制转移焦点到 DeviceSettingsDialog。

**问题流程**：
```
1. 用户在电机列表，按左键
2. MotorControlPage 发出 requestReturnToCategory 信号
3. DeviceSettingsDialog 接收信号
4. 设置 currentFocusArea = 1 ✅
5. ❌ 但是没有调用 forceActiveFocus() ❌
6. 焦点仍然在 MotorControlPage ❌
7. 用户再按左键
8. MotorControlPage 又接收到左键事件 ❌
9. 又发出 requestReturnToCategory 信号 ❌
10. 无限循环 ❌
```

## 🔧 解决方案

### 方案：添加 forceActiveFocus() 强制转移焦点

**核心思想**：
- 在 `requestReturnToCategory` 信号处理中
- 设置 `currentFocusArea = 1` 后
- 调用 `root.forceActiveFocus()` 强制转移焦点
- 确保焦点真正离开 MotorControlPage

### 修改内容

#### 修改 DeviceSettingsDialog.qml 的 requestReturnToCategory 处理（Line 1372-1381）

```qml
// 修改前

    console.log("✅ [DeviceSettingsDialog] 接收到返回类别请求")

// 修改后
item.requestReturnToCategory.connect(function() {
```

## 📊 为什么这个方案有效？

### 问题的本质

**焦点管理的关键**：
- `currentFocusArea` 只是一个状态变量
- 改变它不会自动转移焦点
- 需要显式调用 `forceActiveFocus()` 来转移焦点

### 解决方案的本质

**强制转移焦点**：
- 设置 `currentFocusArea = 1` 后
- 立即调用 `root.forceActiveFocus()`
- 确保焦点真正离开 MotorControlPage
- 这样用户再按左键时，DeviceSettingsDialog 会接收事件

### 为什么之前没有这个问题？

在简化之前（FIX .17 到 .24.7），我们有很多复杂的焦点管理逻辑，包括：
- `requestDialogFocus` 信号
- `keysEnabled` 标志
- `isReturningToCategory` 标志
- 定时器延迟重置

这些逻辑虽然复杂，但是确保了焦点的正确转移。简化后（FIX .25），我们移除了这些逻辑，但是忘记了添加 `forceActiveFocus()`。
