## 💡 关键知识点

### 1. CustomSpinBox 的自动滚动机制

**核心原理**：
1. `activateVirtualKeyboard()` 显示虚拟键盘
2. 监听 `Qt.inputMethod.visible` 变化
3. 使用 `mapToItem()` 计算屏幕坐标
4. 自动滚动 ScrollView
5. 虚拟键盘关闭时恢复滚动位置

**优点**：
- ✅ 完全自动化
- ✅ 精确计算坐标
- ✅ 自动处理滚动
- ✅ 自动恢复位置

### 2. 为什么不使用 virtualKeyboard.openForField()？

**旧的方式**（BasicConfigTab 之前的实现）：
```qml
virtualKeyboard.openForField(inputField, function(newValue) {
    console.log("✅ [BasicConfigTab] 虚拟键盘输入完成:", newValue)
}, inputMode, root)
```

**问题**：
1. 需要手动管理虚拟键盘的显示和隐藏
2. 需要手动计算滚动距离
3. 需要手动处理回调函数
4. 代码复杂，容易出错

**新的方式**（使用 CustomSpinBox）：
```qml
if (inputField.activateVirtualKeyboard) {
    inputField.activateVirtualKeyboard()
}
```

**优点**：
1. CustomSpinBox 自动处理一切
2. 代码简洁，只需一行
3. 更可靠，经过充分测试

### 3. 为什么移除键盘导航代码？

**原因**：
1. `Qt.application.setEnvironmentVariable()` 在 QML 中不存在（C++ API）
2. Qt Virtual Keyboard 的方向键导航需要编译时启用（CONFIG+=）
3. QDS 自带的 Qt Virtual Keyboard 可能没有启用这个功能
4. 用户决定不再追求键盘导航，而是使用已经工作的自动滚动功能

**决议**：
- ❌ 不实施键盘导航方案
- ✅ 继续使用 Qt Virtual Keyboard + 自动滚动
- ✅ 应用到所有需要输入的页面

### 4. mapToItem() 的重要性

**为什么使用 mapToItem()？**

**手动累加方式**（不准确）：
```qml
var y = 0
var current = item
while (current) {
    y += current.y
    current = current.parent
}
```

**问题**：
- 没有考虑 ScrollView 的 contentY 偏移
- 没有考虑变换（rotation、scale等）
- 代码复杂，容易出错

**mapToItem() 方式**（准确）：
```qml
var windowItem = item.Window.window.contentItem
var mappedPos = item.mapToItem(windowItem, 0, 0)
var y = mappedPos.y
```

**优点**：
- ✅ 自动处理 ScrollView 的 contentY 偏移
- ✅ 自动处理所有变换
- ✅ 代码简洁，一行搞定
- ✅ QML 内部实现，更可靠
