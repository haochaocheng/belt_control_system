## 🎯 问题描述

### 用户反馈

用户测试后报告："开关量输入和模拟量输入都有这个问题"

**问题**：鼠标点击列表项后，按左键无法返回到左侧类别列表。

### 根本原因

与 MotorControlPage 完全一样的问题：

1. 用户鼠标点击列表项后，焦点转移到了 SwitchInputPage
2. DeviceSettingsDialog 失去了焦点
3. 用户按左键时，DeviceSettingsDialog 无法接收到键盘事件
4. 导致左键无法返回到左侧类别列表

**问题流程**：
```
1. 用户使用导航键切换列表项 → 正常 ✅
2. 用户鼠标点击列表项 → 焦点转移到 SwitchInputPage ❌
3. 用户按左键 → SwitchInputPage 接收事件，但没有处理 ❌
4. 焦点仍然在 SwitchInputPage ❌
5. 用户再按左键 → 仍然无法返回 ❌
```

---

## 🔧 解决方案

### 方案：添加 requestReturnToCategory 信号和 forceActiveFocus()

**核心思想**：
1. 在 SwitchInputPage 中添加 `requestReturnToCategory()` 信号
2. 在 Keys.onLeftPressed 中，当焦点在列表区域时，发出信号
3. 在鼠标点击处理中，同步焦点状态
4. 在 DeviceSettingsDialog 中，监听信号并调用 `root.forceActiveFocus()`

### 修改内容

#### 1. SwitchInputPage.qml - 添加信号（Line 20-21）

```qml
// ✅ 2026-02-03 [FIX 100.300.112.8.25.9]: 添加返回类别信号
signal requestReturnToCategory()
```

#### 2. SwitchInputPage.qml - 添加 Keys.onLeftPressed 处理（Line 50-58）

```qml
// ✅ 2026-02-03 [FIX 100.300.112.8.25.9]: 添加左键返回类别处理
Keys.onLeftPressed: function(event) {
    if (focusSubArea === 0) {
        // 在列表区域，按左键返回到左侧类别
        console.log("✅ [SwitchInputPage] 列表区域按左键，请求返回到左侧类别")
        root.requestReturnToCategory()
        event.accepted = true
    }
}
```

#### 3. SwitchInputPage.qml - 修改鼠标点击处理（Line 229-236）

```qml
MouseArea {
    anchors.fill: parent
    onClicked: {
        // ✅ 2026-02-03 [FIX 100.300.112.8.25.9]: 鼠标点击时同步焦点状态
        console.log("🔍 [SwitchInputPage] 鼠标点击列表项:", index)
        root.currentProtectionIndex = index
        root.focusItemIndex = index
        root.focusSubArea = 0  // 确保在列表区域
        loadProtectionData(index)
    }
}
```

#### 4. DeviceSettingsDialog.qml - 监听信号（Line 1208-1215）

```qml
// ✅ 2026-02-03 [FIX 100.300.112.8.25.9]: 监听返回类别信号
item.requestReturnToCategory.connect(function() {
    console.log("✅ [DeviceSettingsDialog] 接收到开关量输入返回类别请求")
    root.currentFocusArea = 1  // 切换到左侧类别区域
    // ✅ 强制转移焦点到 DeviceSettingsDialog
    console.log("✅ [DeviceSettingsDialog] 强制转移焦点到 DeviceSettingsDialog")
    root.forceActiveFocus()
})
```
