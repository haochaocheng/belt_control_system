# FIX 100.300.112.8.25.7.25 - 简化左键返回逻辑

## 🎯 问题描述

### 用户反馈

用户指出：焦点如果在电机列表，左键就直接将焦点移动到电机控制大类，这个不是很简单的操作吗，为什么这么复杂？

### 当前实现的复杂性

当前的实现使用了：
1. `returnToCategory` 信号
2. `keysEnabled` 标志
3. `isReturningToCategory` 标志
4. 定时器延迟重置
5. `requestDialogFocus` 信号
6. 复杂的焦点管理逻辑

**问题**：
- 逻辑过于复杂
- 容易出现各种边界情况
- 难以维护和理解

### 正确的简单逻辑

**应该是**：
1. 焦点在电机列表（1号、2号、3号...）
2. 按左键 → 焦点直接移动到左侧的"电机控制"大类按钮
3. 然后用户可以用上下键在大类之间切换

**实现方式**：
- 按左键时，设置 `currentFocusArea = 1`（切换到左侧类别区域）
- DeviceSettingsDialog 自动处理焦点转移
- 完成！

---

## 🔧 解决方案

### 方案：简化为直接切换焦点区域

**核心思想**：
- 移除所有复杂的标志和信号
- 按左键时，直接设置 `currentFocusArea = 1`
- 让 DeviceSettingsDialog 的现有逻辑处理焦点转移

### 修改内容

#### 1. 简化 NavigationManager 的 moveInMotorList（Line 90-94）

```qml
// 修改前
case "Left":
    // ✅ 2026-01-30 [FIX 100.300.109 Phase 2.8]: 向左返回到大类（电机控制）
    // 通过自定义信号通知外部返回到左侧类别
    returnToCategory()
    return

// 修改后
case "Left":
    // ✅ 2026-02-03 [FIX 100.300.112.8.25.7.25]: 简化为直接切换焦点区域
    // 不再使用信号，直接由 MotorControlPage 处理
    // 这里什么都不做，让 MotorControlPage 的 Keys.onLeftPressed 处理
    return
```

#### 2. 简化 MotorControlPage 的 Keys.onLeftPressed（Line 299-312）

```qml
// 修改前
Keys.onLeftPressed: {
    if (!keysEnabled) {
        console.log("⚠️ [DEBUG] 键盘事件已禁用，忽略 Left 键")
        event.accepted = true
        return
    }
    if (isReturningToCategory) {
        console.log("⚠️ [DEBUG] 正在返回大类，忽略 Left 键")
        event.accepted = true
        return
    }
    navigationManager.handleDirectionKey("Left")
    event.accepted = true
}

// 修改后
Keys.onLeftPressed: {
    // ✅ 2026-02-03 [FIX 100.300.112.8.25.7.25]: 简化为直接切换焦点区域
    console.log("✅ [MotorControlPage] 按左键，切换到左侧类别区域")
    // 通过父组件的属性切换焦点区域
    if (root.parent && root.parent.currentFocusArea !== undefined) {
        root.parent.currentFocusArea = 1  // 切换到左侧类别区域
    }
    event.accepted = true
}
```

#### 3. 移除所有不需要的代码

**移除**：
- `isReturningToCategory` 标志
- `keysEnabled` 标志
- `resetFlagTimer` 定时器
- `requestDialogFocus` 信号
- `onReturnToCategory` 处理器
- `onActiveFocusChanged` 中的重新启用逻辑
- DeviceSettingsDialog 中的 `requestDialogFocus` 连接

### 修复后的完整流程

**用户按左键返回大类**：
```
1. 用户在电机列表，按左键
2. MotorControlPage 接收 Keys.onLeftPressed
3. 设置 parent.currentFocusArea = 1 ✅
4. DeviceSettingsDialog 监听到 currentFocusArea 变化
5. DeviceSettingsDialog 自动处理焦点转移到左侧类别列表 ✅
6. 用户按上下键
7. DeviceSettingsDialog 切换类别 ✅
```

**用户从大类按右键进入电机控制**：
```
1. 用户在大类列表，按右键
2. DeviceSettingsDialog 设置 currentFocusArea = 2
3. MotorControlPage 获得焦点 ✅
4. 用户按上下键
5. NavigationManager 切换电机 ✅
```

## 📊 为什么这个方案更好？

### 简单性

**之前的方案**：
- 5个标志/信号
- 3个处理器
- 1个定时器
- 复杂的时序控制

**新方案**：
- 1行代码：`parent.currentFocusArea = 1`
- 利用现有的焦点管理系统
- 没有额外的标志或信号

### 可维护性

**之前的方案**：
- 难以理解
- 容易出现边界情况
- 需要处理各种时序问题

**新方案**：
- 逻辑清晰
- 没有边界情况
- 没有时序问题

### 可靠性

**之前的方案**：
- 依赖多个组件的协调
- 容易出现状态不一致

**新方案**：
- 只依赖现有的焦点管理系统
- 状态一致性由系统保证
