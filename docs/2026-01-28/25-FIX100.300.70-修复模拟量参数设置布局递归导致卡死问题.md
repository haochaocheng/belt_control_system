# FIX 100.300.70 - 修复模拟量参数设置布局递归导致卡死问题

**日期**: 2026-01-28
**文件**: `src/qml/components/device_info/pages/AnalogInputPage.qml`
**问题**: 点击模拟量参数设置，程序卡死，QDS 预览区域显示一片空白
**原因**: 使用 `parent.width / 2 - 22` 动态计算宽度导致布局递归重排

---

## 🐛 问题现象

### 错误日志

```
Warning: Qt Quick Layouts: Detected recursive rearrange. Aborting after two iterations.
Warning: Qt Quick Layouts: Detected recursive rearrange. Aborting after two iterations.
```

### 用户体验

1. **程序卡死**：点击模拟量参数设置后，程序无响应
2. **显示空白**：QDS 预览区域显示一片空白
3. **无法操作**：无法关闭对话框，无法进行任何操作

---

## 🔍 根本原因

### 布局递归重排

**问题代码**（FIX 100.300.69）：
```qml
ColumnLayout {
    Layout.fillWidth: true
    Layout.preferredWidth: parent.width / 2 - 22  // ❌ 动态计算导致递归
    ...
}
```

**递归过程**：
1. 父容器 `RowLayout` 的宽度依赖于子元素的 `preferredWidth`
2. 子元素的 `preferredWidth` 又依赖于父容器的 `width`
3. 形成循环依赖：`parent.width` → `child.preferredWidth` → `parent.width` → ...
4. 布局引擎不断重新计算，进入无限循环
5. Qt 检测到递归，中止布局，导致显示空白

### 为什么会发生

**QML 布局系统的工作原理**：
1. 父容器根据子元素的 `preferredWidth` 计算自己的宽度
2. 子元素根据父容器的 `width` 计算自己的实际宽度
3. 如果子元素的 `preferredWidth` 依赖于 `parent.width`，就会形成循环

**触发条件**：
- 使用 `Layout.preferredWidth: parent.width / 2`
- 同时使用 `Layout.fillWidth: true`
- 父容器也使用 `Layout.fillWidth: true`

---

## ✅ 解决方案

### 使用固定宽度

**修复代码**：
```qml
// 左列
ColumnLayout {
    Layout.fillWidth: true
    Layout.preferredWidth: 250  // ✅ 使用固定宽度，避免布局递归
    Layout.alignment: Qt.AlignTop
    spacing: 12
    ...
}

// 右列
ColumnLayout {
    Layout.fillWidth: true
    Layout.preferredWidth: 250  // ✅ 使用固定宽度，避免布局递归
    Layout.alignment: Qt.AlignTop
    spacing: 12
    ...
}
```

**为什么有效**：
- 固定宽度不依赖于父容器的宽度
- 打破了循环依赖
- 布局引擎可以正常计算

### 宽度选择

**左列宽度**：250px
- 标签宽度：120px
- 输入框宽度：约 120px
- 间距：10px
- 总计：250px

**右列宽度**：250px
- 标签宽度：140px
- 输入框宽度：约 100px
- 间距：10px
- 总计：250px

**分隔条**：2px + 左右边距各 20px = 42px

**总宽度**：250 + 42 + 250 = 542px（适合 800px 宽的对话框）

## 🎯 技术要点

### 1. QML 布局递归的常见原因

**循环依赖**：
```qml
// ❌ 错误：子元素宽度依赖父元素宽度
RowLayout {
    ColumnLayout {
        Layout.preferredWidth: parent.width / 2  // 依赖 parent.width
    }
}
```

**正确做法**：
```qml
// ✅ 正确：使用固定宽度或 Layout.fillWidth
RowLayout {
    ColumnLayout {
        Layout.preferredWidth: 250  // 固定宽度
    }
    ColumnLayout {
        Layout.fillWidth: true  // 填充剩余空间
    }
}
```

### 2. Layout.fillWidth vs Layout.preferredWidth

**Layout.fillWidth**：
- 填充剩余空间
- 不会导致递归（因为不依赖 parent.width）

**Layout.preferredWidth**：
- 指定首选宽度
- 如果使用 `parent.width` 计算，会导致递归

**最佳实践**：
- 使用固定的 `Layout.preferredWidth`
- 或者只使用 `Layout.fillWidth`，不设置 `preferredWidth`
- 避免 `Layout.preferredWidth: parent.width * ratio`

### 3. 如何检测布局递归

**警告信息**：
```
Warning: Qt Quick Layouts: Detected recursive rearrange. Aborting after two iterations.
```

**症状**：
- 程序卡死或无响应
- 界面显示空白
- CPU 占用率高

**调试方法**：
1. 查看控制台警告信息
2. 检查是否使用了 `parent.width` 计算 `preferredWidth`
3. 使用固定宽度替代动态计算
