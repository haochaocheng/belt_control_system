# FIX 100.300.77 - 明确设置 ScrollView contentWidth 解决运行时布局问题

**日期**: 2026-01-28
**问题**: QDS 预览时两列分开，但实际运行时还是单列布局
**根本原因**: ScrollBar.horizontal.policy: ScrollBar.AlwaysOff 阻止了 contentWidth 扩展
**解决方案**: 移除水平滚动条禁用，明确设置 contentWidth

---

## 🐛 问题现象

### QDS 预览 vs 实际运行

**QDS 预览**：
- ✅ 两列分开显示
- ✅ 充分利用右侧空间
- ✅ implicitWidth 生效

**实际运行**：
- ❌ 还是单列布局
- ❌ 右侧有大片空白
- ❌ implicitWidth 没有生效

---

## 🔍 根本原因

### ScrollBar.horizontal.policy: ScrollBar.AlwaysOff 的影响

**问题代码**：
```qml
ScrollView {
    ScrollBar.horizontal.policy: ScrollBar.AlwaysOff  // ❌ 禁用水平滚动条

    ColumnLayout {
        implicitWidth: 1200  // 想要 1200px 宽度
    }
}
```

**问题分析**：
1. `ScrollBar.horizontal.policy: ScrollBar.AlwaysOff` 禁用了水平滚动条
2. ScrollView 认为"既然没有水平滚动条，就不需要扩展 contentWidth"
3. contentWidth 被限制为内容的自然宽度（591px）
4. 即使设置了 implicitWidth: 1200，也不会生效

### 为什么 QDS 预览可以工作

**QDS 预览环境**：
- 可能使用不同的 Qt 版本或配置
- 对 implicitWidth 的处理更宽松
- 或者 ScrollView 的行为不同

**实际运行环境**：
- 严格遵守 ScrollBar.horizontal.policy
- 禁用水平滚动条 = 不扩展 contentWidth
- implicitWidth 被忽略

---

## ✅ 解决方案

### 1. 移除水平滚动条禁用

**修改位置**: `AnalogInputPage.qml` 第 235-251 行

**修改内容**：
```qml
ScrollView {
    Layout.fillWidth: true
    Layout.fillHeight: true
    clip: true

    // ✅ 2026-01-28 [FIX 100.300.77]: 移除水平滚动条禁用，让内容可以扩展
    // ScrollBar.horizontal.policy: ScrollBar.AlwaysOff  ← 注释掉
    ScrollBar.vertical.policy: ScrollBar.AsNeeded

    // ✅ 2026-01-28 [FIX 100.300.77]: 明确设置 contentWidth，确保内容可以充分展开
    contentWidth: Math.max(width, 1200)  // 至少 1200px，或者使用 ScrollView 的实际宽度
}
```

### 2. 明确设置 contentWidth

**为什么使用 Math.max(width, 1200)**：

```qml
contentWidth: Math.max(width, 1200)
```

**逻辑**：
- 如果 ScrollView 宽度 >= 1200px：使用 ScrollView 宽度（不出现水平滚动条）
- 如果 ScrollView 宽度 < 1200px：使用 1200px（出现水平滚动条）

**效果**：
- 在 1920×1080 屏幕：ScrollView 宽度 = 1178px，contentWidth = 1178px ✅
- 在 1280×800 屏幕：ScrollView 宽度 = 约 600px，contentWidth = 1200px（出现水平滚动条）

## 🎯 技术要点

### 1. ScrollBar.horizontal.policy 的影响

**AlwaysOff**：
```qml
ScrollBar.horizontal.policy: ScrollBar.AlwaysOff
```
- 禁用水平滚动条
- ScrollView 不会扩展 contentWidth
- 内容被压缩到 ScrollView 宽度

**默认（AsNeeded）**：
```qml
// 不设置，或者：
ScrollBar.horizontal.policy: ScrollBar.AsNeeded
```
- 根据需要显示水平滚动条
- 如果 contentWidth > width，显示滚动条
- 如果 contentWidth <= width，不显示滚动条

### 2. contentWidth 的设置

**自动计算（默认）**：
```qml
ScrollView {
    // contentWidth 由内容的 implicitWidth 决定
}
```
- 依赖内容的 implicitWidth
- 可能不准确

**明确设置（推荐）**：
```qml
ScrollView {
    contentWidth: Math.max(width, 1200)
}
```
- 明确告诉 ScrollView 内容需要多宽
- 更可靠

### 3. 为什么不直接设置 contentWidth: 1200

**问题**：
```qml
contentWidth: 1200  // 固定 1200px
```
- 在大屏幕上（如 1920×1080），ScrollView 宽度 = 1178px
- contentWidth = 1200px > 1178px
- 会出现不必要的水平滚动条

**解决**：
```qml
contentWidth: Math.max(width, 1200)  // 动态调整
```
- 在大屏幕上：contentWidth = 1178px（无滚动条）
- 在小屏幕上：contentWidth = 1200px（有滚动条）
