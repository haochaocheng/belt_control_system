## 🐛 问题分析

### FIX 100.300.99 失败原因

**QDS 测试日志分析** (`docs/log/pjsip.md`):

```
Line 109: [Screen01] 回车键 - 打开设备设置对话框
Line 124: [Screen01] DeviceSettingsDialog 已打开
Line 125-162: [Screen01] 按键事件 - Key: 16777237 焦点: ?
              [Screen01] 导航成功: ↓ 下 - 索引 1 → 5
```

**关键发现**:
1. ❌ **没有看到 DeviceSettingsDialog 的焦点获取日志**
2. ❌ **Timer 根本没有启动** - 没有 "延迟焦点获取" 日志
3. ❌ **Screen01 持续接收所有按键事件**

### 根本原因

**`onVisibleChanged` 没有触发**！

原因：
1. DeviceSettingsDialog 是动态创建的 (`Qt.createComponent` + `createObject`)
2. Rectangle 的 `visible` 默认值是 `true`
3. Screen01 设置 `dialog.visible = true` 时，**没有变化**
4. 所以 `onVisibleChanged` 根本不会触发

**代码证据** (`Screen01.qml:166-172`):
```qml
var dialog = component.createObject(root.parent, {
    // 创建时 visible 已经是 true（Rectangle 默认值）
})
if (dialog) {
    dialog.visible = true  // ❌ 没有变化，不会触发 onVisibleChanged
    dialog.z = 1000
}
```

## 🔧 解决方案

### FIX 100.300.100: 完整模态遮罩方案

**核心思路**:
1. **全屏 MouseArea 遮罩** - 阻止所有鼠标和键盘事件传播到主界面
2. **FocusScope** - 创建独立的焦点作用域，隔离对话框和主界面
3. **Component.onCompleted** - 在组件创建完成时强制获取焦点（不依赖 visible 变化）
4. **三层结构** - Item (容器) → MouseArea (遮罩) + FocusScope (焦点) → Rectangle (对话框)

Component.onCompleted: {
    keyboardManager.initialize(virtualKeyboard)
    console.log("✅ [DeviceSettingsDialog] 虚拟键盘管理器已初始化")

focus: true

Timer {
    id: focusTimer
    interval: 100
    running: false
    repeat: true
    property int retryCount: 0
    property int maxRetries: 5

    onTriggered: {
        retryCount++
        root.forceActiveFocus()
        console.log("✅ [DeviceSettingsDialog] 延迟焦点获取 (尝试 " + retryCount + "/" + maxRetries + ")")

        if (retryCount >= maxRetries) {
            stop()
            retryCount = 0
            console.log("✅ [DeviceSettingsDialog] 焦点获取完成")
        }
    }
}

onVisibleChanged: {
    if (visible) {
        root.forceActiveFocus()
        focusTimer.retryCount = 0
        focusTimer.restart()
        console.log("✅ [DeviceSettingsDialog] 对话框显示，开始获取焦点...")
    } else {
        focusTimer.stop()
        console.log("✅ [DeviceSettingsDialog] 对话框已关闭，焦点返回主界面")
    }
}

## 📚 技术说明

### 为什么需要 MouseArea 遮罩？

**问题**:
- Rectangle 不会自动阻止事件传播
- 没有遮罩，主界面仍然可以接收鼠标和键盘事件

**解决**:
- MouseArea 覆盖整个屏幕
- `propagateComposedEvents: false` 阻止事件传播
- `hoverEnabled: true` 阻止鼠标悬停事件传播
- 所有鼠标事件处理器都设置 `mouse.accepted = true`

### 为什么需要 FocusScope？

**QML 焦点系统**:
- 每个 Window 有一个焦点树
- FocusScope 创建一个子焦点树
- 焦点在 FocusScope 内部独立管理
- 外部元素无法抢夺 FocusScope 内的焦点

**优势**:
- 隔离对话框和主界面的焦点管理
- 确保焦点在对话框内部循环
- 防止主界面抢夺焦点

### 为什么使用 Component.onCompleted？

**问题**:
- `onVisibleChanged` 不会触发（visible 默认值已经是 true）
- Timer 方案依赖 `onVisibleChanged`，所以也不会执行

**解决**:
- `Component.onCompleted` 在组件创建完成时**必定触发**
- 不依赖 `visible` 属性变化
- 可靠性 100%
