# FIX 100.300.98 - 修复对话框焦点管理问题

**日期**: 2026-01-28
**问题**: 对话框弹出后，焦点仍在主界面，导航键控制主界面而非对话框
**状态**: 待修复 ⏳

---

## 🐛 问题描述

### 当前行为

1. 在主界面选择一个组件（如"开关量输入"）
2. 按 Enter 键 → 弹出 DeviceSettingsDialog
3. 在对话框中按导航键（上/下）→ 焦点仍在主界面的左侧菜单
4. 焦点在"基本配置"和"开关量输入"之间切换

### 预期行为

- 对话框弹出后，焦点应该立即转移到对话框内部
- 导航键应该控制对话框内的焦点切换
- 主界面应该停止响应键盘事件
- 对话框关闭后，焦点应该返回主界面

---

## 🔍 根本原因

### 1. 焦点管理问题

**DeviceSettingsDialog.qml** (Line 52):
```qml
focus: true
```

虽然设置了 `focus: true`，但是：
- 对话框弹出时，焦点没有**强制**转移到对话框
- 主界面仍然保持焦点，继续接收键盘事件
- QML 的焦点系统需要显式的焦点转移

### 2. 焦点作用域问题

DeviceSettingsDialog 是一个 Rectangle，不是 Dialog 或 Popup：
- Rectangle 不会自动获取焦点
- 需要手动调用 `forceActiveFocus()` 来强制获取焦点
- 需要在 `visible` 变化时触发焦点转移

### 3. 键盘事件传播问题

- 主界面和对话框都定义了键盘事件处理
- 没有阻止事件向下传播
- 导致主界面仍然接收键盘事件

---

## 🔧 解决方案

### 方案 1: 使用 forceActiveFocus()（推荐）

在对话框显示时，强制获取焦点：

```qml
Rectangle {
    id: root
    focus: true

    // ✅ 监听 visible 变化，自动获取焦点
    onVisibleChanged: {
        if (visible) {
            root.forceActiveFocus()
            console.log("✅ [DeviceSettingsDialog] 焦点已转移到对话框")
        }
    }

    // 现有的键盘事件处理...
    Keys.onUpPressed: { ... }
    Keys.onDownPressed: { ... }
}
```

### 方案 2: 使用 FocusScope（更完善）

使用 FocusScope 包装对话框内容，确保焦点管理正确：

```qml
Rectangle {
    id: root

    FocusScope {
        id: dialogFocusScope
        anchors.fill: parent
        focus: true

        onVisibleChanged: {
            if (visible) {
                dialogFocusScope.forceActiveFocus()
            }
        }

        Keys.onUpPressed: { ... }
        Keys.onDownPressed: { ... }

        // 对话框内容...
    }
}
```

### 方案 3: 添加 MouseArea 阻止事件传播

在对话框最外层添加 MouseArea，阻止键盘和鼠标事件传播到主界面：

```qml
Rectangle {
    id: root
    focus: true

    // ✅ 阻止事件传播到主界面
    MouseArea {
        anchors.fill: parent
        onClicked: {
            root.forceActiveFocus()
            mouse.accepted = true
        }
        // 阻止所有鼠标事件传播
        propagateComposedEvents: false
    }

    onVisibleChanged: {
        if (visible) {
            root.forceActiveFocus()
        }
    }
}
```

## 📝 推荐实施方案

**结合方案 1 和方案 3**，既简单又有效：

### 修改 DeviceSettingsDialog.qml

**位置**: Line 52 附近

**修改前**:
```qml
// ✅ 2026-01-24 [FIX]: 键盘导航支持
focus: true

Keys.onUpPressed: {
    // 上键：选择上一个类别
    if (root.currentCategory > 0) {
        root.currentCategory--
        root.currentBottomButtonIndex = 0
    }
}
```

**修改后**:
```qml
// ✅ 2026-01-24 [FIX]: 键盘导航支持
// ✅ 2026-01-28 [FIX 100.300.98]: 强制获取焦点，阻止主界面接收键盘事件
focus: true

// ✅ 2026-01-28 [FIX 100.300.98]: 对话框显示时强制获取焦点
onVisibleChanged: {
    if (visible) {
        root.forceActiveFocus()
        console.log("✅ [DeviceSettingsDialog] 焦点已转移到对话框")
    } else {
        console.log("✅ [DeviceSettingsDialog] 对话框已关闭，焦点返回主界面")
    }
}

Keys.onUpPressed: {
    // 上键：选择上一个类别
    if (root.currentCategory > 0) {
        root.currentCategory--
        root.currentBottomButtonIndex = 0
    }
}
```

### 可选：添加全局 MouseArea（如果上述方案不够）

在 Rectangle 的最外层（Line 13 之后）添加：

```qml
Rectangle {
    id: root

    // ... 现有属性 ...

    // ✅ 2026-01-28 [FIX 100.300.98]: 阻止事件传播到主界面
    MouseArea {
        anchors.fill: parent
        z: -100  // 放在最底层，不影响内部组件
        onPressed: {
            root.forceActiveFocus()
            mouse.accepted = false  // 允许事件传递给子组件
        }
        // 阻止键盘事件传播
        Keys.forwardTo: [root]
    }

    // ... 现有内容 ...
}
```
