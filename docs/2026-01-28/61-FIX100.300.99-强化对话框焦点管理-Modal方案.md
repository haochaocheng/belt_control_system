# FIX 100.300.99 - 强化对话框焦点管理（Modal 方案）

**日期**: 2026-01-28
**问题**: FIX 100.300.98 的 forceActiveFocus() 方案无效，焦点仍在主界面
**状态**: 待修复 ⏳

---

## 🐛 问题分析

### FIX 100.300.98 失败原因

1. **Rectangle 不是模态组件**
   - DeviceSettingsDialog 使用 Rectangle，不是 Dialog 或 Popup
   - Rectangle 不会自动阻止背后元素接收事件
   - 主界面仍然可以接收键盘事件

2. **forceActiveFocus() 不够强力**
   - 主界面 Screen01 设置了 `focus: true` 和 `activeFocusOnTab: true`
   - 主界面持续监听焦点变化并尝试重新获取焦点
   - `forceActiveFocus()` 被主界面的焦点管理覆盖

3. **缺少模态遮罩**
   - 没有全屏遮罩阻止点击和键盘事件传播到主界面
   - 主界面仍然是活动的焦点作用域

---

## 🔧 解决方案

### 方案：添加模态遮罩 + FocusScope + 延迟焦点获取

**核心思路**:
1. 添加全屏 MouseArea 作为模态遮罩，阻止事件传播
2. 使用 FocusScope 包装对话框内容，创建独立的焦点作用域
3. 使用 Timer 延迟获取焦点，确保在主界面之后执行
4. 设置 z-index 确保对话框在最顶层

---

## 📝 实施步骤

### 修改 DeviceSettingsDialog.qml

**位置**: Line 13 开始

**修改方案**:

```qml
// ✅ 2026-01-28 [FIX 100.300.99]: 添加模态遮罩层
Rectangle {
    id: modalOverlay
    anchors.fill: parent
    color: "#80000000"  // 半透明黑色遮罩
    visible: root.visible
    z: 999  // 确保在最顶层

    // ✅ 阻止所有鼠标和键盘事件传播到主界面
    MouseArea {
        anchors.fill: parent
        onClicked: {
            // 点击遮罩时，强制对话框获取焦点
            dialogFocusScope.forceActiveFocus()
            mouse.accepted = true
        }
        onPressed: mouse.accepted = true
        onReleased: mouse.accepted = true
        onWheel: wheel.accepted = true
        // 阻止所有事件传播
        propagateComposedEvents: false
        hoverEnabled: true
    }

    // ✅ 2026-01-28 [FIX 100.300.99]: 使用 FocusScope 创建独立焦点作用域
    FocusScope {
        id: dialogFocusScope
        anchors.centerIn: parent
        width: parent.width * 0.8
        height: parent.height * 0.8
        focus: true  // FocusScope 获取焦点

        Rectangle {
            id: root
            anchors.fill: parent
            color: "#ec1e1e1e"

            // ✅ 2026-01-28 [FIX 100.300.99]: 延迟获取焦点
            Timer {
                id: focusTimer
                interval: 50  // 延迟 50ms
                running: false
                repeat: false
                onTriggered: {
                    dialogFocusScope.forceActiveFocus()
                    root.forceActiveFocus()
                    console.log("✅ [DeviceSettingsDialog] 延迟焦点获取完成")
                }
            }

            // ✅ 2026-01-28 [FIX 100.300.99]: 监听 visible 变化
            onVisibleChanged: {
                if (visible) {
                    // 立即获取焦点
                    dialogFocusScope.forceActiveFocus()
                    root.forceActiveFocus()
                    // 延迟再次获取焦点，确保覆盖主界面
                    focusTimer.restart()
                    console.log("✅ [DeviceSettingsDialog] 对话框显示，焦点转移中...")
                } else {
                    console.log("✅ [DeviceSettingsDialog] 对话框关闭，焦点返回主界面")
                }
            }

            // 现有的键盘事件处理...
            Keys.onUpPressed: { ... }
            Keys.onDownPressed: { ... }

            // 对话框内容...
        }
    }
}
```

## 📝 实施细节

### 1. 模态遮罩层

```qml
Rectangle {
    id: modalOverlay
    anchors.fill: parent
    color: "#80000000"  // 半透明黑色
    visible: root.visible
    z: 999

    MouseArea {
        anchors.fill: parent
        onClicked: {
            dialogFocusScope.forceActiveFocus()
            mouse.accepted = true
        }
        propagateComposedEvents: false
        hoverEnabled: true
    }
}
```

**作用**:
- 全屏覆盖，阻止点击主界面
- 半透明黑色，提供视觉反馈
- MouseArea 阻止所有鼠标和键盘事件传播

### 2. FocusScope 焦点作用域

```qml
FocusScope {
    id: dialogFocusScope
    anchors.centerIn: parent
    width: parent.width * 0.8
    height: parent.height * 0.8
    focus: true
}
```

**作用**:
- 创建独立的焦点作用域
- 隔离对话框和主界面的焦点管理
- 确保焦点在对话框内部循环

### 3. 延迟焦点获取

```qml
Timer {
    id: focusTimer
    interval: 50
    running: false
    repeat: false
    onTriggered: {
        dialogFocusScope.forceActiveFocus()
        root.forceActiveFocus()
    }
}

onVisibleChanged: {
    if (visible) {
        dialogFocusScope.forceActiveFocus()
        root.forceActiveFocus()
        focusTimer.restart()
    }
}
```

**作用**:
- 立即获取焦点（第一次尝试）
- 延迟 50ms 再次获取焦点（确保覆盖主界面）
- 双重保险，确保焦点转移成功

## 📚 技术说明

### 为什么需要 FocusScope？

QML 的焦点系统是层级的：
- 每个 Window 有一个焦点树
- FocusScope 创建一个子焦点树
- 焦点在 FocusScope 内部独立管理
- 外部元素无法抢夺 FocusScope 内的焦点

### 为什么需要延迟获取焦点？

- QML 的焦点系统是异步的
- visible 变化后，焦点系统需要时间更新
- 主界面可能在 visible 变化后尝试重新获取焦点
- 延迟 50ms 确保在主界面之后执行

### 为什么需要模态遮罩？

- Rectangle 不会自动阻止事件传播
- 没有遮罩，主界面仍然可以接收鼠标和键盘事件
- 遮罩提供视觉反馈，表明对话框是模态的
