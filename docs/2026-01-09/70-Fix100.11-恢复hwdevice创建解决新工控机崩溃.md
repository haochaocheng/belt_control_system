# Fix 100.11 - 恢复 hwdevice 创建，解决新工控机崩溃

**修复编号**: Fix 100.11
**日期**: 2026-01-10 14:20
**类型**: 关键修复
**影响**: 新工控机（192.168.1.8）视频通话崩溃

---

## 问题现象

### 崩溃点

在新工控机（192.168.1.8）上，视频通话**立即崩溃**：

```
13:55:29.820  ffmpeg_vid_codecs.c  .......✅ [FIX 84] Detected RKMPP decoder: h264_rkmpp
13:55:29.820  ffmpeg_vid_codecs.c  .......   Strategy: Hybrid mode (VPU decode + system memory output)
13:55:29.820  ffmpeg_vid_codecs.c  .......   ❌ NOT creating hwdevice → avoid DRM_PRIME → get_format works
13:55:29.820  ffmpeg_vid_codecs.c  .......   ✅ VPU hardware decode → NV12/I420 system memory → RemoteVideoManager
13:55:29.820  ffmpeg_vid_codecs.c  .......   ✅ get_format callback set (will select NV12 or I420)
Application exited with code: 139
```

**Exit Code**: 139 (SIGSEGV - 段错误)

### 崩溃位置

**文件**: `cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-codec/ffmpeg_vid_codecs.c`
**行号**: Line 2214

```c
dec_err = avcodec_open2(ff->dec_ctx, ff->dec, NULL);  // ← 在这里崩溃
```

---

## 问题诊断

### 关键发现

1. **旧工控机（192.168.10.188）**：
   - Fix 84 工作正常（不创建 hwdevice）
   - 视频通话稳定

2. **新工控机（192.168.1.8）**：
   - Fix 84 崩溃（不创建 hwdevice）
   - 崩溃在 `avcodec_open2()` **内部**
   - 没有返回错误码，直接 SIGSEGV

### 根本原因

**不同设备的 RKMPP 驱动版本不同**：

- **旧工控机**：RKMPP 解码器支持"混合模式"
  - 可以不创建 hwdevice
  - 自动输出到系统内存（NV12/I420）

- **新工控机**：RKMPP 解码器**必须有 hwdevice**
  - 不创建 hwdevice → 解码器初始化失败
  - 空指针解引用或其他内部错误
  - 导致 SIGSEGV 崩溃

### 用户发现的线索

用户注意到日志中的：
```
❌ NOT creating hwdevice → avoid DRM_PRIME → get_format works
```

这一行暴露了 Fix 84 的策略：**不创建 hwdevice**。正是这个策略在新工控机上导致了崩溃。

---

## 解决方案

### Fix 100.11 策略

**恢复 hwdevice 创建，但保留 get_format 回调**（尝试两全其美）：

1. ✅ **创建 hwdevice** → 满足新工控机 RKMPP 驱动要求
2. ✅ **保留 get_format 回调** → 仍然尝试选择 NV12/I420 系统内存格式
3. ✅ **优雅处理失败** → 如果 hwdevice 创建失败，继续尝试（可能崩溃，但至少有日志）

### 修改代码

**位置**: `ffmpeg_vid_codecs.c:2203-2223`

```c
// ✅ 2026-01-10 14:20 [修复 100.11] 恢复 hwdevice 创建（解决新工控机崩溃）
// 问题：新工控机（192.168.1.8）RKMPP 解码器需要 hwdevice 才能初始化
// 根因：不同设备的 RKMPP 驱动版本不同，新工控机的驱动要求必须有 hwdevice
// 证据：旧工控机 Fix 84 正常，新工控机崩溃在 avcodec_open2() 内部
// 解决：恢复 hwdevice 创建，但保留 get_format 回调（尝试两全其美）
int hwdev_err = av_hwdevice_ctx_create(&ctx->hw_device_ctx,
                                         AV_HWDEVICE_TYPE_RKMPP,
                                         "/dev/dri/renderD128", NULL, 0);
if (hwdev_err < 0) {
    char errbuf[128];
    av_strerror(hwdev_err, errbuf, sizeof(errbuf));
    PJ_LOG(2,(THIS_FILE, "   ⚠️ [FIX 100.11] hwdevice_ctx_create failed: %d (%s)", hwdev_err, errbuf));
    PJ_LOG(2,(THIS_FILE, "      Will try without hwdevice (may crash on some devices)"));
} else {
    PJ_LOG(1,(THIS_FILE, "   ✅ [FIX 100.11] hwdevice created: /dev/dri/renderD128"));
}

// ✅ 设置 get_format 回调（让 PJSIP 选择 NV12）
// 注意：即使有 hwdevice，get_format 回调仍然可能被调用（取决于解码器实现）
ctx->get_format = pjmedia_ffmpeg_get_format;
PJ_LOG(1,(THIS_FILE, "   ✅ get_format callback set (will select NV12 or I420)"));
```

## 可能的副作用

### 如果 hwdevice 导致 DRM_PRIME 强制输出

**症状**：
- 视频通话建立，但无法显示对方视频
- 日志显示大量解码错误

**原因**：
- hwdevice → 强制 DRM_PRIME 格式（GPU 内存）
- get_format 回调被跳过
- RemoteVideoManager 无法访问 GPU 内存

**解决方案**：
- 如果出现此问题，需要添加环境变量开关
- 允许用户选择："hwdevice 模式" vs "混合模式"

## 备用方案

### 如果 Fix 100.11 仍然崩溃

**可能原因**：
- `/dev/dri/renderD128` 不存在或权限不足
- RKMPP 驱动完全损坏

**解决方案**：
1. 检查 DRM 设备：`ls -la /dev/dri/`
2. 检查容器权限：`docker exec belt-control-app ls -la /dev/dri/`
3. 使用 **Core Dump 分析**（scripts/2026-01-09/19-enable-core-dump.ps1）

### 如果 Fix 100.11 导致 DRM_PRIME 问题

**可能原因**：
- hwdevice 导致强制 DRM_PRIME 输出
- RemoteVideoManager 无法访问 GPU 内存

**解决方案**：
1. 添加环境变量开关 `USE_RKMPP_HWDEVICE`
2. 允许用户选择策略
3. 可能需要实现 DRM_PRIME → 系统内存的转换（复杂）

## 关键要点

### ⚠️ 重要

1. **不同设备的 RKMPP 驱动行为不同**
   - 不能假设所有设备支持相同的初始化方式
   - 需要根据设备适配策略

2. **hwdevice 是双刃剑**
   - 优点：某些设备必须有 hwdevice 才能工作
   - 缺点：可能导致 DRM_PRIME 强制输出，RemoteVideoManager 无法访问

3. **Fix 100.11 是妥协方案**
   - 创建 hwdevice → 避免新工控机崩溃
   - 保留 get_format 回调 → 尝试选择系统内存格式
   - 可能需要进一步优化
