## 🎯 RKMPP 编码器工作原理

### 内部转换机制

根据 libavcodec/rkmppenc.c 的实现：

```
输入：I420 软件帧（avframe.format = 0）
  ↓
RKMPP 编码器接收帧
  ↓
检查 hw_device_ctx
  ↓ （如果 hw_device_ctx 存在）
内部分配 r->hwframe（DRM_PRIME buffer）
  ↓
自动转换 I420 → DRM_PRIME（使用 RGA 硬件加速）
  ↓
硬件编码器处理 DRM_PRIME 帧
  ↓
输出：H.264 编码数据
```

**关键**:
- **我们**不需要手动转换格式（"no hardware conversion needed" 指的是这个）
- **编码器内部**会自动转换并使用硬件加速
- hw_device_ctx 存在 → 编码器知道如何访问 RKMPP 硬件

## 📊 日志解读

### 误导性日志分析

**日志内容**:
```
Encoder: h264_rkmpp (software codec, no hardware conversion needed)
```

**正确解读**:
- `h264_rkmpp`: ✅ 正确，使用的是 RKMPP 编码器
- `software codec`: ❌ **误导**，应该是 "hardware codec"
- `no hardware conversion needed`: ✅ 部分正确，意思是我们不需要手动转换格式

**应该显示**:
```
Encoder: h264_rkmpp (hardware codec, internal format conversion via RGA)
```

或者更详细：
```
Encoder: h264_rkmpp (hardware codec with hw_device_ctx)
  Input: I420 software frames
  Internal: Auto-convert to DRM_PRIME via RGA
  Hardware: VPU encoding
```

## 🔧 修复方案：Fix 97.2

### 修改目标

更新 Line 2987-2988 的日志，准确反映编码器工作模式。

### 修改内容

**文件**: [ffmpeg_vid_codecs.c:2985-2991](../../cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-codec/ffmpeg_vid_codecs.c#L2985-L2991)

#### 修改前（误导性日志）
```c
// ✅ 2026-01-06 11:30 [Fix 55] 修正日志 - 实际使用 libx264 软件编码器，不是 RKMPP
if (ff->enc_ctx && ff->enc_ctx->codec) {
    PJ_LOG(1,(THIS_FILE, "    Encoder: %s (software codec, no hardware conversion needed)",
              ff->enc_ctx->codec->name));
} else {
    PJ_LOG(1,(THIS_FILE, "    Encoder: Unknown (ctx or codec is NULL)"));
}
```

#### 修改后（Fix 97.2 - 准确日志）
```c
// ✅ 2026-01-09 18:35 [修复 97.2] 准确显示编码器工作模式
if (ff->enc_ctx && ff->enc_ctx->codec) {
    const char *codec_name = ff->enc_ctx->codec->name;
    const char *mode_desc = "unknown mode";

    // 检查是否为 RKMPP 硬件编码器
    if (pj_ansi_strstr(codec_name, "rkmpp") != NULL) {
        if (ff->enc_ctx->hw_device_ctx) {
            mode_desc = "hardware codec with hw_device_ctx, auto-convert I420→DRM_PRIME via RGA";
        } else {
            mode_desc = "hardware codec without hw_device_ctx (may fail)";
        }
    } else {
        // 软件编码器（libx264, libx265 等）
        mode_desc = "software codec, no hardware acceleration";
    }

    PJ_LOG(1,(THIS_FILE, "    Encoder: %s (%s)", codec_name, mode_desc));

    // 额外调试信息
    if (ff->enc_ctx->hw_device_ctx) {
        PJ_LOG(1,(THIS_FILE, "      hw_device_ctx: %p", ff->enc_ctx->hw_device_ctx));
    } else {
        PJ_LOG(1,(THIS_FILE, "      hw_device_ctx: NULL"));
    }
} else {
    PJ_LOG(1,(THIS_FILE, "    Encoder: Unknown (ctx or codec is NULL)"));
}
```

**关键变化**:
1. ✅ 动态检查 `ff->enc_ctx->hw_device_ctx` 是否存在
2. ✅ 根据编码器名称和 hw_device_ctx 状态输出准确描述
3. ✅ 对于 RKMPP 编码器，说明内部转换机制
4. ✅ 输出 hw_device_ctx 地址，方便调试
