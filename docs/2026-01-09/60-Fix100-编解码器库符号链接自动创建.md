# Fix 100：编解码器库符号链接自动创建

**日期**: 2026-01-10 00:50
**问题**: PJSIP configure 失败 "cannot find -lx264"
**根本原因**: 容器 sysroot 中只有版本化库文件（libx264.so.164），缺少通用链接名（libx264.so）
**状态**: ✅ **已修复 - 自动创建符号链接**

---

## 🎯 修复目标

在 PJSIP 编译前自动创建所有编解码器库的符号链接，确保 configure 和链接器能找到库文件。

---

## 📊 问题分析

### 错误现象

**执行**: `.\build-ubuntu24-apt.ps1 192.168.10.188`

**错误输出**:
```
checking whether the C compiler works... no
aconfigure: error: C compiler cannot create executables
See `config.log' for more details

config.log 内容:
/usr/lib/gcc-cross/aarch64-linux-gnu/13/../../../../aarch64-linux-gnu/bin/ld:
cannot find -lx264: No such file or directory
/usr/lib/gcc-cross/aarch64-linux-gnu/13/../../../../aarch64-linux-gnu/bin/ld:
cannot find -lx265: No such file or directory
/usr/lib/gcc-cross/aarch64-linux-gnu/13/../../../../aarch64-linux-gnu/bin/ld:
cannot find -lvpx: No such file or directory
```

### 根本原因

1. **库文件命名**:
   - 容器中存在：`/opt/rk3588-sysroot/usr/lib/aarch64-linux-gnu/libx264.so.164`
   - 链接器需要：`libx264.so`（通用链接名）

2. **链接器行为**:
   - configure 测试：`gcc -o conftest -lx264 conftest.c`
   - 链接器搜索：`libx264.so`（不是 `libx264.so.164`）
   - 结果：找不到库文件 → configure 失败

3. **缺少的库**:
   ```bash
   # 以下库文件需要符号链接：
   libx264.so.164 → libx264.so
   libx265.so.199 → libx265.so
   libvpx.so.7.0.0 → libvpx.so
   libwebp.so.7 → libwebp.so
   libdav1d.so.7 → libdav1d.so
   libaom.so.3 → libaom.so
   ... （共 20+ 个编解码器库）
   ```

### 修改位置

**文件**: `build-ubuntu24-apt.ps1`
**行号**: Line 311-337
**时机**: 复制 sysroot 到容器后，configure 前

### 修改内容

## 📋 实施过程

### 第一次尝试（失败）

**方法**: 使用 PowerShell here-string 语法 `@"..."@`

**问题**: Here-string 在 `docker exec` 中没有正确执行，可能是换行符或转义问题

**现象**:
- 脚本显示：`✓ 符号链接创建完成`
- 实际验证：符号链接不存在
- configure 仍然失败

### 第二次尝试（成功）

**方法**: 使用单独的 `docker exec` 命令，每条命令创建一组符号链接

**优点**:
- ✅ 每个命令独立执行，易于调试
- ✅ 避免 here-string 的转义问题
- ✅ 可以单独验证每组链接

**验证**:
```powershell
# 验证命令
$x264Check = docker exec $pjsipContainerName sh -c "test -L /opt/rk3588-sysroot/usr/lib/aarch64-linux-gnu/libx264.so && echo 'OK' || echo 'FAIL'"

# 输出：OK（符号链接存在）
```

## 🔍 为什么第一次修复不够？

虽然符号链接创建成功，但 configure 仍然失败，因为还有更深层的问题：**LDFLAGS 优先级错误**（见 [61-Fix101-LDFLAGS优先级修正.md](61-Fix101-LDFLAGS优先级修正.md)）。

Fix 100 只是解决了符号链接问题，但链接器搜索路径优先级错误导致仍然找不到库。

## 📖 技术细节

### 符号链接的作用

**Linux 库命名约定**（soname 机制）:
```bash
# 实际库文件（包含版本号）
libx264.so.164        # 完整版本

# SONAME 链接（主版本号）
libx264.so.164 → libx264.so.164

# 开发链接（用于编译/链接）
libx264.so → libx264.so.164
```

**为什么需要符号链接**:
1. **编译时**：编译器使用 `-lx264` 查找 `libx264.so`
2. **运行时**：动态链接器根据 SONAME 加载 `libx264.so.164`
3. **版本管理**：可以同时安装多个版本，通过符号链接选择使用哪个版本

### 交叉编译中的库路径

**宿主机** (x86_64):
```bash
/usr/lib/x86_64-linux-gnu/libx264.so.164  # 宿主机库（不能用于交叉编译）
```

**目标机 sysroot** (aarch64):
```bash
/opt/rk3588-sysroot/usr/lib/aarch64-linux-gnu/libx264.so.164  # 目标机库（需要符号链接）
/opt/rk3588-sysroot/usr/lib/aarch64-linux-gnu/libx264.so     # ← 需要创建这个
```

**为什么宿主机的库不能用**:
- 宿主机库是 x86_64 架构（不兼容 aarch64）
- 交叉编译必须使用目标机的库
