## 📊 问题分析

### 错误现象

**日志输出**（voip.md 最后一行）:
```
x264 [error]: baseline profile doesn't support 4:4:4
```

**关键日志** (Line -9):
```
10:26:28.648    ffmpeg_vid_codecs.c  .......✅ [PIX_FMT] Using encoder preferred format: 121 (libx264rgb)
```

### 根本原因

1. **像素格式 121 = libx264rgb = RGB 4:4:4**:
   - 代码 Line 1967 使用编码器首选格式：`ctx->pix_fmt = ff->enc->pix_fmts[0];`
   - 旧版 libx264.so.160 的首选格式是 libx264rgb（RGB 4:4:4）
   - H.264 baseline profile 只支持 4:2:0（YUV420P），不支持 4:4:4

2. **libx264 版本问题**:
   ```
   libx264.so.160  ← 旧版本（1.3 MB，2021年）❌ 首选格式可能是 RGB
   libx264.so.165  ← 新版本（1.4 MB，2025-12-23）✅ 首选格式可能是 YUV420P
   libx264.so → libx264.so.160  ❌ 符号链接指向旧版本！
   ```

3. **用户发现**:
   - 用户打开 voip.md，查看日志发现崩溃
   - 用户指出："libx264.so.165，应该使用这个最新的"

## 📖 技术细节

### H.264 Profile 和像素格式限制

**H.264 Profiles**:
```
Baseline Profile (最常用):
  - 像素格式：4:2:0 (YUV420P)
  - 不支持：4:4:4（所有颜色分量全分辨率）
  - 应用：视频会议、移动设备

High Profile:
  - 像素格式：4:2:0, 4:2:2, 4:4:4
  - 支持：RGB 4:4:4
  - 应用：高清视频、专业视频编辑
```

**为什么 baseline 不支持 4:4:4**:
- Baseline Profile 为低功耗设备设计
- 4:4:4 数据量是 4:2:0 的 3 倍
- 编码复杂度和带宽需求更高

### libx264 像素格式首选列表

**编码器注册时的 pix_fmts 数组**:
```c
// libx264 (旧版可能)

    },
};

// libx264 (新版可能)
AVCodec ff_libx264_encoder = {
    .pix_fmts = (const enum AVPixelFormat[]) {

    },
};
```

## 📝 教训总结

### 不要盲目使用编码器首选格式

**错误做法**:
```c
if (ff->enc && ff->enc->pix_fmts) {
    ctx->pix_fmt = ff->enc->pix_fmts[0];  // ← 盲目使用首选格式
}
```

**正确做法**:
```c
// 强制使用 YUV420P（H.264 标准格式）
ctx->pix_fmt = AV_PIX_FMT_YUV420P;

// 或者检查编码器支持的格式
if (ff->enc && ff->enc->pix_fmts) {
    for (int i = 0; ff->enc->pix_fmts[i] != AV_PIX_FMT_NONE; i++) {
        if (ff->enc->pix_fmts[i] == AV_PIX_FMT_YUV420P) {
            ctx->pix_fmt = AV_PIX_FMT_YUV420P;
            break;
        }
    }
}
```

### 检查符号链接的目标版本

**问题**:
- 下载新库后，符号链接可能仍指向旧版本
- 旧版本可能有已知的 bug 或不兼容问题

**解决**:
- 定期检查符号链接：`ls -la *.so`
- 确保指向最新版本：`ln -sf libx264.so.165 libx264.so`
