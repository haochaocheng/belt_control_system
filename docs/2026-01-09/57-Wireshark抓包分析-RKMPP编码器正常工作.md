## 📊 STAP-A 格式分析

### STAP-A（Single-Time Aggregation Packet）是什么？

根据 **RFC 6184**（RTP Payload Format for H.264 Video）：

**STAP-A 格式**:
```
RTP Header
|
+-- NAL Unit Type = 24 (STAP-A)
|
+-- NAL Unit 1 Size (2 bytes) = SPS 大小
+-- NAL Unit 1 Data = SPS
|
+-- NAL Unit 2 Size (2 bytes) = PPS 大小
+-- NAL Unit 2 Data = PPS
```

**作用**:
- 将**多个小的 NAL 单元**（如 SPS + PPS）**打包到一个 RTP 包**中
- 避免为每个 NAL 单元单独发送 RTP 包（减少网络开销）
- **节省带宽和减少延迟**

**本机的 STAP-A 包分析**:
```
Line 24: H.264  86  STAP-A SPS PPS
         包大小：86 字节

组成：
- RTP Header: 12 字节
- UDP Header: 8 字节
- IP Header: 20 字节
- Ethernet Header: 14 字节
总开销：54 字节

实际负载：86 - 54 = 32 字节
- STAP-A Header: 1 字节（NAL Type = 24）
- SPS Size: 2 字节
- SPS Data: ~10-15 字节
- PPS Size: 2 字节
- PPS Data: ~10-15 字节
```

**结论**: ✅ **PJSIP 的 H.264 打包器正确将 SPS 和 PPS 打包为 STAP-A 格式**

## 📊 FU-A 分片分析

### FU-A（Fragmentation Unit）是什么？

**FU-A 格式**:
```
RTP Header
|
+-- NAL Unit Type = 28 (FU-A)
|
+-- FU Indicator (1 byte):
|   - F (1 bit): forbidden_zero_bit
|   - NRI (2 bits): nal_ref_idc (重要性)
|   - Type (5 bits): 28 (FU-A)
|
+-- FU Header (1 byte):
|   - S (1 bit): Start bit（第一个分片）
|   - E (1 bit): End bit（最后一个分片）
|   - R (1 bit): Reserved
|   - Type (5 bits): 原始 NAL 单元类型（如 5=IDR）
|
+-- NAL Unit Data（分片数据）
```

**本机的 FU-A 包分析**:

**第一个分片**（Line 25）:
```
H.264  1358  FU-A Start:IDR-Slice
包大小：1358 字节
实际负载：1358 - 54 = 1304 字节
- FU-A Indicator: 1 字节
- FU-A Header: 1 字节（S=1, E=0, Type=5）
- IDR 数据: 1302 字节
```

**中间分片**（Line 26-39）:
```
H.264  1358  FU-A
FU-A Header: S=0, E=0
```

**最后一个分片**（Line 40）:
```
H.264  1081  FU-A End
FU-A Header: S=0, E=1
```

**IDR 帧总大小计算**:
- 第一个分片: 1302 字节
- 13 个中间分片: 13 × 1302 = 16926 字节
- 最后一个分片: 1081 - 54 - 2 = 1025 字节

**可能原因**:
1. 测试环境特殊（手动触发关键帧请求？）

**影响**:

- ⚠️ **编码器负载增加**（每次关键帧都需要全帧编码）
- 🔴 **这可能是 CPU 负载高的主要原因之一**！
