### 根本原因

**代码位置**: [ffmpeg_vid_codecs.c:710-731](../../cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-codec/ffmpeg_vid_codecs.c#L710-L731)

**Fix 52 代码被注释掉**:
```c
// ❌ 2026-01-04 23:05 [修复 52] 编码器使用共享 RKMPP hwdevice（已废弃）
// 问题：修复52共享 hwdevice，但仍然崩溃（exit 139）
// 根因：RKMPP 编码器强制创建自己的 hwframe（rkmppenc.c Line 1289）
//       两个独立 hwframes 共享一个 hwdevice → MPP 内核资源冲突
// 证据：MPP Issue #157 - 编解码器同时使用导致 segfault（已知 Bug）

    // ... 创建 hw_device_ctx 的代码被注释 ...

```

**历史原因**:
1. Fix 52 尝试为编码器初始化 hw_device_ctx（共享 hwdevice）
2. 但因为 MPP Issue #157（编解码器冲突导致崩溃）被禁用
3. Fix 53 改为只使用软件编码器（libx264）
4. 现在 h264_rkmpp 没有 hw_device_ctx，无法真正使用硬件加速


## ✅ 解决方案：Fix 97.1

### 修改策略

**采用调研报告推荐的 DRM Render Node 方案**:
1. ✅ 恢复 Fix 52 原始代码（共享 hwdevice）
2. ✅ 使用 DRM Render Node (`/dev/dri/renderD128`) 代替 DRM Master
3. ✅ 添加回退机制（renderD128 失败时回退到默认设备）
4. ✅ 添加详细日志标识 `[FIX 97.1]`

### 代码修改

**文件**: [cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-codec/ffmpeg_vid_codecs.c](../../cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-codec/ffmpeg_vid_codecs.c)

**位置**: h264_preopen() 函数（Line 719-748）

**关键代码**:
```c
// ✅ 2026-01-09 18:15 [修复 97.1] 恢复共享 hwdevice，使用 DRM Render Node
// 调研：全网调研确认 nyanmisaka/ffmpeg-rockchip 6.1 已规避 MPP Issue #157
// 证据：
//   1. Jellyfin (2024-02) 生产环境：双硬件加速稳定运行
//   2. Frigate (2024-2025) NVR：8 路 4K 同时编解码，CPU 10-15%
//   3. Radxa 社区验证：4K 转码 220 FPS，CPU 8-12%
// 策略：使用 DRM Render Node (/dev/dri/renderD128) 避免独占锁冲突
// 架构：编码器和解码器共享 hwdevice，各自创建 hwframes（nyanmisaka 已解决冲突）
// 性能：预期 CPU 从 60-80% 降至 10-15%（节省 70%）
// 参考：docs/2026-01-08/17-Rockchip-MPP-Issue157全网调研报告.md
if (ff->enc && (pj_ansi_strstr(ff->enc->name, "rkmpp") != NULL)) {
    int ret;
    PJ_LOG(1,(THIS_FILE, "✅ [FIX 97.1] Detected RKMPP encoder: %s", ff->enc->name));
    if (!g_rkmpp_hwdevice) {
        PJ_LOG(1,(THIS_FILE, "   Creating shared RKMPP hwdevice via DRM Render Node..."));
        // ✅ 使用 DRM Render Node 而非 DRM Master，避免独占锁冲突
        ret = av_hwdevice_ctx_create(&g_rkmpp_hwdevice, AV_HWDEVICE_TYPE_RKMPP, "/dev/dri/renderD128", NULL, 0);
        if (ret < 0) {
            PJ_LOG(1,(THIS_FILE, "   ❌ [FIX 97.1] Failed to create RKMPP hwdevice via renderD128: %d", ret));
            PJ_LOG(1,(THIS_FILE, "   Trying fallback to default device..."));
            // 回退到默认设备（NULL）
            ret = av_hwdevice_ctx_create(&g_rkmpp_hwdevice, AV_HWDEVICE_TYPE_RKMPP, NULL, NULL, 0);
            if (ret < 0) {
                PJ_LOG(1,(THIS_FILE, "   ❌ [FIX 97.1] Fallback also failed: %d", ret));
                return PJMEDIA_CODEC_EFAILED;
            }
        }
        PJ_LOG(1,(THIS_FILE, "   ✅ [FIX 97.1] Shared RKMPP hwdevice created successfully"));
    } else {
        PJ_LOG(1,(THIS_FILE, "   ✅ [FIX 97.1] Using existing shared RKMPP hwdevice"));
    }
    ctx->hw_device_ctx = av_buffer_ref(g_rkmpp_hwdevice);
    if (!ctx->hw_device_ctx) {
        PJ_LOG(1,(THIS_FILE, "   ❌ [FIX 97.1] Failed to ref shared RKMPP hwdevice for encoder"));
        return PJMEDIA_CODEC_EFAILED;
    }
    PJ_LOG(1,(THIS_FILE, "   ✅ [FIX 97.1] Encoder hw_device_ctx set (shared with decoder via renderD128)"));
    PJ_LOG(1,(THIS_FILE, "   Strategy: DRM Render Node (/dev/dri/renderD128) for concurrent encode/decode"));
    PJ_LOG(1,(THIS_FILE, "   Verified by: Jellyfin, Frigate, Radxa Community"));
}
```

**关键变化**:
1. ✅ Line 725: 从 `NULL` 改为 `"/dev/dri/renderD128"`
2. ✅ 添加回退机制（Line 726-735）
3. ✅ 详细日志标识便于验证
