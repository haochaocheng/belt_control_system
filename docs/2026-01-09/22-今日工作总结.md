## 完成的修复

### Fix 90：FFmpeg 6.0 分支添加 DRM_PRIME 转换
- **问题**：DRM_PRIME 转换代码只在旧 FFmpeg 分支，实际使用 FFmpeg 6.0
- **原因**：条件编译 `LIBAVCODEC_VER_AT_LEAST(58,137)` 判断错误
- **修复**：在 FFmpeg 6.0 分支（Line 3341-3422）添加转换逻辑
- **文档**：[18-修复90-FFmpeg6.0分支添加DRM_PRIME转换.md](../2026-01-08/18-修复90-FFmpeg6.0分支添加DRM_PRIME转换.md)

### Fix 91：添加 EAGAIN 错误处理
- **问题**：`err=-11` (EAGAIN) 被误判为错误，返回 `EBADBITSTREAM`
- **原因**：FFmpeg 6.0 分支缺少 EAGAIN 处理逻辑
- **修复**：清除 EAGAIN 错误码，设置 `got_picture=FALSE`
- **效果**：解码器不再返回错误，程序继续喂数据
- **文档**：[19-修复91-添加EAGAIN错误处理.md](./19-修复91-添加EAGAIN错误处理.md)

### Fix 92：正确的内存管理 ⭐ 关键修复
- **问题**：`avframe = *sw_frame` 浅拷贝导致内存泄漏和悬空指针
- **原因**：错误的所有权转移，只释放结构不释放数据
- **修复**：使用 `av_frame_move_ref()` 正确转移所有权
- **效果**：无内存泄漏，编码器不再崩溃
- **影响**：修复了 Fix 89 和 Fix 90 引入的严重 bug
- **文档**：[21-修复92-正确的内存管理.md](./21-修复92-正确的内存管理.md)

## 技术难点突破

### 1. 条件编译分支错误
- **问题**：代码在源文件中，但运行时不执行
- **原因**：`LIBAVCODEC_VER_AT_LEAST(58,137)` 判断错误
- **解决**：在正确的分支添加代码

### 2. FFmpeg 新旧 API 差异
- **新 API** (FFmpeg 6.0)：`avcodec_send_packet()` / `avcodec_receive_frame()`
- **旧 API**：`avcodec_decode_video2()`
- **差异**：EAGAIN 错误处理逻辑不同

### 3. AVFrame 内存管理
- **错误**：结构赋值 `avframe = *sw_frame`
- **正确**：引用移动 `av_frame_move_ref(&avframe, sw_frame)`
- **差异**：所有权转移 vs. 浅拷贝

## 关键洞察

### 1. 编码器崩溃不是编码器的问题
用户说："编码器一直是正常的，不修复解码器之前，工作正常。"

**分析正确**！崩溃是解码器的 Fix 90 引入的内存管理 bug，影响了编码器。

### 2. 浅拷贝的危害
```c
AVFrame avframe;  // 栈变量
AVFrame *sw_frame = av_frame_alloc();  // 堆变量

avframe = *sw_frame;  // ❌ 浅拷贝指针
av_free(sw_frame);    // ❌ 只释放结构

// avframe.data[] 现在是悬空指针 → 段错误
```

### 3. FFmpeg 内存管理规则
- 使用 `av_frame_alloc()` 分配结构
- 使用 `av_frame_free()` 释放结构+数据
- 使用 `av_frame_move_ref()` 转移所有权
- 使用 `av_frame_unref()` 清空引用
- **永远不要** 使用结构赋值 `avframe = *other`
