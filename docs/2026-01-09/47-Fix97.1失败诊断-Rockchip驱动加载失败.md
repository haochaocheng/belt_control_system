## 📊 问题诊断

### 核心问题

**hw_device_ctx 已设置，但编码器仍以软件模式运行**

**原因**:
1. ✅ Fix 97.1 成功创建了 hw_device_ctx（地址 0x7ee00165d0）
2. ✅ 编码器成功引用了 hw_device_ctx
3. ❌ 但 `avcodec_open2()` 时，**Rockchip DRM 驱动加载失败**
4. ❌ 编码器回退到软件模式（pix_fmt=0, I420）

### 错误信息解读

```
glx: failed to create dri3 screen
failed to load driver: rockchip
```

**可能原因**:
1. **DRM 设备不存在或无法访问**
   - `/dev/dri/renderD128` 不存在
   - 或容器没有权限访问 DRM 设备

2. **FFmpeg RKMPP 库配置问题**
   - FFmpeg 找不到 Rockchip MPP 库
   - RKMPP 驱动未正确编译到 FFmpeg

3. **环境变量或路径问题**
   - LD_LIBRARY_PATH 不包含 MPP 库路径
   - 缺少必要的共享库

**在设备 188 上运行**:

**如果缺少设备映射**:
- 问题：容器无法访问 DRM 设备
- 解决：添加 `--device /dev/dri:/dev/dri` 到 docker run 命令

## 🎯 可能的解决方案

### 方案 1: 修复 DRM 设备访问（推荐）

**问题**: 容器无法访问 `/dev/dri/renderD128`

**解决**: 确保容器启动时映射 DRM 设备

**Dockerfile.ubuntu24-apt** 或 **docker run 命令**:
```bash
docker run \
  --device /dev/dri:/dev/dri \
  --group-add video \
  --group-add render \
  -e USE_HARDWARE_ENCODER=1 \
  belt-control-app:ubuntu24-apt
```

**build-ubuntu24-apt.ps1** Line 1100+（SSH 部署部分）:
```powershell
# 添加 DRM 设备映射
$DOCKER_DEVICES = "--device /dev/dri:/dev/dri"
$DOCKER_GROUPS = "--group-add video --group-add render"

ssh linaro@$TARGET_IP @"
docker run -d \
  --name belt-control-latest \
  $DOCKER_DEVICES \
  $DOCKER_GROUPS \
  ...
"@
```

### 方案 2: 回退到 NULL 设备

**问题**: `/dev/dri/renderD128` 不存在

**解决**: Fix 97.1 已经有回退机制，但可能 NULL 设备也失败了

**修改**: 增强回退日志

**文件**: [ffmpeg_vid_codecs.c:725-735](../../cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-codec/ffmpeg_vid_codecs.c#L725-L735)

```c
ret = av_hwdevice_ctx_create(&g_rkmpp_hwdevice, AV_HWDEVICE_TYPE_RKMPP, "/dev/dri/renderD128", NULL, 0);
if (ret < 0) {
    char errbuf[128];
    av_strerror(ret, errbuf, sizeof(errbuf));
    PJ_LOG(1,(THIS_FILE, "   ❌ [FIX 97.1] renderD128 failed: %d (%s)", ret, errbuf));
    PJ_LOG(1,(THIS_FILE, "   Trying fallback to default device..."));

    ret = av_hwdevice_ctx_create(&g_rkmpp_hwdevice, AV_HWDEVICE_TYPE_RKMPP, NULL, NULL, 0);
    if (ret < 0) {
        av_strerror(ret, errbuf, sizeof(errbuf));
        PJ_LOG(1,(THIS_FILE, "   ❌ [FIX 97.1] Default device also failed: %d (%s)", ret, errbuf));
        return PJMEDIA_CODEC_EFAILED;
    }
    PJ_LOG(1,(THIS_FILE, "   ✅ [FIX 97.1] Fallback to default device successful"));
}
```

### 方案 3: 检查是否使用了正确的 FFmpeg

**问题**: 容器内的 FFmpeg 不是 nyanmisaka/ffmpeg-rockchip 6.1

**解决**: 确认编译链接使用的 FFmpeg

**检查**:
```bash
# 在容器内
ldd /app/bin/belt_control_system | grep avcodec

# 应该指向 nyanmisaka FFmpeg
libavcodec.so.60 => /opt/ffmpeg-rockchip/lib/libavcodec.so.60
```

### 方案 4: 暂时禁用硬件编码器

**如果无法解决 DRM 访问问题**，暂时回退到软件编码器：

```bash
docker run -e USE_HARDWARE_ENCODER=0 belt-control-app
```

或修改默认值：
```c
// Line 1112
int enable_hw_encoder = 0;  // 默认：禁用硬件编码器
```
