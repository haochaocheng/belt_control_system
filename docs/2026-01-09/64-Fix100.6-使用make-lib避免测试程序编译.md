# Fix 100.6：使用 make lib 避免测试程序编译失败

**日期**: 2026-01-10 02:30
**问题**: 脚本使用 `make` 编译所有内容，导致 `pjmedia-test` 链接失败后整个构建停止
**根本原因**: 测试程序链接需要额外的运行时库（libswresample.so.4），但我们只需要静态库
**状态**: ✅ **已修复 - 使用 make lib 只编译库文件**

---

## 🎯 修复目标

使用 `make lib` 代替 `make`，只编译 PJSIP 静态库（21个 .a 文件），跳过测试程序编译。

---

## 📊 问题分析

### 错误现象

**执行**: `.\build-ubuntu24-apt.ps1 192.168.10.188`

**错误输出**:
```
/usr/lib/gcc-cross/aarch64-linux-gnu/13/../../../../aarch64-linux-gnu/bin/ld: warning: libswresample.so.4, needed by /opt/rk3588-sysroot/usr/lib/aarch64-linux-gnu/libavcodec.so, not found (try using -rpath or -rpath-link)
/usr/lib/gcc-cross/aarch64-linux-gnu/13/../../../../aarch64-linux-gnu/bin/ld: /opt/rk3588-sysroot/usr/lib/aarch64-linux-gnu/libavcodec.so: undefined reference to `swr_alloc@LIBSWRESAMPLE_4'
...
collect2: error: ld returned 1 exit status
make[2]: *** [/workspace/build/rules.mak:125: ../bin/pjmedia-test-aarch64-unknown-linux-gnu] Error 1
    [错误] PJSIP 编译失败（退出码: 1）
```

### 根本原因

1. **测试程序需要额外的运行时库**:
   - `pjmedia-test` 链接失败是因为缺少 `libswresample.so.4`（FFmpeg 音频重采样库）
   - 这是一个**运行时库**，不是静态库
   - 测试程序需要动态链接这些库

2. **静态库编译已经成功**:
   - 所有 21 个 PJSIP 静态库（.a 文件）已经成功编译
   - 主应用程序不需要测试程序
   - 测试程序失败不影响主应用程序

3. **用户经验**:
   - "根据以往的经验，make 不一定行，需要 make lib"
   - 之前的测试显示，`make lib` 成功编译了所有 21 个 PJSIP 静态库

---

## 🔧 解决方案

### 修改位置

**文件**: `build-ubuntu24-apt.ps1`
**行号**: Line 588-606
**作用**: PJSIP 编译命令

### 修改内容

```powershell
echo ""
echo "编译 PJSIP 静态库（使用 $(nproc) 线程）..."
# ✅ 2026-01-10 02:30 [修复 100.6] 使用 make lib 代替 make
# 原因：
#   1. make lib 只编译静态库（21个 .a 文件），不编译测试程序
#   2. 测试程序（pjmedia-test）链接失败不影响主应用程序
#   3. 测试程序失败通常是因为 libswresample 等库的版本问题
# 旧代码（2026-01-10 02:30 注释）：
#   make -j$(nproc) 2>&1 | tee /tmp/make.log
# 说明：根据以往的经验，make 不一定行，需要 make lib
make lib -j$(nproc) 2>&1 | tee /tmp/make.log

# ⚠️ make lib 必须成功，否则说明链接库配置有问题
if [ ${PIPESTATUS[0]} -ne 0 ]; then
    echo "✗ make lib 编译失败"
    echo ""
    echo "=== 最后 100 行编译日志 ==="
    tail -100 /tmp/make.log
    exit 1
fi

echo ""
echo "复制静态库到输出目录..."
mkdir -p /output/lib
find . -name "*.a" -type f -exec cp {} /output/lib/ \;

FINAL_COUNT=$(ls /output/lib/*.a 2>/dev/null | wc -l)
echo ""
if [ $FINAL_COUNT -lt 20 ]; then
    echo "✗ 静态库数量不足：${FINAL_COUNT} 个（预期 >=20）"
    exit 1
else
    echo "✓ 静态库生成成功：${FINAL_COUNT} 个"
    echo "✓ PJSIP 静态库编译完成（不包括测试程序）"
    # 记录配置文件时间戳（用于检测配置是否修改）
    echo "$CONFIG_TIMESTAMP" > /workspace/.config_timestamp
fi
```

### 关键变化

**修改前**（错误）:
```bash
make -j$(nproc)  # ← 编译所有内容（包括测试程序）
```

**修改后**（正确）:
```bash
make lib -j$(nproc)  # ← 只编译静态库（21个 .a 文件）
```

### 为什么测试程序失败不影响主应用程序？

**原因**:
1. **主应用程序静态链接 PJSIP**:
   - 主应用程序使用 PJSIP 静态库（.a 文件）
   - 不依赖测试程序

2. **测试程序是独立的可执行文件**:
   - `pjmedia-test`、`pjsip-test` 等测试程序用于 PJSIP 库的内部测试
   - 主应用程序不使用这些测试程序

3. **静态库已经包含所有功能**:
   - 21 个静态库包含了所有 PJSIP 功能（SIP、媒体、编解码器等）
   - 主应用程序链接这些静态库就足够了

## 📖 技术细节

### make vs make lib

**`make`（编译所有内容）**:
```bash
make  # 编译：
      # 1. 所有静态库（.a 文件）
      # 2. 所有测试程序（pjmedia-test, pjsip-test, pjsua-test 等）
      # 3. 示例程序（pjsua, pjsua2_demo 等）
```

**`make lib`（只编译库）**:
```bash
make lib  # 编译：
          # 1. 所有静态库（.a 文件）
          # 2. 跳过测试程序
          # 3. 跳过示例程序
```
