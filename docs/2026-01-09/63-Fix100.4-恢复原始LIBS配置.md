## 🔍 根本原因

### LIBS 配置对比

**原始配置**（Fix 97.2 时，可以编译）:
```bash
export LIBS="-lx264 -lx265 -lvpx -lcairo -lva -lva-drm -lva-x11 -ltwolame -lwebp -lcodec2 -ldav1d -laom -lwavpack -ltheora -ltheoraenc -ltheoradec -lxvidcore -lopenjp2 -lshine -lsnappy -lzvbi -lrsvg-2 -lvdpau -lrga -lrockchip_mpp -lpthread -lm -lrt"
```

**Fix 100.2 配置**（编译失败）:
```bash
export LIBS="-lx264 -lx265 -lvpx -lcairo -ltwolame -lwebp -lcodec2 -ldav1d -laom -lwavpack -ltheora -ltheoraenc -ltheoradec -lxvidcore -lopenjp2 -lshine -lsnappy -lzvbi -lrga -lrockchip_mpp -lpthread -lm -lrt"
```

**差异**:
- 删除了：`-lva -lva-drm -lva-x11 -lrsvg-2 -lvdpau`

### 为什么删除库会导致编译失败？

**错误的假设**（Fix 100.2）:
- 认为 libva（Intel VA-API）、libvdpau（NVIDIA）在 ARM 平台不存在，删除它们可以避免链接错误

**实际情况**:
1. **链接器的顺序敏感性**:
   - `-l` 参数的顺序决定了依赖解析的顺序
   - 链接器从左到右处理库，如果 A 依赖 B，B 必须在 A 之后

2. **LIBS 变量的作用**:
   - 这些库不是直接被 PJSIP 链接的
   - 而是作为 **FFmpeg 依赖库**在 configure 测试时使用
   - configure 脚本会测试 FFmpeg 编解码器是否可用

3. **删除库后的影响**:
   - 原始顺序中，libva 等库在 libtheora 和 libxvidcore 之后
   - 删除它们后，链接顺序发生了变化
   - 导致 libswresample（FFmpeg 音频重采样库）的依赖没有被正确解析

4. **链接器的容错机制**:
   - 如果链接器找不到某个库（如 `-lva`），它会：
     - 发出警告（warning）
     - 继续处理后续的库
     - 不会导致致命错误
   - **删除不存在的库反而会改变链接顺序**，导致其他库的依赖解析失败

## 📖 技术细节

### 链接器的顺序敏感性

**概念**:
- 静态链接时，链接器从左到右处理库
- 如果库 A 引用了库 B 的符号，B 必须在 A 之后

**示例**:
```bash
# 正确顺序
gcc -o program main.o -lA -lB  # A 依赖 B

# 错误顺序（会报错 "undefined reference"）
gcc -o program main.o -lB -lA  # B 在 A 之前
```

**本案例**:
- libavcodec.so（FFmpeg 视频编解码器）依赖 libswresample.so（音频重采样）
- 原始 LIBS 中的库顺序确保了依赖关系正确
- 删除部分库后，顺序发生变化，导致依赖解析失败

### 为什么不显式添加 -lswresample？

**原因**:
1. **PJSIP 的 configure 脚本会自动检测 FFmpeg**:
   - 使用 `pkg-config --libs libavcodec` 获取所有依赖
   - 自动添加到链接命令

2. **LIBS 变量的作用**:
   - 用于 configure 测试时的链接
   - 不是最终应用程序的链接命令

3. **保持原始配置最安全**:
   - 原始配置经过验证，可以编译
   - 不应该随意修改，除非有明确的问题

### 教训

**不要随意删除 LIBS 中的库**:
1. 即使某些库不存在，链接器会自动忽略
2. 删除库会改变链接顺序，可能导致其他依赖解析失败
3. 保持原始配置（经过验证的）最安全

**链接器顺序很重要**:
1. `-l` 参数的顺序决定依赖解析顺序
2. 修改顺序前，必须理解依赖关系
3. 如果不确定，不要修改
