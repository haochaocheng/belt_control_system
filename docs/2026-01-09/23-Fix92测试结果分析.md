## 关键问题分析

### 问题 1：为什么 Fix 92 没有执行但还是崩溃？

**Fix 92 的代码**（Line 3420-3427）：
```c
// 只有在 format == AV_PIX_FMT_DRM_PRIME (179) 时才执行
if (avframe.format == AV_PIX_FMT_DRM_PRIME) {
    // ...
    av_frame_move_ref(&avframe, sw_frame);  // Fix 92
    av_frame_free(&sw_frame);
}
```

**实际情况**：
- 解码器返回 `err=-11, format=-1`
- `format=-1` != `179`，所以 Fix 92 代码**没有执行**
- 但是程序还是崩溃了

**可能的原因**：
1. **崩溃不是内存管理问题**？
2. **其他地方也有内存问题**？
3. **多线程竞态条件**？

### 问题 2：为什么解码器一直返回 EAGAIN？

**EAGAIN 的含义**：解码器需要更多输入数据才能产生完整的帧。

**可能的原因**：
1. **对方1006没有发送完整的视频数据**？
   - 用户说："对方1006 100%没有问题"
   - 所以这个可能性不大
2. **数据包丢失或乱序**？
   - 网络问题导致数据包不完整
3. **解码器初始化问题**？
   - SPS/PPS 参数没有收到

### 问题 3：崩溃位置在哪里？

**最后一行日志**：
```
14:45:55.097     v
Application exited with code: 139
```

**分析**：
- `v` 应该是 `vstenc0x7f44012620` 的开头
- 说明在打印日志时崩溃
- 可能是在访问 `vstenc` 对象的属性时崩溃

**可能的原因**：
1. **内存损坏**：某处的内存被破坏，影响了日志系统
2. **对象被提前释放**：`vstenc` 对象被释放但指针还在使用
3. **栈溢出**：日志格式化时栈溢出

### 方向 2：检查 AVFrame 初始化

**问题**：FFmpeg 6.0 分支使用栈变量 `AVFrame avframe`
```c
AVFrame avframe;  // Line 3284
```

**可能的问题**：
- EAGAIN 返回时，`avframe` 的某些字段可能是未初始化的
- 后续代码可能访问了这些未初始化的字段

**解决方案**：
```c
AVFrame avframe;
memset(&avframe, 0, sizeof(avframe));  // 初始化为零
```

或者使用堆分配：
```c
AVFrame *avframe = av_frame_alloc();
// ... 使用 avframe
av_frame_free(&avframe);
```

### 方向 3：检查对方1006的视频数据

**验证步骤**：
1. 使用 tcpdump 抓包：
   ```bash
   tcpdump -i any -w /tmp/video.pcap port 5060 or portrange 10000-20000
   ```
2. 使用 Wireshark 分析 RTP 流
3. 检查是否有：
   - SPS/PPS 参数
   - 完整的 NAL 单元
   - 数据包丢失

### 方向 4：检查多线程问题

**PJSIP 的线程模型**：
- 编码器线程：负责编码本地视频
- 解码器线程：负责解码远程视频
- RTP 线程：负责发送和接收 RTP 包

**可能的竞态条件**：
- FFmpeg context 的线程安全问题
- PJSIP 内部的锁问题

**验证方法**：
1. 添加线程 ID 日志：
   ```c
   PJ_LOG(3,(THIS_FILE, "🔍 [THREAD] decoder thread: %lu", pthread_self()));
   ```
2. 使用 ThreadSanitizer（TSan）检测竞态条件
