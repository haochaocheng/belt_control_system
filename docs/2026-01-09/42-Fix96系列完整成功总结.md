## 💡 关键技术洞察

### 1. Qt Multimedia 插件机制缺陷

**问题**: Qt 插件加载失败后不自动尝试其他插件

**Qt 源码逻辑**（简化）:
```cpp
QMediaPlatform* loadPlugin() {
    QPluginLoader loader("libffmpegmediaplugin.so");
    if (!loader.load()) {
        // ❌ 直接返回 nullptr，不尝试其他插件！
        qWarning() << "could not load multimedia backend";
        return nullptr;
    }
    return loader.instance();
}
```

**缺失的逻辑**:
```cpp
// ✅ 应该有的逻辑（但 Qt 没有）
if (!loader.load()) {
    // 尝试下一个插件（GStreamer）
    QPluginLoader loaderGst("libgstreamermediaplugin.so");
    if (loaderGst.load()) {
        return loaderGst.instance();
    }
}
```

### 2. 平台差异根本原因

| 平台 | Qt Multimedia 后端 | 依赖管理 |
|------|-------------------|---------|
| **Windows** | DirectShow / WMF | ✅ 系统内置 |
| **macOS** | AVFoundation | ✅ 系统内置 |
| **Linux** | FFmpeg / GStreamer | ❌ 需手动安装 |

**Linux 的挑战**:
- 共享库（Shared Libraries）哲学
- 版本严格匹配（major version）
- 依赖链复杂

### 3. 解决方案演进

| 方案 | 原理 | 可靠性 | 实施结果 |
|------|------|--------|---------|
| Fix 96 | 安装 GStreamer 库 | 🔸 解决依赖 | ✅ 库安装成功 |
| Fix 96.1 | 环境变量指定后端 | 🔸 依赖 Qt 支持 | ❌ Qt 不支持 |
| Fix 96.2 | 删除冲突插件 | ⭐⭐⭐⭐⭐ | ✅ 100% 成功 |

**最终策略**: **物理删除冲突插件**，强制 Qt 加载唯一可用的 GStreamer 插件
