# Fix 97.2 最终修复：librga.so.2 符号链接问题

**日期**: 2026-01-09 20:45
**问题**: librga.so.2 未被复制到 Docker 镜像，导致应用启动失败
**根本原因**: WSL 符号链接（26 字节）被脚本过滤逻辑跳过
**状态**: ✅ **已修复 - 删除符号链接 + Dockerfile 创建符号链接**

---

## 🔍 问题发现

### 用户反馈

应用程序启动失败：
```
/app/belt_control_system: error while loading shared libraries: librga.so.2: cannot open shared object file: No such file or directory

Application exited with code: 127
```

提示：`librga.so.2 => not found (will be mounted from host at runtime)`

---

## 📊 问题诊断

### 步骤 1: 检查 rk3588-libs 目录

```powershell
PS> Get-ChildItem 'docker\rk3588\rk3588-libs\lib\librga.so*' | Format-Table Name, Length -AutoSize

Name            Length
----            ------
librga.so           26  ⚠️ WSL 符号链接

```

**发现**:
- `librga.so` 和 `librga.so.2` 都是 WSL 符号链接（26 字节）
- `librga.so.2.1.0` 是实际文件（209208 字节）

---

### 步骤 2: 检查脚本过滤逻辑

**build-ubuntu24-apt.ps1 Line 1115-1122**:
```powershell
foreach ($lib in $codecLibs) {
    # ⚠️ 2026-01-03 修复：只复制实际文件（> 1KB），跳过符号链接
    # 原因：Windows PowerShell 复制 WSL 符号链接会导致 "file too short" 错误
    if ($lib.Length -gt 1KB) {
        Copy-Item $lib.FullName "$DockerContextDir\lib\" -Force -ErrorAction SilentlyContinue
        Write-Host "      ✓ $($lib.Name) ($([math]::Round($lib.Length / 1KB, 0)) KB)" -ForegroundColor Gray
        $codecCount++
    } else {
        $skippedCount++  # librga.so.2 (26字节) 被跳过 ❌
    }
}
```

**问题**:
- `librga.so.2`（26 字节）< 1KB → 被跳过
- `librga.so.2.1.0`（204KB）> 1KB → 被复制 ✅

**结果**:
- 镜像中只有 `librga.so.2.1.0`
- 应用程序需要 `librga.so.2` → 找不到 → 启动失败

---

## 🎯 根本原因

### WSL 符号链接的特性

在 Windows 上，WSL 符号链接被 PowerShell 识别为小文件（26 字节）：
```
符号链接内容（文本）：
"librga.so.2.1.0\n"  ← 指向目标文件名（14 字节 + 换行符）
```

**Windows PowerShell 行为**:
- `Copy-Item` 复制符号链接会复制文本内容（26 字节）
- Docker 镜像中得到的是一个 26 字节的文本文件
- 应用程序加载 `librga.so.2` 失败（不是有效的 ELF 文件）

---

## 🔧 解决方案

### 方案选择

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| **A: 强制复制符号链接** | 简单 | 得到无效的文本文件 | ❌ |
| **B: 使用 -FollowSymbolicLinks** | 自动解析符号链接 | PowerShell 7+ 特性，兼容性问题 | ❌ |
| **C: 删除符号链接 + Dockerfile 创建** | 可靠，与 Linux 兼容 | 需要修改 Dockerfile | ✅ |

**选择方案 C**: 删除 WSL 符号链接，只保留实际文件，在 Dockerfile 中创建 Linux 符号链接

---

### 修改 2: Dockerfile 添加 librga 符号链接

**文件**: [Dockerfile.ubuntu24-apt](../../Dockerfile.ubuntu24-apt)

**修改位置**: Line 38-46

**修改前**:
```dockerfile
for lib in libavcodec libavformat ... \
           librockchip_mpp libdav1d \  ← 缺少 librga
           libsherpa-onnx-c-api ...; do \
```

**修改后**（Line 45）:
```dockerfile
# ✅ 2026-01-09 20:45 [Fix 97.2 配套] 添加 librga 符号链接
# 原因：librga.so.2.1.0 已复制到镜像，需创建 librga.so.2 → librga.so.2.1.0 符号链接
for lib in libavcodec libavformat ... \
           librockchip_mpp libdav1d librga \  ← 添加 librga
           libsherpa-onnx-c-api ...; do \
    if ls ${lib}.so.* 1> /dev/null 2>&1; then
        latest=$(ls -v ${lib}.so.* 2>/dev/null | grep -v '\.backup-' | tail -1);
        [ -z "$latest" ] && continue;
        basename_file=$(basename "$latest");
        version=$(echo "$basename_file" | sed "s/${lib}.so.//");
        major=$(echo "$version" | cut -d. -f1);
        [ -n "$major" ] && ln -sf "$basename_file" "${lib}.so.${major}" 2>/dev/null || true;
        ln -sf "$basename_file" "${lib}.so" 2>/dev/null || true;
    fi;
done
```

**创建的符号链接**:
```bash
/app/lib/librga.so.2.1.0      # 实际文件（从 rk3588-libs 复制）
/app/lib/librga.so.2 → librga.so.2.1.0  # 主版本符号链接
/app/lib/librga.so → librga.so.2.1.0    # 通用符号链接
```

### 1. WSL 符号链接的陷阱

**问题**: Windows PowerShell 复制 WSL 符号链接会得到文本文件，不是有效的库文件

**解决**:
- 删除所有 WSL 符号链接，只保留实际文件
- 在 Dockerfile 中创建 Linux 原生符号链接

**检查方法**:
```powershell
# 检查文件大小
Get-ChildItem *.so* | Where-Object { $_.Length -lt 1KB }
# 如果是符号链接，删除：
Remove-Item <symlink-file> -Force
```

---

### 2. 符号链接创建时机

**Windows（宿主机）**:
- ❌ 不要创建 WSL 符号链接
- ✅ 只保留实际文件（*.so.X.Y.Z）

**Linux（Docker 镜像）**:
- ✅ 在 Dockerfile RUN 指令中创建符号链接
- ✅ 使用 `ln -sf` 创建 Linux 原生符号链接
