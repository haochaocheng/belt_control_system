# Fix 100.7：手动创建 RGA 库符号链接

**日期**: 2026-01-10 02:35
**问题**: 主应用程序编译失败 "No rule to make target '/opt/rk3588-libs/lib/librga.so'"
**根本原因**: rk3588-libs/lib 目录中只有 librga.so.2.1.0，缺少 librga.so 和 librga.so.2
**状态**: ✅ **已修复 - 手动创建文件副本**

---

## 🎯 修复目标

在宿主机的 `docker/rk3588/rk3588-libs/lib/` 目录中创建 RGA 库的符号链接（或文件副本），确保 CMake 能找到 librga.so。

---

## 📊 问题分析

### 错误现象

**执行**: `.\build-ubuntu24-apt.ps1 192.168.10.188`

**错误输出**:
```
make[2]: *** No rule to make target '/opt/rk3588-libs/lib/librga.so', needed by 'bin_arm64/belt_control_system'.  Stop.
make[1]: *** [CMakeFiles/Makefile2:1477: src/main/CMakeFiles/belt_control_system.dir/all] Error 2
make: *** [Makefile:91: all] Error 2
```

### 根本原因

1. **主应用程序需要链接 RGA 库**:
   - CMakeLists.txt 配置需要 `librga.so`
   - 容器内路径：`/opt/rk3588-libs/lib/librga.so`
   - 宿主机路径：`docker/rk3588/rk3588-libs/lib/librga.so`

2. **缺少符号链接**:
   ```
   ✅ 存在：librga.so.2.1.0（版本化文件）
   ❌ 缺少：librga.so（通用链接名）← CMake 需要这个
   ❌ 缺少：librga.so.2（SONAME 链接）
   ```

3. **其他库有完整的链接**:
   ```bash
   libaom.so → libaom.so.3 → libaom.so.3.8.2  ✅
   libcairo.so → libcairo.so.2 → libcairo.so.2.11600.0  ✅
   librockchip_mpp.so, librockchip_mpp.so.0, librockchip_mpp.so.1  ✅

   librga.so（缺少）→ librga.so.2（缺少）→ librga.so.2.1.0  ❌
   ```

---

## 🔧 解决方案

### 修改位置

**宿主机目录**: `docker/rk3588/rk3588-libs/lib/`
**作用**: 容器通过 `-v` 挂载这个目录到 `/opt/rk3588-libs/`

### 手动创建文件副本

**原因**:
- Windows 创建符号链接需要管理员权限
- 文件副本对编译来说效果相同
- 容器启动时会看到宿主机上的文件

**命令**:
```powershell
cd "e:\2025\3_gongkongji\belt_control_system\docker\rk3588\rk3588-libs\lib"

# 创建 librga.so.2 副本
Copy-Item 'librga.so.2.1.0' 'librga.so.2' -Force

# 创建 librga.so 副本
Copy-Item 'librga.so.2.1.0' 'librga.so' -Force
```

**验证**:
```powershell
Get-ChildItem *rga*

# 输出应该显示：
# librga.so         (209208 bytes)
# librga.so.2       (209208 bytes)
# librga.so.2.1.0   (209208 bytes)
```

## 📖 技术细节

### CMake 如何查找库文件

**CMakeLists.txt 配置**:
```cmake
find_library(RGA_LIBRARY NAMES rga PATHS /opt/rk3588-libs/lib NO_DEFAULT_PATH)
target_link_libraries(belt_control_system ${RGA_LIBRARY})
```

**查找顺序**:
1. CMake 使用 `find_library(... NAMES rga ...)` 查找库
2. 查找文件：`librga.so`（首选），`librga.a`（备选）
3. 如果找到 `librga.so` → 使用动态链接
4. 如果只有 `librga.so.2.1.0` → 找不到 → 编译失败

### 符号链接 vs 文件副本

**符号链接**（Linux 标准方式）:
```bash
ln -s librga.so.2.1.0 librga.so.2
ln -s librga.so.2 librga.so
```
- ✅ 节省磁盘空间（只有指针）
- ✅ 文件更新自动生效
- ❌ Windows 需要管理员权限

**文件副本**（Windows 临时方案）:
```powershell
Copy-Item librga.so.2.1.0 librga.so.2
Copy-Item librga.so.2.1.0 librga.so
```
- ✅ 不需要管理员权限
- ✅ 对编译来说效果相同
- ❌ 占用额外磁盘空间（3倍）
- ❌ 文件更新需要重新复制

### 为什么之前没有这个问题？

**可能原因**:
1. **初次下载 sysroot 时缺少符号链接**:
   - 从设备 188 下载 `/usr/lib/aarch64-linux-gnu/` 时
   - 可能只复制了实际文件，没有保留符号链接

2. **Windows 文件系统限制**:
   - Linux 的符号链接在 Windows 上可能变成普通文件
   - 或者根本没有被复制

3. **之前可能手动修复过但没有记录**:
   - 其他库（libaom, libcairo）有完整的文件
   - 可能之前手动创建过，但没有记录步骤
