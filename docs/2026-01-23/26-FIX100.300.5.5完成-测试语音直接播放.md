## 🎓 技术要点

### 1. SherpaOnnxTTS 的两种使用方式

**方式 1: 生成文件**（用于缓存）
```cpp
bool synthesizeToFile(const QString &text, const QString &outputFile);
```
- 用途：生成音频文件保存到磁盘
- 场景：预缓存常用语音、网络传输前准备

**方式 2: 直接播放**（用于实时播放）
```cpp
void say(const QString &text);
```
- 用途：合成并立即播放
- 场景：实时语音提示、测试功能

### 2. 测试功能的设计原则

**好的测试功能**:
- ✅ 即时反馈 - 用户立即看到/听到结果
- ✅ 简单直观 - 一键测试，无需额外操作
- ✅ 真实场景 - 模拟实际使用情况

**不好的测试功能**:
- ❌ 延迟反馈 - 需要手动查找结果
- ❌ 复杂操作 - 需要多步骤验证
- ❌ 脱离场景 - 测试结果与实际使用不符

### 3. Docker 容器文件系统隔离

**容器内路径**:
```
/tmp/tts_test.wav  ← 容器内可见
```

**主机路径**:
```
/tmp/tts_test.wav  ← 主机上看不到容器内的文件
```

**解决方案**:
1. **挂载卷** - 将容器路径挂载到主机（如 `/app/appdata`）
2. **直接播放** - 不生成文件，直接播放（本次采用）✅

## 📝 经验教训

### 教训 1: 测试功能要符合用户直觉

**问题**: 我设计的测试功能只生成文件，不播放

### 教训 2: 容器文件系统隔离

### 教训 3: 选择合适的 API

**SherpaOnnxTTS 提供两种方式**:
- `synthesizeToFile()` - 适合缓存、网络传输
- `say()` - 适合实时播放、测试功能

**选择依据**:
- 测试功能 → 使用 `say()` ✅
- 预缓存 → 使用 `synthesizeToFile()`
- 网络传输 → 使用 `synthesizeToFile()` + 发送
