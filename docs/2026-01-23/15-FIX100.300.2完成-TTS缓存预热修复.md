## 📋 问题回顾

应用程序启动后卡在 TTS 缓存预热阶段，无法继续启动。

**症状**：
```
[DEBUG] 🔥 CommonControl: 启动TTS缓存预热（异步）...
[DEBUG]    🔄 预热缓存: 1 号皮带
[DEBUG]   合成语音到文件: "/app/appdata/tts_cache/network_21839810471ce12c.wav"
[DEBUG]    🔄 预热缓存: 2 号皮带
```

程序卡在这里，无法继续。

---

## 🔍 根本原因

**异步定时器 + 同步阻塞 = 并发灾难**

### 原代码问题（已废弃）

```cpp
// ❌ 错误的异步方式
for (int i = 1; i <= 10; ++i) {
    QTimer::singleShot(i * 200, this, [this, i]() {
        // synthesizeToFile 是同步阻塞的（30秒超时）
        m_tts->synthesizeToFile(warningText, cacheFilePath);
    });
}
```

**问题链**：
1. 每 200ms 启动一个定时器
2. 每个定时器回调中调用 `synthesizeToFile()`
3. `synthesizeToFile()` 内部使用 `QEventLoop::exec()` 阻塞等待响应（30秒超时）
4. 多个定时器同时触发 → 多个 `synthesizeToFile()` 同时阻塞
5. TTS 服务无法处理并发请求 → 响应丢失 → 程序卡死

---

## ✅ 解决方案

**参考 AlarmPlaybackService 的成功模式：同步顺序预热**

### 修改后的代码

**文件**: `src/control/CommonControl.cpp:1196-1244`

```cpp
// ✅ 2026-01-23 10:50 [FIX 100.300.2] 改为同步顺序预热（参考 AlarmPlaybackService）
void CommonControl::preloadTTSCache()
{
    qDebug() << "🔥 CommonControl: 启动TTS缓存预热（同步顺序）...";

    if (!m_tts || m_tts->state() != SherpaOnnxTTS::Ready) {
        qWarning() << "⚠️ CommonControl: TTS引擎不可用，跳过缓存预热";
        return;
    }

    // ✅ 同步顺序预热（参考 AlarmPlaybackService::precacheTtsText）
    int successCount = 0;
    int existsCount = 0;
    int failCount = 0;

    for (int i = 1; i <= 10; ++i) {
        QString chineseNumber = numberToChinese(i);
        QString warningText = QString("%1号皮带准备启动，请注意").arg(chineseNumber);
        QString cacheFilePath = m_tts->getCacheFilePath(warningText);

        // 检查缓存是否已存在
        if (QFile::exists(cacheFilePath)) {
            qDebug() << "   ✅ 缓存已存在:" << i << "号皮带";
            existsCount++;
        } else {
            qDebug() << "   🔄 预热缓存:" << i << "号皮带";

            // ✅ 同步调用，一个接一个完成
            if (m_tts && m_tts->synthesizeToFile(warningText, cacheFilePath)) {
                qDebug() << "   ✅ 缓存成功:" << i << "号皮带";
                successCount++;
            } else {
                qWarning() << "   ❌ 缓存失败:" << i << "号皮带";
                failCount++;
            }
        }
    }

    qDebug() << "✅ CommonControl: TTS缓存预热完成";
    qDebug() << "   统计: 已存在" << existsCount << "个，新生成" << successCount << "个，失败" << failCount << "个";
}
```

## 🎓 技术要点

### 为什么同步方式可行？

1. **启动阶段可以阻塞**
   - 用户可以等待几秒钟
   - 不影响用户体验

2. **TTS 服务不支持并发**
   - 一次只能处理一个请求
   - 必须顺序调用

3. **参考成功案例**
   - AlarmPlaybackService 已经证明可行
   - 10 个文本预缓存成功完成

### 为什么异步方式失败？

1. **异步 + 同步阻塞 = 灾难**
   - 定时器是异步的
   - synthesizeToFile 是同步阻塞的
   - 导致多个阻塞调用同时进行

2. **并发请求导致混乱**
   - TTS 服务无法处理并发
   - 响应丢失或错乱
   - 程序卡死
