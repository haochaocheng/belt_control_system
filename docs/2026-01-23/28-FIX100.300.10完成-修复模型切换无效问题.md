## 🔍 根本原因

### 代码分析

**文件**: `src/control/AudioManagementController.cpp`

**问题代码**（Lines 340-358）：
```cpp
void AudioManagementController::testTts(const QString &text)
{
    // 使用Test场景的配置
    int modelIndex = m_config->modelIndex(TTSConfigManager::Test);  // ✅ 读取了索引
    int speakerId = m_config->speakerId(TTSConfigManager::Test);
    double rate = m_config->rate(TTSConfigManager::Test);
    double volume = m_config->volume(TTSConfigManager::Test);

    qDebug() << "  模型索引:" << modelIndex;
    qDebug() << "  说话人ID:" << speakerId;

    // ❌ 没有读取 modelPath
    // ❌ 没有调用 switchModel()

    m_tts->setSceneName("Test");
    m_tts->setSpeakerId(speakerId);
    m_tts->setRate(rate);
    m_tts->setVolume(volume);
    m_tts->say(text);  // 使用的是初始化时的模型
}
```

**问题**：
1. **只读取了 modelIndex**，没有读取 modelPath
2. **没有调用 switchModel()**，TTS 引擎一直使用初始化时的模型
3. 虽然 UI 上选择了不同模型，但实际播放时没有切换

### 为什么日志显示了不同的模型名称？

**原因**：日志中的模型名称来自 `say()` 方法内部的调试输出，它显示的是**当前加载的模型**，而不是**应该使用的模型**。

由于没有调用 `switchModel()`，TTS 引擎一直使用的是：
- 初始化时加载的第一个模型（可能是 vits-zh-aishell3）
- 或者上一次手动切换后的模型

```cpp
void AudioManagementController::testTts(const QString &text)
{
    // 使用Test场景的配置
    int modelIndex = m_config->modelIndex(TTSConfigManager::Test);
    QString modelPath = m_config->modelPath(TTSConfigManager::Test);  // ✅ 读取模型路径
    int speakerId = m_config->speakerId(TTSConfigManager::Test);
    double rate = m_config->rate(TTSConfigManager::Test);
    double volume = m_config->volume(TTSConfigManager::Test);

    qDebug() << "  模型索引:" << modelIndex;
    qDebug() << "  模型路径:" << modelPath;  // ✅ 打印模型路径
    qDebug() << "  说话人ID:" << speakerId;

    // ✅ 2026-01-23 16:10 [FIX 100.300.10] 切换到选定的模型
    if (!modelPath.isEmpty() && modelPath != m_tts->currentModel()) {
        qDebug() << "🔄 [AudioMgmt] 切换TTS模型:" << modelPath;
        bool success = m_tts->switchModel(modelPath);
        if (!success) {
            qWarning() << "❌ [AudioMgmt] 模型切换失败:" << modelPath;
            emit errorOccurred("模型切换失败");
            return;
        }
        qDebug() << "✅ [AudioMgmt] 模型切换成功";
    }

    m_tts->setSceneName("Test");
    m_tts->setSpeakerId(speakerId);
    m_tts->setRate(rate);
    m_tts->setVolume(volume);
    m_tts->say(text);
}
```

## 🎓 技术要点

### 1. TTS 模型切换流程

**完整流程**：
```
用户选择模型
    ↓
TTSConfig 保存 modelIndex 和 modelPath
    ↓
testTts() 读取配置
    ↓
检查 modelPath != currentModel()
    ↓
调用 switchModel(modelPath)
    ↓
TTS 服务重新加载模型
    ↓
设置说话人 ID、语速、音量
    ↓
播放测试语音
```

### 2. 为什么需要检查 currentModel()?

**优化原因**：
- 避免重复切换相同模型
- 模型切换需要时间（重新加载模型文件）
- 如果已经是目标模型，直接使用即可

**代码**：
```cpp
if (!modelPath.isEmpty() && modelPath != m_tts->currentModel()) {
    // 只在模型不同时才切换
    m_tts->switchModel(modelPath);
}
```

### 3. 模型切换失败处理

**可能的失败原因**：
- 模型路径不存在
- 模型文件损坏
- TTS 服务进程异常
- 内存不足

**处理方式**：
```cpp
bool success = m_tts->switchModel(modelPath);
if (!success) {
    qWarning() << "❌ [AudioMgmt] 模型切换失败:" << modelPath;
    emit errorOccurred("模型切换失败");
    return;  // 不继续播放
}
```

### 4. TTSConfig 的两个关键属性

**modelIndex**：
- 类型：int（0-6）
- 用途：UI 显示、下拉框选择
- 存储：QSettings

**modelPath**：
- 类型：QString（完整路径）
- 用途：实际加载模型
- 示例：`/app/models/vits-zh-aishell3`

**关系**：
```cpp
modelIndex → modelPath
    0      → /app/models/vits-zh-aishell3
    1      → /app/models/vits-zh-hf-fanchen-wnj
    2      → /app/models/vits-zh-hf-fanchen-C
    ...
```

## 📝 经验教训

### 教训 1: 配置读取要完整

**问题**: 只读取了 modelIndex，没有读取 modelPath

**原因**:
- modelIndex 用于 UI 显示
- modelPath 才是实际使用的路径
- 两者都需要读取

**正确做法**:
```cpp
int modelIndex = config->modelIndex(scene);    // UI 显示
QString modelPath = config->modelPath(scene);  // 实际使用 ✅
```

### 教训 2: 不要假设状态会自动同步

**问题**: 假设 UI 选择模型后，TTS 引擎会自动切换

**真相**:
- UI 只更新了配置（TTSConfig）
- TTS 引擎需要显式调用 switchModel()
- 状态不会自动同步

**正确做法**:
- 读取配置后，显式调用切换方法
- 不要依赖隐式的状态同步

### 教训 3: 日志可能误导

**问题**: 日志显示了模型名称，但实际没有切换

**原因**:
- 日志显示的是"当前加载的模型"
- 不是"应该使用的模型"
- 两者可能不一致

**正确做法**:
- 打印关键操作（如模型切换）
- 打印前后状态对比
- 不要只看结果，要看过程

### 教训 4: 用户反馈很重要

**问题**: 代码看起来正确（日志显示模型名称），但用户说声音一样

**启示**:
- 用户的感知是最真实的反馈
- 不要只相信日志，要相信用户体验
- 日志可能只显示部分真相
