## ✅ 修复方案

### 核心思路

**不再硬编码 model.onnx，而是智能查找模型文件**

**查找逻辑**：
1. 优先使用 `model.onnx`（兼容旧模型）
2. 如果不存在，查找第一个 `.onnx` 文件
3. 如果都找不到，返回默认路径（后续会失败并报错）

### 修复：添加智能模型文件查找函数

**文件**: `src/tts_service/sherpa_tts_service.cpp`

**修改 2: 添加智能查找函数（Lines 167-214）**：

```cpp
// ✅ 2026-01-23 20:30 [FIX 100.300.16] 智能查找模型文件
// 原因：不同模型的 .onnx 文件名不同（model.onnx vs vits-xxx.onnx）
// 方案：优先使用 model.onnx，如果不存在则查找第一个 .onnx 文件
std::string findModelFile(const std::string& model_dir) {
    // 优先使用 model.onnx
    std::string default_path = model_dir + "/model.onnx";
    #ifdef _WIN32
    struct _stat buffer;
    if (_stat(default_path.c_str(), &buffer) == 0) {
        return default_path;
    }
    #else
    struct stat buffer;
    if (stat(default_path.c_str(), &buffer) == 0) {
        return default_path;
    }
    #endif

    // 如果 model.onnx 不存在，查找第一个 .onnx 文件
    #ifdef _WIN32
    // Windows: 使用 _findfirst/_findnext
    struct _finddata_t fileinfo;
    std::string pattern = model_dir + "/*.onnx";
    intptr_t handle = _findfirst(pattern.c_str(), &fileinfo);
    if (handle != -1) {
        std::string found = model_dir + "/" + fileinfo.name;
        _findclose(handle);
        return found;
    }
    #else
    // Linux: 使用 opendir/readdir
    DIR* dir = opendir(model_dir.c_str());
    if (dir) {
        struct dirent* entry;
        while ((entry = readdir(dir)) != nullptr) {
            std::string filename = entry->d_name;
            if (filename.size() > 5 && filename.substr(filename.size() - 5) == ".onnx") {
                closedir(dir);
                return model_dir + "/" + filename;
            }
        }
        closedir(dir);
    }
    #endif

    // 如果都找不到，返回默认路径（会在后续失败）
    return default_path;
}
```

## 🎓 技术要点

### 1. 跨平台目录遍历

**Windows**：
```cpp
#include <io.h>
struct _finddata_t fileinfo;
intptr_t handle = _findfirst("path/*.onnx", &fileinfo);
if (handle != -1) {
    std::string filename = fileinfo.name;
    _findclose(handle);
}
```

**Linux**：
```cpp
#include <dirent.h>
DIR* dir = opendir("path");
struct dirent* entry;
while ((entry = readdir(dir)) != nullptr) {
    std::string filename = entry->d_name;
}
closedir(dir);
```

### 2. 文件存在性检查

**Windows**：
```cpp
#include <sys/stat.h>
struct _stat buffer;
bool exists = (_stat(path.c_str(), &buffer) == 0);
```

**Linux**：
```cpp
#include <sys/stat.h>
struct stat buffer;
bool exists = (stat(path.c_str(), &buffer) == 0);
```

### 3. 智能查找策略

**优先级**：
1. **model.onnx** - 标准命名（兼容旧模型）
2. **第一个 .onnx 文件** - 自动适配新模型
3. **返回默认路径** - 让 Sherpa-ONNX 报错（更清晰的错误信息）

**为什么不直接报错？**
- 让 Sherpa-ONNX 库处理文件不存在的情况
- 可以获得更详细的错误信息
- 保持代码简洁

### 4. 调试日志的重要性

**添加日志**：
```cpp
std::cerr << "Using model file: " << model_path << std::endl;
```

**好处**：
- 方便验证查找逻辑是否正确
- 快速定位模型文件问题
- 帮助用户理解加载过程

## 📝 经验教训

### 教训 1: 不要假设文件命名一致

**问题**: 假设所有模型都有 `model.onnx` 文件

**真相**:
- 不同来源的模型命名不同
- vits-zh-aishell3 有 model.onnx
- vits-zh-hf-fanchen-wnj 只有 vits-zh-hf-fanchen-wnj.onnx

**启示**:
- 配置要考虑多样性
- 使用智能查找而非硬编码
- 为不同情况提供兼容方案

### 教训 2: 调试要深入到底层

**调试路径**:
1. 用户报告：模型切换失败

**启示**:
- 不要满足于表面修复
- 深入到底层代码分析
- 对比成功和失败的案例
- 验证假设（检查文件结构）

### 教训 3: 日志是最好的调试工具

std::cerr << "Using model file: " << model_path << std::endl;
