## 📋 问题回顾

### 原始问题
- **现象**: TTS合成延时1.8-2秒，不可接受
- **根本原因**: 相同文本"一号皮带准备启动，请注意"每次都重新合成
- **日志证据**: voip.md 显示相同文本合成3次，每次约1.9秒

### 现有方案分析
- **AlarmPlaybackService**: 已有TTS缓存，但只缓存10个报警文本
- **SherpaOnnxTTS::sayToNetwork()**: 无缓存机制，使用临时文件（QTemporaryFile）
- **CommonControl::playWarningOnce()**: 调用sayToNetwork()，每次都重新合成

### 问题根源
起车预警文本不在AlarmPlaybackService的缓存列表中，且sayToNetwork()没有缓存机制。

---

## 🎯 解决方案

### 方案设计
在SherpaOnnxTTS层添加智能缓存机制（底层统一方案）：
1. 首次合成后缓存到持久化文件
2. 后续播放直接使用缓存（<50ms）
3. 系统启动时预热1-10号皮带文本

### 与现有方案的区别

| 特性 | 现有方案（AlarmPlaybackService） | 新方案（SherpaOnnxTTS） |
|------|--------------------------------|------------------------|
| **缓存范围** | 仅10个报警文本 | 所有TTS文本（报警+起车预警+其他） |
| **调用路径** | AlarmPlaybackService专用 | 所有TTS调用（底层统一） |
| **起车预警** | ❌ 不支持（每次1.9秒） | ✅ 支持（首次1.9秒，后续<50ms） |
| **预热机制** | 仅报警文本 | 报警文本 + 起车预警文本（1-10号皮带） |
| **实施难度** | - | 简单（只修改SherpaOnnxTTS） |

**修改后**（使用持久化缓存）:
```cpp
void SherpaOnnxTTS::sayToNetwork(const QString &text, bool useTcp)
{
    // ✅ 检查缓存
    QString cacheFilePath = getCacheFilePath(text);

    if (QFile::exists(cacheFilePath)) {
        // 缓存命中，直接使用（<50ms）
        qDebug() << "   ✅ 使用TTS缓存（零延时）:" << cacheFilePath;

        if (useTcp) {
            m_tcpSender->playAudioToNetwork(cacheFilePath);
        }
        return;
    }

    // 缓存未命中，合成并缓存
    qDebug() << "   ⚠️  缓存未命中，开始TTS合成...";

    if (!synthesize(text, cacheFilePath)) {
        return;
    }

    qDebug() << "   💾 已缓存，下次播放将零延时";

    // 发送到网络
    if (useTcp) {
        m_tcpSender->playAudioToNetwork(cacheFilePath);
    }
}
```

**关键改进**:
1. ✅ 使用持久化文件路径（而非临时文件）
2. ✅ 缓存检查逻辑（QFile::exists）
3. ✅ 缓存命中时跳过合成（零延时）
4. ✅ 缓存未命中时合成并保存

### 修改3: SherpaOnnxTTS.cpp - getCacheFilePath实现

**文件**: [src/control/SherpaOnnxTTS.cpp](../../src/control/SherpaOnnxTTS.cpp:602-615)

```cpp
// ✅ 2026-01-23 09:00 [FIX 100.300.1] 获取TTS缓存文件路径
QString SherpaOnnxTTS::getCacheFilePath(const QString &text) const
{
    // 生成缓存文件路径
    // 使用 qHash 生成文本哈希值（16进制）
    QString cacheKey = QString::number(qHash(text), 16);

    // 缓存目录：/app/appdata/tts_cache/
    // 文件命名：network_{qHash}.wav
    // 与 AlarmPlaybackService 的缓存共用目录，但使用不同前缀区分
    QString cacheFilePath = QString("/app/appdata/tts_cache/network_%1.wav").arg(cacheKey);

    return cacheFilePath;
}
```

**缓存文件命名策略**:
- AlarmPlaybackService: `alarm_{MD5}.wav`
- SherpaOnnxTTS: `network_{qHash}.wav`
- 共用目录但不同前缀，避免冲突

### 修改6: CommonControl.cpp - 预热实现

**文件**: [src/control/CommonControl.cpp](../../src/control/CommonControl.cpp:1196-1231)

```cpp
// ✅ 2026-01-23 09:00 [FIX 100.300.1] TTS缓存预热实现
void CommonControl::preloadTTSCache()
{
    qDebug() << "🔥 CommonControl: 启动TTS缓存预热（异步）...";

    if (!m_tts || m_tts->state() != SherpaOnnxTTS::Ready) {
        qWarning() << "⚠️ CommonControl: TTS引擎不可用，跳过缓存预热";
        return;
    }

    // 预合成1-10号皮带的预警文本
    for (int i = 1; i <= 10; ++i) {
        // 延迟启动，避免阻塞主线程（每个间隔200ms）
        QTimer::singleShot(i * 200, this, [this, i]() {
            QString chineseNumber = numberToChinese(i);
            QString warningText = QString("%1号皮带准备启动，请注意").arg(chineseNumber);

            // 生成缓存文件路径
            QString cacheFilePath = m_tts->getCacheFilePath(warningText);

            // 检查缓存是否已存在
            if (!QFile::exists(cacheFilePath)) {
                qDebug() << "   🔄 预热缓存:" << i << "号皮带";

                // 异步合成到缓存
                if (m_tts) {
                    m_tts->synthesizeToFile(warningText, cacheFilePath);
                }
            } else {
                qDebug() << "   ✅ 缓存已存在:" << i << "号皮带";
            }
        });
    }

    qDebug() << "✅ CommonControl: TTS缓存预热已启动（后台进行）";
}
```

**预热策略**:
- 延迟5秒启动（等待系统稳定）
- 每个文本间隔200ms合成（避免CPU峰值）
- 检查缓存是否已存在（避免重复合成）
- 异步后台执行（不阻塞主线程）
