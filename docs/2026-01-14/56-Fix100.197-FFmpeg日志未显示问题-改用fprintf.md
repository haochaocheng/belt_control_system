# Fix 100.197 - FFmpeg 日志未显示问题 - 改用 fprintf(stderr)

**时间**: 2026-01-15 23:15
**状态**: 🔧 待实施
**问题**: FIX 100.196 诊断日志未出现在测试输出中

---

## 🔍 问题分析

### 症状
- PJSIP 修改（max_b_frames=2）出现在日志中 ✅
- FFmpeg 修改（FIX 100.196 DIAG）不出现在日志中 ❌
- 用户坚持编译是最新的："100%是最新的"

### 根本原因
**两个日志系统分离**：
- `av_log(avctx, AV_LOG_WARNING, ...)` → FFmpeg 日志系统 → **stderr**
- `PJ_LOG(level, (THIS_FILE, ...))` → PJSIP 日志系统 → **设备串口/文件**

用户提供的 voip.md 日志只包含 PJSIP 的 `PJ_LOG()` 输出，**不包含 FFmpeg 的 stderr 输出**！

### 证据
1. FIX 68 的日志正常出现：
   ```
   14:39:58.702 ffmpeg_vid_codecs.c ...✅ libx264 detected: Setting ESSENTIAL fields ONLY
   ```
   → 因为使用的是 `PJ_LOG()`

2. FIX 100.196 DIAG 不出现：
   ```c
   av_log(avctx, AV_LOG_WARNING, "[FIX 100.196 DIAG] ...");
   ```
   → 因为使用的是 `av_log()`，输出到 stderr，未被捕获

---

## 🎯 解决方案

### 修改 libx264.c Line 1306-1308

**原代码**（使用 av_log）：
```c
av_log(avctx, AV_LOG_WARNING,
       "[FIX 100.196 DIAG] delayed_frames=%d, nb_reordered_opaque=%d\n",
       delayed_frames, x4->nb_reordered_opaque);
```

**新代码**（使用 fprintf + fflush）：
```c
/* 🔍 诊断日志：打印计算结果（使用 fprintf 确保输出）*/
fprintf(stderr, "[FIX 100.196 DIAG] delayed_frames=%d, nb_reordered_opaque=%d\n",
        delayed_frames, x4->nb_reordered_opaque);
fflush(stderr);  // 强制立即刷新，防止缓冲
```

**原因**：
- `fprintf(stderr, ...)` 直接输出到标准错误流
- `fflush(stderr)` 强制立即输出，不缓冲
- 即使程序崩溃，日志也能输出

### 同时修改 Line 1299-1302（条件日志）

**原代码**：
```c
if (x4->nb_reordered_opaque < 1) {
    av_log(avctx, AV_LOG_WARNING,
           "[FIX 100.196] nb_reordered_opaque was %d (delayed_frames=%d), forcing to 1\n",
           x4->nb_reordered_opaque, delayed_frames);
    x4->nb_reordered_opaque = 1;
}
```

**新代码**：
```c
if (x4->nb_reordered_opaque < 1) {
    fprintf(stderr, "[FIX 100.196] nb_reordered_opaque was %d (delayed_frames=%d), forcing to 1\n",
            x4->nb_reordered_opaque, delayed_frames);
    fflush(stderr);
    x4->nb_reordered_opaque = 1;
}
```

## 📝 完整修改代码

**文件**: `cross-compile/src/ffmpeg-rockchip-6.0/libavcodec/libx264.c`
**位置**: Line 1284-1315

```c
/* ✅ 2026-01-15 23:15 [FIX 100.197 - 改用 fprintf(stderr) 确保日志输出]
 * 问题：av_log() 输出到 FFmpeg 日志系统，PJSIP 日志未捕获
 * 修复：使用 fprintf(stderr) + fflush(stderr) 确保立即输出
 * 参考：docs/2026-01-14/56-Fix100.197-FFmpeg日志未显示问题-改用fprintf.md
 */
// Overestimate the reordered opaque buffer size, in case a runtime
// reconfigure would increase the delay (which it shouldn't).
int delayed_frames = x264_encoder_maximum_delayed_frames(x4->enc);
x4->nb_reordered_opaque = delayed_frames + 17;

/* ⭐ 强制最小值为 1（防止数组越界）*/
if (x4->nb_reordered_opaque < 1) {
    fprintf(stderr, "[FIX 100.196] nb_reordered_opaque was %d (delayed_frames=%d), forcing to 1\n",
            x4->nb_reordered_opaque, delayed_frames);
    fflush(stderr);
    x4->nb_reordered_opaque = 1;
}

/* 🔍 诊断日志：打印计算结果（使用 fprintf 确保输出）*/
fprintf(stderr, "[FIX 100.196 DIAG] delayed_frames=%d, nb_reordered_opaque=%d\n",
        delayed_frames, x4->nb_reordered_opaque);
fflush(stderr);

x4->reordered_opaque    = av_calloc(x4->nb_reordered_opaque,
                                    sizeof(*x4->reordered_opaque));
if (!x4->reordered_opaque) {
    x4->nb_reordered_opaque = 0;
    return AVERROR(ENOMEM);
}

return 0;
```

## ✍️ 总结

**问题核心**：
- `av_log()` 输出到 FFmpeg 日志系统（stderr）
- 用户日志只捕获 PJSIP 的 `PJ_LOG()` 输出
- 导致 FFmpeg 诊断日志"丢失"

**解决方案**：
- 改用 `fprintf(stderr, ...)` + `fflush(stderr)`
- 确保日志立即输出到标准错误流
- 即使程序崩溃也能看到诊断信息

**预期效果**：
- FIX 100.196 DIAG 日志出现在设备输出中
- 确认 `delayed_frames` 和 `nb_reordered_opaque` 的值
- 验证修复是否有效
