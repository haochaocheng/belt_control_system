**版本判断错误**：

**结果**：
1. DRM_PRIME 格式没有被转换
2. PJSIP 无法处理 GPU 内存格式
3. 返回 `PJ_ENOTFOUND` 错误

### 为什么 58.137 这个版本号？

**历史原因**（推测）：
- 原开发者可能基于 FFmpeg 5.x 的某个版本（libavcodec 58.137+）
- 在那个版本之后，FFmpeg 引入了新的 API 或修复了某些 bug
- 但 FFmpeg 6.1 的 libavcodec 版本号回退到 58.91

**实际情况**：
- FFmpeg 版本号（6.1）和 libavcodec 版本号（58.91）不完全对应
- libavcodec 58.x 系列都支持相同的 API
- 应该基于功能而非具体版本号来判断

### DRM_PRIME 格式问题

**什么是 DRM_PRIME**：
- 格式 ID：179
- 用途：GPU 内存，用于硬件加速的零拷贝
- 特点：数据在 GPU 显存中，CPU 无法直接访问

**为什么需要转换**：
- PJSIP 使用 `pj_pool_alloc` 分配系统内存
- 无法直接访问 GPU 内存
- 需要调用 `av_hwframe_transfer_data()` 将 GPU 内存拷贝到系统内存

**Fix 90 的作用**：
- 检测 DRM_PRIME 格式（179）
- 分配系统内存帧（`av_frame_alloc()`）
- 执行 GPU → CPU 内存转换（`av_hwframe_transfer_data()`）
- 转换为 I420（0）或 NV12（23）格式
- PJSIP 可以处理系统内存格式
