```

但运行时使用的是 libx264rgb：
```

### 2. 检查编码器选择逻辑
**代码路径**：
- 初始化：`pjmedia_codec_ffmpeg_init()` → 注册编解码器到 `codec_desc[]`
- 运行时：`ffmpeg_alloc_codec()` → `ff->enc = desc->enc;` (line 1803)
- 打开：`open_ffmpeg_codec()` → 使用 `ff->enc->name` (line 2406)

**结论**：`desc->enc` 被设置为 libx264rgb，说明初始化时注册了错误的编码器。

### 3. 检查编解码器注册逻辑
**关键代码** (line 959-965)：
```c
/* Skip duplicated codec implementation */
if ((is_encoder && (desc->info.dir & PJMEDIA_DIR_ENCODING))
    ||
    (is_decoder && (desc->info.dir & PJMEDIA_DIR_DECODING)))
{
    return;  // 跳过重复的编解码器
}
```

**结论**：**第一个注册的编码器会被使用**，后续相同 codec_id 的编码器会被跳过。

## 💡 根本原因 ⭐

### 代码分支问题

**ffmpeg_vid_codecs.c** (lines 1100-1487) 有两个互斥的代码分支：

#### 分支 A：`#if LIBAVCODEC_VER_AT_LEAST(58,137)` (lines 1100-1316)
- **条件**：libavcodec ≥ 58.137
- **内容**：我们的硬件编码器注册代码（lines 1125-1294）
- **状态**：⛔ **不执行**（当前版本 58.91.100 < 58.137）

#### 分支 B：`#else` (lines 1318-1487)
- **条件**：libavcodec < 58.137
- **内容**：`av_codec_iterate()` 遍历所有 FFmpeg 编解码器（line 1472-1480）
- **状态**：✅ **执行**（当前环境满足条件）

### 执行流程

**实际执行的代码**：
```c
#else  // FFmpeg < 58.137 (line 1318)
    // ... 旧版 FFmpeg 兼容代码 ...

    // Line 1472-1480: 遍历所有 FFmpeg 编解码器
    void *opaque = NULL;
    while ((c = av_codec_iterate(&opaque))) {
        // 注册所有编解码器，包括 h264_rkmpp 和 libx264rgb
        init_codec(c, AVCODEC_HAS_ENCODE(c), AVCODEC_HAS_DECODE(c));
    }
#endif
```

**问题**：
1. `av_codec_iterate()` 按照 FFmpeg 内部顺序遍历
2. libx264rgb 在 h264_rkmpp **之前**被注册
3. `init_codec()` 跳过重复编解码器
4. **结果**：libx264rgb 被注册并使用，h264_rkmpp 被跳过！

### 我们的代码位置错误

**硬件编码器注册代码**（lines 1125-1294）在：
```c
#if LIBAVCODEC_VER_AT_LEAST(58,137)  // ← 条件不满足！
    // Line 1129: int enable_hw_encoder = 1;
    // Line 1144: hw_encoder_name = "h264_rkmpp";
    // Line 1189-1260: 注册 h264_rkmpp 编码器
    // ...
#else  // ← 实际执行的是这里
    // 这里没有我们的硬件编码器注册代码！
    // 只有 av_codec_iterate() 遍历所有编解码器
#endif
```

---

## ✅ 解决方案

### 方案：将硬件编码器注册逻辑移到 `#else` 分支

**修改位置**：
- 将 lines 1125-1294（硬件编码器注册代码）
- 移到 `#else` 分支的开头（line 1318 之后）
- **在 `av_codec_iterate()` 之前**执行

**修改后的执行顺序**：
```c
#else  // FFmpeg < 58.137
    // ✅ 1. 首先注册 h264_rkmpp 硬件编码器（如果 enable_hw_encoder = 1）
    //    → codec_desc[idx].enc = h264_rkmpp
    //    → codec_desc[idx].info.dir |= PJMEDIA_DIR_ENCODING

    // 2. 然后遍历所有 FFmpeg 编解码器
    av_codec_iterate() {
        // 当遇到 libx264rgb 时：
        // if (desc->info.dir & PJMEDIA_DIR_ENCODING)  // ← TRUE（h264_rkmpp已注册）
        //     return;  // ← 跳过 libx264rgb ✅
    }
#endif
```

**预期效果**：
1. ✅ h264_rkmpp 先注册
2. ✅ libx264rgb 被跳过
3. ✅ 运行时使用 h264_rkmpp
4. ✅ DRM_PRIME 格式直接传递
5. ✅ 不再崩溃

## 📚 技术细节

### LIBAVCODEC_VER_AT_LEAST 宏定义

**定义** (libavcodec/version.h)：
```c
#define LIBAVCODEC_VER_AT_LEAST(major, minor) \
    (LIBAVCODEC_VERSION_MAJOR > major || \
     (LIBAVCODEC_VERSION_MAJOR == major && LIBAVCODEC_VERSION_MINOR >= minor))
```

**当前环境**：
- `LIBAVCODEC_VERSION_MAJOR` = 58
- `LIBAVCODEC_VERSION_MINOR` = 91
- `LIBAVCODEC_VERSION_MICRO` = 100
- 完整版本：**58.91.100**

**条件判断**：
```c
LIBAVCODEC_VER_AT_LEAST(58, 137)
= (58 > 58 || (58 == 58 && 91 >= 137))
= (FALSE || (TRUE && FALSE))
= FALSE  ← 不满足条件
```

### av_codec_iterate() 顺序

**FFmpeg 6.0/6.1** 中，`av_codec_iterate()` 按照编解码器在 FFmpeg 库中的注册顺序遍历：

**H.264 编解码器顺序**（根据日志）：
1. Codec 193: h264_rkmpp (encoder=1, decoder=0)
2. Codec 288: h264_rkmpp (encoder=1, decoder=1)
3. ...其他编解码器...
4. **libx264rgb** (encoder=1, decoder=0)  ← 较晚注册

**但实际执行结果**：libx264rgb 被使用

**原因分析**：
- 虽然 h264_rkmpp 被遍历到（Codec 193, 288）
- 但 `init_codec()` 可能因为某些条件（如 `c->pix_fmts` 为空）提前返回
- 导致 h264_rkmpp 没有被成功注册
- 后来 libx264rgb 成功注册并被使用

**验证**：查看 `init_codec()` 函数的日志（line 973-1040）

## 📝 总结

### 根因
硬件编码器注册代码在错误的 `#if` 分支中：
- **代码位置**：`#if LIBAVCODEC_VER_AT_LEAST(58,137)` 分支
- **当前环境**：libavcodec 58.91.100 < 58.137
- **结果**：代码不执行，h264_rkmpp 未注册，libx264rgb 被使用

### 影响
- ❌ 硬件编码器完全失效
- ❌ 软件编码器 libx264rgb 无法处理 DRM_PRIME 格式
- ❌ 视频通话崩溃（exit code 139）

### 解决方案
将硬件编码器注册代码移到 `#else` 分支，在 `av_codec_iterate()` 之前执行。

### 优先级
🔴 **紧急**：这是阻止硬件编码器工作的根本原因
