## ✅ 用户确认的参数（2026-01-21 19:30）

### 网络参数（固定，不可更改）

```cpp
// UDP 组播配置（音频模块预定义）
QString udpMulticastAddress = "224.1.1.1";         // 组播地址（固定）
quint16 udpPort = 8800;                             // 组播端口（固定）
QByteArray multicastMAC = {0x01,0x00,0x5e,0x01,0x01,0x01};  // 组播 MAC（固定）

// 数据包格式
// 纯 Opus 帧，无协议头
// 格式：[Opus Data (20ms)]
```

### 音频参数

```cpp
// PCM 参数
int sampleRate = 16000;      // 16kHz（固定）
int channels = 1;            // 单声道（固定）
int bitDepth = 16;           // 16bit（固定）

// Opus 编码参数
int opusBitrate = 16000;     // 16kbps（可调整 16-32kbps）
int opusFrameDuration = 20;  // 20ms（固定）

// 计算：
// 20ms @ 16kHz = 320 样本 × 2 字节 = 640 字节 PCM
// 编码后 ≈ 40 字节 Opus @ 16kbps
```

### 音频源

1. **MP3 文件**（预录音频）
   - 如："1号皮带启动.mp3"
   - 需要：解码 MP3 → PCM → Opus 编码 → UDP 发送

2. **TTS 语音**（Sherpa-ONNX）
   - 输出：WAV 文件（PCM, 16bit, 单声道, 采样率由模型决定）
   - 位置：临时文件（QTemporaryFile）
   - 需要：WAV 解码 → PCM → Opus 编码 → UDP 发送

### 实现方式

1. **网络库**：Qt QUdpSocket（跨平台：Windows + Linux）
2. **发送策略**：批量发送 + 实时发送（通过 if 选择）
   - 批量发送：解码全部 → 编码全部 → 定时发送（20ms 定时器）
   - 实时发送：边解码边编码边发送（如批量延迟过高）
3. **输出模式**：双输出（本地 ES8388 + 网络音频模块同时）

## ⚠️ 关键风险和缓解措施

### 风险 1：音频模块协议不明确（🔴 高风险）

**影响**：
- 无法确定数据包格式
- 可能需要多次试错

**缓解措施**：
1. **优先**：获取官方协议文档或示例代码
2. **备选**：使用 Wireshark 抓包分析现有设备通讯
3. **最后**：联系音频模块厂商技术支持

### 风险 2：FFmpeg 库冲突（🟡 中风险）

**影响**：
- 音频解码可能与现有视频编解码器冲突
- 可能需要重新编译 FFmpeg

**缓解措施**：
1. 复用现有 FFmpeg 库（优先）
2. 如冲突，使用独立的 FFmpeg 实例（隔离）
3. 如需重新编译，参考 `scripts/2026-01-18/21-Opus编译脚本创建完成-Phase1完成.md`

### 风险 3：Opus 编码性能（🟢 低风险）

**影响**：
- RK3588 CPU 编码 Opus 可能有延迟
- 可能影响实时性

**缓解措施**：
1. 使用 Opus 的 VOIP 模式（低延迟）
2. 设置较低的复杂度（OPUS_SET_COMPLEXITY(5)）
3. 如性能不足，考虑使用硬件加速或更简单的编码器

### 风险 4：网络不稳定（🟡 中风险）

**影响**：
- UDP 组播丢包
- TCP 连接断开

**缓解措施**：
1. UDP：添加简单的 FEC（前向纠错）或重传机制
2. TCP：实现自动重连机制
3. 添加网络状态监控和日志
