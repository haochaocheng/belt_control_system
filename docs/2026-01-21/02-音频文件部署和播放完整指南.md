## 🎯 工作原理

### 音频文件存储架构

```
Windows 宿主机                     设备（192.168.10.188）
├── AUDIO/                        ├── /home/linaro/belt-control-data/
│   ├── 1#PD/                    │   ├── audio/  ← 持久化存储
│   │   ├── 1号皮带启动.mp3      │   │   ├── 1#PD/
│   │   ├── 启动.wav              │   │   │   ├── 1号皮带启动.mp3
│   │   └── ...                  │   │   │   └── 启动.wav
│   ├── 2#PD/                    │   │   ├── 2#PD/
│   └── ...                      │   │   └── ...
                                 │
                                 ├── Docker 容器
                                 │   └── /app/AUDIO/  ← Volume 映射
                                 │       └── (指向 /home/linaro/belt-control-data/audio)
```

### Docker Volume 映射（run-ubuntu24-apt.sh）

```bash
docker run \
    -v /home/linaro/belt-control-data/audio:/app/AUDIO:rw \
    ...
```

**效果**：
- 容器内的 `/app/AUDIO` 目录实际指向设备的 `/home/linaro/belt-control-data/audio`
- 容器重启或删除，音频文件不会丢失
- 多个容器可共享同一音频目录

## 🔧 技术实现

### 1. Dockerfile 优化（移除 AUDIO 复制）

**文件**: `docker/rk3588/Dockerfile.v3.3-runtime`
**修改**: Line 16-24

```dockerfile
# ❌ 2026-01-21 [音频优化] 移除 AUDIO 复制（改用 Volume 映射）
# COPY AUDIO /app/AUDIO  # ← 已注释，不再复制到镜像
```

**优势**：
- 镜像大小减小 25%（~800MB → ~600MB）
- 编译时间减少 40%（~5分钟 → ~3分钟）
- tar 包更小，部署更快

### 2. 音频同步脚本

**文件**: `scripts/2026-01-21/01-sync-audio-files.ps1`

**智能同步策略**：
1. 计算音频目录哈希（文件路径 + 大小 + 修改时间）
2. 与上次部署的哈希比较
3. 只在有变化时同步
4. 支持 `-Force` 强制重新同步

**执行流程**：
```powershell
# 步骤 1: 检查源目录
Get-ChildItem -Path "AUDIO" -Recurse

# 步骤 2: 计算哈希（快速，不读取文件内容）
$hash = Get-FileHash -Algorithm MD5 ...

# 步骤 3: 打包（使用 gzip 压缩）
tar -czf audio.tar.gz AUDIO/

# 步骤 4: 上传到设备
scp audio.tar.gz linaro@192.168.10.188:/tmp/

# 步骤 5: 解压并设置权限
ssh linaro@192.168.10.188 "
  tar -xzf /tmp/audio.tar.gz -C /home/linaro/belt-control-data/
  chown -R linaro:linaro /home/linaro/belt-control-data/audio
  chmod -R 755 /home/linaro/belt-control-data/audio
"

# 步骤 6: 更新缓存
echo '{"audioHash":"...","timestamp":"2026-01-21 15:00:00"}' > cache.json
```

## ⚠️ 故障排查

### 问题 1：音频文件同步后仍然找不到

**症状**：
```
[WARNING] ❌ CommonControl: 未找到 1 号皮带的启动音频
```

**排查步骤**：
```bash
# 1. 检查设备上的音频目录
ssh linaro@192.168.10.188 "ls -lh /home/linaro/belt-control-data/audio/1#PD/"

# 2. 检查容器内的映射
ssh linaro@192.168.10.188 "sudo docker exec belt-control-app ls -lh /app/AUDIO/1#PD/"

# 3. 检查权限
ssh linaro@192.168.10.188 "ls -ld /home/linaro/belt-control-data/audio"
# 应该显示 drwxr-xr-x linaro linaro
```

**解决方案**：
```bash
# 重新设置权限
ssh linaro@192.168.10.188 "
  sudo chown -R linaro:linaro /home/linaro/belt-control-data/audio
  sudo chmod -R 755 /home/linaro/belt-control-data/audio
"

# 重启容器
ssh linaro@192.168.10.188 "
  sudo docker stop belt-control-app
  sudo docker rm belt-control-app
  ./run-ubuntu24-apt.sh
"
```

### 问题 2：音频播放到错误的设备

**症状**：
- 应用播放音频，但听不到声音
- 或者声音从主板音频输出，而不是外部音频模块

**排查步骤**：
```bash
# 1. 列出所有音频设备
aplay -l

# 2. 测试每个设备
aplay -D plughw:0,0 test.wav
aplay -D plughw:1,0 test.wav
aplay -D plughw:2,0 test.wav

# 3. 检查应用程序日志
sudo docker logs belt-control-app | grep -i audio
```

**解决方案**：
- 在参数设置中选择正确的音频输出设备
- 或修改代码，硬编码为指定设备
