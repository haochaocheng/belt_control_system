# 音频播放到 ES8388 设备修复方案

**日期**: 2026-01-21
**问题**: 起车预警听不到声音
**根本原因**: 应用使用 Qt Multimedia 默认设备（HDMI），而不是 ES8388 音频芯片
**状态**: 待实施

---

## 📋 问题排查过程

### 1. 音频文件部署问题（已解决）

**问题序列**：
1. ❌ Windows tar.exe 无法处理 `#` 字符（编码问题）
2. ❌ PowerShell Compress-Archive 不支持 UTF-8 中文文件名（CP437 编码）
3. ❌ `mv AUDIO/* audio/` 通配符展开失败

**最终解决方案**：
- 使用 7-Zip 创建 UTF-8 编码的 zip 文件
- Linux 使用 `unzip -O UTF-8` 解压
- 整体移动目录（`mv AUDIO audio`）避免通配符问题

**相关文档**：
- [01-音频文件部署优化方案.md](01-音频文件部署优化方案.md)
- [02-音频文件部署和播放完整指南.md](02-音频文件部署和播放完整指南.md)

### 2. 容器 Volume 映射问题（已解决）

**问题**：容器启动时音频目录为空

**解决方案**：
- 先同步音频文件到设备：`/home/linaro/belt-control-data/audio`
- 再启动容器（自动映射 Volume）

**验证**：
```bash
# 设备上有 2166 个音频文件
find /home/linaro/belt-control-data/audio -type f | wc -l
# 输出：2166

# 容器内能看到音频文件
docker exec belt-control-app ls /app/AUDIO/1#PD/ | grep '启动'
# 输出：1号皮带启动.mp3, 6号皮带启动请注意.mp3, 集控起车启动.mp3
```

### 3. 音频设备配置问题（当前问题）

**硬件检测**：
```bash
aplay -l
```

**输出**：
```
card 1: rockchip-es8388 [rockchip-es8388], device 0
card 2: rockchip-hdmi0 [rockchip-hdmi0], device 0
card 3: rockchip-hdmi1 [rockchip-hdmi1], device 0
card 4: USB PnP Sound Device [USB Audio], device 0
```

**硬件测试**：
```bash
# 测试 ES8388 (Card 1) - ✅ 能正常听到声音
ffplay -nodisp -autoexit /home/linaro/belt-control-data/audio/1#PD/1号皮带启动.mp3

# 应用程序日志 - ✅ 能找到文件，但听不到声音
[DEBUG] ✅ CommonControl: 找到运行失败音频: "/app/AUDIO/1#PD/1号松闸运行失败.mp3"
[DEBUG] 🔊 CommonControl: 播放运行失败音频
```

**结论**：应用使用 Qt Multimedia 默认设备（可能是 HDMI），而不是 ES8388。

## 🔧 修复方案

### 1. 修改代码：指定使用 ES8388 设备

**文件**：`src/control/CommonControl.cpp`

**修改位置**：Line 13-36（构造函数）

**修改前**：
```cpp
CommonControl::CommonControl(QObject *parent)
    : QObject(parent)
    , m_mediaPlayer(new QMediaPlayer(this))
    , m_audioOutput(new QAudioOutput(this))  // ← 使用默认设备
    ...
{
    // 配置音频输出
    m_audioOutput->setVolume(1.0);  // 音量100%
    m_mediaPlayer->setAudioOutput(m_audioOutput);
    ...
}
```

**修改后**：
```cpp
CommonControl::CommonControl(QObject *parent)
    : QObject(parent)
    , m_mediaPlayer(new QMediaPlayer(this))
    , m_audioOutput(nullptr)  // ← 延迟初始化
    ...
{
    // ✅ 2026-01-21 [音频设备] 选择 ES8388 音频芯片（Card 1）
    // 原因：默认设备可能是 HDMI，导致听不到声音
    // 方案：枚举所有音频设备，选择 ES8388（包含 "es8388" 或 "rockchip-es8388"）

    QAudioDevice selectedDevice;
    const QList<QAudioDevice> devices = QMediaDevices::audioOutputs();

    qDebug() << "🔍 CommonControl: 枚举音频输出设备（共" << devices.size() << "个）:";
    for (const QAudioDevice &device : devices) {
        qDebug() << "   -" << device.description()
                 << (device.isDefault() ? "[默认]" : "");

        // 优先选择 ES8388 音频芯片
        QString desc = device.description().toLower();
        if (desc.contains("es8388") || desc.contains("rockchip-es8388")) {
            selectedDevice = device;
            qDebug() << "   ✅ 选择 ES8388 音频设备:" << device.description();
        }
    }

    // 如果没找到 ES8388，使用默认设备
    if (selectedDevice.isNull()) {
        selectedDevice = QMediaDevices::defaultAudioOutput();
        qWarning() << "⚠️  CommonControl: 未找到 ES8388 设备，使用默认设备:"
                   << selectedDevice.description();
    }

    // 创建音频输出并指定设备
    m_audioOutput = new QAudioOutput(selectedDevice, this);
    m_audioOutput->setVolume(1.0);  // 音量100%
    m_mediaPlayer->setAudioOutput(m_audioOutput);

    qDebug() << "🔊 CommonControl: 音频输出设备已配置:" << selectedDevice.description();

    // 连接信号...
    ...
}
```

## ⚠️ 可能的问题

### 问题 1：设备名称不匹配

**症状**：
```
⚠️  CommonControl: 未找到 ES8388 设备，使用默认设备: rockchip-hdmi0
```

**排查**：
```bash
# 在容器内检查 Qt 能看到的设备名称
docker exec -it belt-control-app bash
export QT_LOGGING_RULES="qt.multimedia*=true"
./belt_control_system
```

**解决**：根据实际设备名称调整匹配逻辑

### 问题 2：权限问题

**症状**：无法访问音频设备

**解决**：
```bash
# 确保容器映射了 /dev 目录
docker inspect belt-control-app | grep -A 5 '"/dev"'
```
