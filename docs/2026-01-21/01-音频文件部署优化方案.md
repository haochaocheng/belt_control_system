# 音频文件部署优化方案

**日期**: 2026-01-21
**问题**: 每次容器重新部署都复制音频文件，浪费时间
**目标**: 音频文件只部署一次，容器重启不丢失

---

## 🎯 核心思路

使用 **Docker Volume 持久化映射** + **单独的音频同步脚本**：

1. 音频文件存储在设备的持久化目录（`/home/linaro/belt-control-data/audio`）
2. 容器启动时映射这个目录（`-v /home/linaro/belt-control-data/audio:/app/AUDIO:rw`）
3. 应用容器不包含音频文件，镜像更小，构建更快
4. 音频文件单独同步一次，后续只在有更新时同步

## 🎓 技术细节

### Docker Volume vs COPY

**COPY（当前方式）**：
```dockerfile
COPY AUDIO /app/AUDIO  # ← 打包到镜像层
```
- ❌ 每次编译都包含音频文件
- ❌ 镜像大，部署慢
- ❌ 容器删除，音频文件丢失

**Volume 映射（推荐方式）**：
```bash
docker run -v /host/audio:/app/AUDIO:rw  # ← 运行时映射
```
- ✅ 音频文件存储在宿主机
- ✅ 镜像不包含音频文件（更小）
- ✅ 容器删除，音频文件保留
- ✅ 多个容器可共享同一音频目录

### 智能同步策略

**使用文件哈希缓存**：
```powershell
# 1. 计算 Windows 上 AUDIO 目录的哈希值
$audioHash = Get-FileHash -Path "AUDIO\*" -Algorithm MD5

# 2. 与上次部署的哈希比较
if ($audioHash -eq $previousHash) {
    Write-Host "音频文件无变化，跳过同步"
    exit 0
}

# 3. 只在有变化时同步
tar -czf audio.tar.gz AUDIO/
scp audio.tar.gz linaro@192.168.10.188:/tmp/
ssh linaro@192.168.10.188 "tar -xzf /tmp/audio.tar.gz -C /home/linaro/belt-control-data/"
```

## ⚠️ 注意事项

### 1. 音频文件权限

**问题**：设备上的 `~/AUDIO` 目录是 root 拥有
```bash
drwxr-xr-x  2 root   root        1024 12月 22 15:52 AUDIO
```

**解决**：同步脚本会自动设置正确的权限
```bash
sudo chown -R linaro:linaro /home/linaro/belt-control-data/audio
sudo chmod -R 755 /home/linaro/belt-control-data/audio
```

### 2. 容器内路径

**应用程序读取路径**：`/app/AUDIO/1#PD/`
- ✅ 容器内看到的路径是 `/app/AUDIO`
- ✅ 实际映射到设备的 `/home/linaro/belt-control-data/audio`
- ✅ 应用代码无需修改

### 3. 磁盘空间

**音频文件大小检查**：
```powershell
# Windows 上查看 AUDIO 目录大小
Get-ChildItem -Path "AUDIO" -Recurse -File |
    Measure-Object -Property Length -Sum |
    Select-Object @{Name="TotalMB";Expression={[math]::Round($_.Sum / 1MB, 2)}}
```

**设备磁盘空间检查**：
```bash
ssh linaro@192.168.10.188 "df -h /home/linaro"
```
