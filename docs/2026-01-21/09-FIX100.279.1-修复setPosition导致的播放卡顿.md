# FIX 100.279.1 - 修复 setPosition(0) 导致的播放卡顿

**日期**: 2026-01-21 17:00
**问题**: 重复播放音频时开头卡顿 300ms+
**根因**: `setPosition(0)` 导致 GStreamer 状态机切换延迟
**状态**: ✅ 代码修改完成，等待测试

### 根本原因定位

```
时间轴分析：

[0ms] playAudio() 调用
  ↓
[0-5ms] playAudio() 执行（stop + setPosition(0) + play）
  ↓
[5ms] playAudio() 返回
  ↓
  ⚠️ [5ms - 342ms] 等待状态转换（300ms+ 延迟）← 卡顿发生在这里！
  ↓
[342ms] 媒体状态变为 LoadedMedia
  ↓
[343ms] 开始播放音频 ✅
```

**结论**：
- `playAudio()` 调用本身很快（2-5ms）✅
- 卡顿发生在 `playAudio()` 返回之后 ❌
- **`setPosition(0)` 触发了 GStreamer 复杂的状态机切换** ← 真正的原因

## 技术原理

### setPosition(0) 的内部流程

```
QMediaPlayer::setPosition(0)
  ↓
GStreamer pipeline 处理：
  1. 停止当前播放
  2. 清除所有缓冲区
  3. Seek 到位置 0（需要重新解析文件）
  4. 重新初始化解码器状态
  5. 重新填充缓冲区
  6. 准备播放
  ↓
  ⚠️ 整个过程需要 300ms+
```

### 为什么第一次播放没有卡顿？

**第一次播放**：
```
[新源] 设置新音频源
setSource(newSource)  ← 正常流程，GStreamer 优化过的路径
  ↓
114ms 后 → LoadedMedia ✅（比较快）
```

**第二、三次播放**：
```
[重用] 同一音频源，重置位置
setPosition(0)  ← 异常流程，GStreamer 需要复杂处理
  ↓
337ms 后 → LoadedMedia ❌（很慢，卡顿！）
```

**关键差异**：
- `setSource(newSource)`：GStreamer 有优化的加载路径
- `setPosition(0)`：GStreamer 需要 seek 操作，更复杂

## 解决方案

### FIX 100.279.1：清空源 + 重新加载

**修改文件**: [src/control/CommonControl.cpp](../../src/control/CommonControl.cpp) Line 207-235

**修改前**（导致卡顿）：
```cpp
// 检查是否是同一个音频文件
if (currentSource == newSource) {
    // 同一个文件，只需重置位置并播放
    m_mediaPlayer->setPosition(0);  // ← 卡顿 300ms+
} else {
    // 不同文件，需要重新设置源
    m_mediaPlayer->setSource(newSource);
}
m_mediaPlayer->play();
```

**修改后**（避免卡顿）：
```cpp
// ✅ 2026-01-21 17:00 [FIX 100.279.1] 总是重新加载源（避免状态切换延迟）
// 原理：清空源 + 重新加载 比 setPosition(0) 快得多

m_mediaPlayer->stop();

// 清空源
qDebug() << "   [清空] 清空音频源";
m_mediaPlayer->setSource(QUrl());  // 清空源

// 重新加载
qDebug() << "   [新源] 设置新音频源:" << fileName;
QUrl newSource = QUrl::fromLocalFile(audioPath);
m_mediaPlayer->setSource(newSource);

m_mediaPlayer->play();
```

**关键变化**：
1. ❌ 不再区分"同一文件"和"不同文件"
2. ❌ 不再使用 `setPosition(0)`
3. ✅ 每次都清空源（`setSource(QUrl())`）
4. ✅ 每次都重新加载源（`setSource(newSource)`）

### 为什么清空+重新加载更快？

**GStreamer 内部优化路径**：

```
setPosition(0)：
  1. Seek 到位置 0
  2. 需要维护当前解码器状态
  3. 需要重新解析文件索引
  4. 需要清除缓冲但保留部分状态
  5. 状态机切换复杂
  → 耗时 300ms+ ❌

setSource(newSource)：
  1. 创建新的解码器实例
  2. 简单的线性加载流程
  3. GStreamer 有缓存优化
  4. 状态机切换简单
  → 耗时 ~114ms ✅
```

**为什么清空源？**
- `setSource(QUrl())` 强制 GStreamer 释放旧的 pipeline
- 确保下一次 `setSource(newSource)` 使用干净的初始化路径
- 避免任何残留状态导致的延迟

## 备选方案（如果 FIX 100.279.1 仍不理想）

### 方案 2：双 QMediaPlayer 交替播放

```cpp
class CommonControl {
private:
    QMediaPlayer *m_mediaPlayer1;
    QMediaPlayer *m_mediaPlayer2;
    bool m_usePlayer1 = true;

void playAudio(const QString &audioPath) {
    // 使用两个播放器交替播放，避免状态切换延迟
    QMediaPlayer *currentPlayer = m_usePlayer1 ? m_mediaPlayer1 : m_mediaPlayer2;
    QMediaPlayer *nextPlayer = m_usePlayer1 ? m_mediaPlayer2 : m_mediaPlayer1;

    // 预加载下一个播放器
    nextPlayer->setSource(QUrl::fromLocalFile(audioPath));

    // 停止当前播放器
    currentPlayer->stop();

    // 开始下一个播放器
    nextPlayer->play();

    // 切换
    m_usePlayer1 = !m_usePlayer1;
}
};
```

**优点**：
- 预加载机制，延迟更低（可能 <50ms）
- 完全避免状态切换问题

**缺点**：
- 代码复杂度高
- 需要管理两个播放器的生命周期
