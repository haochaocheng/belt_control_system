## 问题描述

### 现象
```
[DEBUG] 🔍 CommonControl: 枚举音频输出设备（共 0 个）:
[WARNING] ⚠️  CommonControl: 未找到 ES8388 设备，使用默认设备: ""
[WARNING] PulseAudioService: pa_context_connect() failed
```

- Qt Multimedia 无法枚举音频设备
- 音频文件播放无声音
- 日志显示 0 个音频输出设备

### 根本原因

1. **Qt Multimedia 设备枚举失败**：
   - 容器环境中没有 PulseAudio 服务
   - Qt 依赖 PulseAudio 或 D-Bus 枚举设备
   - QMediaDevices::audioOutputs() 返回空列表

2. **GStreamer 后端可用但未正确配置**：
   - GStreamer alsasink 可以直接使用 ALSA 设备
   - 但需要 ALSA 默认设备配置
   - 否则可能选错设备（如 HDMI 而非 ES8388）

### 方案对比

| 方案 | 实施难度 | 稳定性 | 代码复杂度 | 结论 |

| GStreamer 环境变量 | 中 | 中 | 中 | ⚠️ 备选方案 |

### 选择方案：ALSA 默认设备配置

**核心思路**：
- 不依赖 Qt Multimedia 的设备枚举
- 通过 ALSA 配置文件设置默认设备为 ES8388
- GStreamer alsasink 自动使用 ALSA "default" 设备
- 无需修改应用代码的设备选择逻辑

**工作流程**：
```
QMediaPlayer::play()
  ↓
QAudioOutput (default, 无参数)
  ↓
GStreamer pipeline
  ↓
alsasink (使用 ALSA "default")
  ↓
/etc/asound.conf 配置
  pcm.!default → plug → hw:1,0
  ↓
ES8388 硬件设备（Card 1）🔊
```

## 修改内容

### 1. 创建 ALSA 配置文件

**文件**: [docker/rk3588/asound.conf](docker/rk3588/asound.conf)

```conf
# ALSA 默认设备配置
pcm.!default {
    type plug
    slave.pcm "hw:1,0"
}

ctl.!default {
    type hw
    card 1
}
```

**说明**：
- `pcm.!default`: 默认播放设备 → ES8388（Card 1, Device 0）
- `type plug`: 自动格式转换（采样率、位深度等）
- `ctl.!default`: 默认控制设备（音量调节）

## 技术细节

### ALSA 设备层次结构

```
物理硬件
  ├─ ES8388 音频芯片（RK3588 板载）
  └─ HDMI 音频输出

内核驱动（/dev/snd/）
  ├─ pcmC0D0p  →  HDMI 音频（Card 0）
  └─ pcmC1D0p  →  ES8388 音频（Card 1）← 我们的目标

ALSA 设备名称
  ├─ hw:0,0           HDMI 直接访问
  ├─ plughw:0,0       HDMI 插件层
  ├─ hw:1,0           ES8388 直接访问
  └─ plughw:1,0       ES8388 插件层 ← 推荐

/etc/asound.conf 配置
  pcm.!default → plug → hw:1,0

应用程序使用
  "default" → ALSA 解析 → ES8388 ✅
```

### GStreamer 设备选择逻辑

```
GStreamer alsasink 插件：

1. 检查 device 属性是否设置
   - 如果设置：使用指定设备（如 "hw:1,0"）
   - 如果未设置：继续步骤 2

2. 读取 ALSA 配置（/etc/asound.conf）
   - 如果 pcm.!default 存在：使用配置的默认设备 ← 我们的方案
   - 如果不存在：使用 Card 0（可能是 HDMI）

Qt QMediaPlayer：
  - 不指定设备 → GStreamer alsasink 使用 "default"
  - alsasink 读取 /etc/asound.conf → hw:1,0 (ES8388) ✅
```

### 为什么不使用 PJSIP 的枚举方法？

SIP 功能使用 PJSIP 库，可以成功枚举 ALSA 设备：
```cpp
// SipPhoneManager.cpp 中的工作代码
pjmedia_aud_dev_info info[64];
unsigned count = 64;
pj_status_t status = pjsua_enum_aud_devs(info, &count);  // ✅ 成功
```

**为什么不在 CommonControl 中使用？**

| 原因 | 说明 |
|------|------|
| **架构分离** | CommonControl 不应依赖 SIP 库 |
| **PJSIP 初始化** | pjsua_enum_aud_devs() 需要 PJSIP 先初始化 |
| **设备兼容性** | PJSIP 设备索引与 Qt 设备对象不兼容 |
| **代码复杂度** | 需要引入新依赖，违反单一职责原则 |

**ALSA 配置方案更优**：
- ✅ 无需新增代码依赖
- ✅ 符合 Linux 音频标准用法
- ✅ 所有使用 ALSA 的程序都受益
- ✅ 配置文件易于理解和调试
