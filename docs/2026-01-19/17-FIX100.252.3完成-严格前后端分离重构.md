### 架构一致性问题

**FIX 100.246（设备管理）**：✅ 完全前后端分离
- 使用 `Q_PROPERTY` 定义属性
- QML 直接绑定属性：`model: SipPhoneManager.audioInputDevices`
- 后端通过 `Signal` 自动通知 QML 更新

**FIX 100.252（编解码器管理）**：❌ 部分前后端分离
- 使用 `Q_INVOKABLE` 定义函数
- QML 手动调用函数：`SipPhoneManager.getAudioCodecs()`
- 手动监听信号更新 model（需要 `Component.onCompleted` + `Connections`）

**结论**：FIX 100.252 没有完全遵循 FIX 100.246 的前后端分离模式，必须重构。

## ✅ 解决方案

### 架构目标

**严格前后端分离**：
1. ✅ 后端：使用 `Q_PROPERTY` 定义属性（不使用 `Q_INVOKABLE` 函数）
2. ✅ 后端：提供 `const` 属性 getter 函数
3. ✅ 后端：通过 `Signal` 通知前端数据变化
4. ✅ 前端：直接绑定属性（不手动调用函数）
5. ✅ 前端：自动响应信号更新（不需要 `Connections`）

### 修改 3：SipPhoneManager.cpp - Property Getters 实现

**位置**: [src/sip_phone/SipPhoneManager.cpp](../../src/sip_phone/SipPhoneManager.cpp) (Lines 3298-3311)

**修改内容**：

```cpp
// ✅ 2026-01-19 20:00 [FIX 100.252.3] Property getters（严格前后端分离）
// 原因：QML 直接绑定 property，而非手动调用函数
// 好处：与 FIX 100.246 设备列表保持一致，统一的前后端分离架构

QStringList SipPhoneManager::audioCodecs() const
{
    // 调用现有实现（去掉 const 限制）
    return const_cast<SipPhoneManager*>(this)->getAudioCodecs();
}

QStringList SipPhoneManager::videoCodecs() const
{
    // 调用现有实现（去掉 const 限制）
    return const_cast<SipPhoneManager*>(this)->getVideoCodecs();
}
```

**技术细节**：
- **为什么使用 `const_cast`**：
  - Property getter 必须是 `const` 成员函数（Qt 要求）
  - 现有 `getAudioCodecs()` 不是 `const` 函数（因为内部访问 `d->initialized`）
  - 使用 `const_cast` 临时去掉 `const` 限制，调用现有实现
  - 这是 Qt 属性系统常见的适配器模式

- **为什么不直接修改 `getAudioCodecs()` 为 `const`**：
  - 保留现有函数供内部使用（向后兼容）
  - 新增 property getter 作为 QML 专用接口
  - 分离内部实现和对外接口

**对比 FIX 100.246 设备管理**：

```cpp
// ✅ 2026-01-18 12:00 [FIX 100.246] 设备列表 property getters 实现
QStringList SipPhoneManager::audioInputDevices() const
{
    return d->audioInputDeviceList;  // 直接返回缓存列表
}
```

**差异原因**：
- 设备管理：使用缓存列表（`d->audioInputDeviceList`），直接返回
- 编解码器管理：每次调用 PJSIP API 枚举（没有缓存），需要调用现有函数

## 🔍 技术原理

### Qt 属性系统工作流程

**1. QML 绑定属性**：
```qml
Repeater {
    model: SipPhoneManager.audioCodecs  // QML 引擎读取 Q_PROPERTY
}
```

**2. Qt 元对象系统解析 Q_PROPERTY**：
```cpp
Q_PROPERTY(QStringList audioCodecs READ audioCodecs NOTIFY audioCodecsChanged)
           └─────┬─────┘            └────┬────┘         └───────┬───────┘
              属性名                 getter 函数           信号名称
```

**3. QML 引擎自动调用 getter 函数**：
```cpp
QStringList SipPhoneManager::audioCodecs() const
{
    return const_cast<SipPhoneManager*>(this)->getAudioCodecs();
}
```

**4. 后端数据变化时发射信号**：
```cpp
void SipPhoneManager::initializeEndpoint()
{
    // ... PJSIP 初始化完成 ...
    emit audioCodecsChanged();  // 通知 QML 更新
}
```

**5. QML 引擎自动重新读取属性**：
- Qt 属性系统监听 `audioCodecsChanged()` 信号
- 信号触发 → 重新调用 `audioCodecs()` getter
- 返回新数据 → 更新 QML UI

**关键点**：
- ✅ QML 无需手动调用函数
- ✅ QML 无需手动监听信号
- ✅ Qt 框架自动处理一切
