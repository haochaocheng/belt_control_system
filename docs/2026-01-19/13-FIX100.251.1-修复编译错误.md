## 📋 问题描述

### 编译错误

```
/workspace/src/sip_phone/SipPhoneManager.cpp:1020:13: error: redeclaration of 'QString settingsPath'
 1020 |     QString settingsPath = Private::getPersistentSettingsPath();
      |             ^~~~~~~~~~~~
/workspace/src/sip_phone/SipPhoneManager.cpp:927:13: note: 'QString settingsPath' previously declared here
  927 |     QString settingsPath = Private::getPersistentSettingsPath();
      |             ^~~~~~~~~~~~

/workspace/src/sip_phone/SipPhoneManager.cpp:1021:15: error: redeclaration of 'QSettings settings'
 1021 |     QSettings settings(settingsPath, QSettings::IniFormat);
      |               ^~~~~~~~
/workspace/src/sip_phone/SipPhoneManager.cpp:928:15: note: 'QSettings settings' previously declared here
  928 |     QSettings settings(settingsPath, QSettings::IniFormat);
      |               ^~~~~~~~
```

### 根本原因

在 `initializeEndpoint()` 函数中，`settingsPath` 和 `settings` 变量被重复声明了两次：

1. **Line 927-928**: 音频设备恢复部分
   ```cpp
   QString settingsPath = Private::getPersistentSettingsPath();
   QSettings settings(settingsPath, QSettings::IniFormat);
   int savedInputIndex = settings.value("SIP/AudioInputDevice", -1).toInt();
   int savedOutputIndex = settings.value("SIP/AudioOutputDevice", -1).toInt();
   ```

2. **Line 1020-1021**: 视频设备恢复部分（FIX 100.251 新增）
   ```cpp
   QString settingsPath = Private::getPersistentSettingsPath();  // ❌ 重复声明
   QSettings settings(settingsPath, QSettings::IniFormat);       // ❌ 重复声明
   int savedVideoIndex = settings.value("SIP/VideoDevice", -1).toInt();
   ```

**为什么会出现这个错误**：
- FIX 100.251 实现时直接复制了音频设备恢复的代码模式
- 忽略了两个部分都在同一个函数作用域内
- C++ 不允许在同一作用域内重复声明同名变量

---

## ✅ 解决方案

### 修改内容

**位置**: [src/sip_phone/SipPhoneManager.cpp:1020-1023](../../src/sip_phone/SipPhoneManager.cpp#L1020-L1023)

**修改前**（错误代码）：
```cpp
QString settingsPath = Private::getPersistentSettingsPath();  // ❌ 重复声明
QSettings settings(settingsPath, QSettings::IniFormat);       // ❌ 重复声明
int savedVideoIndex = settings.value("SIP/VideoDevice", -1).toInt();
```

**修改后**（正确代码）：
```cpp
// ✅ 2026-01-19 17:30 [FIX 100.251.1] 修复编译错误 - 重用已有的 settings 变量
// 原因：settingsPath 和 settings 已在音频设备恢复部分声明，无需重复声明
// 音频和视频设备配置都在同一个 sip_accounts.ini 文件中
int savedVideoIndex = settings.value("SIP/VideoDevice", -1).toInt();
```

### 修复要点

1. **删除重复声明**：移除 `QString settingsPath` 和 `QSettings settings` 的重复声明
2. **直接重用变量**：视频设备恢复部分直接使用音频设备恢复部分已声明的 `settings` 变量
3. **逻辑合理性**：
   - 音频和视频设备配置都保存在同一个文件：`/app/appdata/sip_accounts.ini`
   - 两个部分都在同一个函数内，顺序执行
   - 无需重新创建 `QSettings` 对象

## 🔍 技术分析

### 变量作用域

```cpp
bool SipPhoneManager::initializeEndpoint()
{
    // ... 设备枚举代码

    // ✅ 音频设备恢复部分（Line 927-1011）
    QString settingsPath = Private::getPersistentSettingsPath();  // 声明 settingsPath
    QSettings settings(settingsPath, QSettings::IniFormat);       // 声明 settings

    int savedInputIndex = settings.value("SIP/AudioInputDevice", -1).toInt();
    int savedOutputIndex = settings.value("SIP/AudioOutputDevice", -1).toInt();

    // ... 音频设备恢复逻辑 ...

    // ✅ 视频设备恢复部分（Line 1013-1052）
    // 直接重用已声明的 settingsPath 和 settings 变量
    int savedVideoIndex = settings.value("SIP/VideoDevice", -1).toInt();  // ← 重用 settings

    // ... 视频设备恢复逻辑 ...

    return true;
}  // ← settingsPath 和 settings 作用域结束
```

### QSettings 对象复用

**为什么可以复用**：
1. `QSettings` 对象在整个函数执行期间保持有效
2. 音频和视频设备恢复部分顺序执行（不是并发）
3. 两个部分读取同一个配置文件（`sip_accounts.ini`）
4. 不需要重新打开文件，性能更好

**为什么必须复用**：
- C++ 不允许在同一作用域内重复声明同名变量
- 重复创建 `QSettings` 对象是不必要的开销
