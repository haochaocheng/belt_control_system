## 🔍 问题回顾

### 用户测试反馈（2026-01-19 10:00）

> "100.25测试完成，第一次切换扬声器和麦克风完成，第二次关闭程序在打开，显示的还是未修改的扬声器和麦克风"

**测试结果分析**：
1. ✅ **首次设备选择成功** - 用户选择 USB 麦克风后立即生效
2. ❌ **重启后设备不保存** - 关闭程序再启动，UI 显示回到旧设备（rockchipes8388）

### 根本原因（从日志分析）

**位置**: `docs/log/voip.md` Lines 181-187

```
[DEBUG] 📢 [FIX 100.250] Reading saved audio input device index: 0
[WARNING]    ⚠️ [FIX 100.250] Saved index 0 is out of range
```

**问题流程**：
1. **应用启动时** → QML 绑定触发 `getCurrentAudioInputDevice()`
2. **此时映射数组为空** → 索引验证失败（`savedIndex >= audioInputDeviceMapping.size()`）
3. **返回默认值 0** → UI 显示第一个设备（旧设备）
4. **之后设备枚举完成** → 映射数组建立（`[6, 21]`）
5. **但没有代码主动恢复设备** → PJSIP 仍使用默认设备

**关键缺陷**：
- ✅ FIX 100.250 已实现：设备索引映射、保存到 QSettings、UI 查询验证
- ❌ **缺少**：PJSIP 初始化后自动恢复保存的设备

**前后端同步恢复**：
- **枚举完成后**（映射数组已建立）
- **主动从 QSettings 读取保存的设备索引**
- **映射到 PJSIP 索引**
- **调用 `pjsua_set_snd_dev2()` 恢复设备**

### 实现位置

**文件**: `src/sip_phone/SipPhoneManager.cpp`
**位置**: Lines 904-995（设备枚举完成后）

## 🔧 解决方案 2：日志限流优化

### 问题描述

**用户反馈**（2026-01-19 10:00）：
> "有大量的这个日志：⚠️ [WARNING] RMS too low (15 < 100)! Microphone volume may be too low!"

**问题分析**：
- **位置**: `cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-audiodev/alsa_dev.c:779`
- **触发频率**: 每 100 次音频读取检测一次（约 2-3 秒）
- **通话时长**: 假设 5 分钟通话 = 100-150 条重复警告
- **影响**: 日志文件爆炸，难以查找有用信息

### 核心理念

**时间限流机制**：
- 记录上次输出警告的时间
- 同一类型警告 30 秒内只输出一次
- 第一次警告立即输出（`last_warning_time.sec == 0`）

### 实现位置

**文件**: `cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-audiodev/alsa_dev.c`

### 关键修改

#### 1. 添加时间戳字段（Lines 141-147）

```c
/* ✅ 2026-01-19 10:15 [FIX 100.250.1] 日志限流：避免重复警告日志爆炸 */
/* 原因：RMS 过低警告每隔几秒就输出一次，通话过程中可能产生几百条重复日志 */
/* 解决：记录上次输出警告的时间，30秒内不重复输出同一类型的警告 */
pj_time_val         last_rms_warning_time;      /* 上次 RMS 过低警告时间 */
pj_time_val         last_silent_warning_time;   /* 上次静音警告时间 */
pj_time_val         last_low_amp_warning_time;  /* 上次低振幅警告时间 */
pj_time_val         last_dc_bias_warning_time;  /* 上次 DC 偏置警告时间 */
```

**说明**：
- 使用 `PJ_POOL_ZALLOC_T` 分配时自动初始化为 0
- 第一次警告时 `last_warning_time.sec == 0` → 立即输出

#### 2. RMS 过低警告限流（Lines 798-806）

```c
} else if (rms < 100) {
    /* RMS 过低警告：30秒限流 */
    pj_time_val time_diff;
    PJ_TIME_VAL_SUB(time_diff, current_time, stream->last_rms_warning_time);
    if (time_diff.sec >= 30 || stream->last_rms_warning_time.sec == 0) {
        PJ_LOG (3,(THIS_FILE, "⚠️ [WARNING] RMS too low (%d < 100)! Microphone volume may be too low!", rms));
        PJ_LOG (3,(THIS_FILE, "   [INFO] This warning will not repeat for 30 seconds"));
        stream->last_rms_warning_time = current_time;
    }
}
```

#### 3. 其他警告类型同理（Lines 790-823）

- **静音警告** (Line 790-797): 30 秒限流
- **低振幅警告** (Line 807-814): 30 秒限流
- **DC 偏置警告** (Line 815-823): 30 秒限流

## 📝 问题排查

### 问题 1：重启后设备仍显示旧设备

**症状**：重启应用，UI 仍显示 `rockchipes8388`

**检查日志**：
```bash
grep "FIX 100.250.1.*Restoring" docs\log\voip.md
```

**可能原因**：
1. **索引超出范围**：
   - 日志显示：`Invalid device index 1 invalid, using current PJSIP device 6`
   - 解决：设备配置可能变化（USB 拔出），检查映射数组大小

2. **pjsua_set_snd_dev2() 失败**：
   - 日志显示：`❌ [FAILED] pjsua_set_snd_dev2() error: ...`
   - 解决：检查错误信息，可能是设备权限或占用问题

3. **恢复代码未执行**：
   - 日志未显示：`Restoring saved audio devices from QSettings`
   - 解决：检查 PJSIP 初始化流程，确认设备枚举成功
