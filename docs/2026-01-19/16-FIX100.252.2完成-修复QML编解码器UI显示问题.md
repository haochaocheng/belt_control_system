## 📋 问题描述

### 用户报告

**用户反馈**（2026-01-19 19:30）：

> "我是音频解码器和视频解码器下面是一个很长的输入框，我们使用的是checkbox.是不是因为没有找到解码器，还是参数不对，新的voip.md包含日志"

**翻译**：
在音频编解码器和视频编解码器区域下面显示的是长输入框，而不是复选框。怀疑是没有找到编解码器或参数错误。

### 问题现象

1. **预期**：显示 10 个音频编解码器复选框和 3 个视频编解码器复选框
2. **实际**：显示空白或长输入框
3. **日志分析**：voip.md 中没有编解码器枚举的日志输出

### 根本原因

**时序问题**：

1. **QML 页面加载时**：
   ```qml
   Repeater {
       model: SipPhoneManager.getAudioCodecs()  // ← 此时 PJSIP 未初始化
       CheckBox { ... }
   }
   ```

2. **执行顺序**：
   ```
   1. QML 页面加载 → 调用 getAudioCodecs()
   2. PJSIP 未初始化 → 返回空列表 []
   3. Repeater 使用空列表 → 不创建任何 CheckBox
   4. PJSIP 初始化完成 → 但 model 已经固定为空列表
   5. 结果：UI 永久显示空白
   ```

3. **为什么会这样**：
   - QML `Repeater.model` 直接绑定函数调用只执行一次
   - 函数调用发生在组件实例化时（页面加载）
   - PJSIP 初始化是异步的，在页面加载后才完成
   - `model` 不会自动更新，即使 PJSIP 初始化后

## 🔍 技术分析

### QML 动态模型更新机制

#### 1. 为什么直接函数调用不行

```qml
// ❌ 错误模式：只执行一次
Repeater {
    model: SipPhoneManager.getAudioCodecs()
}

// 执行时序：
// 1. QML 引擎创建 Repeater 对象
// 2. 评估 model 属性 → 调用 getAudioCodecs()
// 3. 返回空列表（PJSIP 未初始化）
// 4. model 固定为空列表
// 5. ❌ PJSIP 初始化后，model 不会自动更新
```

#### 2. 正确的动态更新模式

```qml
// ✅ 正确模式：支持动态更新
Repeater {
    id: codecRepeater
    model: []  // 初始为空

    // 在组件完成创建后手动更新
    Component.onCompleted: {
        codecRepeater.model = SipPhoneManager.getCodecs()
    }

    // 监听后端信号变化
    Connections {
        target: SipPhoneManager
        function onCodecsChanged() {
            codecRepeater.model = SipPhoneManager.getCodecs()
        }
    }
}
```

#### 3. 执行时序对比

**错误模式时序**：
```
T0: QML 页面加载
T1: 创建 Repeater，model = getCodecs() → []
T2: PJSIP 初始化完成
T3: 用户打开设置页面 → 依然显示空白（model 未更新）
```

**正确模式时序**：
```
T0: QML 页面加载
T1: 创建 Repeater，model = []
T2: Component.onCompleted → model = getCodecs() → []（PJSIP 未就绪）
T3: PJSIP 初始化完成 → emit codecsChanged()
T4: Connections 接收信号 → model = getCodecs() → [10个编解码器]
T5: Repeater 自动创建 10 个 CheckBox
T6: 用户打开设置页面 → 正确显示 10 个复选框
```

### Component.onCompleted vs Connections

| 特性 | Component.onCompleted | Connections |
|------|----------------------|-------------|
| **触发时机** | 组件创建完成后（一次） | 信号发射时（多次） |
| **用途** | 初始化加载 | 动态更新 |
| **是否必须** | ✅ 是（确保首次加载数据） | ✅ 是（监听后续变化） |
| **执行次数** | 1 次 | N 次（每次信号发射） |

**为什么两者都需要**：
1. `Component.onCompleted`：
   - PJSIP 可能在页面加载前就初始化完成
   - 此时不会再发射 `codecsChanged()` 信号
   - 需要主动调用 `getCodecs()` 加载数据

2. `Connections`：
   - 用户可能修改编解码器启用/禁用状态
   - PJSIP 重新初始化时编解码器列表可能变化
   - 需要监听信号更新 UI
