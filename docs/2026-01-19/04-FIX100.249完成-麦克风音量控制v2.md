## 🔍 问题回顾

### v1 实现失败（会议桥方案）

**用户反馈**（2026-01-19 06:50）：
> 进行两次通话测试，音量条件到99，扬声器和麦克风切换了设备，查看音量是否变化，但是对方感觉没有变化

**根本原因分析**：

1. **设计缺陷**：v1 使用会议桥 API (`pjsua_conf_adjust_tx_level()`)
   - ❌ 只能在通话建立后（`d->inCall && d->currentCall`）调整音量
   - ❌ 用户在通话前调整音量 → 只保存到 QSettings，未应用到 PJSIP
   - ❌ 软件音量调节，效果不如硬件增益明显

2. **日志证据**（`docs/log/voip.md` Lines 2088-2107）：
   ```
   🎤 [FIX 100.249] Setting microphone volume: 99 %
   ✅ [Settings] Microphone volume saved: 99
   📌 [Call State] No active call          ← ⚠️ 未应用到 PJSIP
      d->inCall: false
      d->currentCall: null
      Volume will be applied when call starts  ← 承诺未兑现
   ```

3. **恢复代码问题**：通话建立时尝试恢复音量，但缺少成功/失败日志

4. **ALSA 警告**（`docs/log/voip.md` Line 5081）：
   ```
   ⚠️ [WARNING] RMS too low (14 < 100)! Microphone volume may be too low!
   ```
   硬件麦克风输入电平本身很低，软件音量调节效果有限。

## 🔧 v2 实现方案（硬件增益 API）

### 核心 API 变更

**旧方案（v1）**：
```cpp
// ❌ 会议桥软件音量（只能通话中使用）
pjsua_conf_adjust_tx_level(0, level);  // level: 0.0-2.0
```

**新方案（v2）**：
```cpp
// ✅ 硬件麦克风增益（通话前即可设置）
pjsua_snd_set_setting(
    PJMEDIA_AUD_DEV_CAP_INPUT_VOLUME_SETTING,  // 输入音量能力
    &pj_volume,                                 // 音量：0-255
    PJ_TRUE                                     // 持久化设置
);
```

### 方案优势

| 特性 | v1 会议桥方案 | v2 硬件增益方案 |
|-----|--------------|----------------|
| **何时可用** | 仅通话中 | 随时可用 |
| **是否持久化** | 否（每次通话需重新设置） | 是（PJ_TRUE 自动持久化） |
| **调整范围** | 0.0-2.0（0%-200%） | 0-255（0%-100%增益） |
| **调整位置** | 会议桥软件层 | ALSA 硬件层 |
| **效果** | 软件放大（可能失真） | 硬件增益（清晰） |
| **ALSA 低电平问题** | 无法解决 | 可缓解 |

### 修改 1：`SipPhoneManager.cpp` - 音量设置函数重写

**文件**: `src/sip_phone/SipPhoneManager.cpp`
**位置**: Lines 2192-2271

#### 关键改动：

```cpp
// ✅ 新方案：硬件增益 API
void SipPhoneManager::setMicrophoneVolume(int volume)
{
    // 1. 保存到 QSettings
    QSettings settings;
    settings.setValue("SIP/MicrophoneVolume", volume);

    // 2. 如果 PJSIP 已初始化，立即应用（无需等待通话）
    if (d->initialized) {
        // 转换百分比 (0-100) 到 PJSIP 音量 (0-255)
        unsigned int pj_volume = (volume * 255) / 100;

        // 使用硬件增益 API
        pj_status_t status = pjsua_snd_set_setting(
            PJMEDIA_AUD_DEV_CAP_INPUT_VOLUME_SETTING,
            &pj_volume,
            PJ_TRUE  // 持久化设置
        );

        if (status == PJ_SUCCESS) {
            qDebug() << "✅ [SUCCESS] Microphone hardware gain applied!";

            // 验证设置
            unsigned int verify_volume = 0;
            pjsua_snd_get_setting(PJMEDIA_AUD_DEV_CAP_INPUT_VOLUME_SETTING, &verify_volume);
            qDebug() << "✅ [Verify] Current hardware gain:" << verify_volume << "/255";
        } else {
            qWarning() << "⚠️ Failed to set microphone hardware gain";
        }
    } else {
        qDebug() << "📌 [PJSIP] Not initialized yet, will apply on startup";
    }
}
```

**关键点**：
- ✅ 无需 `d->inCall` 检查 - 通话前即可设置
- ✅ 使用 `d->initialized` 检查 PJSIP 是否就绪
- ✅ 立即验证设置是否生效
- ✅ 详细调试日志（成功/失败都有输出）

## 📊 音量转换逻辑

### v1 会议桥方案（已废弃）
```cpp
// UI 百分比 → PJSIP 浮点数
float level = (volume / 100.0f) * 2.0f;
// 0%   → 0.0 (静音)
// 50%  → 1.0 (正常)
// 100% → 2.0 (200% 增益)
```

### v2 硬件增益方案（新）
```cpp
// UI 百分比 → PJSIP 整数
unsigned int pj_volume = (volume * 255) / 100;
// 0%   → 0   (静音)
// 50%  → 127 (50% 增益)
// 100% → 255 (100% 增益)
```

**差异说明**：
- v1 允许超过 100%（最高 200%），但容易失真
- v2 最高 100% 增益，但效果在硬件层更清晰

  1. 检查 PJSIP 设备能力枚举

- **测试方法**：使用系统录音工具测试麦克风
- **解决方案**：更换麦克风硬件

## 📚 技术参考

### PJSIP API 文档

#### 1. `pjsua_snd_set_setting()`
```c
pj_status_t pjsua_snd_set_setting(
    pjmedia_aud_dev_cap cap,    // 音频设备能力
    const void *pval,            // 设置值指针
    pj_bool_t keep               // 是否持久化
);
```

**参数说明**：
- `cap`: `PJMEDIA_AUD_DEV_CAP_INPUT_VOLUME_SETTING` - 输入音量设置
- `pval`: `unsigned int*` - 音量值 0-255
- `keep`: `PJ_TRUE` - 持久化设置，应用到所有未来的音频设备

**返回值**：
- `PJ_SUCCESS`: 成功
- `PJ_ENOTFOUND`: 音频设备未初始化
- `PJ_EINVAL`: 设备不支持此能力

---

#### 2. `pjsua_snd_get_setting()`
```c
pj_status_t pjsua_snd_get_setting(
    pjmedia_aud_dev_cap cap,    // 音频设备能力
    void *pval                   // 输出值指针
);
```

**用途**：验证当前音量设置是否生效

---

### 音频设备能力枚举

| 能力常量 | 说明 | 数据类型 |
|---------|------|---------|
| `PJMEDIA_AUD_DEV_CAP_INPUT_VOLUME_SETTING` | 输入音量（麦克风增益） | `unsigned int` (0-255) |
| `PJMEDIA_AUD_DEV_CAP_OUTPUT_VOLUME_SETTING` | 输出音量（扬声器） | `unsigned int` (0-255) |
| `PJMEDIA_AUD_DEV_CAP_EC` | 回声消除 | `pj_bool_t` |
| `PJMEDIA_AUD_DEV_CAP_VAD` | 语音活动检测 | `pj_bool_t` |

## 💡 关键教训

### 1. 选择正确的 API 层次很重要
- ❌ 会议桥 API：软件层，功能受限
- ✅ 硬件设备 API：接近硬件，功能强大

### 2. 理解 PJSIP 音频架构
```
硬件麦克风 (ALSA)
  ↓ 硬件增益 (pjsua_snd_set_setting) ← ✅ v2 在这里调整
PJSIP 音频设备
  ↓
会议桥 (Conference Bridge)
  ↓ 软件音量 (pjsua_conf_adjust_tx_level) ← ❌ v1 在这里调整
RTP 编码器
  ↓
网络 (RTP)
```

### 3. 测试场景要全面
- ❌ v1 只测试了"通话中调整"
- ✅ v2 需要测试"通话前调整"（用户真实场景）

- v1 缺少恢复代码的成功/失败日志
