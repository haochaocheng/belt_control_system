## 📋 问题回顾

### 用户反馈（FIX 100.249 v2 失败）

> **"音量条件到99，但对方感觉没有变化"**

### 根本原因

**完整调查文档**: [21-音量控制失败根本原因分析.md](21-音量控制失败根本原因分析.md)

**根本原因**：
- USB 摄像头麦克风（`plughw:CARD=camera,DEV=0`）不支持 ALSA mixer 音量控制
- PJSIP 的 `get_mixer_name()` 找不到 capture mixer 元素 → `cap_mixer_name` 为空
- `pjsua_snd_set_setting(PJMEDIA_AUD_DEV_CAP_INPUT_VOLUME_SETTING)` 返回 `PJMEDIA_EAUD_INVCAP`
- 设备层音量控制完全失效

**错误证据**（`docs/log/voip.md`）：
```
[WARNING] ⚠️ Failed to restore microphone volume: Invalid or unsupported audio capability (PJMEDIA_EAUD_INVCAP)
```

## ✅ 解决方案

### 方案选择

**从设备层改为会议桥层**：

| 层级 | API | 可行性 | 限制 |
|------|-----|--------|------|
| **设备层**（硬件增益） | `pjsua_snd_set_setting()` | ❌ 不可用 | 硬件不支持 |
| **会议桥层**（软件增益） | `pjsua_conf_adjust_tx_level()` | ✅ 可用 | 只能在通话中 |

**选择理由**：
- ✅ 纯软件实现，无硬件依赖
- ✅ 直接控制发送给对方的音量
- ✅ PJSIP 会议桥标准功能，稳定可靠
- ⚠️ 限制：只能在通话中使用（需要保存设置，通话时应用）

## 🔧 实现方案

### 信号流分析

**修改前（设备层 - 失败）**：
```
Physical Mic → ALSA → [Device Gain ❌] → PJSIP → Bridge
                       ^^^^^^^^^^^^^^^^
                       硬件不支持，设置失败
```

**修改后（会议桥层 - 成功）**：
```
Physical Mic → ALSA → PJSIP → Bridge → [TX Gain ✅] → Encoder → RTP
                                        ^^^^^^^^^^^^
                                        软件增益，完全可控
```

### 核心 API

**PJSIP API**：
```c
/**
 * Adjust the signal level to be transmitted from the bridge to the
 * specified port by making it louder or quieter.
 * @param slot          The conference bridge slot number.
 * @param level         Signal level adjustment. Value 1.0 means no level
 *                      adjustment, while value 0 means to mute the port.
 * @return              PJ_SUCCESS on success, or the appropriate error code.
 */
PJ_DECL(pj_status_t) pjsua_conf_adjust_tx_level(pjsua_conf_port_id slot,
                                                float level);
```

**参数说明**：
- `slot = 0`: 声音设备端口（Port 0 = sound device）
- `level`: 增益倍数（0.0-2.0）
  - `0.0` = 完全静音
  - `1.0` = 无调整（默认）
  - `2.0` = 放大 2 倍

**转换公式**：
```cpp
// UI 滑块百分比 (0-100) → PJSIP 增益倍数 (0.0-2.0)
float level = (volume / 50.0f);

// 示例：
// 0%   → 0.0 (静音)
// 25%  → 0.5 (减半)
// 50%  → 1.0 (正常)
// 75%  → 1.5 (放大1.5倍)
// 100% → 2.0 (放大2倍)
```

```cpp
// ✅ 2026-01-19 23:45 [FIX 100.249 v3] 通话建立时恢复麦克风音量
// 从 QSettings 读取保存的音量，应用到会议桥 TX 增益
void SipPhoneManager::restoreMicrophoneVolume()
{
    qDebug() << "════════════════════════════════════════════════";
    qDebug() << "🎤 [FIX 100.249 v3] Restoring microphone volume from settings...";
    qDebug() << "════════════════════════════════════════════════";

    // 从 QSettings 读取保存的音量（默认 50%）
    QSettings settings;
    int savedVolume = settings.value("SIP/MicrophoneVolume", 50).toInt();
    qDebug() << "   Saved volume:" << savedVolume << "%";

    // 转换百分比 (0-100) 到 PJSIP 增益倍数 (0.0-2.0)
    float level = (savedVolume / 50.0f);
    qDebug() << "   Converted to PJSIP level:" << level;

    // 应用到会议桥 TX 增益
    pj_status_t status = pjsua_conf_adjust_tx_level(0, level);

    if (status == PJ_SUCCESS) {
        qDebug() << "   ✅ [SUCCESS] Microphone volume restored!";
        qDebug() << "      PJSIP level:" << level << "(" << savedVolume << "%)";
        qDebug() << "      对方将听到此音量级别";
    } else {
        char errmsg[PJ_ERR_MSG_SIZE];
        pj_strerror(status, errmsg, sizeof(errmsg));
        qWarning() << "   ⚠️ [PJSIP] Failed to restore microphone volume:" << errmsg;
        qWarning() << "      Volume will remain at default level (1.0)";
    }

    qDebug() << "════════════════════════════════════════════════";
    qDebug() << "";
}
```

## 📝 经验教训

### 教训 1：硬件限制比想象中更常见

**错误假设**：
- ❌ "现代 USB 设备都应该支持音量控制"
- ❌ "ALSA 驱动会提供统一的音量控制接口"

**现实情况**：
- ✅ 简单的 USB 音频设备（摄像头内置麦克风）通常没有 ALSA mixer 元素
- ✅ 音量控制能力取决于硬件设计和驱动支持
- ✅ 不能假设所有设备都支持相同的功能

### 教训 2：分层架构的重要性

**PJSIP 音频架构**：
```
Application Layer (QML)
    ↓
Qt API (SipPhoneManager)
    ↓
PJSIP High-Level API (pjsua_*)
    ↓
PJSIP Conference Bridge ← ⭐ 可靠的 fallback 层
    ↓
PJSIP Audio Device API
    ↓
ALSA Backend ← ❌ 可能失败
    ↓
Hardware
```

**经验**：
- 如果底层（硬件/驱动）失败，使用上层（会议桥）fallback
- 会议桥是纯软件实现，不依赖硬件能力
- 分层设计让我们有多个解决方案选择

### 教训 3：日志是最好的调试工具

**发现过程**：
1. 用户报告：音量调到 99%，对方感觉没变化
2. 查看日志：`PJMEDIA_EAUD_INVCAP` 错误
3. 追踪错误码：定位到 ALSA backend 失败
4. 分析根因：硬件不支持 mixer 控制
5. 确定方案：改用会议桥软件增益

**没有详细日志**，我们可能会：
- ❌ 继续尝试修复设备层 API（徒劳）
- ❌ 怀疑是代码逻辑错误（浪费时间）
- ❌ 无法向用户解释原因（缺乏证据）

**有了详细日志**，我们能：
- ✅ 5 分钟内定位问题
- ✅ 快速确定替代方案
- ✅ 向用户提供明确的技术解释

### 教训 4：API 设计的限制要考虑使用场景

**会议桥 API 限制**：
- ⚠️ `pjsua_conf_adjust_tx_level()` 只能在通话中调用
- ⚠️ 通话前调用会失败（会议桥未建立）

**解决方案**：
- ✅ 通话前：保存到 QSettings
- ✅ 通话中：立即应用
- ✅ 通话建立：自动恢复保存值

**经验**：
- API 的使用限制不是缺陷，而是设计权衡
- 需要在应用层添加状态管理来弥补限制
- 持久化 + 状态检查 = 完整的用户体验
