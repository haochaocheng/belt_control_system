### FIX 100.250 - 设备索引映射错误（优先级 2）

**问题**：
- 用户选择麦克风设备后，关闭程序再启动，仍然使用旧设备
- 新选择的设备没有保存

**潜在原因**：
- 用户层设备索引（过滤后）：0, 1, 2...
- PJSIP 层设备索引（原始）：0-28
- 保存的用户索引直接传给 PJSIP → 选错设备

**计划方案**（参考修复方案文档）：
1. 添加索引映射数组：`QVector<int> m_audioInputDeviceMapping`
2. 枚举时保存 PJSIP 原始索引
3. 设置时转换：用户索引 → PJSIP 索引

**等待**：先测试 FIX 100.249 和 FIX 100.251，确认无问题后再实现

### 问题 1：麦克风音量调整无效

**症状**：滑块移动，但对方听到的音量没有变化

**检查日志**：
```bash
grep "🎤 \[FIX 100.249\]" docs/log/voip.md
```

**可能原因**：
1. **未在通话中调整**：
   - 日志显示：`📌 [Call State] No active call`
   - 解决：先拨打电话，然后调整音量

2. **pjsua_conf_adjust_tx_level 失败**：
   - 日志显示：`❌ [FAILED] pjsua_conf_adjust_tx_level() error: ...`
   - 解决：检查错误信息，可能需要调整 PJSIP 配置

3. **会议桥未初始化**：
   - 日志显示：`Listener count: 0`
   - 解决：确保通话已建立（CONFIRMED 状态）

---

### 问题 2：Opus 仍使用 48kHz/2

**症状**：SDP 显示 `opus/48000/2`

**检查日志**：
```bash
grep "Opus" docs/log/voip.md
```

**可能原因**：
1. **Opus 配置失败**：
   - 日志显示：`⚠️ Failed to set Opus default param: ...`
   - 解决：检查 PJSIP Opus 库是否正确编译

2. **编解码器 ID 不匹配**：
   - 日志显示：
     ```
     ⚠️ opus/16000/1 not found, trying alternative IDs...
     ✅ opus/48000/2 enabled (priority: 213)
        注意：编解码器 ID 为 48000/2，但实际参数为 16000/1（已配置）
     ```
   - **这是正常的**：PJSIP 编解码器 ID 可能不变，但参数已修改
   - 验证：检查 SDP 的 `a=fmtp` 行是否包含 16kHz 参数

3. **对方不支持 Opus**：
   - 协商回退到 PCMA/PCMU
   - 解决：使用支持 Opus 的客户端测试

### 问题 3：编译错误

**症状**：`build-ubuntu24-apt.ps1` 失败

**可能原因**：
1. **Opus 头文件缺失**：
