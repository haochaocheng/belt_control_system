## 🔍 问题分析

### PJSIP "No changes" 的含义

PJSIP 返回 "No changes" 说明：
- 在调用 `pjsua_set_snd_dev2()` 时，PJSIP 认为：
  - 当前 capture_dev 已经是 22
  - 当前 playback_dev 已经是 22
- 因此拒绝设置（认为没有变化）

### 问题点

**为什么 PJSIP 当前设备已经是 22？**

可能原因：
1. PJSIP 在枚举设备后自动选择了设备 22 作为默认设备
2. PJSIP 在首次启动时使用了设备 22，并且状态持久化到某处
3. 容器重启后，PJSIP 重新初始化时自动选择了相同的默认设备

### 缺失的调试信息

当前代码在恢复设备前调用了 `pjsua_get_snd_dev2(&param)` 获取当前设备，但**没有打印当前设备**，所以无法确认问题原因。

## ✅ 修复方案

### 修改 1：添加当前设备调试日志

**位置**: [src/sip_phone/SipPhoneManager.cpp:960-965](../../src/sip_phone/SipPhoneManager.cpp#L960-L965)

```cpp
} else {
    // ✅ 2026-01-19 16:30 [FIX 100.250.3] 打印当前 PJSIP 设备（调试用）
    qDebug() << "   📌 [CURRENT DEVICES] PJSIP current devices before restore:";
    qDebug() << "      Current capture_dev (input):" << param.capture_dev;
    qDebug() << "      Current playback_dev (output):" << param.playback_dev;
}
```

**作用**：
- 显示 PJSIP 当前设备索引
- 帮助定位为什么 PJSIP 认为当前已经是设备 22

### 修改 2：统一配置文件路径

**位置**: [src/sip_phone/SipPhoneManager.cpp:266-272](../../src/sip_phone/SipPhoneManager.cpp#L266-L272)

**之前**：
```cpp

```

**修改后**：
```cpp
// ✅ 2026-01-19 16:30 [FIX 100.250.3] 统一使用 sip_accounts.ini（与其他 SIP 配置一致）

    return DataPathConfig::getDataDirectory() + "/sip_accounts.ini";
```

**影响**：

- ✅ 之后的设备选择会保存到 `sip_accounts.ini`
- ✅ 配置文件路径统一，便于管理
