## 一、测试概述

本次测试对 RK3588 工控机的主要外设进行了全面检测，包括：
- CAN 总线（CAN1 和 CAN2）
- 串口（COM 口）
- GPIO（通用输入输出口）

测试目的是验证硬件支持情况，确认是否可以直接使用，并明确还需要哪些资料和配置。

## 二、测试结果详情

### 2.1 CAN 总线测试

#### ✅ 硬件支持状态：**完全支持**

**检测结果**：
- **CAN 接口**: 检测到 `can0` 和 `can1` 两个 CAN 接口
- **设备路径**:
  - `/sys/class/net/can0` → `/devices/platform/fea50000.can/net/can0`
  - `/sys/class/net/can1` → `/devices/platform/fea60000.can/net/can1`
- **内核驱动**: 已启用 Rockchip CAN 驱动
  - `CONFIG_CAN_ROCKCHIP=y`
  - `CONFIG_CANFD_ROCKCHIP=y`
- **SocketCAN 支持**: 已启用（标准 Linux CAN 协议栈）
- **当前状态**: 接口处于 DOWN 状态（未配置）

**已安装工具**：
- ✅ `candump` - CAN 数据抓包工具
- ✅ `cansend` - CAN 数据发送工具
- ✅ `ip` - 网络接口配置工具

**使用示例**：
```bash
# 配置 CAN0，波特率 500kbps
sudo ip link set can0 type can bitrate 500000
sudo ip link set can0 up

# 配置 CAN1，波特率 250kbps
sudo ip link set can1 type can bitrate 250000
sudo ip link set can1 up

# 监听 CAN0 数据
candump can0

# 发送 CAN 数据到 CAN1
cansend can1 123#DEADBEEF
```

**缺少的资料**：
1. ❌ **CAN 总线物理接口定义**
   - 需要硬件原理图或接口说明
   - 确认 CAN_H、CAN_L 引脚位置
   - 确认终端电阻配置（120Ω）

2. ❌ **CAN 收发器芯片型号**
   - 需要确认使用的 CAN 收发器（如 TJA1050、SN65HVD230 等）
   - 确认收发器的电源和使能引脚

3. ❌ **CAN 总线电气特性**
   - 最大波特率支持（标准 CAN 或 CAN-FD）
   - 总线负载能力
   - 隔离保护措施

### 2.2 串口（COM 口）测试

#### ✅ 硬件支持状态：**完全支持**

**检测结果**：
- **标准串口**: 检测到 4 个标准 UART 串口
  - `/dev/ttyS0` - UART0
  - `/dev/ttyS7` - UART7
  - `/dev/ttyS8` - UART8
  - `/dev/ttyS9` - UART9

- **USB 转串口**: 检测到 4 个 USB 串口（CH9344 芯片）
  - `/dev/ttyUSB0` - USB 串口 0
  - `/dev/ttyUSB1` - USB 串口 1
  - `/dev/ttyUSB2` - USB 串口 2
  - `/dev/ttyUSB3` - USB 串口 3

- **内核驱动**: 已启用
  - `CONFIG_SERIAL_8250=y` - 标准 8250 串口驱动
  - `CONFIG_SERIAL_CH9344=y` - CH9344 USB 转串口驱动

**设备权限**：
- 所有串口设备属于 `dialout` 组
- 需要将用户添加到 `dialout` 组才能访问：
  ```bash
  sudo usermod -a -G dialout linaro
  ```

**使用示例**：
```bash
# 使用 screen 连接串口（需要安装）
sudo apt install screen
screen /dev/ttyS0 115200

# 使用 minicom 连接串口（需要安装）
sudo apt install minicom
minicom -D /dev/ttyS0 -b 115200

# 使用 Python pyserial 库
python3 -c "import serial; ser = serial.Serial('/dev/ttyS0', 115200); print(ser.read(10))"
```

**缺少的资料**：
1. ❌ **串口物理接口定义**
   - 需要硬件原理图或接口说明
   - 确认每个串口的引脚位置（TX、RX、GND、VCC）
   - 确认接口类型（DB9、排针、端子等）

2. ❌ **串口电平标准**
   - 确认是 TTL 电平（3.3V/5V）还是 RS232 电平（±12V）
   - 确认是否支持 RS485（需要收发器芯片）

3. ❌ **串口功能分配**
   - 哪些串口用于调试？
   - 哪些串口用于外部设备通信？
   - 是否有硬件流控（RTS/CTS）？

4. ⚠️ **串口工具未安装**
   - 需要安装：`sudo apt install minicom screen setserial`

### 2.3 GPIO（通用输入输出口）测试

#### ✅ 硬件支持状态：**完全支持**

**检测结果**：
- **GPIO 芯片**: 检测到 8 个 GPIO 控制器
  - `gpiochip0` (gpio0) - 32 个引脚
  - `gpiochip1` (gpio1) - 32 个引脚
  - `gpiochip2` (gpio2) - 32 个引脚
  - `gpiochip3` (gpio3) - 32 个引脚
  - `gpiochip4` (gpio4) - 32 个引脚
  - `gpiochip5` (rk806-gpio) - 3 个引脚（电源管理芯片）
  - `gpiochip6` (6-0020) - 16 个引脚（I2C GPIO 扩展器）
  - `gpiochip7` (6-0021) - 16 个引脚（I2C GPIO 扩展器）

- **总引脚数**: 163 个 GPIO 引脚
- **内核驱动**: 已启用
  - `CONFIG_GPIOLIB=y`
  - `CONFIG_GPIO_ROCKCHIP=y`
  - `CONFIG_GPIO_SYSFS=y` - sysfs 接口
  - `CONFIG_GPIO_CDEV=y` - 字符设备接口

**已安装工具**：
- ✅ `gpiodetect` - 检测 GPIO 芯片
- ✅ `gpioinfo` - 查看 GPIO 引脚信息
- ✅ `gpioget` - 读取 GPIO 引脚状态
- ✅ `gpioset` - 设置 GPIO 引脚状态

**使用示例**：

**方法 1: 使用 libgpiod 工具（推荐）**
```bash
# 列出所有 GPIO 芯片
sudo gpiodetect

# 查看 gpiochip0 的所有引脚
sudo gpioinfo gpiochip0

# 读取 gpiochip0 的第 10 号引脚
sudo gpioget gpiochip0 10

# 设置 gpiochip0 的第 10 号引脚为高电平
sudo gpioset gpiochip0 10=1

# 设置 gpiochip0 的第 10 号引脚为低电平
sudo gpioset gpiochip0 10=0
```

**方法 2: 使用 sysfs 接口（传统方法）**
```bash
# 导出 GPIO 引脚（例如 GPIO0_A2，计算方式：0*32+2=2）
echo 2 | sudo tee /sys/class/gpio/export

# 设置为输出模式
echo out | sudo tee /sys/class/gpio/gpio2/direction

# 设置为高电平
echo 1 | sudo tee /sys/class/gpio/gpio2/value

# 设置为低电平
echo 0 | sudo tee /sys/class/gpio/gpio2/value

# 读取引脚状态
cat /sys/class/gpio/gpio2/value

# 取消导出
echo 2 | sudo tee /sys/class/gpio/unexport
```

**方法 3: 使用 Python gpiod 库**
```python
import gpiod

# 打开 GPIO 芯片
chip = gpiod.Chip('gpiochip0')

# 获取引脚 10
line = chip.get_line(10)

# 设置为输出模式并设置为高电平
line.request(consumer='test', type=gpiod.LINE_REQ_DIR_OUT, default_vals=[1])

# 读取输入引脚
line.request(consumer='test', type=gpiod.LINE_REQ_DIR_IN)
value = line.get_value()
```

**当前引脚使用情况**：
- **gpio0**:
  - line 0: 蓝牙复位（已使用）
  - line 3, 17, 30: 电压选择（已使用）
  - 其他引脚: 未使用（可用）

- **gpio2**:

- **gpio3, gpio4**: 大部分引脚未使用（可用）

**缺少的资料**：

## 六、注意事项

### 6.1 权限问题
- CAN 和 GPIO 操作需要 root 权限（使用 `sudo`）
- 串口访问需要用户在 `dialout` 组中

### 6.2 安全提示
- 在操作 GPIO 之前，务必确认引脚功能，避免损坏硬件
- 不要在未知引脚上进行输出操作
- 建议先使用万用表测量引脚电平

### 6.3 调试建议
- 使用 `dmesg` 查看内核日志，排查驱动问题
- 使用 `lsmod` 查看已加载的内核模块
- 使用 `cat /proc/interrupts` 查看中断使用情况
