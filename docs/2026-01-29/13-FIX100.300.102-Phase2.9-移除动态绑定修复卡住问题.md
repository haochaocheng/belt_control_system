# FIX 100.300.102 Phase 2.9 - 移除动态绑定，使用 Connections 信号槽

**日期**: 2026-01-29
**状态**: 已修复 ✅

---

## 🐛 问题描述

程序在 QDS 预览模式下，打开设备设置对话框并按下键切换类别时卡住，鼠标转圈圈。

---

## 🔍 根本原因

### 问题代码

**文件**: DeviceSettingsDialog.qml Line 696-698

```qml
onLoaded: {
    if (item) {
        // ...
        // ❌ 问题：动态绑定导致事件循环阻塞
        item.focusItemIndex = Qt.binding(function() {
            return (root.currentFocusArea === 2 && root.currentCategory === 1)
                   ? root.currentContentItemIndex
                   : -1
        })
    }
}
```

### 为什么会卡住？

1. **动态绑定在 onLoaded 中设置**：
   - `onLoaded` 在 SwitchInputPage 加载完成后立即执行
   - 此时设置动态绑定，绑定表达式立即开始计算

2. **绑定依赖 3 个属性**：
   - `root.currentFocusArea`
   - `root.currentCategory`
   - `root.currentContentItemIndex`
   - 任何一个属性变化，绑定都会重新计算

3. **可能形成绑定循环**：
   ```
   currentCategory 变化
     ↓
   StackLayout 切换页面
     ↓
   Loader 加载 SwitchInputPage
     ↓
   onLoaded 设置 focusItemIndex 绑定
     ↓
   focusItemIndex 变化
     ↓
   ListView delegate 的 isFocused 属性变化
     ↓
   大量绑定重新计算
     ↓
   可能触发布局重新计算
     ↓
   布局变化可能触发某个属性变化
     ↓
   属性变化触发 focusItemIndex 绑定重新计算
     ↓
   循环...
   ```

4. **事件循环阻塞**：
   - 绑定循环导致事件循环被大量计算占用
   - `Qt.callLater` 的回调无法执行
   - 程序卡住

---

## ✅ 解决方案

### 修复代码

**移除动态绑定，使用 Connections 信号槽**：

```qml
onLoaded: {
    if (item) {
        // ...
        // ✅ 只设置初始值，不使用动态绑定
        item.focusItemIndex = (root.currentFocusArea === 2 && root.currentCategory === 1)
                              ? root.currentContentItemIndex
                              : -1
    }
}

// ✅ 使用 Connections 代替动态绑定
Connections {
    target: root
    enabled: switchInputPageLoader.item !== null

    function onCurrentFocusAreaChanged() {
        if (switchInputPageLoader.item) {
            switchInputPageLoader.item.focusItemIndex =
                (root.currentFocusArea === 2 && root.currentCategory === 1)
                ? root.currentContentItemIndex
                : -1
        }
    }

    function onCurrentCategoryChanged() {
        if (switchInputPageLoader.item) {
            switchInputPageLoader.item.focusItemIndex =
                (root.currentFocusArea === 2 && root.currentCategory === 1)
                ? root.currentContentItemIndex
                : -1
        }
    }

    function onCurrentContentItemIndexChanged() {
        if (switchInputPageLoader.item &&
            root.currentFocusArea === 2 &&
            root.currentCategory === 1) {
            switchInputPageLoader.item.focusItemIndex = root.currentContentItemIndex
        }
    }
}
```

### 修复原理

1. **避免绑定循环**：
   - Connections 是单向的信号槽机制
   - 不会形成循环依赖
   - 只在信号触发时执行，不会持续计算

2. **减少计算量**：
   - 只在属性变化时更新一次
   - 不会像绑定那样持续监听和计算

3. **条件执行**：
   - `enabled: switchInputPageLoader.item !== null` 确保只在 item 存在时才响应
   - 避免空指针访问

4. **明确的更新逻辑**：
   - 每个信号处理函数都有明确的更新逻辑
   - 不会产生意外的副作用

## 🎓 经验教训

### 1. 动态绑定的陷阱

**问题**：
- `Qt.binding()` 创建的动态绑定会持续监听依赖属性
- 在复杂的 UI 中容易形成绑定循环
- 难以调试和定位问题

**最佳实践**：
- 避免在 `onLoaded` 中设置动态绑定
- 优先使用 Connections 信号槽
- 只在必要时使用动态绑定

### 2. 绑定循环的识别

**症状**：
- 程序卡住，鼠标转圈圈
- `Qt.callLater` 回调不执行
- 日志在某个点停止输出
- CPU 占用高

**排查方法**：
- 查看日志，找到卡住的确切位置
- 检查该位置附近的绑定表达式
- 分析绑定依赖链，寻找循环

### 3. Connections vs 动态绑定

**Connections 优势**：
- 单向机制，不会循环
- 明确的更新逻辑
- 易于调试
- 性能更好

**动态绑定优势**：
- 语法简洁
- 自动更新
- 适合简单场景

**选择建议**：
- 简单的单向依赖：使用绑定
- 复杂的多向依赖：使用 Connections
- Loader 的 item 属性：使用 Connections

### 4. 深度分析的重要性

**教训**：
- 不要看到一点问题就改
- 要从整体流程深入分析
- 找到真正的根本原因
- 一次性彻底解决

**方法**：
1. 分析完整的日志时间线
2. 找到程序卡住的确切位置
3. 检查该位置的代码逻辑
4. 分析可能的循环依赖
5. 设计彻底的解决方案
