## 🎯 方案B：交叉导航

### 布局设计

```
┌──────────────────────┬──────────────────────┐
│ 左列（5个字段）       │ 右列（4个字段）       │
├──────────────────────┼──────────────────────┤
│ 0. 保护名称          │ 1. 播放次数          │
│ 2. 模块类型          │ 3. 播放时长          │
│ 4. 寄存器地址        │ 5. TTS文字           │
│ 6. 通道编号          │ 7. 音频文件          │
│ 8. 保护延时          │                      │
└──────────────────────┴──────────────────────┘
```

### 导航顺序

**交叉导航**：0→1→2→3→4→5→6→7→8

- 按下键：0(保护名称) → 1(播放次数) → 2(模块类型) → 3(播放时长) → ...
- 按上键：反向导航

**视觉效果**：
- 上下键在左右列之间交替切换
- 用户体验更自然，符合视觉习惯

## 🎨 优势

### 用户体验优势

1. **视觉自然**: 上下键在左右列之间交替，符合视觉习惯
2. **空间利用**: 所有参数一屏显示，无需滚动
3. **导航流畅**: 焦点在左右列之间平滑切换
4. **客户友好**: 最符合用户的操作直觉

### 技术实现

1. **索引映射**: 清晰的旧索引→新索引映射表
2. **布局分离**: 左右列独立，易于维护
3. **焦点管理**: 统一的焦点指示器逻辑

## 🔍 注意事项

### 可见性处理

某些字段有可见性条件：
- **寄存器地址**: `visible: moduleTypeCombo.currentText !== "主模块"`
- **TTS文字**: `visible: ttsRadio.checked`
- **音频文件**: `visible: fileRadio.checked`

**处理方案**：
- 保持可见性条件不变
- 导航逻辑跳过不可见的字段（未来优化）
- 当前实现：焦点可以导航到不可见字段（用户不会看到焦点）
