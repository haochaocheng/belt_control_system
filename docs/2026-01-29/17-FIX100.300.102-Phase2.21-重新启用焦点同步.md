# FIX 100.300.102 Phase 2.21 - 重新启用焦点同步，修复开关量列表焦点指示器

**日期**: 2026-01-29
**状态**: 已实施 ✅

---

## 🐛 问题描述

**用户反馈**：
- "开关量输入是大类，急停、跑偏等属于小类"
- "现在左键切换到小类，没有明显的矩形边框"
- "在小类上下切换，没有明显的焦点"
- "参数区域保护名称下面的输入框使用导航键能看到蓝色边框"

### 问题分析

1. **参数区域的焦点指示器正常**：
   - 保护名称输入框能看到蓝色边框
   - 说明焦点指示器逻辑本身是正确的

2. **开关量列表的焦点指示器不显示**：
   - 急停、跑偏等项目没有矩形边框
   - 上下切换时看不到焦点变化

3. **根本原因**：
   - Phase 2.11 中为了测试，临时禁用了 Connections（`enabled: false`）
   - 导致 `focusItemIndex` 和 `focusSubArea` 没有被更新
   - 焦点指示器的条件 `(root.focusSubArea === 0 && root.focusItemIndex === index)` 永远不满足

---

### 修复内容

**文件**: `src/qml/components/device_info/DeviceSettingsDialog.qml`

**Line 686-748**: 重新启用 Connections，修复焦点同步逻辑

### 关键修改

#### 1. 恢复 onLoaded 中的属性设置（Line 688-700）

```qml
onLoaded: {
    console.log("✅ [DEBUG] onLoaded 开始")
    if (item) {
```

**说明**：
- 恢复 `deviceId`, `deviceName`, `keyboardManager` 的设置
- 设置初始焦点状态：`focusSubArea = 0`（列表区域）

#### 2. 重新启用 Connections（Line 710-748）

```qml
Connections {
    target: root
    enabled: switchInputPageLoader.item !== null  // ✅ 重新启用

    function onCurrentFocusAreaChanged() {
        if (switchInputPageLoader.item && root.currentCategory === 1) {
            if (root.currentFocusArea === 2) {
                // 焦点进入内容区域，默认在列表区域
                switchInputPageLoader.item.focusSubArea = 0
                switchInputPageLoader.item.focusItemIndex = root.currentContentItemIndex
            } else {
                // 焦点离开内容区域，清除焦点
                switchInputPageLoader.item.focusItemIndex = -1
            }
        }
    }

    function onCurrentCategoryChanged() {
        if (switchInputPageLoader.item) {
            if (root.currentFocusArea === 2 && root.currentCategory === 1) {
                // 切换到开关量输入类别，设置焦点
                switchInputPageLoader.item.focusSubArea = 0
                switchInputPageLoader.item.focusItemIndex = root.currentContentItemIndex
            } else {
                // 切换到其他类别，清除焦点
                switchInputPageLoader.item.focusItemIndex = -1
            }
        }
    }

    function onCurrentContentItemIndexChanged() {
        if (switchInputPageLoader.item &&
            root.currentFocusArea === 2 &&
            root.currentCategory === 1) {
            // 在开关量列表中导航
            switchInputPageLoader.item.focusItemIndex = root.currentContentItemIndex
        }
    }
}
```

**说明**：
- `enabled: switchInputPageLoader.item !== null`：只在 item 存在时才响应信号
- `onCurrentFocusAreaChanged`：焦点区域变化时，设置 `focusSubArea` 和 `focusItemIndex`
- `onCurrentCategoryChanged`：类别变化时，设置焦点状态
- `onCurrentContentItemIndexChanged`：列表导航时，更新 `focusItemIndex`

## 📊 焦点逻辑说明

### 导航区域定义

- **区域 1** (`currentFocusArea === 1`): 左侧类别列表（基本配置、开关量输入、模拟量输入等）
- **区域 2** (`currentFocusArea === 2`): 右侧内容区域
  - **子区域 0** (`focusSubArea === 0`): 开关量列表（急停、跑偏等）
  - **子区域 1** (`focusSubArea === 1`): 参数区域（保护名称、模块类型等）

### 焦点指示器条件

**开关量列表**（SwitchInputPage.qml Line 121）：
```qml
readonly property bool isFocused: (root.focusSubArea === 0 && root.focusItemIndex === index)
```

**参数区域**（SwitchInputPage.qml Line 318）：
```qml
border.color: (root.focusSubArea === 1 && root.focusParamIndex === 0) ? "#2196F3" : "transparent"
```

### 焦点同步流程

1. **用户按右键**：
   - `currentFocusArea` 从 1 变为 2
   - `onCurrentFocusAreaChanged` 触发
   - 设置 `focusSubArea = 0`（默认在列表区域）
   - 设置 `focusItemIndex = currentContentItemIndex`

2. **用户在列表中按上下键**：
   - `currentContentItemIndex` 变化
   - `onCurrentContentItemIndexChanged` 触发
   - 更新 `focusItemIndex`

3. **用户按右键进入参数区域**：
   - （待实现）设置 `focusSubArea = 1`
   - 设置 `focusParamIndex = 0`

## 🎓 经验教训

### 1. 临时禁用代码要记得恢复

**问题**：
- Phase 2.11 中为了测试临时禁用了 Connections
- 但后续修复中忘记恢复
- 导致焦点同步功能失效

**教训**：
- 临时禁用代码时，要添加明确的注释说明原因
- 在修复完成后，要检查所有临时禁用的代码
- 使用 TODO 或 FIXME 标记，便于搜索

### 2. 焦点同步的重要性

**关键点**：
- 焦点指示器依赖 `focusSubArea` 和 `focusItemIndex`
- 这些属性必须由父组件（DeviceSettingsDialog）同步
- 如果同步失败，焦点指示器就不会显示

**最佳实践**：
- 使用 Connections 信号槽机制同步焦点状态
- 在 onLoaded 中设置初始焦点状态
- 在导航事件中更新焦点状态

### 3. 调试日志的价值

**保留的调试日志**：
- `console.log("✅ [DEBUG] onLoaded 开始")`
- `console.log("✅ [DEBUG] Qt.callLater 回调执行 - 事件循环正常")`
- `console.log("✅ [DEBUG] onLoaded 完成")`

**好处**：
- 可以验证代码是否执行
- 可以验证事件循环是否正常
- 便于定位问题
