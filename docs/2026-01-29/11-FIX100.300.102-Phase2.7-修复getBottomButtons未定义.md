## 🔍 根本原因分析

### 问题代码
**文件**: `src/qml/components/device_info/DeviceSettingsDialog.qml`
**位置**: Line 851

```qml
Repeater {
    model: getBottomButtons(root.currentCategory)  // ❌ 问题：未明确指定作用域

    Button {
        text: modelData
        // ...
    }
}
```

### 作用域问题

虽然 `getBottomButtons` 函数定义在 `root` Rectangle 内部（Line 889），但在 Repeater 的 model 绑定表达式中：

1. **绑定表达式的作用域**：
   - Repeater 的 model 绑定在 `root.currentCategory` 变化时重新计算
   - 在某些情况下（如初始化或页面切换），绑定表达式可能在函数完全初始化之前执行
   - 导致 `getBottomButtons` 未定义

2. **QML 绑定执行顺序**：
   - Component.onCompleted 执行时，所有绑定表达式已经开始计算
   - 如果绑定表达式引用的函数在同一个组件内，可能存在初始化顺序问题

3. **最佳实践**：
   - 在绑定表达式中，始终使用 `root.functionName` 明确指定作用域
   - 避免依赖隐式作用域解析

## ✅ 解决方案

### 修复代码

```qml
// ✅ 2026-01-24: 使用 Repeater 根据类别动态生成按钮
// ✅ 2026-01-29 [FIX 100.300.102 Phase 2.7]: 使用 root.getBottomButtons 避免 ReferenceError

    Button {
        text: modelData
        // ...
    }

```

### 修复原理

1. **明确作用域**：
   - 使用 `root.getBottomButtons` 代替 `getBottomButtons`
   - 确保绑定表达式始终能找到正确的函数

2. **避免初始化顺序问题**：
   - 通过 `root.` 前缀，QML 引擎知道在 `root` 对象上查找函数
   - 即使在初始化阶段，也能正确解析函数引用

3. **与其他修复保持一致**：
   - 之前修复了 `currentFocusArea` → `root.currentFocusArea`
   - 现在修复 `getBottomButtons` → `root.getBottomButtons`
   - 统一使用明确的作用域引用

## 🎓 经验教训

### 1. QML 绑定表达式最佳实践

**始终使用明确的作用域引用**：
```qml
// ❌ 不推荐：隐式作用域
model: getBottomButtons(currentCategory)

// ✅ 推荐：明确作用域
model: root.getBottomButtons(root.currentCategory)
```

### 2. 函数引用的作用域规则

- 在同一个 QML 组件内定义的函数，也应该使用 `id.functionName` 引用
- 特别是在绑定表达式中，避免依赖隐式作用域解析
- 这样可以避免初始化顺序问题

### 3. Repeater model 绑定注意事项

- Repeater 的 model 绑定会在依赖属性变化时重新计算
- 如果 model 是函数调用，确保函数始终可访问
- 使用明确的作用域引用可以避免 ReferenceError

### 4. 调试 ReferenceError 的方法

1. **查看错误日志**：确定哪个变量或函数未定义
2. **检查作用域**：确认变量/函数在哪个对象上定义
3. **添加明确引用**：使用 `id.propertyName` 或 `id.functionName`
4. **测试验证**：确认警告消失
