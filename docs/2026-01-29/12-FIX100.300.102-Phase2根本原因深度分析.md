## 🔍 深度分析

### 1. Loader 尺寸为 0 的问题

**代码位置**: DeviceSettingsDialog.qml Line 672-707

```qml
Loader {
    id: switchInputPageLoader
    Layout.fillWidth: true
    Layout.fillHeight: true
    active: root.currentCategory === 1  // 仅在选中时加载
    source: "pages/SwitchInputPage.qml"

    Component.onCompleted: {
        console.log("✅ [DEBUG] SwitchInputPage Loader 宽度:", width)  // 输出: 0
        console.log("✅ [DEBUG] SwitchInputPage Loader 高度:", height) // 输出: 0
    }
}
```

**问题分析**：
- `Component.onCompleted` 在 Loader 创建时立即执行
- 此时 `active: false`（因为 `currentCategory === 0`）
- Loader 未激活时，尺寸为 0 是正常的
- **这不是问题的根本原因**

### 2. 动态绑定的性能问题

**代码位置**: DeviceSettingsDialog.qml Line 696-698

```qml
onLoaded: {
    if (item) {
        // ...
        item.focusItemIndex = Qt.binding(function() {
            return (root.currentFocusArea === 2 && root.currentCategory === 1)
                   ? root.currentContentItemIndex
                   : -1
        })
    }
}
```

**问题分析**：
- 这是一个动态绑定，依赖 3 个属性：
  - `root.currentFocusArea`
  - `root.currentCategory`
  - `root.currentContentItemIndex`
- 任何一个属性变化，都会触发绑定重新计算
- `focusItemIndex` 被 Repeater 的 12 个 delegate 引用（每个 delegate 有 6 个绑定表达式）
- **总共 72 个绑定表达式会被触发**

### 3. Repeater delegate 中的绑定爆炸

**代码位置**: SwitchInputPage.qml Line 119-170

```qml
Repeater {
    model: digitalProtectionModel  // 12 个项目

    delegate: Rectangle {
        // 每个 delegate 有 6 个绑定表达式引用 focusItemIndex:

        // 1. 边框颜色
        border.color: (root.focusSubArea === 0 && root.focusItemIndex === index) ? "#2196F3" : "transparent"

        // 2. 边框宽度
        border.width: (root.focusSubArea === 0 && root.focusItemIndex === index) ? 3 : 0

        // 3. Binding 1 (when)
        when: (root.focusSubArea === 0 && root.focusItemIndex === index)

        // 4. Binding 2 (when)
        when: !(root.focusSubArea === 0 && root.focusItemIndex === index)

        // 5. 可见性
        visible: (root.focusSubArea === 0 && root.focusItemIndex === index)

        // 6. 字体粗细
        font.weight: (root.focusSubArea === 0 && root.focusItemIndex === index) ? Font.Bold : Font.Normal
    }
}
```

**绑定计算量**：
- 12 个 delegate × 6 个绑定 = **72 个绑定表达式**
- 每次 `focusItemIndex` 变化，72 个绑定都会重新计算
- 每次 `focusSubArea` 变化，72 个绑定都会重新计算

### 4. 事件循环阻塞的可能原因

**场景重现**：
1. 用户按下键，`currentCategory` 从 0 变为 1
2. StackLayout 的 `currentIndex` 绑定触发，切换到 SwitchInputPage
3. Loader 的 `active` 变为 true，开始加载 SwitchInputPage
4. SwitchInputPage 加载完成，触发 `onLoaded`
5. `onLoaded` 设置 `focusItemIndex` 动态绑定
6. **此时 `currentCategory === 1`，绑定表达式返回 `currentContentItemIndex`**
7. `focusItemIndex` 变化，触发 Repeater 的 72 个绑定重新计算
8. **如果 Repeater 的绑定计算触发了其他属性变化，可能形成绑定循环**
9. 事件循环被阻塞，程序卡住

## 🎯 根本原因假设

### 假设 1: 绑定循环（最可能）

**循环链**：
```
currentCategory 变化
  ↓
StackLayout 切换页面
  ↓
Loader 加载 SwitchInputPage
  ↓
onLoaded 设置 focusItemIndex 绑定
  ↓
focusItemIndex 变化
  ↓
Repeater 的 72 个绑定重新计算
  ↓
某个绑定触发布局重新计算
  ↓
布局变化触发某个属性变化
  ↓
属性变化触发 focusItemIndex 绑定重新计算
  ↓
循环...
```

### 假设 2: 布局计算死锁

**可能的死锁场景**：
- RowLayout 的宽度依赖父元素（ScrollView）
- ScrollView 的宽度依赖内容（RowLayout）
- 形成循环依赖，布局引擎无法解决

### 假设 3: QDS 预览模式特有问题

**QDS 与实际运行的差异**：
- QDS 预览模式可能没有完整的 Qt 运行时环境
- 某些绑定计算可能在 QDS 中表现异常
- 需要在实际设备上测试验证

## 💡 解决方案

### 方案 1: 简化 focusItemIndex 绑定（推荐）

**问题**: 动态绑定触发大量重新计算

**解决**: 移除动态绑定，使用信号槽机制

```qml
// ❌ 当前代码（动态绑定）
item.focusItemIndex = Qt.binding(function() {
    return (root.currentFocusArea === 2 && root.currentCategory === 1)
           ? root.currentContentItemIndex
           : -1
})

// ✅ 修改后（信号槽）
Connections {
    target: root
    function onCurrentContentItemIndexChanged() {
        if (root.currentFocusArea === 2 && root.currentCategory === 1) {
            item.focusItemIndex = root.currentContentItemIndex
        } else {
            item.focusItemIndex = -1
        }
    }
    function onCurrentFocusAreaChanged() {
        if (root.currentFocusArea === 2 && root.currentCategory === 1) {
            item.focusItemIndex = root.currentContentItemIndex
        } else {
            item.focusItemIndex = -1
        }
    }
}
```

### 方案 2: 减少 Repeater delegate 中的绑定数量

**问题**: 每个 delegate 有 6 个绑定表达式

**解决**: 合并绑定，减少重新计算次数

```qml
// ❌ 当前代码（6 个独立绑定）
border.color: (root.focusSubArea === 0 && root.focusItemIndex === index) ? "#2196F3" : "transparent"
border.width: (root.focusSubArea === 0 && root.focusItemIndex === index) ? 3 : 0
// ...

// ✅ 修改后（使用中间属性）
readonly property bool isFocused: (root.focusSubArea === 0 && root.focusItemIndex === index)

border.color: isFocused ? "#2196F3" : "transparent"
border.width: isFocused ? 3 : 0
// ...
```

**优势**：
- 只有 1 个绑定计算 `isFocused`
- 其他绑定只依赖 `isFocused`，不直接依赖 `focusItemIndex`
- 减少绑定计算次数

### 方案 3: 延迟设置 focusItemIndex 绑定

**问题**: 绑定在页面加载时立即设置，可能触发大量计算

**解决**: 使用 `Qt.callLater` 延迟设置

```qml
onLoaded: {
    if (item) {
        // 先设置其他属性
        item.deviceId = root.deviceId
        item.deviceName = root.deviceName
        item.keyboardManager = keyboardManager

        // 延迟设置 focusItemIndex 绑定
        Qt.callLater(function() {
            item.focusItemIndex = Qt.binding(function() {
                return (root.currentFocusArea === 2 && root.currentCategory === 1)
                       ? root.currentContentItemIndex
                       : -1
            })
        })
    }
}
```

### 方案 4: 禁用 Repeater 的焦点指示器（临时方案）

**目的**: 验证是否是 Repeater 绑定导致的问题

**实施**: 临时注释掉 Repeater delegate 中的所有 `focusItemIndex` 相关绑定

## 📝 技术细节

### Qt Quick 绑定机制

**绑定计算触发条件**：
- 绑定表达式中引用的任何属性变化
- 即使最终值没有变化，绑定也会重新计算

**绑定性能问题**：
- 复杂的绑定表达式（多个条件判断）
- 大量的绑定（Repeater 中的绑定）
- 绑定循环（A 依赖 B，B 依赖 A）

**最佳实践**：
- 使用中间属性减少绑定复杂度
- 避免在 Repeater 中使用复杂绑定
- 使用信号槽代替动态绑定
- 使用 `readonly property` 缓存计算结果

## 🎯 总结
