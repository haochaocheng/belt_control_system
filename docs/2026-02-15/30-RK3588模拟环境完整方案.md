# RK3588模拟环境完整方案

**创建时间**: 2026-02-15 19:30
**目标**: 在没有实体设备的情况下，完全模拟RK3588环境进行开发和测试

---

## 📋 方案对比

### 方案1：Docker + VNC + noVNC（推荐）⭐

**优点**:
- ✅ 通过浏览器访问GUI界面（http://localhost:6080）
- ✅ 跨平台，Windows/Linux/Mac都可用
- ✅ 不需要配置X11服务器
- ✅ 易于集成到现有脚本
- ✅ 支持远程访问

**缺点**:
- ⚠️ 无法使用RK MPP硬件加速
- ⚠️ 性能约为原生的30-50%（QEMU用户模式）

**适用场景**:
- 界面开发和验证
- 功能测试
- 日常开发调试

---

### 方案2：Docker + X11转发

**优点**:
- ✅ 性能略好于VNC
- ✅ 原生显示效果

**缺点**:
- ❌ Windows需要安装X11服务器（VcXsrv/Xming）
- ❌ 配置复杂
- ❌ 不支持远程访问

**适用场景**:
- Linux开发环境
- 需要最佳性能

---

### 方案3：QEMU完整虚拟机

**优点**:
- ✅ 最接近真实设备
- ✅ 可以模拟硬件

**缺点**:
- ❌ 启动慢（5-10分钟）
- ❌ 性能差（约10-20%）
- ❌ 配置极其复杂
- ❌ 资源占用大（需要4GB+内存）

**适用场景**:
- 内核开发
- 驱动开发

## 🚀 推荐方案：Docker + VNC + noVNC

### 架构图

```
Windows 宿主机
    ↓
Docker Desktop
    ↓
Ubuntu 24.04 ARM64 容器（QEMU用户模式）
    ↓
├── Xvfb（虚拟显示服务器）
├── TigerVNC Server（VNC服务）
├── noVNC（Web界面）
└── belt_control_system（应用程序）
    ↓
浏览器访问：http://localhost:6080
```

## 📦 实施步骤

### Step 1: 创建模拟环境Dockerfile

**文件**: `docker/rk3588-simulator/Dockerfile`

```dockerfile
FROM ubuntu:24.04

# 设置环境变量
ENV DEBIAN_FRONTEND=noninteractive
ENV DISPLAY=:1
ENV VNC_PORT=5901
ENV NOVNC_PORT=6080

# 安装基础工具
RUN apt-get update && apt-get install -y \
    wget curl git vim \
    supervisor \
    && rm -rf /var/lib/apt/lists/*

# 安装虚拟显示和VNC
RUN apt-get update && apt-get install -y \
    xvfb \
    x11vnc \
    tigervnc-standalone-server \
    tigervnc-common \
    novnc \
    websockify \
    && rm -rf /var/lib/apt/lists/*

# 安装Qt和QML运行时
RUN apt-get update && apt-get install -y \
    qt6-base-dev \
    qt6-declarative-dev \
    qml6-module-qtquick \
    qml6-module-qtquick-controls \
    qml6-module-qtquick-layouts \
    qml6-module-qtquick-window \
    libqt6multimedia6 \
    libqt6multimediawidgets6 \
    && rm -rf /var/lib/apt/lists/*

# 安装应用依赖
RUN apt-get update && apt-get install -y \
    libmosquitto1 \
    libmosquitto-dev \
    libasound2 \
    libpulse0 \
    && rm -rf /var/lib/apt/lists/*

# 创建工作目录
WORKDIR /app

# 复制应用程序（在构建时复制）
# COPY bin_arm64/belt_control_system /app/
# COPY lib/ /app/lib/
# COPY config/ /app/config/

# 创建VNC密码文件
RUN mkdir -p ~/.vnc && \
    x11vnc -storepasswd 123456 ~/.vnc/passwd

# 创建supervisor配置
RUN mkdir -p /etc/supervisor/conf.d
COPY supervisord.conf /etc/supervisor/conf.d/

# 暴露端口
EXPOSE 5901 6080

# 启动脚本
COPY start.sh /start.sh
RUN chmod +x /start.sh

CMD ["/start.sh"]
```

### Step 2: 创建supervisor配置

**文件**: `docker/rk3588-simulator/supervisord.conf`

```ini
[supervisord]
nodaemon=true
user=root

[program:xvfb]
command=/usr/bin/Xvfb :1 -screen 0 1920x1080x24
autostart=true
autorestart=true
priority=100

[program:x11vnc]
command=/usr/bin/x11vnc -display :1 -forever -shared -rfbport 5901 -rfbauth /root/.vnc/passwd
autostart=true
autorestart=true
priority=200

[program:novnc]
command=/usr/share/novnc/utils/novnc_proxy --vnc localhost:5901 --listen 6080
autostart=true
autorestart=true
priority=300

[program:app]
command=/app/belt_control_system
directory=/app
environment=DISPLAY=":1",LD_LIBRARY_PATH="/app/lib"
autostart=true
autorestart=true
priority=400
stdout_logfile=/var/log/app.log
stderr_logfile=/var/log/app_error.log
```

### Step 4: 修改build-ubuntu24-apt.ps1

在脚本开头添加模拟设备选项：

```powershell
# 添加参数
param(
    [Parameter(Position=0)]
    [string]$Target = "188",  # 188 = 实体设备, "simulator" = 模拟设备

    [switch]$SkipBuild,
    [switch]$SkipDeploy
)

# 检查是否为模拟设备
$IsSimulator = ($Target -eq "simulator")

if ($IsSimulator) {
    Write-Host "🎮 模拟设备模式" -ForegroundColor Cyan
    Write-Host ""

    # 构建模拟环境镜像
    & docker build -t belt-control-simulator:latest -f docker/rk3588-simulator/Dockerfile .

    # 停止旧容器
    docker stop belt-control-sim 2>$null
    docker rm belt-control-sim 2>$null

    # 启动新容器
    docker run -d `
        --name belt-control-sim `
        -p 6080:6080 `
        -p 5901:5901 `
        -v "${PWD}/build_rk3588/bin_arm64:/app" `
        -v "${PWD}/docker/rk3588/lib:/app/lib" `
        -v "${PWD}/config:/app/config" `
        belt-control-simulator:latest

    Write-Host ""
    Write-Host "✅ 模拟环境已启动" -ForegroundColor Green
    Write-Host ""
    Write-Host "📺 访问方式：" -ForegroundColor Yellow
    Write-Host "   浏览器: http://localhost:6080" -ForegroundColor Gray
    Write-Host "   VNC客户端: localhost:5901 (密码: 123456)" -ForegroundColor Gray
    Write-Host ""
    Write-Host "📝 查看日志：" -ForegroundColor Yellow
    Write-Host "   docker logs -f belt-control-sim" -ForegroundColor Gray
    Write-Host ""

    exit 0
}

# 原有的实体设备部署逻辑
Write-Host "🔧 实体设备模式 (192.168.10.$Target)" -ForegroundColor Cyan
# ... 原有代码 ...
```

# 自动打开浏览器

## ⚠️ 限制和注意事项

### 1. 硬件加速不可用

**问题**：
- RK MPP硬件编解码器无法在模拟环境中使用
- 视频编解码会回退到软件实现

**解决方案**：
- 在代码中添加硬件检测
- 自动回退到软件编解码（FFmpeg libx264/libx265）

```cpp
// 示例代码
bool isSimulator = !QFile::exists("/dev/mpp_service");
if (isSimulator) {
    // 使用软件编解码
    useHardwareCodec = false;
}
```

### 2. 性能差异

**模拟环境性能**：
- CPU性能：约为原生的30-50%
- 内存：与原生相同
- 显示：VNC会有轻微延迟

**建议**：
- 界面开发和验证：使用模拟环境 ✅
- 性能测试：使用实体设备 ✅
- 视频编解码测试：使用实体设备 ✅

### 3. 网络配置

**模拟环境网络**：
- 容器内部网络与宿主机隔离
- MQTT需要连接到宿主机或外部服务器

**配置示例**：
```json
{
  "mqtt": {
    "host": "host.docker.internal",  // Windows/Mac
    "port": 1883
  }
}
```
