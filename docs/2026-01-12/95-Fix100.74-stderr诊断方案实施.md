## 一、背景

### VERSION 135 的谜团

**问题现象**：
- ✅ VERSION 135 确实部署（日志显示 `[STARTUP-VERSION] 135`）
- ✅ Fix 100.73 代码存在于源码中
- ❌ **但完全没有任何 `ffmpeg_codec_close()` 的日志输出**
- ❌ 崩溃调用栈显示函数被调用，但第一个 `PJ_LOG` 都没执行

**推测**：
1. 栈损坏导致函数无法正常执行
2. 或者 `codec` 指针指向已释放的内存
3. 或者日志系统在崩溃前就失效了

---

## 二、Fix 100.74 解决方案

### 核心思路

**使用 `fprintf(stderr)` 绕过 PJSIP 日志系统**

**优点**：
- ✅ 直接输出到 stderr，不依赖 PJSIP 日志缓冲
- ✅ 每次输出后 `fflush(stderr)` 强制刷新
- ✅ 即使崩溃，输出也不会丢失
- ✅ 可以精确定位崩溃的代码行

### 实施细节

**修改位置**：`ffmpeg_vid_codecs.c:ffmpeg_codec_close()` (Line 3082-3150)

**添加的诊断日志**：

#### 1. 函数入口（Line 3089-3091）
```c
fprintf(stderr, "\n!!! [STDERR-DIAG] ENTER ffmpeg_codec_close VERSION %d !!!\n", CODE_VERSION);
fprintf(stderr, "!!! [STDERR-DIAG] codec pointer = %p\n", (void*)codec);
fflush(stderr);
```

**目的**：确认函数是否被调用

#### 2. NULL 检查（Line 3100-3107）
```c
if (!codec) {
    fprintf(stderr, "!!! [STDERR-DIAG] codec is NULL! Returning PJ_EINVAL\n");
    fflush(stderr);
    return PJ_EINVAL;
}

fprintf(stderr, "!!! [STDERR-DIAG] codec is valid, about to access codec_data\n");
fflush(stderr);
```

**目的**：确认 `codec` 参数是否有效

#### 3. codec_data 读取（Line 3134-3140）
```c
fprintf(stderr, "!!! [STDERR-DIAG] About to read codec->codec_data (codec=%p)\n", (void*)codec);
fflush(stderr);

ff = (ffmpeg_private*)codec->codec_data;

fprintf(stderr, "!!! [STDERR-DIAG] codec->codec_data = %p\n", (void*)ff);
fflush(stderr);
```

**目的**：确认是否能访问 `codec->codec_data`

#### 4. NULL 检查结果（Line 3142-3150）
```c
if (!ff) {
    fprintf(stderr, "!!! [STDERR-DIAG] codec_data is NULL - DOUBLE CLOSE DETECTED!\n");
    fflush(stderr);
    PJ_LOG(1,(THIS_FILE, "✅ [FIX 100.73] codec_data is NULL, codec already closed (double-close prevented)"));
    return PJ_SUCCESS;
}

fprintf(stderr, "!!! [STDERR-DIAG] codec_data is valid, continuing cleanup\n");
fflush(stderr);
```

**目的**：确认是否检测到 double-close

## 三、预期结果

### 情况 A：函数未被调用

**stderr 输出**：无

**结论**：
- 崩溃发生在调用 `ffmpeg_codec_close()` 之前
- 可能是 `on_destroy()` 或其他调用者的问题

### 情况 B：函数被调用，但 codec 无效

**stderr 输出**：
```
!!! [STDERR-DIAG] ENTER ffmpeg_codec_close VERSION 136 !!!
!!! [STDERR-DIAG] codec pointer = 0x12345678
```
（然后崩溃）

**结论**：
- 函数确实被调用
- 访问 `codec` 时崩溃
- 说明 `codec` 指针指向无效内存

### 情况 C：codec 有效，但 codec_data 无效

**stderr 输出**：
```
!!! [STDERR-DIAG] ENTER ffmpeg_codec_close VERSION 136 !!!
!!! [STDERR-DIAG] codec pointer = 0x12345678
!!! [STDERR-DIAG] codec is NULL! Returning PJ_EINVAL
```
或
```
!!! [STDERR-DIAG] codec is valid, about to access codec_data
!!! [STDERR-DIAG] About to read codec->codec_data (codec=0x12345678)
```
（然后崩溃）

**结论**：
- `codec` 指针有效
- 访问 `codec->codec_data` 时崩溃
- 说明 `codec` 结构体本身在已释放的内存中

### 情况 D：成功检测到 double-close

**stderr 输出**：
```
!!! [STDERR-DIAG] ENTER ffmpeg_codec_close VERSION 136 !!!
!!! [STDERR-DIAG] codec pointer = 0x12345678
!!! [STDERR-DIAG] codec is valid, about to access codec_data
!!! [STDERR-DIAG] About to read codec->codec_data (codec=0x12345678)
!!! [STDERR-DIAG] codec->codec_data = 0x0
!!! [STDERR-DIAG] codec_data is NULL - DOUBLE CLOSE DETECTED!
```

**结论**：
- Fix 100.73 的 NULL 检查生效
- 成功防止了 double-close
- **但仍然崩溃，说明问题在其他地方**

## 四、调试策略

根据 stderr 输出，可以精确定位问题：

| stderr 输出停止位置 | 崩溃位置 | 下一步行动 |
|-------------------|---------|----------|
| 无输出 | 调用前 | 检查调用者（`on_destroy()` 等） |
| `ENTER` 后立即崩溃 | 访问 `codec` | `codec` 是野指针，需在调用前检查 |
| `codec is valid` 后崩溃 | 访问 `codec->codec_data` | `codec` 在已释放内存，需在调用前检查 |
| `DOUBLE CLOSE DETECTED` | NULL 检查后 | Fix 100.73 有效，但还有其他问题 |
| `continuing cleanup` | 清理过程中 | 清理逻辑有问题 |

## 七、关键技术点

### fprintf vs PJ_LOG

| 特性 | fprintf(stderr) | PJ_LOG |
|------|----------------|--------|
| 缓冲 | 可以 fflush 强制输出 | 可能有缓冲 |
| 依赖 | 只依赖 C 标准库 | 依赖 PJSIP 日志系统 |
| 崩溃前输出 | ✅ 可靠 | ❌ 可能丢失 |
| 日志格式 | 简单文本 | PJSIP 格式 |
| 适用场景 | 诊断崩溃 | 正常日志 |

### 为什么每次都 fflush

**原因**：
- stderr 默认是行缓冲或无缓冲
- 但在某些情况下（如 Docker）可能有缓冲
- `fflush(stderr)` 确保立即写入
- 即使崩溃，输出也不会丢失
