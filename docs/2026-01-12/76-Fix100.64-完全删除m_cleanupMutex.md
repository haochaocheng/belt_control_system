## 四、技术原理

### 为什么删除 m_cleanupMutex 能解决问题？

#### 1. QMutex 的生命周期

**作为成员变量**：
```cpp
class LocalVideoManager {
    QMutex m_cleanupMutex;  // ← 与对象共存亡
};
```

**Qt 在以下时刻可能访问 QMutex**：
1. **对象创建时**：QMutex 构造
2. **运行时**：可能的内部检查、调试、元对象系统
3. **信号发射时**：Qt 的信号槽机制可能检查对象状态
4. **对象析构时**：QMutex 析构 → 调用 pthread_mutex_destroy

**如果线程状态异常**（ESRCH）：
- pthread 操作失败
- 程序 abort (Exit code 133)

---

#### 2. Fix 100.63 vs Fix 100.64

| 对比项 | Fix 100.63 ❌ | Fix 100.64 ✅ |
|--------|--------------|--------------|
| **stopPreview() 使用 mutex** | ❌ 否（已注释）| ❌ **否**（已注释）|
| **m_cleanupMutex 成员变量** | ✅ **存在**（Line 72）| ❌ **完全删除** |
| **Qt 可能访问 mutex** | ✅ **可能**（成员变量存在）| ❌ **不可能**（变量不存在）|
| **pthread 依赖** | ✅ **存在**（QMutex 内部）| ❌ **无**（完全删除）|
| **崩溃风险** | ✅ **存在** | ❌ **无** |

---

#### 3. RemoteVideoManager 的成功证明

**RemoteVideoManager 清理代码**（无 mutex）：
```cpp
void RemoteVideoManager::onCallDisconnected()
{
    qDebug() << "📹 RemoteVideoManager: Call disconnected";

    // ✅ 简单清理，无 mutex
    if (m_customSlot != PJSUA_INVALID_ID) {
        pjsua_vid_conf_remove_port(m_customSlot);
        m_customSlot = PJSUA_INVALID_ID;
    }

    if (m_customPool) {
        pj_pool_release(m_customPool);
        m_customPool = nullptr;
    }

    // ✅ 成功，无崩溃
}
```

**对比 LocalVideoManager**：
- LocalVideoManager：QMutex 成员变量 + 复杂的清理逻辑 → 崩溃
- RemoteVideoManager：无 mutex + 简单清理 → **成功** ✅
