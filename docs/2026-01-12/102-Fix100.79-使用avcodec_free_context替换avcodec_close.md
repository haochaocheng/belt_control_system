## 二、根本原因定位

### 关键发现：avcodec_close() 已废弃

**FFmpeg 官方文档**：

```c
/**
 * Close a given AVCodecContext and free all the data associated with it
 * (but not the AVCodecContext itself).
 *
 * @deprecated Use avcodec_free_context() to free the context.
 */
attribute_deprecated
int avcodec_close(AVCodecContext *avctx);
```

**废弃时间**：FFmpeg 3.1 (2016年)

**推荐替代**：
```c
/**
 * Free the codec context and everything associated with it and write NULL to
 * the provided pointer.
 */
void avcodec_free_context(AVCodecContext **avctx);
```

### 问题机制

**当前代码**（VERSION 137-140）：
```c
avcodec_close(ff->enc_ctx);  // ← 废弃 API，可能有 bug
av_free(ff->enc_ctx);         // ← 手动释放上下文
```

**问题**：
1. `avcodec_close()` 已被废弃超过 8 年
2. FFmpeg 可能不再维护其正确性
3. 与现代硬件加速机制（hw_frames_ctx, hw_device_ctx）配合可能有 bug
4. 特别是在 **RKMPP 硬件编码器** 的场景下

**为什么解码器成功但编码器失败？**
- 编码器使用了更复杂的资源（hw_device_ctx 共享、硬件帧分配等）
- `avcodec_close()` 的 bug 在复杂资源场景下被触发
- 解码器资源较简单，侥幸避开了 bug

### FFmpeg 推荐方法

**avcodec_free_context() 优势**：
1. **一步完成**：关闭编解码器 + 释放上下文 + 设置指针为 NULL
2. **现代 API**：持续维护，兼容所有硬件加速方式
3. **正确清理**：保证释放 hw_frames_ctx、hw_device_ctx 等所有资源
4. **避免野指针**：自动设置指针为 NULL

## 四、技术要点

### avcodec_close vs avcodec_free_context

#### avcodec_close（废弃）

```c
int avcodec_close(AVCodecContext *avctx);
```

**特点**：
- 只关闭编解码器，不释放上下文
- 需要手动调用 `av_free(avctx)`
- 自 FFmpeg 3.1 (2016) 起废弃
- 可能与现代硬件加速不兼容

**风险**：
- 可能没有正确清理 hw_frames_ctx, hw_device_ctx
- 在 RKMPP 等硬件编码器场景下可能有 bug
- 不再被 FFmpeg 团队维护

#### avcodec_free_context（推荐）

```c
void avcodec_free_context(AVCodecContext **avctx);
```

**特点**：
- 一步完成：关闭 + 释放 + 设置为 NULL
- 正确处理所有资源（hw_frames_ctx, hw_device_ctx, 内部缓冲区等）
- 持续维护，兼容所有硬件加速方式
- 避免野指针（自动设置为 NULL）

**优势**：
- **简化代码**：两步变一步
- **更可靠**：FFmpeg 团队持续维护
- **更安全**：自动设置指针为 NULL

### 为什么 VERSION 137-140 都失败？

**共同点**：都使用 `avcodec_close()`

**问题根源**：
1. `avcodec_close()` 在处理硬件加速资源时可能有 bug
2. 编码器资源比解码器复杂（共享 hw_device_ctx, 硬件帧分配等）
3. `avcodec_close()` 的 bug 在编码器场景下被触发

**为什么解码器成功？**
- 侥幸：解码器资源较简单，避开了 bug
- 不可靠：依赖运气，不是正确的解决方案

### 为什么 Fix 100.79 会成功？

**理由**：
1. **遵循官方建议**：使用 FFmpeg 推荐的 API
2. **避免已知问题**：不使用有 bug 的废弃 API
3. **正确清理**：`avcodec_free_context()` 保证清理所有资源
4. **持续维护**：FFmpeg 团队持续优化和修复
