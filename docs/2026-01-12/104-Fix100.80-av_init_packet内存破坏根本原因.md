**问题**：**只修复了 avframe.data，没有修复其他可能被破坏的字段或状态**

**每帧编码都会**：
1. 调用 `av_init_packet()` → 破坏内存
2. Fix 100.42.3 修复 `avframe.data`
3. 但**编码器内部状态**可能已经被破坏（引用计数、内部指针等）
4. 累积多帧后，**编码器内部状态严重损坏**

### 步骤 6：清理时崩溃


**为什么崩溃在 free()？**
- 编码器内部的**指针**被破坏（指向非法地址或已释放的内存）
- `avcodec_close()` 尝试 `free(corrupted_pointer)`
- `free()` 内部检查元数据时发现异常 → SIGSEGV

## 五、Fix 100.80 解决方案

### 核心思路

**使用 av_packet_alloc() / av_packet_free() 替换 av_init_packet()**

### FFmpeg 官方推荐方法

**旧方法**（已废弃）：
```c
AVPacket avpacket;  // 栈上分配
av_init_packet(&avpacket);  // 初始化（可能破坏内存）
avpacket.data = buffer;
avpacket.size = size;
// ... 使用 avpacket
av_packet_unref(&avpacket);  // 清理
```

**新方法**（推荐）：
```c
AVPacket *avpacket = av_packet_alloc();  // 堆上分配
if (!avpacket) return ENOMEM;
avpacket->data = buffer;
avpacket->size = size;
// ... 使用 avpacket
av_packet_free(&avpacket);  // 释放
```

**优势**：
1. **堆上分配**：不会与栈上的其他变量相邻
2. **现代 API**：FFmpeg 6.0 持续维护，兼容性好
3. **避免内存破坏**：不会写入超出边界
4. **自动管理**：`av_packet_free()` 自动释放所有资源

### 修改位置

#### 修改 1：编码器路径（Line 3751-3753）

**修改前**：
```c
av_init_packet(&avpacket);
avpacket.data = (pj_uint8_t*)output->buf;
avpacket.size = output_buf_len;
```

**修改后**：
```c
AVPacket *avpacket = av_packet_alloc();
if (!avpacket) {
    PJ_LOG(1,(THIS_FILE, "❌ [FIX 100.80] av_packet_alloc() failed for encoder"));
    return PJMEDIA_CODEC_EFAILED;
}
avpacket->data = (pj_uint8_t*)output->buf;
avpacket->size = output_buf_len;
```

**同时修改所有使用 `avpacket` 的地方**：
```c
// 旧代码：avpacket.xxx
// 新代码：avpacket->xxx

// 例如：
// avcodec_receive_packet(ff->enc_ctx, &avpacket)  ← 旧
avcodec_receive_packet(ff->enc_ctx, avpacket)  // ← 新

// av_packet_unref(&avpacket)  ← 旧
av_packet_free(&avpacket)  // ← 新（自动 unref）
```

#### 修改 2：编码器 Flush（如果恢复 Flush）

**注意**：Fix 100.78 移除了 Flush，如果需要恢复，也要使用 `av_packet_alloc()`

#### 修改 3：解码器路径（Line 4319-4321）

**虽然解码器清理成功**，但为了**统一和安全**，也应该修改：

**修改前**：
```c
av_init_packet(&avpacket);
avpacket.data = (pj_uint8_t*)input->buf;
avpacket.size = (int)input->size;
```

**修改后**：
```c
AVPacket *avpacket = av_packet_alloc();
if (!avpacket) {
    PJ_LOG(1,(THIS_FILE, "❌ [FIX 100.80] av_packet_alloc() failed for decoder"));
    return PJMEDIA_CODEC_EFAILED;
}
avpacket->data = (pj_uint8_t*)input->buf;
avpacket->size = (int)input->size;
```

**同样修改所有使用 `avpacket` 的地方**。

## 七、技术要点

### av_init_packet vs av_packet_alloc

| 特征 | av_init_packet（废弃） | av_packet_alloc（推荐） |
|------|------------------------|------------------------|
| **分配位置** | 栈上（由调用者分配） | 堆上（FFmpeg 分配） |
| **初始化方式** | 直接写入结构体 | 调用内部分配函数 |
| **内存安全** | ❌ 可能破坏相邻变量 | ✅ 隔离，不会破坏其他变量 |
| **FFmpeg 版本** | FFmpeg < 6.0 | FFmpeg 3.1+ |
| **维护状态** | ❌ 已废弃，不再维护 | ✅ 持续维护 |
| **释放方式** | av_packet_unref() | av_packet_free()（自动 unref） |

### 内存破坏的隐蔽性

**为什么 Fix 100.42.3 看起来修复了问题，但清理时还是崩溃？**

1. **表面修复**：Fix 100.42.3 修复了 `avframe.data`，编码能继续
2. **深层破坏**：av_init_packet 可能还破坏了：
   - `avframe` 的其他字段（width, height, format, linesize）
   - 编码器内部的引用计数
   - 编码器内部的指针
   - hw_frames_ctx 的元数据
3. **累积效应**：每帧都破坏一点，累积多帧后内部状态严重损坏
4. **延迟爆发**：崩溃发生在清理时，而不是编码时

### 为什么解码器成功？

**可能的原因**：
1. **栈布局不同**：编译器可能将解码器的 `avframe` 和 `avpacket` 分配到不相邻的位置
2. **破坏不影响关键状态**：即使有破坏，可能没有影响解码器的关键状态
3. **使用时机不同**：解码器的 `av_init_packet` 可能在不同的时机调用

**但不管原因是什么，都应该统一修复**。

- 破坏发生在编码过程中，但**不立即崩溃**

- 每帧编码都破坏一点

- 清理时访问损坏状态 → 崩溃

**教训**：
- 发现内存破坏时，**不要只修复表面问题**
- 应该**消除破坏源**（替换 av_init_packet）
