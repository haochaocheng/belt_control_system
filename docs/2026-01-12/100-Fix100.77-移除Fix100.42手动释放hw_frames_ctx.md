## 二、根本原因定位

### 关键证据：Fix 100.42（Line 2727-2740）

**原代码**（VERSION 138）：
```c
/* ✅ 2026-01-11 17:10 [FIX 100.42] 编码器打开后再次检查并清除 hw_frames_ctx
 * 问题：FFmpeg 可能在 avcodec_open2() 时自动创建 hw_frames_ctx
 * 证据：voip.md 显示 hwfc size=126x1（错误尺寸）导致 avcodec_send_frame() 返回 -22
 * 解决：打开后强制清除，确保编码器使用 CPU 内存输入
 */
if (ff->enc_ctx->hw_frames_ctx) {
    PJ_LOG(1,(THIS_FILE, "⚠️ [FIX 100.42] WARNING: hw_frames_ctx was auto-created by avcodec_open2()!"));
    AVHWFramesContext *hwfc = (AVHWFramesContext *)ff->enc_ctx->hw_frames_ctx->data;
    if (hwfc) {
        PJ_LOG(1,(THIS_FILE, "   Auto-created hwfc: format=%d, sw_format=%d, size=%dx%d",
                  hwfc->format, hwfc->sw_format, hwfc->width, hwfc->height));
    }
    PJ_LOG(1,(THIS_FILE, "   Releasing hw_frames_ctx to force CPU memory input..."));
    av_buffer_unref(&ff->enc_ctx->hw_frames_ctx);  // ← Use-After-Free 的根源！
    ff->enc_ctx->hw_frames_ctx = NULL;
    PJ_LOG(1,(THIS_FILE, "   ✅ hw_frames_ctx cleared successfully"));
} else {
    PJ_LOG(1,(THIS_FILE, "✅ [FIX 100.42] hw_frames_ctx is NULL (good, will use CPU memory)"));
}
```

### 问题机制分析

**时间线**：
1. `avcodec_open2(ff->enc_ctx, ...)` → FFmpeg 内部自动创建了 `hw_frames_ctx`
2. **Fix 100.42 手动释放了它**：`av_buffer_unref(&ff->enc_ctx->hw_frames_ctx)`
3. 虽然清除了指针（`hw_frames_ctx = NULL`），但 **FFmpeg 编码器内部可能仍持有引用**
4. 视频编码过程中，编码器正常使用这些引用
5. `avcodec_close()` 时，编码器尝试访问已释放的 hw_frames_ctx → **Use-After-Free 崩溃**

**这不是 double-free，而是 use-after-free！**

**为什么解码器成功但编码器失败？**
- 解码器没有 Fix 100.42 类似的代码
- 解码器的 hw_frames_ctx 从未被手动释放（直到 avcodec_close()）
- 编码器的 hw_frames_ctx 在初始化后被 Fix 100.42 手动释放

## 五、技术要点

### Use-After-Free vs Double-Free

**Double-Free**：
- 同一块内存被释放两次
- 典型场景：手动 `av_buffer_unref()` + `avcodec_close()` 内部再次 unref

**Use-After-Free**（本次问题）：
- 提前释放内存，但仍有引用在使用
- 典型场景：
  1. FFmpeg 内部创建 hw_frames_ctx 并持有引用
  2. 外部手动释放：`av_buffer_unref(&hw_frames_ctx)`
  3. FFmpeg 内部仍在使用这些引用（编码过程中）
  4. `avcodec_close()` 时访问已释放的内存 → 崩溃

### 为什么清除指针也不够？

```c
av_buffer_unref(&ff->enc_ctx->hw_frames_ctx);
ff->enc_ctx->hw_frames_ctx = NULL;  // ← 清除了指针
```

**问题**：
- 清除的只是 `enc_ctx->hw_frames_ctx` 这个指针
- 但 FFmpeg 编码器**内部**可能还有其他指向同一块内存的引用
- 这些内部引用并没有被清除
- 当 `avcodec_close()` 时，这些内部引用尝试访问已释放的内存

### Fix 100.42 的原始目的

**目的**：强制编码器使用 CPU 内存输入（避免硬件帧格式问题）

**错误的方法**：手动释放 hw_frames_ctx

**正确的方法**（如果仍需要）：
1. 在 `avcodec_open2()` 之前设置参数，防止 FFmpeg 创建 hw_frames_ctx
2. 或者接受 FFmpeg 创建的 hw_frames_ctx，并正确使用它
3. **绝对不能手动释放 FFmpeg 管理的资源**
