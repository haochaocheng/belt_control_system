## 二、技术洞察总结

### 🔑 关键洞察 1：mutex 是问题源，不是解决方案

**错误路径**：
- Fix 100.58：引入 `QMutex m_cleanupMutex;` 保护清理逻辑
- Fix 100.59-100.62：保留 mutex，尝试各种清理策略
- Fix 100.63：移除 mutex 使用，但保留成员变量

**正确路径**：
- Fix 100.64：**完全删除 m_cleanupMutex 成员变量**

**原因**：
1. Fix 100.62 的操作足够简单（只做标记，不实际清理）
2. 所有操作都是原子的或 Qt 线程安全的
3. mutex 反而引入 pthread 依赖和失败风险
4. **成员变量的存在本身就是问题**（Qt 会在对象生命周期访问它）

---

### 🔑 关键洞察 2：PJSIP 自动清理的时序

**日志证据**（docs/log/voip.md Line 3107）：
```
13:23:21.989  vid_conf.c !.Port 3 (USB camera: USB camera) stop transmitting to port 2 (vstenc0x7ef80108b0)
13:23:21.989  vid_conf.c  .Port 3 (USB camera: USB camera) stop transmitting to port 4 (qt_local_video_sink)
              ↑ PJSIP 自动断开连接（用户挂断后）

13:23:21.990  [DEBUG] 🔧 [FIX 100.64] Initiating cleanup (custom_slot: 4)
              ↑ LocalVideoManager 响应（晚 1ms）
```

**教训**：
- **手动 disconnect 总是失败**（PJSIP 已自动处理，返回 PJ_EINVAL）
- **手动 remove 与 PJSIP 竞争**（异步操作，时序不可控）
- **正确做法**：让 PJSIP 自动处理，在 on_destroy 回调中清理资源

---

### 🔑 关键洞察 3：静态映射避免访问 this

**问题**：
- on_destroy 回调时，LocalVideoManager 对象可能已销毁
- 访问 `this->m_customPool` 导致野指针崩溃

**解决方案**：
```cpp
// ✅ 静态映射（Fix 100.62）
static std::unordered_map<pjmedia_port*, pj_pool_t*> s_portPoolMap;

// 创建时保存
s_portPoolMap[m_customPort] = m_customPool;

// 销毁时查找
auto it = s_portPoolMap.find(port);
if (it != s_portPoolMap.end()) {
    pj_pool_release(it->second);
    s_portPoolMap.erase(it);
}
```

**优势**：
- 完全不依赖对象生命周期
- 即使对象已销毁，静态映射仍可访问
- 线程安全（C++ 静态变量）

---

### 🔑 关键洞察 4：RemoteVideoManager 的成功证明

**对比分析**：

| 对比项 | RemoteVideoManager ✅ | LocalVideoManager (Fix 100.63) ❌ |
|--------|----------------------|----------------------------------|
| **清理结果** | 成功，无崩溃 | 崩溃 (pthread_mutex_lock 失败) |
| **QMutex 成员变量** | ❌ **无** | ✅ **有**（`QMutex m_cleanupMutex`）|
| **清理逻辑** | 简单直接 | 复杂（Fix 100.56-100.63）|

**结论**：
- RemoteVideoManager 无 QMutex 成员变量 → 清理成功 ✅
- LocalVideoManager 有 m_cleanupMutex 成员变量 → 清理崩溃 ❌
- **成员变量的存在本身就是问题源**

## 四、新的挑战：编码器崩溃

### 崩溃现象

**Exit Code**: 139 (SIGSEGV)

**Core Dump 分析**:
```
[1] 崩溃位置
#0  __GI___libc_free (mem=<optimized out>) at ./malloc/malloc.c:3375
#1  0x0000007f84e73500 in avcodec_close () from /app/lib/libavcodec.so.60
#2  0x00000055702ce244 in ffmpeg_codec_close ()
#3  0x0000005570318484 in on_destroy ()
```

**关键发现**:
- 崩溃在 `avcodec_close()` → `__GI___libc_free()`
- 这是 **PJSIP 编码器的 on_destroy() 回调**
- **不是 LocalVideoManager 的 custom port on_destroy()**

---

### 时序分析

```
t0  用户挂断电话
    ↓
t1  LocalVideoManager::stopPreview() 被调用
    ├─ [DEBUG] 🔧 [FIX 100.64] Initiating cleanup...

    └─ [DEBUG] ✅ [FIX 100.64] Custom port cleanup initiated...
    ✅ 完成，正常返回

t2  PJSIP 开始自动清理所有资源
    ├─ 清理 cap_slot (摄像头) ✅
    ├─ 清理 enc_slot (编码器) ❌ ← 崩溃在这里！
    │  └─ on_destroy() → ffmpeg_codec_close() → avcodec_close() → free() → SIGSEGV
    └─ 清理 custom_slot (LocalVideoManager) ⏸️ 未执行（已崩溃）
```

**结论**:
- **LocalVideoManager 的清理已完成** ✅
- **崩溃发生在 LocalVideoManager 清理之后** ⚠️
- **是 PJSIP 编码器清理时崩溃** ❌
