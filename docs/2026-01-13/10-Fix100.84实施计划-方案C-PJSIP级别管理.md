# Fix 100.84 方案C实施计划：PJSIP级别管理硬件上下文

**时间**: 2026-01-13 15:40
**目标**: 按照FFmpeg最佳实践，在PJSIP级别管理hw_frames_ctx和hw_device_ctx，避免double-free崩溃

## 当前问题回顾

### 崩溃路径（Fix 100.83分析）
```
1. rkmpp_encode_close()
   → av_buffer_unref(&r->hwframe)  ← 第一次释放
   → av_buffer_unref(&r->hwdevice)  ← 第一次释放
   → return 0 (SUCCESS)

2. ffmpeg_codec_close()
   → avcodec_free_context(&ff->enc_ctx)
      → 内部调用编码器的close (已完成)
      → av_buffer_unref(&avctx->hw_frames_ctx)  ← 第二次释放（如果不为NULL）
      → ❌ CRASH: double-free in libc_free()
```

### 根本原因
- **编码器内部创建的hwframe**：rkmpp编码器在init时创建`r->hwframe`（私有）
- **但编码器可能也设置了`avctx->hw_frames_ctx`**：如果设置了，avcodec_free_context会尝试释放
- **重复释放导致崩溃**：同一个buffer被释放两次

## 方案C：PJSIP级别管理（推荐）

### 1. **原理（参考VA-API、NVENC、QSV）**

FFmpeg官方硬件编码器最佳实践：
```c
// 应用层（PJSIP）负责创建hw_frames_ctx
AVBufferRef *hw_device_ctx = NULL;
AVBufferRef *hw_frames_ctx = NULL;

// 创建硬件设备
av_hwdevice_ctx_create(&hw_device_ctx, AV_HWDEVICE_TYPE_RKMPP, NULL, NULL, 0);

// 创建硬件帧上下文
hw_frames_ctx = av_hwframe_ctx_alloc(hw_device_ctx);
AVHWFramesContext *frames_ctx = (AVHWFramesContext *)hw_frames_ctx->data;
frames_ctx->format = AV_PIX_FMT_DRM_PRIME;
frames_ctx->sw_format = AV_PIX_FMT_NV12;  // 或I420
frames_ctx->width = 640;
frames_ctx->height = 480;
av_hwframe_ctx_init(hw_frames_ctx);

// 传递给编码器（增加引用计数）
enc_ctx->hw_frames_ctx = av_buffer_ref(hw_frames_ctx);

// 打开编码器
avcodec_open2(enc_ctx, encoder, NULL);

// 清理时，只需调用一次avcodec_free_context
avcodec_free_context(&enc_ctx);  // 自动释放hw_frames_ctx

// 释放我们持有的引用
av_buffer_unref(&hw_frames_ctx);
av_buffer_unref(&hw_device_ctx);
```

### 2. **关键优势**

1. ✅ **明确所有权**：hw_frames_ctx由PJSIP创建，编码器只是引用
2. ✅ **符合FFmpeg规范**：与VA-API、NVENC、QSV保持一致
3. ✅ **避免double-free**：引用计数机制保证安全释放
4. ✅ **不修改FFmpeg源码**：只修改PJSIP集成代码（ffmpeg_vid_codecs.c）

### 3. **rkmpp编码器支持检查**

查看rkmppenc.c Line 1387-1403：
```c
if (avctx->hw_frames_ctx || avctx->hw_device_ctx) {
    AVBufferRef *device_ref = avctx->hw_device_ctx;
    AVHWFramesContext *hwfc = NULL;

    if (avctx->hw_frames_ctx) {
        hwfc = (AVHWFramesContext *)avctx->hw_frames_ctx->data;
        device_ref = hwfc->device_ref;  // ← 从frames_ctx获取device
    }
    device_ctx = (AVHWDeviceContext *)device_ref->data;

    if (device_ctx && device_ctx->type == AV_HWDEVICE_TYPE_RKMPP) {
        r->hwdevice = av_buffer_ref(device_ref);  // ← 增加引用计数
        if (r->hwdevice)
            av_log(avctx, AV_LOG_VERBOSE, "Picked up an existing RKMPP hardware device\n");
    }
}
```

**重要发现**：
- ✅ **编码器支持外部hw_frames_ctx**：如果检测到avctx->hw_frames_ctx，会使用它
- ✅ **编码器会引用外部hwdevice**：`r->hwdevice = av_buffer_ref(device_ref)`
- ⚠️ **但编码器仍会创建内部r->hwframe**：Line 1414调用`init_hwframes_ctx()`

### 4. **需要修改的地方**

#### A. **问题：编码器总是创建内部hwframe**
Line 1414-1416（rkmppenc.c）：
```c
ret = init_hwframes_ctx(avctx);  // ← 总是创建内部r->hwframe
if (ret < 0)
    goto fail;
```

即使avctx->hw_frames_ctx已经设置，编码器仍会创建内部r->hwframe。

#### B. **解决方案：修改rkmppenc.c跳过内部创建**

**方案B.1：检查avctx->hw_frames_ctx**
```c
// Line 1384-1418修改
if (avctx->pix_fmt == AV_PIX_FMT_DRM_PRIME) {
    // ✅ 检查是否已有外部hw_frames_ctx
    if (avctx->hw_frames_ctx) {
        // 使用外部hw_frames_ctx，不创建内部r->hwframe
        AVHWFramesContext *hwfc = (AVHWFramesContext *)avctx->hw_frames_ctx->data;
        r->hwdevice = av_buffer_ref(hwfc->device_ref);
        r->hwframe = av_buffer_ref(avctx->hw_frames_ctx);  // ← 引用外部
        av_log(avctx, AV_LOG_INFO, "Using external hw_frames_ctx\n");
    } else {
        // 没有外部hw_frames_ctx，使用原有逻辑创建内部
        // ... 原有代码 ...
        ret = init_hwframes_ctx(avctx);
        if (ret < 0)
            goto fail;
    }
    return 0;
}
```

**方案B.2：修改close函数检查所有权**
```c
// Line 1215-1224修改 (rkmpp_encode_close)
if (r->hwframe) {
    // 检查是否是外部传入的hw_frames_ctx
    if (avctx->hw_frames_ctx && avctx->hw_frames_ctx->data == r->hwframe->data) {
        // 外部hw_frames_ctx，不释放（avcodec_free_context会处理）
        av_log(avctx, AV_LOG_INFO, "Skipping hwframe unref (managed externally)\n");
        r->hwframe = NULL;  // 清除指针，但不释放
    } else {
        // 内部创建的hwframe，需要释放
        av_buffer_unref(&r->hwframe);
    }
}
```

## 实施步骤

### Step 1: 修改PJSIP（ffmpeg_vid_codecs.c）

在编码器打开前创建hw_frames_ctx（Line 2670前插入）：

```c
// ✅ 2026-01-13 16:00 [FIX 100.84] 方案C - PJSIP级别管理hw_frames_ctx
// 原理：按照VA-API/NVENC/QSV最佳实践，由应用层创建和管理硬件上下文
// 参考：FFmpeg官方示例（qsv_transcode.c, vaapi_encode.c）
// 详细：docs/2026-01-13/08-FFmpeg硬件编码器资源管理-全网最佳实践.md
if (ff->enc && (pj_ansi_strstr(ff->enc->name, "rkmpp") != NULL)) {
    AVBufferRef *hw_device_ctx = NULL;
    AVBufferRef *hw_frames_ctx = NULL;
    int ret;

    PJ_LOG(1,(THIS_FILE, "✅ [FIX 100.84] Creating hw_frames_ctx at PJSIP level"));

    // Step 1: 创建硬件设备上下文
    ret = av_hwdevice_ctx_create(&hw_device_ctx, AV_HWDEVICE_TYPE_RKMPP, NULL, NULL, 0);
    if (ret < 0) {
        char errbuf[128];
        av_strerror(ret, errbuf, sizeof(errbuf));
        PJ_LOG(2,(THIS_FILE, "❌ [FIX 100.84] Failed to create hw_device_ctx: %s", errbuf));
        status = PJMEDIA_CODEC_EFAILED;
        goto on_error;
    }
    PJ_LOG(1,(THIS_FILE, "   ✅ hw_device_ctx created: %p", hw_device_ctx));

    // Step 2: 创建硬件帧上下文
    hw_frames_ctx = av_hwframe_ctx_alloc(hw_device_ctx);
    if (!hw_frames_ctx) {
        PJ_LOG(2,(THIS_FILE, "❌ [FIX 100.84] Failed to alloc hw_frames_ctx"));
        av_buffer_unref(&hw_device_ctx);
        status = PJMEDIA_CODEC_EFAILED;
        goto on_error;
    }

    AVHWFramesContext *frames_ctx = (AVHWFramesContext *)hw_frames_ctx->data;
    frames_ctx->format    = AV_PIX_FMT_DRM_PRIME;
    frames_ctx->sw_format = AV_PIX_FMT_NV12;  // RKMPP编码器使用NV12
    frames_ctx->width     = ff->enc_ctx->width;
    frames_ctx->height    = ff->enc_ctx->height;

    ret = av_hwframe_ctx_init(hw_frames_ctx);
    if (ret < 0) {
        char errbuf[128];
        av_strerror(ret, errbuf, sizeof(errbuf));
        PJ_LOG(2,(THIS_FILE, "❌ [FIX 100.84] Failed to init hw_frames_ctx: %s", errbuf));
        av_buffer_unref(&hw_frames_ctx);
        av_buffer_unref(&hw_device_ctx);
        status = PJMEDIA_CODEC_EFAILED;
        goto on_error;
    }
    PJ_LOG(1,(THIS_FILE, "   ✅ hw_frames_ctx initialized: format=%d, sw_format=%d, size=%dx%d",
              frames_ctx->format, frames_ctx->sw_format, frames_ctx->width, frames_ctx->height));

    // Step 3: 传递给编码器（增加引用计数）
    ff->enc_ctx->hw_frames_ctx = av_buffer_ref(hw_frames_ctx);
    PJ_LOG(1,(THIS_FILE, "   ✅ hw_frames_ctx passed to encoder (ref count increased)"));

    // Step 4: 保存PJSIP持有的引用（用于清理）
    // 注意：我们需要在ffmpeg_private结构体中添加字段保存这些引用
    // ff->hw_frames_ref = hw_frames_ctx;  // 不释放，保留引用
    // ff->hw_device_ref = hw_device_ctx;  // 不释放，保留引用

    // ⚠️ 暂时策略：立即释放我们的引用，因为encoder已经增加了引用计数
    // 清理时avcodec_free_context会自动处理
    av_buffer_unref(&hw_frames_ctx);
    av_buffer_unref(&hw_device_ctx);
    PJ_LOG(1,(THIS_FILE, "   ✅ Released local references (encoder holds refs)"));
}
```

### Step 2: 修改rkmpp编码器（rkmppenc.c）

**方案：修改close函数，检查所有权**（推荐，最小改动）

在rkmpp_encode_close函数中（Line 1215-1224）：

```c
/* DIAG-10: 硬件上下文清理 */
fprintf(stderr, "[FIX 100.83 DIAG-10] About to unref hw contexts (hwframe=%p, hwdevice=%p)\n",
        r->hwframe, r->hwdevice);
fflush(stderr);

// ✅ 2026-01-13 16:00 [FIX 100.84] 检查hwframe所有权，避免double-free
if (r->hwframe) {
    // 检查是否是外部传入的hw_frames_ctx
    if (avctx->hw_frames_ctx && r->hwframe->data == avctx->hw_frames_ctx->data) {
        fprintf(stderr, "[FIX 100.84] hwframe is external (avctx->hw_frames_ctx), skipping unref\n");
        fflush(stderr);
        // 不释放，由avcodec_free_context处理
        r->hwframe = NULL;
    } else {
        fprintf(stderr, "[FIX 100.84] hwframe is internal, unreferencing\n");
        fflush(stderr);
        av_buffer_unref(&r->hwframe);
        fprintf(stderr, "[FIX 100.83 DIAG-11] hwframe unref SUCCESS\n");
        fflush(stderr);
    }
}

if (r->hwdevice) {
    // hwdevice总是内部引用（即使设备本身是外部的，r->hwdevice是我们自己ref的）
    av_buffer_unref(&r->hwdevice);
    fprintf(stderr, "[FIX 100.83 DIAG-12] hwdevice unref SUCCESS\n");
    fflush(stderr);
}
```
