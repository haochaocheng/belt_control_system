## 💡 根本原因

### 原因分析

**三种可能性**：

#### 可能性 1：日志缓冲未 flush（⭐ 最可能）

**机制**：
- FFmpeg 的 av_log() 使用内部缓冲
- 程序崩溃时，缓冲区数据未写入 stderr
- 导致 DIAG-1 日志"写入"了但没"输出"

**证据**：
- STDERR-DIAG 使用 `fprintf(stderr, ...)` + `fflush(stderr)` → ✅ 立即输出
- av_log() 使用内部缓冲机制 → ❌ 崩溃时丢失

**类比**：
```c
// STDERR-DIAG（立即输出）
fprintf(stderr, "DIAG-9: About to call...\n");
fflush(stderr);  // ← 强制刷新
avcodec_free_context(enc_ctx);  // 崩溃

// Fix 100.81（缓冲丢失）
av_log(avctx, AV_LOG_ERROR, "DIAG-1: Enter\n");  // 写入缓冲
// 崩溃前未 flush，日志丢失
```

#### 可能性 2：崩溃发生在 rkmpp_encode_close() 入口之前

**机制**：
- avcodec_free_context() 在调用 codec->close() **之前**崩溃
- 可能是访问无效指针、空指针解引用等

**证据不足**：
- avcodec_free_context() 是 FFmpeg 核心函数，应该稳定
- 没有其他证据表明崩溃在 close() 之前

#### 可能性 3：stderr 重定向问题

**机制**：
- FFmpeg 日志可能输出到不同的文件描述符
- stderr 重定向配置可能过滤了某些日志

**证据不足**：
- 其他 av_log() 日志（如解码器）正常输出
- 不太可能只有编码器日志被过滤

---

## ✅ 最终结论

**根本原因**：**av_log() 缓冲未 flush**（可能性 1）

**证据链**：
1. ✅ 源码已修改（包含 DIAG-1）
2. ✅ 增量编译成功（库时间戳 08:37）
3. ✅ PJSIP 重新链接（时间戳 08:59）
4. ✅ 硬件编码器已启用（h264_rkmpp）
5. ✅ STDERR-DIAG-9 输出（使用 fflush）
6. ❌ DIAG-1 未输出（av_log 缓冲）
7. ✅ 立即崩溃（exit code 139）

**逻辑推理**：
- 如果 rkmpp_encode_close() 没有被调用 → 不可能，因为 avcodec_free_context() 会调用 close()
- 如果崩溃在 close() 之前 → 不太可能，avcodec_free_context() 是稳定函数
- 如果日志被过滤 → 不太可能，其他 av_log() 正常输出
- **如果日志缓冲未 flush → 最合理解释** ⭐

## 🔧 Fix 100.83 解决方案

### 核心策略

**使用 fprintf(stderr) + fflush(stderr) 替换 av_log()**

**原理**：
- fprintf(stderr) 直接写入 stderr
- fflush(stderr) 立即刷新缓冲
- 保证崩溃前日志已输出

### 修改方案

#### 修改 1：rkmpp_encode_close() 函数

**文件**：`cross-compile/src/ffmpeg-rockchip-6.0/libavcodec/rkmppenc.c`
**位置**：Line 1124-1180

**替换所有 av_log() 为 fprintf(stderr)**：

```c
static av_cold int rkmpp_encode_close(AVCodecContext *avctx)
{
    RKMPPEncContext *r = avctx->priv_data;

    // ✅ 2026-01-13 09:50 [FIX 100.83] 使用 stderr 直接输出（避免缓冲丢失）
    // 原因：av_log() 缓冲在崩溃时未 flush，导致 Fix 100.81 日志丢失
    // 解决：使用 fprintf(stderr) + fflush(stderr) 保证立即输出
    // 参考：docs/2026-01-13/05-Fix100.81调试日志未输出根本原因分析.md

    fprintf(stderr, "[FIX 100.83 DIAG-1] rkmpp_encode_close() ENTER\n");
    fprintf(stderr, "   priv_data=%p, cfg_init=%d, async_frames=%d\n",
            r, r->cfg_init, r->async_frames);
    fflush(stderr);  // ⚠️ 关键：立即刷新，保证崩溃前输出

    r->cfg_init = 0;
    r->async_frames = 0;

    // DIAG-2: MPP 配置清理
    fprintf(stderr, "[FIX 100.83 DIAG-2] About to deinit mcfg=%p\n", r->mcfg);
    fflush(stderr);

    if (r->mcfg) {
        mpp_enc_cfg_deinit(r->mcfg);
        r->mcfg = NULL;
        fprintf(stderr, "[FIX 100.83 DIAG-3] mcfg deinit SUCCESS\n");
        fflush(stderr);
    } else {
        fprintf(stderr, "[FIX 100.83 DIAG-3] mcfg is NULL, skipped\n");
        fflush(stderr);
    }

    // DIAG-4: MPP 上下文销毁
    fprintf(stderr, "[FIX 100.83 DIAG-4] About to destroy mpp context (mapi=%p, mctx=%p)\n",
            r->mapi, r->mctx);
    fflush(stderr);

    if (r->mapi) {
        fprintf(stderr, "[FIX 100.83 DIAG-5] Calling mapi->reset()\n");
        fflush(stderr);

        r->mapi->reset(r->mctx);

        fprintf(stderr, "[FIX 100.83 DIAG-6] mapi reset SUCCESS, calling mpp_destroy()\n");
        fflush(stderr);

        mpp_destroy(r->mctx);

        fprintf(stderr, "[FIX 100.83 DIAG-7] mpp_destroy() SUCCESS\n");
        fflush(stderr);

        r->mctx = NULL;
    } else {
        fprintf(stderr, "[FIX 100.83 DIAG-5] mapi is NULL, skipped\n");
        fflush(stderr);
    }

    // DIAG-8: 帧列表清理
    fprintf(stderr, "[FIX 100.83 DIAG-8] About to clear frame list (frame_list=%p)\n",
            r->frame_list);
    fflush(stderr);

    clear_frame_list(&r->frame_list);

    fprintf(stderr, "[FIX 100.83 DIAG-9] clear_frame_list() SUCCESS\n");
    fflush(stderr);

    // DIAG-10: 硬件上下文清理
    fprintf(stderr, "[FIX 100.83 DIAG-10] About to unref hw contexts (hwframe=%p, hwdevice=%p)\n",
            r->hwframe, r->hwdevice);
    fflush(stderr);

    if (r->hwframe) {
        av_buffer_unref(&r->hwframe);
        fprintf(stderr, "[FIX 100.83 DIAG-11] hwframe unref SUCCESS\n");
        fflush(stderr);
    }

    if (r->hwdevice) {
        av_buffer_unref(&r->hwdevice);
        fprintf(stderr, "[FIX 100.83 DIAG-12] hwdevice unref SUCCESS\n");
        fflush(stderr);
    }

    fprintf(stderr, "[FIX 100.83 DIAG-13] rkmpp_encode_close() EXIT SUCCESS\n");
    fflush(stderr);

    return 0;
}
```

#### 修改 2：clear_frame_list() 函数

**位置**：Line 238-300

**同样使用 fprintf(stderr)**：

```c
static void clear_frame_list(MPPEncFrame **list)
{
    int frame_count = 0;
    fprintf(stderr, "[FIX 100.83 DIAG] clear_frame_list() START (list=%p, *list=%p)\n",
            list, list ? *list : NULL);
    fflush(stderr);

    while (*list) {
        MPPEncFrame *frame = NULL;
        MppFrame mpp_frame = NULL;
        MppBuffer mpp_buf = NULL;

        frame_count++;
        fprintf(stderr, "[FIX 100.83 DIAG] Clearing frame #%d (frame=%p)\n",
                frame_count, *list);
        fflush(stderr);

        frame = *list;
        *list = (*list)->next;

        // MPP frame 清理
        fprintf(stderr, "[FIX 100.83 DIAG]   mpp_frame=%p\n", frame->mpp_frame);
        fflush(stderr);

        mpp_frame = frame->mpp_frame;
        if (mpp_frame) {
            mpp_buf = mpp_frame_get_buffer(mpp_frame);
            fprintf(stderr, "[FIX 100.83 DIAG]   mpp_buf=%p\n", mpp_buf);
            fflush(stderr);

            if (mpp_buf && mpp_buffer_get_index(mpp_buf) >= 0) {
                fprintf(stderr, "[FIX 100.83 DIAG]   About to mpp_buffer_put()\n");
                fflush(stderr);

                mpp_buffer_put(mpp_buf);

                fprintf(stderr, "[FIX 100.83 DIAG]   mpp_buffer_put() SUCCESS\n");
                fflush(stderr);
            }

            fprintf(stderr, "[FIX 100.83 DIAG]   About to mpp_frame_deinit()\n");
            fflush(stderr);

            mpp_frame_deinit(&frame->mpp_frame);

            fprintf(stderr, "[FIX 100.83 DIAG]   mpp_frame_deinit() SUCCESS\n");
            fflush(stderr);

            frame->mpp_frame = NULL;
        }

        // SEI set 清理
        fprintf(stderr, "[FIX 100.83 DIAG]   About to free SEI set (datas=%p)\n",
                frame->mpp_sei_set.datas);
        fflush(stderr);

        av_freep(&frame->mpp_sei_set.datas);
        frame->mpp_sei_set.count = 0;

        fprintf(stderr, "[FIX 100.83 DIAG]   SEI set freed\n");
        fflush(stderr);

        // AVFrame 清理
        fprintf(stderr, "[FIX 100.83 DIAG]   About to av_frame_free() (frame->frame=%p)\n",
                frame->frame);
        fflush(stderr);

        av_frame_free(&frame->frame);

        fprintf(stderr, "[FIX 100.83 DIAG]   av_frame_free() SUCCESS\n");
        fflush(stderr);

        // MPPEncFrame 清理
        fprintf(stderr, "[FIX 100.83 DIAG]   About to free MPPEncFrame (frame=%p)\n", frame);
        fflush(stderr);

        av_freep(&frame);

        fprintf(stderr, "[FIX 100.83 DIAG]   MPPEncFrame freed\n");
        fflush(stderr);
    }

    fprintf(stderr, "[FIX 100.83 DIAG] clear_frame_list() END (cleared %d frames)\n",
            frame_count);
    fflush(stderr);
}
```

## 📝 关键改进

### Fix 100.81 vs Fix 100.83

| 特性 | Fix 100.81 | Fix 100.83 |
|------|-----------|-----------|
| 日志函数 | `av_log(avctx, AV_LOG_ERROR, ...)` | `fprintf(stderr, ...)` |
| 缓冲机制 | FFmpeg 内部缓冲 | 直接写入 stderr |
| 刷新策略 | 自动刷新（不可靠） | `fflush(stderr)` 强制刷新 |
| 崩溃安全 | ❌ 缓冲丢失 | ✅ 立即输出 |
| 日志标识 | `[FIX 100.81 DIAG-X]` | `[FIX 100.83 DIAG-X]` |

### 技术对比

**av_log() 工作原理**：
```c
av_log(avctx, AV_LOG_ERROR, "message\n");
  → 写入 FFmpeg 内部缓冲
  → 等待缓冲满或程序退出时 flush
  → 崩溃时缓冲丢失 ❌
```

**fprintf(stderr) + fflush(stderr) 工作原理**：
```c
fprintf(stderr, "message\n");  // 写入 libc 缓冲
fflush(stderr);                // 立即写入内核缓冲 → 文件/终端
  → 即使程序崩溃，日志已在内核中 ✅
```

## 💡 技术启示

### 关键经验

1. **调试崩溃场景必须使用 fflush**
   - av_log() 适合常规日志
   - fprintf(stderr) + fflush(stderr) 适合崩溃调试

2. **验证链条要完整**
   - ✅ 源码修改
   - ✅ 编译成功
   - ✅ 链接正确
   - ❌ 日志输出 ← 这一步也要验证！

3. **日志缓冲是常见陷阱**
   - 程序正常退出 → 缓冲自动 flush
   - 程序崩溃 → 缓冲丢失
   - 调试崩溃必须手动 fflush
