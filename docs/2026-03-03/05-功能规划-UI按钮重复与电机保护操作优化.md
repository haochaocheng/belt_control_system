## 零、关键 BUG：键盘导航无法触发 SwitchInputPage 底部按钮

> **2026-03-03 代码核查补充**：经精确阅读代码，发现一个根本性 BUG，优先于其他问题修复。

### 0.1 现象

用户反映键盘导航在"开关量输入"界面实际使用的是底部的保存/删除/重置按钮（鼠标/触摸点击），而非顶部按钮。但键盘导航（方向键+确认键）能否正确触发底部按钮存疑。

### 0.2 根因：focusSubArea 值不一致

**DeviceSettingsDialog.qml（第 1655-1806 行）** 对确认键的路由逻辑基于 `focusSubArea` 值：

```javascript
// DeviceSettingsDialog.qml 第 1655 行注释：
// MotorControlPage 的 focusSubArea 定义：0=列表, 1=Tab, 2=参数, 3=按钮
if (currentPage.focusSubArea === 2) {
    // → 触发 triggerParamInput()（弹出虚拟键盘）← ⚠️ SwitchInputPage 的按钮区也是 2！
}
} else if (currentPage.focusSubArea === 3) {
    // → 触发 triggerButton()（底部按钮）
}
```

**各页面的 focusSubArea 定义对比：**

| 页面文件 | focusSubArea=0 | focusSubArea=1 | focusSubArea=2 | focusSubArea=3 |
|---------|---------------|---------------|---------------|---------------|
| **MotorControlPage** | 列表 | Tab | 参数 | **按钮** ✅ |
| **SwitchInputPage** | 列表 | 参数 | **按钮** ❌ | 不存在 |
| **AnalogInputPage** | 列表 | 参数 | **按钮** ❌ | 不存在 |

```
// SwitchInputPage.qml 第 39 行
property int focusSubArea: 0  // 0:列表区域 1:参数区域 2:底部按钮区域
```

### 0.3 Bug 影响

```
键盘用户在 SwitchInputPage 中：
  焦点进入底部按钮区 → focusSubArea = 2
  按 Enter 键 →
    DeviceSettingsDialog 看到 focusSubArea === 2 →
    调用 triggerParamInput()（弹出虚拟键盘）← 错误！

  底部按钮（保存/删除/重置）永远无法通过键盘 Enter 触发

唯一能触发底部按钮的方式：鼠标/触摸点击（不走键盘路由）
```

### 0.4 修复方案（最小改动）

**选项 A（推荐）：修改 SwitchInputPage 和 AnalogInputPage，将底部按钮区改为 `focusSubArea = 3`**

```qml
// SwitchInputPage.qml 第 39 行 修改
// 旧：property int focusSubArea: 0  // 0:列表区域 1:参数区域 2:底部按钮区域
// 新：property int focusSubArea: 0  // 0:列表区域 1:参数区域 3:底部按钮区域（与MotorControlPage一致）
```

同时修改所有使用 `focusSubArea === 2` 判断按钮区的代码，改为 `=== 3`。

修改文件：
- `SwitchInputPage.qml`：`focusSubArea` 注释更新 + 所有 `focusSubArea === 2`（按钮判断）改为 `=== 3`
- `AnalogInputPage.qml`：同上

**修改范围（SwitchInputPage.qml 主要涉及行）：**

| 涉及位置 | 修改内容 |
|---------|---------|
| 第 39 行：属性注释 | `2:底部按钮区域` → `3:底部按钮区域` |
| 所有按钮背景 color 判断 | `root.focusSubArea === 2` → `root.focusSubArea === 3` |
| 下方向键导航到按钮区 | 设置 `focusSubArea = 2` → 改为 `focusSubArea = 3` |

> ⚠️ 注意：修改前需确认 SwitchInputPage 中所有使用 `focusSubArea === 2` 的地方，区分"参数区判断"和"按钮区判断"，只改"按钮区"的。

## 二、问题 1：开关量输入 - 顶部/底部保存按钮重复

### 2.1 现状

**DeviceSettingsDialog.qml 顶部**（3 个按钮）：

| 按钮 | 实现状态 | 代码位置 |
|------|---------|---------|
| 关闭 | ✅ 已实现 | `triggerTopButton(0)` → `modalContainer.visible = false` |
| 保存 | ❌ 未实现（stub） | `triggerTopButton(1)` → `// 保存逻辑（待实现）` |
| 重置 | ❌ 未实现（stub） | `triggerTopButton(2)` → `// 重置逻辑（待实现）` |

**SwitchInputPage.qml 底部**（5 个按钮，两行）：

| 行 | 按钮 | 实现状态 | 调用函数 |
|----|------|---------|---------|
| 第一行 | 添加输入 | ❌ 未实现（TODO） | — |
| 第一行 | 删除输入 | ❌ 未实现（TODO） | — |
| 第二行 | **保存** | **✅ 已实现** | `saveProtectionData()` → SQLite |
| 第二行 | 删除 | ❌ 未实现（TODO） | — |
| 第二行 | 重置 | ✅ 已实现 | `loadProtectionData(index)` |

### 2.2 问题分析

```
用户看到两个"保存"：
  顶部保存 ← 键盘导航默认先到这里（currentFocusArea=0），但实际无效！
  底部保存 ← 唯一真正有效的保存按钮

结果：
  1. 键盘用户按确认键 → 触发顶部"保存" → 无任何操作，参数未保存
  2. 触摸/鼠标用户：不确定该点哪个"保存"
  3. 界面显得杂乱，违反"单一操作点"原则
```

### 2.3 修复方案

**方案：实现顶部保存/重置 + 移除底部重复按钮**

```
修改 DeviceSettingsDialog.qml:
  triggerTopButton(1) → 获取当前页面引用，调用页面的 save() 方法
  triggerTopButton(2) → 调用页面的 reset() 方法

修改 SwitchInputPage.qml:
  保留底部第一行：添加输入 | 删除输入（页面专属操作，保留）
  移除底部第二行：保存 | 删除 | 重置 → 保存/重置由顶部统一处理
  "删除" 按钮保留，但改放入第一行末尾，并重命名为"删除保护项"
```

**修改后底部按钮布局（SwitchInputPage）：**
```
第一行（RowLayout）：
  [添加输入]  [删除输入]  [删除保护项]
```

**修改 DeviceSettingsDialog.qml 中的 `triggerTopButton()`：**
```qml
case 1:  // 保存
    var currentPage = getCurrentPage(currentCategory)
    if (currentPage && typeof currentPage.saveProtectionData === "function") {
        currentPage.saveProtectionData()
    } else if (currentPage && typeof currentPage.saveMotorConfig === "function") {
        currentPage.saveMotorConfig()
    }
    break
case 2:  // 重置
    var currentPage = getCurrentPage(currentCategory)
    if (currentPage && typeof currentPage.loadProtectionData === "function") {
        currentPage.loadProtectionData(currentPage.currentProtectionIndex)
    }
    break
```

**各页面需暴露统一接口（建议）：**
```qml
// 每个页面添加统一函数：
function saveCurrentPage() { saveProtectionData() }
function resetCurrentPage() { loadProtectionData(currentProtectionIndex) }
```

## 三、问题 2：模拟量输入 - 按钮重复 + 缺少添加/删除功能

### 3.1 现状

**AnalogInputPage.qml 底部**（3 个按钮，单行）：

| 按钮 | 实现状态 |
|------|---------|
| 保存 | ✅ 已实现 → `saveProtectionData()` |
| 删除 | ❌ 未实现（TODO） |
| 重置 | ✅ 已实现 → `loadProtectionData(index)` |

缺少：**添加输入 / 删除输入** 按钮（SwitchInputPage 有，AnalogInputPage 没有）

### 3.2 问题分析

```
问题一：同 2.2，顶部保存未实现，底部保存是唯一有效保存
问题二：模拟量输入界面缺少"添加输入"和"删除输入"功能按钮
        而开关量输入界面已有这两个按钮（虽然未实现）
```

### 3.3 修复方案

**修改 AnalogInputPage.qml：**
```
移除底部：保存 | （重置）
保留底部：删除（重命名为"删除保护项"）
新增底部：添加输入 | 删除输入（参考 SwitchInputPage 的 addInputButton / deleteInputButton 样式）
```

**修改后底部按钮布局（AnalogInputPage）：**
```
第一行（RowLayout）：
  [添加输入]  [删除输入]  [删除保护项]
```

**添加输入/删除输入的含义（需与业务确认）：**
- "添加输入"：为当前保护项新增一个模拟量输入通道配置
- "删除输入"：删除当前选中的模拟量输入通道配置

## 四、问题 3：电机控制 - 按钮标签错误 + 缺少确认框

### 4.1 现状

**MotorControlPage.qml 底部**（5 个按钮，两行）：

| 行 | 按钮 | 当前文本 | 实现状态 |
|----|------|---------|---------|
| 第一行 | addInputButton | **"添加输入"** | ❌ 未实现（TODO） |
| 第一行 | deleteInputButton | **"删除输入"** | ❌ 未实现（TODO） |
| 第二行 | saveButton | "保存" | ✅ 已实现 → `saveMotorConfig()` |
| 第二行 | deleteButton | "删除" | ❌ 未实现（TODO） |
| 第二行 | resetButton | "重置" | ❌ 未实现（TODO） |

### 4.2 问题分析

```
问题一：按钮文本错误
  "添加输入" / "删除输入" → 文本复制自 SwitchInputPage，未针对电机控制场景修改
  在电机控制界面，操作对象是"电机保护标签页"（Tab），而非"输入通道"

问题二：无删除确认框
  删除电机保护 Tab 是破坏性操作，若无确认框容易误触
  规范：删除操作必须弹出确认对话框，防止误删

问题三：同 2.2，顶部保存/重置是 stub，底部保存才有效
```

### 4.3 修复方案

**Step 1：修改按钮文本**

```qml
// 修改前
text: "添加输入"
text: "删除输入"

// 修改后
text: "添加电机保护"
text: "删除电机保护"
```

**Step 2：实现"添加电机保护"逻辑**

```
行为：在 TabBar 末尾新增一个空白标签页（Tab）
  - 新 Tab 标题：自动命名（如"电机保护 N"）或弹出命名对话框
  - 新 Tab 内容：使用默认空白配置预填参数
  - 切换到新 Tab
```

**Step 3：实现"删除电机保护"逻辑（带确认框）**

```qml
Button {
    text: "删除电机保护"
    onClicked: {
        deleteConfirmDialog.targetTabIndex = tabBar.currentIndex
        deleteConfirmDialog.open()
    }
}

Dialog {
    id: deleteConfirmDialog
    title: "确认删除"
    property int targetTabIndex: -1

    // 内容
    Text {
        text: "确认删除当前电机保护配置（\"" + tabBar.currentTab.title + "\"）？\n此操作不可撤销。"
    }

    // 按钮
    standardButtons: Dialog.Ok | Dialog.Cancel

    onAccepted: {
        // 执行删除
        motorController.deleteProtectionTab(targetTabIndex)
        tabBar.currentIndex = Math.max(0, targetTabIndex - 1)
    }
}
```

**修改后底部按钮布局（MotorControlPage）：**
```
第一行（RowLayout）：
  [添加电机保护]  [删除电机保护（带确认框）]

第二行（RowLayout）：
  移除 保存/重置（由顶部统一处理），仅保留"删除"（若指删除整台电机则保留）
```

## 五、三个问题的统一修改计划

### 5.1 统一原则（修改完成后的按钮规范）

```
顶部（DeviceSettingsDialog）：
  关闭  |  保存（→代理到当前页的保存函数）  |  重置（→代理到当前页的重置函数）

底部（各页面）：
  仅放置页面专属操作：
    - SwitchInputPage：添加输入 | 删除输入 | 删除保护项
    - AnalogInputPage：添加输入 | 删除输入 | 删除保护项
    - MotorControlPage：添加电机保护 | 删除电机保护（确认框）
```

### 5.2 修改文件清单

| 文件 | 修改内容 |
|------|---------|
| `DeviceSettingsDialog.qml` | 实现 `triggerTopButton(1)` 保存 和 `triggerTopButton(2)` 重置，代理到 `getCurrentPage()` |
| `SwitchInputPage.qml` | 移除底部"保存/重置"按钮，保留"添加输入/删除输入"，新增"删除保护项" |
| `AnalogInputPage.qml` | 移除底部"保存/重置"按钮，新增"添加输入/删除输入"，保留"删除保护项" |
| `MotorControlPage.qml` | 修改"添加输入"→"添加电机保护"，"删除输入"→"删除电机保护"（加确认框），移除底部"保存/重置" |

### 5.3 实施顺序建议

```
Step 1：先实现 DeviceSettingsDialog 顶部保存/重置代理（最先完成，消除"顶部保存无效"的问题）
Step 2：修改各页面底部按钮布局（移除重复的保存/重置）
Step 3：修改 MotorControlPage 按钮标签 + 实现确认框
Step 4：实现添加/删除输入功能（业务逻辑层面，需与后端确认）
```
