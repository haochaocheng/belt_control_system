## 一、当前状态

### 1.1 模块固件（/root/mqtt_io_publisher.py，已确认）

| 参数 | 当前值 | 问题 |
|------|--------|------|
| Client ID | `luckfox-io-module` | 唯一，可用于 EMQX API 查询 |
| DI 发送频率 | 100ms 定时器 | 每秒 10 次，无变化也发送，占用带宽 |
| AI 发送频率 | 500ms 定时器 | 每秒 2 次，无变化也发送，占用带宽 |
| EMQX 地址 | 192.168.10.142:1883 | 固定配置 |
| DI 引脚 | GPIO 68-75（8位） | 8个开关量通道 |
| AI 通道 | ADC 0-4（5通道） | 5个模拟量通道 |

### 1.2 问题分析

**问题1 - 数据频率过高**：
- DI 100ms 定时器：即使数字量无任何变化，每秒发 10 条消息
- AI 500ms 定时器：即使模拟量无变化，每秒发 2 条消息
- 8台模块共计：DI 80条/秒 + AI 16条/秒 = 96条/秒，大量冗余

**问题2 - 无法区分"模块离线"和"IO故障"**：
- 当前：只有"数据超时"（`m_dataTimeoutThreshold` 秒内未收到数据）
- 无法区分：(A) 模块网络断开 vs (B) 模块在线但IO端口故障（始终一个状态）
- 例如：开关量 8 路全0 → 可能是保护被触发，也可能是模块通信中断

## 二、优化方案

### 2.1 DI 传输优化：变化触发 + 心跳

**原理**：仅当数字量状态变化时立即发送；无变化时每1秒发送一次心跳确认

```python
# 修改后的逻辑（伪代码）
last_di_state = None
heartbeat_interval = 1000  # 1秒心跳

def on_di_timer():  # 仍用100ms检查变化，但只在变化时发送
    current = read_gpio()
    if current != last_di_state:
        publish(current)  # 立即发送变化
        last_di_state = current

def on_heartbeat_timer():  # 1秒定时器
    publish(last_di_state)  # 定期心跳，无论是否变化
```

**效果**：
- 有事件时：≤100ms 延迟（实时性保持）
- 无事件时：1条/秒（占用减少90%）

### 2.2 AI 传输优化：阈值变化触发 + 心跳

**原理**：当模拟量变化超过阈值时立即发送；无显著变化时每2秒发送一次心跳

```python
# 阈值建议
AI_THRESHOLD = 0.05  # 5%变化才发送（可配置）
heartbeat_interval = 2000  # 2秒心跳

def check_ai_change():
    for ch in range(5):
        if abs(current[ch] - last[ch]) > AI_THRESHOLD:
            publish()  # 有显著变化立即发送
            break
```

**效果**：
- 传送带速度稳定时：2条/秒（从2条/秒降至更低）
- 速度快速变化时：及时响应

### 2.3 EMQX REST API 查询模块连接状态

**目的**：独立于数据流，直接向 EMQX Broker 查询模块的 TCP 连接状态

**API 调用**：
```
GET http://192.168.10.142:18083/api/v5/clients/luckfox-io-module
Authorization: Basic <base64(admin:password)>
```

**返回判断**：
- HTTP 200 + `connected: true` → 模块网络在线（但可能IO故障）
- HTTP 200 + `connected: false` → 模块曾连接过，当前已断开
- HTTP 404 → 模块从未连接过，或长期离线后被清除

**区分逻辑**：

```
┌─────────────────────────────────────────────────────────────┐
│  EMQX API: connected = true + 数据超时                      │
│  → 判断：模块 MQTT 连接正常，但IO端口数据异常（传感器故障）  │
│  语音提示："X号通道传感器故障，请检查传感器连接"            │
├─────────────────────────────────────────────────────────────┤
│  EMQX API: connected = false + 数据超时                     │
│  → 判断：模块网络断开（断电/断网/设备故障）                 │
│  语音提示："开关量模块一离线，请检查设备连接"               │
├─────────────────────────────────────────────────────────────┤
│  EMQX API 请求失败（EMQX 本身不可达）                       │
│  → 判断：EMQX Broker 断开（网络问题）                       │
│  语音提示："连接MQTT服务器失败，请检查网络连接"             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 阶段A详细实现

**新增类：MQTTStatusChecker**（或集成到 MQTTAutoManager）

```cpp
// 调用 EMQX REST API，返回 clientId 是否在线

struct ModuleOnlineStatus {
    bool emqxReachable;    // EMQX 本身是否可达
    bool clientConnected;  // 客户端 MQTT 连接是否在线
};

void MQTTAutoManager::checkModuleOnlineStatus(int moduleIndex);
// → 异步结果通过信号回调：void onModuleStatusChecked(int moduleIndex, ModuleOnlineStatus status)
```

## 五、注意事项

1. **EMQX API 认证**：需要配置 EMQX 管理员密码，存储在系统配置中（不硬编码）
2. **查询频率**：仅在"数据超时"事件触发时查询一次，不定时轮询（避免 API 压力）
3. **去重逻辑**：同一模块"离线"语音 5 分钟内只播放一次，恢复后重置
4. **模块固件修改**：需要 SSH 登录设备 `192.168.10.154`（root，无密码）修改 Python 脚本
5. **向后兼容**：固件修改后，现有"数据超时"检测逻辑仍然有效（心跳间隔内超时 = 离线）
