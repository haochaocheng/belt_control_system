# 功能规划：参数修改未保存离开提示

**日期**: 2026-03-03
**状态**: 规划中（待实施）
**优先级**: 中（用户体验改善）

---

## 一、问题描述

用户在保护参数设置界面修改参数后，未点击"保存"按钮直接：
- 切换到其他分类页（DeviceSettingsDialog 的 category 切换）
- 滑动/切换到其他顶级页面（App.qml 的 SwipeView 切换）
- 切换选中的保护项（从"急停"切换到"跑偏"）

所有修改**静默丢失**，没有任何提示。

---

## 二、现状分析

### 2.1 保存模式分类

通过代码分析，当前各参数界面的保存模式如下：

| 界面 | 保存模式 | 说明 | 需要警告 |
|------|---------|------|---------|
| `SwitchInputPage.qml` | **手动保存** | 需点击"保存"按钮 → `saveProtectionData()` → SQLite | ✅ 是 |
| `ParameterSettings.qml` | **手动保存** | 需点击"保存设置"按钮 → `systemConfig.saveConfig()` | ✅ 是 |
| `CurrentProtectionTab.qml` | 实时保存 | `onValueModified` 即时写入后端 | ❌ 否 |
| `timeoutSpin`（数据超时） | 实时保存 | `onValueModified` → `mqttAutoManager.setDataTimeoutThreshold()` | ❌ 否 |
| `brokerTimeoutSpin`（连接超时） | 实时保存 | `onValueModified` → `mqttAutoManager.setBrokerConnectTimeout()` | ❌ 否 |

**本次规划只针对 `SwitchInputPage.qml` 和 `ParameterSettings.qml`。**

### 2.2 页面结构与拦截点

## 三、功能设计

### 3.1 未保存状态检测

在 `SwitchInputPage.qml` 添加 `hasUnsavedChanges` 属性：

```qml
// 开关量保护参数页面
property bool hasUnsavedChanges: false

// 每个字段修改时设置标志（以保护名称字段为例）
TextField {
    onTextChanged: {
        if (!_isLoadingData) root.hasUnsavedChanges = true
    }
}

// 成功保存后清除标志
function saveProtectionData() {
    // ... 现有保存逻辑 ...
    root.hasUnsavedChanges = false
}

// 加载新保护项时清除标志（并在加载期间屏蔽字段变化触发）
property bool _isLoadingData: false
function loadProtectionData(index) {
    _isLoadingData = true
    // ... 现有加载逻辑 ...
    _isLoadingData = false
    hasUnsavedChanges = false
}
```

在 `ParameterSettings.qml` 同样添加 `hasUnsavedChanges` 属性。

### 3.2 警告弹窗

统一弹窗内容（在两个页面内各自定义一个 Dialog）：

```
┌─────────────────────────────────────┐
│  ⚠️  参数已修改                       │
│                                     │
│  当前保护项的参数已修改，              │
│  但尚未保存。                         │
│                                     │
│  离开后修改将会丢失。                  │
│                                     │
│  [ 保存并离开 ]  [ 放弃修改 ]  [ 取消 ] │
└─────────────────────────────────────┘
```

**三个按钮的行为：**

| 按钮 | 行为 |
|------|------|
| **保存并离开** | 调用 `saveProtectionData()`，然后执行原来的导航动作 |
| **放弃修改** | 不保存，直接执行原来的导航动作，`hasUnsavedChanges = false` |
| **取消** | 关闭弹窗，停留在当前页面，不做任何操作 |

### 3.3 拦截逻辑伪代码

#### 拦截点 A：DeviceSettingsDialog 切换 Category

```qml
// DeviceSettingsDialog.qml
onCurrentCategoryChanged: {
    var switchPage = getSwitchInputPage()
    if (switchPage && switchPage.hasUnsavedChanges) {
        // 先保存目标 category，弹窗确认后再切换
        pendingCategory = newCategory
        unsavedWarningDialog.open()
        return  // 阻止立即切换
    }
    // 正常切换
    doSwitchCategory(newCategory)
}
```

#### 拦截点 B：DeviceSettingsDialog 关闭

```qml
onClosing: function(close) {
    var switchPage = getSwitchInputPage()
    if (switchPage && switchPage.hasUnsavedChanges) {
        close.accepted = false  // 阻止关闭
        pendingAction = "close"
        unsavedWarningDialog.open()
    }
}
```

#### 拦截点 C：SwipeView 切换顶级页面

```qml
// App.qml
SwipeView {
    onCurrentIndexChanged: {
        // 从 ParameterSettings 离开时（页面索引 2）
        if (previousIndex === 2 && parameterSettings.hasUnsavedChanges) {
            currentIndex = previousIndex  // 立刻回滚
            parameterSettings.showUnsavedWarning(targetIndex)
        }
    }
}
```

#### 拦截点 D：切换保护项

```qml
// SwitchInputPage.qml
onCurrentProtectionIndexChanged: {
    if (hasUnsavedChanges && !_isLoadingData) {
        pendingProtectionIndex = newIndex
        // 回滚选中项索引
        currentProtectionIndex = oldIndex
        unsavedWarningDialog.open()
    }
}
```

## 五、关键技术问题

### 5.1 如何获取 SwitchInputPage 引用

`DeviceSettingsDialog` 通过 `Loader`/`SwipeView` 动态加载各 Category 页面。需要：
- 用 `objectName` 标记 SwitchInputPage 实例
- 或通过信号向上传递 `hasUnsavedChanges` 状态（推荐）

**推荐方案**：在 `DeviceSettingsDialog` 中添加属性：
```qml
property bool hasSwitchPageUnsavedChanges: false
// SwitchInputPage 通过 Binding 或 onHasUnsavedChangesChanged 信号通知上层
```

### 5.2 拦截 QML SwipeView 切换的时序

QML 的 `onCurrentIndexChanged` 是变化后才触发，**无法真正阻止**切换。解决方案：
- 变化后立即回滚（`currentIndex = previousIndex`），再弹窗
- 弹窗确认后再切换（`currentIndex = pendingIndex`）
- 回滚动作要用 `Qt.callLater` 避免与 QML 引擎绑定冲突

### 5.3 加载数据时屏蔽字段触发

加载保护项数据时会批量设置各字段值，如果不屏蔽，会误触发 `hasUnsavedChanges = true`。
用 `_isLoadingData` 标志在 `onTextChanged` / `onValueModified` 中加守卫：
```qml
onValueModified: {
    if (!_isLoadingData) hasUnsavedChanges = true
}
```

### 5.4 ParameterSettings 与 SwipeView 的交互

`ParameterSettings` 在 SwipeView 页面 2，用户可以向左/向右滑动或按方向键切换。
需要在滑动开始时（`onCurrentIndexChanged` 已变化后立即回滚）而非滑动结束时拦截。

## 六、范围界定（不做的事情）

| 不实施 | 原因 |
|--------|------|
| CurrentProtectionTab 离开提示 | 实时保存，无需提示 |
| timeoutSpin/brokerTimeoutSpin 离开提示 | 实时保存，无需提示 |
| 自动保存（Auto Save） | 用户未确认的参数自动生效可能造成意外行为 |
| 跨页面全局 hasUnsavedChanges | 当前只有两个手动保存页面，不需要全局状态管理 |
