# 修复 81 - 调整初始化顺序解决 DRM 冲突

**日期**: 2026-01-08 14:20
**状态**: 🚧 测试中

---

## 🎯 问题回顾

### Fix 80 的问题

**现象**：
```
✅ [FIX 80] RKMPP hwdevice created (DRM render node)  ← 成功
✅ Decoder configured                                  ← 成功
💥 Application exited with code: 139                   ← 崩溃（1ms后）
```

**分析**：
- DRM render node (`/dev/dri/renderD128`) 创建成功
- 但 `avcodec_open2(dec_ctx)` 仍然崩溃（SIGSEGV）
- Fix 80 的隔离策略（`enc_ctx->hw_device_ctx = NULL`）无效

---

## 💡 根本原因假设

### 初始化顺序问题

**原流程**（错误）：
```c
Line 2242: avcodec_open2(enc_ctx, enc, NULL);  // ①先：libx264
           ↓
           内部可能做了硬件检测，占用了某些资源

Line 2461: avcodec_open2(dec_ctx, dec, NULL);  // ②后：RKMPP
           ↓
           💥 崩溃（资源冲突）
```

**推理**：
1. libx264 虽然是软件编码器，但可能在初始化时检测硬件能力
2. 检测过程中尝试访问 `/dev/dri/card0`（DRM master）
3. RKMPP 后续初始化时，发现资源被占用
4. 导致崩溃

---

## 🔧 Fix 81 解决方案

### 核心策略

**让硬件解码器先占用 DRM 资源，软件编码器后初始化不会干扰**

### 新初始化顺序

```c
#ifdef USE_HARDWARE_DECODER
    // STEP 1: 先打开硬件解码器（RKMPP）
    PJ_LOG(1, "✅ [FIX 81] STEP 1: Opening HARDWARE decoder FIRST");
    avcodec_open2(dec_ctx, dec, NULL);  // ① RKMPP 先占用 DRM
#endif

    // STEP 2: 然后打开编码器
    PJ_LOG(1, "✅ [FIX 81] STEP 2: Opening encoder AFTER decoder");
    avcodec_open2(enc_ctx, enc, NULL);  // ② libx264 后初始化

#ifndef USE_HARDWARE_DECODER
    // STEP 3: 软件解码器打开（只在非硬件解码时）
    PJ_LOG(1, "✅ [FIX 81] STEP 3: Opening SOFTWARE decoder");
    avcodec_open2(dec_ctx, dec, NULL);  // ③ 软件解码
#endif
```

## 📝 代码修改

### 文件 1: ffmpeg_vid_codecs.c (Line 2183-2214)

```c
/* ✅ 2026-01-08 13:45 [修复 81] 调整初始化顺序：硬件解码时先打开解码器
 * 问题：Fix 80 DRM render node 创建成功，但 avcodec_open2(dec_ctx) 仍然崩溃
 * 原因：编码器（libx264）先初始化，可能做了硬件检测占用了资源
 * 策略：让 RKMPP 解码器先占用 DRM render node，然后 libx264 再初始化
 */
#ifdef USE_HARDWARE_DECODER
    /* STEP 1: 先打开硬件解码器（RKMPP）*/
    if (ff->param->dir & PJMEDIA_DIR_DECODING) {
        int dec_err = 0;

        PJ_LOG(1,(THIS_FILE, "✅ [FIX 81] STEP 1: Opening HARDWARE decoder FIRST (before encoder)"));
        PJ_LOG(1,(THIS_FILE, "   Decoder: %s", ff->dec->name));
        PJ_LOG(1,(THIS_FILE, "   RKMPP hwdevice: %p", ff->dec_ctx->hw_device_ctx));
        PJ_LOG(1,(THIS_FILE, "   Strategy: Let RKMPP occupy DRM render node first"));

        dec_err = avcodec_open2(ff->dec_ctx, ff->dec, NULL);

        if (dec_err < 0) {
            char errbuf[128];
            av_strerror(dec_err, errbuf, sizeof(errbuf));
            PJ_LOG(1,(THIS_FILE, "❌ [FIX 81] Decoder avcodec_open2() failed: %d (%s)", dec_err, errbuf));
            print_ffmpeg_err(dec_err);
            status = PJMEDIA_CODEC_EFAILED;
            goto on_error;
        }

        dec_opened = PJ_TRUE;
        PJ_LOG(1,(THIS_FILE, "✅ [FIX 81] STEP 1 SUCCESS: Decoder opened successfully"));
        PJ_LOG(1,(THIS_FILE, "   Decoder output format: %d", ff->dec_ctx->pix_fmt));
        PJ_LOG(1,(THIS_FILE, "   Decoder dimensions: %dx%d", ff->dec_ctx->width, ff->dec_ctx->height));
    }
#endif
```

            goto on_error;
        }

        dec_opened = PJ_TRUE;

        PJ_LOG(1,(THIS_FILE, "   Decoder output format: %d", ff->dec_ctx->pix_fmt));

## 🔍 自动GDB调试系统

### 目的

程序崩溃时自动生成完整堆栈信息，无需手动GDB操作。

### 实现

#### 1. GDB包装脚本 (docker/rk3588/gdb-wrapper.sh)

```bash
#!/bin/bash
# 使用 GDB 运行程序，崩溃时自动生成完整堆栈信息

# 创建GDB命令文件
cat > /tmp/gdb_commands.txt <<'EOF'
run

# 如果崩溃，自动打印堆栈
echo 💥 [FIX 81] APPLICATION CRASHED!\n

# 打印完整堆栈（所有线程）
thread apply all bt full

# 打印崩溃位置
frame 0
info registers

# 打印变量
info locals

# 打印共享库
info sharedlibrary

quit
EOF

# 使用GDB运行（批处理模式）
gdb -batch -x /tmp/gdb_commands.txt /app/belt_control_system

# 保存退出码
EXIT_CODE=$?

# 如果崩溃（139 = SIGSEGV），保持容器运行以便查看日志
if [ $EXIT_CODE -eq 139 ]; then
    echo "💥 [FIX 81] SIGSEGV detected! Container will sleep for 10 minutes..."
    sleep 600
fi

exit $EXIT_CODE
```

#### 2. Dockerfile修改

```dockerfile
# 安装GDB
RUN apt-get update && apt-get install -y gdb && rm -rf /var/lib/apt/lists/* && \
    chmod +x /app/gdb-wrapper.sh

# 复制GDB包装脚本
COPY docker/rk3588/gdb-wrapper.sh /app/gdb-wrapper.sh

# 使用GDB包装脚本启动
CMD ["/app/gdb-wrapper.sh"]
```
