# 修复 81.1 - 移除条件编译解决 Fix 81 未执行问题

## 🎯 问题回顾

### Fix 81 未执行

**日志证据**：
```
✅ [FIX 80] Detected RKMPP decoder: h264_rkmpp  ← Fix 80 执行了
   ✅ RKMPP hwdevice created using DRM render node
Application exited with code: 139                ← 仍然崩溃

❌ 完全没有 [FIX 81] 日志                        ← Fix 81 未执行！
```

### 根本原因

1. **Fix 81 代码存在于源文件** (`ffmpeg_vid_codecs.c` Line 2183-2218)
2. **但被条件编译包裹** (`#ifdef USE_HARDWARE_DECODER`)
3. **宏未在编译时定义**，导致 Fix 81 代码被跳过

**对比**：
- Fix 80 (Line 2075)：**无条件编译** → 总是执行 ✅
- Fix 81 (Line 2189)：**有条件编译** → 被跳过 ❌

---

## 💡 解决方案

### 策略：移除条件编译，改为运行时检测

**核心思路**：
- 不依赖编译时宏定义
- 运行时检测解码器名称是否包含 "rkmpp"
- 根据检测结果动态调整初始化顺序

---

## 🔧 代码修改

### 修改 1: STEP 1 - 硬件解码器优先打开

**文件**: `cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-codec/ffmpeg_vid_codecs.c`
**位置**: Line 2183-2218

**修改前**：
```c
#ifdef USE_HARDWARE_DECODER  // ❌ 条件编译导致代码被跳过
    /* STEP 1: 先打开硬件解码器（RKMPP）*/
    if (ff->param->dir & PJMEDIA_DIR_DECODING) {
        // ... 解码器初始化代码
    }
#endif
```

**修改后**：
```c
/* ✅ 2026-01-08 16:15 [修复 81.1] 移除条件编译，改为运行时检测 */
/* STEP 1: 如果是硬件解码器（RKMPP），先打开解码器 */
if ((ff->param->dir & PJMEDIA_DIR_DECODING) &&
    ff->dec && (pj_ansi_strstr(ff->dec->name, "rkmpp") != NULL))
{
    int dec_err = 0;

    PJ_LOG(1,(THIS_FILE, "✅ [FIX 81] STEP 1: Opening HARDWARE decoder FIRST (before encoder)"));
    PJ_LOG(1,(THIS_FILE, "   Decoder: %s", ff->dec->name));
    PJ_LOG(1,(THIS_FILE, "   RKMPP hwdevice: %p", ff->dec_ctx->hw_device_ctx));
    PJ_LOG(1,(THIS_FILE, "   Strategy: Let RKMPP occupy DRM render node first"));

    dec_err = avcodec_open2(ff->dec_ctx, ff->dec, NULL);
    // ... 错误处理

    dec_opened = PJ_TRUE;  // ← 设置标志位
    PJ_LOG(1,(THIS_FILE, "✅ [FIX 81] STEP 1 SUCCESS: Decoder opened successfully"));
}
```

**关键改进**：
- ✅ 运行时检测：`pj_ansi_strstr(ff->dec->name, "rkmpp")`
- ✅ 设置标志位：`dec_opened = PJ_TRUE`（防止 STEP 3 重复打开）
