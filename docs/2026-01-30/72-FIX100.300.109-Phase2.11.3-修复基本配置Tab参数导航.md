# FIX 100.300.109 Phase 2.11.3 - 修复基本配置Tab参数导航

**日期**: 2026-01-30
**任务编号**: FIX 100.300.109 Phase 2.11.3
**状态**: ✅ 完成

## 🐛 问题描述

### 用户反馈

> 基本配置参数区域在最后一项参数时，需要按三次向下键才切换到底部按钮区，其他的不需要，可以直接切换

### 具体问题

1. **基本配置Tab（Tab 0）**：
   - 在最后一项参数（索引4或5）
   - 按向下键 → 没有切换到按钮区
   - 再按向下键 → 还是没有切换
   - 再按向下键 → 才切换到按钮区
   - **需要按3次向下键** ❌

2. **其他Tab（Tab 1-9）**：
   - 在最后一项参数（索引6、7或8）
   - 按向下键 → 直接切换到按钮区
   - **只需要按1次向下键** ✅

### 对比

| Tab | 参数数量 | 最后参数索引 | 按下键次数 | 状态 |
|-----|---------|------------|-----------|------|
| 基本配置（Tab 0） | 6个（0-5） | 4, 5 | 3次 | ❌ 错误 |
| 其他Tab（Tab 1-9） | 9个（0-8） | 6, 7, 8 | 1次 | ✅ 正确 |

## 🔍 问题分析

### 根本原因

**NavigationManager.qml 硬编码假设所有Tab有9个参数**：

```qml
// ❌ 错误：硬编码假设最后参数索引是7或8
case "Down":
    if (paramIndex <= 5) {
        newIndex = paramIndex + 2
    } else if (paramIndex === 6) {
        newIndex = 8  // 跳转到第5行
    } else if (paramIndex === 7) {
        // 右列最后一个参数，向下进入底部按钮区
        switchToArea(areaButtons)
        return
    } else if (paramIndex === 8) {
        // 左列最后一个参数，向下进入底部按钮区
        switchToArea(areaButtons)
        return
    }
    break
```

**问题**：
1. 假设所有Tab有9个参数（0-8）
2. 只有索引7或8才能进入按钮区
3. 基本配置Tab只有6个参数（0-5）
4. 从索引5按下键 → 索引7（不存在）→ 继续按 → 索引8 → 再按 → 进入按钮区

### 参数数量差异

**基本配置Tab（Tab 0）**：
```
行0：[0] 运行状态    [1] 模块类型
行1：[2] 额定电流    [3] 额定功率
行2：[4] 额定电压    [5] 额定转速
```
- 6个参数（0-5）
- 最后一行：索引4（左列）、5（右列）

**其他Tab（Tab 1-9）**：
```
行0：[0] 是否投入          [1] 报警类型
行1：[2] 动作保护类型      [3] 故障保护类型
行2：[4] 温度上限          [5] 温度下限
行3：[6] 温度下限          [7] 输入点选择
行4：[8] 过滤干扰延时      [ ] 空
```
- 9个参数（0-8）
- 最后一行：索引8（左列，单独一行）
- 倒数第二行：索引6（左列）、7（右列）

## 🔧 修复方案

### 解决方法

**动态跟踪每个Tab的最后一个参数索引**：

1. **添加 lastParamIndex 属性**：
   - 跟踪当前Tab的最后一个参数索引
   - 默认值：8（大多数Tab）

2. **Tab切换时更新 lastParamIndex**：
   - 基本配置（Tab 0）：lastParamIndex = 5
   - 其他Tab（Tab 1-9）：lastParamIndex = 8

3. **参数区向下键逻辑改为动态判断**：
   - 计算下一个索引：nextIndex = paramIndex + 2
   - 如果 nextIndex > lastParamIndex，进入按钮区
   - 否则移动到 nextIndex

### 修复代码

**NavigationManager.qml - 添加 lastParamIndex 属性（Line 22-26）**：

```qml
// ✅ 2026-01-30 [FIX 100.300.109 Phase 2.11.3]: 当前Tab的最后一个参数索引
// 不同Tab有不同的参数数量：
// - 基本配置（Tab 0）：6个参数（0-5），最后索引=5
// - 其他Tab（Tab 1-9）：9个参数（0-8），最后索引=8
property int lastParamIndex: 8  // 默认为8（大多数Tab）
```

**NavigationManager.qml - Tab切换时更新 lastParamIndex（Line 123-134）**：

```qml
if (newIndex !== tabIndex) {
    tabIndex = newIndex
    // ✅ 2026-01-30 [FIX 100.300.109 Phase 2.11.3]: 根据Tab索引更新最后一个参数索引
    // 基本配置（Tab 0）有6个参数（0-5），其他Tab有9个参数（0-8）
    if (newIndex === 0) {
        lastParamIndex = 5  // 基本配置：最后参数索引=5
    } else {
        lastParamIndex = 8  // 其他Tab：最后参数索引=8
    }
    console.log("✅ [NavigationManager] Tab索引:", newIndex, "（参数区自动切换显示）lastParamIndex:", lastParamIndex)
}
```

**NavigationManager.qml - 参数区向下键动态判断（Line 161-178）**：

```qml
case "Down":
    // ✅ 2026-01-30 [FIX 100.300.109 Phase 2.11.3]: 使用 lastParamIndex 判断最后一个参数
    // 向下移动（同列）

    // 计算下一个索引（同列下一行）
    var nextIndex = paramIndex + 2

    // 检查下一个索引是否超出范围
    if (nextIndex > lastParamIndex) {
        // 超出范围，进入底部按钮区
        switchToArea(areaButtons)
        buttonIndex = 0
        return
    } else {
        // 在范围内，移动到下一个索引
        newIndex = nextIndex
    }
    break
```

## 💡 经验教训

### 动态参数数量处理

1. **不要硬编码参数数量**：
   ```qml
   // ❌ 错误：硬编码假设9个参数
   if (paramIndex === 8) {
       switchToArea(areaButtons)
   }

   // ✅ 正确：动态判断
   if (nextIndex > lastParamIndex) {
       switchToArea(areaButtons)
   }
   ```

2. **跟踪每个Tab的参数数量**：
   - 使用属性存储当前Tab的最后参数索引
   - Tab切换时更新该属性
   - 导航逻辑使用该属性判断

3. **简化逻辑**：
   - 不需要复杂的条件判断
   - 只需检查 `nextIndex > lastParamIndex`
   - 简单、清晰、易维护

### 导航系统设计原则

1. **统一行为**：
   - 所有Tab的导航行为应该一致
   - 用户不应该感觉到不同Tab有不同的导航规则

2. **动态适应**：
   - 导航系统应该适应不同的内容结构
   - 不要假设固定的元素数量

3. **边界处理**：
   - 明确定义边界行为（最后一个元素）
   - 确保边界处理对所有情况都适用

### 调试技巧

1. **添加日志输出**：
   ```qml
   console.log("✅ [NavigationManager] Tab索引:", newIndex, "lastParamIndex:", lastParamIndex)
   ```

2. **对比不同Tab的行为**：
   - 测试基本配置Tab
   - 测试其他Tab
   - 找出差异

3. **分析参数数量**：
   - 检查每个Tab的实际参数数量
   - 确认最后一个参数的索引
