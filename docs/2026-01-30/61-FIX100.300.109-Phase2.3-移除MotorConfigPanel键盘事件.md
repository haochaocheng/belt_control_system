# FIX 100.300.109 Phase 2.3 - 移除MotorConfigPanel的键盘事件处理

**日期**: 2026-01-30
**任务编号**: FIX 100.300.109 Phase 2.3
**状态**: ✅ 完成

---

## 🐛 问题描述

### 测试反馈

用户测试后反馈：**导航逻辑不对**

**具体问题**：
- 操作：1号电机 → 按右键进入基本配置 → 再按右键
- **预期**：应该在Tab之间切换（基本配置 → 电流保护）
- **实际**：进入了基本配置的参数区域（模块类型参数）

### 问题分析

**导航路径错误**：
```
正确路径：电机列表 → Tab导航区（基本配置） → Tab导航区（电流保护）
错误路径：电机列表 → Tab导航区（基本配置） → 参数区域（模块类型）
```

**根本原因**：
- MotorConfigPanel有自己的键盘事件处理
- 这些旧的键盘事件处理与NavigationManager冲突
- 当MotorConfigPanel获得焦点时，它会处理左右键
- 导致NavigationManager的导航逻辑被覆盖

---

## 🔍 代码分析

### MotorConfigPanel的旧键盘事件处理

**MotorConfigPanel.qml（修复前）**：
```qml
// ❌ 问题：有自己的键盘事件处理
focus: true

Keys.onLeftPressed: {
    if (root.currentTabIndex > 0) {
        root.currentTabIndex--
    }
}

Keys.onRightPressed: {
    if (root.currentTabIndex < 9) {
        root.currentTabIndex++
    }
}
```

### NavigationManager的导航逻辑

**NavigationManager.qml**：
```qml
// ✅ 正确：统一的导航逻辑
function moveInTabBar(direction) {
    switch(direction) {
    case "Left":
        if (tabIndex > 0) {
            newIndex = tabIndex - 1
        } else {
            switchToArea(areaMotorList)  // 返回电机列表
            return
        }
        break
    case "Right":
        if (tabIndex < 8) {
            newIndex = tabIndex + 1  // Tab之间切换
        }
        break
    }
}
```

### 冲突原因

**焦点传递链**：
```
MotorControlPage (focus: true)
  → MotorConfigPanel (focus: true)  ❌ 获得焦点
    → 处理左右键事件
    → NavigationManager的逻辑被覆盖
```

**事件处理顺序**：
1. 用户按右键
2. MotorConfigPanel的Keys.onRightPressed先被触发
3. MotorConfigPanel直接修改currentTabIndex
4. NavigationManager的handleDirectionKey没有机会执行
5. 导致导航逻辑错误

---

## 🔧 修复方案

### 解决方法

**移除MotorConfigPanel的键盘事件处理**：
- 移除 `focus: true`
- 注释掉 `Keys.onLeftPressed` 和 `Keys.onRightPressed`
- 由MotorControlPage的NavigationManager统一处理所有键盘事件

### 修复代码

**MotorConfigPanel.qml（修复后）**：

## 💡 经验教训

### QML焦点管理的最佳实践

1. **统一的键盘事件处理**：
   ```qml
   // ✅ 正确：只在顶层组件处理键盘事件
   MotorControlPage {
       focus: true
       Keys.onRightPressed: {
           navigationManager.handleDirectionKey("Right")
       }
   }

   // ❌ 错误：子组件也处理键盘事件
   MotorConfigPanel {
       focus: true  // 冲突！
       Keys.onRightPressed: { ... }
       }
   }
   ```

2. **避免焦点冲突**：
   - 只在需要接收键盘事件的顶层组件设置 `focus: true`
   - 子组件不应该有自己的键盘事件处理
   - 使用统一的导航管理器处理所有键盘事件

3. **清晰的职责分离**：
   ```qml
   // MotorControlPage: 负责键盘事件和导航逻辑
   // MotorConfigPanel: 只负责显示，不处理键盘事件
   // NavigationManager: 统一的导航状态管理
   ```
