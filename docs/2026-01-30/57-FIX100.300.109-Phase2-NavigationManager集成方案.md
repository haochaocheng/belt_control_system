## 🎯 集成目标

将NavigationManager集成到DeviceSettingsDialog，实现平面导航逻辑。

---

## 📊 当前状态分析

### DeviceSettingsDialog现有导航系统

**现有属性**：
```qml
property int currentFocusArea: 1              // 当前焦点区域 (0:顶部 1:左侧类别 2:右侧内容 3:底部)
property int currentCategory: 0               // 当前选中的参数类别
property int currentTopButtonIndex: 0         // 顶部按钮索引
property int currentContentItemIndex: 0       // 右侧内容区域焦点项索引
property int currentBottomButtonIndex: 0      // 底部按钮索引
```

**现有键盘事件**：
- Keys.onUpPressed：复杂的区域内导航逻辑
- Keys.onDownPressed：复杂的区域内导航逻辑
- Keys.onLeftPressed：左侧类别切换
- Keys.onRightPressed：右侧内容切换
- Keys.onReturnPressed：Enter键激活
- Keys.onEscapePressed：Esc键关闭

### NavigationManager新导航系统

**新属性**：
```qml
property string currentArea: "A"              // 当前焦点区域 (A/B/C/D)
property int motorListIndex: 0                // 电机列表索引（0-7）
property int tabIndex: 0                      // Tab索引（0-8）
property int paramIndex: 0                    // 参数索引（0-8）
property int buttonIndex: 0                   // 按钮索引（0-2）
```

**新导航函数**：
- handleDirectionKey(direction)：统一处理方向键
- moveInMotorList()：电机列表导航
- moveInTabBar()：Tab导航
- moveInParamArea()：参数区域导航
- moveInButtonArea()：底部按钮导航

## 🔄 集成方案对比

### 方案A：完全替换（推荐）

**优点**：
- 导航逻辑清晰统一
- 易于维护和扩展
- 符合新的平面导航设计

**缺点**：
- 需要大量修改DeviceSettingsDialog
- 可能影响现有功能
- 需要充分测试

**实施步骤**：
1. 在DeviceSettingsDialog中创建NavigationManager实例
2. 移除现有的导航属性和逻辑
3. 替换所有键盘事件处理
4. 更新焦点指示器绑定
5. 测试所有导航功能

### 方案B：渐进式集成（保守）

**优点**：
- 风险较低
- 可以逐步验证
- 保留现有功能

**缺点**：
- 会有两套导航系统并存
- 代码冗余
- 维护成本高

**实施步骤**：
1. 在DeviceSettingsDialog中创建NavigationManager实例
2. 保留现有导航逻辑
3. 添加一个开关来选择使用哪套导航系统
4. 逐步迁移各个区域
5. 最终移除旧的导航系统

### 方案C：仅用于新页面（最保守）

**优点**：
- 不影响现有功能
- 风险最低
- 可以先验证NavigationManager

**缺点**：
- 不能解决DeviceSettingsDialog的导航问题
- NavigationManager无法发挥作用

**实施步骤**：
1. 只在新创建的页面中使用NavigationManager
2. DeviceSettingsDialog保持现有导航逻辑
3. 未来新页面都使用NavigationManager

## 💡 推荐方案：方案A（完全替换）

### 理由

1. **符合新设计**：NavigationManager完全按照新的平面导航逻辑设计
2. **代码清晰**：统一的导航逻辑，易于理解和维护
3. **长期收益**：一次性解决导航问题，避免技术债务

### 实施计划

#### Step 1: 添加NavigationManager实例

在DeviceSettingsDialog的root Rectangle中添加：

```qml
Rectangle {
    id: root
    // ... 现有属性 ...

    // ✅ 2026-01-30 [FIX 100.300.109 Phase 2]: 集成NavigationManager
    DeviceInfo.NavigationManager {
        id: navigationManager

        // 监听Tab索引变化，切换参数区显示
        onTabIndexChanged: function(newIndex) {
            console.log("✅ [DeviceSettingsDialog] Tab切换:", newIndex)
            currentCategory = newIndex  // 更新当前类别
        }

        // 监听参数索引变化，更新焦点
        onParamIndexChanged: function(newIndex) {
            console.log("✅ [DeviceSettingsDialog] 参数焦点:", newIndex)
            var currentPage = getCurrentPage(currentCategory)
            if (currentPage) {
                currentPage.focusParamIndex = newIndex
            }
        }
    }
}
```

## ⚠️ 注意事项

### 1. 现有导航逻辑的处理

DeviceSettingsDialog有复杂的现有导航逻辑（约500行代码），包括：
- 4个焦点区域（顶部、左侧、右侧、底部）
- 子区域导航（列表区域、参数区域）
- 两列布局和单列布局的不同处理

**建议**：
- 保留现有逻辑作为注释（添加日期和原因）
- 逐步验证新逻辑是否覆盖所有场景
- 如果发现问题，可以快速回退

### 2. 焦点指示器的更新

参数区域的焦点指示器已经存在，通过`focusParamIndex`控制。NavigationManager的`onParamIndexChanged`信号会自动更新`focusParamIndex`，所以焦点指示器会自动工作。

### 3. Tab切换联动

NavigationManager的`onTabIndexChanged`信号会更新`currentCategory`，这会触发参数区的切换显示。这个联动已经在现有代码中实现。
