# FIX 100.300.109 Phase 2.8 - 修复焦点管理和返回导航

**日期**: 2026-01-30
**任务编号**: FIX 100.300.109 Phase 2.8
**状态**: ✅ 完成

## 🐛 问题描述

### 问题1：电机列表向左无法返回到大类

**用户反馈**：
> 从基本配置、开关量输入、模拟量输入这大类，当在电机控制进入电机列表继续向右，这个方向没有问题，但是向左时问题包括，在电机列表任意一个键时向左时，无法将焦点返回到大类的电机控制。

**具体问题**：
- 在电机列表任意位置按左键
- **预期**：返回到左侧大类的"电机控制"
- **实际**：焦点保持不变，无法返回

### 问题2：焦点指示器不清除，导致多个蓝色边框

**用户反馈**：
> 从电机列表向右进入tab按钮的基本配置时，基本列表内任意按钮的蓝色边框不应该存在，只有从tab的基本配置向左按键按下有切换到电机列表才在相对应的电机按键焦点上蓝色边框才显示，同意上下也是，从参数区域向上进入tab区域按钮时，参数的区域蓝色边框也存在，这就表明在整个画面包含两个蓝色框，不知道焦点在哪里

**具体问题**：
- 从电机列表向右进入Tab时，电机列表的蓝色边框还在
- 从参数区向上进入Tab时，参数区的蓝色边框还在
- **导致画面上有两个蓝色边框，不知道焦点在哪里**

---

## 🔍 问题分析

### 问题1根本原因

**NavigationManager.qml 第66-68行**：
```qml
case "Left":
    // 在左侧边界，保持不变
    break
```

**问题**：
- 电机列表向左时，只是"保持不变"
- 没有返回到左侧大类的逻辑
- 用户无法通过键盘返回到大类

### 问题2根本原因

**MotorControlPage.qml 第87-105行**：
```qml
onAreaChanged: function(newArea) {
    switch(newArea) {
    case areaMotorList:
        root.focusSubArea = 0
        root.focusItemIndex = motorListIndex
        break  // ❌ 没有清除其他区域的焦点
    case areaTabBar:
        root.focusSubArea = 1
        break  // ❌ 没有清除其他区域的焦点
    // ...
    }
}
```

**问题**：
- 切换区域时，只更新了 `focusSubArea`
- 没有清除其他区域的焦点索引（`focusItemIndex`, `focusTabIndex`, `focusParamIndex`）
- 导致多个区域同时显示蓝色边框

## 🔧 修复方案

### 问题1修复：添加返回到类别功能

**信号传递链**：
```
NavigationManager (电机列表向左)
  ↓ returnToCategory() 信号
MotorControlPage (监听信号)
  ↓ requestReturnToCategory() 信号
DeviceSettingsDialog (监听信号)
  ↓ currentFocusArea = 1 (切换到左侧类别)
```

**修改代码**：

1. **NavigationManager.qml - 添加信号和发出逻辑**：
```qml
// 第28-29行：添加信号定义
signal areaChanged(string newArea)
signal returnToCategory()  // ✅ 新增：返回到左侧类别信号

// 第67-71行：电机列表向左时发出信号
case "Left":
    // ✅ 向左返回到大类（电机控制）
    returnToCategory()
    return
```

2. **MotorControlPage.qml - 监听信号并转发**：
```qml
// 第257-258行：添加公开信号
signal requestReturnToCategory()  // 请求返回到左侧类别

// 第123-128行：监听 NavigationManager 的信号
onReturnToCategory: {
    console.log("✅ [MotorControlPage] 返回到左侧类别")
    // 发出信号通知 DeviceSettingsDialog
    root.requestReturnToCategory()
}
```

3. **DeviceSettingsDialog.qml - 监听信号并切换区域**：
```qml
// 第1188-1192行：在 motorControlPageLoader.onLoaded 中连接信号
item.requestReturnToCategory.connect(function() {
    console.log("✅ [DeviceSettingsDialog] 接收到返回类别请求")
    root.currentFocusArea = 1  // 切换到左侧类别区域
})
```

### 问题2修复：清除其他区域的焦点指示器

**修改代码**：

**MotorControlPage.qml 第89-121行**：
```qml
onAreaChanged: function(newArea) {
    console.log("✅ [MotorControlPage] 区域变化:", newArea)
    // ✅ 清除其他区域的焦点指示器
    switch(newArea) {
    case areaMotorList:
        root.focusSubArea = 0
        root.focusItemIndex = motorListIndex
        // ✅ 清除其他区域的焦点
        root.focusTabIndex = -1
        root.focusParamIndex = -1
        break
    case areaTabBar:
        root.focusSubArea = 1
        root.focusTabIndex = tabIndex
        // ✅ 清除其他区域的焦点
        root.focusItemIndex = -1
        root.focusParamIndex = -1
        break
    case areaParams:
        root.focusSubArea = 2
        root.focusParamIndex = paramIndex
        // ✅ 清除其他区域的焦点
        root.focusItemIndex = -1
        root.focusTabIndex = -1
        break
    case areaButtons:
        root.focusSubArea = 3
        // ✅ 清除其他区域的焦点
        root.focusItemIndex = -1
        root.focusTabIndex = -1
        root.focusParamIndex = -1
        break
    }
}
```

## 💡 经验教训

### 焦点管理的最佳实践

1. **单一焦点原则**：
   - 任何时候只有一个区域应该显示焦点指示器
   - 切换区域时，必须清除其他区域的焦点

2. **焦点索引的清除**：
   ```qml
   // ✅ 正确：切换区域时清除其他焦点
   onAreaChanged: function(newArea) {
       switch(newArea) {
       case areaA:
           focusIndexA = currentIndex
           focusIndexB = -1  // 清除
           focusIndexC = -1  // 清除
           break
       }
   }

   // ❌ 错误：不清除其他焦点
   onAreaChanged: function(newArea) {
       switch(newArea) {
       case areaA:
           focusIndexA = currentIndex
           // 其他焦点索引保持不变 ❌
           break
       }
   }
   ```

3. **使用 -1 表示无焦点**：
   - `focusIndex = -1` 表示该区域没有焦点
   - 组件检查 `focusIndex === index` 来显示焦点边框
   - 当 `focusIndex === -1` 时，所有组件的边框都不显示

### 信号传递的最佳实践

1. **跨层级通信使用信号**：
   ```qml
   // NavigationManager → MotorControlPage → DeviceSettingsDialog
   // 使用信号链传递事件
   ```

2. **信号命名清晰**：
   - `returnToCategory()` - 内部信号
   - `requestReturnToCategory()` - 公开信号
   - 清楚表达信号的用途

3. **信号连接在 onLoaded**：
   ```qml
   onLoaded: {
       item.requestReturnToCategory.connect(function() {
           // 处理逻辑
       })
   }
   ```

### 调试技巧

1. **添加日志追踪信号传递**：
   ```qml
   console.log("✅ [组件名] 信号发出/接收")
   ```

2. **检查焦点索引值**：
   ```qml
   console.log("focusItemIndex:", focusItemIndex)
   console.log("focusTabIndex:", focusTabIndex)
   console.log("focusParamIndex:", focusParamIndex)
   ```

3. **验证边框显示逻辑**：
   ```qml
   border.color: (focusIndex === index) ? "#2196F3" : "transparent"
   // 当 focusIndex === -1 时，所有边框都是透明的
   ```
