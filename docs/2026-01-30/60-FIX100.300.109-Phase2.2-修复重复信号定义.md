## 🐛 问题描述

### 测试反馈

用户测试后反馈：**问题依旧，电机列表及参数区不显示**

### 错误日志

```
Warning: file:///E:/2025/3_gongkongji/belt_control_system/src/qml/components/device_info/pages/MotorControlPage.qml:33:5: Type DeviceInfo.NavigationManager unavailable
Warning: file:///E:/2025/3_gongkongji/belt_control_system/src/qml/components/device_info/NavigationManager.qml:24:12: Duplicate signal name: invalid override of property change signal or superclass signal
Critical: ❌ [DeviceSettingsDialog] MotorControlPage 加载失败
```

### 根本原因

**QML属性自动生成信号的机制**：
- 在QML中，当你定义一个 `property` 时，QML会**自动生成**一个对应的 `Changed` 信号
- 例如：`property int motorListIndex: 0` 会自动生成 `onMotorListIndexChanged` 信号
- 如果手动定义 `signal motorListIndexChanged(int newIndex)`，就会导致**重复定义错误**

**NavigationManager.qml中的错误代码**：
```qml
// ❌ 错误：手动定义的信号与自动生成的信号冲突
property int motorListIndex: 0                 // 自动生成 onMotorListIndexChanged
signal motorListIndexChanged(int newIndex)     // ❌ 重复定义！

property int tabIndex: 0                       // 自动生成 onTabIndexChanged
signal tabIndexChanged(int newIndex)           // ❌ 重复定义！

property int paramIndex: 0                     // 自动生成 onParamIndexChanged
signal paramIndexChanged(int newIndex)         // ❌ 重复定义！

property int buttonIndex: 0                    // 自动生成 onButtonIndexChanged
signal buttonIndexChanged(int newIndex)        // ❌ 重复定义！
```

---

## 🔧 修复方案

### 解决方法

1. **移除手动定义的信号**：删除重复的signal定义
2. **移除手动调用信号**：删除代码中手动调用这些信号的地方
3. **依赖自动信号**：属性值改变时会自动触发对应的Changed信号

### 修复代码

**修复前**：
```qml
// ❌ 错误：手动定义信号
property int motorListIndex: 0
signal motorListIndexChanged(int newIndex)

function moveInMotorList(direction) {
    var newIndex = motorListIndex
    // ...
    if (newIndex !== motorListIndex) {
        motorListIndex = newIndex
        motorListIndexChanged(newIndex)  // ❌ 手动调用信号
    }
}
```

**修复后**：
```qml
// ✅ 正确：只定义property，自动生成信号
property int motorListIndex: 0
// ✅ 移除手动定义的信号

function moveInMotorList(direction) {
    var newIndex = motorListIndex
    // ...
    if (newIndex !== motorListIndex) {
        motorListIndex = newIndex
        // ✅ 移除手动调用，属性改变时会自动触发 onMotorListIndexChanged
    }
}
```

## 📊 QML信号机制详解

### 自动生成的信号

QML中，每个property都会自动生成3个东西：
1. **属性本身**：`motorListIndex`
2. **Changed信号**：`onMotorListIndexChanged`
3. **信号处理器**：可以在外部监听 `onMotorListIndexChanged`

**示例**：
```qml
// 定义
property int motorListIndex: 0

// 使用（在外部）
onMotorListIndexChanged: function(newValue) {
    console.log("索引变化:", newValue)
}

// 触发（自动）
motorListIndex = 5  // 自动触发 onMotorListIndexChanged(5)
```

### 自定义信号

只有当你需要**传递额外参数**或**自定义触发时机**时，才需要手动定义signal：

```qml
// ✅ 正确：自定义信号，因为需要传递参数
signal areaChanged(string newArea)

function switchToArea(newArea) {
    if (currentArea !== newArea) {
        currentArea = newArea
        areaChanged(newArea)  // 手动触发自定义信号
    }
}
```

## 💡 经验教训

### QML信号机制的最佳实践

1. **不要手动定义属性变化信号**：
   ```qml
   // ❌ 错误
   property int value: 0
   signal valueChanged(int newValue)  // 重复定义！

   // ✅ 正确
   property int value: 0
   // QML自动生成 onValueChanged 信号
   ```

2. **不要手动调用属性变化信号**：
   ```qml
   // ❌ 错误
   value = 10
   valueChanged(10)  // 不需要手动调用！

   // ✅ 正确
   value = 10  // 自动触发 onValueChanged(10)
   ```

3. **只在需要时定义自定义信号**：
   ```qml
   // ✅ 正确：自定义信号，因为需要传递额外参数
   signal customEvent(string message, int code)

   function doSomething() {
       customEvent("完成", 200)  // 手动触发自定义信号
   }
   ```

### 调试技巧

1. **查看QML错误日志**：
   - 错误信息会明确指出 "Duplicate signal name"
   - 错误位置会指向具体的行号

2. **理解QML自动生成机制**：
   - 每个property都有对应的Changed信号
   - 不需要手动定义或调用

3. **使用console.log验证**：
   ```qml
   onMotorListIndexChanged: function(newValue) {
       console.log("✅ 信号自动触发:", newValue)
   }
   ```
