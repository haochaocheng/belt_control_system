# 修复对话框关闭后焦点恢复

**日期**: 2026-01-30
**问题编号**: FIX 100.300.104.3
**状态**: ✅ 已完成

---

## 🐛 问题描述

### 测试结果

**改进的地方**：
- ✅ 虚拟键盘可以使用 ESC 键关闭

**未解决的问题**：
- ❌ 弹出对话框使用 ESC 关闭后，主界面的导航键依然不可以使用

### 根本原因

**DeviceSettingsDialog 关闭时没有恢复焦点**：

1. **ESC 键处理**（第 478-481 行）：
```qml
Keys.onEscapePressed: {
    // Escape 键：关闭弹窗
    root.visible = false  // ❌ 只是隐藏，没有恢复焦点
}
```

2. **关闭按钮处理**（第 574-577 行）：
```qml
onClicked: {
    // ✅ 2026-01-24: 关闭弹窗
    root.visible = false  // ❌ 只是隐藏，没有恢复焦点
}
```

3. **导航触发关闭**（第 1174-1177 行）：
```qml
case 0:  // 关闭
    console.log("✅ [导航] 触发：关闭")
    root.visible = false  // ❌ 只是隐藏，没有恢复焦点
    break
```

**问题分析**：
- 对话框关闭时，只是设置 `visible = false`
- 焦点仍然停留在对话框上（虽然不可见）
- 主界面无法接收键盘事件
- 导航键不起作用

---

## ✅ 解决方案

### 修改内容

**文件**：`DeviceSettingsDialog.qml`

#### 修改 1：ESC 键处理

```qml
Keys.onEscapePressed: {
    // Escape 键：关闭弹窗
    console.log("✅ [DeviceSettingsDialog] ESC 键关闭对话框")
    root.visible = false
    // ✅ 2026-01-30 [修复]: 关闭对话框后，恢复焦点到父容器
    if (root.parent) {
        console.log("✅ [DeviceSettingsDialog] 恢复焦点到父容器")
        root.parent.forceActiveFocus()
    }
}
```

#### 修改 2：关闭按钮处理

```qml
onClicked: {
    // ✅ 2026-01-24: 关闭弹窗
    console.log("✅ [DeviceSettingsDialog] 关闭按钮被点击")
    root.visible = false
    // ✅ 2026-01-30 [修复]: 关闭对话框后，恢复焦点到父容器
    if (root.parent) {
        console.log("✅ [DeviceSettingsDialog] 恢复焦点到父容器")
        root.parent.forceActiveFocus()
    }
}
```

#### 修改 3：导航触发关闭

```qml
function triggerTopButton(buttonIndex) {
    switch(buttonIndex) {
    case 0:  // 关闭
        console.log("✅ [导航] 触发：关闭")
        root.visible = false
        // ✅ 2026-01-30 [修复]: 关闭对话框后，恢复焦点到父容器
        if (root.parent) {
            console.log("✅ [DeviceSettingsDialog] 恢复焦点到父容器")
            root.parent.forceActiveFocus()
        }
        break
    // ...
    }
}
```

**关键点**：
1. 在所有关闭对话框的地方，都添加焦点恢复逻辑
2. 使用 `root.parent.forceActiveFocus()` 主动恢复焦点到父容器
3. 添加日志输出，便于调试

## 🔍 技术说明

### 焦点管理流程

**对话框打开时**：
```
主界面 (有焦点) → 对话框打开 → 对话框 (有焦点)
```

**对话框关闭时（修复前）**：
```
对话框 (有焦点) → visible = false → 对话框 (仍有焦点，但不可见) ❌
主界面 (无焦点) ← 导航键不起作用
```

**对话框关闭时（修复后）**：
```
对话框 (有焦点) → visible = false → root.parent.forceActiveFocus()
                                    ↓
主界面 (有焦点) ← 导航键正常工作 ✅
```

### 为什么需要 forceActiveFocus()？

**visible = false 的行为**：
- 只是隐藏组件，不改变焦点
- 焦点仍然停留在隐藏的组件上
- 键盘事件仍然发送到隐藏的组件

**forceActiveFocus() 的作用**：
- 主动将焦点设置到指定组件
- 移除原组件的焦点
- 确保键盘事件发送到正确的组件

### 为什么使用 root.parent？

**对话框的层级结构**：
```
Screen01 (主界面)
  └─ DeviceSettingsDialog (对话框)
       └─ FocusScope (对话框内容)
```

**root.parent 指向**：
- `root` 是 DeviceSettingsDialog 的根 Item
- `root.parent` 是 Screen01（主界面）
- 关闭对话框后，焦点应该返回到 Screen01
