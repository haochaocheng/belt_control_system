# 修复虚拟键盘关闭后焦点问题

**日期**: 2026-01-30
**问题编号**: FIX 100.300.104
**状态**: ✅ 已完成

---

## 🐛 问题描述

### 用户报告

**现象**：
- 在开关量输入页面，按回车键弹出虚拟键盘 ✅
- 输入完成后，点击虚拟键盘的关闭按钮（×）✅
- 虚拟键盘关闭后，使用导航键（上下键）❌
- **问题**：方向键只能增加/减少当前输入框的数值，不能在参数选项间移动

### 根本原因

**焦点管理问题**：
1. 虚拟键盘打开时，焦点被设置到输入框（`textField.forceActiveFocus()`）
2. 虚拟键盘关闭时，焦点**没有被移除**
3. 焦点仍然停留在输入框上
4. 方向键事件被输入框捕获（SpinBox 的上下键用于增减数值）
5. 方向键事件无法传递到参数列表进行导航

**代码位置**：
- `src/qml/components/virtual_keyboard/QtVirtualKeyboardIntegration.qml`
- 缺少 `onClosed` 处理

---

## ✅ 解决方案

### 修改内容

**文件**：`QtVirtualKeyboardIntegration.qml`

**添加 `onClosed` 事件处理**：

```qml
// ✅ 2026-01-30 [修复]: 虚拟键盘关闭时恢复焦点
onClosed: {
    console.log("✅ [QtVirtualKeyboard] 虚拟键盘已关闭，恢复焦点")
    // 移除输入框的焦点，让焦点返回到父容器
    if (targetTextField) {
        targetTextField.focus = false
    }
    // 清空目标输入框引用
    targetTextField = null
    updateCallback = null
}
```

**修改位置**：第 58-68 行

## 🔍 技术说明

### 焦点管理机制

**Qt/QML 焦点系统**：
1. 每个 Item 都有一个 `focus` 属性
2. 只有一个 Item 可以拥有焦点
3. 拥有焦点的 Item 会接收键盘事件
4. 焦点可以通过 `forceActiveFocus()` 强制设置
5. 焦点可以通过 `focus = false` 移除

**焦点传递顺序**：
```
键盘事件 → 拥有焦点的 Item → 父 Item → 祖父 Item → ...
```

**问题场景**：
```
虚拟键盘打开：
  参数列表 (无焦点) → 输入框 (有焦点) ← 键盘事件

虚拟键盘关闭（修复前）：
  参数列表 (无焦点) → 输入框 (仍有焦点) ← 键盘事件 ❌

虚拟键盘关闭（修复后）：
  参数列表 (有焦点) ← 键盘事件 ✅
  输入框 (无焦点)
```

### 为什么需要清空引用

**清空 `targetTextField` 和 `updateCallback`**：
1. 防止内存泄漏
2. 防止下次打开虚拟键盘时使用旧的引用
3. 确保状态清理干净
