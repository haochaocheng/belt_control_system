# 修复虚拟键盘关闭后焦点问题

**日期**: 2026-01-30
**问题编号**: FIX 100.300.104
**状态**: ✅ 已完成（包含 ESC 键修复）

---

## 🐛 问题描述

### 问题 1：点击关闭按钮后焦点问题（✅ 已解决）

**现象**：
- 在开关量输入页面，按回车键弹出虚拟键盘 ✅
- 输入完成后，点击虚拟键盘的关闭按钮（×）✅
- 虚拟键盘关闭后，使用导航键（上下键）❌
- **问题**：方向键只能增加/减少当前输入框的数值，不能在参数选项间移动

### 问题 2：ESC 键处理逻辑错误（✅ 已解决）

**现象**：
- 虚拟键盘打开的情况下，按 ESC 键
- 弹出对话框（DeviceSettingsDialog）关闭了
- 但虚拟键盘还在显示
- 左右导航键不起作用

**期望行为**：
1. 虚拟键盘打开时，按 ESC → 关闭虚拟键盘，焦点回到参数区域
2. 再按 ESC → 关闭弹出对话框，回到 4*3 主界面
3. 导航键依然可以使用

### 根本原因

**问题 1 的原因**：
1. 虚拟键盘打开时，焦点被设置到输入框（`textField.forceActiveFocus()`）
2. 虚拟键盘关闭时，焦点**没有被移除**
3. 焦点仍然停留在输入框上
4. 方向键事件被输入框捕获（SpinBox 的上下键用于增减数值）
5. 方向键事件无法传递到参数列表进行导航

**问题 2 的原因**：
1. ESC 键事件被 DeviceSettingsDialog 捕获，关闭了对话框
2. 虚拟键盘没有收到 ESC 事件，所以没有关闭
3. 虚拟键盘"孤立"在界面上，失去了父容器
4. 导航键无法工作

**代码位置**：
- `src/qml/components/virtual_keyboard/QtVirtualKeyboardIntegration.qml`
- 缺少 `onClosed` 处理
- 缺少 ESC 键处理

## ✅ 解决方案

### 修复 1：第一次尝试（不完整）

**文件**：`QtVirtualKeyboardIntegration.qml`

**添加 `onClosed` 事件处理**：

```qml
// ✅ 2026-01-30 [修复]: 虚拟键盘关闭时恢复焦点
onClosed: {
    console.log("✅ [QtVirtualKeyboard] 虚拟键盘已关闭，恢复焦点")
    // 移除输入框的焦点，让焦点返回到父容器
    if (targetTextField) {
        targetTextField.focus = false
    }
    // 清空目标输入框引用
    targetTextField = null
    updateCallback = null
}
```

**测试结果**：
- ❌ 焦点被移除，但没有返回到任何组件
- ❌ 导航键仍然不起作用

### 修复 2：主动恢复焦点（✅ 完整解决）

**问题分析**：
- 第一次修复只是移除了焦点，但没有主动将焦点返回到父页面
- 焦点处于"孤立"状态，没有组件接收键盘事件

**解决方案**：

#### 步骤 1：允许父页面接收焦点

**文件**：`SwitchInputPage.qml`

```qml
Rectangle {
    id: root
    implicitWidth: 800
    implicitHeight: 600
    color: "transparent"

    // ✅ 2026-01-30 [修复]: 允许接收焦点，以便虚拟键盘关闭后焦点可以返回
    focus: true
    activeFocusOnTab: true
```

#### 步骤 2：保存父页面引用

**文件**：`QtVirtualKeyboardIntegration.qml`

```qml
property var targetTextField: null
property var updateCallback: null
property string inputMode: "numeric"
// ✅ 2026-01-30 [修复]: 保存父页面引用，用于恢复焦点
property var parentPage: null

// Show keyboard for specific field
function openForField(textField, callback, mode, parentPageRef) {
    targetTextField = textField
    updateCallback = callback
    inputMode = mode || "numeric"
    parentPage = parentPageRef || null
    // ...
}
```

#### 步骤 3：主动恢复焦点

**文件**：`QtVirtualKeyboardIntegration.qml`

```qml
// ✅ 2026-01-30 [修复]: 虚拟键盘关闭时恢复焦点
onClosed: {
    console.log("✅ [QtVirtualKeyboard] 虚拟键盘已关闭，恢复焦点")
    // 移除输入框的焦点
    if (targetTextField) {
        targetTextField.focus = false
    }
    // ✅ 2026-01-30 [修复]: 主动将焦点返回到父页面
    if (parentPage) {
        console.log("✅ [QtVirtualKeyboard] 恢复焦点到父页面")
        parentPage.forceActiveFocus()
    }
    // 清空引用
    targetTextField = null
    updateCallback = null
    parentPage = null
}
```

#### 步骤 4：传递父页面引用

**文件**：`SwitchInputPage.qml`

```qml
if (virtualKeyboard) {
    // ✅ 2026-01-30 [修复]: 传递父页面引用，用于恢复焦点
    virtualKeyboard.openForField(inputField, function(newValue) {
        console.log("✅ [SwitchInputPage] 虚拟键盘输入完成:", newValue)
    }, inputMode, root)  // ← 传递 root 作为第 4 个参数
}
```

**测试结果**：
- ✅ 点击关闭按钮后，焦点正确返回到参数区域
- ✅ 导航键可以正常工作

### 修复 3：ESC 键处理（✅ 完整解决）

**文件**：`QtVirtualKeyboardIntegration.qml`

#### 步骤 1：允许虚拟键盘接收键盘事件

```qml
Popup {
    id: root
    width: parent.width
    height: 300
    y: parent.height - height
    modal: false
    // ✅ 2026-01-30 [修复]: 允许接收键盘事件，以便处理 ESC 键
    focus: true
    closePolicy: Popup.NoAutoClose
```

#### 步骤 2：添加 ESC 键处理

```qml
// ✅ 2026-01-30 [修复]: 处理 ESC 键关闭虚拟键盘
Keys.onPressed: (event) => {
    if (event.key === Qt.Key_Escape) {
        console.log("✅ [QtVirtualKeyboard] ESC 键被按下，关闭虚拟键盘")
        // 保存输入内容
        if (root.targetTextField && root.updateCallback) {
            root.updateCallback(root.targetTextField.text)
        }
        // 关闭虚拟键盘
        root.close()
        // 阻止事件继续传播到父容器
        event.accepted = true
    }
}
```

**关键点**：
1. `focus: true` - 允许 Popup 接收键盘事件
2. `event.accepted = true` - 阻止 ESC 事件传播到 DeviceSettingsDialog
3. 先保存输入内容，再关闭虚拟键盘
4. 关闭时会触发 `onClosed`，自动恢复焦点

**测试结果**：
- ✅ 虚拟键盘打开时，按 ESC → 关闭虚拟键盘，焦点回到参数区域
- ✅ 再按 ESC → 关闭弹出对话框，回到 4*3 主界面
- ✅ 导航键依然可以使用

## 🔍 技术说明

### 焦点管理机制

**Qt/QML 焦点系统**：
1. 每个 Item 都有一个 `focus` 属性
2. 只有一个 Item 可以拥有焦点
3. 拥有焦点的 Item 会接收键盘事件
4. 焦点可以通过 `forceActiveFocus()` 强制设置
5. 焦点可以通过 `focus = false` 移除

**焦点传递顺序**：
```
键盘事件 → 拥有焦点的 Item → 父 Item → 祖父 Item → ...
```

**问题场景**：
```
虚拟键盘打开：
  参数列表 (无焦点) → 输入框 (有焦点) ← 键盘事件

虚拟键盘关闭（修复前）：
  参数列表 (无焦点) → 输入框 (仍有焦点) ← 键盘事件 ❌

虚拟键盘关闭（修复后）：
  参数列表 (有焦点) ← 键盘事件 ✅
  输入框 (无焦点)
```

### ESC 键事件传播机制

**事件传播顺序**：
```
ESC 键按下 → 虚拟键盘 (Popup) → DeviceSettingsDialog (Dialog) → ...
```

**修复前的问题**：
```
ESC 键按下 → 虚拟键盘 (focus: false, 不接收事件)
             ↓
             DeviceSettingsDialog (接收事件，关闭对话框) ❌

结果：对话框关闭，虚拟键盘还在
```

**修复后的行为**：
```
ESC 键按下 → 虚拟键盘 (focus: true, 接收事件)
             ↓
             处理 ESC 键，关闭虚拟键盘
             ↓
             event.accepted = true (阻止事件传播) ✅

结果：虚拟键盘关闭，对话框保持打开
```

### 为什么需要清空引用

**清空 `targetTextField` 和 `updateCallback`**：
1. 防止内存泄漏
2. 防止下次打开虚拟键盘时使用旧的引用
3. 确保状态清理干净
