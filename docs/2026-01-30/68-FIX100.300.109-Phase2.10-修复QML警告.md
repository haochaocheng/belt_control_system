## ⚠️ 问题描述

### QML 警告信息

测试日志中出现多个 QML 警告：

```
Warning: file:///E:/2025/3_gongkongji/belt_control_system/src/qml/components/device_info/DeviceSettingsDialog.qml:427:5
Parameter "event" is not declared. Injection of parameters into signal handlers is deprecated.
Use JavaScript functions with formal parameters instead.
```

**出现位置**：
- Line 100: `Keys.onUpPressed`
- Line 217: `Keys.onDownPressed`
- Line 337: `Keys.onLeftPressed`
- Line 427: `Keys.onRightPressed`

### 警告原因

**QML 新版本规范变化**：
- 旧版本：允许在信号处理器中隐式使用 `event` 参数
- 新版本：要求显式声明参数，不再支持参数注入

**错误代码示例**：
```qml
Keys.onUpPressed: {
    // 使用 event 参数，但没有声明
    event.accepted = true  // ❌ 警告：Parameter "event" is not declared
}
```

**正确代码示例**：
```qml
Keys.onUpPressed: function(event) {
    // 显式声明 event 参数
    event.accepted = true  // ✅ 正确
}
```

## 🔍 问题分析

### 根本原因

在 Phase 2.4 中添加的键盘事件转发逻辑使用了旧的 QML 语法：

```qml
Keys.onUpPressed: {
    if (currentCategory === 3 && currentFocusArea === 2) {
        var motorPage = motorControlPageLoader.item
        if (motorPage && typeof motorPage.handleKeyPress === "function") {
            motorPage.handleKeyPress("Up")
            event.accepted = true  // ❌ 使用了 event 但没有声明
            return
        }
    }
    // ...
}
```

**问题**：
- 使用了 `event.accepted = true`
- 但没有在函数签名中声明 `event` 参数
- QML 新版本不再支持这种隐式参数注入

### 影响范围

**4 个键盘事件处理器**：
1. `Keys.onUpPressed` (line 100)
2. `Keys.onDownPressed` (line 218)
3. `Keys.onLeftPressed` (line 337)
4. `Keys.onRightPressed` (line 430)

**影响**：
- 功能正常工作（向后兼容）
- 但会产生警告信息
- 不符合 QML 新版本规范

---

## 🔧 修复方案

### 解决方法

**将隐式参数改为显式声明**：

```qml
// ❌ 修复前：隐式参数
Keys.onUpPressed: {
    event.accepted = true
}

// ✅ 修复后：显式声明参数
Keys.onUpPressed: function(event) {
    event.accepted = true
}
```

### 修复代码

**DeviceSettingsDialog.qml - Keys.onUpPressed (line 100)**：

```qml

            return
        }
    }
    // ...
}
```

**同样的修复应用到其他 3 个事件处理器**：

## 💡 经验教训

### QML 信号处理器的最佳实践

1. **显式声明参数**：
   ```qml
   // ✅ 推荐：显式声明参数
   Keys.onPressed: function(event) {
       console.log("Key:", event.key)
   }

   // ❌ 避免：隐式参数（已弃用）
   Keys.onPressed: {
       console.log("Key:", event.key)  // 警告
   }
   ```

2. **自定义信号处理器**：
   ```qml
   // 自定义信号
   signal mySignal(string message, int code)

   // ✅ 正确：显式声明参数
   onMySignal: function(message, code) {
       console.log(message, code)
   }
   ```

3. **属性变化信号**：
   ```qml
   // 属性定义
   property int value: 0

   // ✅ 正确：属性变化信号不需要参数
   onValueChanged: {
       console.log("New value:", value)  // 直接使用属性
   }

   // ❌ 错误：属性变化信号不传递参数
   onValueChanged: function(newValue) {
       console.log("New value:", newValue)  // undefined
   }
   ```

### QML 版本兼容性

1. **向后兼容**：
   - 旧语法仍然可以工作
   - 但会产生警告信息

2. **向前兼容**：
   - 新语法在旧版本中也能工作
   - 建议使用新语法

3. **最佳实践**：
   - 始终显式声明信号处理器参数
   - 避免依赖隐式参数注入

### 调试技巧

1. **检查警告信息**：
   ```
   Warning: Parameter "event" is not declared
   ```
   - 说明使用了隐式参数
   - 需要添加 `function(event)` 声明

2. **区分信号类型**：
   - **键盘事件**：需要 `event` 参数
   - **属性变化**：不需要参数，直接使用属性
   - **自定义信号**：根据信号定义声明参数

3. **代码审查**：
   - 搜索 `Keys.on` 开头的信号处理器
   - 检查是否使用了 `event` 参数
   - 确保参数已显式声明

## 📝 QML 信号处理器参数总结

### 需要显式声明参数的信号

| 信号类型 | 参数 | 示例 |
|---------|------|------|
| 键盘事件 | event | `Keys.onPressed: function(event)` |
| 鼠标事件 | mouse | `MouseArea.onClicked: function(mouse)` |
| 自定义信号 | 根据定义 | `onMySignal: function(param1, param2)` |

### 不需要参数的信号

| 信号类型 | 使用方式 | 示例 |
|---------|---------|------|
| 属性变化 | 直接使用属性 | `onValueChanged: { use value }` |
| 无参数信号 | 不需要参数 | `onCompleted: { ... }` |
