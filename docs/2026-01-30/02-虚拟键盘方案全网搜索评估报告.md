# 虚拟键盘方案评估报告

## 需求概述

- **目标平台**: QML应用程序
- **输入方式**: 非触摸屏，仅支持导航键（方向键）和回车键
- **语言支持**: 必须支持中文输入
- **部署环境**: 嵌入式系统（基于RK3588 ARM64平台）

---

## 方案对比

### 方案 A: Qt 官方 Virtual Keyboard (Qt Virtual Keyboard)

#### 基本信息
- **仓库**: https://github.com/qt/qtvirtualkeyboard
- **许可证**: GPL v3 / 商业许可
- **Qt版本支持**: Qt 5.12+, Qt 6.x
- **官方文档**: https://doc.qt.io/qt-6/qtvirtualkeyboard-overview.html

#### 核心功能

##### 1. 导航键支持 ✅
- **配置选项**: `-vkb-arrow-keynavigation`
- **支持功能**:
  - 使用方向键在键盘按键间导航
  - 使用回车键确认输入选中的字符
  - 提供视觉焦点指示器（通过KeyboardStyle自定义）
- **限制**:
  - 该功能**默认关闭**，需要在编译时通过 `CONFIG += arrow-key-navigation` 启用
  - 需要重新编译Qt Virtual Keyboard插件

##### 2. 中文输入支持 ✅✅✅
- **拼音输入法**: 内置PinyinIME（来自Android开源项目）
- **繁体中文**: 支持仓颉（Cangjie）和注音（Zhuyin）输入法
- **配置选项**:
  - `lang-zh_CN`: 启用简体中文拼音输入法
  - `-vkb-cangjie`: 启用/禁用仓颉输入法（繁体）
  - `-vkb-zhuyin`: 启用/禁用注音输入法（繁体）
  - `-vkb-no-bundle-pinyin`: 排除拼音资源（用于减小插件体积）
- **词库**: 包含完整的中文词库资源

##### 3. 部署要求
- 需要从Qt源码编译Virtual Keyboard模块
- 编译命令示例:
  ```bash
  ./configure -vkb-arrow-keynavigation -vkb-enable zh_CN
  make
  make install
  ```
- 运行时设置:
  ```cpp
  qputenv("QT_IM_MODULE", QByteArray("qtvirtualkeyboard"));
  ```

##### 4. 优缺点

**优点**:
- ✅ Qt官方支持，稳定可靠
- ✅ 完整的中文输入法支持（拼音、仓颉、注音）
- ✅ 支持箭头键导航（需编译时启用）
- ✅ 支持多种键盘布局
- ✅ 可自定义样式
- ✅ 与Qt生态系统完美集成

**缺点**:
- ❌ **许可证限制**: 开源版本使用GPL v3，商业项目需要付费许可
- ❌ **编译复杂**: 需要从源码编译，配置选项较多
- ❌ **体积较大**: 包含多语言资源和词库
- ❌ **arrow-key-navigation默认关闭**: 需要重新编译才能启用

### 方案 B: CuteKeyboard

#### 基本信息
- **仓库**: https://github.com/amarula/cutekeyboard
- **许可证**: MIT（完全免费，可商用）
- **Qt版本支持**: Qt 5.12+, Qt 6.x
- **官网**: https://amarula.github.io/cutekeyboard/

#### 核心功能

##### 1. 导航键支持 ❓
- **文档未明确提及**原生箭头键导航支持
- 可能需要自定义实现
- **优点**: MIT许可，易于定制和扩展

##### 2. 中文输入支持 ❌
- **文档仅提及**: "Supports natively a lot of languages"
- **未找到**: 具体的中文输入法实现细节
- **推测**: 可能只支持多语言键盘布局，**不支持输入法**（如拼音选词）
- **注意**: 有一个独立的中文输入法项目 `lg11/cute-input-method`，但需要集成

##### 3. 部署要求
```bash
mkdir build && cd build
qmake ..
make -j4
make install
```
- 运行时设置:
  ```cpp
  qputenv("QT_IM_MODULE", QByteArray("cutekeyboard"));
  ```

##### 4. 优缺点

**优点**:
- ✅ **MIT许可证**: 完全免费，可商用
- ✅ **易于定制**: 只需修改一个QML文件
- ✅ **轻量级**: 专为嵌入式系统设计
- ✅ **开源活跃**: 有活跃的维护者
- ✅ **多语言支持**: 支持多种语言的键盘布局

**缺点**:
- ❌ **中文输入法不明确**: 文档未说明是否支持拼音等输入法
- ❌ **导航键支持未知**: 未明确说明箭头键导航支持
- ❌ **功能相对简单**: 相比Qt官方键盘功能较少
- ❌ **社区较小**: 相比Qt官方社区，资源较少

### 方案 C: OpenVirtualKeyboard

#### 基本信息
- **仓库**: https://github.com/pavelhromada/OpenVirtualKeyboard
- **许可证**: MIT（完全免费，可商用）
- **Qt版本支持**: Qt 5.12+（最低版本）
- **特性**: 专注于自定义和灵活性

#### 核心功能

##### 1. 导航键支持 ❓
- **文档未提及**原生箭头键导航支持
- 可通过C++自定义实现

##### 2. 中文输入支持 ❌
- **未提及**中文输入法支持
- 主要专注于键盘布局和样式自定义
- **不支持**: 输入法引擎（如拼音）

##### 3. 部署要求
- 将插件部署到 `platforminputcontexts` 文件夹
- 运行时设置:
  ```cpp
  qputenv("QT_IM_MODULE", QByteArray("openvirtualkeyboard"));
  ```

##### 4. 优缺点

**优点**:
- ✅ **MIT许可证**: 完全免费，可商用
- ✅ **高度可定制**: 每个按键类型都可自定义样式
- ✅ **灵活配置**: 支持多种运行时参数
- ✅ **轻量级**: 无需加载不必要的功能
- ✅ **JavaScript免费**: 键盘处理在C++端完成

**缺点**:
- ❌ **无中文输入法**: 不支持拼音等输入法
- ❌ **无导航键支持**: 未支持箭头键导航
- ❌ **功能有限**: 相比Qt官方键盘功能较少
- ❌ **开发状态**: 项目仍在开发中，功能不完整

## 方案推荐

### 🏆 推荐方案: Qt 官方 Virtual Keyboard (方案 A)

**理由**:
1. ✅ **完全满足需求**:
   - 支持箭头键导航（需启用 `arrow-key-navigation`）
   - 支持回车键确认
   - **完整的中文拼音输入法**（PinyinIME）
2. ✅ **官方支持**: Qt官方维护，稳定可靠
3. ✅ **成熟度高**: 经过大量项目验证
4. ✅ **与你的项目兼容**: 你的项目已经使用Qt，集成简单

**实施步骤**:
1. 下载Qt源码（或使用你现有的Qt安装包）
2. 编译Qt Virtual Keyboard模块:
   ```bash
   cd <qt-source-dir>/qtvirtualkeyboard
   mkdir build && cd build
   <qt-install-dir>/bin/qmake .. CONFIG+=arrow-key-navigation -vkb-enable zh_CN
   make
   make install
   ```
3. 在你的应用中设置环境变量:
   ```cpp
   qputenv("QT_IM_MODULE", QByteArray("qtvirtualkeyboard"));
   ```
4. 在QML中导入虚拟键盘模块:
   ```qml
   import QtQuick.VirtualKeyboard 2.0
   ```

**注意事项**:
- 如果你的项目是**商业项目**，需要考虑Qt许可证问题
- GPL v3要求开源你的项目代码，或购买商业许可证

### 🥈 备选方案: CuteKeyboard (方案 B) + 自定义中文输入法

**适用场景**:
- 项目需要完全免费的MIT许可证
- 可以接受功能有限或需要自行开发

**理由**:
1. ✅ MIT许可证，无限制
2. ✅ 专为嵌入式设计
3. ❓ 中文输入法支持不明确，可能需要集成 `lg11/cute-input-method`
4. ❓ 箭头键导航需要自定义实现

**实施建议**:
1. 先测试CuteKeyboard是否满足基本需求
2. 如果需要中文输入法，考虑集成 `cute-input-method` 项目
3. 自定义实现箭头键导航功能

## 最终建议

### 如果你的项目是:
1. **开源项目** → **选择 Qt 官方 Virtual Keyboard**
2. **商业项目且已购买Qt商业许可** → **选择 Qt 官方 Virtual Keyboard**
3. **商业项目但预算有限** → **考虑 CuteKeyboard + 自定义开发**，或评估购买Qt许可的成本

### 针对你的项目 (RK3588嵌入式系统):
- **强烈推荐**: Qt 官方 Virtual Keyboard
- **理由**: 你的项目是工业控制应用，稳定性和可靠性至关重要，Qt官方方案是最安全的选择
