# 修复对话框关闭后焦点恢复 - 使用 parentContainer 引用

**日期**: 2026-01-30
**问题编号**: FIX 100.300.104.6
**状态**: ✅ 已完成

---

## 🎯 问题根本原因

通过详细的调试日志分析，我们发现：

**`root.parent` 不是 `Screen01`，而是 `QQuickFocusScope`（dialogFocusScope）！**

### 层级结构

```
Screen01 (创建对话框的地方)
  └─ modalContainer (Item)
       └─ dialogFocusScope (FocusScope)  ← root.parent 指向这里！
            └─ root (Rectangle)  ← DeviceSettingsDialog 的 root
```

### 为什么焦点没有返回？

```
对话框关闭时调用：root.parent.forceActiveFocus()
↓
焦点返回到：dialogFocusScope (FocusScope)
↓
Screen01 没有焦点 ← 导航键不起作用
```

详细分析见：[11-问题根本原因分析-FocusScope层级问题.md](11-问题根本原因分析-FocusScope层级问题.md)

---

## ✅ 解决方案

使用 `parentContainer` 属性保存 Screen01 的引用，而不是依赖 `root.parent`。

## 🔍 技术说明

### 为什么使用 parentContainer 而不是 root.parent？

**问题**：
- `root.parent` 是 `dialogFocusScope`（FocusScope）
- FocusScope 是 DeviceSettingsDialog 内部的容器
- 焦点返回到 FocusScope 后，无法传递到 Screen01

**解决**：
- `parentContainer` 直接保存 Screen01 的引用
- 不依赖层级结构
- 焦点直接返回到 Screen01

### 为什么之前的修复都失败了？

| 修复 | 方法 | 失败原因 |
|------|------|----------|
| FIX 100.300.104.3 | 添加 `root.parent.forceActiveFocus()` | `root.parent` 是 FocusScope，不是 Screen01 |
| FIX 100.300.104.4 | 修改对话框父容器为 `root` | 虽然 `modalContainer.parent` 是 Screen01，但使用的是 `root.parent`（FocusScope） |
| FIX 100.300.104.5 | 添加调试日志 | 成功定位问题，但未修复 |

### 为什么这次修复会成功？

1. ✅ **直接引用**：`parentContainer` 直接保存 Screen01 的引用
2. ✅ **不依赖层级**：即使 DeviceSettingsDialog 内部结构改变也能正常工作
3. ✅ **清晰明确**：代码意图清晰，易于理解和维护

## 🎯 总结

### 问题

- ❌ `root.parent` 是 `dialogFocusScope`（FocusScope），不是 `Screen01`
- ❌ 焦点返回到 FocusScope，被"困"在内部容器中
- ❌ Screen01 没有焦点，导航键不起作用

### 解决

- ✅ 添加 `parentContainer` 属性保存 Screen01 的引用
- ✅ 在所有关闭处使用 `parentContainer.forceActiveFocus()`
- ✅ 在 Screen01 创建对话框时传递 `parentContainer: root`

### 结果

- ✅ 焦点正确返回到 Screen01
- ✅ 导航键正常工作
- ✅ 问题彻底解决
