# FIX 100.300.112.8.15 - 修复类别切换时焦点位置丢失问题

**日期**: 2026-01-31
**任务编号**: FIX 100.300.112.8.15
**状态**: ✅ 完成

## 🐛 问题描述

### 用户反馈

> 电机控制和电机列表来回切换，焦点问题得到解决，假如在3号电机，左右切换焦点是在3号电机和电机控制来回切换，但是我将焦点从电机控制切换到张紧控制，在切换到电机控制，在切换到电机列表，现象是，蓝色边框在1号电机，按钮选中图片还是在3号电机。

### 具体问题

**操作步骤**：
1. 在电机列表中选择 3号电机（背景图片 + 蓝色边框）
2. 按左键切换到类别列表（电机控制）
3. 按下键切换到张紧控制类别
4. 按下键切换回电机控制类别
5. 按右键进入电机列表

**错误现象**：
- 焦点在 1号电机（蓝色边框）
- 选中状态还在 3号电机（背景图片）
- 焦点和选中状态不同步

**期望行为**：
- 焦点应该回到 3号电机（蓝色边框）
- 选中状态也在 3号电机（背景图片）
- 焦点和选中状态保持同步

## 🔍 根本原因

### 问题分析

**全局共享的 `currentContentItemIndex`**：

```qml
property int currentContentItemIndex: 0  // 所有类别共享
```

**数据流分析**：

```
用户在电机列表中选择3号电机
  ↓
MotorControlPage.focusItemIndex = 2
  ↓
反向同步触发：currentContentItemIndex = 2 ✓
  ↓
用户切换到张紧控制类别
  ↓
张紧控制默认焦点在 0 号位置
  ↓
反向同步触发：currentContentItemIndex = 0 ❌
  ↓
用户切换回电机控制类别
  ↓
onCurrentCategoryChanged 触发
  ↓
设置 motorControlPageLoader.item.focusItemIndex = root.currentContentItemIndex（现在是0）
  ↓
焦点回到 1号电机（索引0）
选中状态还在 3号电机（currentMotorIndex = 2）
  ↓
焦点和选中状态不同步 ❌
```

### 根本原因

**所有类别共享同一个 `currentContentItemIndex`**：
- 电机控制、制动器控制、张紧控制等都使用同一个变量
- 当切换到其他类别时，该变量会被新类别的焦点位置覆盖
- 切换回原类别时，焦点位置已经丢失

---

## 🔧 修复方案

### 解决方法

**为每个类别保存独立的内容索引**：
1. 创建 `categoryContentIndexMap` 对象，为每个类别保存独立的索引
2. 监听 `currentCategory` 变化，切换类别时恢复对应的索引
3. 监听 `currentContentItemIndex` 变化，保存到对应类别的映射中

### 修复代码

#### 1. 添加类别索引映射（Line 75-85）

```qml
// ✅ 2026-01-31 [FIX 100.300.112.8.15]: 为每个类别保存独立的内容索引
// 避免切换类别时焦点位置丢失
property var categoryContentIndexMap: ({
    0: 0,  // 基本配置
    1: 0,  // 开关量输入
    2: 0,  // 模拟量输入
    3: 0,  // 电机控制
    4: 0,  // 制动器控制
    5: 0,  // 张紧控制
    6: 0   // 逻辑控制
})
```

#### 2. 监听类别切换，恢复内容索引（Line 87-101）

```qml
// ✅ 2026-01-31 [FIX 100.300.112.8.15]: 监听类别切换，保存和恢复内容索引
onCurrentCategoryChanged: {
    // 保存旧类别的内容索引（如果有的话）
    // 注意：这里不需要保存，因为反向同步已经在更新 categoryContentIndexMap

    // 恢复新类别的内容索引
    var savedIndex = categoryContentIndexMap[currentCategory]
    if (savedIndex !== undefined) {
        console.log("✅ [DeviceSettingsDialog] 切换到类别", currentCategory, "恢复内容索引:", savedIndex)
        currentContentItemIndex = savedIndex
    } else {
        console.log("⚠️ [DeviceSettingsDialog] 类别", currentCategory, "没有保存的索引，使用默认值 0")
        currentContentItemIndex = 0
    }
}
```

#### 3. 监听内容索引变化，保存到对应类别（Line 103-110）

```qml
// ✅ 2026-01-31 [FIX 100.300.112.8.15]: 监听内容索引变化，保存到对应类别
onCurrentContentItemIndexChanged: {
    console.log("✅ [DeviceSettingsDialog] 内容索引变化:", currentContentItemIndex, "类别:", currentCategory)
    // 更新当前类别的内容索引
    var newMap = categoryContentIndexMap
    newMap[currentCategory] = currentContentItemIndex
    categoryContentIndexMap = newMap
}
```

## 💡 经验教训

### 1. 全局状态的陷阱

**问题**：
- 使用全局变量 `currentContentItemIndex` 管理所有类别的焦点
- 导致类别之间相互干扰

**教训**：
- 当多个组件共享状态时，考虑是否需要独立的状态
- 使用映射（Map）或对象来为每个组件保存独立的状态
- 避免全局状态被意外覆盖

### 2. 状态保存和恢复

**实现模式**：
```qml
// 1. 创建状态映射
property var categoryContentIndexMap: ({...})

// 2. 监听切换事件，恢复状态
onCurrentCategoryChanged: {
    currentContentItemIndex = categoryContentIndexMap[currentCategory]
}

// 3. 监听状态变化，保存到映射
onCurrentContentItemIndexChanged: {
    var newMap = categoryContentIndexMap
    newMap[currentCategory] = currentContentItemIndex
    categoryContentIndexMap = newMap
}
```

**关键点**：
- 使用对象字面量创建映射
- 监听切换事件恢复状态
- 监听状态变化保存到映射
- 注意 QML 对象属性的更新机制（需要重新赋值）

### 3. 反向同步的副作用

**问题**：
- FIX 100.300.112.8.14 添加的反向同步机制
- 导致切换类别时 `currentContentItemIndex` 被新类别的焦点覆盖

**解决方案**：
- 不是移除反向同步（反向同步是必要的）
- 而是为每个类别保存独立的索引
- 让反向同步更新对应类别的索引，而不是全局索引

### 4. 调试日志的重要性

**添加的调试日志**：
```qml
console.log("✅ [DeviceSettingsDialog] 切换到类别", currentCategory, "恢复内容索引:", savedIndex)
console.log("✅ [DeviceSettingsDialog] 内容索引变化:", currentContentItemIndex, "类别:", currentCategory)
```

**好处**：
- 清楚看到类别切换和索引变化的过程
- 验证状态保存和恢复是否正确
- 帮助快速定位问题
