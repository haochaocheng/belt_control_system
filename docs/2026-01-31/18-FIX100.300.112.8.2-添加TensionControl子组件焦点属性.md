
## 🔍 根本原因

### 问题分析

**TensionControlPage.qml 的 Loader onLoaded**（Line 374-386, 403-411）：

```qml
// 控制列表 Loader
onLoaded: {
    item.currentControlIndex = Qt.binding(function() { return navigationManager.controlListIndex })
    item.focusItemIndex = Qt.binding(function() { return root.focusItemIndex })  // ❌ 属性不存在
    item.focusSubArea = Qt.binding(function() { return root.focusSubArea })      // ❌ 属性不存在
    // ...
}

// 配置面板 Loader
onLoaded: {
    item.controlIndex = Qt.binding(function() { return root.currentControlIndex })
    item.focusSubArea = Qt.binding(function() { return root.focusSubArea })                          // ❌ 属性不存在
    item.focusUsageStatusIndex = Qt.binding(function() { return navigationManager.usageStatusIndex }) // ❌ 属性不存在
    item.focusParamIndex = Qt.binding(function() { return root.focusParamIndex })                    // ❌ 属性不存在
    item.focusButtonIndex = Qt.binding(function() { return root.focusButtonIndex })                  // ❌ 属性不存在
    item.virtualKeyboard = Qt.binding(function() { return root.virtualKeyboard })                    // ❌ 属性不存在
}
```

**问题**：
- TensionControlPage 尝试将焦点属性传递给子组件
- 但 TensionControlListPanel 和 TensionControlConfigPanel 缺少这些属性
- 导致属性绑定失败，焦点指示器无法显示


## 💡 经验教训

### 1. 属性传递的完整性

**问题**：
- 父组件尝试传递属性给子组件
- 但子组件缺少这些属性
- 导致绑定失败

**教训**：
- 复制页面时要检查所有属性
- 确保子组件有父组件传递的所有属性
- 参考已有的正确实现（BrakeControlPage）

### 2. 焦点指示器的实现模式

**标准模式**：
```qml
// 1. 在组件中定义属性
property int focusItemIndex: -1
property int focusSubArea: 0

// 2. 在 delegate 中添加焦点指示器
Rectangle {
    anchors.fill: parent
    color: "transparent"
    border.color: (root.focusSubArea === 0 && root.focusItemIndex === index) ? "#2196F3" : "transparent"
    border.width: (root.focusSubArea === 0 && root.focusItemIndex === index) ? 3 : 0
    radius: 4
    z: 10
}
```

**关键点**：
- 必须同时检查 focusSubArea 和 focusItemIndex
- 确保只在当前区域显示焦点
- z: 10 确保焦点边框在最上层

### 3. 属性命名的一致性

**保持一致**：
- TensionControlListPanel.focusItemIndex（与 BrakeListPanel 一致）
- TensionControlConfigPanel.focusSubArea（与 BrakeConfigPanel 一致）
- 所有焦点属性命名保持统一

**好处**：
- 易于理解和维护
- 减少错误
- 代码风格统一

### 4. 测试的重要性

**问题发现**：
- 代码修改后没有完整测试
- 只测试了主页面，没有测试子组件
- 用户测试时才发现焦点不显示

**教训**：
- 每次修改后都要完整测试
- 测试所有导航路径
- 检查焦点指示器是否正常显示
