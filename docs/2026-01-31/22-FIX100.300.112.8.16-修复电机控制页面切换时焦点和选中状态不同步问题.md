## 🐛 问题描述

### 用户反馈

> 还是没有，我只描述从制动器控制切换到电机控制现象，之前还是选择的3号电机，从制动器控制切换到电机控制是，电机列表显示是这样的，1号电机只有背景图片被选中状态，3号电机只有蓝色边框，按向下键，背景图片和蓝色边框都在2号电机。

### 具体问题

**操作步骤**：
1. 在电机列表中选择 3号电机（背景图片 + 蓝色边框）
2. 按左键切换到类别列表
3. 按下键切换到制动器控制类别
4. 按下键切换回电机控制类别
5. 按右键进入电机列表

**错误现象**：
- 1号电机有背景图片（选中状态，`currentMotorIndex = 0`）
- 3号电机有蓝色边框（焦点状态，`focusItemIndex = 2`）
- 焦点和选中状态分离 ❌
- 按下键后，2号电机才同时有背景图片和蓝色边框

**期望行为**：
- 3号电机应该同时有背景图片和蓝色边框
- 焦点和选中状态应该在同一个电机上

---

## 🔍 根本原因

### 问题分析

**MotorControlPage 缺少 `onFocusItemIndexChanged` 监听器**：

```qml
// ❌ MotorControlPage.qml（修复前）
property int currentMotorIndex: 0
property int focusItemIndex: -1

// 没有监听 focusItemIndex 变化来同步 currentMotorIndex
```

**数据流分析**：

```
用户在电机列表中选择3号电机
  ↓
MotorControlPage.currentMotorIndex = 2 ✓
MotorControlPage.focusItemIndex = 2 ✓
  ↓
反向同步触发：DeviceSettingsDialog.currentContentItemIndex = 2 ✓
  ↓
保存到映射：categoryContentIndexMap[3] = 2 ✓
  ↓
用户切换到制动器控制类别
  ↓
MotorControlPage 被卸载（Loader.active = false）
  ↓
用户切换回电机控制类别
  ↓
MotorControlPage 重新加载（Loader.active = true）
  ↓
Component.onCompleted 触发
  ↓
初始化：currentMotorIndex = 0 ❌（重置为0）
初始化：focusItemIndex = 0 ❌（重置为0）
  ↓
DeviceSettingsDialog.onCurrentCategoryChanged 触发
  ↓
恢复：currentContentItemIndex = categoryContentIndexMap[3] = 2 ✓
  ↓
设置：motorControlPageLoader.item.focusItemIndex = 2 ✓
  ↓
但是 currentMotorIndex 仍然是 0 ❌（没有同步）
  ↓
结果：
- focusItemIndex = 2（3号电机有蓝色边框）✓
- currentMotorIndex = 0（1号电机有背景图片）❌
  ↓
焦点和选中状态不同步 ❌
```

### 根本原因

**MotorControlPage 没有监听 `focusItemIndex` 变化**：
- 当 DeviceSettingsDialog 恢复 `focusItemIndex` 时
- MotorControlPage 的 `currentMotorIndex` 没有同步更新
- 导致焦点状态（蓝色边框）和选中状态（背景图片）分离

**对比其他页面**：
- BrakeControlPage 有 `onFocusItemIndexChanged` 监听器 ✓
- TensionControlPage 有 `onFocusItemIndexChanged` 监听器 ✓
- MotorControlPage 缺少这个监听器 ❌

---

## 🔧 修复方案

### 解决方法

**为 MotorControlPage 添加 `onFocusItemIndexChanged` 监听器**：
- 监听 `focusItemIndex` 变化
- 同步更新 `currentMotorIndex` 和 `navigationManager.motorListIndex`
- 确保焦点状态和选中状态始终一致

### 修复代码

#### MotorControlPage.qml（Line 35-43）

```qml
// ✅ 2026-01-31 [FIX 100.300.112.8.16]: 监听 focusItemIndex 变化，同步到 currentMotorIndex
// 当 DeviceSettingsDialog 恢复焦点位置时，同步更新选中状态
onFocusItemIndexChanged: {
    if (focusSubArea === 0 && focusItemIndex >= 0 && focusItemIndex < 8) {
        console.log("✅ [MotorControlPage] focusItemIndex 变化:", focusItemIndex, "→ 同步 currentMotorIndex")
        currentMotorIndex = focusItemIndex
        navigationManager.motorListIndex = focusItemIndex
    }
}
```

## 💡 经验教训

### 1. 组件重新加载的状态丢失

**问题**：
- 使用 Loader 的 `active` 属性动态加载组件
- 当 `active = false` 时，组件被卸载，状态丢失
- 当 `active = true` 时，组件重新加载，状态重置

**教训**：
- 组件重新加载时，需要恢复之前的状态
- 使用 `onFocusItemIndexChanged` 等监听器同步状态
- 不能依赖 `Component.onCompleted` 的初始化值

### 2. 双向同步的完整性

**需要的同步机制**：
1. **正向同步**：DeviceSettingsDialog → MotorControlPage
   - `onCurrentCategoryChanged` 恢复 `focusItemIndex`
2. **反向同步**：MotorControlPage → DeviceSettingsDialog
   - `onFocusItemIndexChanged` 更新 `currentContentItemIndex`
3. **内部同步**：MotorControlPage 内部状态同步
   - `onFocusItemIndexChanged` 同步 `currentMotorIndex` ✅（本次修复）

**缺一不可**：
- 只有正向和反向同步，没有内部同步 → 焦点和选中状态分离 ❌
- 三个同步机制都完整 → 状态完全同步 ✅

### 3. 一致性检查

**检查清单**：
- ✅ BrakeControlPage 有 `onFocusItemIndexChanged` 监听器
- ✅ TensionControlPage 有 `onFocusItemIndexChanged` 监听器
- ❌ MotorControlPage 缺少 `onFocusItemIndexChanged` 监听器（本次修复）

**教训**：
- 发现一个页面的问题，检查其他类似页面
- 保持代码模式的一致性
- 使用相同的同步机制

### 4. 调试日志的价值

**添加的调试日志**：
```qml
console.log("✅ [MotorControlPage] focusItemIndex 变化:", focusItemIndex, "→ 同步 currentMotorIndex")
```

**好处**：
- 清楚看到状态同步的过程
- 验证修复是否生效
- 帮助快速定位问题
