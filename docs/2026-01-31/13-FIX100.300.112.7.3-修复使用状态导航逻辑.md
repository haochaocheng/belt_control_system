# FIX 100.300.112.7.3 - 修复使用状态导航逻辑

## 🐛 问题描述

### 用户反馈

> 对于使用状态有两个选项投入和禁用，使用导航键怎么操作最好，蓝色边框应该包含整个使用状态，而不是投入和禁用两个都有，这两个是参数的可选项。而且目前的状态是，向右可以，但是总禁用焦点向左无法移动

### 具体问题

1. **设计问题**：
   - 当前设计：使用状态区域有两个独立的焦点项（投入、禁用）
   - 用户期望：整个使用状态区域作为一个焦点单元
   - "投入"和"禁用"应该是参数的可选项，不是独立的导航项

2. **导航问题**：
   - 右键：在投入/禁用之间切换（错误）
   - 应该：右键进入参数区域

3. **焦点指示器问题**：
   - 当前：投入和禁用各有一个蓝色边框
   - 应该：整个使用状态区域只有一个蓝色边框

---

## 🔍 根本原因

### 设计理念错误

**错误理解**：
- 将"投入"和"禁用"视为两个独立的导航项
- 使用 `usageStatusIndex` (0/1) 在两个选项之间导航
- 右键切换选项，回车键选中

**正确理解**：
- 整个"使用状态"是一个参数字段
- "投入"和"禁用"是这个参数的两个可选值
- 应该像其他参数字段一样：
  - 左键：返回列表
  - 右键：进入下一个参数
  - 回车键：切换选项值

### 数据流问题

**修复前**：
```
使用状态区域（两个独立焦点项）
  ├─ 投入（索引0）← 右键切换 → 禁用（索引1）
  └─ 各自有独立的焦点指示器
```

**修复后**：
```
使用状态区域（一个焦点单元）
  ├─ 整个区域有一个焦点指示器
  ├─ 左键：返回制动器列表
  ├─ 右键：进入参数区域
  ├─ 下键：进入参数区域
  └─ 回车键：切换投入/禁用
```

## 🔧 修复方案

### 解决方法

**三个关键修改**：
1. 修改焦点指示器：整个区域一个边框（已在 FIX 100.300.112.7.3 前期完成）
2. 修改导航逻辑：右键进入参数区域，不再切换选项
3. 修改回车键处理：切换 RadioButton 选项

**修复后**：
```qml
// ✅ 2026-01-31 [FIX 100.300.112.7.3]: 已废弃，改用 toggleUsageStatus()
// function triggerUsageStatus(usageStatusIndex) { ... }

// ✅ 2026-01-31 [FIX 100.300.112.7.3]: 切换使用状态（投入 ↔ 禁用）
function toggleUsageStatus() {
    console.log("✅ [BrakeConfigPanel] 切换使用状态")

    if (statusEnabled.checked) {
        // 当前是投入，切换到禁用
        statusDisabled.checked = true

        console.log("✅ [BrakeConfigPanel] 切换为：投入")
    }
}
```

## 💡 经验教训

### 1. 设计理念的重要性

**问题**：
- 将"投入"和"禁用"视为两个独立的导航项
- 导致复杂的导航逻辑和不符合用户期望的行为

**正确理解**：
- "使用状态"是一个参数字段
- "投入"和"禁用"是这个字段的两个可选值
- 应该像其他参数字段一样处理

**教训**：
- 在实现导航逻辑前，先理解用户的心智模型
- 参数字段的可选值不应该是独立的导航项
- 保持导航逻辑的一致性

### 2. 焦点指示器的设计

**原则**：
- 一个焦点单元 = 一个焦点指示器
- 不要为同一个逻辑单元的子元素创建多个焦点指示器

**模式**：
```qml
// ✅ 正确：整个区域一个焦点指示器
Item {
    // 包含多个子元素
    RowLayout {
        RadioButton { id: option1 }
        RadioButton { id: option2 }
    }

    // 一个焦点指示器覆盖整个区域
    Rectangle {
        anchors.fill: parent
        border.color: (focused) ? "#2196F3" : "transparent"
    }
}
```

### 3. 导航逻辑的简化

**修复前**：
- 需要跟踪 `usageStatusIndex` (0/1)
- 需要在两个选项之间切换
- 需要处理边界条件

**修复后**：
- 不需要跟踪索引
- 直接切换 RadioButton 状态
- 逻辑更简单

**教训**：
- 如果导航逻辑很复杂，可能是设计有问题
- 简化设计可以简化实现

**关键洞察**：
- 用户明确指出了设计问题

## 🎯 最终导航架构

### 使用状态区域导航

```
使用状态区域（一个焦点单元）
  ├─ 焦点指示器：整个区域一个蓝色边框
  ├─ 左键：返回制动器列表
  ├─ 右键：进入参数区域
  ├─ 下键：进入参数区域
  └─ 回车键：切换投入/禁用选项
```

### 完整导航流程

```
制动器列表（区域0）
  ↓ 右键
使用状态（区域1）← 一个焦点单元
  ├─ 左键 → 返回制动器列表
  ├─ 右键 → 进入参数区域
  ├─ 下键 → 进入参数区域
  └─ 回车 → 切换投入/禁用
  ↓ 右键/下键
参数区域（区域2）
  ├─ 左键（左列）→ 返回使用状态
  ├─ 上键（第一行）→ 返回使用状态
  └─ 下键 → 进入按钮区域
  ↓ 下键
按钮区域（区域3）
  ├─ 左键（第一个）→ 返回使用状态
  └─ 上键 → 返回参数区域
```

### 关键设计原则

1. **一个参数字段 = 一个焦点单元**
2. **可选值不是独立的导航项**
3. **回车键用于切换/编辑参数值**
4. **方向键用于在焦点单元之间导航**
