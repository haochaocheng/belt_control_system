## 🐛 问题描述

### 用户反馈

> 第一次从电机控制切换到电机列表，1号电机背景和蓝色边框都可以看到，按下键，例如切换到3号电机时，这个时候焦点在三号电机，背景和蓝色边框都是三号电机，继续按左键切换到电机控制，此时电机列表3号电机背景图片是选中状态，焦点是电机控制蓝色边框和电机控制选中背景，继续按右键后，测试电机列表内1号电机只有蓝色边框，没有背景选择的图片，3号电机是背景选择的图片，没有蓝框。

### 问题澄清

用户澄清："问题描述错误，只是在电机控制和电机列表来回切换，没有进入参数区域"

### 具体问题

**操作步骤**：
1. 在电机列表中选择 3号电机（背景图片 + 蓝色边框）
2. 按左键切换到类别列表（电机控制）
3. 按右键返回电机列表

**错误现象**：
- 焦点回到 1号电机（蓝色边框）
- 选中状态还在 3号电机（背景图片）
- 焦点和选中状态不同步

**期望行为**：
- 焦点应该回到 3号电机（蓝色边框）
- 选中状态也在 3号电机（背景图片）
- 焦点和选中状态保持同步

## 🔍 根本原因

### 初步修复尝试（FIX 100.300.112.8.13）

**修改**：注释掉 DeviceSettingsDialog.qml Line 561 的 `currentContentItemIndex = 0`

**结果**：用户反馈"问题现象依旧"

### 深入分析

**问题根源**：缺少反向同步机制

**数据流分析**：

```
用户在电机列表中导航（选择3号电机）
  ↓
MotorControlPage.currentMotorIndex = 2 ✓
MotorControlPage.focusItemIndex = 2 ✓
DeviceSettingsDialog.currentContentItemIndex = 0 ✗（没有同步）
  ↓
用户按左键切换到类别列表
  ↓
焦点离开电机列表，currentContentItemIndex 仍然是 0
  ↓
用户按右键返回电机列表
  ↓
DeviceSettingsDialog 设置：
motorControlPageLoader.item.focusItemIndex = root.currentContentItemIndex（仍然是0）
  ↓
焦点回到 1号电机（索引0）
选中状态还在 3号电机（currentMotorIndex = 2）
  ↓
焦点和选中状态不同步 ❌
```

### 现有同步机制（单向）

**DeviceSettingsDialog.qml Line 1329-1368**：

```qml
// ✅ 2026-01-30 [FIX 100.300.106]: MotorControlPage 焦点同步
Connections {
    target: root
    enabled: motorControlPageLoader.item !== null

    function onCurrentFocusAreaChanged() {
        if (motorControlPageLoader.item && root.currentCategory === 3) {
            if (root.currentFocusArea === 2) {
                // 焦点进入内容区域，默认在电机列表区域
                motorControlPageLoader.item.focusSubArea = 0
                motorControlPageLoader.item.focusItemIndex = root.currentContentItemIndex
            } else {
                // 焦点离开内容区域，清除焦点
                motorControlPageLoader.item.focusItemIndex = -1
            }
        }
    }

    function onCurrentContentItemIndexChanged() {
        if (motorControlPageLoader.item &&
            root.currentFocusArea === 2 &&
            root.currentCategory === 3) {
            // 在电机列表中导航
            motorControlPageLoader.item.focusItemIndex = root.currentContentItemIndex
        }
    }
}
```

**问题**：
- 只有从 DeviceSettingsDialog → MotorControlPage 的同步
- 没有从 MotorControlPage → DeviceSettingsDialog 的反向同步
- 当用户在电机列表中导航时，`currentContentItemIndex` 不会更新

## 🔧 修复方案

### 解决方法

**添加反向同步机制**：监听 MotorControlPage 的 `focusItemIndex` 变化，同步更新 DeviceSettingsDialog 的 `currentContentItemIndex`

### 修复代码

#### 1. 电机控制页面（MotorControlPage）

**DeviceSettingsDialog.qml Line 1370-1387**：

```qml
// ✅ 2026-01-31 [FIX 100.300.112.8.14]: MotorControlPage 反向焦点同步（从 Page 到 Dialog）
// 当用户在电机列表中导航时，同步更新 Dialog 的 currentContentItemIndex
// 这样当焦点离开再返回时，能恢复到正确的位置
Connections {
    target: motorControlPageLoader.item
    enabled: motorControlPageLoader.item !== null

    function onFocusItemIndexChanged() {
        if (root.currentCategory === 3 &&
            root.currentFocusArea === 2 &&
            motorControlPageLoader.item.focusSubArea === 0 &&
            motorControlPageLoader.item.focusItemIndex >= 0) {
            // 只在焦点在电机列表区域时同步
            console.log("✅ [DeviceSettingsDialog] 同步电机列表焦点:", motorControlPageLoader.item.focusItemIndex)
            root.currentContentItemIndex = motorControlPageLoader.item.focusItemIndex
        }
    }
}
```

## 💡 经验教训

### 1. 双向同步的重要性

**问题**：
- 只实现了单向同步（从父组件到子组件）
- 忽略了反向同步（从子组件到父组件）

**教训**：
- 当父子组件共享状态时，需要双向同步
- 父组件需要知道子组件的状态变化
- 使用 Connections 监听子组件的属性变化

### 2. 状态管理的一致性

**问题**：
- `currentContentItemIndex` 和 `focusItemIndex` 不同步
- 导致焦点恢复时使用了错误的索引

**教训**：
- 确保所有相关状态保持一致
- 当一个状态变化时，同步更新其他相关状态
- 使用调试日志验证状态同步

### 3. 条件判断的完整性

**反向同步条件**：
```qml
if (root.currentCategory === 3 &&
    root.currentFocusArea === 2 &&
    motorControlPageLoader.item.focusSubArea === 0 &&
    motorControlPageLoader.item.focusItemIndex >= 0) {
    // 只在焦点在电机列表区域时同步
    root.currentContentItemIndex = motorControlPageLoader.item.focusItemIndex
}
```

**关键条件**：
- `currentCategory === 3`：确保在电机控制类别
- `currentFocusArea === 2`：确保焦点在内容区域
- `focusSubArea === 0`：确保焦点在列表区域（不是参数区域）
- `focusItemIndex >= 0`：确保有有效的焦点索引

**教训**：
- 条件判断要完整，避免误触发
- 只在正确的场景下同步状态
- 使用调试日志验证条件判断

### 4. 一致性修复

**问题**：
- 电机控制、制动器控制、张紧控制使用相同的模式
- 需要为所有页面添加相同的反向同步

**教训**：
- 发现一个页面的问题，检查其他类似页面
- 保持代码模式的一致性
- 统一修复所有相关页面

**正向同步（Dialog → Page）**：
