## 🐛 问题描述

### 用户反馈

> 在制动器列表，下键无法切换焦点

### 具体问题

1. **在制动器列表中按下键**：
   - 焦点不切换
   - 焦点指示器不移动
   - 无法导航到其他制动器

2. **上键也有同样问题**：
   - 焦点不切换
   - 无法返回上一个制动器

---

## 🔍 根本原因

### 问题分析

**BrakeListPanel.qml** 有自己的键盘导航逻辑（Line 31-43）：
```qml
Keys.onUpPressed: {
    if (root.currentBrakeIndex > 0) {
        root.currentBrakeIndex--
        brakeSelected(root.currentBrakeIndex)
    }
}

Keys.onDownPressed: {
    if (root.currentBrakeIndex < 7) {
        root.currentBrakeIndex++
        brakeSelected(root.currentBrakeIndex)
    }
}
```

**但是**，BrakeControlPage 已经通过 NavigationManager 处理所有键盘事件了（Line 230-274）。

### 冲突原因

1. **BrakeControlPage 的 `focus: true` 捕获了所有键盘事件**
   - BrakeListPanel 的键盘处理器永远不会被触发

2. **NavigationManager 正确更新了 `brakeListIndex`**
   - `navigationManager.brakeListIndex` 从 0 变为 1

3. **但 BrakeListPanel 的 `currentBrakeIndex` 没有同步**
   - `item.currentBrakeIndex` 绑定到 `root.currentBrakeIndex`
   - 而 `root.currentBrakeIndex` 只在鼠标点击时更新
   - NavigationManager 更新的是 `navigationManager.brakeListIndex`
   - 两者没有同步

### 数据流问题

**修复前**：
```
NavigationManager.brakeListIndex 变化 (0 → 1)
  ↓
root.currentBrakeIndex 不变 (仍然是 0) ❌
  ↓
BrakeListPanel.currentBrakeIndex 不变 (仍然是 0) ❌
  ↓
焦点指示器不移动 ❌
```

**修复后**：
```
NavigationManager.brakeListIndex 变化 (0 → 1)
  ↓
BrakeListPanel.currentBrakeIndex 直接绑定到 navigationManager.brakeListIndex ✅
  ↓
BrakeListPanel.currentBrakeIndex 变化 (0 → 1) ✅
  ↓
焦点指示器移动 ✅
```

---

## 🔧 修复方案

### 解决方法

**将 BrakeListPanel.currentBrakeIndex 绑定到 navigationManager.brakeListIndex**

### 修复代码

**BrakeControlPage.qml（修复前）**：
```qml
onLoaded: {
    item.currentBrakeIndex = Qt.binding(function() { return root.currentBrakeIndex })
    // ...
}
```

**BrakeControlPage.qml（修复后）**：
```qml
onLoaded: {
    // ✅ 2026-01-31 [FIX 100.300.112.3]: 绑定到 navigationManager.brakeListIndex 而不是 root.currentBrakeIndex
    // 这样 NavigationManager 的导航逻辑才能正确更新列表焦点
    item.currentBrakeIndex = Qt.binding(function() { return navigationManager.brakeListIndex })
    // ...
}
```

## 💡 经验教训

### 1. 属性绑定的重要性

**问题**：
- 多个组件需要同步同一个状态
- 如果绑定到中间变量，可能导致同步失败

**解决**：
```qml
// ❌ 错误：绑定到中间变量
item.currentBrakeIndex = Qt.binding(function() { return root.currentBrakeIndex })

// ✅ 正确：直接绑定到源变量
item.currentBrakeIndex = Qt.binding(function() { return navigationManager.brakeListIndex })
```

### 2. NavigationManager 模式

**原则**：
- NavigationManager 是唯一的导航状态源
- 所有子组件应该直接绑定到 NavigationManager 的属性
- 不要通过中间变量传递状态

**模式**：
```qml
NavigationManager {
    property int brakeListIndex: 0  // 唯一的状态源
}

// 子组件直接绑定
item.currentBrakeIndex = Qt.binding(function() {
    return navigationManager.brakeListIndex
})
```

### 3. 调试技巧

**问题定位**：
1. 检查 NavigationManager 的状态是否更新
2. 检查子组件的属性是否同步
3. 检查属性绑定是否正确

**日志输出**：
```qml
onBrakeListIndexChanged: {
    console.log("✅ [NavigationManager] brakeListIndex 变化:", brakeListIndex)
}

onCurrentBrakeIndexChanged: {
    console.log("✅ [BrakeListPanel] currentBrakeIndex 变化:", currentBrakeIndex)
}
```

### 4. 键盘事件处理

**问题**：
- 多个组件都有键盘处理器
- 只有获得焦点的组件才能处理键盘事件

**解决**：
- 在父组件统一处理键盘事件（BrakeControlPage）
- 子组件不需要自己的键盘处理器（BrakeListPanel）
- 通过属性绑定同步状态

## 📝 修改详情

### BrakeControlPage.qml

**修改位置**：Line 300-302

**修改内容**：
```qml
onLoaded: {
    // ✅ 2026-01-31 [FIX 100.300.112.3]: 绑定到 navigationManager.brakeListIndex 而不是 root.currentBrakeIndex
    // 这样 NavigationManager 的导航逻辑才能正确更新列表焦点

    })
}
```
