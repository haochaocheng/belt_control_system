## 🐛 问题描述

### 用户反馈

> 在qds测试完成，问题得到解决，现在部署到设备后，发现使用导航键可以切换主界面，但是在切换到第五个界面后，这个时候导航键就不能在4*3每一个组件切换，在QDS运行时，第一个主界面就是input界面，使用导航键可以切换到任意4*3的组件，但是在设备部署后就不行了，voip.md是调试日志，找出在input界面无法使用导航键，无法选择，默认选择的是input第一个组件，但是按回车键，也无法弹出弹窗。

### 具体问题

**QDS 测试环境**：
- Input1Page 是第一个主界面
- 导航键可以在 4x3 组件中切换 ✓
- 按回车键可以弹出弹窗 ✓

**设备部署环境**：
- Input1Page 是第五个界面（索引4）
- 使用导航键可以切换主界面（左右键） ✓
- 切换到 Input1Page 后，导航键无法在 4x3 组件中切换 ❌
- 按回车键无法弹出弹窗 ❌
- 默认选择的是第一个组件，但无法操作

### 问题分析

**焦点管理问题**：

```
Screen01 加载完成
  ↓
Component.onCompleted 触发
  ↓
Screen01.forceActiveFocus() ✓（获得焦点）
  ↓
App.qml 的 Keys.onPressed 处理键盘事件
  ↓
App 获得焦点（因为它处理了键盘事件）
  ↓
Screen01 失去焦点 ❌
  ↓
导航键事件被 App 处理（切换页面）
Screen01 无法接收导航键事件 ❌
  ↓
无法在 4x3 组件中切换 ❌
无法按回车键弹出弹窗 ❌
```

### 根本原因

**App.qml 的 `Keys.onPressed` 抢夺了焦点**：
- App.qml 处理左右键来切换页面
- 当 Screen01 加载完成并获得焦点后
- 用户按左右键切换到 Input1Page
- App.qml 处理了键盘事件，焦点转移到 App
- Screen01 失去焦点，无法接收后续的键盘事件

**QDS 测试环境 vs 设备部署环境**：
- **QDS 测试**：Input1Page 是第一个页面，直接加载，Screen01 获得焦点并保持 ✓
- **设备部署**：Input1Page 是第五个页面，需要切换才能到达，切换过程中焦点被 App 抢夺 ❌

## 🔧 修复方案

### 解决方法

**在 SwipeView 切换到 Input1Page 时，恢复 Screen01 的焦点**：
1. 监听 SwipeView 的 `onCurrentIndexChanged` 事件
2. 当切换到 Input1Page（索引4）时
3. 使用 `Qt.callLater` 延迟执行（确保页面已完全加载）
4. 找到 Screen01 并调用 `forceActiveFocus()`

### 修复代码

#### App.qml（Line 170-192）

```qml
// SwipeView for pages (full screen)
SwipeView {
    id: swipeView
    anchors.fill: parent
    currentIndex: 0

    // ✅ 2026-01-31 [FIX 100.300.112.8.17]: 监听页面切换，恢复焦点
    onCurrentIndexChanged: {
        console.log("[SwipeView] 页面切换到索引:", currentIndex)

        // 当切换到 Input1Page（索引4）时，将焦点转移到 Screen01
        if (currentIndex === 4) {
            console.log("[SwipeView] 切换到 Input1Page，恢复 Screen01 焦点")
            Qt.callLater(function() {
                var input1Page = swipeView.itemAt(4)
                if (input1Page && input1Page.children[0]) {
                    var screenLoader = input1Page.children[0]
                    if (screenLoader && screenLoader.item) {
                        console.log("[SwipeView] 找到 Screen01，强制获取焦点")
                        screenLoader.item.forceActiveFocus()
                    } else {
                        console.warn("[SwipeView] ⚠️ Screen01 未加载")
                    }
                } else {
                    console.warn("[SwipeView] ⚠️ Input1Page 未找到")
                }
            })
        }
    }

    // Page 1: Control Panel
    ControlPanel {
        ...
    }

    // Page 2: Parameter Settings
    ParameterSettings {
    }

    // Page 3: Alarm Page
    AlarmPage {
    }

    // Page 4: Device Operation Log
    DeviceOperationLog {
    }

    // Page 5: Input1 Page
    Input1Page {
    }
}
```

## 💡 经验教训

### 1. 焦点管理的复杂性

**问题**：
- 多个组件都可以处理键盘事件
- 焦点可能在不同组件之间转移
- 需要明确管理焦点的生命周期

**教训**：
- 使用 `forceActiveFocus()` 明确设置焦点
- 在页面切换时恢复焦点
- 使用调试日志跟踪焦点变化

### 2. QDS 测试环境 vs 实际部署环境

**差异**：
- **QDS 测试**：页面是第一个，直接加载
- **实际部署**：页面是第五个，需要切换

**教训**：
- QDS 测试环境可能无法发现所有问题
- 需要在实际部署环境中测试
- 考虑页面加载顺序和切换逻辑

### 3. 使用 Qt.callLater 延迟执行

**原因**：
- 页面切换时，组件可能还未完全加载
- 立即调用 `forceActiveFocus()` 可能失败

**解决方案**：
```qml
Qt.callLater(function() {
    // 确保页面已完全加载
    screenLoader.item.forceActiveFocus()
})
```

**教训**：
- 在异步操作中使用 `Qt.callLater`
- 确保组件已完全加载再操作
- 添加错误检查和日志输出

### 4. 组件层次结构的理解

**Input1Page 结构**：
```
Input1Page
  ↓
Loader (screenLoader)
  ↓
Screen01
```

**访问方式**：
```qml
var input1Page = swipeView.itemAt(4)
var screenLoader = input1Page.children[0]
var screen01 = screenLoader.item
```

**教训**：
- 理解组件的层次结构
- 使用正确的方式访问子组件
- 添加空值检查避免崩溃
