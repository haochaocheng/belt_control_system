# 排查结果 - 选择默认音频来源，播放仍为TTS合成语音

## 问题描述
- **现象**：选择"开关量输入"中的"默认音频"选项并保存，但保护触发时仍然播放TTS合成语音
- **日志**：`[DEBUG] 📋 [MqttProtectionMonitor] 保护 "急停" 音频来源: TTS合成`

---

## 根本原因分析

### 问题链路
```
数据库记录中 use_text_to_speech=1
    ↓
加载时读取DB，protection.use_text_to_speech=1
    ↓
SwitchInputPage.qml 第1749行：
  audioSourceMode = (protection.use_text_to_speech == 1) ? 1 : 0
    ↓
audioSourceMode=1（TTS合成）
    ↓
保护触发时调用 MqttProtectionMonitor.onBitChanged()
    ↓
第151行：useTTS = (protection.value("use_text_to_speech", 1).toInt() == 1)
    ↓
useTTS=true，使用TTS音频路径
```

### 根本原因：数据库初始化时 use_text_to_speech 默认为 1

**源文件**：`src/control/DeviceConfigManager.cpp`

#### 问题1：表定义（第114-134行）
```cpp
// ✅ 2026-02-28 [Phase 7.47.52]: 默认改为0（默认音频），旧值1导致新建保护默认TTS
use_text_to_speech BOOLEAN DEFAULT 0,
```
✅ 表定义已修改为DEFAULT 0，但...

#### 问题2：初始化时插入记录（第395-426行）
```cpp
bool DeviceConfigManager::initDefaultDigitalProtections(int deviceId)
{
    // ...
    query.prepare(R"(
        INSERT INTO device_digital_protections
        (device_id, protection_name, module_type, register_address, channel_number, tts_text)
        VALUES (?, ?, ?, ?, ?, ?)
    )");
    // ⚠️ 没有指定 use_text_to_speech 字段！
```
❌ **问题**：INSERT语句中没有指定 `use_text_to_speech` 字段

**后果**：
- 如果表已存在（CREATE TABLE IF NOT EXISTS），不会重新定义DEFAULT值
- SQLite不会更新已有表的DEFAULT值
- INSERT时省略的字段使用**旧的DEFAULT值（1）**

#### 问题3：迁移脚本（第304-327行）
```cpp
void DeviceConfigManager::runMigrations()
{
    // ...
    // 迁移 001：将 use_text_to_speech 默认值从 1 改为 0
    query.prepare("SELECT COUNT(*) FROM schema_migrations WHERE version = '001_reset_audio_source'");
    if (query.exec() && query.next() && query.value(0).toInt() == 0) {
        QSqlQuery fix(m_database);
        if (fix.exec("UPDATE device_digital_protections SET use_text_to_speech = 0 WHERE use_text_to_speech = 1")) {
            int affected = fix.numRowsAffected();
            qDebug() << "✅ [DeviceConfigManager] 迁移001: 重置" << affected << "条保护记录的音频来源为默认(0)";
            query.exec("INSERT INTO schema_migrations (version) VALUES ('001_reset_audio_source')");
        }
    }
}
```
⚠️ **问题**：迁移机制有隐患
- 需要 `schema_migrations` 表不存在或记录未存在 才会执行
- 如果数据库被删除重建，迁移会重新执行
- 但日志中**看不到迁移执行的日志消息**（没有"✅ 迁移001"的日志）

## 现场问题诊断

### voip.md 日志分析
```
[DEBUG] 📋 [MqttProtectionMonitor] 保护 "急停" 音频来源: TTS合成
```

这表明：
1. `loadDigitalProtection()` 返回**非空**的protection map
2. `protection.value("use_text_to_speech", 1)` 返回值为 **1**
3. 因此 `useTTS = true`，使用TTS音频路径

### 原因排查

| 序号 | 可能原因 | 判断方法 | 结论 |
|-----|--------|-------|------|
| 1 | 数据库中use_text_to_speech确实是1 | 检查DB文件 | ✅ 很可能是这个 |
| 2 | runMigrations没执行成功 | 搜索日志"迁移001" | ❓ 看不到日志，说明可能没执行 |
| 3 | 用户在UI中手动改回TTS | 检查修改时间戳 | ❓ 需要确认 |
| 4 | DEFAULT值在CREATE TABLE时就是1 | 查看代码历史 | ✅ 确认：旧代码DEFAULT 1 |

## 解决方案

### 方案 A：修复初始化代码（推荐）
**修改** `src/control/DeviceConfigManager.cpp` 第405-415行：

```cpp
query.prepare(R"(
    INSERT INTO device_digital_protections
    (device_id, protection_name, module_type, register_address, channel_number, tts_text, use_text_to_speech)
    VALUES (?, ?, ?, ?, ?, ?, ?)
)");
query.addBindValue(deviceId);
query.addBindValue(name);
query.addBindValue("输入模块1");
query.addBindValue(2);
query.addBindValue(i);           // 通道编号 0-7
query.addBindValue(name + "保护报警");
query.addBindValue(0);           // ✅ 默认为0（默认音频）
```

### 方案 B：手动修复现有数据库
如果数据库已经被污染（use_text_to_speech都是1），有三种修复方法：

#### B1：删除数据库重新初始化（最彻底）
```bash
# Docker容器内
rm /home/linaro/belt-control-data/device_config.db
# 重启应用，会自动重建数据库
```

#### B2：运行SQL修复语句（最快）
```bash
# 进入Docker容器
sqlite3 /home/linaro/belt-control-data/device_config.db

# 执行修复
UPDATE device_digital_protections SET use_text_to_speech = 0;
INSERT OR IGNORE INTO schema_migrations (version) VALUES ('001_reset_audio_source');

# 验证
SELECT COUNT(*) FROM device_digital_protections WHERE use_text_to_speech = 1;  -- 应为0
SELECT COUNT(*) FROM device_digital_protections WHERE use_text_to_speech = 0;  -- 应为96（12皮带*8个保护）
```

#### B3：让迁移脚本自动修复（需要强制执行）
修改 `src/control/DeviceConfigManager.cpp` 第317-318行，强制删除迁移记录：
```cpp
// 强制重新执行迁移（调试用）
query.exec("DELETE FROM schema_migrations WHERE version = '001_reset_audio_source'");

// 再次检查迁移条件
query.prepare("SELECT COUNT(*) FROM schema_migrations WHERE version = '001_reset_audio_source'");
```
