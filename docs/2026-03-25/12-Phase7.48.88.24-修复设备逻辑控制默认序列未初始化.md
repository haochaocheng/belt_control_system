# Phase 7.48.88.24 - 修复设备逻辑控制默认序列未初始化

## 日期
2026-03-25

## 问题描述

### 现象
5-8号皮带在界面上显示有启停序列（张紧控制、1号制动器、1号电机、2号电机），但实际启动时日志输出"启动顺序为空，无需执行"，不执行任何设备动作。

### 根本原因
数据库迁移030（创建 `device_logic_configs` 表）的初始化代码有缺陷：
- **device_id=1**：预设了默认启停序列 ✅
- **device_id=2~12**：只插入了 device_id，`startup_sequence` 和 `stop_sequence` 使用表默认值 `'[]'`（空数组）❌

QML `LogicControlPanel.qml` 第109行在DB返回空数组时，用硬编码回退值显示假序列：
```javascript
startupSeq = loadedStartup.length > 0 ? migrateOldNames(loadedStartup) : ["张紧控制", "1号制动器", "1号电机", "2号电机"]
```

用户看到界面有序列，以为已配置生效，实际上数据库里是空的。只有手动点"保存"按钮才会写入数据库。

### 设备实际DB状态（修复前）
| device_id | startup_sequence | stop_sequence |
|-----------|-----------------|---------------|
| 1 | ["1号制动器","1号电机","2号电机"] | ["2号电机","1号电机","1号制动器","张紧控制"] |
| 2 | ["张紧控制","1号制动器","2号电机","3号电机"] | ["3号电机","2号电机","1号制动器","张紧控制"] |
| 3 | ["张紧控制","1号制动器","1号电机"] | ["2号电机","1号电机","1号制动器","张紧控制"] |
| 4 | ["张紧控制","1号制动器","1号电机"] | ["1号电机","1号制动器","张紧控制"] |
| 5-12 | [] | [] |

## 修复方案

新增数据库迁移036（`036_init_default_sequences`）：
- 扫描 `device_logic_configs` 表中 `startup_sequence` 为空（`[]`、NULL、空字符串）的记录
- 自动写入默认启停序列
- 默认启动：张紧控制 → 1号制动器 → 1号电机 → 2号电机
- 默认停止：2号电机 → 1号电机 → 1号制动器 → 张紧控制

## 修改文件

| 文件 | 修改内容 |
|------|---------|
| `src/control/DeviceConfigManager.cpp` | 新增迁移036，为空序列设备初始化默认启停序列 |

## 验证方法
1. 部署后查看启动日志，确认"迁移036完成，共更新N条记录"
2. 按5-8号数字键启动 → 确认日志显示设备序列执行（不再是"序列为空"）
3. 在界面上打开5-8号逻辑控制面板 → 确认显示默认序列
