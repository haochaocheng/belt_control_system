# 设备监控卡片数据显示优化规划

## 日期
2026-03-25

## 现状分析

### 当前问题
12个设备卡片（8条皮带 + 转载机/破碎机/前刮板/后刮板）显示**硬编码的虚假数据**：
- 速度：1200 m/min（固定值）
- 温度：45 °C（固定值）
- 压力：2.5 MPa（固定值）
- 电流：32 A（固定值）
- 运行状态：固定"运行中"
- 通讯状态：固定"在线"

**问题**：这些数据对操作人员毫无参考价值，无法反映设备真实状态。

### 当前卡片组件
- **文件**：`src/qml/Input1/Input1Content/MyIN_Data.ui.qml`
- **布局**：标题 → 分隔线 → 2×2参数网格 → 分隔线 → 状态指示灯
- **背景**：科技风边框（青色正常/绿色选中），深色透明背景
- **尺寸**：每卡片约 480×333px

### 可用实时数据源

| 数据源 | 类 | 数据内容 | 更新频率 |
|--------|----|---------|---------:|
| 模拟量(AI) | AIDataManager | 16通道模拟值（速度/张力/温度等） | 500ms |
| 开关量(DI) | DIDataManager | 16位开关状态（急停/跑偏/撕裂等） | 100ms |
| 继电器反馈(DO) | DODataManager | 8路输出+8路反馈+急停 | 实时 |
| 沿线点位(CS) | CSDataManager | 192个保护点位 | 实时 |
| 电机保护(Modbus) | MqttProtectionMonitor | 8电机×9项（电流/温度/振动） | 实时 |
| 皮带运行状态 | CommonControl | m_beltRunning[1-8] | 实时 |
| 运行时间统计 | DeviceRuntimeTracker | 日/周/月运行时间和开机率 | 1秒 |
| MQTT连接健康 | MQTTAutoManager | 模块在线/离线/超时 | 2秒 |

## 优化方案

### 设计原则

1. **数据优先级**：只显示操作人员最关心的实时数据
2. **一眼识别**：运行/停止/故障状态通过颜色直观区分
3. **异常高亮**：参数超限时颜色变红，正常时保持白色
4. **差异化显示**：不同类型设备显示不同参数组合
5. **保留背景风格**：沿用现有科技风卡片边框图片

### 卡片布局重新设计

```
┌──────────────────────────────────────────┐
│           ▼ 标题栏（设备名称）▼            │  ← 顶部六角形装饰区域
├──────────────────────────────────────────┤
│                                          │
│  ┌─────────────┐  ┌─────────────┐       │
│  │ 核心参数1    │  │ 核心参数2    │       │  ← 主数据区（大字体）
│  │ ███ 数值 ███ │  │ ███ 数值 ███ │       │
│  └─────────────┘  └─────────────┘       │
│                                          │
│  ┌─────────────┐  ┌─────────────┐       │
│  │ 核心参数3    │  │ 核心参数4    │       │  ← 辅助数据区
│  │ ███ 数值 ███ │  │ ███ 数值 ███ │       │
│  └─────────────┘  └─────────────┘       │
│                                          │
├──────────────────────────────────────────┤
│  ● 运行状态    ● 通讯状态    ⏱ 运行时间  │  ← 状态栏（三段式）
└──────────────────────────────────────────┘
```

**改进点**：
- 底部状态栏从2段改为3段：运行状态 + 通讯状态 + 今日运行时间
- 参数值支持颜色变化（正常白色/报警红色/警告黄色）
- 参数名使用更小字体，值使用大字体突出

### 数据颜色规则

| 状态 | 颜色 | 应用场景 |
|------|------|---------|
| 正常 | `#FFFFFF`（白色） | 参数在正常范围内 |
| 警告 | `#FFD740`（琥珀色） | 参数接近阈值（80%-100%） |
| 报警 | `#FF5252`（红色） | 参数超限，保护将触发 |
| 离线/无数据 | `#757575`（灰色） | 通讯中断或数据无效 |
| 运行中 | `#4CAF50`（绿色） | 设备正常运行 |
| 已停止 | `#9E9E9E`（灰色） | 设备停止 |
| 故障 | `#FF5252`（红色） | 保护触发/设备故障 |

### 状态指示灯颜色方案

**运行状态指示灯**：
- 绿色闪烁：正在启动序列中
- 绿色常亮：正常运行
- 灰色：已停止
- 红色闪烁：故障/保护触发

**通讯状态指示灯**：
- 绿色：在线（数据正常更新）
- 黄色：延迟（数据超时但未断开）
- 红色：离线（连接断开）

### 实现步骤

#### 第1步：扩展 MyIN_Data.ui.qml 属性
```
新增属性：
- param1Color / param2Color / param3Color / param4Color（参数值颜色）
- statusText3 / statusColor3（第三状态：运行时间）
- deviceStatusColor（运行状态指示灯颜色，支持闪烁）
- commStatusColor（通讯状态指示灯颜色）
```

#### 第2步：创建数据绑定桥接
在 Screen01.qml 中，为每个卡片建立数据绑定：
- 订阅 AIDataManager.channelChanged → 更新速度/张力
- 订阅 MqttProtectionMonitor.motorValueUpdated → 更新电流/温度
- 订阅 CommonControl.beltRunningChanged → 更新运行状态
- 订阅 MQTTAutoManager.moduleHealthChanged → 更新通讯状态
- 订阅 DeviceRuntimeTracker → 更新运行时间

#### 第3步：参数通道映射配置
需要在数据库或配置中建立映射关系：
```
1号皮带 → AI模块X通道Y = 速度
1号皮带 → Modbus电机1 Tab0 = 电流
1号皮带 → Modbus电机1 Tab3 = 温度
1号皮带 → AI模块X通道Z = 张力
```
（利用已有的 ProtectionConfigManager 的保护配置来获取通道映射）

#### 第4步：异常阈值判断
复用 ProtectionConfigManager 中已配置的上下限值，用于卡片颜色变化。

### 预期效果

**操作人员一眼就能看到**：
1. 哪些皮带在运行（绿色），哪些停止（灰色），哪些故障（红色）
2. 每条皮带的**速度**是否正常（白色正常/红色超速欠速）
3. 电机**电流**是否过载（白色正常/红色过流）
4. 电机**温度**是否过高（白色正常/黄色接近/红色超温）
5. **通讯**是否正常（绿色在线/红色离线）
6. 今天累计**运行了多长时间**
