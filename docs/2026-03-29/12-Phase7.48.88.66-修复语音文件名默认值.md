# Phase 7.48.88.66 - 修复语音文件名默认值与批量生成不一致

## 修改日期
2026-03-29

## 问题描述
2号电机配置界面的"预警语音"和"失败语音"输入框显示灰色占位符文字（"预警音频文件名"、"失败音频文件名"），而1号电机显示白色正常文本（"电机1启动"、"电机1失败"）。

灰色占位符意味着文本内容为空，即数据库中该字段为空字符串。

## 根因分析

### 问题1：applyConfig 空值处理
`applyConfig()` 从数据库加载配置时：
```qml
// 旧代码：空字符串直接赋值，导致显示占位符
warningVoiceField.text = (config["warning_voice"] !== undefined) ? config["warning_voice"] : ""
```
当数据库值为 `""` 时，TextField 显示灰色占位符。

### 问题2：失败语音默认文件名不一致
| 来源 | 格式 | 示例 |
|------|------|------|
| QML默认值（旧） | `"电机{N}失败"` | "电机2失败" |
| 批量生成（实际文件） | `"{N}号电机运行失败"` | "2号电机运行失败" |
| CommonControl搜索 | 两者都搜索（兼容） | 主搜"2号电机运行失败"，备搜"电机2失败" |

## 修复方案

### BasicConfigTab.qml
1. **QML默认值**：失败语音从 `"电机{N}失败"` 改为 `"{N}号电机运行失败"`（匹配批���生成）
2. **applyConfig()**：空值时使用正确的默认名：
   - 预警语音默认：`"电机{N}启动"`
   - 失败语音默认：`"{N}号电机运行失败"`

## 测试要点
1. 新建电机配置 → 语音字段显示白色默认值（非灰色占位符）
2. 2号电机：预警显示"电机2启动"，失败显示"2号电机运行失败"
3. 已保存的1号电机不受影响（保留已存值"电机1启动"、"电机1失败"）
4. 实际启动测试：语音播放正常
