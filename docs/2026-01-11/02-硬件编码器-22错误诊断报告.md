# 硬件编码器 -22 错误诊断报告

**日期**：2026-01-11 01:00
**问题**：对方看不到本机视频
**错误**：`❌ [ENCODE] avcodec_send_frame() failed: -22 (Invalid argument)`

## 问题现象

### 编码器错误
```
07:48:42.450    ffmpeg_vid_codecs.c  ❗❗❗ [CRITICAL] About to call avcodec_send_frame()
07:48:42.450    ffmpeg_vid_codecs.c      Frame format: 0 (I420), size: 768x432
07:48:42.450    ffmpeg_vid_codecs.c      Encoder: h264_rkmpp (software codec, no hardware conversion needed)
07:48:42.450    ffmpeg_vid_codecs.c  ❗❗❗ [CRITICAL] avcodec_send_frame() returned: -22
07:48:42.450    ffmpeg_vid_codecs.c  ❌ [ENCODE] avcodec_send_frame() failed: -22 (Invalid argument)
```

### 摄像头实际输出
```
07:48:42.386             vid_port.c  ..Opening device icspring camera: icspring camer [v4l2]
                                      for capture: format=YUY2, size=640x360 @25:1 fps
```

## 根本原因

### 分辨率不匹配
- **摄像头输出**：640x360 @ 25fps (YUY2 → I420 转换后)
- **编码器配置**：768x432（从 SDP 协商获取）
- **错误码**：-22 (EINVAL = Invalid argument)

### 代码路径分析

#### 1. 编码器分辨率配置（Line 2025-2026, 2118-2119）
```c
/* Get video format detail for shortcut access to encoded format */
vfd = pjmedia_format_get_video_format_detail(&ff->param->enc_fmt, PJ_TRUE);

/* 后续... */
ctx->width = vfd->size.w;   // ← 768 (从 SDP 协商)
ctx->height = vfd->size.h;  // ← 432 (从 SDP 协商)
```

#### 2. 输入帧配置（Line 3059-3061）
```c
avframe.height = ff->enc_ctx->height;  // ← 768
avframe.width = ff->enc_ctx->width;    // ← 432
avframe.format = ff->enc_ctx->pix_fmt; // ← I420
```

#### 3. 实际数据来源
输入帧的 `data` 指针指向的是 640x360 的 I420 数据，但编码器期望 768x432。

### h264_rkmpp 硬件编码器的限制
- 要求输入帧的分辨率必须与编码器配置的分辨率一致
- 不支持自动缩放
- 分辨率不匹配 → 返回 EINVAL (-22)

## 解决方案选项

### 方案 1：禁用硬件编码器（最快最稳定）⭐
**优点**：
- 立即可用，无需代码修改
- libx264 软件编码器支持任意分辨率
- libx264 会自动处理分辨率不匹配（内部缩放）

**缺点**：
- CPU 占用增加（约 20-30%）
- 功耗略高

**实施方法**：
```bash
# 在设备上设置环境变量
export USE_HARDWARE_ENCODER=0

# 或者修改应用启动脚本
```

### 方案 2：修复分辨率不匹配（需要代码修改）
**两个子方案**：

#### 方案 2A：强制编码器使用摄像头分辨率
修改 `open_ffmpeg_codec()` 函数（Line 2118-2119）：
```c
// ⚠️ 旧代码
ctx->width = vfd->size.w;   // 使用 SDP 协商的分辨率
ctx->height = vfd->size.h;

// ✅ 新代码
ctx->width = ff->param->dec_fmt.det.vid.size.w;   // 使用摄像头实际分辨率
ctx->height = ff->param->dec_fmt.det.vid.size.h;
```

**风险**：
- 可能导致 SDP 协商失败（对方期望 768x432）
- 需要重新协商 SDP

#### 方案 2B：添加视频缩放器
在摄像头和编码器之间添加缩放器：
```c
// 使用 libswscale 或 RGA 硬件缩放器
// 640x360 → 768x432
```

**优点**：
- 保持 SDP 协商结果
- 对方能看到视频

**缺点**：
- 增加 CPU 开销（软件缩放）或需要 RGA 配置（硬件缩放）
- 代码复杂度增加

### 方案 3：修改 SDP 协商配置
修改应用层代码，强制 SDP 使用 640x360：
```cpp
// 在 SipPhoneManager 或 VideoCallManager 中
pjsua_vid_codec_param codec_param;
pjsua_vid_codec_get_param(&codec_id, &codec_param);
codec_param.enc_fmt.det.vid.size.w = 640;
codec_param.enc_fmt.det.vid.size.h = 360;
pjsua_vid_codec_set_param(&codec_id, &codec_param);
```

**风险**：
- 需要深入了解 PJSUA API
- 可能影响其他通话流程

## 768x432 分辨率来源分析

### 可能的原因
1. **对方发送的 SDP Offer** 指定了 768x432
2. **默认编码器配置** 设置为 768x432
3. **视频会议桥接器** 的默认分辨率

### 调试建议
查看 SDP 协商日志，确认：
- 本机 SDP Offer 的视频分辨率
- 对方 SDP Answer 的视频分辨率
- 最终协商结果

命令：
```bash
# 在 voip.md 中搜索 SDP
grep -i "sdp\|fmtp.*size" voip.md
```

## 技术细节

### 错误码 -22 (EINVAL) 的含义
在 FFmpeg/RKMPP 中，EINVAL 通常表示：
1. 输入参数与编码器配置不匹配
2. 像素格式不支持
3. **分辨率不匹配**（本案例）
4. 帧率配置错误

### h264_rkmpp 的特性
- 纯硬件编码器，依赖 VPU（Video Processing Unit）
- 不支持软件缩放
- 要求输入数据与配置严格匹配
- 相比 libx264，性能更高但灵活性较差
