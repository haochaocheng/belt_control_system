## 问题诊断

### 可能的原因

根据源码分析，返回 -22 的可能原因：

**原因 1：PJSIP 传入的帧尺寸 > 编码器初始化的尺寸**

```
示例：
- 编码器初始化：avctx->width = 640, avctx->height = 480
- hwfc 初始化：hwfc->width = 640, hwfc->height = 480
- PJSIP 传入帧：avframe.width = 768, avframe.height = 432
  ↓
检查：768 > 640 → 返回 -22 ❌
```

**原因 2：编码器初始化的尺寸本身不正确**

```
示例：
- 编码器配置：应该是 640x480
- 实际初始化：avctx->width = 320, avctx->height = 240
- PJSIP 传入帧：avframe.width = 640, avframe.height = 480
  ↓
检查：640 > 320 → 返回 -22 ❌
```

**原因 3：enc_ctx->hw_frames_ctx 没有正确设置**

```
如果 ff->enc_ctx->hw_frames_ctx == NULL：
- RKMPP 编码器使用的是 r->hwframe（内部 hwframe）
- 但 avcodec_send_frame() 检查的是 enc_ctx->hw_frames_ctx
- 可能导致 hwfc 为 NULL 或指向错误的上下文
```

## 验证目标

通过这些日志，我们可以验证：

### 1. AVFrame 的真实格式和尺寸

- 不是硬编码的"(I420)"字符串
- 实际值：`format=23` (nv12) 或 `format=0` (yuv420p)
- 实际尺寸：`width=?`, `height=?`

### 2. 编码器上下文的期望

- `enc_ctx->pix_fmt`：应该是 23 (NV12) for RKMPP
- `enc_ctx->width`：应该是 640
- `enc_ctx->height`：应该是 480

### 3. hw_frames_ctx 的状态

- 是否存在 `hw_frames_ctx`？
- 如果存在：
  - `hwfc->width`：应该是 640
  - `hwfc->height`：应该是 480
  - `hwfc->sw_format`：应该是 23 (NV12)

### 4. 关键检查结果

- `avframe.width` vs `hwfc->width`
- `avframe.height` vs `hwfc->height`
- 如果 `avframe > hwfc` → **这就是 -22 错误的真正原因**
