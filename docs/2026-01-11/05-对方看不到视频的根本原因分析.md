# 对方看不到视频的根本原因分析

**时间**: 2026-01-11 03:10
**问题**: Fix 100.30 和 Fix 100.31 部署后，对方仍然看不到本机视频
**症状**: 编码器持续 -22 错误，无法编码视频帧

## 完整问题链

### 1. V4L2 摄像头不支持 640x368 分辨率

**请求的分辨率** (Fix 100.31):
```
Line 1277: ✅ [FIX 100.31] Forced camera resolution to 640x368@25fps
Line 1279: Opening device ... size=640x368 @25:1 fps
```

**实际打开的分辨率**:
```
Line 1288: Device ... opened: size=1280x720 @25:1 fps
```

**根本原因**: V4L2 驱动不支持非标准分辨率 640x368，自动 fallback 到摄像头的原生分辨率 1280x720。

### 2. 视频会议桥自动缩放到 768x432

**摄像头连接**:
```
Line 1293: Port 3 (camera 1280x720) transmitting to port 2 (vstenc编码器)
```

**编码器收到的帧**:
```
Line 1403: Frame format: 0 (I420), size: 768x432
```

**缩放计算**:
- 768 ÷ 1280 = 0.6
- 432 ÷ 720 = 0.6
- **768x432 = 1280x720 × 0.6**

**根本原因**: 视频会议桥（`pjmedia_vid_conf`）根据编码器端口的配置，将 1280x720 的摄像头帧自动缩放到 768x432。

### 3. 编码器配置与实际帧大小不匹配

**编码器期望的分辨率** (推测):
- 可能是 SDP 协商后计算得出的某个分辨率（需进一步验证）
- 或者是编码器端口创建时的默认分辨率

**编码器实际收到**:
- 768x432 的帧

**编码器初始化**:
- 从 FFmpeg codec descriptor: 640x368 ✅
- 从 risipendpoint.cpp: 640x368 ✅
- 但编码器实际接收到 768x432 ❌

**结果**:
```
Line 1405-1406: ❌ [ENCODE] avcodec_send_frame() failed: -22 (Invalid argument)
```

h264_rkmpp 编码器初始化为 640x368，但收到 768x432 的帧 → 尺寸不匹配 → -22 错误。

## 关键发现

### V4L2 驱动的分辨率选择逻辑

```bash
# 在设备上查询摄像头支持的分辨率
v4l2-ctl --device=/dev/video11 --list-framesizes=I420
```

**预期结果**:
- 摄像头不支持 640x368
- 支持的分辨率可能包括: 1280x720, 640x480, 320x240 等
- V4L2 驱动选择最接近的分辨率（1280x720）

### 视频会议桥的缩放策略

PJSIP 的 `pjmedia_vid_conf` 在连接两个不同分辨率的端口时：
1. 检测源端口（摄像头）分辨率: 1280x720
2. 检测目标端口（编码器）分辨率: 推测为某个值
3. 自动插入缩放转换器（libswscale）
4. 将 1280x720 缩放为目标分辨率

**问题**: 缩放后的分辨率（768x432）与编码器初始化的分辨率（640x368）不一致。

## 解决方案选择

### 方案 A：使用摄像头原生支持的分辨率（推荐）

**策略**: 使用摄像头原生支持的分辨率，避免 V4L2 fallback。

**候选分辨率**:
1. **640x480** (VGA)
   - 640 = 16 × 40 ✅
   - 480 = 16 × 30 ✅
   - 摄像头几乎100%支持
   - 4:3 宽高比（非理想）

2. **1280x720** (720P)
   - 1280 = 16 × 80 ✅
   - 720 = 16 × 45 ✅
   - 摄像头原生分辨率
   - 16:9 宽高比 ✅
   - 数据量较大，性能影响

3. **864x480** (WVGA)
   - 864 = 16 × 54 ✅
   - 480 = 16 × 30 ✅
   - 16:9 宽高比 ✅
   - 需验证摄像头是否支持

### 方案 B：强制视频会议桥使用固定分辨率

修改 `pjsua_vid.c` 的 `setup_vid_capture()`，在摄像头和编码器之间插入固定分辨率的转换器。

**问题**: 需要修改 PJSIP 核心代码，复杂度高。

### 方案 C：修改编码器配置匹配视频会议桥的缩放结果

**问题**: 需要找到视频会议桥缩放到 768x432 的逻辑，并修改编码器配置。

**根本问题**: 768 和 432 都不是 16 的倍数！
- 768 ÷ 16 = 48 ✅
- 432 ÷ 16 = 27 ✅

等等，768 和 432 **都是 16 的倍数**！那为什么还有 -22 错误？

**深入分析**: 可能是编码器初始化时的分辨率与运行时分辨率不一致导致的。

- PJSIP 视频会议桥支持自动格式转换和缩放
- h264_rkmpp 要求分辨率必须是 16 的倍数
