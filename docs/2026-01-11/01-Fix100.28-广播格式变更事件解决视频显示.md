# Fix 100.28：广播格式变更事件解决视频显示

**日期**：2026-01-11 00:25
**版本**：CODE_VERSION 188
**状态**：✅ 测试成功 - **本机可以显示对方视频**

## 问题描述

### 现象
- 解码器正常工作（Fix 100.26 成功转换 DRM_PRIME → NV12）
- `decode()` 正确填充了 output 缓冲区
- **但 `put_frame` 回调收到的全是空帧**（`frame->buf=NULL` 或 `frame->size=0`）
- 导致视频显示黑屏

### Fix 100.27 诊断结果
```
🔍 [FIX 100.27 DIAG] Before memcpy:
  - output->buf=0x7f049c8ca8     ← ✅ 有效指针（不是 NULL）
  - output_buf_len=518400         ← ✅ 缓冲区足够大
  - vafp->framebytes=345600       ← ✅ 正确的 NV12 帧大小

✅ [FIX 100.27 DIAG] After memcpy:
  - output->type=3                ← ✅ PJMEDIA_FRAME_TYPE_VIDEO
  - output->size=345600           ← ✅ 正确设置帧大小
```

**结论**：`decode()` 输出正常，但数据没有传递到 `put_frame`！

## 根本原因

### PJSIP 视频流水线工作机制
1. **decode()** 填充 output 缓冲区 ✅（已确认正常）
2. **广播 PJMEDIA_EVENT_FMT_CHANGED** 通知上层格式改变 ❌（被 Fix 100.25 跳过）
3. **上层收到事件后** 更新视频渲染管道
4. **put_frame** 接收并显示视频帧

### Fix 100.25 的副作用
```c
/* ✅ 2026-01-10 [修复 100.25] 跳过 DRM_PRIME 格式检查 */
if (ff->dec_ctx->pix_fmt == 179) {  // AV_PIX_FMT_DRM_PRIME
    return PJ_SUCCESS;  // ⚠️ 跳过所有格式检查和缓冲区分配！
}
```

被跳过的关键代码（Line 3492-3497）：
```c
/* Broadcast format changed event */
pjmedia_event_init(&event, PJMEDIA_EVENT_FMT_CHANGED, ts, codec);
event.data.fmt_changed.dir = PJMEDIA_DIR_DECODING;
pj_memcpy(&event.data.fmt_changed.new_fmt, &ff->param->dec_fmt,
          sizeof(ff->param->dec_fmt));
pjmedia_event_publish(NULL, codec, &event, 0);  // ⚠️ 未执行！
```

**结果**：
- PJSIP 上层（video port/conference）不知道格式从 DRM_PRIME 变成 NV12
- 上层丢弃所有帧数据
- `put_frame` 收到空帧
- 视频显示黑屏

## 解决方案

### Fix 100.28 实现
在 Fix 100.26 成功更新 `dec_vfi`/`dec_vafp` 后，**手动广播格式变更事件**。

### 代码修改

#### 位置 1：Line 3774-3796（Fix 90 分支）
```c
if (update_status == PJ_SUCCESS) {
    PJ_LOG(3,(THIS_FILE, "✅ [FIX 100.26] Updated dec_vfi/dec_vafp for format %d (%dx%d)",
              avframe.format, avframe.width, avframe.height));

    /* ✅ 2026-01-11 00:25 [修复 100.28] 广播格式变更事件
     * 问题：put_frame 收到空帧（frame->buf=NULL），尽管 decode() 正确填充了 output
     * 根因：Fix 100.25 跳过了 check_decode_result()，未广播 PJMEDIA_EVENT_FMT_CHANGED
     * 影响：PJSIP 上层（video port/conference）不知道格式从 DRM_PRIME 变成 NV12
     * 结果：上层丢弃所有帧数据，导致黑屏
     * 诊断：Fix 100.27 证明 output->buf 有效，output->size 正确，但 put_frame 收到空帧
     * 策略：在 Fix 100.26 成功更新格式后，手动广播格式变更事件
     * 效果：通知上层格式已变更，启用视频渲染管道
     * 版本：CODE_VERSION 188
     */
    {
        pjmedia_event event;
        pjmedia_event_init(&event, PJMEDIA_EVENT_FMT_CHANGED, &input->timestamp, codec);
        event.data.fmt_changed.dir = PJMEDIA_DIR_DECODING;
        pj_memcpy(&event.data.fmt_changed.new_fmt, &ff->param->dec_fmt,
                  sizeof(ff->param->dec_fmt));
        pjmedia_event_publish(NULL, codec, &event, 0);
        PJ_LOG(3,(THIS_FILE, "✅ [FIX 100.28] Broadcasted PJMEDIA_EVENT_FMT_CHANGED for format %d", new_fmt_id));
    }
}
```
