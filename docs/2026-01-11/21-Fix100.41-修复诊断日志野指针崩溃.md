# Fix 100.41：修复 Fix 100.40 诊断日志野指针崩溃

**时间**: 2026-01-11 16:00
**触发**: Fix 100.40 测试时程序崩溃 (exit code 139 - SIGSEGV)
**根本原因**: `av_get_pix_fmt_name()` 返回野指针,在 strlen() 时访问无效内存导致段错误
**解决方案**: 移除 `av_get_pix_fmt_name()` 调用,只打印格式数字和对照表

## 根本原因

### Fix 100.40 原代码（有问题）

```c
// Line 3230-3234
const char *fmt_name = av_get_pix_fmt_name((enum AVPixelFormat)avframe.format);
PJ_LOG(1,(THIS_FILE, "❗❗❗ [CRITICAL] About to call avcodec_send_frame()"));
PJ_LOG(1,(THIS_FILE, "    AVFrame: format=%d (%s), size=%dx%d",
          avframe.format, fmt_name ? fmt_name : "unknown",
          avframe.width, avframe.height));
```

**问题**:
1. `av_get_pix_fmt_name()` 可能返回**野指针**(不是 NULL,而是指向无效内存)
2. 虽然有 `fmt_name ? fmt_name : "unknown"` 的 NULL 检查
3. 但野指针**不是 NULL**,所以条件判断通过
4. 在 `PJ_LOG` 内部调用 `strlen(fmt_name)` 时访问无效内存 → **SIGSEGV**

### 为什么是野指针而不是 NULL？

**可能的原因**:
1. `av_get_pix_fmt_name()` 返回指向静态缓冲区的指针
2. 在多线程环境下,缓冲区可能被其他线程修改或释放
3. FFmpeg 内部的实现问题(线程不安全)

// ❌ 2026-01-11 16:00 [Fix 100.41] 移除 av_get_pix_fmt_name() 调用避免野指针崩溃

//    修复: 只打印格式数字 (23=NV12, 0=I420, 179=DRM_PRIME),避免任何字符串指针

    PJ_LOG(1,(THIS_FILE, "    AVFrame: format=%d (23=NV12,0=I420,179=DRM_PRIME), size=%dx%d",

              avframe.linesize[0], avframe.linesize[1], avframe.linesize[2]));
    PJ_LOG(1,(THIS_FILE, "    AVFrame: data[0]=%p, data[1]=%p, data[2]=%p",
              avframe.data[0], avframe.data[1], avframe.data[2]));

    if (ff->enc_ctx) {
        PJ_LOG(1,(THIS_FILE, "    Encoder context: pix_fmt=%d (23=NV12,0=I420), size=%dx%d",
                  ff->enc_ctx->pix_fmt, ff->enc_ctx->width, ff->enc_ctx->height));

        if (ff->enc_ctx->codec) {
            // ✅ 2026-01-11 16:00 [Fix 100.41] codec->name 是常量字符串,安全
            PJ_LOG(1,(THIS_FILE, "    Encoder: %s", ff->enc_ctx->codec->name));
        }

        // ✅ 2026-01-11 15:30 [Fix 100.40 关键检查] 如果编码器使用 hw_frames_ctx（RKMPP），记录其尺寸
        if (ff->enc_ctx->hw_frames_ctx) {
            AVHWFramesContext *hwfc = (AVHWFramesContext *)ff->enc_ctx->hw_frames_ctx->data;
            PJ_LOG(1,(THIS_FILE, "    ⚠️ hw_frames_ctx exists! hwfc: format=%d, sw_format=%d, size=%dx%d",
                      hwfc->format, hwfc->sw_format, hwfc->width, hwfc->height));
            PJ_LOG(1,(THIS_FILE, "    🔍 [FIX 100.40 CHECK] avframe(%dx%d) vs hwfc(%dx%d)",
                      avframe.width, avframe.height, hwfc->width, hwfc->height));

                PJ_LOG(1,(THIS_FILE, "    ❌ [FIX 100.40] SIZE MISMATCH! avframe > hwfc → will return -22 (EINVAL)"));

        }

1. **移除野指针调用**:

## 经验教训

### 1. FFmpeg API 的线程安全性问题

**`av_get_pix_fmt_name()` 不是线程安全的**:
- 可能返回指向静态缓冲区的指针
- 在多线程环境下可能被其他线程修改
- 即使返回值不是 NULL,也可能是野指针

### 2. 日志中的字符串安全

**安全的字符串来源**:
- ✅ 编译时常量字符串 (`"literal string"`)
- ✅ 结构体中的常量字符串 (`codec->name`)
- ✅ 局部数组 (`char buf[256]`)

**不安全的字符串来源**:
- ❌ 函数返回的指针 (`av_get_pix_fmt_name()`)
- ❌ 静态缓冲区指针 (多线程环境)
- ❌ 未初始化的指针

### 3. NULL 检查不够

**问题代码**:
```c
const char *fmt_name = av_get_pix_fmt_name(...);
PJ_LOG(..., fmt_name ? fmt_name : "unknown");  // ← NULL 检查无效
```

**为什么无效**:
- 野指针不是 NULL
- `fmt_name ? fmt_name : "unknown"` 条件判断通过
- strlen(野指针) 崩溃

**正确做法**:
- 不依赖外部函数返回的字符串指针
- 使用数字 + 对照表
- 或者复制字符串到局部缓冲区 (需要额外开销)
