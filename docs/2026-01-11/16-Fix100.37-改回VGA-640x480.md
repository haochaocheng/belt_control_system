# Fix 100.37：改回 VGA (640x480) 分辨率

**时间**: 2026-01-11 11:20
**触发条件**: 用户明确要求"全部改为VGA"
**根本原因**: Fix 100.34 测试失败，V4L2 不支持 I420@640x360，只支持 MJPEG@640x360
**解决方案**: 将所有配置改回 VGA 640x480，利用 V4L2 对 YUYV@640x480 的完美支持

## 问题回顾

### Fix 100.34 测试结果

**配置**：全部改为 640x360（匹配对方 PortSIP）

**测试结果**：
```
11:04:41.052: ✅ [FIX 100.34] Forced camera resolution to 640x360@30fps
11:04:41.144: Device ... opened: format=I420, size=640x480 @30:1 fps  ← V4L2 fallback!
11:04:46.832: Frame format: 0 (I420), size: 768x432  ← 视频会议桥仍在缩放
11:04:50.564: ❌ [ENCODE] avcodec_send_frame() failed: -22 (Invalid argument)
```

**根本原因**：V4L2 不支持 I420@640x360，fallback 到 640x480，导致视频会议桥缩放为 768x432

### V4L2 格式支持调查结果

**重要发现**（根据树莓派摄像头调查）：
- **MJPEG 格式**：640x360 @ 30fps ✅（需要解压缩）
- **I420/YUYV 格式**：640x360 @ 30fps ❌（不支持）
- **YUYV 格式**：640x480 @ 30fps ✅（未压缩，最佳性能）

- [13-树莓派摄像头分辨率支持调查结果.md](./13-树莓派摄像头分辨率支持调查结果.md)
- [15-Fix100.36-使用MJPEG格式打开640x360.md](./15-Fix100.36-使用MJPEG格式打开640x360.md)

### 用户明确要求

**用户指令**："全部改为VGA"

**理由**：
1. 对方（PortSIP）声称已切换到 VGA 方式
2. VGA 640x480 是标准分辨率
3. V4L2 完美支持 YUYV@640x480 @ 30fps
4. 完美 16 像素对齐（640÷16=40, 480÷16=30）

## VGA 640x480 的优势

### 技术优势

| 特性 | 640x360 | VGA 640x480 |
|------|---------|-------------|
| **16像素对齐** | ❌ 360÷16=22.5 | ✅ 480÷16=30 |
| **V4L2 I420支持** | ❌ | ✅ |
| **V4L2 YUYV支持** | ❌ | ✅ @ 30fps |
| **V4L2 MJPEG支持** | ✅ @ 30fps | ✅ @ 30fps |
| **h264_rkmpp兼容** | ❓ 需测试 | ✅ 100% |
| **标准分辨率** | ❌ 非标准 | ✅ VGA 标准 |
| **数据量** | 100% | 133% |

### YUYV 格式优势

**YUYV (YUV 4:2:2 packed) vs MJPEG**：
- ✅ 未压缩格式，无需解压缩步骤
- ✅ CPU 开销低，直接送入编码器
- ✅ 数据流清晰，无压缩伪影
- ✅ V4L2 驱动支持完美

**YUYV vs I420**：
- YUYV: 每像素 2 字节（4:2:2）
- I420: 每像素 1.5 字节（4:2:0）
- PJSIP 会自动转换 YUYV → I420 → H.264
