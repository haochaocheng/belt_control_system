# Fix 100.39：修复 enc_vfi/enc_vafp 内存布局不匹配导致编码器 -22 错误

**时间**: 2026-01-11 15:00
**触发**: Fix 100.38 实施后，编码器仍然返回 -22 错误
**用户反馈**: "日志误导的信息全部改正，最新的日志完成，还是错误，深入排查原因"
**根本原因**: enc_vfi 和 enc_vafp 基于 I420 格式（3 平面）初始化，但编码器 pix_fmt 被设置为 NV12（2 平面），导致 AVFrame 内存布局与格式声明不匹配

## Fix 100.39 解决方案

### 核心思路

**根据编码器类型选择正确的格式 ID**：
- **h264_rkmpp 硬件编码器** → `PJMEDIA_FORMAT_NV12` (2 平面)
- **libx264 软件编码器** → `dec_fmt.id` (I420, 3 平面)

这样 `enc_vfi` 和 `enc_vafp` 的内存布局就会与 `ctx->pix_fmt` 完美匹配！

### 修改位置

**文件**: `cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-codec/ffmpeg_vid_codecs.c`

**函数**: `open_ffmpeg_codec` (Lines 2031-2949)

**修改**: Line 2916（`enc_vfi` 初始化）

### 修改前（原代码）

```c
/* Init format info and apply-param of encoder */
ff->enc_vfi = pjmedia_get_video_format_info(NULL, ff->param->dec_fmt.id);
if (!ff->enc_vfi) {
    status = PJ_EINVAL;
    goto on_error;
}
```

**问题**：
- 总是使用 `dec_fmt.id` (I420)
- 不考虑编码器实际使用的 `pix_fmt` (可能是 NV12)

### 修改后（Fix 100.39）

```c
/* Init format info and apply-param of encoder */
// ✅ 2026-01-11 15:00 [修复 100.39] 根据编码器类型选择正确的格式 ID
// 问题：enc_vfi 总是基于 dec_fmt.id (I420)，导致 enc_vafp 按 I420 的 3 平面布局初始化
//       但 Fix 100.38 将 h264_rkmpp 的 pix_fmt 设置为 NV12 (2 平面)
//       造成 AVFrame 内存布局（3 平面）与格式声明（NV12, 2 平面）不匹配 → -22 错误
// 根因：docs/2026-01-11/18-编码器-22错误根因-格式不匹配NV12vsI420.md
// 解决：h264_rkmpp 使用 PJMEDIA_FORMAT_NV12，libx264 使用 dec_fmt.id (I420)
pjmedia_format_id enc_fmt_id = ff->param->dec_fmt.id;  // 默认使用解码器格式 (I420)

if (ff->enc && (pj_ansi_strstr(ff->enc->name, "rkmpp") != NULL)) {
    // RKMPP 硬件编码器使用 NV12 格式（匹配 Fix 100.38 的 ctx->pix_fmt）
    enc_fmt_id = PJMEDIA_FORMAT_NV12;
    PJ_LOG(3,(THIS_FILE, "✅ [FIX 100.39] RKMPP encoder: using NV12 format info for enc_vfi/enc_vafp"));
    PJ_LOG(3,(THIS_FILE, "   This ensures AVFrame memory layout (2 planes) matches pix_fmt (NV12)"));
} else {
    // 软件编码器（libx264）使用 I420 格式（保持原有行为）
    PJ_LOG(3,(THIS_FILE, "✅ [FIX 100.39] Software encoder: using I420 format info for enc_vfi/enc_vafp"));
}

ff->enc_vfi = pjmedia_get_video_format_info(NULL, enc_fmt_id);
if (!ff->enc_vfi) {
    status = PJ_EINVAL;
    goto on_error;
}
```

## NV12 vs I420 内存布局对比

### NV12 格式（Semi-planar，2 平面）

```
640x480 图像：

平面 0 (Y):  640 × 480 = 307,200 bytes
   [Y Y Y Y Y Y Y Y ...] (640 pixels per row, 480 rows)

平面 1 (UV): 640 × 240 = 153,600 bytes (UV 交错)
   [U V U V U V U V ...] (320 UV pairs per row, 240 rows)

总大小: 307,200 + 153,600 = 460,800 bytes

AVFrame 结构:
  data[0] → Y 平面首地址
  data[1] → UV 平面首地址
  data[2] = NULL
  linesize[0] = 640  (Y 平面步长)
  linesize[1] = 640  (UV 平面步长，包含 U 和 V)
  linesize[2] = 0
  format = 23 (AV_PIX_FMT_NV12)
  plane_cnt = 2
```

### I420 格式（Planar，3 平面）

```
640x480 图像：

平面 0 (Y):  640 × 480 = 307,200 bytes
   [Y Y Y Y Y Y Y Y ...] (640 pixels per row, 480 rows)

平面 1 (U):  320 × 240 = 76,800 bytes
   [U U U U U U U U ...] (320 pixels per row, 240 rows)

平面 2 (V):  320 × 240 = 76,800 bytes
   [V V V V V V V V ...] (320 pixels per row, 240 rows)

总大小: 307,200 + 76,800 + 76,800 = 460,800 bytes

AVFrame 结构:
  data[0] → Y 平面首地址
  data[1] → U 平面首地址
  data[2] → V 平面首地址
  linesize[0] = 640  (Y 平面步长)
  linesize[1] = 320  (U 平面步长)
  linesize[2] = 320  (V 平面步长)
  format = 0 (AV_PIX_FMT_YUV420P)
  plane_cnt = 3
```

### 关键差异

| 特性 | NV12 | I420 |
|------|------|------|
| **平面数** | 2 (Y, UV) | 3 (Y, U, V) |
| **UV 布局** | 交错存储 | 分离存储 |
| **总大小** | 460,800 bytes | 460,800 bytes |
| **硬件支持** | RK3588 原生支持 | 需要转换 |
| **PJMEDIA ID** | `PJMEDIA_FORMAT_NV12` | `PJMEDIA_FORMAT_I420` |
| **FFmpeg ID** | 23 (`AV_PIX_FMT_NV12`) | 0 (`AV_PIX_FMT_YUV420P`) |

## 为什么 Fix 100.38 单独不够？

**Fix 100.38 只修改了编码器的"期望格式"**（`ctx->pix_fmt`），但**没有修改 AVFrame 的"实际内存布局"**（`enc_vfi`/`enc_vafp`）。

**类比**：
- Fix 100.38: 告诉编码器"我要给你 NV12 格式的数据"
- Fix 100.39: 真正把数据按照 NV12 的格式排列

如果只有 Fix 100.38：
- 编码器期望 NV12 (2 平面)
- AVFrame 的内存仍然是 I420 布局 (3 平面)
- **期望与实际不符 → -22 错误**

Fix 100.38 + 100.39 配合：
- 编码器期望 NV12 (2 平面)
- AVFrame 的内存也是 NV12 布局 (2 平面)
- **期望与实际一致 → 编码成功**

## 经验教训

### 1. 像素格式设置需要两个方面

**不仅要设置编码器的"期望格式"**（`ctx->pix_fmt`），**还要设置 AVFrame 的"实际内存布局"**（`enc_vfi`/`enc_vafp`）。

**错误做法**（只有 Fix 100.38）：
```c
ctx->pix_fmt = AV_PIX_FMT_NV12;  // ✅ 编码器期望 NV12
// ❌ 但 enc_vfi 仍然是 I420 布局 → 内存布局不匹配
```

**正确做法**（Fix 100.38 + 100.39）：
```c
ctx->pix_fmt = AV_PIX_FMT_NV12;          // ✅ 编码器期望 NV12
enc_fmt_id = PJMEDIA_FORMAT_NV12;        // ✅ AVFrame 布局也是 NV12
ff->enc_vfi = pjmedia_get_video_format_info(NULL, enc_fmt_id);
```

### 2. 内存布局的重要性

**AVFrame 的内存布局（`data[]` 和 `linesize[]`）必须与 `format` 字段完全一致**。

**NV12 格式**：
- `format = 23` → 编码器期望 2 个平面
- `data[0/1]` 必须正好有 2 个平面
- `linesize[0/1]` 必须正好有 2 个步长

**I420 格式**：
- `format = 0` → 编码器期望 3 个平面
- `data[0/1/2]` 必须正好有 3 个平面
- `linesize[0/1/2]` 必须正好有 3 个步长

### 3. 格式转换的隐性环节

**格式转换不只发生在显式的 `av_hwframe_transfer_data()` 等函数中**，还发生在：
- `enc_vfi->apply_fmt()` 函数（设置内存布局）
- AVFrame 准备时的 `data[]` 和 `linesize[]` 赋值

这些隐性环节同样需要格式一致！

### 4. 深入排查的思路

**当日志显示"格式正确"但仍然失败时**：
1. ✅ 检查编码器的 `pix_fmt` 设置（Fix 100.38 已检查）
2. ✅ 检查 AVFrame 的 `format` 字段（日志显示 23，正确）
3. ✅ **检查 AVFrame 的内存布局**（`data[]` 和 `linesize[]` 的来源）
4. ✅ **追踪 `enc_vfi` 和 `enc_vafp` 的初始化**（Fix 100.39 发现问题）

**关键线索**：`enc_vfi->plane_cnt` 的值
- 如果是 3，说明内存布局是 I420
- 如果是 2，说明内存布局是 NV12

## 总结

Fix 100.39 通过修改 `enc_vfi` 的初始化逻辑，让 h264_rkmpp 硬件编码器使用 `PJMEDIA_FORMAT_NV12` 格式信息，确保 AVFrame 的内存布局（2 平面）与 `pix_fmt` 声明（NV12）完全一致。

**Fix 100.38 + 100.39 配合**：
- Fix 100.38: 设置编码器期望 NV12 格式
- Fix 100.39: 设置 AVFrame 实际使用 NV12 布局
- **结果**: 期望与实际一致 → 编码成功

**关键洞察**：
- 像素格式设置需要两个层面：编码器期望 + AVFrame 布局
- 内存布局必须与格式声明完全一致（平面数量、步长、字节数）
- 硬件编码器和软件编码器已完全隔离，互不影响
