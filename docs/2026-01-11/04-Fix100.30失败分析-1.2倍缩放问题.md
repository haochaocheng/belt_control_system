# Fix 100.30 失败分析：1.2倍分辨率缩放问题

**时间**: 2026-01-11 02:40
**问题**: Fix 100.30 修改了 FFmpeg codec descriptor 默认分辨率为 640x368，但摄像头仍以 768x432 打开
**影响**: 编码器 -22 错误持续

## 问题现象

### 日志分析

```
Line 848: About to init enc_fmt: fmt_id=0x34363248, 640x368  ✅
Line 853-855: TX size: 640 x 368 @ 25fps  ✅
Line 1556: Opening device icspring camera: size=768x432 @25:1 fps  ❌
Line 1680: Frame format: 0 (I420), size: 768x432  ❌
Line 1683: ❌ [ENCODE] avcodec_send_frame() failed: -22 (Invalid argument)
```

### 关键发现

**计算验证**:
- 768 ÷ 640 = 1.2
- 432 ÷ 360 = 1.2

**结论**: 768x432 = 640x360 × 1.2 倍（不是 640x368！）

## 根本原因

### 1. FFmpeg Codec Descriptor 修改生效

Fix 100.30 成功将默认分辨率改为 640x368：
- Line 356: `{640, 368}, {25, 1}, 800000, 1200000` ✅
- 日志确认: "About to init enc_fmt: 640x368" ✅

### 2. 但分辨率被 1.2 倍缩放

摄像头最终打开为 768x432，说明存在缩放逻辑：
- 640 × 1.2 = 768
- 360 × 1.2 = 432（注意是360，不是368！）

### 3. 缩放基数仍使用旧值 640x360

问题定位：
1. SDP 协商后某个环节对分辨率进行了 1.2 倍缩放
2. 缩放的基数是 640x360（旧的默认值）
3. 而不是我们修改后的 640x368

## 可能的缩放来源

### 1. SDP Offer/Answer 协商

对方 SDP answer：
```
a=rtpmap:100 H264/90000
a=fmtp:100 packetization-mode=1;profile-level-id=42e01e;session-id=24
```

没有 `imageattr` 或 `max-fs` 参数，但可能有隐式的分辨率协商。

### 2. Codec 参数覆盖

可能的流程：
1. `pjsua_vid_codec_set_param()` 设置 640x368 ✅
2. SDP 协商完成
3. **某个回调或更新函数重新计算分辨率** → 640x360 × 1.2 = 768x432 ❌
4. 摄像头使用最终计算的分辨率打开

### 3. 视频流创建时的参数计算

`pjmedia_vid_stream_create()` 或类似函数可能：
- 从 codec parameter 读取分辨率
- 应用某种缩放策略（1.2倍）
- 设置到 stream info
- 最终传递给摄像头

## 下一步计划

### 方案 A：禁用分辨率缩放（推荐）

如果找到缩放代码，直接禁用或修改为 1.0 倍。

### 方案 B：修复缩放基数

将缩放基数从 640x360 改为 640x368。

### 方案 C：强制覆盖摄像头分辨率

在 `setup_vid_capture()` 中强制设置：
```c
// pjsua_vid.c Line 1135
vp_param.vidparam.fmt.det.vid.size.w = 640;
vp_param.vidparam.fmt.det.vid.size.h = 368;  // 强制使用16像素对齐分辨率
```
