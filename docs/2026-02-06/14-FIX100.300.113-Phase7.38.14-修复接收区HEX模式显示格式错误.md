## 📋 问题描述

用户在测试 COM5 (RS485) 串口通信时，发现接收区显示格式错误：

**现象**：
- 接收区格式选择：HEX
- 实际显示：`\X01\X03\X00`（每个字节前面有 `\X` 前缀）
- 期望显示：`01 03 00`（空格分隔的十六进制）

**原因**：
- SerialPortController 默认 `m_receiveHexMode = false`（ASCII模式）
- SerialPortReceiveTab.qml 默认 `currentIndex: 0`（HEX模式）
- 两者不同步，导致使用了错误的格式化逻辑
- ASCII模式下，不可打印字符显示为 `\xHH` 格式

---

## 🎯 解决方案

### 修改：SerialPortController 默认接收模式

**修改前**:
```cpp
SerialPortController::SerialPortController(QObject *parent)
    : QObject(parent)
    , m_currentPortIndex(0)
    , m_currentSerialPort(nullptr)
    , m_receiveHexMode(false)  // ← 默认ASCII模式
    , m_pendingSlaveAddress(0)
    , m_pendingFunctionCode(0)
```

**修改后**:
```cpp
SerialPortController::SerialPortController(QObject *parent)
    : QObject(parent)
    , m_currentPortIndex(0)
    , m_currentSerialPort(nullptr)
    , m_receiveHexMode(true)  // ✅ 2026-02-06 [FIX 100.300.113 Phase 7.38.14]: 默认HEX模式（与UI默认选项一致）
    , m_pendingSlaveAddress(0)
    , m_pendingFunctionCode(0)
```

**修改文件**:
- `src/control/SerialPortController.cpp` (第15行)

## 💡 技术要点

### 1. 为什么默认HEX模式？

**原因**：
1. **二进制协议调试**：MODBUS RTU 等二进制协议，HEX 模式更易读
2. **避免乱码**：二进制数据在 ASCII 模式下显示为乱码
3. **与UI一致**：SerialPortReceiveTab.qml 默认选择 HEX 模式
4. **用户期望**：大多数串口调试工具默认 HEX 模式

### 2. HEX vs ASCII 模式对比

**HEX 模式**：
- 显示格式：`01 03 00 00 00 0A C5 CD`（空格分隔）
- 适用场景：二进制协议（MODBUS、CAN、自定义协议）
- 优点：清晰、易读、便于分析数据包

**ASCII 模式**：
- 显示格式：`\x01\x03\x00\x00\x00\x0A\xC5\xCD`（不可打印字符显示为 \xHH）
- 适用场景：文本协议（AT 命令、JSON、XML）
- 优点：可打印字符正常显示，便于阅读文本内容

### 3. 初始化顺序问题

**问题根源**：
```
SerialPortController 构造函数
    ↓
m_receiveHexMode = false（默认ASCII）
    ↓
SerialPortReceiveTab.qml 加载
    ↓
receiveFormat.currentIndex = 0（默认HEX）
    ↓
onCurrentIndexChanged 可能不触发（初始化时）
    ↓
两者不同步
```

**解决方案**：
- 修改 SerialPortController 默认值为 `true`
- 与 UI 默认选项保持一致
- 避免依赖 `onCurrentIndexChanged` 的初始化触发

### 4. 为什么不修改 QML？

**考虑的方案**：
1. 修改 SerialPortController 默认值（✅ 采用）
2. 在 QML `Component.onCompleted` 中显式设置（❌ 不采用）

**选择方案1的原因**：
- 更简单直接
- 符合用户期望（默认 HEX 模式）
- 不需要修改 QML 代码
- 避免依赖 QML 初始化顺序

## 🔄 相关问题

### 1. 为什么 onCurrentIndexChanged 不触发？

**原因**：
- QML 组件初始化时，`currentIndex` 设置为默认值
- 如果默认值与初始值相同，`onCurrentIndexChanged` 不会触发
- 这是 Qt 的正常行为

**解决方案**：
- 不依赖 `onCurrentIndexChanged` 的初始化触发
- 在后端设置正确的默认值

### 2. 如果用户切换格式会怎样？

**行为**：
- 用户切换格式时，`onCurrentIndexChanged` 会触发
- 更新 `serialPortController.receiveHexMode`
- 新接收的数据按新格式显示
- 旧数据保持原格式（不会重新格式化）

### 3. 为什么不重新格式化旧数据？

**原因**：
1. **性能考虑**：重新格式化大量数据可能影响性能
2. **历史记录**：保留原始格式便于对比
3. **实现复杂度**：需要解析已格式化的字符串，容易出错

**用户体验**：
- 用户可以清空接收区，重新接收数据
- 或者在切换格式前，先清空接收区

## 📝 注意事项

1. **默认模式**：
   - SerialPortController 默认 HEX 模式
   - 与 UI 默认选项一致
   - 符合用户期望

2. **格式切换**：
   - 用户可以随时切换 HEX/ASCII 模式
   - 切换后，新数据按新格式显示
   - 旧数据保持原格式

3. **数据显示**：
   - HEX 模式：`01 03 00 00 00 0A C5 CD`（空格分隔）
   - ASCII 模式：`\x01\x03\x00\x00\x00\x0A\xC5\xCD`（不可打印字符显示为 \xHH）

4. **初始化顺序**：
   - 后端默认值应与 UI 默认选项一致
   - 避免依赖 QML 初始化事件

5. **用户体验**：
   - 默认 HEX 模式更适合调试二进制协议
   - 用户可以根据需要切换格式
   - 清空接收区可以重新格式化所有数据
