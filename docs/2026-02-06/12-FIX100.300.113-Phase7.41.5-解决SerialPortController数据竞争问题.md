## 🔍 问题确认

### Qt 信号机制导致的数据竞争

**问题原理**：
1. 串口接收到数据时，Qt 触发 `readyRead` 信号
2. **所有连接到这个信号的槽函数都会被调用**
3. 槽函数执行顺序取决于连接顺序

**数据竞争场景**：
```cpp
// SerialPortController::handleReadyRead()
QByteArray data = m_currentSerialPort->readAll();  // 读取所有数据

// ModbusSlaveController::handleSerialPortReadyRead()
QByteArray data = serialPort->readAll();  // 缓冲区已经空了！
```

**结果**：
- 第一个执行的槽函数读取所有数据
- 第二个槽函数读取到空数据
- MODBUS 从站无法接收到完整的 MODBUS 帧
- 主站显示超时

### Step 2: 在 SerialPortController.cpp 中实现方法

**文件**: `src/control/SerialPortController.cpp`

**实现内容**:

#### disconnectReadyReadSignal()
```cpp
void SerialPortController::disconnectReadyReadSignal()
{
    if (m_currentSerialPort) {
        disconnect(m_currentSerialPort, &QSerialPort::readyRead,
                   this, &SerialPortController::handleReadyRead);
        qDebug() << "✅ [SerialPortController] 已断开 readyRead 信号连接";
        qDebug() << "   - 串口:" << m_currentSerialPort->portName();
        qDebug() << "   - 原因: MODBUS 从站需要独占串口数据接收";
    } else {
        qDebug() << "⚠️ [SerialPortController] 当前串口对象不存在，无需断开信号";
    }
}
```

**功能**：
- 断开 SerialPortController 的 readyRead 信号连接
- 让 MODBUS 从站独占串口数据接收
- 打印详细的调试日志

#### reconnectReadyReadSignal()
```cpp
void SerialPortController::reconnectReadyReadSignal()
{
    if (m_currentSerialPort) {
        // 使用 Qt::UniqueConnection 避免重复连接
        connect(m_currentSerialPort, &QSerialPort::readyRead,
                this, &SerialPortController::handleReadyRead, Qt::UniqueConnection);
        qDebug() << "✅ [SerialPortController] 已重新连接 readyRead 信号";
        qDebug() << "   - 串口:" << m_currentSerialPort->portName();
    } else {
        qDebug() << "⚠️ [SerialPortController] 当前串口对象不存在，无法重新连接信号";
    }
}
```

**功能**：
- 重新连接 SerialPortController 的 readyRead 信号
- 使用 `Qt::UniqueConnection` 避免重复连接
- 恢复 SerialPortController 的数据接收功能

## 💡 技术要点

### 1. Qt 信号断开/重连

**断开信号**：
```cpp
disconnect(sender, &SenderClass::signal, receiver, &ReceiverClass::slot);
```

**重连信号**：
```cpp
connect(sender, &SenderClass::signal, receiver, &ReceiverClass::slot, Qt::UniqueConnection);
```

**Qt::UniqueConnection**：
- 避免重复连接
- 如果已经连接，不会再次连接
- 推荐在重连时使用

### 2. 数据竞争的根本原因

**Qt 信号机制**：
- 一个信号可以连接多个槽函数
- 所有槽函数都会被调用
- 槽函数执行顺序不确定

**串口数据读取**：
- `readAll()` 读取串口缓冲区的所有数据
- 读取后，缓冲区被清空
- 其他对象无法再读取到数据

### 3. 解决方案的优势

**方案 1（已实施）**：
- ✅ 彻底解决数据竞争
- ✅ 实现简单，代码清晰
- ✅ 不增加耦合度
- ✅ 易于维护和调试

**其他方案对比**：
- 方案 2（检测从站运行）：增加耦合度
- 方案 3（互斥锁）：复杂度高，可能死锁
