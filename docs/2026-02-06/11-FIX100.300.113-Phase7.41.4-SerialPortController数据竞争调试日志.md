## 🔍 问题分析

### 数据竞争场景

**SerialPortController 的数据接收流程**：
```cpp
void SerialPortController::handleReadyRead()
{
    // 读取所有可用数据
    QByteArray data = m_currentSerialPort->readAll();

    // 追加到缓冲区
    m_dataBuffer.append(data);

    // 更新接收区显示
    // ...
}
```

**ModbusSlaveController 的数据接收流程**：
```cpp
void ModbusSlaveController::handleSerialPortReadyRead()
{
    // 读取所有可用数据
    QByteArray data = serialPort->readAll();

    // 解析 MODBUS RTU 帧
    // ...
}
```

### 问题根源

**关键问题**：两个控制器都监听同一个串口的 `readyRead` 信号

1. **串口数据到达时**：
   - Qt 的信号机制会触发所有连接的槽函数
   - SerialPortController::handleReadyRead() 被调用
   - ModbusSlaveController::handleSerialPortReadyRead() 也被调用

2. **数据竞争**：
   - 如果 SerialPortController 先执行 `readAll()`
   - 它会读取串口缓冲区的所有数据
   - ModbusSlaveController 再执行 `readAll()` 时，缓冲区已经空了
   - 导致 ModbusSlaveController 无法接收到 MODBUS 帧

3. **结果**：
   - SerialPortController 的接收区显示了 MODBUS 数据
   - ModbusSlaveController 没有接收到任何数据
   - MODBUS 从站无法响应主站请求
   - 主站显示超时

### 为什么之前没有发现

**Phase 7.41.1 的修复**：
```qml
// 启动从站前关闭 SerialPortController 的串口
if (serialPortController.isOpen) {
    serialPortController.closeSerialPort()
}
```

这个修复只是关闭了串口，但是：
1. **串口对象仍然存在**
2. **信号连接仍然有效**
3. **如果用户在启动从站后又打开了串口**，数据竞争问题仍然会出现

### 添加详细调试日志

**文件**: `src/control/SerialPortController.cpp`

**修改位置**: `handleReadyRead()` 函数（第555-602行）

**修改内容**:
```cpp
void SerialPortController::handleReadyRead()
{
    // ✅ 2026-02-06 [FIX 100.300.113 Phase 7.41.4]: 添加详细调试日志
    if (!m_currentSerialPort) {
        return;
    }

    // ⚠️ 关键调试日志
    // 这里会读取串口的所有数据，可能与 ModbusSlaveController 产生数据竞争
    qDebug() << "🔍 [SerialPortController] handleReadyRead() 被调用";
    qDebug() << "   - 当前串口:" << m_currentSerialPort->portName();
    qDebug() << "   - 可用字节数:" << m_currentSerialPort->bytesAvailable();

    // 读取所有可用数据
    QByteArray data = m_currentSerialPort->readAll();

    if (data.isEmpty()) {
        qDebug() << "⚠️ [SerialPortController] 读取到的数据为空";
        return;
    }

    // 数据拼接逻辑
    m_dataBuffer.append(data);
    m_dataTimer->start();

    // 日志：显示接收到的数据片段
    qDebug() << "✅ [SerialPortController] 接收数据片段:"
             << data.size() << "字节"
             << "[HEX]" << byteArrayToHexString(data)
             << "缓冲区总计:" << m_dataBuffer.size() << "字节";

    // ⚠️ 检查是否是 MODBUS RTU 帧
    if (data.size() >= 4) {
        quint8 slaveAddr = static_cast<quint8>(data[0]);
        quint8 functionCode = static_cast<quint8>(data[1]);
        qDebug() << "🔍 [SerialPortController] 可能是 MODBUS RTU 帧:";
        qDebug() << "   - 从站地址:" << slaveAddr;
        qDebug() << "   - 功能码:" << QString("0x%1").arg(functionCode, 2, 16, QChar('0'));
        qWarning() << "⚠️ [SerialPortController] 警告：SerialPortController 读取了可能的 MODBUS 数据！";
        qWarning() << "   这可能导致 ModbusSlaveController 无法接收到完整的 MODBUS 帧！";
    }
}
```

1. 在界面左侧选择 COM1

3. 切换到"从站模式"
4. 点击"启动从站"按钮
5. 使用主站工具发送请求
6. **查看日志**：
   - 如果只看到 `🔍 [ModbusSlaveController] 串口接收到数据`
   - 没有看到 `🔍 [SerialPortController] handleReadyRead() 被调用`
   - 说明没有数据竞争
   - **从站应该能正常工作**

### Step 4: 对比两种场景的日志

**场景 A（有问题）**：
- SerialPortController 和 ModbusSlaveController 都收到 readyRead 信号
- SerialPortController 先读取数据

## 💡 解决方案

### 方案 1：启动从站前断开 SerialPortController 的信号连接（推荐）

**优点**：
- 彻底解决数据竞争问题
- 不影响 SerialPortController 的其他功能

**实现**：
```cpp
// 在 ModbusSlaveController::startSlave() 中
// 断开 SerialPortController 的 readyRead 信号
if (serialPortController && serialPortController->m_currentSerialPort) {
    disconnect(serialPortController->m_currentSerialPort, &QSerialPort::readyRead,
               serialPortController, &SerialPortController::handleReadyRead);
}
```

### 方案 2：在 SerialPortController 中检测从站是否运行

**优点**：
- 自动检测，无需手动操作

**实现**：
```cpp
void SerialPortController::handleReadyRead()
{
    // 检查是否有从站在运行
    if (isModbusSlaveRunning()) {
        qDebug() << "⚠️ [SerialPortController] MODBUS 从站正在运行，跳过数据读取";
        return;
    }

    // 正常读取数据
    // ...
}
```

### 方案 3：使用互斥锁（不推荐）

**缺点**：
- 增加复杂度
- 可能影响性能

## 💡 经验总结

### 成功经验
1. ✅ 通过添加详细日志，可以准确定位数据竞争问题
2. ✅ 识别了 SerialPortController 和 ModbusSlaveController 之间的冲突
3. ✅ 提供了多种解决方案供选择

### 技术要点
1. **Qt 信号机制**：
   - 一个信号可以连接多个槽函数
   - 所有槽函数都会被调用
   - 槽函数的执行顺序不确定

2. **串口数据读取**：
   - `readAll()` 会读取串口缓冲区的所有数据
   - 读取后，缓冲区会被清空
   - 其他对象无法再读取到数据

3. **数据竞争**：
   - 多个对象同时读取串口会导致数据分割
   - 需要确保同一时间只有一个对象读取串口
   - 或者使用信号断开/重连机制
