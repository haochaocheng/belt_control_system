**文档版本**: v1.0
**创建日期**: 2026-01-24

## 1. 需求概述

### 1.1 背景
- 第5个页面（输入监控）显示 4x3 网格（12个设备）
- 每个设备需要独立的参数配置
- 参数设置弹窗需要支持多个类别的参数

### 1.2 核心需求
1. **独立参数存储**：每个设备（1-12号皮带）有独立的参数配置
2. **参数复用**：基本参数直接复用主参数设置页面的内容
3. **新增类别**：左侧按钮需要支持设备特定的控制类别

---

## 2. 参数类别设计

### 2.1 左侧按钮类别（7个）

| 序号 | 类别名称 | 说明 | 参数来源 |
|------|---------|------|---------|
| 1 | **基本配置** | 设备基本信息、网络配置 | 复用主参数设置页面 |
| 2 | **开关量输入** | 数字输入信号配置 | 设备特定 |
| 3 | **模拟量输入** | 模拟输入信号配置 | 设备特定 |
| 4 | **电机控制** | 电机启停、速度控制 | 设备特定 |
| 5 | **制动器控制** | 制动器参数配置 | 设备特定 |
| 6 | **张紧控制** | 张紧装置参数配置 | 设备特定 |
| 7 | **逻辑控制** | 联锁逻辑、保护逻辑 | 设备特定 |

### 2.2 基本配置内容（复用）

**来源**：主参数设置页面（ParameterSettings.qml）

**包含内容**：
1. **基本参数**（BasicParametersSection.qml）
   - 本机编号
   - 工作模式（检修/运行）
   - 起车预警时间
   - 起车预警播放次数
   - 播放模式

2. **网络参数**（NetworkParametersSection.qml）
   - Modbus服务器IP
   - 网关
   - 子网掩码
   - 轮询间隔

**实现方式**：
- 直接引用现有的 QML 组件
- 参数绑定到设备特定的配置对象

## 3. 数据存储架构

### 3.1 数据结构设计

```cpp
// C++ 后端数据模型
class DeviceConfig {
public:
    int deviceId;                    // 设备ID (1-12)
    QString deviceName;              // 设备名称

    // 基本配置（复用主参数设置）
    BasicParameters basicParams;
    NetworkParameters networkParams;

    // 设备特定参数
    DigitalInputConfig digitalInputs;    // 开关量输入
    AnalogInputConfig analogInputs;      // 模拟量输入
    MotorControlConfig motorControl;     // 电机控制
    BrakeControlConfig brakeControl;     // 制动器控制
    TensionControlConfig tensionControl; // 张紧控制
    LogicControlConfig logicControl;     // 逻辑控制
};

// 设备配置管理器
class DeviceConfigManager : public QObject {
    Q_OBJECT
public:
    Q_INVOKABLE DeviceConfig* getDeviceConfig(int deviceId);
    Q_INVOKABLE void saveDeviceConfig(int deviceId, const DeviceConfig& config);
    Q_INVOKABLE void loadDeviceConfigs();

private:
    QMap<int, DeviceConfig> m_deviceConfigs;  // 12个设备的配置
    QString m_configFilePath;                  // 配置文件路径
};
```

## 4. QML 组件架构

```
│   │   └── NetworkParametersSection.qml (复用)
│   ├── DigitalInputPage.qml (开关量输入)
│   ├── AnalogInputPage.qml (模拟量输入)
│   ├── MotorControlPage.qml (电机控制)
│   ├── BrakeControlPage.qml (制动器控制)
│   ├── TensionControlPage.qml (张紧控制)
│   └── LogicControlPage.qml (逻辑控制)
└── 底部按钮区域 (动态按钮)
```

### 4.2 Loader 动态加载机制

```qml
// DeviceSettingsDialog.qml 中间内容区域
Loader {
    id: contentLoader
    anchors.fill: parent

    source: {
        switch(root.currentCategory) {
            case 0: return "pages/BasicConfigPage.qml"
            case 1: return "pages/DigitalInputPage.qml"
            case 2: return "pages/AnalogInputPage.qml"
            case 3: return "pages/MotorControlPage.qml"
            case 4: return "pages/BrakeControlPage.qml"
            case 5: return "pages/TensionControlPage.qml"
            case 6: return "pages/LogicControlPage.qml"
            default: return ""
        }
    }

    onLoaded: {
        // 传递设备配置对象
        if (item) {
            item.deviceConfig = deviceConfigManager.getDeviceConfig(root.deviceId)
        }
    }
}
```

## 5. 参数复用实现

### 5.1 BasicConfigPage.qml（基本配置页面）

```qml
// src/qml/components/device_info/pages/BasicConfigPage.qml
import QtQuick 2.15
import QtQuick.Controls 2.15
import "../../parameter_settings"  // 引用现有组件

Rectangle {
    id: root
    color: "transparent"

    property var deviceConfig  // 设备配置对象

    Column {
        anchors.fill: parent
        spacing: 20

        // ✅ 复用基本参数组件
        BasicParametersSection {
            width: parent.width

            // 绑定到设备配置
            machineNumber: deviceConfig ? deviceConfig.basicParams.machineNumber : 1
            workMode: deviceConfig ? deviceConfig.basicParams.workMode : "检修"
            startWarningTime: deviceConfig ? deviceConfig.basicParams.startWarningTime : 10
            // ... 其他参数绑定

            // 参数变化时更新设备配置
            onMachineNumberChanged: {
                if (deviceConfig) {
                    deviceConfig.basicParams.machineNumber = machineNumber
                }
            }
            // ... 其他参数变化处理
        }

        // ✅ 复用网络参数组件
        NetworkParametersSection {
            width: parent.width

            // 绑定到设备配置
            modbusServerIp: deviceConfig ? deviceConfig.networkParams.modbusServerIp : ""
            gateway: deviceConfig ? deviceConfig.networkParams.gateway : ""
            // ... 其他参数绑定
        }
    }
}
```

### 5.2 参数组件改造

**现有组件**：
- `BasicParametersSection.qml` - 基本参数
- `NetworkParametersSection.qml` - 网络参数

**改造要点**：
1. **添加属性绑定**：支持外部传入参数值
2. **添加信号**：参数变化时发出信号
3. **保持独立性**：不影响主参数设置页面的使用

**示例**：
```qml
// BasicParametersSection.qml 改造
Rectangle {
    id: root

    // ✅ 添加公开属性（支持外部绑定）
    property int machineNumber: 1
    property string workMode: "检修"
    property int startWarningTime: 10

    // ✅ 添加信号（参数变化通知）
    signal machineNumberChanged(int value)
    signal workModeChanged(string value)
    signal startWarningTimeChanged(int value)

    // 内部 UI 组件
    SpinBox {
        value: root.machineNumber
        onValueChanged: {
            root.machineNumber = value
            root.machineNumberChanged(value)
        }
    }
    // ...
}
```

## 8. 技术要点

### 8.1 参数隔离
- 每个设备有独立的配置对象
- 修改一个设备的参数不影响其他设备
- 配置文件按设备ID分组存储

### 8.2 组件复用
- 基本参数和网络参数直接复用现有组件
- 通过属性绑定实现数据传递
- 保持组件的独立性和可维护性

### 8.3 动态加载
- 使用 Loader 按需加载参数页面
- 减少内存占用
- 提高响应速度

### 8.4 数据持久化
- JSON 格式存储配置文件
- 支持导入/导出功能
- 支持恢复默认配置

## 10. 总结

### 10.1 架构优势
- ✅ **独立配置**：每个设备有独立的参数存储
- ✅ **组件复用**：基本参数直接复用现有组件
- ✅ **扩展性强**：易于添加新的参数类别
- ✅ **维护性好**：清晰的数据层和UI层分离

### 10.2 关键决策
1. **数据存储**：使用 JSON 文件存储，便于导入导出
2. **参数复用**：通过属性绑定复用现有组件
3. **动态加载**：使用 Loader 按需加载页面
4. **类别设计**：7个类别覆盖设备所有控制需求
