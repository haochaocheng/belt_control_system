# 参数设置区域切换方案对比

## 1. 方案对比

### 方案1: StackLayout（推荐 ⭐⭐⭐⭐⭐）

**实现方式**：
```qml
StackLayout {
    id: contentStack
    currentIndex: root.currentCategory

    BasicConfigPage { }      // 0: 基本配置
    DigitalInputPage { }     // 1: 开关量输入
    AnalogInputPage { }      // 2: 模拟量输入
    MotorControlPage { }     // 3: 电机控制
    BrakeControlPage { }     // 4: 制动器控制
    TensionControlPage { }   // 5: 张紧控制
    LogicControlPage { }     // 6: 逻辑控制
}
```

**优点**：
- ✅ **简单直观**：一行代码切换页面
- ✅ **自动管理**：StackLayout 自动处理显示/隐藏
- ✅ **性能好**：所有页面预加载，切换无延迟
- ✅ **状态保持**：切换后页面状态保留

**缺点**：
- ❌ **内存占用**：所有页面同时加载到内存
- ❌ **启动慢**：初始化时需要创建所有页面

**适用场景**：
- 页面数量少（7个页面可接受）
- 需要快速切换
- 页面状态需要保持

---

### 方案2: Loader 动态加载（推荐 ⭐⭐⭐⭐）

**实现方式**：
```qml
Loader {
    id: contentLoader
    anchors.fill: parent

    source: {
        switch(root.currentCategory) {
            case 0: return "pages/BasicConfigPage.qml"
            case 1: return "pages/DigitalInputPage.qml"
            case 2: return "pages/AnalogInputPage.qml"
            case 3: return "pages/MotorControlPage.qml"
            case 4: return "pages/BrakeControlPage.qml"
            case 5: return "pages/TensionControlPage.qml"
            case 6: return "pages/LogicControlPage.qml"
            default: return ""
        }
    }

    onLoaded: {
        if (item) {
            item.deviceConfig = deviceConfigManager.getDeviceConfig(root.deviceId)
        }
    }
}
```

**优点**：
- ✅ **内存高效**：只加载当前页面
- ✅ **启动快**：初始化只创建第一个页面
- ✅ **灵活**：可以动态传递参数
- ✅ **解耦**：页面独立，易于维护

**缺点**：
- ❌ **切换延迟**：首次加载页面有短暂延迟
- ❌ **状态丢失**：切换后页面状态不保留（除非手动保存）

**适用场景**：
- 页面数量多
- 内存受限
- 页面复杂度高

---

### 方案3: SwipeView（不推荐 ⭐⭐）

**实现方式**：
```qml
SwipeView {
    id: contentSwipe
    currentIndex: root.currentCategory

    BasicConfigPage { }
    DigitalInputPage { }
    // ...
}
```

**优点**：
- ✅ **支持手势**：可以滑动切换
- ✅ **动画流畅**：内置切换动画

**缺点**：
- ❌ **不适合键盘导航**：主要为触摸设计
- ❌ **内存占用**：所有页面预加载
- ❌ **非线性导航**：不适合跳跃式切换

**适用场景**：
- 触摸屏设备
- 线性导航（上一页/下一页）

---

### 方案4: 条件渲染（不推荐 ⭐）

**实现方式**：
```qml
BasicConfigPage {
    visible: root.currentCategory === 0
}
DigitalInputPage {
    visible: root.currentCategory === 1
}
// ...
```

**优点**：
- ✅ **简单**：无需额外容器

**缺点**：
- ❌ **性能差**：所有页面同时存在，只是隐藏
- ❌ **内存浪费**：所有页面占用内存
- ❌ **代码冗余**：每个页面都要写 visible 条件

**适用场景**：
- 页面非常简单
- 页面数量极少（2-3个）

## 2. 推荐方案：StackLayout

### 2.1 为什么选择 StackLayout？

对于您的场景（7个参数页面），**StackLayout 是最佳选择**：

1. **页面数量适中**：7个页面不会造成明显的内存压力
2. **快速切换**：键盘导航需要即时响应
3. **状态保持**：用户在不同页面间切换时，输入的参数不会丢失
4. **代码简洁**：一行代码 `currentIndex: root.currentCategory` 即可切换

### 2.2 实现方案

```qml
// DeviceSettingsDialog.qml 中间内容区域
Rectangle {
    id: contentArea
    anchors.left: leftButtonsContainer.right
    anchors.right: parent.right
    anchors.top: topButtonsContainer.bottom
    anchors.bottom: bottomButtonsContainer.top
    anchors.margins: 20
    color: "transparent"

    // ✅ 使用 StackLayout 切换页面
    StackLayout {
        id: contentStack
        anchors.fill: parent
        currentIndex: root.currentCategory  // 自动切换

        // 0: 基本配置
        BasicConfigPage {
            deviceId: root.deviceId
            deviceName: root.deviceName
        }

        // 1: 开关量输入
        DigitalInputPage {
            deviceId: root.deviceId
        }

        // 2: 模拟量输入
        AnalogInputPage {
            deviceId: root.deviceId
        }

        // 3: 电机控制
        MotorControlPage {
            deviceId: root.deviceId
        }

        // 4: 制动器控制
        BrakeControlPage {
            deviceId: root.deviceId
        }

        // 5: 张紧控制
        TensionControlPage {
            deviceId: root.deviceId
        }

        // 6: 逻辑控制
        LogicControlPage {
            deviceId: root.deviceId
        }
    }
}
```

### 2.3 页面组件结构

每个页面组件都遵循统一的结构：


## 3. 性能对比

### 3.1 内存占用

| 方案 | 初始内存 | 切换后内存 | 总内存 |
|------|---------|-----------|--------|
| **StackLayout** | 7页面 | 7页面 | 7页面 |
| **Loader** | 1页面 | 1页面 | 1页面 |
| **SwipeView** | 7页面 | 7页面 | 7页面 |
| **条件渲染** | 7页面 | 7页面 | 7页面 |

**结论**：Loader 内存最优，但对于7个页面，StackLayout 的内存占用可接受。

### 3.2 切换速度

| 方案 | 首次切换 | 后续切换 |
|------|---------|---------|
| **StackLayout** | 0ms | 0ms |
| **Loader** | 50-100ms | 50-100ms |
| **SwipeView** | 0ms | 0ms |
| **条件渲染** | 0ms | 0ms |

**结论**：StackLayout 切换最快，无延迟。

### 3.3 代码复杂度

| 方案 | 代码行数 | 维护难度 |
|------|---------|---------|
| **StackLayout** | 少 | 低 |
| **Loader** | 中 | 中 |
| **SwipeView** | 少 | 低 |
| **条件渲染** | 多 | 高 |

**结论**：StackLayout 代码最简洁。

## 5. 备选方案：Loader（未来优化）

如果未来页面数量增加（超过10个），或者页面复杂度很高，可以考虑切换到 Loader 方案：

**优化策略**：
1. **缓存机制**：使用 Loader 的 `active` 属性，保留最近访问的3个页面
2. **预加载**：在空闲时预加载下一个可能访问的页面
3. **状态保存**：手动保存页面状态到 C++ 后端

**示例代码**：
```qml
Loader {
    id: contentLoader
    anchors.fill: parent
    active: true  // 保持活动状态

    source: getPageSource(root.currentCategory)

    // 缓存最近3个页面
    property var pageCache: []

    function getPageSource(index) {
        // 缓存逻辑
        return "pages/" + getPageName(index) + ".qml"
    }
}
```
