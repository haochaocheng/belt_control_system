## 问题分析

### 代码检查

**SerialPortSendTab.qml的handleEnterKey()函数（lines 103-112）**：
```qml
case 2:  // 发送数据TextArea
    // 弹出虚拟键盘
    if (virtualKeyboard && typeof virtualKeyboard.activateVirtualKeyboard === "function") {
        console.log("✅ [SerialPortSendTab] 激活虚拟键盘 - 发送数据")
        virtualKeyboard.activateVirtualKeyboard(sendInput)
        return true
    } else {
        console.log("⚠️ [SerialPortSendTab] 虚拟键盘不可用")  // ← 执行了这里
        return false
    }
```

**条件判断失败**：
- `virtualKeyboard`为null/undefined，或者
- `virtualKeyboard.activateVirtualKeyboard`不是函数

### 属性传递链检查

**完整的属性传递链**：
```
DeviceSettingsDialog (持有虚拟键盘)
    ↓ virtualKeyboard 属性
SerialPortControlPage
    ↓ virtualKeyboard 属性
SerialPortConfigPanel
    ↓ virtualKeyboard 属性
SerialPortSendTab
    ↓ 在 handleEnterKey 中使用
```

**检查结果**：

1. **SerialPortSendTab.qml（line 20）**：
   ```qml
   property var virtualKeyboard: null  // ✅ 属性定义存在
   ```

2. **SerialPortConfigPanel.qml（lines 292-294）**：
   ```qml
   item.virtualKeyboard = Qt.binding(function() {
       return root.virtualKeyboard  // ✅ 正确传递
   })
   ```

3. **SerialPortControlPage.qml（line 505）**：
   ```qml
   item.virtualKeyboard = Qt.binding(function() { return root.virtualKeyboard })  // ✅ 正确传递
   ```

4. **DeviceSettingsDialog.qml（lines 2124-2135）**：
   ```qml
   id: serialPortControlPageLoader
   source: "pages/SerialPortControlPage.qml"

   onLoaded: {
       console.log("✅ [DeviceSettingsDialog] SerialPortControlPage 加载成功")
       // ❌ 没有传递 virtualKeyboard 属性！
   }
   ```

### 根本原因

**DeviceSettingsDialog没有传递virtualKeyboard给SerialPortControlPage！**

这导致SerialPortControlPage的virtualKeyboard属性始终为null，进而导致整个传递链中的virtualKeyboard都是null。

## 修复方案

### 修改DeviceSettingsDialog.qml

在serialPortControlPageLoader的onLoaded处理器中，添加virtualKeyboard属性传递：

**修改位置**：DeviceSettingsDialog.qml lines 2127-2129

**修改前**：
```qml
onLoaded: {
    console.log("✅ [DeviceSettingsDialog] SerialPortControlPage 加载成功")
}
```

**修改后**：
```qml
onLoaded: {
    console.log("✅ [DeviceSettingsDialog] SerialPortControlPage 加载成功")

    // ✅ 2026-02-05 [FIX 100.300.113 Phase 7.37.13.2]: 传递虚拟键盘引用
    if (item) {
        item.virtualKeyboard = Qt.binding(function() {
            return root.virtualKeyboard
        })
    }
}
```

## 技术要点

### 1. 属性传递链的完整性

**关键原则**：
- 属性传递链必须完整，不能有断点
- 每个Loader的onLoaded处理器都要传递必要的属性
- 使用Qt.binding()保持双向绑定

**检查方法**：
1. 从最终使用的地方开始，逆向检查每一层
2. 确认每个Loader都正确传递了属性
3. 使用日志输出属性值，确认不是null

### 2. Qt.binding()的重要性

**为什么使用Qt.binding()**：
```qml
// ✅ 正确：使用Qt.binding()
item.virtualKeyboard = Qt.binding(function() {
    return root.virtualKeyboard
})

// ❌ 错误：直接赋值
item.virtualKeyboard = root.virtualKeyboard
```

**原因**：
- Qt.binding()创建动态绑定，属性值会自动更新
- 直接赋值只在初始化时复制一次，后续不会更新
- 如果root.virtualKeyboard在初始化时是null，直接赋值会永远是null

### 3. 调试方法

**如何快速定位属性传递问题**：

1. **在每个Loader的onLoaded中添加日志**：
   ```qml
   onLoaded: {
       console.log("✅ [Component] 加载成功")
       console.log("   - virtualKeyboard:", item.virtualKeyboard)
       console.log("   - root.virtualKeyboard:", root.virtualKeyboard)
   }
   ```

2. **在使用属性的地方添加日志**：
   ```qml
   function handleEnterKey() {
       console.log("✅ virtualKeyboard:", virtualKeyboard)
       console.log("✅ typeof activateVirtualKeyboard:",
                   typeof virtualKeyboard.activateVirtualKeyboard)
   }
   ```

3. **逐层检查**：
   - 从最终使用的地方开始
   - 逆向检查每一层的属性值
   - 找到第一个为null的地方

## 教训总结

### ✅ 成功经验

1. **详细的日志分析**
   - 通过日志快速定位问题
   - 发现"虚拟键盘不可用"的关键信息
   - 区分"函数不存在"和"属性为null"

2. **逆向检查属性传递链**
   - 从使用的地方开始，逆向检查
   - 逐层确认每个Loader的配置
   - 找到断点所在

3. **代码对比**
   - 对比其他正常工作的页面（如电机控制）
   - 发现缺失的属性传递
   - 参考成功的实现

### ⚠️ 避免的错误

1. **假设属性会自动传递**
   - 每个Loader都要显式传递属性
   - 不能假设子组件会自动获得父组件的属性

2. **忽略Loader的onLoaded处理器**
   - onLoaded是传递属性的关键时机
   - 必须在这里配置所有必要的属性

3. **不检查属性传递链的完整性**
   - 属性传递链必须完整
   - 任何一层缺失都会导致整个链断裂
