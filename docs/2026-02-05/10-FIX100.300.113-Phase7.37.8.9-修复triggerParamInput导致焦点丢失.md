## 📋 问题描述

**用户反馈**:
> "查看日志，布局问题解决了，继续参考电机控制，导航键使用的方法，现在焦点只要移动到com1.导航键再也无法使用，不能移动焦点了"

**问题现象**:
- Phase 7.37.8.8 修复后，布局问题已解决（GridLayout 宽度正常）
- 新问题：焦点移动到参数区域（COM1）后，导航键停止工作
- 无法使用上下左右键移动焦点
- 焦点指示器不显示

**日志分析**（pjsip.md lines 346-348）:
```
Debug: ? [SerialPortControlPage] triggerParamInput - 参数索引: 0
Debug: ? [SerialPortParamsTab] 触发参数输入 - 索引: 0
Debug: ?? [DeviceSettingsDialog root] activeFocus 变化: false
```

**关键发现**：
- `triggerParamInput()` 被调用后，DeviceSettingsDialog 失去 activeFocus
- DeviceSettingsDialog 失去焦点后，Keys 事件不再被处理
- 导航键无法工作

## 🔍 问题分析

### 根本原因

**对比 BasicConfigTab（电机控制，成功）和 SerialPortParamsTab（串口控制，失败）**：

**BasicConfigTab.qml**（成功）:
```qml
function triggerParamInput(paramIndex) {
    console.log("✅ [BasicConfigTab] 触发参数输入 - 索引:", paramIndex)

    var inputField = null

    switch(paramIndex) {
    case 0:  // 运行状态（RadioButton 组）
        console.log("✅ [BasicConfigTab] 切换运行状态")
        break
    case 1:  // 模块类型（只读）
        console.log("✅ [BasicConfigTab] 模块类型（只读）")
        break
    case 2:  // 模块地址
        inputField = moduleAddressSpin
        break
    // ... other cases
    }

    // ✅ 只对可编辑控件调用 activateVirtualKeyboard
    // ✅ 不调用 forceActiveFocus()
    if (inputField) {
        if (inputField.activateVirtualKeyboard) {
            inputField.activateVirtualKeyboard()
        } else {
            inputField.forceActiveFocus()  // 只作为后备方案
        }
    }
}
```

**焦点指示器使用 `root.focusParamIndex`**:
```qml
Rectangle {
    anchors.fill: parent
    color: "transparent"
    border.color: (root.focusParamIndex === 0) ? "#2196F3" : "transparent"
    border.width: (root.focusParamIndex === 0) ? 3 : 0
    radius: 4
    z: 10
}
```

**SerialPortParamsTab.qml**（失败，Phase 7.37.8.8 之前）:
```qml
function triggerParamInput(paramIndex) {
    // ... switch cases ...

    // ❌ 对所有控件调用 forceActiveFocus()
    if (inputField) {
        inputField.forceActiveFocus()  // 导致 DeviceSettingsDialog 失去焦点
    }
}
```

**焦点指示器使用 `activeFocus`**:
```qml
Rectangle {
    anchors.fill: parent
    color: "transparent"
    border.color: parent.activeFocus ? "#2196F3" : "transparent"  // ❌ 需要 forceActiveFocus()
    border.width: parent.activeFocus ? 3 : 0
    radius: 4
    z: 10
}
```

### 为什么会导致焦点丢失

**问题链**：
1. `triggerParamInput()` 调用 `forceActiveFocus()` 激活输入控件
2. 输入控件获得 activeFocus，DeviceSettingsDialog 失去 activeFocus
3. DeviceSettingsDialog 的 Keys 事件处理器不再接收事件（需要 activeFocus）
4. 导航键无法工作

**为什么 BasicConfigTab 不会有这个问题**：
1. BasicConfigTab 不调用 `forceActiveFocus()`（只读字段）
2. 焦点指示器使用 `root.focusParamIndex`，不依赖 activeFocus
3. DeviceSettingsDialog 始终保持 activeFocus
4. Keys 事件正常处理

## 💡 技术要点

### forceActiveFocus() 的副作用

**问题**：
- `forceActiveFocus()` 会将 activeFocus 从父元素转移到子元素
- 父元素失去 activeFocus 后，Keys 事件处理器不再接收事件
- 导致导航键无法工作

**解决方案**：
- 不调用 `forceActiveFocus()`
- 使用 `focusParamIndex` 属性控制焦点指示器
- 只对可编辑字段调用 `activateVirtualKeyboard()`

### focusParamIndex vs activeFocus

**focusParamIndex**（推荐）:
```qml
// ✅ 不依赖 activeFocus
// ✅ 不需要调用 forceActiveFocus()
// ✅ 父元素保持 activeFocus
border.color: (root.focusParamIndex === 0) ? "#2196F3" : "transparent"
```

**activeFocus**（不推荐）:
```qml
// ❌ 依赖 activeFocus
// ❌ 需要调用 forceActiveFocus()
// ❌ 父元素失去 activeFocus
border.color: parent.activeFocus ? "#2196F3" : "transparent"
```

### 参考 BasicConfigTab 的成功经验

**BasicConfigTab 的关键设计**：
1. **不调用 forceActiveFocus()**：只读字段不设置 inputField
2. **使用 focusParamIndex**：焦点指示器不依赖 activeFocus
3. **只激活虚拟键盘**：可编辑字段只调用 `activateVirtualKeyboard()`
4. **保持父元素焦点**：DeviceSettingsDialog 始终保持 activeFocus

**SerialPortParamsTab 的修复**：
- 完全复制 BasicConfigTab 的设计
- 移除所有 `forceActiveFocus()` 调用
- 将所有焦点指示器改为使用 `focusParamIndex`
