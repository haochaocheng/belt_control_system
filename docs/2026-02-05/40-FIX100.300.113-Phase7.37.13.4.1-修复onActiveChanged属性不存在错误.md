**DeviceSettingsDialog.qml（lines 128-140）**：
```qml

    id: qtVirtualKeyboard

    // ❌ 错误：使用了不存在的 onActiveChanged
```

### 问题分析

**QtVirtualKeyboardIntegration的实际类型**：

- `Popup`没有`active`属性，也没有`onActiveChanged`信号
- `Popup`有`visible`属性和`onClosed`信号

**正确的信号**：

- ❌ `onActiveChanged`：不存在

## 修复方案

### 使用onClosed代替onActiveChanged

**修改DeviceSettingsDialog.qml（lines 128-137）**：

**修改前**：
```qml
// ✅ 2026-02-05 [FIX 100.300.113 Phase 7.37.13.4]: 监听虚拟键盘关闭事件
// 当虚拟键盘关闭时，恢复对话框的焦点，以便导航键继续工作
onActiveChanged: {
    console.log("✅ [DeviceSettingsDialog] 虚拟键盘 active 变化:", active)
    if (!active) {
        // 虚拟键盘关闭，恢复对话框焦点
        console.log("✅ [DeviceSettingsDialog] 虚拟键盘关闭，恢复对话框焦点")
        Qt.callLater(function() {
            root.forceActiveFocus()
            console.log("✅ [DeviceSettingsDialog] 对话框焦点已恢复")
        })
    }
}
```

**修改后**：
```qml
// ✅ 2026-02-05 [FIX 100.300.113 Phase 7.37.13.4.1]: 监听虚拟键盘关闭事件
// 当虚拟键盘关闭时，恢复对话框的焦点，以便导航键继续工作
// 注意：QtVirtualKeyboardIntegration 是 Popup，使用 onClosed 而不是 onActiveChanged
onClosed: {
    console.log("✅ [DeviceSettingsDialog] 虚拟键盘已关闭，恢复对话框焦点")
    Qt.callLater(function() {
        root.forceActiveFocus()
        console.log("✅ [DeviceSettingsDialog] 对话框焦点已恢复")
    })
}
```

**关键变化**：
- ❌ 不再使用`onActiveChanged`
- ✅ 使用`onClosed`
- ✅ 简化逻辑，不需要判断`if (!active)`
- ✅ 添加注释说明QtVirtualKeyboardIntegration是Popup

## 技术要点

### 1. QtVirtualKeyboardIntegration的实际类型

**定义**（QtVirtualKeyboardIntegration.qml line 8）：
```qml
Popup {
    id: root
    width: parent.width
    height: 350
    y: parent.height - height
    modal: false
    closePolicy: Popup.NoAutoClose
    // ...
}
```

**关键信息**：
- QtVirtualKeyboardIntegration是`Popup`，不是`InputPanel`
- `Popup`有`visible`属性，但没有`active`属性
- `Popup`有`onClosed`信号，但没有`onActiveChanged`信号

### 2. Popup的信号

**可用信号**：
- `onOpened`：当Popup打开时触发
- `onClosed`：当Popup关闭时触发
- `onVisibleChanged`：当visible属性变化时触发

**不可用信号**：
- `onActiveChanged`：不存在

### 3. 为什么Phase 7.37.13.4使用了错误的信号

**原因**：
- 假设QtVirtualKeyboardIntegration是Qt官方的InputPanel
- Qt官方的InputPanel有`active`属性和`onActiveChanged`信号
- 但是我们的QtVirtualKeyboardIntegration是自定义的Popup
- 没有检查实际的实现就使用了错误的信号

**教训**：
- 使用组件前，先检查组件的实际实现
- 不要假设组件的类型和属性
- 查看源码确认可用的属性和信号

### 4. 如何避免类似错误

**步骤**：
1. 使用组件前，先查看组件的定义文件
2. 确认组件的基类（Popup、Item、Rectangle等）
3. 查看组件的可用属性和信号
4. 使用正确的属性和信号

**示例**：
```qml
// ❌ 错误：假设组件有某个属性
MyComponent {
    onSomeSignal: { /* ... */ }  // 可能不存在
}

// ✅ 正确：先查看组件定义，确认信号存在
MyComponent {
    onActualSignal: { /* ... */ }  // 确认存在
}
```
