## 问题描述

### 用户反馈

Phase 7.37.13.3修复后，用户测试发现：

1. **问题1**：焦点进入文本输入区就直接打开了虚拟键盘，需要按回车键才能打开
2. **问题2**：按ESC退出虚拟键盘后，导航键无法使用，使用下键无法将焦点移动到发送区

## 问题分析

### 问题1：虚拟键盘自动弹出

**日志分析（pjsip.md lines -11 to -7）**：
```
Debug: ✅ [SerialPortSendTab] 触发参数输入 - 索引: 2
Debug: ✅ [SerialPortSendTab] 发送数据
Debug: ✅ [SerialPortSendTab] 激活虚拟键盘 - 控件: TextArea_QMLTYPE_285(0x25161a1ecc0)
Debug:    - inputField.activateVirtualKeyboard 类型: undefined
Debug: ✅ [SerialPortSendTab] 调用 inputField.forceActiveFocus()
```

**根本原因**：
1. 当焦点移动到TextArea时，`triggerParamInput()`函数被调用
2. `inputField.activateVirtualKeyboard`是`undefined`（不存在）
3. 执行了回退方案：`inputField.forceActiveFocus()`
4. `forceActiveFocus()`会自动触发虚拟键盘打开

**问题所在**：
- `triggerParamInput()`的职责应该是移动焦点，不应该打开虚拟键盘
- 只有按回车键（`handleEnterKey()`）时才应该打开虚拟键盘
- 这样用户可以使用方向键在控件之间导航，而不会自动弹出虚拟键盘

### 问题2：虚拟键盘关闭后焦点丢失

**日志分析（pjsip.md lines -2 to -1）**：
```
Debug: ⚠️ [DeviceSettingsDialog root] activeFocus 变化: false
Debug: ⚠️ [QDS InputPanel] Active changed: false
```

**根本原因**：
1. 虚拟键盘关闭后，DeviceSettingsDialog失去了activeFocus
2. 没有activeFocus，Keys事件处理器不会接收键盘事件
3. 导致导航键无法工作

**问题所在**：
- 虚拟键盘关闭时，没有恢复对话框的焦点
- 需要监听虚拟键盘的关闭事件，主动恢复焦点

```qml
        console.log("   - inputField.activateVirtualKeyboard 类型:", typeof inputField.activateVirtualKeyboard)

        // 如果控件有 activateVirtualKeyboard 函数，调用它

            console.log("✅ [SerialPortSendTab] 调用 inputField.activateVirtualKeyboard()")
            inputField.activateVirtualKeyboard()
        } else {
            // 否则直接设置焦点
            console.log("✅ [SerialPortSendTab] 调用 inputField.forceActiveFocus()")
            inputField.forceActiveFocus()
        }
    }

```

**修改后**：

**关键变化**：
- ❌ 不再调用`inputField.activateVirtualKeyboard()`
- ❌ 不再调用`inputField.forceActiveFocus()`
- ✅ 只更新焦点指示器，不打开虚拟键盘
- ✅ 只有按回车键时才打开虚拟键盘

### 修复2：虚拟键盘关闭后恢复焦点

**修改DeviceSettingsDialog.qml的qtVirtualKeyboard（lines 122-141）**：

**修改前**：
```qml
// ✅ 2026-01-29 [Qt 虚拟键盘]: 使用 Qt 自带的虚拟键盘
VirtualKeyboard.QtVirtualKeyboardIntegration {
    id: qtVirtualKeyboard
    parent: Overlay.overlay  // 显示在最顶层
    z: 2000  // 确保在对话框上方
}
```

**修改后**：
```qml
// ✅ 2026-01-29 [Qt 虚拟键盘]: 使用 Qt 自带的虚拟键盘
VirtualKeyboard.QtVirtualKeyboardIntegration {
    id: qtVirtualKeyboard
    parent: Overlay.overlay  // 显示在最顶层
    z: 2000  // 确保在对话框上方

    // ✅ 2026-02-05 [FIX 100.300.113 Phase 7.37.13.4]: 监听虚拟键盘关闭事件
    // 当虚拟键盘关闭时，恢复对话框的焦点，以便导航键继续工作
    onActiveChanged: {
        console.log("✅ [DeviceSettingsDialog] 虚拟键盘 active 变化:", active)
        if (!active) {
            // 虚拟键盘关闭，恢复对话框焦点
            console.log("✅ [DeviceSettingsDialog] 虚拟键盘关闭，恢复对话框焦点")
            Qt.callLater(function() {
                root.forceActiveFocus()
                console.log("✅ [DeviceSettingsDialog] 对话框焦点已恢复")
            })
        }
    }
}
```

**关键变化**：
- ✅ 添加`onActiveChanged`处理器
- ✅ 监听虚拟键盘的active属性变化
- ✅ 当虚拟键盘关闭（active变为false）时，恢复对话框焦点
- ✅ 使用`Qt.callLater()`确保在虚拟键盘完全关闭后再恢复焦点

## 技术要点

### 1. triggerParamInput vs handleEnterKey

**triggerParamInput()**：
- 职责：移动焦点，更新焦点指示器
- 触发时机：使用方向键导航时
- 行为：只更新focusParamIndex，不打开虚拟键盘

**handleEnterKey()**：
- 职责：处理回车键，执行控件的默认操作
- 触发时机：按回车键时
- 行为：根据控件类型执行不同操作（切换选项、打开虚拟键盘、执行按钮）

### 2. 焦点管理的重要性

**为什么需要恢复焦点**：
- Qt的Keys事件处理器只在控件有activeFocus时才工作
- 虚拟键盘打开时，会抢占焦点
- 虚拟键盘关闭后，如果不恢复焦点，Keys事件处理器不会接收事件
- 导致导航键无法工作

**恢复焦点的方法**：
```qml
onActiveChanged: {
    if (!active) {
        Qt.callLater(function() {
            root.forceActiveFocus()
        })
    }
}
```

**为什么使用Qt.callLater()**：
- 确保在虚拟键盘完全关闭后再恢复焦点
- 避免焦点冲突
- 更可靠

### 3. 用户体验设计

**导航键 vs 回车键**：
- 导航键：快速浏览，不打开虚拟键盘
- 回车键：确认输入，打开虚拟键盘

**为什么这样设计**：
- 用户可以快速浏览所有控件，不会被虚拟键盘打断
- 只有在确定要输入时，才按回车键打开虚拟键盘
- 提升操作效率，减少干扰

## 教训总结

### ✅ 成功经验

1. **区分不同函数的职责**
   - triggerParamInput：移动焦点
   - handleEnterKey：执行操作
   - 不要混淆职责

2. **监听虚拟键盘状态变化**
   - 使用onActiveChanged监听
   - 虚拟键盘关闭时恢复焦点
   - 确保导航键继续工作

3. **使用Qt.callLater()确保时序**
   - 避免焦点冲突
   - 确保操作在正确的时机执行

4. **详细的日志输出**
   - 帮助快速定位问题
   - 区分不同的执行路径

### ⚠️ 避免的错误

1. **triggerParamInput自动打开虚拟键盘**
   - 导致用户无法快速导航
   - 虚拟键盘频繁弹出，干扰操作

2. **虚拟键盘关闭后不恢复焦点**
   - 导致导航键无法工作
   - 用户体验很差

3. **混淆导航和输入的职责**
   - 导航应该快速、不打断
   - 输入应该明确、有确认
