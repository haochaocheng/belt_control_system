## 问题描述

### 用户反馈

Phase 7.37.9.2修复后，焦点指示器工作正常，但导航逻辑有两个问题：

1. **左键导航失效**：
   - 焦点在清空按钮（索引4）时，按左键无法移动到发送按钮（索引3）
   - 日志显示：`[NavigationManager] 方向键: Left 当前区域: C 当前索引: 4`
   - 但焦点没有变化

2. **下键导航逻辑错误**：
   - 焦点在发送数据（索引2）时，按下键进入清空按钮（索引4）
   - ❌ 应该进入发送按钮（索引3）
   - 用户反馈："正常使用状态时焦点在文本输入框，下键直接进入发送按钮"

### 日志分析

```
Debug: ? [NavigationManager] 方向键: Down 当前区域: C 当前索引: 0
Debug: ?? [NavigationManager] paramIndex 变化: 2
Debug: ? [NavigationManager] 方向键: Down 当前区域: C 当前索引: 2
Debug: ?? [NavigationManager] paramIndex 变化: 4  // ❌ 应该是3
Debug: ? [NavigationManager] 方向键: Left 当前区域: C 当前索引: 4
// ❌ 没有变化
```

## 问题分析

### 1. 发送区的布局特殊

发送区的布局不是标准的2列布局：

```
行0：[0] 格式（右上角）    [1] （空）
行1：[2] 发送数据（跨2列）
行2：[3] 发送按钮          [4] 清空按钮
```

**特点**：
- 索引1为空（保留用于对齐）
- 索引2跨2列（发送数据文本框）
- 索引3和4在同一行（发送按钮和清空按钮）

### 2. NavigationManager的2列布局假设

NavigationManager假设所有参数区域都是标准的2列布局：

```qml
case "Down":
    var nextIndex = paramIndex + 2  // 下键：同列下一行（索引+2）
    if (nextIndex > lastParamIndex) {
        switchToArea(areaButtons)
    } else {
        paramIndex = nextIndex
    }
    break

case "Left":
    if (paramIndex % 2 === 1) {  // 奇数列（右列）
        paramIndex = paramIndex - 1  // 向左移动到左列
    }
    // 偶数列（左列）：保持不变
    break
```

**问题**：

1. **下键导航**：
   - 索引2按下键：nextIndex = 2 + 2 = 4（清空按钮）
   - ❌ 应该是：nextIndex = 3（发送按钮）

2. **左键导航**：
   - 索引4按左键：4 % 2 = 0（偶数，认为在左列）
   - NavigationManager认为已经在左列，无法向左移动
   - ❌ 应该是：4是右列，可以向左移动到3

### 3. 根本原因

**NavigationManager的2列布局逻辑不适用于发送区的特殊布局**。

## 解决方案

### 方案选择

**方案1**：在SerialPortSendTab中重写导航逻辑（✅ 采用）
- 优点：不影响其他Tab，灵活性高
- 缺点：需要在SerialPortControlPage中添加调用逻辑

**方案2**：调整发送区的索引分配，使其符合2列布局
- 优点：不需要修改导航逻辑
- 缺点：索引分配不直观，难以维护

**选择方案1**，因为发送区的布局确实特殊（发送数据跨2列），自定义导航逻辑更合理。

### 实现步骤

#### Step 1: 在SerialPortSendTab中添加handleDirectionKey()函数

```qml
// SerialPortSendTab.qml
function handleDirectionKey(direction) {
    console.log("✅ [SerialPortSendTab] 自定义导航 - 方向:", direction, "当前索引:", focusParamIndex)

    var newIndex = focusParamIndex

    switch(direction) {
    case "Down":
        if (focusParamIndex === 0) {
            newIndex = 2  // 格式 → 发送数据
        } else if (focusParamIndex === 2) {
            newIndex = 3  // 发送数据 → 发送按钮（左侧按钮）
        }
        break

    case "Up":
        if (focusParamIndex === 3 || focusParamIndex === 4) {
            newIndex = 2  // 发送按钮或清空按钮 → 发送数据
        } else if (focusParamIndex === 2) {
            newIndex = 0  // 发送数据 → 格式
        }
        break

    case "Left":
        if (focusParamIndex === 4) {
            newIndex = 3  // 清空按钮 → 发送按钮
        }
        break

    case "Right":
        if (focusParamIndex === 3) {
            newIndex = 4  // 发送按钮 → 清空按钮
        }
        break
    }

    if (newIndex !== focusParamIndex) {
        console.log("✅ [SerialPortSendTab] 导航索引变化:", focusParamIndex, "→", newIndex)
        requestFocusParamIndex(newIndex)
        return true  // 导航成功
    }

    return false  // 导航无变化
}
```

#### Step 2: 在SerialPortConfigPanel中添加getCurrentTabItem()函数

```qml
// SerialPortConfigPanel.qml
function getCurrentTabItem() {
    switch(currentTabIndex) {
    case 0:  // 参数配置
        return paramsTabLoader.item
    case 1:  // 发送区
        return sendTabLoader.item
    case 2:  // 接收区
        return receiveTabLoader.item
    case 3:  // MODBUS寄存器
        return modbusTabLoader.item
    default:
        return null
    }
}
```

#### Step 3: 在SerialPortControlPage中调用自定义导航

```qml
// SerialPortControlPage.qml
Keys.onDownPressed: {
    // ...
    // ✅ 2026-02-05 [FIX 100.300.113 Phase 7.37.9.3]: 发送区Tab使用自定义导航
    if (navigationManager.currentArea === navigationManager.areaParams) {
        var configPanel = serialConfigPanel.item
        if (configPanel && typeof configPanel.getCurrentTabItem === "function") {
            var currentTab = configPanel.getCurrentTabItem()
            if (currentTab && typeof currentTab.handleDirectionKey === "function") {
                console.log("✅ [SerialPortControlPage] 调用当前Tab自定义导航")
                var handled = currentTab.handleDirectionKey("Down")
                if (handled) {
                    event.accepted = true
                    return
                }
            }
        }
    }

    navigationManager.handleDirectionKey("Down")
    event.accepted = true
}
```

**同样的逻辑应用于上键、左键、右键**。


## 技术要点

### 1. 自定义导航的实现模式

**在Tab组件中实现handleDirectionKey()函数**：

```qml
function handleDirectionKey(direction) {
    var newIndex = focusParamIndex

    // 根据direction和focusParamIndex计算newIndex
    switch(direction) {
    case "Down":
        // 自定义下键逻辑
        break
    case "Up":
        // 自定义上键逻辑
        break
    case "Left":
        // 自定义左键逻辑
        break
    case "Right":
        // 自定义右键逻辑
        break
    }

    if (newIndex !== focusParamIndex) {
        requestFocusParamIndex(newIndex)
        return true  // 导航成功
    }

    return false  // 导航无变化
}
```

**返回值**：
- `true`：导航成功，调用者应该停止处理
- `false`：导航无变化，调用者应该继续使用默认逻辑

### 2. 在父组件中调用自定义导航

**检查当前Tab是否有自定义导航**：

```qml
if (navigationManager.currentArea === navigationManager.areaParams) {
    var configPanel = serialConfigPanel.item
    if (configPanel && typeof configPanel.getCurrentTabItem === "function") {
        var currentTab = configPanel.getCurrentTabItem()
        if (currentTab && typeof currentTab.handleDirectionKey === "function") {
            var handled = currentTab.handleDirectionKey(direction)
            if (handled) {
                return  // 自定义导航成功，停止处理
            }
        }
    }
}

// 使用默认导航逻辑
navigationManager.handleDirectionKey(direction)
```

### 3. 辅助函数的设计

**getCurrentTabItem()函数**：

```qml
function getCurrentTabItem() {
    switch(currentTabIndex) {
    case 0: return paramsTabLoader.item
    case 1: return sendTabLoader.item
    case 2: return receiveTabLoader.item
    case 3: return modbusTabLoader.item
    default: return null
    }
}
```

**优点**：
- 封装了Tab item的访问逻辑
- 避免在父组件中直接访问children
- 易于维护和扩展

## 总结

### 问题根源

NavigationManager的2列布局逻辑不适用于发送区的特殊布局（发送数据跨2列）。

### 修复方法

在SerialPortSendTab中实现自定义的handleDirectionKey()函数，在SerialPortControlPage中优先调用自定义导航。

### 教训总结

1. ✅ **特殊布局需要自定义导航逻辑**
2. ✅ **使用返回值表示导航是否成功**
3. ✅ **封装辅助函数（getCurrentTabItem）**
4. ✅ **保持代码一致性（上下左右键都使用相同的模式）**
5. ✅ **优先调用自定义导航，失败时使用默认逻辑**
