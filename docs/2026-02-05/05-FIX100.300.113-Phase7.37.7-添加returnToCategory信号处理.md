## 📋 问题描述

**用户反馈**:
> "解决得问题：焦点从modbus寄存器时，按左键可以依次得向左移动，新问题，焦点在COM1时，按左键无法回到串口控制按钮"

**问题现象**:
- ✅ Phase 7.37.6 已修复：焦点从MODBUS寄存器按左键可以依次向左移动（Tab导航正常）
- ❌ 新问题：焦点在COM1（串口列表）时，按左键无法返回到串口控制按钮（类别区域）

**日志分析**（pjsip.md lines 412-436）:
```
Debug: ✅ [导航] 左键 - 当前区域: 2
Debug: ✅ [导航] 串口控制页面左键 - 调用NavigationManager
Debug: ✅ [NavigationManager] 方向键: Left 当前区域: A 当前索引: 0
```

重复了很多次，说明在列表区域按左键，NavigationManager处理了，但是没有返回到类别区域。

---

## 🔍 问题分析

### 根本原因

**NavigationManager.qml lines 107-111**：
```qml
case "Left":
    // ✅ 2026-01-30 [FIX 100.300.109 Phase 2.8]: 向左返回到大类（电机控制）
    // 通过自定义信号通知外部返回到左侧类别
    returnToCategory()
    return
```

NavigationManager的`moveInMotorList`函数中，左键会调用`returnToCategory()`信号。

**问题**：
- MotorControlPage连接了这个信号（lines 143-149）
- 但SerialPortControlPage**没有连接**这个信号
- 导致列表区域按左键时，信号发出但没有处理器接收
- 焦点无法返回到类别区域

### MotorControlPage的实现（参考）

**MotorControlPage.qml lines 143-149**：
```qml
// ✅ 2026-02-03 [FIX 100.300.112.8.25.7.24]: 监听 returnToCategory 信号，释放焦点
onReturnToCategory: {
    console.log("✅ [MotorControlPage] 接收到 returnToCategory 信号，释放焦点")
    // 设置标志，防止后续键盘事件被处理
    root.isReturningToCategory = true
    // 禁用键盘事件接收
    root.keysEnabled = false
    // 主动通知 DeviceSettingsDialog 获取焦点
    root.requestReturnToCategory()
    // 延迟重置标志
    resetFlagTimer.start()
}
```

### 为什么Phase 7.37.6没有解决这个问题

**Phase 7.37.6的修复**：
- 在DeviceSettingsDialog的Keys.onLeftPressed中添加了串口控制页面判断
- 调用`serialPage.navigationManager.handleDirectionKey("Left")`
- 这修复了Tab区域的左键导航

**但是**：
- NavigationManager的`handleDirectionKey("Left")`会调用`moveInMotorList("Left")`
- `moveInMotorList("Left")`会发出`returnToCategory()`信号
- 但SerialPortControlPage没有连接这个信号
- 所以列表区域的左键返回逻辑没有工作

## 💡 技术要点

### 为什么需要连接returnToCategory信号

**问题**：
- NavigationManager是通用的导航管理器
- 不同页面需要不同的返回逻辑
- NavigationManager通过信号通知外部页面

**解决方案**：
- NavigationManager发出`returnToCategory()`信号
- 页面连接这个信号，实现自己的返回逻辑
- 页面调用`requestReturnToCategory()`通知DeviceSettingsDialog

**效果**：
- ✅ 解耦：NavigationManager不需要知道页面的具体实现
- ✅ 灵活：不同页面可以有不同的返回逻辑
- ✅ 可维护：信号机制清晰明了

### 为什么需要isReturningToCategory和keysEnabled标志

**问题**：
- 返回到类别区域时，焦点会发生变化
- 焦点变化可能触发其他键盘事件
- 可能导致事件循环或意外行为

**解决方案**：
- 设置`isReturningToCategory = true`，标记正在返回
- 设置`keysEnabled = false`，禁用键盘事件接收
- 在Keys.onUpPressed/onDownPressed/onLeftPressed/onRightPressed中检查这些标志
- 如果标志为true，直接返回，不处理事件

**效果**：
- ✅ 防止事件循环
- ✅ 防止意外行为
- ✅ 确保焦点正确切换

### 为什么需要resetFlagTimer

**问题**：
- 标志设置后，需要在适当的时候重置
- 如果不重置，后续的键盘事件会被永久禁用

**解决方案**：
- 使用Timer延迟重置标志
- 延迟时间为100ms（足够完成焦点切换）
- Timer触发后，重置`isReturningToCategory = false`

**效果**：
- ✅ 自动重置标志
- ✅ 不影响后续的键盘事件
- ✅ 简单可靠
