## 🔍 问题分析

### 根本原因

**NavigationManager的参数导航逻辑**（NavigationManager.qml lines 174-224）：
```qml
// 参数索引映射：
// 行0：[0] 是否投入          [1] 报警类型
// 行1：[2] 动作保护类型      [3] 故障保护类型
// 行2：[4] 温度量程          [5] 温度上限
// 行3：[6] 温度下限          [7] 输入点选择
// 行4：[8] 过滤干扰延时      [ ] 空

function moveInParamArea(direction) {
    switch(direction) {
    case "Down":
        var nextIndex = paramIndex + 2  // ← 假设2列布局
        if (nextIndex > lastParamIndex) {
            switchToArea(areaButtons)
            return
        } else {
            newIndex = nextIndex
        }
        break
    }
}
```

**SerialPortParamsTab的实际布局**（SerialPortParamsTab.qml line 179）：
```qml
GridLayout {
    columns: 4  // ← 实际是4列布局！

    // 第1行：串口名称 | 波特率
    // 第2行：设备路径 | 数据位
    // 第3行：串口类型 | 停止位
    // 第4行：空白     | 校验位
    // 第5行：状态     | 打开串口 | 关闭串口
}
```

**问题**：
- NavigationManager假设**2列布局**，下键：`paramIndex + 2`（同列下一行）
- SerialPortParamsTab实际是**4列布局**
- 导致下键导航失败：
  - 参数索引0（串口名称）按下键 → 期望到索引2（设备路径）
  - 但实际布局中，索引2是"设备路径"，不在同一列
  - NavigationManager计算错误，导致焦点无法移动

### 布局对比

**电机控制页面（2列布局）**：
```
行0：[0] 是否投入          [1] 报警类型
行1：[2] 动作保护类型      [3] 故障保护类型
行2：[4] 温度量程          [5] 温度上限
行3：[6] 温度下限          [7] 输入点选择
行4：[8] 过滤干扰延时      [ ] 空
```

**串口控制页面（4列布局）**：
```
行0：[0] 串口名称标签  [1] 串口名称值  [2] 波特率标签  [3] 波特率值
行1：[4] 设备路径标签  [5] 设备路径值  [6] 数据位标签  [7] 数据位值
行2：[8] 串口类型标签  [9] 串口类型值  [10] 停止位标签 [11] 停止位值
行3：[12] 空白         [13] 空白       [14] 校验位标签 [15] 校验位值
行4：[16] 状态标签     [17] 状态值     [18] 打开按钮   [19] 关闭按钮
```

**导航失败原因**：
- 参数索引0（串口名称标签）按下键 → `0 + 2 = 2`（波特率标签）
- 但用户期望：串口名称值 → 波特率值
- 实际应该是：索引1 → 索引3

## ✅ 解决方案

### 方案1：修改SerialPortParamsTab为2列布局（推荐）

**优点**：
- ✅ 与电机控制页面保持一致
- ✅ 不需要修改NavigationManager
- ✅ 导航逻辑简单清晰

**缺点**：
- ❌ 需要重新设计布局
- ❌ 修改量较大

**实施步骤**：
1. 将`columns: 4`改为`columns: 2`
2. 调整所有参数的Layout.column和Layout.row
3. 重新设计参数索引映射

**新的2列布局设计**：
```
行0：[0] 串口名称（只读）    [1] 波特率（可编辑）
行1：[2] 设备路径（只读）    [3] 数据位（可编辑）
行2：[4] 串口类型（只读）    [5] 停止位（可编辑）
行3：[6] 状态（只读）        [7] 校验位（可编辑）
行4：[8] 打开串口按钮        [9] 关闭串口按钮
```

**参数数量**：10个（0-9）

### 方案2：修改NavigationManager支持不同列数

**优点**：
- ✅ 保持SerialPortParamsTab的4列布局
- ✅ 更灵活，支持不同页面的不同布局

**缺点**：
- ❌ 需要修改NavigationManager的核心逻辑
- ❌ 增加复杂度
- ❌ 可能影响其他页面

**不推荐**：会增加系统复杂度，不利于维护

**采用方案1**：修改SerialPortParamsTab为2列布局


#### Step 2: 重新设计参数布局

**行0：串口名称 | 波特率**
```qml
// 索引0：串口名称（只读）
Text { text: "串口名称:"; Layout.column: 0; Layout.row: 0 }
TextField { id: serialNameText; Layout.column: 1; Layout.row: 0; readOnly: true }

// 索引1：波特率（可编辑）
Text { text: "波特率:"; Layout.column: 0; Layout.row: 0 }  // 与串口名称共享标签列
CustomComboBox { id: baudRateCombo; Layout.column: 1; Layout.row: 0 }
```

**等等...**

实际上，2列布局应该是：
```
列0：标签列
列1：值列
```

所以应该是：
```
行0：串口名称标签 | 串口名称值
行1：波特率标签   | 波特率值
行2：设备路径标签 | 设备路径值
行3：数据位标签   | 数据位值
行4：串口类型标签 | 串口类型值
行5：停止位标签   | 停止位值
行6：校验位标签   | 校验位值
行7：状态标签     | 状态值
行8：打开串口按钮 | 关闭串口按钮
```

**参数索引映射**（NavigationManager视角）：
```
[0] 串口名称值
[1] 波特率值
[2] 设备路径值
[3] 数据位值
[4] 串口类型值
[5] 停止位值
[6] 校验位值
[7] 状态值
[8] 打开串口按钮
[9] 关闭串口按钮
```

**导航逻辑**（NavigationManager）：
- 下键：`paramIndex + 2`（同列下一行）
  - 索引0（串口名称）→ 索引2（设备路径）✅
  - 索引1（波特率）→ 索引3（数据位）✅
- 上键：`paramIndex - 2`（同列上一行）
- 左键：`paramIndex - 1`（左列）
- 右键：`paramIndex + 1`（右列）

**但是**，这样的话，参数索引和行号不匹配！

让我重新理解NavigationManager的逻辑...

实际上，NavigationManager的参数索引是**按行优先顺序**排列的：
```
行0：[0] 左列  [1] 右列
行1：[2] 左列  [3] 右列
行2：[4] 左列  [5] 右列
```

所以，2列布局应该是：
```
行0：[0] 串口名称（左列）  [1] 波特率（右列）
行1：[2] 设备路径（左列）  [3] 数据位（右列）
行2：[4] 串口类型（左列）  [5] 停止位（右列）
行3：[6] 状态（左列）      [7] 校验位（右列）
行4：[8] 打开串口（左列）  [9] 关闭串口（右列）
```

这样的话，导航逻辑就正确了：
- 下键：`paramIndex + 2`
  - 索引0（串口名称）→ 索引2（设备路径）✅
  - 索引1（波特率）→ 索引3（数据位）✅
