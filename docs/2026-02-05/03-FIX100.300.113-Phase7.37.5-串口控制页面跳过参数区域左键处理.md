## 🔍 问题分析

### 根本原因

**DeviceSettingsDialog.qml lines 728-755还有另一段代码处理`focusSubArea === 1`**：

```qml
if (currentPage.focusSubArea === 1) {
    // ✅ 2026-01-30 [FIX 100.300.106.3]: 检查布局模式
    var currentTab = currentPage.getCurrentTab ? currentPage.getCurrentTab() : null
    var layoutMode = (currentTab && currentTab.layoutMode) ? currentTab.layoutMode : "two-column"

    if (layoutMode === "single-column") {
        // ✅ 一列布局：左键返回列表区域
        currentPage.focusSubArea = 0
        console.log("✅ [导航] 从参数区域（一列）返回列表区域")
        return
    } else {
        // ✅ 两列布局：两列交叉导航
        var currentIndex = currentPage.focusParamIndex
        if (currentIndex % 2 === 1) {
            // 当前在右列，切换到左列
            currentPage.focusParamIndex = prevIndex
            return
        } else {
            // 当前在左列，返回列表区域
            currentPage.focusSubArea = 0
            console.log("✅ [导航] 从参数区域返回列表区域")  // ← 这就是日志来源！
            return
        }
    }
}
```

**问题**：
- 这段代码是为**电机控制页面**设计的，用于处理参数区域（Tab内容区域）的左键导航
- 电机控制页面的区域定义：0=列表 1=参数 2=按钮
- 串口控制页面的区域定义：0=列表 1=Tab 2=参数 3=按钮
- 对于串口控制页面，`focusSubArea = 1` 是**Tab区域**，不是参数区域
- 这段代码错误地认为这是参数区域，执行了参数区域的左键逻辑
- 导致焦点直接跳到列表区域

### 为什么Phase 7.37.4的修复不够

**Phase 7.37.4删除的代码**（lines 723-739）：
```qml
var isSerialPortControlPage = (currentCategory === 6)
if (isSerialPortControlPage) {
    if (currentPage.focusSubArea === 1) {
        // 从参数区域返回串口列表
        currentPage.focusSubArea = 0
        ...
    }
}
```

**但是还有另一段代码**（lines 728-755）：
```qml
if (currentPage.focusSubArea === 1) {  // ← 没有检查是否是串口控制页面
    // 检查布局模式...
    // 执行参数区域的左键逻辑
}
```

**问题**：
- Phase 7.37.4只删除了第一段串口控制特殊处理代码
- 但是第二段代码（为电机控制页面设计的）也会影响串口控制页面
- 因为第二段代码没有检查`isSerialPortControlPage`
- 所以串口控制页面的`focusSubArea === 1`也会被这段代码处理

### 区域定义差异

| 页面 | focusSubArea=0 | focusSubArea=1 | focusSubArea=2 | focusSubArea=3 |
|------|---------------|---------------|---------------|---------------|
| 电机控制 | 列表 | **参数** | 按钮 | - |
| 串口控制 | 列表 | **Tab** | 参数 | 按钮 |

**关键差异**：
- 电机控制页面：`focusSubArea=1` 是参数区域
- 串口控制页面：`focusSubArea=1` 是Tab区域

**冲突**：
- DeviceSettingsDialog的代码检查`if (focusSubArea === 1)`
- 对电机控制页面：正确处理参数区域的左键导航 ✅
- 对串口控制页面：错误地认为是参数区域，执行了错误的逻辑 ❌

## ✅ 修复内容

### 添加串口控制页面判断

**文件位置**: DeviceSettingsDialog.qml line 735

**修改内容**:
```qml
// ✅ 2026-02-05 [FIX 100.300.113 Phase 7.37.5]: 串口控制页面跳过参数区域左键处理
// 串口控制页面的区域定义：0=列表 1=Tab 2=参数 3=按钮
// 电机控制页面的区域定义：0=列表 1=参数 2=按钮
// 下面的代码是为电机控制页面设计的，检查 focusSubArea === 1 认为是参数区域
// 但对串口控制页面来说，focusSubArea === 1 是Tab区域，不应该执行参数区域的逻辑
var isSerialPortControlPage = (currentCategory === 6)  // 串口控制类别

if (currentPage.focusSubArea === 1 && !isSerialPortControlPage) {
    // 电机控制页面的参数区域左键处理
    ...
}
```

**修改前**:
```qml
if (currentPage.focusSubArea === 1) {
    // 没有检查是否是串口控制页面
    ...
}
```

**效果**:
- 添加`&& !isSerialPortControlPage`条件
- 串口控制页面的`focusSubArea === 1`不会进入这段代码
- 让SerialPortControlPage自己处理Tab区域的左键事件
- 电机控制页面不受影响，仍然正常处理参数区域的左键导航

## 💡 技术要点

### 为什么需要两次修复

**Phase 7.37.4的修复**：
- 删除了第一段串口控制特殊处理代码（lines 723-739）
- 这段代码显式检查`isSerialPortControlPage`
- 删除后，串口控制页面不再被这段代码拦截

**Phase 7.37.5的修复**：
- 修改了第二段电机控制参数区域处理代码（lines 728-755）
- 这段代码没有检查`isSerialPortControlPage`
- 添加`&& !isSerialPortControlPage`条件，排除串口控制页面

**为什么第二段代码也会影响串口控制页面**：
- 第二段代码检查`if (focusSubArea === 1)`
- 对电机控制页面：`focusSubArea=1` 是参数区域 ✅
- 对串口控制页面：`focusSubArea=1` 是Tab区域 ❌
- 没有区分页面类型，导致串口控制页面也进入这段代码

### 区域定义的不一致性

**问题根源**：
- 不同页面使用相同的`focusSubArea`属性
- 但是区域定义不同
- DeviceSettingsDialog的通用代码无法区分

**解决方案**：
- 在通用代码中添加页面类型判断
- 使用`isSerialPortControlPage`区分串口控制和电机控制
- 让每个页面自己处理特殊的导航逻辑

**更好的设计**（未来改进）：
- 使用枚举定义区域类型（而不是数字）
- 例如：`areaList`, `areaTab`, `areaParams`, `areaButtons`
- 避免不同页面的区域定义冲突

### 事件处理的优先级

**QML事件处理顺序**：
```
1. DeviceSettingsDialog.Keys.onLeftPressed（外层）
2. SerialPortControlPage.Keys.onLeftPressed（内层）
```

**如果外层代码设置`event.accepted = true`或`return`**：
- 事件不会继续传播到内层
- 内层的事件处理器不会被调用

**修复后的流程**：
```
1. DeviceSettingsDialog.Keys.onLeftPressed 触发
2. 检查 focusSubArea === 1 && !isSerialPortControlPage
3. 条件为 false，不进入电机控制的参数区域处理
4. 事件继续传播
5. SerialPortControlPage.Keys.onLeftPressed 触发
6. Tab导航正常工作 ✅
```
