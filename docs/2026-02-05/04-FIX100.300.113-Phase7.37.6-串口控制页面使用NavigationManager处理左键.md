## 🔍 问题分析

### 根本原因

**DeviceSettingsDialog的`Keys.onLeftPressed`在最后有代码（line 791-792）**：

```qml
// 否则切换到左侧类别
currentFocusArea = 1
break
```

**问题流程**：
```
1. 用户在串口控制页面的Tab区域按左键
2. DeviceSettingsDialog.Keys.onLeftPressed 触发
3. 检查各种条件（电机控制、制动器控制、张紧控制等）
4. 串口控制页面没有被前面的条件拦截
5. 执行最后的 currentFocusArea = 1（切换到类别区域）
6. 触发 onCurrentFocusAreaChanged
7. 设置 serialPortControlPageLoader.item.focusSubArea = 0（列表区域）
8. 焦点跳到类别区域和列表区域
```

### 为什么SerialPortControlPage的Keys.onLeftPressed没有被触发

**原因**：
- DeviceSettingsDialog的`Keys.onLeftPressed`先被触发（外层组件）
- 执行了`currentFocusArea = 1`，改变了焦点区域
- 触发了`onCurrentFocusAreaChanged`，清除了`focusItemIndex`
- DeviceSettingsDialog失去焦点（`activeFocus 变化: false`）
- SerialPortControlPage也失去焦点
- SerialPortControlPage的`Keys.onLeftPressed`不会被触发

### 为什么前面的修复都没有生效

**Phase 7.37.3**：添加了`lastTabIndex`属性
- ✅ 修复了右键导航（在最后一个Tab保持不变）
- ❌ 左键导航仍然被DeviceSettingsDialog拦截

**Phase 7.37.4**：删除了旧的串口控制特殊处理代码
- ✅ 删除了第一段拦截代码
- ❌ 但是`Keys.onLeftPressed`的最后仍然有`currentFocusArea = 1`

**Phase 7.37.5**：添加了`&& !isSerialPortControlPage`条件
- ✅ 串口控制页面不会进入电机控制的参数区域处理
- ❌ 但是`Keys.onLeftPressed`的最后仍然有`currentFocusArea = 1`

**Phase 7.37.6**：在`currentFocusArea = 1`之前添加串口控制页面判断
- ✅ 串口控制页面在内容区域按左键时，调用NavigationManager处理
- ✅ 然后return，不执行后面的`currentFocusArea = 1`
- ✅ 焦点不会跳到类别区域

## ✅ 修复内容

### 添加串口控制页面左键处理

**文件位置**: DeviceSettingsDialog.qml lines 791-800

**添加内容**:
```qml
// ✅ 2026-02-05 [FIX 100.300.113 Phase 7.37.6]: 串口控制页面使用NavigationManager处理左键
if (currentCategory === 6 && currentFocusArea === 2) {
    var serialPage = serialPortControlPageLoader.item
    if (serialPage && serialPage.navigationManager) {
        console.log("✅ [导航] 串口控制页面左键 - 调用NavigationManager")
        serialPage.navigationManager.handleDirectionKey("Left")
        event.accepted = true
        return
    }
}

// 否则切换到左侧类别
currentFocusArea = 1
break
```

**效果**:
- 在串口控制页面的内容区域（currentFocusArea=2）按左键
- 调用`serialPage.navigationManager.handleDirectionKey("Left")`
- NavigationManager处理Tab导航、参数导航、按钮导航
- 然后return，不执行后面的`currentFocusArea = 1`
- 焦点不会跳到类别区域

## 💡 技术要点

### 为什么需要在DeviceSettingsDialog中处理

**问题**：
- SerialPortControlPage的`Keys.onLeftPressed`没有被触发
- 因为DeviceSettingsDialog的`Keys.onLeftPressed`先被触发
- 执行了`currentFocusArea = 1`，改变了焦点区域
- SerialPortControlPage失去焦点，Keys事件处理器不再工作

**解决方案**：
- 在DeviceSettingsDialog的`Keys.onLeftPressed`中
- 添加串口控制页面的判断
- 调用NavigationManager处理左键
- 然后return，不执行后面的`currentFocusArea = 1`

**效果**：
- ✅ NavigationManager的左键逻辑正常工作
- ✅ 焦点不会跳到类别区域
- ✅ Tab导航正常工作

### 为什么不能依赖事件传播

**理想情况**：
```
1. DeviceSettingsDialog.Keys.onLeftPressed 触发
2. 不处理，让事件继续传播
3. SerialPortControlPage.Keys.onLeftPressed 触发
4. 调用 navigationManager.handleDirectionKey("Left")
```

**实际情况**：
```
1. DeviceSettingsDialog.Keys.onLeftPressed 触发
2. 执行 currentFocusArea = 1（改变焦点区域）
3. DeviceSettingsDialog 失去焦点
4. SerialPortControlPage 也失去焦点
5. SerialPortControlPage.Keys.onLeftPressed 不会被触发
```

**问题**：
- DeviceSettingsDialog的`Keys.onLeftPressed`在最后有`currentFocusArea = 1`
- 这会改变焦点区域，导致组件失去焦点
- 事件传播机制失效

**解决方案**：
- 在`currentFocusArea = 1`之前添加串口控制页面判断
- 主动调用NavigationManager处理左键
- 然后return，不执行`currentFocusArea = 1`
