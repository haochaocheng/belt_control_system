## 问题分析

### SerialPortControlPage的结构

查看SerialPortControlPage.qml的代码，发现：

```qml
Rectangle {
    id: root

    ColumnLayout {
        RowLayout {
            // 左侧：串口列表
            SerialPortListPanel { ... }

            // 分隔线
            Rectangle { ... }

            // 右侧：串口配置和操作区域
            Loader {
                id: serialConfigPanel  // ✅ 这里定义了 serialConfigPanel
                source: "SerialPortConfigPanel.qml"
                ...
            }
        }
    }
}
```

**问题**：
- `serialConfigPanel`是在`ColumnLayout → RowLayout`内部定义的
- QML的`id`只在定义它的作用域内可见
- 从外部（DeviceSettingsDialog）访问`serialPage.serialConfigPanel`时，无法访问到这个id

### 为什么内部可以访问

SerialPortControlPage内部的`getCurrentTab()`函数可以访问`serialConfigPanel`：

```qml
function getCurrentTab() {
    if (!serialConfigPanel.item) {  // ✅ 内部可以访问
        return null
    }
    return serialConfigPanel.item.getCurrentTabItem()
}
```

**原因**：
- 在SerialPortControlPage内部，`serialConfigPanel`在同一个作用域内
- 但是从外部访问时，`serialConfigPanel`不是`root`的直接子组件，无法通过`serialPage.serialConfigPanel`访问

---

## 解决方案

### 添加属性别名

在SerialPortControlPage.qml中，添加一个属性别名来暴露`serialConfigPanel`：

```qml
// ========== 公开属性 ==========
property int currentSerialIndex: 0
property int focusItemIndex: -1
property int focusSubArea: 0
property int focusTabIndex: -1
property int focusParamIndex: 0
property int focusButtonIndex: 0

// ✅ 2026-02-04 [FIX 100.300.113 Phase 7.37.1]: 添加导航控制标志
property bool isReturningToCategory: false
property bool keysEnabled: true

// ✅ 2026-02-04 [FIX 100.300.113 Phase 7.2]: 暴露 navigationManager 供外部访问
property alias navigationManager: navigationManager

// ✅ 2026-02-05 [FIX 100.300.113 Phase 7.37.11.3]: 暴露 serialConfigPanel 供外部访问
property alias serialConfigPanel: serialConfigPanel

// ✅ 2026-02-04 [FIX 100.300.113 Phase 7.2]: Qt 虚拟键盘引用
property var virtualKeyboard: null
```

**关键点**：
- 使用`property alias`将内部的`serialConfigPanel` id暴露为公开属性
- 这样从外部就可以通过`serialPage.serialConfigPanel`访问到Loader对象
- 然后通过`serialPage.serialConfigPanel.item`访问到加载的SerialPortConfigPanel对象

## 技术要点

### 1. QML的id作用域

**id的可见性规则**：
- id只在定义它的QML文件内可见
- 子组件的id不会自动暴露给父组件的外部访问者
- 如果需要从外部访问，必须使用`property alias`暴露

**示例**：
```qml
// MyComponent.qml
Rectangle {
    id: root

    ColumnLayout {
        Loader {
            id: myLoader  // 这个id只在MyComponent内部可见
        }
    }
}

// 外部访问
var component = myComponentInstance.myLoader  // ❌ 错误！无法访问

// 正确方法：在MyComponent中添加
property alias myLoader: myLoader

// 外部访问
var component = myComponentInstance.myLoader  // ✅ 正确！
```

### 2. property alias的用法

**语法**：
```qml
property alias aliasName: targetId
```

**作用**：
- 将内部的id暴露为公开属性
- 外部可以通过属性名访问内部对象
- 保持对象的引用关系（不是复制）

**示例**：
```qml
Rectangle {
    id: root

    property alias myButton: button  // 暴露button

    Button {
        id: button
        text: "Click me"
    }
}

// 外部访问
myComponent.myButton.text = "New text"  // ✅ 可以访问和修改
```

### 3. 为什么不使用property var

**错误方法**：
```qml
property var serialConfigPanel: serialConfigPanel  // ❌ 错误！
```

**原因**：
- `property var`会在初始化时复制值
- 如果`serialConfigPanel`在初始化时还不存在，会得到`undefined`
- 即使后来`serialConfigPanel`被创建，属性值也不会更新

**正确方法**：
```qml
property alias serialConfigPanel: serialConfigPanel  // ✅ 正确！
```

**原因**：
- `property alias`创建的是引用，不是复制
- 始终指向最新的对象
- 即使对象被重新创建，引用也会自动更新

## 总结

### 问题根源

SerialPortControlPage中的`serialConfigPanel` id在内部定义，但没有暴露为公开属性，导致从外部（DeviceSettingsDialog）无法访问。

### 修复方法

使用`property alias`将`serialConfigPanel`暴露为公开属性，使外部可以访问。
