## 问题分析

### 1. 发送区的索引映射

**发送区使用逻辑索引映射**（不是GridLayout的物理索引）：

```
GridLayout物理顺序：
- 第1个元素：标题（左侧）
- 第2个元素：格式（右侧）
- 第3个元素：发送数据（跨2列）
- 第4个元素：发送按钮
- 第5个元素：清空按钮

逻辑索引映射：
- 索引0 = 格式（虽然在GridLayout中是第2个元素）
- 索引1 = 空（保留，虽然在GridLayout中是第1个元素）
- 索引2 = 发送数据
- 索引3 = 发送按钮
- 索引4 = 清空按钮
```

**关键点**：
- 格式输入框的焦点指示器使用`focusParamIndex === 0`
- triggerParamInput(0)处理格式输入框
- 这样NavigationManager设置paramIndex=0时，焦点直接出现在格式输入框上

### 2. 接收区的原始索引映射（Phase 7.37.9.7）

```
逻辑索引映射：
- 索引0 = 空（保留）  ← 问题！
- 索引1 = 格式
- 索引2 = 接收数据
- 索引3 = 清空按钮
- 索引4 = 暂停按钮
```

**问题**：
- 格式输入框的焦点指示器使用`focusParamIndex === 1`
- triggerParamInput(0)返回"索引0为空"
- NavigationManager设置paramIndex=0时，焦点不出现
- 需要按下键，导航到索引1，焦点才出现

### 3. 根本原因

**接收区的逻辑索引映射和发送区不一致**，导致用户体验不一致。

## 解决方案

### 调整接收区索引映射，匹配发送区

**新的逻辑索引映射**：
```
- 索引0 = 格式（虽然在GridLayout中是第2个元素）✅
- 索引1 = 空（保留，虽然在GridLayout中是第1个元素）
- 索引2 = 接收数据
- 索引3 = 清空按钮
- 索引4 = 暂停按钮
```

**修改内容**：
1. triggerParamInput()：case 0处理格式，case 1为空
2. 焦点指示器：从`focusParamIndex === 1`改为`focusParamIndex === 0`
3. handleDirectionKey()：已经使用索引0=格式的映射，无需修改

## 技术要点

### 1. 逻辑索引 vs 物理索引

**GridLayout的物理索引**：
- 从左到右、从上到下排列
- 第1个元素 = 索引0，第2个元素 = 索引1，...

**逻辑索引映射**：
- 根据用户交互习惯定义
- 可以和物理索引不一致
- 通过triggerParamInput()和焦点指示器实现映射

**优点**：
- 用户体验一致（发送区和接收区都是索引0=格式）
- NavigationManager无需特殊处理
- 代码逻辑清晰

### 2. 焦点指示器的关键作用

**焦点指示器决定了用户看到的焦点位置**：
```qml
border.color: (root.focusParamIndex === 0) ? "#2196F3" : "transparent"
```

**即使triggerParamInput(0)返回（不做任何操作），焦点指示器仍然会显示**，因为：
- NavigationManager设置paramIndex=0
- SerialPortControlPage同步focusParamIndex=0
- 焦点指示器检测到focusParamIndex === 0，显示蓝色边框

### 3. 为什么不修改GridLayout的物理顺序

**方案1**：修改GridLayout，让格式在左侧（物理索引0）
- 缺点：破坏UI布局，格式应该在右上角

**方案2**：使用逻辑索引映射（✅ 采用）
- 优点：保持UI布局不变，只修改逻辑映射
- 实现：通过triggerParamInput()和焦点指示器实现

## 总结

### 问题根源

接收区的逻辑索引映射和发送区不一致，导致从Tab按钮到格式输入框需要按两次下键。

### 修复方法

调整接收区的逻辑索引映射，让格式成为索引0（和发送区一致）：
1. triggerParamInput()：case 0处理格式（虽然返回）
2. 焦点指示器：使用`focusParamIndex === 0`
3. handleDirectionKey()：已经使用索引0=格式的映射

1. ✅ **保持不同Tab的逻辑索引映射一致**
