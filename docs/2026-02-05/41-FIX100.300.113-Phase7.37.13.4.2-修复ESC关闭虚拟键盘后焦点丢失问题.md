# FIX 100.300.113 Phase 7.37.13.4.2 - 修复ESC关闭虚拟键盘后焦点丢失问题

**修复人员**: AI Assistant
**关联问题**: Phase 7.37.13.4.1部署后，按ESC退出虚拟键盘后，下键无法将焦点移动到发送按钮

## 问题描述

### 用户反馈

Phase 7.37.13.4.1部署后，用户测试发现：

> "按ESC后虚拟键盘退出，下键无法将焦点移动到发送按钮上"

### 日志分析

**pjsip.md日志（lines -6 to -1）**：
```
Debug: ?? [DeviceSettingsDialog root] activeFocus 变化: false  ← 虚拟键盘打开时
Debug: ?? [QDS InputPanel] ESC键被按下，关闭虚拟键盘
Debug: ?? [QDS InputPanel] Active changed: false
```

**关键发现**：
- ✅ 虚拟键盘打开时，DeviceSettingsDialog失去activeFocus
- ✅ 按ESC键，InputPanel关闭
- ❌ **没有看到**：`✅ [DeviceSettingsDialog] 虚拟键盘已关闭，恢复对话框焦点`
- ❌ **没有看到**：`✅ [DeviceSettingsDialog] 对话框焦点已恢复`

**结论**：Phase 7.37.13.4.1的焦点恢复代码没有执行

## 根本原因

### Phase 7.37.13.4.1的实现

**DeviceSettingsDialog.qml（lines 128-137）**：
```qml
VirtualKeyboard.QtVirtualKeyboardIntegration {
    id: qtVirtualKeyboard
    parent: Overlay.overlay
    z: 2000

    // ❌ 使用 onClosed 监听虚拟键盘关闭
    onClosed: {
        console.log("✅ [DeviceSettingsDialog] 虚拟键盘已关闭，恢复对话框焦点")
        Qt.callLater(function() {
            root.forceActiveFocus()
            console.log("✅ [DeviceSettingsDialog] 对话框焦点已恢复")
        })
    }
}
```

### 为什么onClosed不工作

**main_qds.qml的InputPanel ESC处理（line 332）**：
```qml
Shortcut {
    enabled: virtualKeyboard.active
    sequence: "Esc"
    onActivated: {
        console.log("⌨️ [QDS InputPanel] ESC键被按下，关闭虚拟键盘")
        Qt.inputMethod.hide()  // ❌ 只是隐藏虚拟键盘
    }
}
```

**问题分析**：

1. main_qds.qml的InputPanel Shortcut先捕获ESC键
2. 调用`Qt.inputMethod.hide()`隐藏虚拟键盘
3. 但是**没有调用QtVirtualKeyboardIntegration的`root.close()`**
4. 所以QtVirtualKeyboardIntegration的`onClosed`信号没有触发
5. DeviceSettingsDialog的焦点恢复代码没有执行

**执行流程**：
```
用户按ESC键
    ↓
main_qds.qml的Shortcut捕获ESC键
    ↓
调用 Qt.inputMethod.hide()
    ↓
InputPanel的active变为false
    ↓
❌ QtVirtualKeyboardIntegration的onClosed没有触发
    ↓
❌ DeviceSettingsDialog的焦点恢复代码没有执行
    ↓
❌ 导航键无法工作
```

## 修复方案

### 使用Qt.inputMethod.visibleChanged信号

**修改DeviceSettingsDialog.qml（lines 143-159）**：

**修改前**：
```qml
VirtualKeyboard.QtVirtualKeyboardIntegration {
    id: qtVirtualKeyboard
    parent: Overlay.overlay
    z: 2000

    onClosed: {
        console.log("✅ [DeviceSettingsDialog] 虚拟键盘已关闭，恢复对话框焦点")
        Qt.callLater(function() {
            root.forceActiveFocus()
            console.log("✅ [DeviceSettingsDialog] 对话框焦点已恢复")
        })
    }
}
```

**修改后**：
```qml
VirtualKeyboard.QtVirtualKeyboardIntegration {
    id: qtVirtualKeyboard
    parent: Overlay.overlay
    z: 2000

    // ❌ 2026-02-05 [FIX 100.300.113 Phase 7.37.13.4.1]: onClosed 不工作
    // 原因：main_qds.qml 的 InputPanel ESC 处理调用 Qt.inputMethod.hide()
    // 没有调用 QtVirtualKeyboardIntegration 的 root.close()
    // 所以 onClosed 信号不会触发
    /*
    onClosed: {
        console.log("✅ [DeviceSettingsDialog] 虚拟键盘已关闭，恢复对话框焦点")
        Qt.callLater(function() {
            root.forceActiveFocus()
            console.log("✅ [DeviceSettingsDialog] 对话框焦点已恢复")
        })
    }
    */
}

// ✅ 2026-02-05 [FIX 100.300.113 Phase 7.37.13.4.2]: 监听 Qt.inputMethod.visibleChanged
// 当虚拟键盘关闭时（visible 变为 false），恢复对话框的焦点
// 这样可以确保 ESC 键关闭虚拟键盘后，导航键继续工作
Connections {
    target: Qt.inputMethod

    function onVisibleChanged() {
        console.log("✅ [DeviceSettingsDialog] Qt.inputMethod.visible 变化:", Qt.inputMethod.visible)
        if (!Qt.inputMethod.visible) {
            console.log("✅ [DeviceSettingsDialog] 虚拟键盘已关闭，恢复对话框焦点")
            Qt.callLater(function() {
                root.forceActiveFocus()
                console.log("✅ [DeviceSettingsDialog] 对话框焦点已恢复")
            })
        }
    }
}
```

### 关键变化

- ❌ 不再使用`onClosed`信号（不会触发）
- ✅ 使用`Connections`监听`Qt.inputMethod.visibleChanged`
- ✅ 当`Qt.inputMethod.visible`变为`false`时，恢复焦点
- ✅ 使用`Qt.callLater()`确保在虚拟键盘完全关闭后再恢复焦点

## 技术要点

### 1. Qt.inputMethod vs QtVirtualKeyboardIntegration

**Qt.inputMethod**：
- Qt的全局输入法对象
- 提供`visible`属性和`visibleChanged`信号
- 当调用`Qt.inputMethod.hide()`时，`visible`变为`false`，触发`visibleChanged`信号
- ✅ 可靠，适合监听虚拟键盘关闭

**QtVirtualKeyboardIntegration**：
- 自定义的Popup组件
- 提供`onClosed`信号
- 只有调用`root.close()`时才触发`onClosed`
- ❌ 不可靠，因为main_qds.qml的ESC处理不调用`root.close()`

### 2. 为什么Phase 7.37.13.4.1使用了错误的信号

**Phase 7.37.13.4.1的假设**：
- 假设QtVirtualKeyboardIntegration的`onClosed`会在虚拟键盘关闭时触发
- 没有考虑main_qds.qml的ESC处理方式

**实际情况**：
- main_qds.qml的ESC处理调用`Qt.inputMethod.hide()`
- 没有调用QtVirtualKeyboardIntegration的`root.close()`
- 所以`onClosed`不会触发

### 3. Connections的使用

**为什么使用Connections**：
```qml
Connections {
    target: Qt.inputMethod
    function onVisibleChanged() {
        // 处理信号
    }
}
```

**优点**：
- 可以监听任何对象的信号
- 不需要修改被监听的对象
- 代码清晰，易于理解

### 4. Qt.callLater()的重要性

**为什么使用Qt.callLater()**：
```qml
Qt.callLater(function() {
    root.forceActiveFocus()
})
```

**原因**：
- 确保在虚拟键盘完全关闭后再恢复焦点
- 避免焦点冲突
- 更可靠

## 教训总结

### ✅ 成功经验

1. **详细的日志分析**
   - 通过日志发现焦点恢复代码没有执行
   - 发现`onClosed`信号没有触发
   - 快速定位问题

2. **查看源码确认实现**
   - 查看main_qds.qml的ESC处理
   - 发现调用`Qt.inputMethod.hide()`，不是`root.close()`
   - 理解为什么`onClosed`不触发

3. **使用更可靠的信号**
   - 不依赖自定义组件的信号
   - 使用Qt的全局对象`Qt.inputMethod`
   - 更简单、更可靠

4. **使用Connections监听信号**
   - 不需要修改被监听的对象
   - 代码清晰，易于理解
   - 灵活性高

### ⚠️ 避免的错误

1. **假设信号会触发**
   - Phase 7.37.13.4.1假设`onClosed`会触发
   - 没有考虑实际的执行流程
   - 导致焦点恢复代码没有执行

2. **不查看完整的执行流程**
   - 应该查看main_qds.qml的ESC处理
   - 确认虚拟键盘关闭的完整流程
   - 避免使用不会触发的信号

3. **依赖自定义组件的信号**
   - QtVirtualKeyboardIntegration是自定义组件
   - 它的`onClosed`信号依赖于`root.close()`
   - 应该使用Qt的全局对象，更可靠
