- 导致NavigationManager的左键逻辑根本没有被调用

## 🔍 问题分析

### 根本原因

**DeviceSettingsDialog.qml lines 723-739（修复前）有旧的串口控制页面特殊处理**：

```qml
// ✅ 2026-02-04 [FIX 100.300.113 Phase 6.2]: 串口控制页面特殊处理
var isSerialPortControlPage = (currentCategory === 6)  // 串口控制类别

if (isSerialPortControlPage) {
    // ✅ SerialPortControlPage 2区域模式：0=列表 1=参数
    console.log("🔍 [串口控制导航] 左键 - focusSubArea:", currentPage.focusSubArea, ...)
    if (currentPage.focusSubArea === 1) {
        // 从参数区域返回串口列表
        currentPage.focusSubArea = 0
        currentPage.focusItemIndex = currentPage.currentSerialIndex
        console.log("✅ [导航] 串口控制：从参数区域返回列表")
        event.accepted = true
        return  // ❌ 拦截事件，不让SerialPortControlPage处理
    }
}
```

**问题**：
- 这段代码是在Phase 6.2添加的，当时串口控制页面只有**2个区域**（列表和参数）
- 现在串口控制页面已经改成了**4个区域**（列表、Tab、参数、按钮）
- 旧代码检查`if (currentPage.focusSubArea === 1)`，认为这是参数区域
- 但实际上`focusSubArea=1`现在是**Tab区域**，不是参数区域！
- 旧代码直接设置`currentPage.focusSubArea = 0`，跳到列表区域
- 导致Tab区域的左键导航逻辑被完全绕过

### 事件处理顺序

**正常流程（应该是）**:
```
1. 用户在Tab区域按左键
2. DeviceSettingsDialog.Keys.onLeftPressed 触发
3. 检查是否需要特殊处理
4. 不需要，让事件继续传播
5. SerialPortControlPage.Keys.onLeftPressed 触发
6. 调用 navigationManager.handleDirectionKey("Left")
7. NavigationManager.moveInTabBar("Left")
8. tabIndex 从 3 → 2（逐个向左切换）
```

**实际流程（有问题）**:
```
1. 用户在Tab区域按左键
2. DeviceSettingsDialog.Keys.onLeftPressed 触发
3. 检查 isSerialPortControlPage && focusSubArea === 1
4. ❌ 旧代码认为这是参数区域，直接设置 focusSubArea = 0
5. event.accepted = true, return
6. ❌ 事件被拦截，SerialPortControlPage.Keys.onLeftPressed 不会触发
7. ❌ NavigationManager 的左键逻辑根本没有被调用
8. ❌ 焦点直接跳到列表区域
```

### 为什么Phase 7.37.3的修复没有生效

**Phase 7.37.3的修复**：
- 添加了`lastTabIndex`属性到NavigationManager
- 修改了`moveInTabBar`函数使用`lastTabIndex`
- 设置了SerialPortControlPage的`lastTabIndex=3`

**但是**：
- NavigationManager的`moveInTabBar`函数根本没有被调用！
- 因为DeviceSettingsDialog的旧代码在之前就拦截了左键事件
- 所以Phase 7.37.3的修复对左键导航没有任何效果

**Phase 7.37.3只修复了右键导航**：
- 右键导航没有被DeviceSettingsDialog拦截
- 所以右键可以正确限制在Tab 0-3范围内
- 但左键导航仍然被旧代码拦截

## 💡 技术要点

### 为什么旧代码会拦截Tab区域的左键

**旧代码的假设**：
- 串口控制页面只有2个区域：列表（0）和参数（1）
- `if (currentPage.focusSubArea === 1)` 认为这是参数区域

**实际情况**：
- 串口控制页面现在有4个区域：列表（0）、Tab（1）、参数（2）、按钮（3）
- `focusSubArea === 1` 现在是Tab区域，不是参数区域
- 旧代码错误地认为Tab区域是参数区域，直接跳到列表区域

### 为什么要删除而不是修改

**选项1：修改旧代码**：
```qml
if (isSerialPortControlPage) {
    if (currentPage.focusSubArea === 2) {  // 修改为2（参数区域）
        // 从参数区域返回Tab区域
        currentPage.focusSubArea = 1
        ...
    }
}
```

**选项2：删除旧代码**（✅ 选择）：
```qml
// 删除整段代码，让SerialPortControlPage自己处理
```

**为什么选择删除**：
1. **SerialPortControlPage已经有完整的导航逻辑**：
   - Keys.onLeftPressed处理左键
   - NavigationManager管理4个区域的导航
   - 不需要DeviceSettingsDialog的特殊处理

2. **避免重复逻辑**：
   - 如果在DeviceSettingsDialog中添加特殊处理
   - 需要与SerialPortControlPage的逻辑保持同步
   - 容易出现不一致

3. **简化代码**：
   - 删除旧代码，减少复杂度
   - 让每个组件负责自己的导航逻辑
   - 更容易维护

### 事件传播机制

**QML事件传播顺序**：
```
1. 最外层组件（DeviceSettingsDialog）
2. 中间层组件
3. 最内层组件（SerialPortControlPage）
```

**如果外层组件设置`event.accepted = true`**：
- 事件不会继续传播到内层组件
- 内层组件的事件处理器不会被调用

**修复后的流程**：
```
1. DeviceSettingsDialog.Keys.onLeftPressed 触发
2. 不拦截（不设置 event.accepted = true）
3. 事件继续传播
4. SerialPortControlPage.Keys.onLeftPressed 触发
5. 调用 navigationManager.handleDirectionKey("Left")
6. Tab导航正常工作 ✅
```
