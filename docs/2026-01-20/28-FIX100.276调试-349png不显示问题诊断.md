## ✅ 最终解决方案

### 根本原因

**时序问题**：
1. 图片加载完成时，Image 尺寸还是 0 x 0
2. QML 引擎在此时渲染了一个 0x0 的图片（不可见）
3. 后来尺寸变为 1280 x 585，但**没有触发重新渲染**

### 解决方案：强制重新渲染

**修改位置**：[AlarmPage.qml:284-323](file:///e:/2025/3_gongkongji/belt_control_system/src/qml/pages/AlarmPage.qml#L284-L323)

**关键修改**：
```qml
Image {
    id: _349
    width: parent.width
    height: parent.height
    source: "images/349.png"
    fillMode: Image.PreserveAspectCrop
    z: -100

    // ✅ 强制重新渲染的关键
    smooth: true          // 启用平滑缩放，强制重新渲染
    mipmap: true          // 启用 mipmap，提高缩放质量

    // ✅ 监听尺寸变化
    onWidthChanged: {
        if (width > 0 && height > 0) {
            console.log("🔄 Image 宽度变化:", width, "强制刷新显示")
        }
    }

    onHeightChanged: {
        if (width > 0 && height > 0) {
            console.log("🔄 Image 高度变化:", height, "强制刷新显示")
        }
    }
}
```

### 工作原理

**smooth 和 mipmap 的作用**：
- `smooth: true`：启用平滑缩放（双线性插值）
  - **副作用**：每次尺寸变化都会触发重新渲染
  - 正是这个副作用解决了我们的问题

- `mipmap: true`：启用 mipmap 纹理
  - **副作用**：图片加载后会生成多级纹理
  - 每次尺寸变化会自动选择合适的 mipmap 级别
  - 也会触发重新渲染

**尺寸变化监听**：
- `onWidthChanged` / `onHeightChanged`：监听尺寸变化
- 当尺寸从 0 变为实际值时，触发回调
- 虽然回调本身不做任何事，但结合 `smooth: true`，会强制重新渲染

## 🎯 技术要点

### QML Image 渲染机制

**渲染时机**：
1. 图片加载完成（onStatusChanged: Ready）
2. 尺寸变化（width/height changed）
3. 属性变化（source/fillMode/smooth 等）

**问题场景**：
- 如果图片加载完成时尺寸为 0，QML 会渲染一个 0x0 的图片
- 后来尺寸变化，但如果没有触发重新渲染，图片仍然不可见

**触发重新渲染的方法**：
1. ✅ `smooth: true` - 强制每次尺寸变化都重新渲染
2. ✅ `mipmap: true` - 生成多级纹理，触发重新渲染
3. ✅ 修改 `source` 属性
4. ✅ 修改 `fillMode` 属性

### anchors.fill 的陷阱

**冲突场景**：
```qml
Rectangle {
    Image {
        anchors.fill: parent  // ❌ 与 ColumnLayout 冲突
    }

    ColumnLayout {
        anchors.fill: parent  // ❌ 与 Image 冲突
    }
}
```

**为什么会冲突**：
- QML 布局引擎按声明顺序计算尺寸
- Image 先声明，计算时 parent 尺寸可能还是 0
- ColumnLayout 后声明，会占据 parent 的所有空间
- Image 被 ColumnLayout 挤压，尺寸变为 0

**正确做法**：
```qml
Rectangle {
    Image {
        width: parent.width   // ✅ 显式绑定
        height: parent.height
        z: -100              // ✅ 在最底层
    }

    ColumnLayout {
        anchors.fill: parent  // ✅ 保持不变
    }
}
```

### z-order 和渲染顺序

**z-order 规则**：
- 同一父元素的子元素按 z 值排序
- z 值越小，越在底层
- 默认 z = 0
- 声明顺序：z 相同时，后声明的在上层

**本案例的层级结构**：
```
Rectangle (Table container)
├─ Image (z: -100, 背景图片，最底层)
└─ ColumnLayout (z: 0, 表格内容，上层)
   ├─ Rectangle (表格标题，半透明)
   ├─ ListView (表格数据，半透明)
   └─ ...
```

## 🎓 经验教训

### 1. QML 布局时序问题

**教训**：不要假设 `onStatusChanged` 时布局已经完成

**正确做法**：
- 使用 `Component.onCompleted` 确保布局完成
- 添加尺寸变化监听处理动态布局
- 使用 `smooth: true` 强制重新渲染

### 2. 调试 QML 布局问题

**步骤**：
1. 添加 `Component.onCompleted` 日志，检查初始尺寸
2. 添加 `onStatusChanged` 日志，检查图片加载状态
3. 添加 `onWidthChanged` / `onHeightChanged`，检查尺寸变化
4. 使用测试元素（如红色边框 Rectangle）验证容器存在

### 3. anchors.fill 的正确使用

**规则**：
- 同一个 parent 下，只有一个子元素使用 `anchors.fill: parent`
- 其他子元素使用显式绑定（`width: parent.width`）或固定尺寸
- 背景元素使用 `z: -100` 确保在底层
