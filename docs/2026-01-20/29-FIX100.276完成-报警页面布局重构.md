## 🔍 关键技术点

### 1. z-order 层级管理（⚠️ 重要修正）

**问题**：初版错误地将 349.png 设置为 `z: -100`

**原因分析**：
- AlarmPage 中已有 **Back 组件**（整个屏幕背景），z: 0
- 如果 349.png 设置为 z: -100，会在 Back (z: 0) **下面**
- Back 会遮挡 349.png，导致报警页面背景不可见

**正确的 z-order 分配**：
```qml
// ✅ 正确层级（从底到顶）
Back {
    z: 0  // 整个屏幕背景（最底层）
}

Image {  // 349.png
    z: 1  // 报警页面背景（在 Back 上面）
}

Rectangle {  // Main container
    z: 2  // 表格内容（在 349.png 上面）
}
```

**z-order 规则回顾**：
- z 值越小，越在底层
- 同一 z 值，后声明的在上层
- ⚠️ 负数 z 值会在 z: 0 的元素**下面**

**教训**：
- ❌ 不能盲目使用负数 z 值（如 -100）
- ✅ 必须检查同级所有组件的 z 值
- ✅ 使用正数递增（0, 1, 2...）更清晰安全

---

### 2. Image 填充策略

**PreserveAspectCrop**（保持比例裁剪）：
- ✅ 保持图片原始比例（不变形）
- ✅ 填充整个区域（无黑边）
- ⚠️ 可能裁剪图片边缘

**适用场景**：
- 图片分辨率（2604x1924）远大于屏幕（1280x800 或 1920x1080）
- 可以接受裁剪边缘内容
- 需要无黑边填充

### 2. QML 层级和锚点

**层级结构**：
```qml
Item (root)
├── Item (headerContainer) - 固定高度
├── Image (backgroundImage) - anchors.top: headerContainer.bottom
└── Rectangle (Main container) - anchors.top: headerContainer.bottom
```

**锚点关系**：
- Image 和 Main container **同时锚定**到 headerContainer.bottom
- Image 在**声明顺序**上先于 Main container → 自动在底层
- Image 显式设置 `z: -100` → 确保在最底层

### 3. 透明度和颜色叠加

**透明层级**（从底到顶）：
```
z: -100  Image 349.png（完全不透明）
z: 0     Rectangle (Main container, transparent)
z: 0     Table header (color: "#800f3460", 50% 透明)
z: 0     ListView rows (color: "#801e2a3a" 等, 50% 透明)
z: 0     底部状态栏 (color: "#0f3460", opacity: 0.8)
```

**视觉效果**：
- 背景图片完整显示
- 半透明表格内容叠加在背景上
- 形成"磨砂玻璃"效果
