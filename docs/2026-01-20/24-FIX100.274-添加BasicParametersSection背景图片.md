## 🔍 问题分析

### 1. Image 组件的尺寸要求

**QML Image 组件的尺寸规则**：
```qml
// ❌ 错误示例（用户的代码）
Image {
    x: 0
    y: 0
    source: "images/039.png"
    fillMode: Image.Stretch
    // 问题：没有 width 和 height
    // 结果：图片不显示或显示为原始尺寸的一小部分
}

// ✅ 正确示例 1（固定尺寸）
Image {
    x: 0
    y: 0
    width: 800
    height: 600
    source: "images/039.png"
    fillMode: Image.Stretch
}

// ✅ 正确示例 2（填充父容器 - 用于背景）
Image {
    anchors.fill: parent  // 自动填充父容器
    source: "images/039.png"
    fillMode: Image.Stretch
    z: -1  // 在最底层，不遮挡其他内容
}
```

**fillMode 的各种模式**：
- `Image.Stretch`：拉伸填充，忽略原始比例（需要明确尺寸）
- `Image.PreserveAspectFit`：保持比例，完整显示（需要明确尺寸）
- `Image.PreserveAspectCrop`：保持比例，裁剪超出部分（需要明确尺寸）
- `Image.Pad`：原始尺寸，居中显示（可以不设置尺寸）

**本案例应该使用的方案**：
- 用户希望"代替原来的矩形方框"
- **意图**：作为背景图片
- **最佳方案**：`anchors.fill: parent` + `z: -1`

### 2. Qt 资源系统的工作原理

**相对路径 vs 资源路径**：
```qml
// ❌ 相对路径（开发时可能工作，部署时失败）
Image {
    source: "images/039.png"
    // QML 引擎会在文件系统中查找：
    // src/qml/components/parameter_settings/images/039.png
    // 如果未编译到资源文件，运行时找不到
}

// ✅ 资源路径（编译后嵌入可执行文件）
Image {
    source: "qrc:/qt/qml/BeltControlQml/components/parameter_settings/images/039.png"
    // 或者简写（如果配置了 RESOURCE_PREFIX）
    source: "images/039.png"
    // 前提：必须在 CMakeLists.txt RESOURCES 中注册
}
```

**Qt 资源系统的优势**：
1. **编译时嵌入**：图片编译到可执行文件中
2. **路径无关**：不依赖运行时文件系统结构
3. **跨平台**：Windows/Linux/macOS 统一路径
4. **部署简单**：无需单独复制图片文件

## 📝 技术要点

### 1. QML Image 组件的尺寸控制

**三种常见的尺寸设置方式**：

**方式1：固定尺寸**
```qml
Image {
    width: 800
    height: 600
    source: "image.png"
    fillMode: Image.Stretch
}
// 适用：需要固定大小的图片
```

**方式2：填充父容器（背景图片）**
```qml
Image {
    anchors.fill: parent
    source: "background.png"
    fillMode: Image.Stretch
    z: -1  // 在最底层
}
// ✅ 本案例使用这种方式
// 适用：作为背景图片
```

**方式3：自动尺寸（原始尺寸）**
```qml
Image {
    source: "icon.png"
    // 不设置 width/height
    // 图片以原始尺寸显示
}
// 适用：图标、Logo 等
```

### 2. QML z-order 层级控制

**z-order 的工作原理**：
```qml
Rectangle {
    id: parent

    Image {
        id: background
        z: -1  // 最底层
    }

    ColumnLayout {
        id: content
        z: 0   // 默认层级（不设置 z 时为 0）
    }

    Rectangle {
        id: overlay
        z: 10  // 最上层
    }
}
```

**渲染顺序**：
1. background (z: -1) - 先绘制
2. content (z: 0) - 后绘制
3. overlay (z: 10) - 最后绘制

**本案例应用**：
```qml
Rectangle {
    ColumnLayout {
        // z: 0 (默认)
        // UI 内容：文本、输入框、下拉框
    }

    Image {
        z: -1  // ✅ 在 ColumnLayout 下方
        // 背景图片
    }
}
```

### 3. Qt 资源系统的路径解析

**QML 中的资源路径解析规则**：
```qml
// BasicParametersSection.qml 的位置：
// src/qml/components/parameter_settings/BasicParametersSection.qml

Image {
    source: "images/039.png"
    // 相对路径解析：

    // = src/qml/components/parameter_settings/
    // 完整路径 = src/qml/components/parameter_settings/images/039.png
}
```

**资源系统的路径映射**：
```

（相对于 src/qml/）

编译后的资源路径：

（RESOURCE_PREFIX = /qt/qml）

QML 中的简写路径：
```

**Qt 资源系统的查找顺序**：

2. 如果找不到，再在文件系统中查找

### 4. CMakeLists.txt qt_add_qml_module 配置

**qt_add_qml_module 的关键参数**：

**RESOURCES 的路径规则**：
- 相对于 CMakeLists.txt 所在目录（src/qml/）

**添加新资源的步骤**：

### 2. 图片文件命名规范

**当前文件名**：`039.png`

**命名建议**：

### 3. 背景图片的性能考虑

**Image.Stretch 的性能影响**：
- `fillMode: Image.Stretch`：实时拉伸，消耗 GPU 资源
- 如果图片尺寸与目标尺寸差异很大，性能可能下降

**优化建议**：
1. 提供与目标尺寸接近的图片（减少拉伸）
2. 使用压缩格式（PNG/JPEG）减少内存占用
3. 避免超大图片（建议 < 2MB）

**本案例**：
- BasicParametersSection 尺寸较小（不是全屏）
- 单张图片性能影响可忽略

### 4. 多个 Image 组件的 z-order 管理
