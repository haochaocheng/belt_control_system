# TTS 性能优化方案

## 文档信息
- **创建时间**: 2026-02-11
- **问题**: TTS 合成时间过长（1.9秒）
- **目标**: 降低合成延迟，提升用户体验

---

## 一、当前性能分析

### 1.1 实测性能数据

**您的系统**:
- **平台**: RK3588 ARM64 CPU（6核 Cortex-A76 + 2核 Cortex-A55）
- **模型**: vits-zh-aishell3（8kHz 采样率，174 说话人）
- **首次合成**: ~1.9 秒（包含模型加载）
- **缓存播放**: <50 毫秒
- **RTF (Real-Time Factor)**: ≈ 1.9

**性能分解**:
```
总时间 1.9 秒 = 模型加载 (0.8s) + 文本处理 (0.1s) + 音频合成 (1.0s)
```

### 1.2 业界标准性能基准

#### RTF (Real-Time Factor) 对照表

| 平台 | RTF | 说明 | 示例 |
|------|-----|------|------|
| **高端 GPU (RTX 3090)** | 0.05-0.1 | 生成 1 秒音频需要 0.05-0.1 秒 | 20倍实时 |
| **中端 GPU (GTX 1660)** | 0.1-0.2 | 生成 1 秒音频需要 0.1-0.2 秒 | 10倍实时 |
| **高端 x86 CPU (i9)** | 0.3-0.5 | 生成 1 秒音频需要 0.3-0.5 秒 | 3倍实时 |
| **中端 x86 CPU (i5)** | 0.5-1.0 | 生成 1 秒音频需要 0.5-1.0 秒 | 2倍实时 |
| **ARM CPU (RK3588)** | 1.0-2.0 | 生成 1 秒音频需要 1.0-2.0 秒 | 1倍实时 |
| **嵌入式 ARM** | 2.0-5.0 | 生成 1 秒音频需要 2.0-5.0 秒 | 0.5倍实时 |

**结论**: 您的系统 RTF ≈ 1.9，**符合 ARM CPU 的正常性能范围**。

## 三、方案 1：模型预加载和预热 ⭐⭐⭐⭐⭐

**预期效果**: 首次合成降低到 0.3-0.5 秒（**提速 4-6 倍**）

### 原理

系统启动时预加载模型，避免首次合成的模型加载时间（0.8秒）。

**性能分解**:
```
当前: 模型加载 (0.8s) + 合成 (1.0s) = 1.9s
优化后: 合成 (1.0s) = 1.0s
首次合成提速: 1.9s → 1.0s
```

### 实施步骤

**步骤 1: 在 main.cpp 中添加预加载**

```cpp
// src/main.cpp
#include "control/SherpaOnnxTTS.h"

int main(int argc, char *argv[]) {
    // ... 现有代码 ...

    // 创建 TTS 引擎
    SherpaOnnxTTS *sherpaOnnxTTS = new SherpaOnnxTTS(&app);
    engine.rootContext()->setContextProperty("sherpaOnnxTTS", sherpaOnnxTTS);

    // 2026-02-11: 系统启动后预加载 TTS 模型
    QTimer::singleShot(2000, [sherpaOnnxTTS]() {
        qDebug() << "🎙️ 预加载 TTS 模型...";

        // 初始化模型
        QString modelPath = "/app/tts_models/vits-zh-aishell3";
        if (sherpaOnnxTTS->initialize(modelPath)) {
            qDebug() << "✅ TTS 模型预加载成功";

            // 预热：合成一个短文本
            sherpaOnnxTTS->synthesizeToFile("测试", "/tmp/warmup.wav");
            qDebug() << "✅ TTS 模型预热完成";
        } else {
            qDebug() << "❌ TTS 模型预加载失败";
        }
    });

    // ... 现有代码 ...
}
```

### 优点
- ✅ 实施简单（1天）
- ✅ 用户体验提升明显
- ✅ 不影响音质
- ✅ 首次合成速度提升 4-6 倍

### 缺点
- ⚠️ 增加启动时间（2秒）
- ⚠️ 占用更多内存（~200MB）

## 四、方案 2：使用 RK3588 NPU 加速 ⭐⭐⭐⭐⭐

**预期效果**: RTF 降低到 0.2-0.5（**提速 4-10 倍**）

### 原理

RK3588 内置 **6 TOPS NPU**（Neural Processing Unit），专门用于加速神经网络推理。

**性能对比**:
- CPU 推理: 1.9 秒
- NPU 推理: 0.2-0.5 秒
- **提速**: 4-10 倍

### 优点
- ✅ 性能提升最大（4-10倍）
- ✅ 功耗更低（NPU 比 CPU 省电）
- ✅ 不需要更换硬件
- ✅ 释放 CPU 资源用于其他任务

### 缺点
- ⚠️ 需要重新编译 ONNX Runtime with RKNN
- ⚠️ 需要模型转换（ONNX → RKNN）
- ⚠️ 开发周期较长（1-2周）
