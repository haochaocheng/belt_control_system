## 🎯 根本原因

### Qt 字体回退机制失败

**失败流程**：
1. Qt 尝试使用默认字体 "Sans Serif" 渲染 emoji
2. Sans Serif 不支持 emoji，触发字体回退（fallback）
3. **Qt 字体回退查找 emoji 字体失败**
4. 原因：**"Noto Color Emoji" 不在 Qt.fontFamilies() 列表中**
5. 回退失败，显示为方框 ❌

### 为什么 Noto Color Emoji 缺失？

虽然 `Dockerfile.ubuntu24-base` 已安装 `fonts-noto-color-emoji` 包，但：

**问题**：**字体缓存未刷新**
- 安装字体后没有运行 `fc-cache`
- fontconfig 缓存过期或不存在
- Qt 依赖 fontconfig 缓存来枚举可用字体
- 导致 Qt.fontFamilies() 无法识别新安装的 emoji 字体

## 💡 修复方案对比

### 方案 A：显式指定 emoji 字体（快速）
```qml
Text {
    text: modelData.icon
    font.family: "Noto Color Emoji"  // 显式指定
    font.pixelSize: 24
}
```
**优点**：快速修复，不需要重建镜像
**缺点**：如果字体真的不存在，仍然无法显示

### ✅ 方案 B：安装 fontconfig 并刷新字体缓存（彻底解决）
```dockerfile
RUN apt-get install -y \
    fonts-noto-color-emoji \
    fontconfig \
    && fc-cache -fv
```
**优点**：彻底解决，所有 Qt 应用都能识别 emoji 字体
**缺点**：需要重新构建 Docker 镜像（约 5-10 分钟）

**✅ 用户选择：方案 B**

## 📚 技术细节

### Qt 字体枚举机制

Qt 使用 `fontconfig` 库枚举系统字体：

```cpp
// Qt 内部调用
FcConfig *config = FcInitLoadConfigAndFonts();
FcPattern *pattern = FcPatternBuild(NULL, NULL);
FcObjectSet *os = FcObjectSetBuild(FC_FAMILY, NULL);
FcFontSet *fs = FcFontList(config, pattern, os);

// 如果 fontconfig 缓存未刷新 → 找不到新安装的字体
```

### fontconfig 缓存机制

**字体缓存文件**：
- `/var/cache/fontconfig/*.cache-*`
- 包含字体元数据、Unicode 覆盖范围等

**fc-cache 命令**：
- `-f`：强制重新生成缓存
- `-v`：详细输出（verbose）

**输出示例**：
```
/usr/share/fonts: caching, new cache contents: 0 fonts, 3 dirs
/usr/share/fonts/truetype: caching, new cache contents: 0 fonts, 3 dirs
/usr/share/fonts/truetype/noto: caching, new cache contents: 125 fonts, 0 dirs
  ✅ 找到 Noto Color Emoji.ttf
```

### Emoji 字体格式

- **Noto Color Emoji**：使用 CBDT/CBLC 表存储彩色位图
- **支持 Unicode 10.0** 的大部分 emoji
- **文件大小**：约 10 MB（包含所有 emoji 位图）
