## 🎯 批量生产部署方案对比

### 方案 A：离线 Docker 安装包 + 镜像 tar ⭐（推荐短期方案）

**适用场景**：已出厂设备、小批量生产、研发测试

**部署流程**：

```
准备阶段（一次性）：
┌─────────────────────────────────────┐
│ 在有网设备上（188）                    │
├─────────────────────────────────────┤
│ 1. 下载 Docker 安装包                 │
│    - docker-ce_*.deb                │
│    - containerd.io_*.deb            │
│    - docker-ce-cli_*.deb            │
│    - 依赖包（iptables, libseccomp2）  │
│ 2. 传输到本地 Windows                 │
│ 3. 准备应用镜像 tar                   │
└─────────────────────────────────────┘
          ↓
批量部署阶段（每台设备）：
┌─────────────────────────────────────┐
│ 传输方式（任选）                       │
├─────────────────────────────────────┤
│ • U盘拷贝                            │
│ • 内网 scp 传输                       │
│ • SD 卡预装                           │
└─────────────────────────────────────┘
          ↓
┌─────────────────────────────────────┐
│ 在目标设备上自动安装                   │
├─────────────────────────────────────┤
│ ./install-docker-offline.sh         │
│ ├── 安装 Docker（dpkg -i *.deb）     │
│ ├── 修复依赖（apt-get install -f）    │
│ ├── 启动服务（systemctl start docker）│
│ └── 验证安装（docker run hello-world）│
│                                      │
│ docker load < belt-control-ubuntu24-apt.tar │
│ ./run-ubuntu24-apt.sh                │
└─────────────────────────────────────┘
```

**工具支持**：
- `scripts/2026-01-17/01-prepare-offline-docker-packages.ps1`

**优点**：
- ✅ 统一部署方式（所有设备都用容器）
- ✅ 环境隔离（不受宿主机 GLIBC 2.35 影响，容器内是 GLIBC 2.39）
- ✅ 易于维护（应用更新只需更换 tar 文件）
- ✅ 可自动化（脚本一键安装）
- ✅ 兼容性好（支持 Ubuntu 22.04/24.04）

**缺点**：
- ⚠️ 安装包体积较大（~200MB Docker + 800MB 镜像）
- ⚠️ 首次安装需要时间（5-10 分钟/台）
- ⚠️ 每台设备都需要执行安装步骤

**适用场景**：
- 小批量生产（<100 台）
- 已出厂设备的后期部署
- 研发和测试阶段

### 方案 B：原生二进制（无 Docker）

**部署流程**：

```
编译阶段：
┌─────────────────────────────────────┐
│ 为 Ubuntu 22.04/GLIBC 2.35 编译      │
├─────────────────────────────────────┤
│ 1. 使用 aarch64-linux-gnu 工具链     │
│ 2. 链接到系统库（Qt 5.15, FFmpeg）    │
│ 3. 打包所有依赖 .so                  │
└─────────────────────────────────────┘
          ↓
部署阶段：
┌─────────────────────────────────────┐
│ /opt/belt-control/                  │
│ ├── bin/belt_control_system         │
│ ├── lib/*.so                        │
│ ├── plugins/                        │
│ └── qml/                            │
│                                      │
│ systemd 服务：                        │
│ /etc/systemd/system/belt-control.service │
└─────────────────────────────────────┘
```

**优点**：
- ✅ 轻量（无需 Docker，~500MB）
- ✅ 启动快（直接运行，无容器开销）
- ✅ 系统资源占用少

**缺点**：
- ❌ 需要维护多个编译版本（Ubuntu 22/24, GLIBC 2.35/2.39）
- ❌ 依赖管理复杂（Qt、FFmpeg、PJSIP 需要匹配宿主机版本）
- ❌ 升级困难（文件替换容易遗漏）
- ❌ 环境不一致（每台设备可能有微小差异）
- ❌ 调试困难（无 GDB，无隔离环境）

**适用场景**：
- 资源极度受限的设备（<2GB 内存）
- 不适合批量生产

### 方案 C：固件预装（批量生产最优）⭐⭐⭐（推荐长期方案）

**适用场景**：大批量生产（>100 台）、产线自动化

**部署流程**：

```
固件制作阶段（一次性）：
┌─────────────────────────────────────┐
│ 基础固件（Ubuntu 22.04/24.04）        │
├─────────────────────────────────────┤
│ + Docker Engine（预装）              │
│ + containerd, runc                  │
│ + 应用镜像（预加载到 /var/lib/docker）│
│ + systemd 服务（自动启动）            │
│ + 运行脚本 /opt/belt-control/        │
└─────────────────────────────────────┘
          ↓
烧录阶段：
┌─────────────────────────────────────┐
│ SD 卡/eMMC 烧录工具                   │
├─────────────────────────────────────┤
│ • balenaEtcher                      │
│ • RKDevTool（Rockchip 专用）          │
│ • dd 命令批量烧录                     │
└─────────────────────────────────────┘
          ↓
出厂验证：
┌─────────────────────────────────────┐
│ 上电启动 → 应用自动运行                │
│ 无需任何配置                          │
└─────────────────────────────────────┘
```

**systemd 服务示例**：

```ini
[Unit]
Description=Belt Control System
After=docker.service
Requires=docker.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/belt-control
ExecStart=/opt/belt-control/run-ubuntu24-apt.sh
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

**优点**：
- ✅ 零配置（开箱即用）
- ✅ 批量生产友好（固件统一烧录，1000 台也很快）
- ✅ 可靠性高（环境完全一致）
- ✅ 售后简单（固件回刷即可修复）
- ✅ 支持 OTA 更新（只需更新镜像 tar）

**缺点**：
- ⚠️ 需要修改固件制作流程（一次性工作）
- ⚠️ 固件体积增加（~1.5GB）

**适用场景**：
- 大批量生产（>100 台）
- 产线自动化
- 长期稳定供货

**实施建议**：
1. 基于 FriendlyWrt/Armbian 定制固件
2. 使用 Packer/Buildroot 自动化构建
3. 固件包含：
   - Ubuntu 24.04 rootfs
   - Docker Engine 26.x
   - 应用镜像（docker save 打包）
   - 自启动脚本

## 🔧 具体问题：设备 150 GLIBC 版本不兼容

### 问题

```
设备 150：Ubuntu 22.04, GLIBC 2.35
我们的应用：Ubuntu 24.04, GLIBC 2.39

直接运行原生二进制 → 失败：
  /lib/aarch64-linux-gnu/libc.so.6: version `GLIBC_2.39' not found
```

### 解决方案

**使用 Docker 容器化部署**（推荐）：

```bash
# 容器内：Ubuntu 24.04 (GLIBC 2.39) ✅
# 宿主机：Ubuntu 22.04 (GLIBC 2.35) → 无影响

docker run --platform linux/arm64 \
    belt-control-ubuntu24-apt:latest
```

**原理**：
- 容器有独立的 rootfs（包含 GLIBC 2.39）
- 宿主机只需提供内核接口（5.10.160 完全兼容）
- 应用运行在容器的 GLIBC 2.39 环境中

**验证**：

```bash
# 在设备 150 上：
docker run --rm ubuntu:24.04 ldd --version
# 输出：ldd (Ubuntu GLIBC 2.39) 2.39

# 应用正常运行，不受宿主机 GLIBC 2.35 影响
```

### 使用方法

**Step 1：准备离线安装包**（在 Windows 本机）

```powershell
# 从有网设备（188）下载 Docker 包
.\scripts\2026-01-17\01-prepare-offline-docker-packages.ps1

# 输出：docker-offline-packages/
# ├── docker-ce_*.deb
# ├── containerd.io_*.deb
# ├── docker-ce-cli_*.deb
# ├── *.deb（所有依赖）
# ├── install-docker-offline.sh（安装脚本）
# └── README.md（使用说明）
```

**Step 2：传输到目标设备**（设备 150）

```powershell
# 方式 1: scp 传输
scp -r docker-offline-packages pi@192.168.10.150:/home/pi/

# 方式 2: U盘拷贝（如果设备完全离线）
# 将 docker-offline-packages 文件夹复制到 U 盘
# 在设备上挂载 U 盘并复制
```

**Step 3：安装 Docker**（在设备 150 上）

```bash
cd ~/docker-offline-packages
chmod +x install-docker-offline.sh
./install-docker-offline.sh

# 输出：
# [1/3] 安装 Docker 包...
# [2/3] 修复依赖...
# [3/3] 启动 Docker 服务...
# ✅ Docker 安装成功！
```

**Step 4：部署应用**

```bash
# 传输应用镜像和运行脚本（从 Windows）
scp belt-control-ubuntu24-apt.tar pi@192.168.10.150:/home/pi/
scp run-ubuntu24-apt.sh pi@192.168.10.150:/home/pi/

# 在设备上加载和运行
docker load < belt-control-ubuntu24-apt.tar
chmod +x run-ubuntu24-apt.sh
./run-ubuntu24-apt.sh
```

## 🚀 批量生产建议（综合方案）

### 短期方案（1-3 个月，<100 台）

使用**方案 A**（离线安装包）：

1. **准备阶段**（一次性）：
   ```powershell
   # 在 Windows 本机
   .\scripts\2026-01-17\01-prepare-offline-docker-packages.ps1
   ```
   输出：`docker-offline-packages/`（~200MB）

2. **批量部署**：
   - U 盘预装：`docker-offline-packages/` + `belt-control-ubuntu24-apt.tar`
   - 每台设备插 U 盘 → 运行安装脚本（5 分钟/台）
   - 或产线局域网批量 scp 传输

3. **优点**：
   - 快速实施（1 天准备）
   - 灵活调整（应用更新只需更换 tar）
   - 适合小批量

---

### 长期方案（>100 台，持续供货）

使用**方案 C**（固件预装）：

1. **固件制作**（一次性，1-2 周）：
   ```
   基础镜像：FriendlyWrt/Armbian Ubuntu 24.04
   + Docker Engine（apt 安装）
   + 应用镜像（docker save 打包到 /opt/）
   + systemd 服务（自动启动）
   ```

2. **烧录流程**：
   - SD 卡/eMMC 批量烧录
   - 烧录后上电测试（自动启动应用）
   - 出厂

3. **OTA 更新**：
   ```bash
   # 设备可联网时：
   scp belt-control-v3.6.tar device:/tmp/
   ssh device "docker load < /tmp/belt-control-v3.6.tar && systemctl restart belt-control"

   # 设备离线时：
   # U 盘拷贝 tar + 更新脚本
   ```

4. **优点**：
   - 零配置（开箱即用）
   - 产线效率高（1 分钟/台）
   - 可靠性高（环境统一）
   - 售后简单（固件回刷）
