# 不同系统版本离线部署完整指南

**日期**：2026-01-17 20:30
**问题**：如何在不同系统版本（Debian 10/11/12, Ubuntu 20/22/24）的离线 aarch64 设备上批量部署应用
**解决方案**：方案 A（离线 Docker 安装包） + 多版本适配

---

## 📊 问题背景

### 批量生产场景

```
设备条件：
✅ 架构：肯定是 aarch64 (ARM64)
❓ 系统：可能是 Debian 10/11/12 或 Ubuntu 20/22/24
❌ 网络：不具备联网条件

应用要求：
- 基于 Ubuntu 24.04 容器镜像
- 需要 GLIBC 2.39
- 依赖 Docker 容器化部署
```

### 核心挑战

1. **系统版本不确定**：无法预知设备的 OS 版本
2. **离线环境**：无法在线下载 Docker
3. **GLIBC 版本差异**：老系统（如 Ubuntu 20.04）GLIBC 2.31 < 2.39
4. **批量部署效率**：需要自动化，避免手动操作

---

## 🎯 解决方案：多版本离线安装包 + 智能检测

**文件**：`scripts/2026-01-17/02-detect-system-info.sh`

**功能**：
- 检测系统版本（OS, Version, Codename）

- 检测磁盘/内存
- 检测网络连接
- 输出 JSON 格式报告

**使用方法**：

```bash
# 方式 1：本地运行
ssh user@device "bash -s" < scripts/2026-01-17/02-detect-system-info.sh

# 方式 2：传输后运行
scp scripts/2026-01-17/02-detect-system-info.sh user@device:/tmp/
ssh user@device "chmod +x /tmp/detect-system-info.sh && /tmp/detect-system-info.sh"
```

**输出示例**：

```

   方式 2（离线安装）:

   3. 传输应用镜像并加载
```

### 工具 2：多版本 Docker 离线安装包准备脚本

**文件**：`scripts/2026-01-17/03-prepare-multi-version-docker-packages.ps1`

**功能**：
- 从有网设备（如 188）下载各版本 Docker 包
- 支持 Ubuntu 20.04/22.04/24.04, Debian 10/11/12
- 自动生成每个版本的安装脚本
- 创建智能部署脚本
- 创建系统检测脚本副本
- 生成完整的 README 文档

**使用方法**：

```powershell
# 基本用法（从设备 188 下载）
.\scripts\2026-01-17\03-prepare-multi-version-docker-packages.ps1

# 指定源设备
.\scripts\2026-01-17\03-prepare-multi-version-docker-packages.ps1 -SourceDevice 188

# 指定输出目录
.\scripts\2026-01-17\03-prepare-multi-version-docker-packages.ps1 -OutputDir "my-docker-packages"
```

**注意事项**：

⚠️ **重要限制**：此脚本只能下载与源设备系统版本匹配的 Docker 包

例如：
- 在 Ubuntu 24.04 设备（188）上运行 → 只能下载 Ubuntu 24.04 的 Docker 包
- 在 Ubuntu 22.04 设备上运行 → 只能下载 Ubuntu 22.04 的 Docker 包

**解决方法**（准备所有版本）：

方案 A：在多台不同系统的设备上分别运行
```powershell
# 在 Ubuntu 24.04 设备上
.\scripts\2026-01-17\03-prepare-multi-version-docker-packages.ps1 -SourceDevice <ubuntu24_device>

# 在 Ubuntu 22.04 设备上
.\scripts\2026-01-17\03-prepare-multi-version-docker-packages.ps1 -SourceDevice <ubuntu22_device>

# 手动合并输出目录
```

方案 B：使用 Docker 容器（推荐）
```powershell
# 在 Windows 上运行不同系统的容器
docker run --rm -it --platform linux/arm64 ubuntu:24.04 bash
# 在容器内下载 Docker 包，传输出来
```

方案 C：在线下载（如果有网）
```bash
# 在线环境直接下载
wget https://download.docker.com/linux/ubuntu/...
```

## 📋 完整部署流程

### 阶段 1：准备（一次性，在 Windows 开发机）

#### Step 1.1：准备 Docker 离线安装包

```powershell
# 从设备 188（Ubuntu 24.04）准备 Ubuntu 24.04 的包
.\scripts\2026-01-17\03-prepare-multi-version-docker-packages.ps1 -SourceDevice 188

# 如果有 Ubuntu 22.04 设备（如 150），也运行一次
# .\scripts\2026-01-17\03-prepare-multi-version-docker-packages.ps1 -SourceDevice 150
```

**输出目录结构**：

```
docker-offline-packages-multi/
├── ubuntu-24.04/
│   ├── docker-ce_*.deb
│   ├── containerd.io_*.deb
│   ├── ...（共约 10 个 .deb 文件，~200MB）
│   └── install-docker-offline.sh
├── ubuntu-22.04/（如果准备了）
├── detect-system-info.sh（系统检测）
├── smart-deploy.sh（智能部署）
└── README.md（使用说明）
```

#### Step 1.2：准备应用镜像

```powershell
# 确保应用镜像是最新的
.\build-ubuntu24-apt.ps1 188

# 输出：belt-control-ubuntu24-apt.tar (~800MB)
```

#### Step 1.3：准备运行脚本

应用镜像导出时自动生成 `run-ubuntu24-apt.sh`，无需额外准备。

---

### 阶段 2：批量部署（在目标设备）

#### 方式 A：U 盘部署（完全离线，适合现场）

**Step 2A.1：准备 U 盘**

```
U 盘目录结构（4GB+）：
/
├── docker-offline-packages-multi/（200MB）
│   ├── ubuntu-24.04/
│   ├── detect-system-info.sh
│   ├── smart-deploy.sh
│   └── README.md
├── belt-control-ubuntu24-apt.tar（800MB）
└── run-ubuntu24-apt.sh
```

**Step 2A.2：在目标设备上部署**

```bash
# 1. 挂载 U 盘
sudo mount /dev/sda1 /mnt

# 2. 复制到本地
cp -r /mnt/* ~/deployment/
cd ~/deployment

# 3. 检测系统（可选）
chmod +x docker-offline-packages-multi/detect-system-info.sh
./docker-offline-packages-multi/detect-system-info.sh

# 4. 智能部署 Docker
cd docker-offline-packages-multi
chmod +x smart-deploy.sh
./smart-deploy.sh

# 5. 加载应用镜像
cd ~/deployment
docker load < belt-control-ubuntu24-apt.tar

# 6. 运行应用
chmod +x run-ubuntu24-apt.sh
./run-ubuntu24-apt.sh
```

**预计时间**：10-15 分钟/台

---

#### 方式 B：局域网部署（产线有内网）

**Step 2B.1：搭建文件服务器**（一次性）

```bash
# 在 Windows 开发机上共享目录
# 或在一台 Linux 服务器上搭建 HTTP 服务

# 示例：使用 Python HTTP 服务器

```

**Step 2B.2：在目标设备上下载并部署**


**预计时间**：5-10 分钟/台（网络传输更快）

#### 方式 C：SSH 批量部署（自动化脚本）

**创建批量部署脚本**（Windows）：

```powershell
# batch-deploy.ps1
param(
    [string[]]$DeviceIPs = @("192.168.10.150", "192.168.10.151", "192.168.10.152")
)

foreach ($ip in $DeviceIPs) {
    Write-Host "部署到设备 $ip ..." -ForegroundColor Cyan

    # 传输文件
    scp -r docker-offline-packages-multi user@${ip}:/home/user/
    scp belt-control-ubuntu24-apt.tar user@${ip}:/home/user/
    scp run-ubuntu24-apt.sh user@${ip}:/home/user/

    # 远程执行部署
    ssh user@$ip @"
cd /home/user/docker-offline-packages-multi
chmod +x smart-deploy.sh
./smart-deploy.sh
cd /home/user
docker load < belt-control-ubuntu24-apt.tar
chmod +x run-ubuntu24-apt.sh
./run-ubuntu24-apt.sh &
"@

    Write-Host "✅ 设备 $ip 部署完成" -ForegroundColor Green
}
```

**使用方法**：

```powershell
.\batch-deploy.ps1 -DeviceIPs @("192.168.10.150", "192.168.10.151")
```

**预计时间**：5 分钟/台（并行执行）

### 阶段 3：验证和监控

#### 验证部署成功

```bash
# 1. 检查 Docker 状态
docker --version
sudo systemctl status docker

# 2. 检查镜像
docker images | grep belt-control

# 3. 检查容器运行状态
docker ps

# 4. 查看应用日志
docker logs <container_id>
```

#### 设置开机自启

```bash
# 创建 systemd 服务
sudo tee /etc/systemd/system/belt-control.service > /dev/null <<EOF
[Unit]
Description=Belt Control System
After=docker.service
Requires=docker.service

[Service]
Type=simple
User=root
WorkingDirectory=/home/user
ExecStart=/home/user/run-ubuntu24-apt.sh
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

# 启用并启动
sudo systemctl enable belt-control
sudo systemctl start belt-control

# 验证
sudo systemctl status belt-control
```

## ⚠️ 常见问题和解决方案

### 问题 1：设备系统版本不在准备的列表中

**场景**：设备是 Ubuntu 21.10 或其他罕见版本

**解决方案**：

```bash
# 方式 1：尝试使用相近版本的安装包
# Ubuntu 21.10 → 尝试 ubuntu-22.04 的包
cd docker-offline-packages-multi/ubuntu-22.04
./install-docker-offline.sh

# 方式 2：在线安装 Docker（如果设备临时有网）
curl -fsSL https://get.docker.com | sudo sh
```

---

### 问题 2：Docker 安装包不完整或损坏

**症状**：`dpkg -i` 报错，缺少依赖

**解决方案**：

```bash
# 1. 检查包完整性
ls -lh *.deb
md5sum *.deb

# 2. 重新下载（如果有网）
sudo apt-get update
apt-get download docker-ce docker-ce-cli containerd.io

# 3. 手动修复依赖
sudo apt-get install -f
```

---

### 问题 3：容器无法启动（Docker 版本过老）

**症状**：`docker run` 报错 "unknown flag"

**解决方案**：

```bash
# 检查 Docker 版本
docker --version

# 如果 < 19.03，升级 Docker
# 离线环境：准备新版 Docker 包
# 在线环境：
sudo apt-get update
sudo apt-get install --only-upgrade docker-ce
```

---

### 问题 4：应用镜像加载失败

**症状**：`docker load` 报错 "invalid tar header"

**解决方案**：

```bash
# 1. 检查镜像文件完整性
ls -lh belt-control-ubuntu24-apt.tar
# 应该约 800MB

# 2. 检查 MD5（如果有原始 MD5 值）
md5sum belt-control-ubuntu24-apt.tar

# 3. 重新传输镜像
scp belt-control-ubuntu24-apt.tar user@device:/home/user/
```

---

### 问题 5：应用运行时找不到库文件

**症状**：容器日志显示 "error while loading shared libraries"

**解决方案**：

```bash
# 这不应该发生（容器自包含）
# 检查容器内库文件
docker run --rm belt-control-ubuntu24-apt:latest ls /app/lib

# 检查 LD_LIBRARY_PATH
docker run --rm belt-control-ubuntu24-apt:latest env | grep LD_LIBRARY_PATH

# 如果确实缺少，重新构建镜像
.\build-ubuntu24-apt.ps1 188
```

### 核心原理

```
应用（Ubuntu 24.04, GLIBC 2.39）
↓
Docker 容器（包含完整 rootfs）
↓
Docker Engine（各系统版本自带）
↓
宿主机内核（5.x，各系统通用）
↓
硬件（aarch64 ARM64）
```

**只要宿主机能运行 Docker，应用就能正常运行**，不受宿主机 GLIBC 版本影响。
