## 🔍 根本原因分析

### 卡住的代码位置

**文件**: `src/risip/core/risipcallmanager.cpp` Line 349

```cpp
void RisipCallManager::accountIncomingCall()
{
    RisipCall *call = new RisipCall(this);
    call->setAccount(m_data->m_activeAccount);
    call->initiateIncomingCall();  // ← 到这里都正常

    // ❌ 卡在这里！
    QString remoteUri = QString::fromStdString(call->pjsipCall()->getInfo().remoteUri);

    // ... 后续代码永远不会执行
}
```

### 为什么 getInfo() 会阻塞？

**PJSIP 内部机制**：
1. `getInfo()` 是同步调用，需要等待 PJSIP 内部状态初始化
2. Call 对象刚创建时，PJSIP 可能还在处理 INVITE 消息
3. `getInfo()` 阻塞等待状态就绪，但由于我们在主线程中同步调用，导致死锁

**调用链分析**：
```
PJSIP Worker Thread: 收到 INVITE
    ↓ (调用)
onIncomingCall(prm) - 同步创建 Call (BlockingQueuedConnection)
    ↓ (等待 Qt 主线程)
Qt Main Thread: 创建 PjsipCall
    ↓ (发射信号)
emit incomingCall()
    ↓ (同步槽)
accountIncomingCall()
    ↓ (调用)
getInfo() - 等待 PJSIP Worker Thread 初始化状态
    ↓
❌ 死锁！主线程等 Worker，Worker 被阻塞在 onIncomingCall()
```

## 🎯 解决方案

### 核心思路

**关键发现**：来电者信息在 INVITE 消息中就已经完整！

**抓包数据分析**（wir.md）：
```
From: <sip:1006@192.168.10.142>;tag=11227d8b9093262c
      来电者号码: 1006  ← 这就是 remoteUri！
```

**PJSIP API 提供的数据**：
```cpp
struct OnIncomingCallParam {
    int callId;
    SipRxData rdata;  // ⭐ 包含原始 INVITE 消息
};

struct SipRxData {
    string wholeMsg;  // ⭐ 完整的 SIP 消息（包括 From 头部）
    void *pjRxData;   // 原始 PJSIP 数据结构指针
};
```

### 修复策略

**方案**：在 `onIncomingCall()` 中从 `prm.rdata` 提取来电者 URI

**优势**：
1. ✅ 不需要调用阻塞的 `getInfo()`
2. ✅ 信息在 INVITE 到达时就已经可用
3. ✅ 避免 PJSIP 内部状态初始化等待
4. ✅ 不会死锁

### Step 3: 实现 URI 提取函数

```cpp
// 方法 1：从 wholeMsg 字符串中解析（简单但不够健壮）
QString extractRemoteUriFromSipMessage(const std::string &sipMsg)
{
    QString msg = QString::fromStdString(sipMsg);

    // 查找 From 头部
    QRegularExpression fromRegex(R"(From:\s*<sip:([^@>]+)@[^>]+>)");
    QRegularExpressionMatch match = fromRegex.match(msg);

    if (match.hasMatch()) {
        QString userPart = match.captured(1);  // 提取号码部分
        // 重构完整 URI（根据实际需求）
        return QString("sip:%1@...").arg(userPart);
    }

    return "sip:unknown";  // 默认值
}

// 方法 2：使用 pjRxData 指针调用 PJSIP C API（更健壮，推荐）
QString extractRemoteUriFromPjRxData(void *pjRxDataPtr)
{
    pjsip_rx_data *rdata = (pjsip_rx_data *)pjRxDataPtr;

    // 获取 From 头部
    pjsip_from_hdr *from_hdr = (pjsip_from_hdr *)
        pjsip_msg_find_hdr(rdata->msg_info.msg, PJSIP_H_FROM, NULL);

    if (from_hdr) {
        char buf[512];
        int len = pjsip_uri_print(PJSIP_URI_IN_FROMTO_HDR, from_hdr->uri, buf, sizeof(buf));
        return QString::fromLatin1(buf, len);
    }

    return "sip:unknown";
}
```

## ⚠️ 风险评估

### 风险 1：URI 格式不一致
**问题**：从 From 头部提取的 URI 格式可能与 `getInfo().remoteUri` 不同
**缓解**：使用 PJSIP C API 提取，确保格式一致

### 风险 2：某些 INVITE 消息缺少 From 头部
**问题**：极端情况下 From 头部可能缺失
**缓解**：提供默认值 "sip:unknown"，后续流程兼容
