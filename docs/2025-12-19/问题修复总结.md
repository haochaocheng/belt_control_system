## 问题2: 151设备显示平台问题 ✅

### 问题描述
151设备不是全屏显示（应该使用EGLFS，但使用了XCB）。

### 根本原因
1. `Dockerfile.ubuntu24-apt` 中设置了 `QT_QPA_PLATFORM=eglfs`（正确）
2. 但 `build-ubuntu24-apt.ps1` 部署脚本中硬编码覆盖为 `QT_QPA_PLATFORM=xcb`（错误）

### 修复方案

#### 修改1: Dockerfile.ubuntu24-apt (第42-50行)
移除硬编码的 `QT_QPA_PLATFORM`，添加说明注释：

```dockerfile
# Environment variables
# ✅ Note: QT_QPA_PLATFORM is NOT set in Dockerfile
# It will be set by run script based on DISPLAY environment:
# - If X11 available (ssh -X) → use xcb (windowed)
# - If no X11 (direct run) → use eglfs (fullscreen)
ENV LD_LIBRARY_PATH=/app/lib:/usr/lib/aarch64-linux-gnu:/lib/aarch64-linux-gnu:$LD_LIBRARY_PATH \
    QT_PLUGIN_PATH=/app/plugins \
    QML2_IMPORT_PATH=/app/qml \
    QT_QPA_EGLFS_INTEGRATION=eglfs_kms \
    QT_QPA_EGLFS_ALWAYS_SET_MODE=1
```

#### 修改2: build-ubuntu24-apt.ps1 (第522-544行)
添加自动检测逻辑，根据X11可用性选择平台：

```bash
# Auto-detect Qt platform based on X11 availability
if xhost +local:docker 2>/dev/null; then
    echo "✅ X11 detected - using XCB platform (windowed mode)"
    QT_PLATFORM=xcb
    DISPLAY_ARG="-e DISPLAY=:0"
    X11_VOLUME="-v /tmp/.X11-unix:/tmp/.X11-unix:rw"
else
    echo "✅ No X11 - using EGLFS platform (fullscreen mode)"
    QT_PLATFORM=eglfs
    DISPLAY_ARG=""
    X11_VOLUME=""
fi

echo "Starting application with persistent data..."
echo "Qt Platform: $QT_PLATFORM"

sudo docker run \
    --name belt-control-app \
    --privileged \
    $DISPLAY_ARG \
    -e QT_QPA_PLATFORM=$QT_PLATFORM \
    -e XDG_RUNTIME_DIR=/tmp \
    $X11_VOLUME \
    ...
```

### 效果
- ✅ **151设备直接运行** → 自动使用EGLFS（全屏模式）
- ✅ **SSH X转发** → 自动使用XCB（窗口模式，用于调试）
- ✅ **Windows平台** → 不受影响

### 使用说明

**全屏运行（EGLFS）**:
```bash
ssh linaro@192.168.10.151 ./run-ubuntu24-apt.sh
```

**窗口调试（XCB）**:
```bash
# 在本地启用X转发
ssh -X linaro@192.168.10.151
# 在设备上运行
./run-ubuntu24-apt.sh
```

## 问题3: SIP界面emoji图标不显示 🔄

### 当前状态
- ✅ 基础镜像已安装emoji字体包（`fonts-noto-color-emoji`）
- ✅ Dockerfile中已添加 `fc-cache -f -v` 重建字体缓存
- ❌ emoji图标仍显示为方框

### 可能原因分析

#### 1. QML Text组件默认不支持彩色emoji
QML的 `Text` 组件默认使用黑白字体渲染，需要使用特殊属性：

```qml
Text {
    text: "📞"  // emoji字符
    font.family: "Noto Color Emoji"  // 指定emoji字体
    renderType: Text.NativeRendering  // 使用原生渲染
}
```

#### 2. FontConfig配置优先级问题
系统可能优先使用DejaVu等非emoji字体，需要调整fontconfig配置。

### 待实施方案

#### 方案A: 修改QML组件（推荐）
在 SIP 界面的 QML 文件中明确指定emoji字体：

**文件**: `src/qml/components/sip_phone/*.qml`

```qml
// 全局字体配置
FontLoader {
    id: emojiFont
    source: "/usr/share/fonts/truetype/noto/NotoColorEmoji.ttf"
}

// 使用emoji的Text组件
Text {
    text: "📞 ☎️ 📲"
    font.family: emojiFont.name
    renderType: Text.NativeRendering
}
```

#### 方案B: 添加FontConfig配置
**文件**: `Dockerfile.ubuntu24-apt`（添加字体配置）

```dockerfile
RUN echo '<?xml version="1.0"?>' > /etc/fonts/local.conf && \
    echo '<!DOCTYPE fontconfig SYSTEM "fonts.dtd">' >> /etc/fonts/local.conf && \
    echo '<fontconfig>' >> /etc/fonts/local.conf && \
    echo '  <!-- Prefer color emoji -->' >> /etc/fonts/local.conf && \
    echo '  <alias>' >> /etc/fonts/local.conf && \
    echo '    <family>sans-serif</family>' >> /etc/fonts/local.conf && \
    echo '    <prefer>' >> /etc/fonts/local.conf && \
    echo '      <family>Noto Color Emoji</family>' >> /etc/fonts/local.conf && \
    echo '    </prefer>' >> /etc/fonts/local.conf && \
    echo '  </alias>' >> /etc/fonts/local.conf && \
    echo '</fontconfig>' >> /etc/fonts/local.conf && \
    fc-cache -f -v
```

需要检查SIP界面QML文件，确认emoji使用方式并应用方案A。
