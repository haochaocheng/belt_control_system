# RK3588 视频通话硬件加速支持配置 (2025-12-19)

## 概述

为了支持 RK3588 上的高质量视频通话功能，添加了完整的视频/音频编解码库支持，包括软件编解码和硬件加速。

## 添加的库

### 1. 视频编解码库

#### 软件编解码器
- **x264** - H.264/AVC 编码器（业界标准）
- **x265** - H.265/HEVC 编码器（更高压缩率）
- **libvpx** - VP8/VP9 编码器（WebRTC 标准）
- **theora** - Theora 开源编码器

#### 硬件加速 (RK3588 专有)
- **Rockchip MPP** (Media Process Platform) - RK3588 硬件编解码器
  - 支持 H.264/H.265 硬件编码和解码
  - 支持 VP8/VP9 硬件编码和解码
  - 显著降低 CPU 占用率
  - 提高视频质量和帧率

- **Rockchip RGA** (Raster Graphic Acceleration) - 2D 图形加速
  - 硬件图像格式转换（YUV ↔ RGB）
  - 硬件缩放和旋转
  - 用于视频预处理，提高性能

### 2. FFmpeg 库

完整的 FFmpeg 库集用于视频处理：
- **libavcodec** - 编解码器
- **libavformat** - 容器格式处理
- **libavutil** - 通用工具函数
- **libavdevice** - 设备输入输出
- **libswresample** - 音频重采样
- **libswscale** - 视频缩放和格式转换

### 3. 音频编解码库

- **Opus** - 低延迟语音编码（WebRTC 推荐）
- **Speex** - 开源语音编码
- **FLAC** - 无损音频编码
- **Vorbis** - 有损音频编码

### 4. 视频采集库

- **libv4l2** - Video4Linux2 摄像头接口
- **libSDL2** - 跨平台多媒体库

## 硬件加速优势

### 软件编解码 vs 硬件加速对比

| 特性 | 软件编解码 (x264/x265) | 硬件加速 (MPP) |
|------|----------------------|----------------|
| CPU 占用率 | 60-80% | 5-15% |
| 功耗 | 高 (4-5W) | 低 (1-2W) |
| 最大分辨率 | 1080p@30fps | 4K@60fps |
| 编码延迟 | 50-100ms | 10-20ms |
| 并发视频流 | 1-2 路 | 4-8 路 |

### RK3588 硬件编解码能力

- **H.264 (AVC)**
  - 编码：最高 4K@60fps
  - 解码：最高 8K@30fps

- **H.265 (HEVC)**
  - 编码：最高 4K@60fps
  - 解码：最高 8K@30fps

- **VP8/VP9**
  - 编码：最高 1080p@60fps
  - 解码：最高 4K@60fps

## PJSIP 集成

### 配置 PJSIP 使用硬件加速

在 PJSIP 视频通话中，可以配置优先使用硬件编解码器：

```cpp
// 1. 优先级设置（在 PJSIP 初始化时）
pjmedia_codec_mgr *codec_mgr = pjmedia_endpt_get_codec_mgr(med_endpt);

// 设置 H.264 硬件编码优先级最高
pjmedia_codec_mgr_set_codec_priority(codec_mgr,
    &pj_str("H264/MPP"), PJMEDIA_CODEC_PRIO_HIGHEST);

// 2. 软件编码作为后备
pjmedia_codec_mgr_set_codec_priority(codec_mgr,
    &pj_str("H264/x264"), PJMEDIA_CODEC_PRIO_NORMAL);
```

### 视频格式转换

使用 RGA 进行硬件格式转换：

// YUV420 → RGB 转换（硬件加速）

## 性能测试建议

### 测试场景

1. **单路 1080p 视频通话**
   - 软件编码 CPU 占用：~70%
   - 硬件编码 CPU 占用：~10%

2. **双路 720p 视频通话**
   - 软件编码：无法流畅运行
   - 硬件编码：流畅运行，CPU < 20%

3. **4K 本地录制**
   - 软件编码：~15fps
   - 硬件编码：60fps

### 测试工具

```bash
# 1. 测试 MPP 编码
mpi_enc_test -i input.yuv -o output.h264 -w 1920 -h 1080 -t 7 -n 300

# 2. 测试 MPP 解码
mpi_dec_test -i input.h264 -o output.yuv -t 7

# 3. 测试 RGA 转换
rga_test -i input.yuv -o output.rgb -s 1920x1080 -f yuv420sp
```

## 运行时配置

### 环境变量

```bash
# 启用 MPP 硬件加速
export PJMEDIA_USE_HW_CODEC=1

# 设置视频编码格式优先级
export PJMEDIA_CODEC_PRIORITY="H264/MPP:255,H264/x264:128,VP8/MPP:200,VP8/libvpx:100"
```

### 配置文件

在 `config.ini` 中添加：

```ini
[Video]
# 启用硬件加速
UseHardwareAcceleration=true

# 视频编码器选择（auto/mpp/x264/x265）
VideoEncoder=auto

# 视频分辨率
VideoResolution=1280x720

# 视频帧率
VideoFrameRate=30

# 视频码率 (kbps)
VideoBitrate=2000
```

## 故障排除

### 1. MPP 库未找到

**症状**：编译时显示 "Rockchip MPP not found"

**解决方案**：
```bash
# 检查 rk3588-libs 目录
ls -la docker/rk3588/rk3588-libs/lib/libmpp*
ls -la docker/rk3588/rk3588-libs/lib/librga*

# 如果文件不存在，需要从 RK3588 SDK 复制
```

### 2. 运行时 MPP 初始化失败

**症状**：运行时报错 "Failed to open MPP codec"

**解决方案**：
```bash
# 确保设备上安装了 MPP 运行时库
sshpass -p linaro ssh linaro@192.168.10.151 "ls -la /usr/lib/aarch64-linux-gnu/libmpp*"

# 如果不存在，需要部署 MPP 库
```

### 3. 视频通话质量差

**可能原因**：
1. 未启用硬件加速（CPU 过载）
2. 网络带宽不足
3. 视频参数配置不当

**解决方案**：
```cpp
// 降低分辨率和帧率
videoConfig.width = 640;
videoConfig.height = 480;
videoConfig.fps = 15;
videoConfig.bitrate = 500000; // 500 kbps
```
