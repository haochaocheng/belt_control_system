# 数据文件统一管理实现总结 (2025-12-19)

## 问题背景

用户提出："为了防止误删，将配置文件和数据库文件放在同一个目录里，修改整个工程，看看哪里需要配置文件数据库"

**原有问题**:
- 配置文件和数据库文件分散在不同位置
- 容易误删导致数据丢失
- Docker容器重建后数据持久化配置复杂

**原有文件分布**:
```
应用根目录/
├── config.ini                    # SystemConfig配置文件
├── operation_logs.db             # 操作日志数据库
├── alarm_history.db              # 报警历史数据库（需初始化指定路径）
├── protection_config.db          # 保护配置数据库（需初始化指定路径）
└── database/                     # SIP相关数据库子目录
    ├── contacts.db               # SIP联系人数据库
    └── call_history.db           # SIP通话记录数据库
```

---

## 解决方案

### 1. 创建统一数据路径配置类

**文件**: [src/control/DataPathConfig.h](../../src/control/DataPathConfig.h)

**实现内容**:
- 定义统一数据目录 `/app/appdata`
- 提供所有配置文件和数据库的标准路径访问方法
- 自动创建数据目录（如不存在）

**新的统一目录结构**:
```
/app/appdata/                     # 统一数据目录
├── config.ini                   # 系统配置文件
├── alarm_history.db             # 报警历史数据库
├── protection_config.db         # 保护配置数据库
├── operation_logs.db            # 操作日志数据库
├── contacts.db                  # SIP联系人数据库
└── call_history.db              # SIP通话记录数据库
```

**关键方法**:
```cpp
class DataPathConfig {
public:
    static QString getDataDirectory()                // 获取统一数据目录
    static QString getConfigFilePath()               // config.ini路径
    static QString getAlarmHistoryDbPath()           // alarm_history.db路径
    static QString getProtectionConfigDbPath()       // protection_config.db路径
    static QString getOperationLogDbPath()           // operation_logs.db路径
    static QString getContactsDbPath()               // contacts.db路径
    static QString getCallHistoryDbPath()            // call_history.db路径
    static void printAllPaths()                      // 调试输出所有路径
};
```

### 4. 更新Docker Volume挂载配置

**文件**: [build-ubuntu24-apt.ps1](../../build-ubuntu24-apt.ps1:517-550)

**修改内容**:

**原来的Docker volume结构** (分散多个目录):
```bash
mkdir -p /home/$DeviceUser/belt-control-data/config
mkdir -p /home/$DeviceUser/belt-control-data/databases
mkdir -p /home/$DeviceUser/belt-control-data/audio

docker run \
    -v /home/$DeviceUser/belt-control-data/config:/app/config:rw \
    -v /home/$DeviceUser/belt-control-data/databases:/app/data:rw \
    -v /home/$DeviceUser/belt-control-data/audio:/app/AUDIO:rw \
    ...
```

**修改后的Docker volume结构** (统一appdata目录):
```bash
mkdir -p /home/$DeviceUser/belt-control-data/appdata
mkdir -p /home/$DeviceUser/belt-control-data/audio

docker run \
    -v /home/$DeviceUser/belt-control-data/appdata:/app/appdata:rw \
    -v /home/$DeviceUser/belt-control-data/audio:/app/AUDIO:rw \
    ...
```

**优势**:
- 所有配置和数据库文件统一挂载一个目录
- 简化了Docker volume配置
- 更容易备份和恢复数据（只需备份appdata目录）

## 优势总结

### 1. 防止误删
- 所有重要数据文件集中在一个目录
- 目录名称明确（appdata），不会误删

### 2. 简化备份
- 只需备份一个appdata目录即可
- Docker volume只需挂载一个目录

### 3. 代码可维护性
- 统一的路径配置，修改更容易
- 避免了硬编码路径分散在多个文件

### 4. 跨平台兼容
- Windows和Linux使用相同的逻辑
- 路径由DataPathConfig自动处理

### 5. 便于调试
- `DataPathConfig::printAllPaths()` 一次性输出所有路径
- 启动时自动显示数据文件位置

## 兼容性说明

### 旧数据迁移
如果用户已有分散的数据文件，首次启动时需要手动迁移：

**Windows平台**:
```bash
# 创建appdata目录
mkdir appdata

# 迁移文件
move config.ini appdata\
move operation_logs.db appdata\
move alarm_history.db appdata\
move protection_config.db appdata\
move database\contacts.db appdata\
move database\call_history.db appdata\
```

**Linux/Docker平台**:
```bash
# 旧数据备份（如有）
cp -r /app/config/* /home/linaro/belt-control-data/appdata/ 2>/dev/null || true
cp -r /app/data/* /home/linaro/belt-control-data/appdata/ 2>/dev/null || true
cp -r /app/database/* /home/linaro/belt-control-data/appdata/ 2>/dev/null || true
```

### 向后兼容
- 如果appdata目录不存在，DataPathConfig会自动创建
- 如果数据库文件不存在，各Database类会自动创建表结构
- SystemConfig会在首次运行时使用默认配置

## 总结

通过创建 `DataPathConfig` 统一配置类，我们将所有配置文件和数据库文件整合到了单一的 `appdata` 目录中。这不仅防止了误删，还简化了数据管理、备份和Docker部署流程。

所有修改向后兼容，旧数据可以通过简单的文件移动进行迁移。新的架构更加清晰、可维护，符合软件工程的最佳实践。
