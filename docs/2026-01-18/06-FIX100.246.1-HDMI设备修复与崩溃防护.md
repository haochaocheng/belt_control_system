# FIX 100.246.1 - HDMI 设备修复与崩溃防护

**时间**: 2026-01-18 16:10
**版本**: VERSION 2026-01-18-16:10
**上一版本**: VERSION 2026-01-18-15:50 (硬编码HDMI)
**状态**: ✅ 已实现，待测试

## 问题回顾

VERSION 2026-01-18-12:40 失败，出现三个问题：
1. ❌ PJSIP 仍选择 Loopback 虚拟设备（而非真实 HDMI）
2. ❌ 程序崩溃：Exit code 133（内存堆损坏）
3. ⚠️ 设备名称显示不具体："USB 摄像头麦克风"无法区分不同设备

## 根本原因分析

### 原因 1：HDMI 设备 `output_count=0`

**日志证据**：
```
Device 0 : "hw:CARD=rockchiphdmi0,DEV=0" | Caps: 0 in / 0 out  ← ❌
Device 1 : "plughw:CARD=rockchiphdmi0,DEV=0" | Caps: 0 in / 0 out  ← ❌
```

**但实际**：
```bash
aplay -l
card 0: rockchiphdmi0 [rockchip,hdmi0]  ← ✅ 物理 HDMI 输出设备
```

**结论**：ALSA 驱动 bug - `pjmedia_aud_dev_get_info()` 返回错误的 `output_count`

### 原因 2：通话中切换设备导致崩溃

**堆栈**：
```
corrupted size vs. prev_size while consolidating
#0  __GI_abort ()
#1  __libc_message_impl ()
#2  malloc_printerr (str="corrupted size vs. prev_size while consolidating")
#3  _int_free_merge_chunk ()
```

**触发场景**：
1. 用户在 SIP 设置页面切换设备
2. PJSIP 重复创建/销毁音频设备
3. 内存管理混乱 → 堆损坏 → 崩溃

### 原因 3：设备名称不具体

**现象**：所有 USB 麦克风都显示"USB 摄像头麦克风"
**原因**：友好翻译逻辑使用通用名称

## 解决方案

### 方案 1：通用设备选择策略（兼容所有系统）✅

**❌ 2026-01-18 15:50 旧思路（硬编码）**：
- 强制选择 `plughw:CARD=rockchiphdmi0` HDMI 设备
- 问题：不兼容没有 HDMI 的系统

**✅ 2026-01-18 16:10 新思路（通用策略）**：
- **不硬编码设备名称**，使用智能优先级选择
- **优先级策略**：
  1. **最优**：`plughw:` 真实设备（任何卡片，不仅HDMI）
  2. **次优**：`hw:` 真实设备
  3. **备选**：`Loopback` 虚拟设备（仅当没有真实设备时）
- **特殊处理**：plughw 设备即使 `output_count=0` 也尝试使用（绕过 ALSA bug）
- **兼容性**：适用于所有系统（有 HDMI / 无 HDMI / 其他声卡）

**实现**（`src/risip/core/risipendpoint.cpp:646-694`）：
```cpp
// ✅ 2026-01-18 16:10 [FIX 100.246.1] 通用设备选择策略（兼容所有系统）
// 策略：1. plughw真实设备 > 2. hw真实设备 > 3. Loopback虚拟设备

// 寻找最佳输入设备（麦克风）
if (dev_info.input_count > 0 && !isLoopback && !isDefault) {
    // 优先选择 plughw 设备（自动格式转换）
    if (dev_name.startsWith("plughw:", Qt::CaseInsensitive)) {
        if (best_capture_dev == -1) {
            best_capture_dev = i;
            qDebug() << "      ✅ Selected as capture device (plughw, priority)";
        }
    }
    // 如果还没找到，接受任何非虚拟设备
    else if (best_capture_dev == -1) {
        best_capture_dev = i;
        qDebug() << "      ✅ Selected as capture device (input)";
    }
}

// 寻找最佳输出设备（扬声器）
// ⚠️ 特殊处理：plughw 设备即使 output_count=0 也可能有效（ALSA bug）
if (!isLoopback && !isDefault) {
    bool is_plughw = dev_name.startsWith("plughw:", Qt::CaseInsensitive);
    bool has_output = dev_info.output_count > 0;

    // plughw 设备：即使 output_count=0 也尝试使用（绕过 ALSA bug）
    if (is_plughw && best_playback_dev == -1) {
        best_playback_dev = i;
        if (has_output) {
            qDebug() << "      ✅ Selected as playback device (plughw, priority)";
        } else {
            qDebug() << "      ✅ FORCE select plughw device (bypass output_count=0 ALSA bug)";
        }
    }
    // 其他设备：必须 output_count > 0
    else if (has_output && best_playback_dev == -1) {
        best_playback_dev = i;
        qDebug() << "      ✅ Selected as playback device (output)";
    }
}
```

## 潜在问题与备选方案

### 问题 1：plughw HDMI 仍然 `output_count=0`

**如果** plughw 设备也显示 `output_count=0`，说明是 PJSIP ALSA 适配的深层 bug。

**备选方案**：
```cpp
// 强制使用 plughw HDMI，忽略 output_count 检查
if (dev_name.startsWith("plughw:CARD=rockchiphdmi", Qt::CaseInsensitive)) {
    best_playback_dev = i;
    qDebug() << "      ✅ FORCE select plughw HDMI (IGNORE output_count)";
    break;  // 立即使用，不继续查找
}
```

### 问题 2：plughw HDMI 设备不存在

**日志证据**：没有找到 `plughw:CARD=rockchiphdmi0` 设备

**解决方案**：检查 ALSA 配置
```bash
ssh pi@192.168.1.8
aplay -L | grep -i hdmi
```
