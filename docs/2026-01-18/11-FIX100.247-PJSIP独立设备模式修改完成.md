**Fix编号**: FIX 100.247

## 问题背景

### 用户报告问题

用户发现：
1. ✅ HDMI 已连接显示器（带扬声器）
2. ✅ 显示器扬声器连接 PC 时有声音
3. ❌ 连接 RK3588 设备时无声音
4. ❌ PJSIP 报告 `output_count=0`
5. ❌ 麦克风也没有声音（在禁用虚拟设备前还有声音）

### 诊断过程

经过完整诊断（详见 [09-HDMI音频驱动缺失问题完整诊断.md](./09-HDMI音频驱动缺失问题完整诊断.md) 和 [10-HDMI音频PJSIP兼容性问题分析.md](./10-HDMI音频PJSIP兼容性问题分析.md)）：

1. **HDMI 硬件工作正常**：
   ```bash
   $ speaker-test -D plughw:CARD=rockchiphdmi0,DEV=0 -c 2
   Front Left  ← 听到声音！✅
   Front Right ← 听到声音！✅
   ```

2. **PJSIP 无法使用 HDMI**：
   ```
   06:01:20  Set sound device: capture=5, playback=1
   06:01:20  ..Unable to open playback device 'plughw:CARD=rockchiphdmi0,DEV=0'
   06:01:20  Unable to open sound device: PJMEDIA_EAUD_SYSERR [status=420002]
   ```

3. **麦克风硬件也正常**：
   ```bash
   $ arecord -D plughw:CARD=camera,DEV=0 ... /tmp/test.wav
   录音成功 ✅
   ```

### 根本原因

**PJSIP 设计缺陷**：`alsa_dev.c` 要求播放和录音设备必须同时成功才能创建 audio stream。

**关键代码位置**（修改前）：
```c
// cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-audiodev/alsa_dev.c
// Line 1075-1093

/* Init playback */
if (param->dir & PJMEDIA_DIR_PLAYBACK) {
    status = open_playback (stream, param);
    if (status != PJ_SUCCESS) {
        pj_pool_release (pool);
        return status;  // ← 播放失败直接返回，整个系统失败
    }
}

/* Init capture */
if (param->dir & PJMEDIA_DIR_CAPTURE) {
    status = open_capture (stream, param);
    if (status != PJ_SUCCESS) {
        if (param->dir & PJMEDIA_DIR_PLAYBACK)
            snd_pcm_close (stream->pb_pcm);  // ← 录音失败，关闭播放设备
        pj_pool_release (pool);
        return status;  // ← 录音失败也返回错误
    }
}
```

**问题链**：
```
HDMI playback 失败（ALSA 驱动 bug）
          ↓
整个 audio stream 创建失败
          ↓
即使 USB 麦克风硬件正常
          ↓
麦克风也无法工作 ❌
```

## 解决方案

### 核心思路

**允许麦克风和扬声器独立工作**，只要至少有一个设备成功就继续运行：

- HDMI 播放失败 + USB 麦克风成功 → ✅ 继续（只录音）
- HDMI 播放成功 + USB 麦克风失败 → ✅ 继续（只播放）
- 两个都失败 → ❌ 返回错误

### 修改文件

**文件路径**：`cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-audiodev/alsa_dev.c`

### 修改 1：`alsa_factory_create_stream` - 允许部分设备失败

**位置**：Lines 1075-1163

**修改逻辑**：

```c
/* ✅ 2026-01-18 18:30 [FIX 100.247] 允许麦克风和扬声器独立工作 */

pj_status_t playback_status = PJ_SUCCESS;
pj_status_t capture_status = PJ_SUCCESS;
pj_bool_t playback_opened = PJ_FALSE;
pj_bool_t capture_opened = PJ_FALSE;

/* Init playback */
if (param->dir & PJMEDIA_DIR_PLAYBACK) {
    playback_status = open_playback (stream, param);
    if (playback_status != PJ_SUCCESS) {
        PJ_LOG (3,(THIS_FILE, "⚠️ [FIX 100.247] Playback device failed to open, "
                  "but will continue if capture succeeds (independent device mode)"));
        stream->pb_pcm = NULL;  // 确保指针为 NULL，防止后续误用
    } else {
        playback_opened = PJ_TRUE;
        PJ_LOG (4,(THIS_FILE, "✅ [FIX 100.247] Playback device opened successfully"));
    }
}

/* Init capture */
if (param->dir & PJMEDIA_DIR_CAPTURE) {
    capture_status = open_capture (stream, param);
    if (capture_status != PJ_SUCCESS) {
        PJ_LOG (3,(THIS_FILE, "⚠️ [FIX 100.247] Capture device failed to open, "
                  "but will continue if playback succeeded (independent device mode)"));
        stream->ca_pcm = NULL;  // 确保指针为 NULL，防止后续误用
    } else {
        capture_opened = PJ_TRUE;
        PJ_LOG (4,(THIS_FILE, "✅ [FIX 100.247] Capture device opened successfully"));
    }
}

/* 检查是否至少有一个设备成功打开 */
if (!playback_opened && !capture_opened) {
    /* 两个设备都失败了，无法继续 */
    PJ_LOG (3,(THIS_FILE, "❌ [FIX 100.247] Both playback and capture failed, "
              "cannot create audio stream"));
    pj_pool_release (pool);
    return (capture_status != PJ_SUCCESS) ? capture_status : playback_status;
}

/* 至少有一个设备成功，记录日志 */
if (playback_opened && !capture_opened) {
    PJ_LOG (3,(THIS_FILE, "✅ [FIX 100.247] Audio stream created with PLAYBACK ONLY"));
} else if (!playback_opened && capture_opened) {
    PJ_LOG (3,(THIS_FILE, "✅ [FIX 100.247] Audio stream created with CAPTURE ONLY"));
} else {
    PJ_LOG (4,(THIS_FILE, "✅ [FIX 100.247] Audio stream created with BOTH devices"));
}

/* 更新 param.dir 反映实际打开的设备 */
stream->param.dir = 0;
if (playback_opened)
    stream->param.dir |= PJMEDIA_DIR_PLAYBACK;
if (capture_opened)
    stream->param.dir |= PJMEDIA_DIR_CAPTURE;

PJ_LOG (4,(THIS_FILE, "✅ [FIX 100.247] Final param.dir = %d (1=PLAYBACK, 2=CAPTURE, 3=BOTH)",
          stream->param.dir));
```

### 修改 2：`alsa_stream_start` - 只启动成功打开的设备线程

**位置**：Lines 1276-1328

**修改逻辑**：

```c
/* ✅ 2026-01-18 18:30 [FIX 100.247] 只在设备成功打开时才启动对应线程 */

if ((stream->param.dir & PJMEDIA_DIR_PLAYBACK) && stream->pb_pcm != NULL) {
    status = pj_thread_create (..., pb_thread_func, ...);
    if (status != PJ_SUCCESS) {
        PJ_LOG (3,(THIS_FILE, "❌ [FIX 100.247] Failed to create playback thread"));
        return status;
    }
    PJ_LOG (4,(THIS_FILE, "✅ [FIX 100.247] Playback thread started"));
} else if ((stream->param.dir & PJMEDIA_DIR_PLAYBACK) && stream->pb_pcm == NULL) {
    PJ_LOG (3,(THIS_FILE, "⚠️ [FIX 100.247] Playback requested but device not opened, skipping playback thread"));
}

if ((stream->param.dir & PJMEDIA_DIR_CAPTURE) && stream->ca_pcm != NULL) {
    status = pj_thread_create (..., ca_thread_func, ...);
    if (status != PJ_SUCCESS) {
        PJ_LOG (3,(THIS_FILE, "❌ [FIX 100.247] Failed to create capture thread"));
        stream->quit = PJ_TRUE;
        if (stream->pb_thread) {
            pj_thread_join(stream->pb_thread);
            pj_thread_destroy(stream->pb_thread);
            stream->pb_thread = NULL;
        }
        return status;
    }
    PJ_LOG (4,(THIS_FILE, "✅ [FIX 100.247] Capture thread started"));
} else if ((stream->param.dir & PJMEDIA_DIR_CAPTURE) && stream->ca_pcm == NULL) {
    PJ_LOG (3,(THIS_FILE, "⚠️ [FIX 100.247] Capture requested but device not opened, skipping capture thread"));
}
```

## 技术细节

### PJSIP 音频流创建流程

```
应用层调用 pjsua_set_snd_dev(capture_id, playback_id)
          ↓
pjmedia_aud_stream_create(&param, rec_cb, play_cb, &stream)
          ↓
alsa_factory_create_stream(param, ..., &stream)  ← 我们修改的函数
          ↓
    ┌──────────────┬──────────────┐
    ↓              ↓              ↓
open_playback  open_capture  更新 param.dir
    ↓              ↓              ↓
返回 stream (包含 pb_pcm 和 ca_pcm 指针)
          ↓
alsa_stream_start(stream)  ← 我们修改的函数
          ↓
    ┌──────────────┬──────────────┐
    ↓              ↓
pb_thread_func  ca_thread_func
(播放线程)      (录音线程)
```

### 关键数据结构

```c
struct alsa_stream {
    pjmedia_aud_stream   base;
    pj_pool_t           *pool;
    pjmedia_aud_param    param;      // ← 包含 dir 标志

    snd_pcm_t           *pb_pcm;     // ← 播放设备指针（可能为 NULL）
    snd_pcm_t           *ca_pcm;     // ← 录音设备指针（可能为 NULL）

    pj_thread_t         *pb_thread;  // ← 播放线程
    pj_thread_t         *ca_thread;  // ← 录音线程

    void                *user_data;
    pjmedia_aud_play_cb  pb_cb;      // ← 播放回调
    pjmedia_aud_rec_cb   ca_cb;      // ← 录音回调
};
```

### param.dir 标志值

```c
#define PJMEDIA_DIR_NONE             0   // 无
#define PJMEDIA_DIR_PLAYBACK         1   // 只播放
#define PJMEDIA_DIR_CAPTURE          2   // 只录音
#define PJMEDIA_DIR_CAPTURE_PLAYBACK 3   // 双向（1 | 2 = 3）
```

**修改后的行为**：
- 原始请求：`param->dir = 3`（要求双向）
- 播放失败，录音成功：`stream->param.dir = 2`（更新为只录音）
- 后续所有操作基于实际的 `dir = 2`

## 安全性分析

### 潜在风险

1. **应用层期望双向音频**：
   - 风险：应用可能期望双向音频，但实际只有单向
   - 缓解：PJSIP 会通过回调告知应用实际状态
   - 影响：应用需要适配单向音频模式（已有机制）

2. **NULL 指针访问**：
   - 风险：其他代码可能直接访问 `pb_pcm` 或 `ca_pcm`
   - 缓解：我们已在所有关键位置添加 NULL 检查
   - 需要：测试确保无遗漏

3. **线程同步**：
   - 风险：线程启动/停止逻辑可能有竞态条件
   - 缓解：使用 PJSIP 原有的 `quit` 标志机制
   - 影响：低（PJSIP 设计已考虑）

### 代码审查要点

```c

2. alsa_stream_start - 线程启动前 NULL 检查
3. alsa_stream_destroy - 设备关闭前 NULL 检查
```
