## 问题现象

### 用户报告

1. ✅ FIX 100.247 编译部署成功
2. ✅ 通话可以建立
3. ❌ **对方听不清声音**（关键问题）
4. ⚠️ 日志出现：`Buffer size adjusted from 2304 to 1660 (eff_cnt=1584)`

### 日志证据

```
07:09:53.046  capdbuf  Buffer size adjusted from 2304 to 1660 (eff_cnt=1584)
```

**这个日志的含义**：
- `capdbuf` = Capture Delay Buffer（录音延迟缓冲区）
- `Buffer size adjusted` = 缓冲区大小被自动调整
- `from 2304 to 1660` = 从 2304 字节缩小到 1660 字节
- `eff_cnt=1584` = 有效数据计数

**⚠️ 频繁调整的危害**：
- 音频断断续续
- 音质下降
- 对方听不清

## 可能原因分析

### 原因 1：录音设备读取不稳定 ⭐ 最可能

**问题**：`snd_pcm_readi()` 读取音频数据时出现错误或延迟

**症状**：
- Buffer size 频繁调整
- 可能有 OVERRUN 错误（设备来不及处理数据）
- 音频采集断断续续

**验证方法**：查看调试日志中的错误统计

### 原因 2：音频数据全为0（静音）

**问题**：麦克风虽然打开了，但没有实际采集到声音

**症状**：
- 音频数据全为 0
- 对方完全听不到声音（不是听不清，是听不到）

**验证方法**：查看调试日志中的音频数据分析

### 原因 3：PJSIP 录音回调失败

**问题**：`stream->ca_cb()` 回调函数失败，音频数据未发送

**症状**：
- 录音成功但回调失败
- 音频数据未传递给上层

**验证方法**：查看调试日志中的回调统计

### 原因 4：设备兼容性问题

**问题**：USB 麦克风与 PJSIP 参数不匹配

**症状**：
- 采样率不匹配
- 通道数不匹配
- 格式不匹配

**验证方法**：查看设备打开日志

### 原因 5：系统负载过高

**问题**：CPU 占用高，音频处理不及时

**症状**：
- Buffer 频繁调整
- 实时性差

**验证方法**：SSH 到设备查看 CPU 使用率

### 步骤 4：分析日志

#### 检查点 1：录音线程是否启动

**查找**：
```
🎤 [FIX 100.247 DEBUG] Capture thread started
🎤 [DEBUG] ca_pcm pointer: 0x...
```

**判断**：
- ✅ 找到且 `ca_pcm pointer` 非 NULL → 录音线程正常启动
- ❌ 未找到或 pointer 为 NULL → 录音设备未打开（FIX 100.247 bug）

#### 检查点 2：音频数据是否有效

**查找**：
```
🎤 [AUDIO DATA] Silent: NO ✅, Non-zero samples: 245/320 (76.6%), Max amplitude: 1256
```

**判断**：
- ✅ `Silent: NO ✅` 且 `Max amplitude > 500` → 音频数据正常
- ⚠️ `Silent: NO ✅` 但 `Max amplitude < 100` → 音量太小
- ❌ `Silent: YES ⚠️` → **麦克风未采集到声音**（关键问题）

#### 检查点 3：是否有错误

**查找**：
```
⚠️ [FIX 100.247 DEBUG] OVERRUN detected!
❌ [FIX 100.247 DEBUG] Read error!
```

**判断**：
- ✅ 未找到 → 无读取错误
- ⚠️ 偶尔出现 OVERRUN → 可接受（<1%）
- ❌ 频繁出现 OVERRUN 或其他错误 → **设备或系统问题**

#### 检查点 4：回调是否成功

**查找**：
```
❌ [FIX 100.247 DEBUG] Callback failed!
```

**判断**：
- ✅ 未找到 → 回调正常
- ❌ 找到 → **PJSIP 回调失败**，音频未发送

#### 检查点 5：统计数据

**查找**：
```
Total reads: 1523
Successful reads: 1520 (99.8%)
Error reads: 3 (0.2%)
Callback success: 1520
Callback failures: 0
```

**判断**：
- ✅ 成功率 > 95% 且回调失败 = 0 → 正常
- ⚠️ 成功率 90-95% → 可能有轻微问题
- ❌ 成功率 < 90% 或回调失败 > 0 → **有问题**

#### 检查点 6：Buffer size adjusted 频率

**查找**：
```

```

**判断**：
- ✅ 通话 30 秒内出现 0-5 次 → 正常
- ⚠️ 通话 30 秒内出现 5-20 次 → 轻微不稳定
- ❌ 通话 30 秒内出现 > 20 次 → **严重不稳定**

## 常见问题和解决方案

### 问题 1：音频数据全为 0（静音）

**症状**：
```
🎤 [AUDIO DATA] Silent: YES ⚠️
⚠️⚠️⚠️ WARNING: Captured audio is SILENT!
```

**原因**：
1. 麦克风未正确打开
2. 麦克风权限问题
3. 麦克风硬件故障

**解决方案**：
```bash
# SSH 到设备测试麦克风
ssh pi@192.168.1.8
arecord -D plughw:CARD=camera,DEV=0 -d 3 -f S16_LE -r 16000 -c 1 /tmp/test.wav
aplay /tmp/test.wav  # 应该听到录音
```

### 问题 2：频繁 OVERRUN

**症状**：
```
⚠️ [FIX 100.247 DEBUG] OVERRUN detected! Total reads: 523
⚠️ [FIX 100.247 DEBUG] OVERRUN detected! Total reads: 545
⚠️ [FIX 100.247 DEBUG] OVERRUN detected! Total reads: 568
```

**原因**：
1. 系统负载过高
2. USB 总线繁忙
3. 设备性能不足

**解决方案**：
```bash
# 检查 CPU 使用率
ssh pi@192.168.1.8
top -bn1 | grep belt_control

# 降低视频编码质量（减轻负载）
# 或使用硬件编码器（如果可用）
```

### 问题 3：回调失败

**症状**：
```
❌ [FIX 100.247 DEBUG] Callback failed! result=70015, total_fails=5
```

**原因**：
1. PJSIP 内部错误
2. 编码器失败
3. 网络发送失败

**解决方案**：
- 查看 PJSIP 其他日志
- 检查网络连接
- 检查编码器设置

### 问题 4：音量太小

**症状**：
```
🎤 [AUDIO DATA] Silent: NO ✅, Max amplitude: 45
```

**原因**：
1. 麦克风音量设置过低
2. 麦克风距离太远
3. 麦克风硬件问题

**解决方案**：
```bash
# 调整麦克风音量
ssh pi@192.168.1.8
amixer -c camera set 'Mic' 100%

# 或使用 alsamixer 图形界面调整
alsamixer -c camera
```

### 问题 5：Buffer size 频繁调整

**症状**：
```
07:09:53.046  capdbuf  Buffer size adjusted from 2304 to 1660
07:09:53.106  capdbuf  Buffer size adjusted from 1660 to 1900
07:09:53.166  capdbuf  Buffer size adjusted from 1900 to 1750
... (每 50-100ms 一次)
```

**原因**：
1. 采集不稳定（见问题 2）
2. PJSIP 自适应算法过于敏感
3. 网络抖动

**解决方案**：
- 修复 OVERRUN 问题
- 调整 PJSIP 延迟缓冲区参数（高级）
