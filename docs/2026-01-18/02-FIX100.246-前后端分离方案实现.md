# FIX 100.246 - 前后端分离方案实现

**日期**: 2026-01-18 12:00
**版本**: VERSION 2026-01-18-12:00
**状态**: ✅ 实现完成，等待测试验证

## 📋 问题回顾

**VERSION 2026-01-18-11:30 测试结果**：
- ✅ 扬声器下拉列表有数据了
- ❌ 但是数据太多（28个设备）
- ❌ **根本问题**：QML 绑定 `model: SipPhoneManager.getVideoDevices()` 导致应用启动时就调用函数
- ❌ 函数调用触发了 PJSIP 提前初始化（违反了懒加载设计）

**日志证据**：
```
02:43:55.183 - getVideoDevices() called!  ← 应用启动时就调用了
02:43:55.187 - initializeEndpoint() called!
```

**用户反馈**：
> "程序启动，QML只是建立下拉表，此时sip功能还没有启动,需要手动启动，因此设备列表为空，完整流程应该是等手动启动sip按钮后，会有完整的音频检测流程，这是可以获取音频信息，这个是后台，等列举完成后，就更新QML,这个就是前后端分离"

---

## 🎯 解决方案：前后端分离

### 设计理念

```
应用启动 → QML 创建下拉框（空列表）
                ↓
          用户点击 SIP 按钮
                ↓
     "Deferred initialization starting"
                ↓
      C++ 初始化 PJSIP endpoint
                ↓
        枚举音视频设备（后台）
                ↓
          更新缓存列表
                ↓
       发射 signals 通知 QML
                ↓
      QML 接收 signal → 更新 UI
```

### 关键技术

**Qt 响应式编程模型**：
- ❌ **函数绑定**：`model: SipPhoneManager.getVideoDevices()` → 立即求值
- ✅ **Property 绑定**：`model: SipPhoneManager.videoDevices` → 响应式更新
- ✅ **Signal/Slot**：后端变化 → 自动通知前端

## 🔧 实现细节

### 1. 后端实现（SipPhoneManager）

#### 1.1 添加 Q_PROPERTY 定义

**文件**：`src/sip_phone/SipPhoneManager.h` (lines 41-46)

```cpp
// ✅ 2026-01-18 12:00 [FIX 100.246] 设备列表 Q_PROPERTY（前后端分离）
// 原因：QML 绑定函数调用会立即求值导致 PJSIP 提前初始化
// 解决：使用 Q_PROPERTY + Signal 通知机制，PJSIP 初始化后才更新设备列表
Q_PROPERTY(QStringList audioInputDevices READ audioInputDevices NOTIFY audioInputDevicesChanged)
Q_PROPERTY(QStringList audioOutputDevices READ audioOutputDevices NOTIFY audioOutputDevicesChanged)
Q_PROPERTY(QStringList videoDevices READ videoDevices NOTIFY videoDevicesChanged)
```

**关键点**：
- 使用 `Q_PROPERTY` 而不是 `Q_INVOKABLE` 函数
- 每个 property 关联一个 `NOTIFY` signal

#### 1.2 添加缓存的设备列表

**文件**：`src/sip_phone/SipPhoneManager.cpp` (Private class, lines 290-294)

```cpp
// ✅ 2026-01-18 12:00 [FIX 100.246] 设备列表缓存（前后端分离）
QStringList cachedAudioInputDevices;   // 音频输入设备列表（麦克风）
QStringList cachedAudioOutputDevices;  // 音频输出设备列表（扬声器）
QStringList cachedVideoDevices;        // 视频设备列表（摄像头）
```

**目的**：
- 缓存设备列表，避免每次访问都调用 PJSIP API
- 初始为空列表，PJSIP 初始化后才填充

#### 1.5 在 initializeEndpoint() 中枚举设备

**文件**：`src/sip_phone/SipPhoneManager.cpp` (lines 851-879)

```cpp
bool SipPhoneManager::initializeEndpoint()
{
    // ... PJSIP 初始化代码 ...

    d->initialized = true;
    emit isInitializedChanged(true);

    // ... 视频子系统初始化 ...
    // ... 账户配置 ...

    // ✅ 2026-01-18 12:00 [FIX 100.246] PJSIP 初始化成功后枚举设备并发射信号
    qDebug() << "📱 [FIX 100.246] Enumerating devices after PJSIP initialization";

    // Enumerate audio input devices
    d->cachedAudioInputDevices = getAudioInputDevices();
    qDebug() << "✅ Audio input devices enumerated:" << d->cachedAudioInputDevices.count();
    emit audioInputDevicesChanged(d->cachedAudioInputDevices);

    // Enumerate audio output devices
    d->cachedAudioOutputDevices = getAudioOutputDevices();
    qDebug() << "✅ Audio output devices enumerated:" << d->cachedAudioOutputDevices.count();
    emit audioOutputDevicesChanged(d->cachedAudioOutputDevices);

    // Enumerate video devices
    d->cachedVideoDevices = getVideoDevices();
    qDebug() << "✅ Video devices enumerated:" << d->cachedVideoDevices.count();
    emit videoDevicesChanged(d->cachedVideoDevices);

    qDebug() << "📱 [FIX 100.246] All devices enumerated, signals emitted to QML";

    return true;
}
```

**关键点**：
- PJSIP 初始化完成后立即枚举设备
- 更新缓存列表
- **发射 signals 通知 QML**

## 🎯 技术要点

### Qt Property 绑定机制

**函数绑定**：
```qml
model: SipPhoneManager.getVideoDevices()
```
- ❌ QML 引擎立即调用函数求值
- ❌ 应用启动时就执行
- ❌ 破坏懒加载设计

**Property 绑定**：
```qml
model: SipPhoneManager.videoDevices
```
- ✅ QML 引擎只读取 property 当前值
- ✅ 监听 `videoDevicesChanged` signal
- ✅ Signal 触发 → 自动重新读取 property → UI 更新

### Signal/Slot 优势

**传统方式（轮询）**：
```cpp
// ❌ 需要 QML 定时轮询
Timer {
    interval: 1000
    running: true
    onTriggered: {
        // 每秒检查一次
        if (SipPhoneManager.isInitialized) {
            // 更新 model
        }
    }
}
```

**响应式方式（Signal）**：
```cpp
// ✅ 后端主动通知前端
emit audioInputDevicesChanged(devices);
```
- 前端无需轮询
- 实时响应
- 性能更好

### 缓存机制

**无缓存（每次调用 API）**：
```cpp
QStringList audioInputDevices() const
{
    QStringList devices;
    pjsua_enum_aud_devs(info, &count);  // ❌ 每次都调用 PJSIP API
    // ...
    return devices;
}
```

**有缓存（读取内存）**：
```cpp
QStringList audioInputDevices() const
{
    return d->cachedAudioInputDevices;  // ✅ 直接返回缓存
}
```

**更新时机**：
- 仅在 PJSIP 初始化完成后枚举一次
- 设备列表一般不变（除非插拔设备）
- 避免频繁调用 PJSIP API

## 📝 经验教训

### ❌ 错误的理解

**我的错误假设**：
```
QML 函数绑定 = 惰性求值（用到时才调用）
```

**实际情况**：
```
QML 函数绑定 = 立即求值（创建时就调用）
```

### ✅ 正确的理解

**Qt 响应式编程模型**：
- **Property 绑定**：响应式，signal 驱动
- **函数绑定**：主动式，立即求值
- **Connections**：显式监听 signal

**前后端分离**：
- 前端（QML）：展示层，响应式更新
- 后端（C++）：业务逻辑，主动通知
- Signal/Slot：连接桥梁

### 🔍 调试技巧

**添加调用时机追踪**：
```cpp
qDebug() << "🔥🔥🔥 [ENTRY] getVideoDevices() called!";
qDebug() << "   [TIMING] Called at:" << QDateTime::currentDateTime().toString("yyyy-MM-dd HH:mm:ss.zzz");
```

**好处**：
- 精确定位函数调用时机
- 发现问题：应用启动时就调用了（02:43:55.183）
- 而不是 SIP 按钮点击时调用

## ✅ 总结

**问题**：QML 函数绑定导致应用启动时就初始化 PJSIP（VERSION 2026-01-18-11:30）

**根因**：
- QML `model: SipPhoneManager.getVideoDevices()` 立即调用函数
- 函数内部触发 PJSIP 自动初始化
- 违反了懒加载设计（应该在 SIP 按钮点击时初始化）

**解决方案**（VERSION 2026-01-18-12:00）：
- 后端：添加 Q_PROPERTY + 缓存列表 + Signals
- 前端：改用 property 绑定 + Connections 监听 signal
- 时机：PJSIP 初始化成功后才枚举设备并发射 signal

**核心技术**：
- Qt Property 绑定机制（响应式）
- Signal/Slot 通知机制（事件驱动）
- 前后端分离（业务逻辑与展示层分离）

**预期结果**：
- ✅ 应用启动时下拉框为空（不调用设备枚举）
- ✅ 点击 SIP 按钮后 PJSIP 初始化
- ✅ 初始化完成后枚举设备并通知 QML
- ✅ QML 自动更新 UI 显示设备列表
