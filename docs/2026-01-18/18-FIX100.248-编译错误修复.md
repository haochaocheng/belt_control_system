## 🔍 根本原因

### 错误假设

我错误地假设 PJSIP2 C++ API 的 `AudDevManager` 有以下方法：

```cpp
AudDevManager::Config getConfig();
void setConfig(const Config &cfg);
```

**事实**：
- PJSIP2 C++ API 的 `AudDevManager` 类**没有** `Config` 结构
- `AudDevManager` 主要用于获取音频媒体流，不是用于配置媒体参数
- 媒体配置需要在 Endpoint 初始化时设置（`EpConfig::medConfig`）

### 正确的 API

通过查看代码库中的其他用法，找到了两种正确方法：

#### 方法 1：初始化时配置（编译前）
```cpp
// risipendpoint.cpp Line 519
m_data->endpointConfig.medConfig.clockRate = 16000;
m_data->endpointConfig.medConfig.channelCount = 2;
```

**缺点**：只能在 Endpoint 创建前设置，运行时无法动态修改。

#### 方法 2：PJSIP C API 动态配置（运行时）⭐
```cpp
pjsua_media_config media_cfg;
pjsua_media_config_default(&media_cfg);
media_cfg.clock_rate = 8000;
pj_status_t status = pjsua_reconfigure_media(&media_cfg);
```

**优点**：
- ✅ 可以在运行时动态修改
- ✅ PJSIP 官方 C API，稳定可靠
- ✅ 可以获取当前配置进行对比

```cpp
// ✅ 2026-01-18 22:15 [FIX 100.248] 配置音频设备采样率为 8kHz
// 原因：
//   - PCMA/PCMU 使用 8000 Hz
//   - plughw 设备支持所有采样率（ALSA 自动重采样）
//   - 设置为 8kHz 避免 PJSIP 内部多次重采样
// 效果：
//   - 麦克风(硬件) → ALSA重采样(一次) → 8kHz → PJSIP(8kHz) → PCMA(8kHz)
//   - PJSIP 内部零重采样（8kHz → 8kHz）
// 核心理念：程序适应设备，而不是设备适应程序
// 配合：FIX 100.248 设备枚举优先选择 plughw（支持所有采样率）
// 参考：docs/2026-01-18/16-FIX100.248-优先使用plughw设备.md
qDebug() << "";
qDebug() << "🔧 [FIX 100.248] Configuring audio device for 8kHz (PCMA/PCMU compatible)...";

// ✅ 使用 PJSIP C API 获取和修改媒体配置
pjsua_media_config media_cfg;
pjsua_media_config_default(&media_cfg);

// 获取当前配置（如果可能）
pjsua_config ua_cfg;
pjsua_logging_config log_cfg;
pjsua_media_config current_media_cfg;
pj_status_t status = pjsua_get_config(&ua_cfg, &log_cfg, &current_media_cfg);

unsigned origClockRate = 16000;  // 默认值
unsigned origChannelCount = 2;   // 默认值

if (status == PJ_SUCCESS) {
    origClockRate = current_media_cfg.clock_rate;
    origChannelCount = current_media_cfg.channel_count;
    qDebug() << "  📋 Current media config: clock_rate=" << origClockRate
             << "Hz, channels=" << origChannelCount;
}

// 设置为 8kHz（匹配 PCMA/PCMU）
media_cfg.clock_rate = 8000;        // ⭐ 8000 Hz（PCMA/PCMU 采样率）
media_cfg.channel_count = 1;        // 单声道
media_cfg.audio_frame_ptime = 20;   // 20ms 帧

// 应用新配置
status = pjsua_reconfigure_media(&media_cfg);

if (status == PJ_SUCCESS) {
    qDebug() << "  ✅ Audio device configured successfully:";
    qDebug() << "     Clock rate: 8000 Hz (was:" << origClockRate << "Hz)";
    qDebug() << "     Channels: 1 (mono) (was:" << origChannelCount << ")";
    qDebug() << "     Frame time: 20 ms";
    qDebug() << "  📊 [EFFECT] Audio resampling chain:";
    qDebug() << "     Microphone (hardware native rate, e.g., 22050 Hz)";
    qDebug() << "       ↓ ALSA resampling (once, by plughw device)";
    qDebug() << "     8000 Hz ← PJSIP requested rate";
    qDebug() << "       ↓ NO PJSIP internal resampling ✅";
    qDebug() << "     PJSIP audio processing (8000 Hz)";
    qDebug() << "       ↓ NO resampling for PCMA/PCMU ✅";
    qDebug() << "     PCMA/PCMU encoding (8000 Hz)";
    qDebug() << "  🎯 [RESULT] Total resampling: 1 (ALSA only)";
    qDebug() << "  🎯 [COMPARE] Previous: 2 (ALSA + PJSIP internal)";
} else {
    qDebug() << "  ⚠️ Warning: Could not reconfigure media (status:" << status << ")";
    qDebug() << "     Continuing with default settings (may have resampling)";
    qDebug() << "     PCMA/PCMU should still work (PJSIP will do internal resampling)";
}
qDebug() << "";
```

## 🎯 关键要点

### PJSIP2 C++ API vs PJSIP C API

| API 类型 | 配置方法 | 时机 | 优缺点 |
|---------|---------|------|--------|
| **PJSIP2 C++** | `EpConfig::medConfig` | 初始化前 | ✅ 类型安全<br>❌ 不能运行时修改 |
| **PJSIP C** | `pjsua_reconfigure_media()` | 运行时 | ✅ 动态修改<br>✅ 灵活性高<br>⚠️ 需要检查返回值 |

### 选择依据

- **初始化配置**: 使用 PJSIP2 C++ API (`EpConfig::medConfig`)
- **运行时修改**: 使用 PJSIP C API (`pjsua_reconfigure_media()`)
- **本次修复**: 需要在 Endpoint 已启动后修改，必须使用 C API

---

## 📝 经验教训

1. **不要假设 C++ API 的完整性**: PJSIP2 C++ 是对 C API 的包装，并不是所有 C API 功能都有 C++ 等价物
2. **优先查看现有代码**: 代码库中已有的用法是最可靠的参考
3. **阅读 PJSIP 文档**: 官方文档明确说明了 `pjsua_reconfigure_media()` 的用途
4. **错误处理**: 使用 C API 时必须检查返回值（PJ_SUCCESS）
