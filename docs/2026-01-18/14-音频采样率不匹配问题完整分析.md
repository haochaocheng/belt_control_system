# 音频采样率不匹配问题完整分析

**日期**: 2026-01-18 20:40
**问题**: 对方听不清声音
**根本原因**: 采样率多次转换导致音质劣化 + 麦克风增益过低

---

## 📋 问题现象

### FIX 100.247.1 测试日志发现

1. **采样率不匹配**:
   ```
   Sample rate: 22050 Hz (requested: 16000)
   ```
   - PJSIP 请求 16000 Hz
   - 设备实际工作在 22050 Hz
   - 需要重采样：22050 Hz → 16000 Hz

2. **麦克风音量偏低**:
   - RMS 值大部分时间在 3000-5000 之间（正常应该 5000-15000）
   - 音量偏低约 50-70%

3. **多次重采样链**:
   ```
   麦克风 (22050 Hz) → PJSIP 内部 (16000 Hz) → 编解码器 (8000 Hz)
   ```
   - 每次重采样都会劣化音质
   - 累积效果：音质明显下降

---

| **opus/48000/2** | 48000 Hz | 宽带/超宽带 | 6-510 kbps | 现代音频编解码器，音质最好 |

```

    ↓ 重采样

    ↓ 编码
RTP 发送 (8000 Hz)
```

**问题**:
- 22050 Hz → 16000 Hz → 8000 Hz（两次重采样）
- 音质损失 + 麦克风增益不足 = 听不清

## 🔍 16000 Hz 采样率来源分析

### PJSIP 默认行为

**16000 Hz 是 PJSIP 的默认宽带音频采样率**

**原因**:
1. **回声消除 (AEC) 需要**: Speex AEC 在 16000 Hz 效果更好
2. **更好的音质**: 16 kHz 可以覆盖 0-8 kHz 频率范围（窄带 8 kHz 只能覆盖 0-4 kHz）
3. **兼容性**: 大多数现代音频设备支持 16000 Hz

**代码位置**:
- PJSIP 内部默认值（未在我们的代码中显式设置）
- 参考: `pjsua_aud.c` 默认创建 16 kHz 音频流

**从日志验证**:
```
Line 518: Speex AEC created, clock_rate=16000, channel=2
```
→ PJSIP 自动选择 16000 Hz 用于音频处理

## 🎯 解决方案对比

### 方案 1: **修改 PJSIP 使用 8000 Hz** ⭐⭐ **最兼容**

**优点**:
- ✅ 避免 16000 Hz 不匹配问题
- ✅ 减少重采样次数（22050 Hz → 8000 Hz，一次）
- ✅ 与 PCMA/PCMU 编解码器完美匹配

**缺点**:
- ❌ 回声消除效果可能稍差
- ❌ 音质受限于 8 kHz（窄带）

**实现难度**: ⭐⭐ 中等（需要修改 PJSIP 配置）

**实现方式**:
```cpp
// 在 risipendpoint.cpp 启动时设置
AudioMediaConfig &audio_config = Endpoint::instance().audDevManager().getAudioDeviceConfig();
audio_config.clockRate = 8000;  // 强制使用 8000 Hz
Endpoint::instance().audDevManager().setAudioDeviceConfig(audio_config);
```

---

### 方案 2: **切换到 Opus 编解码器** ⭐⭐⭐ **推荐**

**优点**:
- ✅ Opus 支持 48000 Hz 宽带/超宽带音质
- ✅ 更好的音质（明显优于 PCMA/PCMU）
- ✅ 灵活的采样率（8k-48k 自适应）
- ✅ 更低的带宽消耗（可调 6-510 kbps）
- ✅ 现代 SIP 服务器普遍支持

**缺点**:
- ❌ 需要对方也支持 Opus
- ❌ 仍需要重采样（22050 Hz → 48000 Hz）

**实现难度**: ⭐ 简单（已配置 opus/48000/2）

**实现方式**:
```cpp

Endpoint::instance().codecSetPriority("PCMU/8000", 0);       // 禁用 PCMU
```

**PJSIP 内部流程**:
```

    ↓ 重采样

    ↓ Opus 编码

```

## 📝 关键问题解答

### Q1: 为什么另一个地方使用同样的 USB 麦克风没问题？

**A**: 可能的原因：
1. **对方使用 8 kHz 采样率**: 直接 22050 Hz → 8000 Hz，一次重采样
2. **对方不使用 PJSIP 宽带模式**: 没有 16000 Hz 中间层
3. **对方麦克风增益更高**: 音量足够抵消重采样损失

### Q2: 16 kHz 是哪个音频编码器的要求？

**A**:
- **不是编解码器要求，是 PJSIP 内部音频处理要求**
- PCMA/PCMU 编解码器使用 8000 Hz
- PJSIP 在编码前使用 16000 Hz 进行回声消除和音频处理
- 目的：更好的音质 + 更好的 AEC 效果

### Q3: 使用 Opus 需要怎么做？

**A**:
1. **修改优先级**（见阶段 2）
2. **确认对方支持 Opus**（大多数现代 SIP 服务器支持）
3. **可选：优化 Opus 参数**（见阶段 3）

**注意**: Opus 已在配置文件中启用（`pjsip_config_site.h` Line 42-43）
```c
#define PJMEDIA_HAS_OPUS_CODEC 1
```

### Q4: Opus 的 48000 Hz 会不会也有重采样问题？

**A**:
- **会有重采样，但音质损失更小**
- 22050 Hz → 48000 Hz（上采样，音质损失小）
- 22050 Hz → 8000 Hz（下采样，音质损失大）
- Opus 本身音质远超 G.711，抵消重采样损失
