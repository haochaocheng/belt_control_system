## 一、模块在线/离线逻辑 — 已实现，链路完整

### 数据链路

```
QMqttClient (底层MQTT客户端)
  → MQTTController::connectedChanged(moduleIndex, connected) 信号
    → MQTTAutoManager::onModuleConnected(moduleIndex, connected) 槽
      → 更新 m_healthStatus[moduleIndex].connected
      → emit healthStatusChanged()
        → QML 绑定 mqttAutoManager.healthStatus[moduleIndex].connected
          → SwitchInputPage.qml moduleStatusItem.isOnline
```

### 关键参数

| 参数 | 值 | 说明 |
|------|------|------|
| 健康检查间隔 | 1000ms (1秒) | `HEALTH_CHECK_INTERVAL` |
| 重连检查间隔 | 5000ms (5秒) | `RECONNECT_CHECK_INTERVAL` |
| 数据超时阈值 | 5秒 | `DATA_TIMEOUT_THRESHOLD` |
| 最大超时次数 | 3次 | `MAX_TIMEOUT_COUNT`，连续3次超时→状态变为"数据超时" |
| DI轮询间隔 | 100ms | `m_diPollingInterval` |
| MQTT KeepAlive | 60秒 | QMqttClient 默认 |

### 模块索引分配

| 索引 | 模块 | MQTT主题 |
|------|------|----------|
| 0 | 开关量输入模块1 | `belt_control/di/module1/` |
| 1 | 开关量输入模块2 | `belt_control/di/module2/` |
| 2 | 模拟量输入模块1 | `belt_control/ai/module1/` |
| 3 | 模拟量输入模块2 | `belt_control/ai/module2/` |
| 4-7 | 未使用 | 状态保持默认 `connected=false` |

### 状态判断逻辑

**MQTTController::isModuleConnected()** — 实时查询 QMqttClient 状态：
```cpp
bool MQTTController::isModuleConnected(int moduleIndex) const
{
    return m_clients[idx]->state() == QMqttClient::Connected;
}
```

**MQTTAutoManager::checkModuleHealth()** — 每秒执行：
1. 调用 `isModuleConnected()` 确认连接状态
2. 未连接 → `status = "未连接"`
3. 已连接但5秒无数据 → `dataTimeoutCount++`
4. 超时次数 ≥ 3 → `status = "数据超时"`，emit `moduleHealthWarning`
5. 数据恢复 → `status = "正常"`，emit `moduleHealthRecovered`

**结论：模块在线/离线逻辑已完整实现，无需额外编写。**

## 二、模块断开后通道状态行为 — 存在问题

### 问题描述

**场景**：模块在线时某通道被激活（bit=1），随后模块因外部原因断开。

**当前行为**：
1. ✅ `moduleStatusItem.isOnline` 变为 `false` → 模块状态显示"离线"（红色LED）
2. ❌ `channelStatusItem.isActive` 仍为 `true` → 通道状态仍显示"信号激活 (1)"（绿色LED闪烁）

**用户看到矛盾的界面**：模块已离线，但通道仍显示保护已触发。

### 根因分析

**DIDataManager 在模块断开后保持最后值，不清零。**

数据停止更新的链路：
```
模块断开
  → pollDIModules() 跳过未连接模块:
      if (!m_mqttController->isModuleConnected(i)) continue;
  → 不再发送 read 命令
  → 不再收到 MQTT 消息
  → DIDataManager::parseData() 不再被调用
  → m_diData 保持最后值不变
  → getBit() 返回断开前的缓存值
  → QML 通道状态不更新
```

**DIDataManager 中没有任何 reset/clear 逻辑**：
- `m_diData` 只在构造函数初始化为全 `false`
- 只在 `parseJsonData()` 收到新数据时更新
- 没有 `resetModule()` 方法
- 模块断开时无人通知 DIDataManager 清零

**QML 层 `channelStatusItem.isActive` 没有联合判断模块在线状态**：
```qml
// 当前代码（SwitchInputPage.qml 第905-920行）
readonly property bool isActive: {
    // 只检查 diDataManager 数据，不检查模块是否在线
    return diDataManager.getBit(moduleIdx, bitIdx)
}
```

### 缺失的逻辑

| 层级 | 缺失内容 | 影响 |
|------|---------|------|
| C++ DIDataManager | 无 `resetModule(int moduleIndex)` 方法 | 模块断开后数据不清零 |
| C++ MQTTAutoManager | `onModuleConnected(idx, false)` 未通知 DIDataManager | 断开事件未传递到数据层 |
| QML SwitchInputPage | `isActive` 未联合判断模块在线状态 | 离线时仍显示激活 |

## 三、修复方案

### 方案A：QML 层快速修复（最小改动）

在 `channelStatusItem.isActive` 中加入模块在线判断：

```qml
readonly property bool isActive: {
    if (root.currentProtectionIndex >= 0 && ...) {
        var item = digitalProtectionModel.get(root.currentProtectionIndex)
        var moduleIdx = (item.moduleType === "开关量输入模块1") ? 0 : 1

        // ✅ 新增：模块离线时强制返回 false
        if (typeof mqttAutoManager !== 'undefined' && mqttAutoManager !== null) {
            var hs = mqttAutoManager.healthStatus
            if (moduleIdx >= 0 && moduleIdx < hs.length && !hs[moduleIdx].connected) {
                return false
            }
        }

        // 原有逻辑
        if (typeof diDataManager !== 'undefined' && diDataManager !== null) {
            var _dep = (moduleIdx === 0) ? diDataManager.module1Data : diDataManager.module2Data
            return diDataManager.getBit(moduleIdx, item.channelNumber)
        }
        return item.active
    }
    return false
}
```

**优点**：改动最小，只修改 QML 一处
**缺点**：DIDataManager 内部数据仍是脏数据，其他使用 getBit() 的地方不受保护

### 方案B：C++ 层完整修复（推荐）

1. **DIDataManager 新增 `resetModule()` 方法**：
```cpp
void DIDataManager::resetModule(int moduleIndex)
{
    if (moduleIndex >= 0 && moduleIndex < 2) {
        m_diData[moduleIndex].fill(false);
        emit (moduleIndex == 0) ? module1DataChanged() : module2DataChanged();
    }
}
```

2. **MQTTAutoManager::onModuleConnected() 断开时调用**：
```cpp
if (!connected) {
    m_healthStatus[moduleIndex].status = "未连接";
    // 通知 DIDataManager 清零对应模块数据
    if (moduleIndex < 2 && m_diDataManager) {
        m_diDataManager->resetModule(moduleIndex);
    }
}
```

3. **QML 层同时加入方案A的保护**（双重保险）

**优点**：从数据源头解决问题，所有使用 getBit() 的地方都受保护
**缺点**：需要修改 C++ 代码，需要重新编译

### 方案C：左侧列表也需要同步处理

左侧保护列表的每个 delegate 也有 `_diIsActive` 属性（第176-264行），同样存在模块离线后仍显示激活的问题。修复方案与右侧通道状态一致。

## 五、建议

推荐采用 **方案B（C++ 层完整修复）+ 方案A（QML 双重保险）**，确保：
1. 模块断开 → DIDataManager 数据立即清零 → 所有绑定自动更新
2. QML 层额外检查在线状态 → 防止任何边界情况

优先级：中等。当前设备运行稳定时不会触发此问题，但在网络不稳定或设备掉电场景下会导致界面显示矛盾。
