## Phase 7.47.55 - 修复pi设备TTS批量合成失败

**提交**: `79e87334`
**设备**: pi@192.168.10.186

### 问题描述
pi 设备上批量语音合成失败，两个根因：

1. **QML outputBaseDir 路径错误** — `getOutputBaseDir()` 使用 `process.env.BELT_CONTROL_USER`（Node.js API），QML 不支持，永远回退 `"linaro"`，pi 设备路径应为 `/home/pi/...`
2. **PaddleSpeech vocoder 下载失败** — `download_and_decompress` 检查 `hifigan_csmsc_ckpt_0.1.1.zip` 是否存在，pi 设备该 zip 缺失，触发网络下载但设备无网络

### 修复内容

| 文件 | 修改 |
|------|------|
| `src/main/main.cpp` | 新增 `setContextProperty("audioBaseDir", DataPathConfig::getAudioBaseDirectory())`，C++ 读取环境变量后注入 QML |
| `src/qml/pages/BatchSynthesisContent.qml` | `getOutputBaseDir()` 改为直接返回 `audioBaseDir`（C++ 注入） |
| `docker/rk3588/tts_engines/paddlespeech/paddle_tts_service.py` | 新增 VOC_PATH_MAP/AM_PATH_MAP，传入 `voc_config`/`voc_ckpt`/`voc_stat` 和 `am_config`/`am_ckpt`/`am_stat` 本地路径参数，绕过 PaddleSpeech 下载机制 |

## Phase 7.47.56 - 修复默认音频来源仍播放TTS

**提交**: `8b6c0224`

### 问题描述
用户在开关量保护参数设置中点击"默认"并保存后，触发通道0仍播放TTS合成音频。

### 根因分析（已验证，非猜测）

1. **pi 设备 DB 数据未迁移** — `schema_migrations` 表不存在，证明 Phase 7.47.52 的 `runMigrations()` C++ 代码未部署。DB 中 96 条记录 `use_text_to_speech` 全部为 `1`
2. **代码默认回退值错误** — `protection.value("use_text_to_speech", 1)` 默认回退值为 `1`（TTS），即使字段缺失也返回 TTS

### 修复内容

| 操作 | 说明 |
|------|------|
| `MqttProtectionMonitor.cpp` Line 151 | `protection.value("use_text_to_speech", 1)` → `protection.value("use_text_to_speech", 0)`，默认回退值改为 0（默认音频） |
| pi 设备 DB 直接修复 | 通过 Python 将 96 条记录 `use_text_to_speech` 从 1 重置为 0，创建 `schema_migrations` 表并记录迁移 |

### 验证
```
# 修复前
[(1, '急停', 1), (1, '跑偏', 1), ...]  # 全部为 1（TTS）

# 修复后
[(1, '急停', 0), (1, '跑偏', 0), ...]  # 全部为 0（默认音频）
```
