## 需求描述

当前"开始生成"按钮只为 PaddleSpeech 引擎的**1个说话人ID**生成全部分类语音（约2,112个文件）。
需要新增按钮，一键为当前加载模型的**所有说话人ID**都生成完整语音文件。

**使用场景**：利用晚上时间批量跑，支持停止后第二天继续，容器重启不丢失进度。

---

## 当前架构说明

### PaddleSpeech 引擎模型体系

系统使用 **PaddleSpeech 引擎**（不是vits），有以下模型：

| PaddleSpeech模型 | 说话人数 | PaddleSpeech modelIndex | 备注 |
|-----------------|----------|------------------------|------|
| fastspeech2_csmsc | 1（单说话人女声） | 0 | 中文 |
| **fastspeech2_aishell3** | **174（ID 0-173）** | 1 | **中文，主要目标** |
| ~~fastspeech2_ljspeech~~ | ~~1（英文女声）~~ | ~~2~~ | ~~英文，不需要~~ |
| ~~fastspeech2_vctk~~ | ~~108（英文多说话人）~~ | ~~3~~ | ~~英文，不需要~~ |

> **注意**：TTSConfigManager中的7个vits模型名（如vits-zh-aishell3）用于文件夹命名，PaddleSpeech实际加载的是fastspeech2系列模型。

### 当前"开始生成"按钮工作流程

1. QML `buildConfig()` 构建配置：
   - `engineName: "PaddleSpeech"` - 固定引擎
   - `modelName`: 从 TTSConfig 获取，**仅用于输出文件夹命名**
   - `speakerId`: 从 TTSConfig 获取当前选中的1个ID
2. C++ `BatchAudioGenerator::executeTask()` 合成时：
   - 调用 `setCurrentEngine("PaddleSpeech")` 切换引擎
   - 调用 `synthesize(text, path, params)` → params.speakerId 传给Python服务
   - **不切换模型**，使用 PaddleSpeech 已加载的模型

## 实施方案

### 只修改1个文件：`src/qml/pages/BatchSynthesisContent.qml`

**不需要修改C++后端**，原因：
- `BatchAudioGenerator` 的 `m_engines` 列表已支持多个 EngineConfig
- `m_skipExisting` 已实现跳过已存在文件（断点续传）
- `executeTask()` 中 `QFile::exists()` 检查已存在
- 音频文件在Docker挂载卷上，容器重启不丢失

### 新增内容

#### 1. 新增按钮"全部ID生成"

位置：在现有"生成所有ID语音"按钮旁边（第525行附近）

```qml
Button {
    text: batchGenerator && batchGenerator.isRunning ? "停止" : "全部ID生成"
    Layout.preferredWidth: 130
    Layout.preferredHeight: 36
    onClicked: {
        if (batchGenerator && batchGenerator.isRunning) {
            batchGenerator.stop()
        } else {
            startFullGeneration()
        }
    }
}
```

#### 2. 新增函数 `startFullGeneration()`

```javascript
function startFullGeneration() {
    // 复用现有配置（分类、皮带数、电机数等全部使用界面当前设置）
    var config = buildConfig()

    // 获取当前模型的说话人上限
    var modelIdx = TTSConfig.modelIndex(TTSConfig.Test)
    var maxId = TTSConfig.maxSpeakerId(modelIdx)
    var modelName = TTSConfig.modelName(modelIdx)

    appendLog("info", "全部ID生成：模型=" + modelName + "，说话人范围=0~" + maxId)
    appendLog("info", "预计总文件数：" + ((maxId + 1) * parseInt(calculateTotalFiles())) + " 个")

    // 为每个说话人ID创建一个EngineConfig（替换buildConfig中的单个engine）
    var engines = []
    for (var id = 0; id <= maxId; id++) {
        engines.push({
            engineName: "PaddleSpeech",
            modelName: modelName,
            speakerId: id,
            rate: TTSConfig.rate(TTSConfig.Test),
            volume: TTSConfig.volume(TTSConfig.Test),
            outputFolder: "paddlespeech-" + modelName + "-spk" + id
        })
    }
    config.engines = engines
    config.skipExisting = true  // 强制启用断点续传

    batchGenerator.setConfig(config)
    batchGenerator.start()
}
```

### 断点续传工作原理

1. 每个说话人ID输出到独立目录：`paddlespeech-{modelName}-spk0/`、`spk1/`...
2. `skipExisting=true` → 文件已存在则跳过
3. 晚上跑到一半按"停止" → 第二天重新点"全部ID生成" → 自动跳过已完成文件
4. 容器重启 → 挂载卷上文件不丢失 → 重新点击即从断点继续
