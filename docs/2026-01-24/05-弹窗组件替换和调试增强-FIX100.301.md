## 3. 修复方案

### 3.1 修复1：替换内联弹窗为现有组件

**文件**: `src/qml/pages/Input1Page.qml`

**修改前（内联弹窗）**：
```qml
Loader {
    id: settingsDialogLoader
    anchors.fill: parent
    active: true
    sourceComponent: Component {
        Rectangle {
            id: settingsDialog
            // ... 大量内联代码 ...
            Rectangle {
                // 弹窗内容
                Column {
                    // 标题栏
                    // 参数内容区域（占位符）
                }
            }
        }
    }
}
```

**修改后（使用现有组件）**：
```qml
// ✅ 2026-01-24 [FIX] 使用现有的 DeviceSettingsDialog.qml 组件
Rectangle {
    id: dialogOverlay
    anchors.fill: parent
    color: "#80000000"  // 半透明黑色背景
    visible: false
    z: 1000

    focus: visible

    Keys.onEscapePressed: {
        dialogOverlay.visible = false
    }

    Keys.onPressed: {
        event.accepted = true
    }

    MouseArea {
        anchors.fill: parent
        onClicked: dialogOverlay.visible = false
    }

    // ✅ 使用现有的 DeviceSettingsDialog 组件
    Loader {
        id: settingsDialogLoader
        anchors.centerIn: parent
        width: Math.min(parent.width * 0.9, 1200)
        height: Math.min(parent.height * 0.9, 800)
        active: dialogOverlay.visible
        source: "qrc:/qt/qml/BeltControlQml/components/device_info/DeviceSettingsDialog.qml"

        onLoaded: {
            if (item) {
                console.log("✅ [Input1Page] DeviceSettingsDialog 加载成功")
                item.deviceId = dialogOverlay.deviceId
                item.deviceName = dialogOverlay.deviceName
            }
        }

        onStatusChanged: {
            if (settingsDialogLoader.status === Loader.Error) {
                console.error("❌ [Input1Page] DeviceSettingsDialog 加载失败")
            }
        }
    }

    property int deviceId: 1
    property string deviceName: ""
}

property alias settingsDialog: dialogOverlay
```

**关键变更**：
1. **外层容器**：dialogOverlay（半透明背景 + 焦点管理）
2. **内层 Loader**：加载现有的 DeviceSettingsDialog.qml
3. **属性传递**：通过 dialogOverlay.deviceId 和 deviceName 传递
4. **焦点管理**：保留 Escape 键和事件捕获
5. **点击背景关闭**：保留用户体验

**DeviceSettingsDialog.qml 特性**：
- ✅ 背景图片：`images/deviceInfo40.png`
- ✅ 顶部按钮：关闭、保存、重置
- ✅ 左侧类别：基本参数、运行参数、报警设置、高级设置、其他
- ✅ 中间内容区域：参数显示和编辑

## 4. 技术亮点

### 4.1 组件复用

**优势**：
- ✅ 使用现有的 DeviceSettingsDialog.qml 组件
- ✅ 避免重复代码
- ✅ 保持一致的 UI 风格
- ✅ 易于维护和扩展

**对比**：
- ❌ 内联弹窗：代码重复，难以维护
- ✅ 组件复用：单一职责，易于测试

### 4.2 Loader 动态加载

**实现**：
```qml
Loader {
    active: dialogOverlay.visible  // 仅在可见时加载
    source: "qrc:/qt/qml/BeltControlQml/components/device_info/DeviceSettingsDialog.qml"

    onLoaded: {
        // 加载完成后设置属性
        item.deviceId = dialogOverlay.deviceId
        item.deviceName = dialogOverlay.deviceName
    }
}
```

**优势**：
- ✅ 延迟加载：弹窗不可见时不占用资源
- ✅ 属性传递：通过 onLoaded 设置组件属性
- ✅ 错误处理：onStatusChanged 捕获加载失败

### 4.3 焦点管理层次

**架构**：
```
dialogOverlay (外层)
├── focus: visible
├── Keys.onEscapePressed
├── Keys.onPressed (捕获所有事件)
└── Loader (内层)
    └── DeviceSettingsDialog
```

**优势**：
- ✅ 外层捕获键盘事件，防止传播到背景
- ✅ 内层组件专注于业务逻辑
- ✅ 清晰的职责分离

## 6. 可能的问题和解决方案

### 6.1 问题：设备数组仍然为 null

**可能原因**：
1. Screen01.ui.qml 中的设备 ID 名称不匹配
2. 设备组件未正确导出
3. Loader 加载时机问题

**解决方案**：
1. 检查 Screen01.ui.qml 中的设备 ID（device1, device2, ...）
2. 确认设备组件是 MyIN_Data 类型
3. 在 onLoaded 中添加延迟初始化

### 6.2 问题：弹窗加载失败

**可能原因**：
1. DeviceSettingsDialog.qml 路径错误
2. 组件未注册到 QML 模块
3. CMakeLists.txt 未包含该文件

**解决方案**：
1. 验证路径：`qrc:/qt/qml/BeltControlQml/components/device_info/DeviceSettingsDialog.qml`
2. 检查 CMakeLists.txt 是否包含 DeviceSettingsDialog.qml
3. 查看日志中的加载错误信息

### 6.3 问题：图片切换仍然不工作

**可能原因**：
1. 图片路径错误
2. State 系统未触发
3. isSelected 属性未正确绑定

**解决方案**：
1. 验证图片文件存在：`src/qml/Input1/Input1Content/images/IN_Data.png` 和 `IN_Data_OK.png`
2. 在 MyIN_Data.ui.qml 中添加 onIsSelectedChanged 日志（需要转为 .qml）
3. 检查 PropertyChanges 是否正确应用
