## 🎯 问题描述

**用户反馈**:
"使用导航键打开虚拟键盘关闭一切正常，当再次使用鼠标点击当前的焦点，使用导航键就混乱了。例如在模块地址，出现问题后，导航键向下应该是焦点在反馈通道，但是实际上没有，按第二次下键是导航键出现在添加输入上了"

**测试场景**:
1. 使用方向键导航到"模块地址"（索引 2）
2. 按回车键打开虚拟键盘 → 按 ESC 关闭 ✅
3. 鼠标点击"模块地址"（当前焦点）
4. 按下键 → 焦点到"反馈通道"（索引 4）✅
5. 再按下键 → **焦点应该保持在反馈通道或移动到下一个参数，但实际上跳到了"添加输入"按钮** ❌

**❌ 问题**：
1. 鼠标点击时，`focusParamIndex` 已经是 2，所以没有触发变化
2. **NavigationManager.paramIndex 没有同步更新**（仍然是旧值）
3. 第一次按下键：NavigationManager 从索引 2 计算 → 4（正确）
4. 第二次按下键：NavigationManager 从索引 4 计算，认为已经到达 `lastParamIndex=4`（基本配置的最后一个参数），所以切换到按钮区域（D）

## 🔍 根本原因

### 单向同步问题

**当前实现**（MotorControlPage Line 100-104）:
```qml
// 监听 NavigationManager.paramIndex 变化 → 更新 focusParamIndex
onParamIndexChanged: {
    console.log("✅ [MotorControlPage] 参数索引变化:", paramIndex)
    root.focusParamIndex = paramIndex  // ✅ 单向同步：NavigationManager → focusParamIndex
}
```

**问题**：
- 只有 NavigationManager → focusParamIndex 的单向同步
- 没有 focusParamIndex → NavigationManager 的反向同步
- 鼠标点击更新 `focusParamIndex` 时，NavigationManager 不知道

### 导航逻辑（NavigationManager Line 176-192）

```qml
function moveInParamArea(direction) {
    var newIndex = paramIndex  // ❌ 使用旧的 paramIndex

    switch(direction) {
    case "Down":
        var nextIndex = paramIndex + 2  // 两列布局，下键 +2

        if (nextIndex > lastParamIndex) {  // ❌ 4 + 2 = 6 > 4
            // 超出范围，进入底部按钮区
            switchToArea(areaButtons)  // ❌ 错误地切换到按钮区域
            buttonIndex = 0
            return
        }
        // ...
    }
}
```

**问题**：
- NavigationManager 使用旧的 `paramIndex` 计算下一个索引
- 鼠标点击后，`paramIndex` 没有同步更新
- 导致导航逻辑基于错误的起始索引计算

## 🔧 解决方案

### 添加双向同步

**文件**: `src/qml/components/device_info/pages/MotorControlPage.qml`

**修改位置**: Line 33-46

**修改前**:
```qml
// ✅ 2026-02-02 [FIX 100.300.112.8.24.5]: 监听 focusParamIndex 变化
onFocusParamIndexChanged: {
    console.log("🔶 [MotorControlPage] focusParamIndex 变化:", focusParamIndex)
    console.log("  - focusSubArea:", focusSubArea)
    console.log("  - navigationManager.paramIndex:", navigationManager.paramIndex)
    console.log("  - navigationManager.currentArea:", navigationManager.currentArea)
    // ❌ 没有同步 NavigationManager.paramIndex
}
```

**修改后**:
```qml
// ✅ 2026-02-02 [FIX 100.300.112.8.24.5]: 监听 focusParamIndex 变化
// ✅ 2026-02-02 [FIX 100.300.112.8.24.6]: 双向同步 - focusParamIndex 变化时也要更新 NavigationManager
onFocusParamIndexChanged: {
    console.log("🔶 [MotorControlPage] focusParamIndex 变化:", focusParamIndex)
    console.log("  - focusSubArea:", focusSubArea)
    console.log("  - navigationManager.paramIndex:", navigationManager.paramIndex)
    console.log("  - navigationManager.currentArea:", navigationManager.currentArea)

    // ✅ 双向同步：当 focusParamIndex 变化时，同步更新 NavigationManager 的 paramIndex
    if (focusSubArea === 2 && navigationManager.currentArea === "C" && navigationManager.paramIndex !== focusParamIndex) {
        console.log("🔶 [MotorControlPage] 同步 NavigationManager.paramIndex:", navigationManager.paramIndex, "→", focusParamIndex)
        navigationManager.paramIndex = focusParamIndex
    }
}
```

---

## 💡 关键修改点

### 1. 双向同步条件

```qml
if (focusSubArea === 2 && navigationManager.currentArea === "C" && navigationManager.paramIndex !== focusParamIndex)
```

**条件说明**:
- `focusSubArea === 2`: 当前在参数区域
- `navigationManager.currentArea === "C"`: NavigationManager 也在参数区域
- `navigationManager.paramIndex !== focusParamIndex`: 两者不一致，需要同步

### 2. 同步操作

```qml
navigationManager.paramIndex = focusParamIndex
```

**效果**:
- 将 NavigationManager 的 `paramIndex` 更新为 `focusParamIndex`
- 确保两者状态一致
- 下次导航时使用正确的起始索引

## 🎯 修复效果

### 修复前

```
1. 鼠标点击模块地址（索引 2）
   - focusParamIndex = 2 ✅
   - NavigationManager.paramIndex = 旧值（可能是 0 或其他）❌

2. 第一次按下键
   - NavigationManager 从旧值计算 → 可能正确到达索引 4 ✅

3. 第二次按下键
   - NavigationManager 从索引 4 计算
   - 4 + 2 = 6 > lastParamIndex(4)
   - 切换到按钮区域 ❌
```

### 修复后

```
1. 鼠标点击模块地址（索引 2）
   - focusParamIndex = 2 ✅
   - 触发 onFocusParamIndexChanged
   - 同步 NavigationManager.paramIndex = 2 ✅

2. 第一次按下键
   - NavigationManager 从索引 2 计算
   - 2 + 2 = 4 ≤ lastParamIndex(4)
   - 移动到索引 4（反馈通道）✅

3. 第二次按下键
   - NavigationManager 从索引 4 计算
   - 4 + 2 = 6 > lastParamIndex(4)
   - 切换到按钮区域 ✅（这是正确的行为）
```
