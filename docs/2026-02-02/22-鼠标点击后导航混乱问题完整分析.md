## 🔍 关键发现

### 发现 1：导航逻辑是正确的

基本配置（BasicConfigTab）有 5 个参数（索引 0-4）：
- 索引 0: 电机编号（左列，第1行）
- 索引 1: 电机类型（右列，第1行）
- 索引 2: 模块地址（左列，第2行）
- 索引 3: 输出通道（右列，第2行）
- 索引 4: 反馈通道（左列，第3行）

**GridLayout 两列布局，下键导航规则**：
- 左列（偶数索引）：0 → 2 → 4 → 按钮区域
- 右列（奇数索引）：1 → 3 → 按钮区域

**当焦点在索引 2（模块地址）时**：
- 按下键 → 到索引 4（反馈通道）✅
- 再按下键 → 索引 4 是左列最后一个，切换到按钮区域 ✅

## 💡 根本原因推测

### 推测 1：Connections 的 target 失效

鼠标点击后，`root` 的焦点状态可能发生了变化，导致 `Connections` 的 `target: root` 失效。

**证据**：
- Line 290-291：点击前 `root.focus: true`, `root.activeFocus: true`
- Line 295-296：点击后 `root.focus: true`, `root.activeFocus: true`
- **root 的焦点状态没有变化**

**结论**：这个推测不成立。

### 推测 2：onFocusParamIndexChanged 触发时机问题

可能 `onFocusParamIndexChanged` 触发了，但是在 `Connections` 的回调函数执行时，`root.focusParamIndex` 还没有更新为 4。

**证据**：
- Line 303：`🔶 [MotorControlPage] focusParamIndex 变化: 4`
- 这个日志是在 MotorControlPage 的 `onFocusParamIndexChanged` 中输出的
- BasicConfigTab 的 `Connections` 应该也会收到这个变化

**结论**：这个推测也不太可能，因为 QML 的属性绑定是同步的。

### 推测 3：日志输出被截断或延迟

可能焦点指示器的日志输出了，但是被截断或延迟了。

**证据**：
- 日志文件可能有缓冲
- 用户可能在日志完全输出前就停止了测试

**结论**：需要用户重新测试，确认日志是否完整。

### 推测 4：BasicConfigTab 的 root 不是 MotorControlPage

可能 `Connections` 的 `target: root` 指向的不是 MotorControlPage，而是 BasicConfigTab 自己。

**证据**：
- BasicConfigTab 是一个独立的 QML 组件
- `root` 是 BasicConfigTab 的根元素
- `root.focusParamIndex` 是 BasicConfigTab 的属性

**检查代码**：

BasicConfigTab.qml Line 1-20：
```qml
Item {
    id: root
    property int motorIndex: 0
    property int focusParamIndex: 0  // ✅ 这是 BasicConfigTab 的属性
    // ...
}
```

MotorControlPage.qml Line 30：
```qml
property int focusParamIndex: 0  // ✅ 这是 MotorControlPage 的属性
```

**问题**：
- BasicConfigTab 有自己的 `focusParamIndex` 属性
- MotorControlPage 也有自己的 `focusParamIndex` 属性
- **它们是两个不同的属性！**

**检查 BasicConfigTab 如何被加载**：

需要查看 MotorControlPage 如何加载 BasicConfigTab，以及如何传递 `focusParamIndex`。
