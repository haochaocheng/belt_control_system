# 鼠标点击后导航混乱问题 - 最终完成总结

## 🎯 问题回顾

**用户反馈**：
"使用导航键打开虚拟键盘关闭一起正常，当再次使用鼠标点击当前的焦点，使用导航键就混乱了。例如再模块地址，出现问题后，导航键向下应该是焦点再反馈通道，但是实际上没有，按第二次下键是导航键出现再添加输入上了"

**测试场景**：
1. 使用键盘导航到"模块地址"（索引 2）
2. 按回车键打开虚拟键盘 → 按 ESC 关闭 ✅
3. 鼠标点击"模块地址"（当前焦点）
4. 按下键 → **焦点应该到"反馈通道"（索引 4），但焦点指示器不显示** ❌
5. 再按下键 → 焦点跳到"添加输入"按钮

---

## 🔍 根本原因

通过深度分析日志（pjsip.md），发现：

1. **Qt.binding 被打破**：
   - BasicConfigTab 的 MouseArea 中 `root.focusParamIndex = 2` 直接赋值
   - 这个操作打破了 Qt.binding
   - 之后 MotorControlPage 的 focusParamIndex 变化不再传递到 BasicConfigTab
   - 导致焦点指示器不再更新

2. **证据**：
   - Line 281：鼠标点击前，BasicConfigTab 正常收到 focusParamIndex 变化
   - Line 292-303：鼠标点击，直接赋值 `root.focusParamIndex = 2`
   - Line 304-320：之后的导航，BasicConfigTab 不再收到 focusParamIndex 变化

---

## 🔧 解决方案

### 方案：信号通知机制

**原理**：
- 不在子组件（BasicConfigTab）中直接修改 focusParamIndex
- 使用信号机制通知父组件（MotorControlPage）
- 父组件更新 NavigationManager.paramIndex
- 保持 Qt.binding 完整，确保属性正确传递

### 实施步骤

#### 1. BasicConfigTab.qml

**添加信号**：
```qml
signal requestFocusParamIndex(int paramIndex)
```

**修改 MouseArea**（3个）：
```qml
MouseArea {
    anchors.fill: parent
    onClicked: function(mouse) {
        console.log("✅ [BasicConfigTab] 鼠标点击模块地址，发射信号: requestFocusParamIndex(2)")
        root.requestFocusParamIndex(2)  // ✅ 发射信号，而不是直接赋值
        mouse.accepted = false
    }
}
```

#### 2. MotorConfigPanel.qml

**添加信号**：
```qml
signal requestFocusParamIndex(int paramIndex)
```

**连接 BasicConfigTab 信号**：
```qml
onLoaded: {
    if (item) {
        item.focusParamIndex = Qt.binding(function() { return root.focusParamIndex })

        // ✅ 连接信号，转发到父组件
        item.requestFocusParamIndex.connect(function(paramIndex) {
            root.requestFocusParamIndex(paramIndex)
        })
    }
}
```

#### 3. MotorControlPage.qml

**连接 MotorConfigPanel 信号**：
```qml
onLoaded: {
    item.focusParamIndex = Qt.binding(function() { return root.focusParamIndex })

    // ✅ 连接信号，更新 NavigationManager
    item.requestFocusParamIndex.connect(function(paramIndex) {
        console.log("✅ [MotorControlPage] 接收信号: requestFocusParamIndex(" + paramIndex + ")")
        navigationManager.paramIndex = paramIndex
    })
}
```

## 🔄 信号流程

```
1. 用户鼠标点击模块地址
   ↓
2. BasicConfigTab.MouseArea 发射信号: requestFocusParamIndex(2)
   ↓
3. MotorConfigPanel 接收信号，转发: requestFocusParamIndex(2)
   ↓
4. MotorControlPage 接收信号，更新: NavigationManager.paramIndex = 2
   ↓
5. NavigationManager.paramIndex 变化 → MotorControlPage.focusParamIndex 变化
   ↓
6. MotorControlPage.focusParamIndex 变化 → BasicConfigTab.focusParamIndex 变化（通过 Qt.binding）
   ↓
7. BasicConfigTab.focusParamIndex 变化 → 焦点指示器显示
```

## 💡 关键经验教训

### 1. Qt.binding 的脆弱性

**问题**：
- Qt.binding 通过 `Qt.binding(function() { return ... })` 创建
- 一旦在子组件中直接赋值，绑定就会被永久打破
- 之后父组件的属性变化不再传递到子组件

**解决方案**：
- 子组件不应该直接修改通过 Qt.binding 传递的属性
- 使用信号机制通知父组件，由父组件更新属性
- 保持单向数据流：父组件 → 子组件

### 2. 调试日志的重要性

**经验**：
- 详细的调试日志帮助我们快速定位问题
- 通过日志对比（鼠标点击前后），发现了 Qt.binding 被打破的证据
- 日志应该包含：属性变化、信号发射、函数调用等关键信息

### 3. 信号机制的优势

**优势**：
- 解耦：子组件不需要知道父组件的实现细节
- 灵活：父组件可以自由决定如何处理信号
- 可维护：信号流程清晰，易于理解和调试
