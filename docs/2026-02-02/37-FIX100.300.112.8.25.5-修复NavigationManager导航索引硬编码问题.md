## 🎯 问题描述

用户反馈：**导航键从电流下限（索引8）直接跳到底部按钮区域，跳过了输入点选择（索引9）和过滤干扰延时（索引10）**

**根本原因**：
NavigationManager 中硬编码了参数数量为9个（索引0-8），导致：
1. `lastParamIndex` 硬编码为8
2. 右键导航判断 `paramIndex < 8` 硬编码
3. Tab切换时硬编码更新 `lastParamIndex = 8`

这导致电流保护Tab的11个参数（索引0-10）无法正确导航。

## 💡 设计说明

### 为什么使用动态更新而不是硬编码？

1. **灵活性**：
   - 不同Tab可以有不同数量的参数
   - 未来添加新Tab或修改参数数量时，不需要修改NavigationManager

2. **可维护性**：
   - 参数数量由Tab自己管理（`getParamFieldCount()`）
   - NavigationManager只负责导航逻辑，不关心具体参数数量

3. **正确性**：
   - 避免硬编码导致的索引不匹配问题
   - 确保导航范围与实际参数数量一致

### 为什么使用Qt.callLater()？

```qml
Qt.callLater(function() {
    var paramCount = root.getParamFieldCount()
    if (paramCount > 0) {
        navigationManager.updateLastParamIndex(paramCount)
    }
})
```

**原因**：
- Tab切换是异步的，需要等待Tab加载完成
- `Qt.callLater()` 确保在下一个事件循环中执行，此时Tab已经加载完成
- 可以正确获取新Tab的参数数量
