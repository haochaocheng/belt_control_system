## 💡 技术要点

### 1. 数据库设计原则
- **外键约束**: 所有配置表都使用 `FOREIGN KEY` 关联到 `devices` 表
- **级联删除**: `ON DELETE CASCADE` 确保删除设备时自动删除相关配置
- **唯一约束**: `UNIQUE(device_id, motor_index, tab_index)` 防止重复记录
- **索引优化**: 为常用查询字段创建索引，提高查询性能

### 2. Q_INVOKABLE 方法
- 所有公开方法都使用 `Q_INVOKABLE` 宏，使其可以从 QML 调用
- 参数使用 `QVariantMap` 传递，灵活且易于扩展
- 返回值使用 `QVariantMap` 或 `QVariantList`，方便 QML 处理

### 3. Qt.callLater() 的使用
- 在切换电机/Tab时使用 `Qt.callLater(root.loadMotorConfig)` 延迟加载配置
- 原因：确保 UI 组件已经完全切换完成后再加载配置
- 避免在组件切换过程中访问未初始化的控件

### 4. collectConfig() 和 applyConfig() 的设计
- **collectConfig()**: 从 UI 控件收集参数值，返回 QVariantMap
- **applyConfig()**: 将参数值应用到 UI 控件
- 每个 Tab 组件独立实现这两个方法，保持模块化
