# 电机配置界面与串口控制界面对比分析

## 📋 分析目的

对比**电机配置界面（MotorControlPage）**和**串口控制界面（SerialPortControlPage）**，找出为什么电机配置界面的焦点导航正常工作，而串口控制界面的焦点会立即丢失。

**用户关键线索**：
> "电机配置界面也是使用滚动，但是没有问题，那个只有弹窗虚拟键盘，界面才会滚动"

---

## 🔍 核心差异对比

### 1. 焦点元素类型差异

#### 电机配置界面（MotorControlPage）

**参数区域不使用 Text 元素作为焦点元素！**

从 MotorControlPage.qml 的代码结构看：
- 使用 `Loader` 加载 `MotorConfigPanel.qml`
- MotorConfigPanel 再加载各个 Tab（BasicConfigTab, CurrentProtectionTab 等）
- **每个 Tab 使用 GridLayout（4列）布局**
- **焦点元素类型**：
  - TextField（可编辑文本）
  - SpinBox（数字输入）
  - ComboBox（下拉选择）
  - **没有使用 Text 元素作为焦点元素！**

**关键代码**（MotorControlPage.qml line 422-448）：
```qml
Loader {
    id: motorConfigPanel
    width: parent.width - motorListPanel.width - 2
    height: parent.height
    source: "MotorConfigPanel.qml"

    onLoaded: {
        item.motorIndex = Qt.binding(function() { return root.currentMotorIndex })
        item.focusSubArea = Qt.binding(function() { return root.focusSubArea })
        item.focusTabIndex = Qt.binding(function() { return root.focusTabIndex })
        item.focusParamIndex = Qt.binding(function() { return root.focusParamIndex })
        item.virtualKeyboard = Qt.binding(function() { return root.virtualKeyboard })
    }
}
```

#### 串口控制界面（SerialPortControlPage）

**参数区域使用 Text 元素作为焦点元素！**

从 SerialPortParamsSection.qml 的代码结构看：
- 使用 GridLayout（4列）布局
- **焦点元素类型**：
  - **Text（只读显示）** ← ❌ 问题所在！
  - ComboBox（可编辑）
  - Button（操作按钮）

**关键代码**（SerialPortParamsSection.qml line 199-258）：
```qml
// 串口名称值（只读）
Item {
    Layout.column: 1
    Layout.row: 0
    Layout.fillWidth: true

    Layout.preferredHeight: 40

            id: serialNameFocusIndicator

            anchors.margins: -4

            border.color: parent.activeFocus ? "#2196F3" : "transparent"
            border.width: parent.activeFocus ? 3 : 0
            radius: 4
            z: 10
        }
    }
}
```

### 2. ScrollView 使用差异

#### 电机配置界面（MotorControlPage）

**MotorConfigPanel 内部使用 ScrollView**

从代码结构推断（未直接看到 MotorConfigPanel.qml 的代码，但从 MotorControlPage 的使用方式推断）：
- MotorConfigPanel 内部可能有 ScrollView
- 但是 **ScrollView 只包裹参数区域**，不包裹整个页面
- **焦点元素（TextField, SpinBox, ComboBox）不会触发 Qt 的自动滚动**
- 用户反馈："只有弹窗虚拟键盘，界面才会滚动"

#### 串口控制界面（SerialPortControlPage）

**SerialPortConfigPanel 使用 ScrollView 包裹所有区域**

从 SerialPortConfigPanel.qml 的代码结构看（根据 system-reminder）：
```qml
ScrollView {
    id: scrollView
    anchors.fill: parent
    clip: true
    ScrollBar.horizontal.policy: ScrollBar.AlwaysOff

    ColumnLayout {
        width: scrollView.width
        spacing: 16

        // SerialPortParamsSection 是第一个子元素
        // SerialPortSendSection
        // SerialPortReceiveSection
        // ModbusRegisterSection
    }
}
```

**关键差异**：
- ScrollView 包裹了 **4个子区域**（参数、发送、接收、MODBUS）
- **contentHeight: 1885**（内容总高度）
- **height: 703**（可见区域高度）
- **contentY: 0**（初始滚动位置）
- **clip: true**（裁剪超出可见区域的内容）

**问题流程**：
1. 用户按右键进入参数区域
2. `serialNameText.forceActiveFocus()` 设置焦点
3. **Qt 检测到焦点元素（Text）在 ScrollView 内**
4. **Qt 自动调用 `ensureVisible()` 或类似方法**
5. **ScrollView 自动滚动使焦点元素可见**
6. **滚动过程中焦点丢失**（contentY: 0 → 1182）

### 3. 焦点元素的 Qt 行为差异

#### TextField / SpinBox / ComboBox（电机配置界面）

**这些是 Qt 的输入控件，设计用于接收焦点**：
- 有内置的焦点管理机制
- 有输入法支持（虚拟键盘）
- **Qt 知道如何正确处理这些控件的焦点**
- **不会触发不必要的自动滚动**

#### Text（串口控制界面）

**Text 是只读显示控件，不是设计用于接收焦点的**：
- 主要用于显示文本
- **没有内置的焦点管理机制**
- **没有输入法支持**
- **Qt 不知道如何正确处理 Text 元素的焦点**
- **可能触发意外的自动滚动行为**

**从日志分析**（docs/log/pjsip.md line 328-334）：
```
line 328: 🔍 [ScrollView] contentY 变化: 189
line 329: 🔍 [ScrollView] contentY 变化: 378
line 330: 🔍 [ScrollView] contentY 变化: 567
line 331: 🔍 [ScrollView] contentY 变化: 756
line 332: 🔍 [ScrollView] contentY 变化: 945
line 333: 🔍 [ScrollView] contentY 变化: 1134
line 334: 🔍 [串口名称] activeFocus 变化: false  ← 焦点丢失！
```

**关键发现**：
- 即使 `interactive: false`，ScrollView 仍然滚动
- 滚动是 **Qt 内部的程序化自动滚动**，不是用户交互滚动
- 这个自动滚动不受 `interactive` 属性控制

## 🎯 根本原因总结

### 电机配置界面为什么正常工作？

1. ✅ **使用正确的焦点元素类型**（TextField, SpinBox, ComboBox）
2. ✅ **Qt 知道如何处理这些控件的焦点**
3. ✅ **不会触发不必要的自动滚动**
4. ✅ **只有虚拟键盘弹出时才滚动**（用户反馈）

### 串口控制界面为什么失败？

1. ❌ **使用错误的焦点元素类型**（Text）
2. ❌ **Text 不是设计用于接收焦点的**
3. ❌ **Qt 不知道如何正确处理 Text 元素的焦点**
4. ❌ **触发 Qt 的自动滚动机制**（ensureVisible）
5. ❌ **ScrollView 自动滚动导致焦点丢失**

## 💡 解决方案

### 方案 1: 将 Text 改为 TextField（readOnly: true）✅ 推荐

**优点**：
- TextField 是 Qt 设计用于接收焦点的控件
- 有内置的焦点管理机制
- 不会触发不必要的自动滚动
- 可以设置 `readOnly: true` 保持只读状态
- 与电机配置界面一致

**缺点**：
- 需要修改 4 个参数字段
- 需要调整样式以匹配 Text 的外观

**实施步骤**：
1. 将 `serialNameText` 从 Text 改为 TextField
2. 设置 `readOnly: true`
3. 调整样式（背景透明，边框透明）
4. 对 `devicePathText`、`serialTypeText`、`statusText` 做同样的修改

### 方案 2: 移除 ScrollView ❌ 不推荐

**优点**：
- 彻底解决 ScrollView 自动滚动问题

**缺点**：
- 如果内容超出可见区域，无法滚动查看
- 不符合用户需求（可能需要滚动查看发送、接收、MODBUS区域）

### 方案 3: 使用 Flickable 替代 ScrollView ❌ 不推荐

**优点**：
- Flickable 的行为更可控

**缺点**：
- 需要重新实现滚动条
- 复杂度高
- 不一定能解决问题

### 方案 4: 禁用 Text 元素的焦点，跳过只读字段 ❌ 不推荐

**优点**：
- 简单

**缺点**：
- 用户无法导航到只读字段
- 不符合用户需求（用户可能想查看只读字段的值）

## 💡 经验教训

### 1. 选择正确的焦点元素类型

- ✅ 使用 Qt 设计用于接收焦点的控件（TextField, SpinBox, ComboBox, Button）
- ❌ 不要使用只读显示控件（Text, Label）作为焦点元素

### 2. 理解 Qt 的焦点系统

- Qt 的焦点系统会自动调用 `ensureVisible()` 使焦点元素可见
- 这个自动滚动不受 `interactive` 属性控制
- 只有使用正确的焦点元素类型，Qt 才能正确处理焦点

- 不要盲目修复，先对比正常工作的实现
