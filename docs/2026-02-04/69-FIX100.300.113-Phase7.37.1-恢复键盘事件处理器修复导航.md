## 📋 任务概述

**目标**: 恢复SerialPortControlPage.qml中的完整键盘事件处理器，修复导航功能

**原因**: Phase 5.4中错误地移除了Keys.onUpPressed/onDownPressed/onRightPressed，导致导航功能失效

**用户反馈**: "串口控制得导航控制还有问题，现在导航就有问题"

---

## 🔍 问题分析

### 问题发现

**对比分析**：
- ✅ **MotorControlPage.qml**：有完整的键盘事件处理器
- ❌ **SerialPortControlPage.qml**：缺少上下右键处理器

**根本原因**：
在Phase 5.4中，SerialPortControlPage.qml的第224-227行有注释：
```qml
// ✅ 2026-02-04 [FIX 100.300.113 Phase 5.4]: 移除 Keys.onUpPressed/onDownPressed/onRightPressed
// 原因：这些处理器会在鼠标点击后拦截导航键事件，导致 DeviceSettingsDialog 的导航逻辑被绕过
// 解决方案：完全依赖 DeviceSettingsDialog 的默认处理 + Connections 同步
// 参考：SwitchInputPage 和 AnalogInputPage 的实现
```

**错误判断**：
- Phase 5.4的判断是错误的
- 串口控制页面需要完整的键盘事件处理器
- 应该参考MotorControlPage.qml的实现，而不是SwitchInputPage

## 💡 技术要点

### 为什么需要isReturningToCategory标志

**问题**：
- 左键返回类别时，可能触发事件循环
- DeviceSettingsDialog接收到requestReturnToCategory信号后，可能再次触发键盘事件

**解决方案**：
```qml
Keys.onLeftPressed: function(event) {
    if (isReturningToCategory) {
        event.accepted = true
        return
    }
    if (navigationManager.currentArea === navigationManager.areaMotorList) {
        root.isReturningToCategory = true
        root.requestReturnToCategory()
        resetFlagTimer.start()
        event.accepted = true
    }
}
```

**效果**：
- ✅ 设置`isReturningToCategory = true`
- ✅ 发送`requestReturnToCategory()`信号
- ✅ 启动定时器，100ms后重置标志
- ✅ 防止事件循环

### 为什么需要keysEnabled标志

**问题**：
- 页面失去焦点后，键盘事件可能仍然被触发
- 导致导航混乱

**解决方案**：
```qml
onActiveFocusChanged: {
    if (activeFocus) {
        keysEnabled = true
    }
}

Keys.onUpPressed: {
    if (!keysEnabled || isReturningToCategory) {
        event.accepted = true
        return
    }
    // ...
}
```

**效果**：
- ✅ 页面获得焦点时，启用键盘事件
- ✅ 页面失去焦点时，禁用键盘事件
- ✅ 防止导航混乱

### 为什么需要event.accepted = true

**问题**：
- 如果不设置`event.accepted = true`，事件会继续传播
- 可能被父组件处理，导致意外行为

**解决方案**：
```qml
Keys.onUpPressed: {
    if (!keysEnabled || isReturningToCategory) {
        event.accepted = true  // ✅ 阻止事件传播
        return
    }
    navigationManager.handleDirectionKey("Up")
    event.accepted = true  // ✅ 阻止事件传播
}
```

**效果**：
- ✅ 阻止事件传播到父组件
- ✅ 确保事件只被当前组件处理
