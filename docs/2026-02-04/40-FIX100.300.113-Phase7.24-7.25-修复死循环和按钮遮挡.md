## 🔍 问题 1：死循环导致导航失效

### 日志分析

```
Debug: ⚠️ [CustomComboBox] 检测到键盘导航修改索引: 4 → 恢复为: 3
Debug: ⚠️ [CustomComboBox] 检测到键盘导航修改索引: 3 → 恢复为: 3
Debug: ⚠️ [CustomComboBox] 检测到键盘导航修改索引: 4 → 恢复为: 3
Debug: ⚠️ [CustomComboBox] 检测到键盘导航修改索引: 3 → 恢复为: 3
... (无限循环)
```

### 根本原因

**Phase 7.22 的实现导致死循环**：

```qml
onCurrentIndexChanged: {
    if (!isUserAction && root.activeFocus) {
        // 恢复原值
        root.currentIndex = savedIndex  // ❌ 这会再次触发 onCurrentIndexChanged
    } else {
        savedIndex = currentIndex
    }
}
```

**问题流程**：
1. 用户按上键 → ComboBox 修改 currentIndex (3 → 4)
2. onCurrentIndexChanged 触发 → 检测到键盘导航
3. 恢复原值：currentIndex (4 → 3)
4. **❌ 恢复操作又触发 onCurrentIndexChanged**
5. 再次检测到变化 → 再次恢复
6. **无限循环**

**为什么导航失效**：
- 死循环占用了所有 CPU 资源
- 事件循环被阻塞
- 导航事件无法被处理

## ✅ 修复方案 1：Phase 7.24

### 核心思路

**添加 `isRestoring` 标志，防止递归触发。**

### 实现代码

**文件**: CustomComboBox.qml

**修改前**（Phase 7.22）:
```qml
property int savedIndex: currentIndex
property bool isUserAction: false

onCurrentIndexChanged: {
    if (!isUserAction && root.activeFocus) {
        // 恢复原值
        root.currentIndex = savedIndex  // ❌ 会再次触发 onCurrentIndexChanged
    } else {
        savedIndex = currentIndex
    }
}
```

**修改后**（Phase 7.24）:
```qml
property int savedIndex: currentIndex
property bool isUserAction: false
property bool isRestoring: false  // ✅ 新增：防止递归标志

onCurrentIndexChanged: {
    if (isRestoring) {
        // ✅ 正在恢复索引，不要再次触发
        return
    }

    if (!isUserAction && root.activeFocus) {
        // 恢复原值
        console.log("⚠️ [CustomComboBox] 检测到键盘导航修改索引:", currentIndex, "→ 恢复为:", savedIndex)
        isRestoring = true  // ✅ 设置恢复标志
        root.currentIndex = savedIndex
        isRestoring = false  // ✅ 重置恢复标志
    } else {
        savedIndex = currentIndex
    }
}
```

**关键变化**：
1. 添加 `isRestoring` 标志
2. 在恢复前设置标志为 true
3. 在 onCurrentIndexChanged 开始时检查标志
4. 如果正在恢复，直接返回，不再处理
5. 恢复完成后重置标志为 false

## 🔍 问题 2：按钮被发送区遮挡

### 根本原因

**SerialPortConfigPanel 的布局问题**：

```qml
// SerialPortConfigPanel.qml
ColumnLayout {
    // 1. 串口参数配置区
    Loader {
        id: paramsSection
        Layout.preferredHeight: 300  // ❌ 高度不够
    }

    // 2. 发送区
    Loader {
        id: sendSection
        Layout.preferredHeight: 380
    }
}
```

**高度计算**：
- 第1行（串口名称/波特率）: 60px
- 第2行（设备路径/数据位）: 60px
- 第3行（串口类型/停止位）: 60px
- 第4行（校验位/状态）: 60px
- 第5行（打开/关闭按钮）: 60px
- 行间距 (4个): 12px × 4 = 48px
- 上下边距: 16px × 2 = 32px
- **总计**: 60×5 + 48 + 32 = **380px**

**问题**：
- SerialPortParamsSection 需要 380px
- 但是 SerialPortConfigPanel 只给了 300px
- 导致第5行（打开/关闭按钮）被裁剪
- 发送区紧接着显示，遮挡了按钮

## 💡 工作原理详解

### Phase 7.24：防止递归的工作流程

```
用户按上键
↓
Qt ComboBox 内部处理：currentIndex: 3 → 4
↓
onCurrentIndexChanged 触发
↓
检查：isRestoring = false（✅ 不是恢复操作）
↓
检查：isUserAction = false, activeFocus = true（✅ 是键盘导航）
↓
设置：isRestoring = true
↓
恢复：currentIndex: 4 → 3
↓
onCurrentIndexChanged 再次触发
↓
检查：isRestoring = true（✅ 正在恢复）
↓
返回：不再处理（✅ 防止递归）
↓
重置：isRestoring = false
↓
结果：参数值没有改变，焦点移动到上一个参数
```

## 📝 经验教训

### 1. 属性变化监听的递归陷阱

**错误做法**：
```qml
onPropertyChanged: {
    property = newValue  // ❌ 会再次触发 onPropertyChanged
}
```

**正确做法**：
```qml
property bool isUpdating: false

onPropertyChanged: {
    if (isUpdating) return  // ✅ 防止递归
    isUpdating = true
    property = newValue
    isUpdating = false
}
```

### 2. 布局高度计算的重要性

**错误做法**：
- 随意设置高度
- 不考虑内容实际需要的空间

**正确做法**：
- 计算所有子元素的高度
- 加上边距和间距
- 留出适当的缓冲空间

用户提示：
