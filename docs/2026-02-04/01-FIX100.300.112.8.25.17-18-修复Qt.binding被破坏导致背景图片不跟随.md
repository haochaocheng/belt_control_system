> "pjsip.md测试完成，背景图片不跟随蓝色边框移动。今天是2月4日"

### 日志分析

从 `docs/log/pjsip.md` 的日志（Line 237-246）来看：

```

238: 🔍 [BrakeListPanel] currentBrakeIndex 变化: 7  ← 问题在这里！
239: 🔍 [BrakeControlPage] 鼠标点击制动器: 7
```

**关键问题**：
- **Line 238**：`currentBrakeIndex` 直接从 1 跳到 7
- **Line 239**：然后才发射 `brakeSelected` 信号
- 这说明 **MouseArea 中直接赋值了 `currentBrakeIndex`**

### 根本原因

**Qt.binding() 被破坏**：

1. **BrakeControlPage.qml Line 382**：
   ```qml
   item.currentBrakeIndex = Qt.binding(function() { return navigationManager.brakeListIndex })
   ```
   这行代码建立了绑定：`currentBrakeIndex` ← `navigationManager.brakeListIndex`

2. **BrakeListPanel.qml Line 187**（旧代码）：
   ```qml
   MouseArea {
       onClicked: {
           root.currentBrakeIndex = index  // ❌ 直接赋值破坏了绑定！
           root.brakeSelected(index)
       }
   }
   ```

3. **问题流程**：
   ```
   鼠标点击8号制动器
       ↓
   MouseArea.onClicked 触发
       ↓
   root.currentBrakeIndex = 7  ← ❌ 直接赋值，破坏 Qt.binding()
       ↓
   发射 brakeSelected(7) 信号
       ↓
   BrakeControlPage 更新 navigationManager.brakeListIndex = 7
       ↓
   ❌ 但是 currentBrakeIndex 不再跟随 navigationManager.brakeListIndex ❌
       ↓
   按上下键
       ↓
   navigationManager.brakeListIndex 更新（7 → 6 → 5...）
       ↓
   ❌ currentBrakeIndex 不更新（仍然是 7）❌
       ↓
   蓝色边框移动（绑定到 focusItemIndex）✅
   背景图片不动（绑定到 currentBrakeIndex）❌
   ```

## 🔧 解决方案

### 核心原则

**永远不要直接赋值已经通过 Qt.binding() 绑定的属性！**

### 修改内容

#### 1. BrakeListPanel.qml - 移除 MouseArea 中的直接赋值

**旧代码**（Line 187-189）：
```qml
MouseArea {
    onClicked: {
        root.currentBrakeIndex = index  // ❌ 破坏绑定！
        root.brakeSelected(index)
        root.focus = true
    }
}
```

**新代码**（Line 187-193）：
```qml
MouseArea {
    onClicked: {
        // ✅ 2026-02-04 [FIX 100.300.112.8.25.17]: 移除直接赋值，避免破坏 Qt.binding()
        // 旧代码：root.currentBrakeIndex = index  // ❌ 这会破坏绑定！
        // 新方案：只发射信号，让 BrakeControlPage 更新 navigationManager.brakeListIndex
        //        然后通过绑定自动更新 currentBrakeIndex
        root.brakeSelected(index)
        root.focus = true  // 获取焦点以支持键盘操作
    }
}
```

#### 2. BrakeListPanel.qml - 修复键盘导航

**旧代码**（Line 42-54）：
```qml
Keys.onUpPressed: {
    if (root.currentBrakeIndex > 0) {
        root.currentBrakeIndex--  // ❌ 破坏绑定！
        brakeSelected(root.currentBrakeIndex)
    }
}

Keys.onDownPressed: {
    if (root.currentBrakeIndex < 7) {
        root.currentBrakeIndex++  // ❌ 破坏绑定！
        brakeSelected(root.currentBrakeIndex)
    }
}
```

**新代码**（Line 45-67）：
```qml
Keys.onUpPressed: {
    // 新方案：只发射信号，不直接修改 currentBrakeIndex
    if (root.currentBrakeIndex > 0) {
        brakeSelected(root.currentBrakeIndex - 1)
    }
}

Keys.onDownPressed: {
    // 新方案：只发射信号，不直接修改 currentBrakeIndex
    if (root.currentBrakeIndex < 7) {
        brakeSelected(root.currentBrakeIndex + 1)
    }
}
```

#### 3. TensionControlListPanel.qml - 同样的修复

- MouseArea 中移除 `root.currentControlIndex = index`
- Keys.onUpPressed 中移除 `root.currentControlIndex--`
- Keys.onDownPressed 中移除 `root.currentControlIndex++`

## 📊 为什么这个方案有效？

### Qt.binding() 的工作原理

**Qt.binding() 建立单向绑定**：
```qml
item.currentBrakeIndex = Qt.binding(function() { return navigationManager.brakeListIndex })
```

这意味着：
- `currentBrakeIndex` 会自动跟随 `navigationManager.brakeListIndex` 的变化
- **但是**，如果直接赋值 `currentBrakeIndex = 7`，绑定会被破坏
- 之后 `navigationManager.brakeListIndex` 变化时，`currentBrakeIndex` 不再跟随

### 正确的做法

**永远通过绑定的源头更新**：
- ❌ 错误：`currentBrakeIndex = 7`（直接赋值，破坏绑定）
- ✅ 正确：`navigationManager.brakeListIndex = 7`（更新源头，绑定自动生效）

### 信号驱动的架构

**使用信号通信，而不是直接修改属性**：
```
BrakeListPanel (子组件)
    ↓ 发射信号
BrakeControlPage (父组件)
    ↓ 更新 navigationManager
Qt.binding()
    ↓ 自动更新
BrakeListPanel.currentBrakeIndex
```

## 🎓 经验教训

### 1. Qt.binding() 的陷阱

**问题**：直接赋值会破坏绑定

### 2. 组件通信的正确方式

**问题**：子组件直接修改父组件传递的属性
**解决**：使用信号通信，让父组件更新

**SwitchInputPage vs BrakeControlPage**：
- SwitchInputPage：列表在页面内部，可以直接更新属性
- BrakeControlPage：使用独立组件，必须通过信号通信
