# FIX 100.300.113 Phase 7.32 - 修复焦点指示器和滑动功能

**日期**: 2026-02-04
**任务编号**: FIX 100.300.113 Phase 7.32
**状态**: 🔄 进行中

## 🐛 问题描述

用户测试反馈（第十五次测试）：
> "pjsip.md测试完成，功能满足要求，左右导航正常"

但发现5个新问题：

### 问题1：串口类型应该是只读Text
- **当前状态**：使用CustomTextField（readOnly: true）
- **期望状态**：使用Text，和串口名称一致

### 问题2：只读参数的焦点蓝色边框会自动变小
- **当前状态**：只读字段（串口名称、设备路径、串口类型、状态）的焦点边框会根据文本内容自动缩小
- **期望状态**：焦点边框应该和可设置参数（如波特率）一样大
- **特别严重**：状态的蓝色边框根本看不到

### 问题3：按钮焦点的蓝色边框看不到
- **当前状态**：打开串口、关闭串口按钮的焦点边框不可见
- **期望状态**：按钮获得焦点时应该有明显的蓝色边框

### 问题4：SerialPortConfigPanel.qml的滑动功能没有添加
- **当前状态**：使用ColumnLayout，内容超出时无法滚动
- **期望状态**：添加ScrollView，支持滚动查看所有内容

### 问题5：焦点在关闭串口后继续下键应该进入发送区
- **当前状态**：焦点在关闭串口按钮（索引9）后，下键无法继续移动
- **期望状态**：下键应该进入发送区，焦点包括格式、发送、清空三个按钮

## 🔍 根本原因

### 问题1：串口类型使用了CustomTextField

**当前代码**（SerialPortParamsSection.qml line 245-252）：
```qml
DeviceInfo.CustomTextField {
    id: serialTypeField
    anchors.fill: parent
    text: currentSerialPort ? currentSerialPort.type : ""
    readOnly: true
    keyboardManager: root.keyboardManager
}
```

**问题**：
- CustomTextField是输入框，即使设置readOnly也会显示输入框样式
- 应该使用Text，和串口名称、设备路径一致

### 问题2：只读字段的Item高度跟随Text内容变化

**当前代码**（SerialPortParamsSection.qml line 82-109）：
```qml
Item {
    Layout.column: 0
    Layout.row: 0
    Layout.fillWidth: true
    Layout.maximumWidth: 300
    implicitHeight: serialNameText.implicitHeight  // ❌ 问题：高度跟随文本内容

    Text {
        id: serialNameText
        anchors.fill: parent
        text: currentSerialPort ? currentSerialPort.name : ""
        font.pixelSize: 21
        color: "#E0E0E0"
        verticalAlignment: Text.AlignVCenter

        focus: true
        activeFocusOnTab: true

        // 焦点指示器
        Rectangle {
            anchors.fill: parent  // ❌ 填充Text，Text大小跟随内容
            anchors.margins: -4
            color: "transparent"
            border.color: parent.activeFocus ? "#2196F3" : "transparent"
            border.width: parent.activeFocus ? 3 : 0
            radius: 4
            z: -1
        }
    }
}
```

**问题**：
- `implicitHeight: serialNameText.implicitHeight` 导致Item高度跟随Text内容变化
- Text的implicitHeight是根据文本内容计算的，内容少时高度小
- 焦点指示器Rectangle填充Text，所以也会变小

**解决方案**：
- 使用固定高度，参考CustomTextField的高度（通常是40px）
- 或者使用Layout.preferredHeight设置固定高度

### 问题3：按钮焦点指示器被遮挡

**当前代码**（SerialPortParamsSection.qml line 379-389）：
```qml
Rectangle {
    anchors.fill: parent
    color: "transparent"
    border.color: parent.activeFocus ? "#2196F3" : "transparent"
    border.width: parent.activeFocus ? 3 : 0
    radius: 4
    z: 10  // ❌ z值太高，可能被按钮背景遮挡
}
```

**问题**：
- 焦点指示器使用`anchors.fill: parent`，边框在按钮内部
- 按钮的背景色可能遮挡边框
- 需要让边框在按钮外部

**解决方案**：
- 使用`anchors.margins: -4`让边框在按钮外部
- 调整z值确保边框在最上层

### 问题4：SerialPortConfigPanel.qml没有ScrollView

**当前代码**（SerialPortConfigPanel.qml line 46-110）：
```qml
ColumnLayout {
    anchors.fill: parent
    anchors.margins: 16
    spacing: 16

    // 4个Loader：paramsSection, sendSection, receiveSection, modbusSection
}
```

**问题**：
- 直接使用ColumnLayout，内容超出时无法滚动
- 4个区域的总高度：400 + 380 + 425 + 600 = 1805px
- 如果窗口高度小于1805px，部分内容会被裁剪

**解决方案**：
- 添加ScrollView包裹ColumnLayout
- 参考Phase 7.26之前的代码

### 问题5：下键无法进入发送区

**当前逻辑**（NavigationManager.qml）：
- 当paramIndex=9（关闭串口按钮）时，下键会检查是否超出lastParamIndex
- 如果超出，会切换到areaButtons（底部按钮区）
- 但是串口控制页面没有底部按钮区，所以下键无效

**期望逻辑**：
- 当paramIndex=9时，下键应该进入发送区
- 发送区有3个控件：格式ComboBox、发送Button、清空Button

**挑战**：
- 发送区不在SerialPortControlPage中，而是在SerialPortConfigPanel的SerialPortSendSection中
- 需要扩展NavigationManager支持更多区域
- 或者在SerialPortControlPage中手动处理焦点切换

#### Step 1：修改SerialPortParamsSection.qml

**1.1 问题1：将串口类型改为Text**

**修改前**：
```qml
DeviceInfo.CustomTextField {

    anchors.fill: parent
```

**1.2 问题2：修复只读字段的焦点指示器尺寸**

**修改位置**：所有只读字段的Item容器

**修改前**：
```qml
Item {
    Layout.column: 0
    Layout.row: 0
```

### 方案2：修复问题5（Phase 7.33）

**优先级**：中
**复杂度**：高

**挑战**：
- 发送区不在SerialPortControlPage中
- 需要扩展NavigationManager支持更多区域
- 或者在SerialPortControlPage中手动处理焦点切换

**可能的实现方案**：

#### 方案A：扩展NavigationManager（推荐）

1. 在NavigationManager中添加新的区域：`areaSendSection`
2. 当paramIndex=9且按下键时，切换到areaSendSection
3. SerialPortSendSection需要支持焦点管理（格式ComboBox、发送Button、清空Button）
4. SerialPortControlPage需要监听区域变化，设置焦点到发送区

**优点**：
- 架构清晰，符合NavigationManager的设计
- 可以继续扩展到接收区、MODBUS区

**缺点**：
- 需要修改多个文件
- 需要SerialPortSendSection支持焦点管理

#### 方案B：手动处理焦点切换

1. 在SerialPortControlPage中监听NavigationManager的paramIndex变化
2. 当paramIndex=9且按下键时，手动设置焦点到发送区的第一个控件
3. SerialPortSendSection需要暴露焦点函数

**优点**：
- 实现简单，不需要修改NavigationManager

**缺点**：
- 不符合NavigationManager的设计
- 难以扩展到其他区域
