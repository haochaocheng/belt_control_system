## 🐛 问题描述

用户测试反馈（第十一次测试）：
> "问题1，焦点移动到波特率后，导航键无法使用，老问题，一直没有解决"

### 问题分析

**现象**：
- 焦点移动到波特率（CustomComboBox）后
- 按上下左右键，焦点不移动
- 导航完全失效

**根本原因**：
1. Qt ComboBox 默认拦截上下左右键用于选择选项
2. Phase 7.24 添加了 `onCurrentIndexChanged` 监听，恢复了被修改的索引
3. **但是没有添加方向键的处理器**
4. 导致：ComboBox 拦截了方向键 → 修改了 currentIndex → 我们恢复了 currentIndex → **事件被消耗，但焦点没有移动**

## ✅ 修复方案

### 核心思路

**添加方向键处理器，显式设置 `event.accepted = false`，让事件传播到父组件。**

**文件**: CustomComboBox.qml

## 💡 为什么 Phase 7.14/7.16 失败了？

### Phase 7.14/7.16 的实现

```qml
Keys.onUpPressed: function(event) {
    event.accepted = false  // 不处理，让父组件处理导航
}
```

**为什么失败**：
- 这个处理器在 `onCurrentIndexChanged` **之后**执行
- 但是 ComboBox 的内部处理在 `onCurrentIndexChanged` **之前**就已经完成了
- 所以 `event.accepted = false` 设置得太晚了
- ComboBox 已经消耗了事件

### Phase 7.27 的改进

**关键区别**：
1. **Phase 7.24 添加了 `onCurrentIndexChanged` 监听**，恢复了被修改的索引
2. **Phase 7.27 添加了方向键处理器**，显式设置 `event.accepted = false`
3. **两者结合**：
   - `onCurrentIndexChanged` 恢复索引（阻止参数值改变）
   - 方向键处理器设置 `event.accepted = false`（让事件传播）
   - 结果：参数值不变，焦点正常移动

### CustomComboBox 键盘处理

| 按键 | 处理器 | 行为 | event.accepted |
|------|--------|------|----------------|
| 上键 | Keys.onUpPressed | 不处理，传播到父组件 | false |
| 下键 | Keys.onDownPressed | 不处理，传播到父组件 | false |
| 左键 | Keys.onLeftPressed | 不处理，传播到父组件 | false |
| 右键 | Keys.onRightPressed | 不处理，传播到父组件 | false |
| 回车键 | Keys.onReturnPressed | 循环切换参数值（不可编辑）或打开键盘（可编辑） | true |
| Space键 | Keys.onSpacePressed | 循环切换参数值（不可编辑）或打开键盘（可编辑） | true |

### 配合 onCurrentIndexChanged

```qml
onCurrentIndexChanged: {
    if (isRestoring) return

    if (!isUserAction && root.activeFocus) {
        // 恢复索引（阻止参数值改变）
        isRestoring = true
        root.currentIndex = savedIndex
        isRestoring = false
    } else {
        savedIndex = currentIndex
    }
}
```

**工作原理**：
1. 用户按上键
2. ComboBox 修改 currentIndex（3 → 2）
3. `onCurrentIndexChanged` 恢复索引（2 → 3）**← 阻止参数值改变**
4. `Keys.onUpPressed` 设置 `event.accepted = false` **← 让事件传播**
5. 父组件处理导航，焦点移动
