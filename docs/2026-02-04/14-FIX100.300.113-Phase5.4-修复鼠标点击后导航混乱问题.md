# FIX 100.300.113 Phase 5.4 - 修复鼠标点击后导航混乱问题

**日期**: 2026-02-04
**任务编号**: FIX 100.300.113 Phase 5.4
**状态**: ✅ 完成

---

## 🎯 问题描述

用户反馈："左右上下导航键可以使用了，但是一旦鼠标点击任意一个串口，导航逻辑就混乱了，不能左右切换在串口控制和串口列表之间"

---

## 🔍 问题诊断

### 日志分析

**关键日志**（docs/log/pjsip.md 第 1235-1263 行）：
```
Debug: ✅ [SerialPortControlPage] 上键 → focusItemIndex: 3  ← SerialPortControlPage 的 Keys 处理器被触发！
Debug: ✅ [SerialPortControlPage] 右键 → 进入参数区  ← SerialPortControlPage 的 Keys 处理器被触发！
Debug: ✅ [SerialPortControlPage] 左键 → 返回列表区, focusItemIndex: 1  ← SerialPortControlPage 的 Keys 处理器被触发！
```

### 根本原因

1. **鼠标点击后，SerialPortControlPage 获得了焦点**
   - 通过 `root.forceActiveFocus()` 调用
   - 导致 SerialPortControlPage 的 Keys 处理器开始工作

2. **SerialPortControlPage 的 Keys 处理器拦截了导航键事件**
   - Keys.onUpPressed
   - Keys.onDownPressed
   - Keys.onLeftPressed
   - Keys.onRightPressed

3. **DeviceSettingsDialog 的导航键处理被绕过**
   - DeviceSettingsDialog 无法处理导航键
   - 导致导航逻辑混乱

### 问题流程

```
用户鼠标点击串口
  ↓
SerialPortControlPage.forceActiveFocus() 被调用
  ↓
SerialPortControlPage 获得焦点
  ↓
用户按导航键（上/下/左/右）
  ↓
SerialPortControlPage 的 Keys 处理器被触发 ← 问题！
  ↓
DeviceSettingsDialog 的 Keys 处理器被绕过
  ↓
导航逻辑混乱
```

---

## ✅ 修复方案

### 方案选择

**实施方案 A**：移除 SerialPortControlPage 的 Keys 处理器

**理由**：
1. 与 SwitchInputPage 和 AnalogInputPage 保持一致
2. 完全依赖 DeviceSettingsDialog 的默认处理 + Connections 同步
3. 避免焦点管理冲突

### 修改内容

**文件**: SerialPortControlPage.qml

## 💡 经验教训

### 1. 焦点管理的一致性

- 所有页面应该使用统一的焦点管理方式
- 不应该让子页面获得焦点，焦点应该由父对话框管理
- SwitchInputPage 和 AnalogInputPage 是正确的参考实现

### 2. forceActiveFocus() 的副作用

- `forceActiveFocus()` 会导致组件获得焦点
- 获得焦点后，组件的 Keys 处理器会被触发
- 这会导致父对话框的导航键处理被绕过

### 3. 调试日志的价值

- 通过日志可以清楚地看到 SerialPortControlPage 的 Keys 处理器被触发
- 这帮助我们快速定位问题
