# FIX 100.300.113 Phase 7.17 - 在 Keys.onPressed 中提前拦截方向键（最终方案）

**日期**: 2026-02-04
**任务编号**: FIX 100.300.113 Phase 7.17

## 🐛 问题描述

用户反馈：
> "必须全部排查一遍代码，上下键还是修改参数，修改了多少次了。不要每次都修改一点点，就让我测试。"

**问题现象**：
- 尽管已经多次修复（Phase 7.14, 7.16），上下键仍然在修改 ComboBox 的参数值
- `event.accepted = false` 没有生效
- 导航功能完全失效

---

## 🔍 全面排查结果

### 根本原因分析

经过全面代码排查，发现了问题的根本原因：

**Qt ComboBox 的键盘处理发生在 C++ 层面，在 QML 的 `Keys.onUpPressed` 之前就已经修改了 `currentIndex`。**

### 事件处理顺序

```
用户按下上键
↓
Qt ComboBox 内部处理（C++ 层面）
↓
currentIndex 被修改（已经发生！）
↓
QML Keys.onUpPressed 被触发
↓
event.accepted = false（太晚了！状态已经改变）
↓
事件继续传播到父组件
```

### 为什么之前的修复没有生效？

#### Phase 7.14 的问题
```qml
Keys.onUpPressed: {
    event.accepted = false  // ❌ 太晚了！ComboBox 的 currentIndex 已经被修改
}
```

#### Phase 7.16 的问题
```qml
Keys.onUpPressed: function(event) {
    event.accepted = false  // ❌ 语法正确，但时机太晚
}
```

**关键发现**：
- `event.accepted = false` 只是阻止事件继续传播
- **不能撤销已经发生的状态改变**
- ComboBox 的内部状态在 `Keys.onUpPressed` 之前就已经被修改了

---

## ✅ 最终解决方案

### 核心思路

**在 `Keys.onPressed` 中提前拦截方向键，设置 `event.accepted = true`，阻止 ComboBox 处理这些键。**

### 为什么 Keys.onPressed 有效？

```
用户按下上键
↓
QML Keys.onPressed 被触发（✅ 最早的拦截点）
↓
event.accepted = true（✅ 拦截事件）
↓
Qt ComboBox 内部处理被阻止（✅ currentIndex 不会被修改）
↓
事件不再传播（已被拦截）
```

### 修改内容

**文件**: CustomComboBox.qml

**修改位置**: line 146-159

**修改前**（Phase 7.14 + 7.16）:
```qml

    event.accepted = false  // 不处理，让父组件处理导航
```

**修改后**（Phase 7.17）:
```qml
// ✅ 2026-02-04 [FIX 100.300.113 Phase 7.17]: 键盘导航修复（最终方案）
// 根本原因：Qt ComboBox 的键盘处理发生在 C++ 层面，在 QML 的 Keys.onUpPressed 之前
// 解决方案：在 Keys.onPressed 中提前拦截方向键，阻止 ComboBox 处理

// ⚠️ 关键：必须在 Keys.onPressed 中拦截，设置 event.accepted = true
// 这样可以阻止 ComboBox 的内部状态改变
Keys.onPressed: function(event) {
    // 拦截方向键，不让 ComboBox 处理
    if (event.key === Qt.Key_Up || event.key === Qt.Key_Down ||
        event.key === Qt.Key_Left || event.key === Qt.Key_Right) {
        event.accepted = true  // ✅ 拦截事件，阻止 ComboBox 处理
        console.log("✅ [CustomComboBox] 拦截方向键:", event.key)
    }
}
```

2. ✅ 添加了 `Keys.onPressed` 统一处理
3. ✅ 使用 `event.accepted = true` 拦截事件（而不是 `false`）
4. ✅ 检查 `event.key` 来判断是否是方向键

## 💡 技术原理

### Qt 事件处理顺序

```
1. Keys.onPressed        ← ✅ 最早的拦截点（Phase 7.17 使用）
2. Qt 内部处理（C++）    ← ❌ ComboBox 修改 currentIndex
3. Keys.onUpPressed      ← ❌ 太晚了（Phase 7.14/7.16 使用）
4. Keys.onDownPressed
5. Keys.onLeftPressed
6. Keys.onRightPressed
7. Keys.onReleased
```

### event.accepted 的作用

| 设置 | 效果 |
|------|------|
| `event.accepted = true` | 拦截事件，阻止后续处理 |
| `event.accepted = false` | 不拦截，允许事件继续传播 |

**关键理解**：
- `event.accepted = true` 在 `Keys.onPressed` 中 → ✅ 阻止 ComboBox 处理
- `event.accepted = false` 在 `Keys.onUpPressed` 中 → ❌ ComboBox 已经处理完了

- 以为 `Keys.onUpPressed` 是第一个处理键盘事件的地方
