## 🔍 根本原因

### Qt ComboBox 事件处理顺序

```
用户按下键
↓
1. Qt ComboBox C++ 层面处理（最先）
   - 修改 currentIndex
   - 标记 event.accepted = true
↓
2. QML onCurrentIndexChanged 触发
   - 我们的代码恢复索引
↓
3. QML Keys.onDownPressed 触发
   - 我们设置 event.accepted = false
   - ❌ 但是太晚了！事件已经被消耗
↓
4. 事件不再传播到父组件
   - ❌ DeviceSettingsDialog 收不到事件
   - ❌ NavigationManager 不会被调用
```

### 为什么 Phase 7.27 失败了？

**Phase 7.27 的实现**：
```qml
Keys.onDownPressed: function(event) {
    console.log("🔍 [CustomComboBox] 下键按下")
    event.accepted = false  // ❌ 太晚了
    console.log("✅ [CustomComboBox] 下键事件传播到父组件")
}
```

**问题**：
- `event.accepted = false` 在 QML 层面设置
- 但是 Qt ComboBox 的 C++ 层面已经设置了 `event.accepted = true`
- QML 层面的修改不会影响 C++ 层面的决定
- 事件不会传播到父组件

### 为什么右键可以工作？

从日志 line 282-303 看到右键是正常工作的：

```
282→Debug: ? [导航] 右键 - 当前区域: 1
...
295→Debug: ?? [串口控制导航] 右键 - 调用 NavigationManager.handleDirectionKey
296→Debug: ? [NavigationManager] 方向键: Right 当前区域: A 当前索引: 0
```

**原因**：
- 右键不会修改 ComboBox 的 currentIndex
- ComboBox 不拦截右键
- 事件可以正常传播到父组件

## ✅ 修复方案

### 核心思路

**不依赖事件传播，而是在 CustomComboBox 内部直接调用父组件的导航逻辑。**

### 实现步骤

1. **添加父组件引用属性**
   - 让 CustomComboBox 知道它的父组件是谁

2. **在方向键处理器中直接调用父组件的导航函数**
   - 不依赖事件传播
   - 直接调用 DeviceSettingsDialog 的导航逻辑

3. **阻止 ComboBox 的默认行为**
   - 设置 `event.accepted = true`（阻止 ComboBox 处理）
   - 然后手动调用父组件的导航

Keys.onUpPressed: function(event) {

## 💡 工作原理详解

### Phase 7.29：直接调用的工作流程

```
用户按下键
↓
1. Qt ComboBox C++ 层面处理
   - 修改 currentIndex
   - 标记 event.accepted = true
↓
2. QML onCurrentIndexChanged 触发
   - 我们的代码恢复索引（阻止参数值改变）
↓
3. QML Keys.onDownPressed 触发
   - ✅ 检查 parentDialog 是否存在
   - ✅ 设置 event.accepted = true（阻止 ComboBox 默认行为）
   - ✅ 直接调用 parentDialog.handleNavigationKey(Qt.Key_Down, event)
↓
4. DeviceSettingsDialog.handleNavigationKey() 执行
   - ✅ 调用 handleDownKey(event)
   - ✅ 执行导航逻辑
   - ✅ 调用 NavigationManager.handleDirectionKey("Down")
↓
5. NavigationManager 处理导航
   - ✅ 焦点移动到下一个参数
```

### 关键优势

1. **不依赖事件传播**
   - 直接调用父组件的函数
   - 绕过 Qt 的事件系统

2. **完全控制**
   - 我们决定何时调用导航
   - 我们决定是否阻止默认行为

3. **调试友好**
   - 清晰的调用链
   - 容易追踪问题

## 📝 经验教训

### 1. Qt 事件系统的限制

**错误理解**：
- 以为在 QML 层面设置 `event.accepted = false` 就能让事件传播
- 忽略了 Qt ComboBox 的 C++ 层面处理

**正确理解**：
- Qt ComboBox 的 C++ 层面处理在 QML 之前
- C++ 层面的 `event.accepted = true` 不会被 QML 层面的修改覆盖
- 需要绕过事件系统，直接调用父组件的函数

### 2. 直接调用 vs 事件传播

**事件传播的问题**：
- 依赖 Qt 的事件系统
- 容易被中间组件拦截
- 难以调试

**直接调用的优势**：
- 不依赖事件系统
- 调用链清晰
- 容易调试
- 完全控制

### 3. 组件间通信的最佳实践

**方法 1：事件传播**
- 适用于：简单的事件通知
- 不适用于：复杂的导航逻辑

**方法 2：直接调用**
- 适用于：复杂的导航逻辑
- 需要：父组件引用
- 优势：清晰、可控、易调试

**方法 3：信号/槽**
- 适用于：松耦合的组件通信
- 优势：解耦、灵活
- 劣势：调试困难
