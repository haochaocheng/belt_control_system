## 🔍 根本原因分析

### ScrollView 自动滚动行为与焦点冲突

**问题流程**：

1. **用户按右键** → NavigationManager 调用 `focusSerialName()`
2. **forceActiveFocus() 设置焦点** → serialNameText 获得焦点
3. **ScrollView 检测到焦点元素** → 自动滚动使其可见（Qt ScrollView 的默认行为）
4. **滚动过程中 ScrollView 抢夺焦点** → serialNameText 失去焦点
5. **Qt.callLater 恢复焦点** → serialNameText 再次获得焦点
6. **又触发 ScrollView 滚动** → 再次抢夺焦点
7. **形成循环** → 用户看到"界面滑动一次"

### 为什么 ScrollView 会抢夺焦点？

**Qt ScrollView 的已知行为**：
- ScrollView 在滚动时会临时获取焦点以处理滚动事件
- 如果 `clip: true`，滚动时可能会裁剪焦点元素
- 滚动动画过程中，焦点链可能被打断

**SerialPortConfigPanel.qml 的 ScrollView 配置**：
```qml
ScrollView {
    id: scrollView
    anchors.fill: parent
    clip: true  // ⚠️ 可能导致焦点元素在滚动时被裁剪
    ScrollBar.horizontal.policy: ScrollBar.AlwaysOff

    ColumnLayout {
        width: scrollView.width
        spacing: 16
        // SerialPortParamsSection 是第一个子元素
    }
}
```

## ✅ 解决方案

### 方案：禁用 ScrollView 交互 + 详细调试

**核心思路**：
1. 在设置焦点前，**暂时禁用 ScrollView 的交互**（`interactive: false`）
2. 设置焦点
3. 在 Qt.callLater 中，**重新启用 ScrollView 的交互**（`interactive: true`）
4. 添加详细的 ScrollView 滚动状态调试

**为什么这样可以工作**：
- `interactive: false` 禁用 ScrollView 的自动滚动行为
- 焦点设置不会触发滚动
- ScrollView 不会抢夺焦点
- 焦点可以稳定保持在 serialNameText 上

## 💡 技术要点

### Qt ScrollView 的自动滚动行为

**默认行为**：
- 当焦点元素不在可见区域时，ScrollView 会自动滚动使其可见
- 滚动过程中，ScrollView 可能会临时获取焦点
- 如果 `clip: true`，滚动时可能会裁剪焦点元素

**禁用方法**：
- 设置 `interactive: false` 禁用所有交互（包括自动滚动）
- 设置焦点后，重新启用 `interactive: true`

### 焦点设置的正确顺序

1. **禁用 ScrollView 交互** → 防止自动滚动
2. **禁用 root.focus** → 防止焦点冲突
3. **设置焦点** → forceActiveFocus()
4. **Qt.callLater 检查** → 确保焦点保持
5. **重新启用 ScrollView 交互** → 恢复正常滚动

### 调试技巧

**追踪 ScrollView 滚动**：
- 监听 `contentY` 变化
- 监听 `flickStarted/flickEnded`
- 监听 `movementStarted/movementEnded`
- 监听 `interactive` 变化

**追踪焦点变化**：
- 监听 `activeFocus` 变化
- 使用 Qt.callLater 延迟检查
- 记录焦点设置前后的状态
