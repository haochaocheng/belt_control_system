# FIX 100.300.113 Phase 7.30 - 修复串口控制参数导航索引

**任务编号**: FIX 100.300.113 Phase 7.30

## 🐛 问题描述

用户测试反馈（第十四次测试）：
> "焦点在波特率时，按下键跳到了停止位，应该是数据位"

### 日志分析


**问题**：
- 从索引 0（波特率）按下键
- NavigationManager 计算出下一个索引是 2（停止位）
- 但应该是索引 1（数据位）

---

## 🔍 根本原因

### NavigationManager 的导航逻辑

NavigationManager 假设参数是**两列布局**：

```
左列：0, 2, 4, 6, 8...
右列：1, 3, 5, 7, 9...
```

所以下键逻辑是：`nextIndex = paramIndex + 2`（同列下一行）

**代码**（NavigationManager.qml line 183-200）：
```qml
case "Down":
    // 向下移动（同列）
    // 计算下一个索引（同列下一行）
    var nextIndex = paramIndex + 2  // ← 加2是因为两列布局

    // 检查下一个索引是否超出范围
    if (nextIndex > lastParamIndex) {
        // 超出范围，进入底部按钮区
        switchToArea(areaButtons)
        buttonIndex = 0
        return
    } else {
        // 在范围内，移动到下一个索引
        newIndex = nextIndex
    }
    break
```

### 串口控制页面的实际布局

**SerialPortParamsSection.qml 的 GridLayout**：

| 行 | 左列（column 0,1） | 右列（column 2,3） |
|----|-------------------|-------------------|
| 0 | 串口名称（只读） | **波特率（索引0）** |
| 1 | 设备路径（只读） | **数据位（索引1）** |
| 2 | 串口类型（只读） | **停止位（索引2）** |
| 3 | **校验位（索引3）** | 状态（只读） |
| 4 | 空 | 打开串口/关闭串口（按钮） |

**参数索引**：
- 0 = 波特率（右列第1行）
- 1 = 数据位（右列第2行）
- 2 = 停止位（右列第3行）
- 3 = 校验位（左列第4行）

**问题**：
- 参数索引是 0,1,2,3（连续的）
- 但 NavigationManager 认为是两列布局（0,2,4,6 在左列，1,3,5,7 在右列）
- 导致下键从索引 0 跳到索引 2（+2），而不是索引 1（+1）

---

## ✅ 解决方案

### 方案 1：重新编号参数索引（推荐）⭐

**将参数索引改为两列布局的标准编号**：

| 行 | 左列 | 右列 |
|----|------|------|
| 0 | 串口名称（只读） | **波特率（索引1）** |
| 1 | 设备路径（只读） | **数据位（索引3）** |
| 2 | 串口类型（只读） | **停止位（索引5）** |
| 3 | **校验位（索引0）** | 状态（只读） |

**新的参数索引**：
- 0 = 校验位（左列第4行）
- 1 = 波特率（右列第1行）
- 3 = 数据位（右列第2行）
- 5 = 停止位（右列第3行）

**优点**：
- 符合 NavigationManager 的两列布局逻辑
- 不需要修改 NavigationManager
- 其他页面（电机控制、制动器控制、张紧控制）都使用相同的逻辑

**缺点**：
- 需要修改 SerialPortControlPage.triggerParamInput 的索引映射
- 索引不连续（0,1,3,5）

### 方案 2：修改 NavigationManager 支持单列布局

**添加 `layoutMode` 属性**：
- `"two-column"`：两列布局（默认），下键 +2
- `"single-column"`：单列布局，下键 +1

**修改 NavigationManager.qml**：
```qml
property string layoutMode: "two-column"  // 新增属性

function moveInParamArea(direction) {
    var newIndex = paramIndex
    var step = (layoutMode === "single-column") ? 1 : 2  // 根据布局模式决定步长

    switch(direction) {
    case "Down":
        var nextIndex = paramIndex + step  // 使用动态步长
        if (nextIndex > lastParamIndex) {
            switchToArea(areaButtons)
            buttonIndex = 0
            return
        } else {
            newIndex = nextIndex
        }
        break
    // ...
    }
}
```

**SerialPortControlPage 设置**：
```qml
NavigationManager {
    id: navigationManager
    layoutMode: "single-column"  // 串口控制使用单列布局
    skipTabArea: true
}
```

**优点**：
- 参数索引保持连续（0,1,2,3）
- 逻辑清晰，易于理解

**缺点**：
- 需要修改 NavigationManager（影响其他页面）
- 需要测试其他页面是否受影响

### 方案 3：串口控制使用独立的导航逻辑

**不使用 NavigationManager**，在 SerialPortControlPage 中实现自己的导航逻辑。

**优点**：
- 完全独立，不影响其他页面
- 可以自由定制导航行为

**缺点**：
- 代码重复
- 维护成本高

---

## 🎯 推荐方案：方案 1

**理由**：
1. 符合现有的 NavigationManager 设计
2. 不需要修改 NavigationManager（避免影响其他页面）
3. 只需要修改串口控制页面的索引映射
4. 其他页面都使用相同的两列布局逻辑

---

## 📝 实施步骤（方案 1）

### Step 1：修改参数索引映射

**SerialPortControlPage.qml** - `triggerParamInput` 函数：

**修改前**：
```qml
function triggerParamInput(index) {
    switch(index) {
    case 0:  // 波特率
        serialConfigPanel.item.paramsSection.item.focusBaudRate()
        break
    case 1:  // 数据位
        serialConfigPanel.item.paramsSection.item.focusDataBits()
        break
    case 2:  // 停止位
        serialConfigPanel.item.paramsSection.item.focusStopBits()
        break
    case 3:  // 校验位
        serialConfigPanel.item.paramsSection.item.focusParity()
        break
    }
}
```

**修改后**：
```qml
function triggerParamInput(index) {
    // ✅ 2026-02-04 [FIX 100.300.113 Phase 7.30]: 重新编号以匹配两列布局
    // 左列：0（校验位）
    // 右列：1（波特率）, 3（数据位）, 5（停止位）
    switch(index) {
    case 0:  // 校验位（左列第4行）
        serialConfigPanel.item.paramsSection.item.focusParity()
        break
    case 1:  // 波特率（右列第1行）
        serialConfigPanel.item.paramsSection.item.focusBaudRate()
        break
    case 3:  // 数据位（右列第2行）
        serialConfigPanel.item.paramsSection.item.focusDataBits()
        break
    case 5:  // 停止位（右列第3行）
        serialConfigPanel.item.paramsSection.item.focusStopBits()
        break
    }
}
```


### Step 3：更新初始焦点

**SerialPortControlPage.qml** - 初始化焦点：

**修改前**：
```qml
Component.onCompleted: {
    focusItemIndex = 0  // 初始焦点在第一个串口
    focusSubArea = 0    // 初始焦点在列表区域
}
```

**修改后**：
```qml
Component.onCompleted: {
    focusItemIndex = 0  // 初始焦点在第一个串口
    focusSubArea = 0    // 初始焦点在列表区域
    // ✅ 2026-02-04 [FIX 100.300.113 Phase 7.30]: 初始参数索引改为1（波特率）
    // 因为重新编号后，波特率的索引是1，而不是0
}
```

## 🔄 预期效果

### 修复后的导航流程

**从列表区域按右键进入参数区域**：
- 焦点移动到索引 1（波特率）

**在波特率按下键**：
- NavigationManager 计算：nextIndex = 1 + 2 = 3
- 焦点移动到索引 3（数据位）✅

**在数据位按下键**：
- NavigationManager 计算：nextIndex = 3 + 2 = 5
- 焦点移动到索引 5（停止位）✅

**在停止位按下键**：
- NavigationManager 计算：nextIndex = 5 + 2 = 7
- 7 > lastParamIndex (5)
- 焦点移动到底部按钮区域✅

**在停止位按左键**：
- NavigationManager 计算：newIndex = 5 - 1 = 4
- 但索引 4 不存在
- 需要特殊处理：跳到索引 0（校验位）

## ⚠️ 注意事项

### 左键导航的特殊处理

由于索引不连续（0,1,3,5），左键导航需要特殊处理：

**NavigationManager.qml** - `moveInParamArea` 函数：

```qml
case "Left":
    // 向左移动（同行）
    if (paramIndex % 2 === 1) {
        // 在右列，向左移动
        // ✅ 2026-02-04 [FIX 100.300.113 Phase 7.30]: 特殊处理串口控制页面
        // 右列索引：1,3,5 → 左列索引：0
        // 但是只有索引0（校验位）在左列
        // 所以只有从索引1（波特率）按左键才能到索引0（校验位）

        // 简化处理：只有索引1可以向左移动到索引0
        if (paramIndex === 1) {
            newIndex = 0  // 波特率 → 校验位
        }
        // 其他右列索引（3,5）按左键不移动
    }
    // 在左列，保持不变
    break
```

**问题**：这样会导致：
- 从波特率（索引1）按左键 → 校验位（索引0）✅
- 从数据位（索引3）按左键 → 不移动 ❌
- 从停止位（索引5）按左键 → 不移动 ❌

**更好的方案**：
- 数据位（索引3）按左键 → 校验位（索引0）
- 停止位（索引5）按左键 → 校验位（索引0）

但这需要修改 NavigationManager 的左键逻辑，增加复杂度。
