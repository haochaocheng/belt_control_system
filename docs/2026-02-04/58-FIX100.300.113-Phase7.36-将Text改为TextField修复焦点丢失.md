# FIX 100.300.113 Phase 7.36 - 将 Text 改为 TextField 修复焦点丢失

**日期**: 2026-02-04
**任务编号**: FIX 100.300.113 Phase 7.36
**状态**: ✅ 完成

## 🐛 问题描述

经过 Phase 7.35 的 10+ 次修复尝试，发现根本原因：

**串口控制界面使用了错误的焦点元素类型（Text），导致 Qt 触发自动滚动，焦点立即丢失。**

### 问题现象

1. ✅ `forceActiveFocus()` 成功设置焦点（activeFocus: true）
2. ✅ 焦点指示器正确显示（蓝色边框，3px）
3. ❌ **ScrollView 自动滚动**（contentY: 0 → 1182）
4. ❌ **滚动过程中焦点丢失**（activeFocus: false）
5. ❌ **焦点循环丢失和恢复**（gain → lose → recover → lose again）

### 用户关键线索

> "电机配置界面也是使用滚动，但是没有问题，那个只有弹窗虚拟键盘，界面才会滚动"

---

## 🔍 根本原因分析

### 对比电机配置界面（正常工作）

**电机配置界面使用的焦点元素类型**：
- ✅ TextField（可编辑文本）
- ✅ SpinBox（数字输入）
- ✅ ComboBox（下拉选择）
- ✅ **没有使用 Text 元素作为焦点元素！**

**为什么正常工作**：
- TextField/SpinBox/ComboBox 是 Qt 设计用于接收焦点的输入控件
- 有内置的焦点管理机制
- **Qt 知道如何正确处理这些控件的焦点**
- **不会触发不必要的自动滚动**

### 串口控制界面的问题

**串口控制界面使用的焦点元素类型**：
- ❌ **Text**（只读显示）← 问题所在！
- ✅ ComboBox（可编辑）
- ✅ Button（操作按钮）

**为什么失败**：
- Text 是只读显示控件，**不是设计用于接收焦点的**
- **没有内置的焦点管理机制**
- **Qt 不知道如何正确处理 Text 元素的焦点**
- **触发 Qt 的自动滚动机制**（ensureVisible）
- **ScrollView 自动滚动导致焦点丢失**

---

## ✅ 解决方案

### 方案：将 Text 改为 TextField（readOnly: true）

**核心思路**：
- 使用 Qt 设计用于接收焦点的控件（TextField）
- 设置 `readOnly: true` 保持只读状态
- 设置透明背景，模拟 Text 外观
- 与电机配置界面保持一致

### 1. 串口名称（索引 0）

**修改位置**: SerialPortParamsSection.qml line 191-264

**修改内容**：

```qml
// 串口名称值（只读）
// ✅ 2026-02-04 [FIX 100.300.113 Phase 7.36]: 改为 TextField（readOnly: true）
// 原因：Text 元素不是设计用于接收焦点的，会触发 Qt 的自动滚动导致焦点丢失
// 参考：电机配置界面使用 TextField，焦点正常工作
Item {
    Layout.column: 1
    Layout.row: 0
    Layout.fillWidth: true
    Layout.maximumWidth: 300
    Layout.preferredHeight: 40

    TextField {
        id: serialNameText
        anchors.fill: parent
        text: currentSerialPort ? currentSerialPort.name : ""
        font.pixelSize: 21
        color: "#E0E0E0"
        verticalAlignment: Text.AlignVCenter

        // ✅ 设置为只读
        readOnly: true

        // ✅ 允许接收焦点
        focus: true
        activeFocusOnTab: true

        // ✅ 透明背景，模拟 Text 外观
        background: Rectangle {
            color: "transparent"
            border.width: 0
        }

        // ✅ 焦点指示器
        Rectangle {
            id: serialNameFocusIndicator
            anchors.fill: parent
            anchors.margins: -4
            color: "transparent"
            border.color: parent.activeFocus ? "#2196F3" : "transparent"
            border.width: parent.activeFocus ? 3 : 0
            radius: 4
            z: 10
        }
    }
}
```

**关键改动**：
1. ✅ `Text` → `TextField`
2. ✅ 添加 `readOnly: true`
3. ✅ 添加透明背景 `background: Rectangle { color: "transparent"; border.width: 0 }`
4. ✅ 保持焦点指示器不变

## 💡 技术要点

### TextField vs Text

**Text**（只读显示控件）：
- 主要用于显示文本
- 没有内置的焦点管理机制
- 没有输入法支持
- **Qt 不知道如何正确处理 Text 元素的焦点**
- **可能触发意外的自动滚动行为**

**TextField**（输入控件）：
- 设计用于接收焦点和输入
- 有内置的焦点管理机制
- 有输入法支持（虚拟键盘）
- **Qt 知道如何正确处理 TextField 的焦点**
- **不会触发不必要的自动滚动**
- 可以设置 `readOnly: true` 保持只读状态

### 透明背景样式

```qml
TextField {
    // ... 其他属性

    // ✅ 透明背景，模拟 Text 外观
    background: Rectangle {
        color: "transparent"
        border.width: 0
    }
}
```

**效果**：
- 外观与 Text 元素完全一致
- 用户看不出区别
- 但焦点行为正确

## 💡 经验教训

### 1. 选择正确的焦点元素类型

- ✅ 使用 Qt 设计用于接收焦点的控件（TextField, SpinBox, ComboBox, Button）
- ❌ 不要使用只读显示控件（Text, Label）作为焦点元素

### 2. 对比正常工作的实现

- ✅ 电机配置界面使用 TextField，焦点正常工作
- ❌ 串口控制界面使用 Text，焦点立即丢失
- ✅ 对比差异，找出根本原因

### 3. 理解 Qt 的焦点系统

- Qt 的焦点系统会自动调用 `ensureVisible()` 使焦点元素可见
- 这个自动滚动不受 `interactive` 属性控制
- 只有使用正确的焦点元素类型，Qt 才能正确处理焦点

### 4. 简化代码

- Phase 7.35: 80+ 行复杂的 ScrollView 控制代码
- Phase 7.36: 8 行简单的 forceActiveFocus() 调用
- **正确的解决方案往往是最简单的**

- ✅ "电机配置界面没有问题" - 提供了参考实现
- ✅ "只有弹窗虚拟键盘，界面才会滚动" - 揭示了焦点元素类型的差异
