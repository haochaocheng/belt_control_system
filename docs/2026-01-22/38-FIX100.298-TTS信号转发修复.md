## 一、问题发现

### 用户反馈

1. **"TTS引擎不可用"** - 日志显示此错误
2. **"听不到TTS合成的声音"** - 预警没有播放

### 根本原因分析

#### 原因 1：代码版本不匹配（主要原因）

```
日志显示编译时间: Jan 22 2026 18:49:11  ← 旧版本
TTS 集成代码添加: 2026-01-23 00:00+      ← 新代码未部署
```

**问题**：
- CommonControl 构造函数中的 TTS 初始化代码（第163-177行）未编译到运行版本
- 导致 `m_tts` 指针虽然创建，但 `initialize()` 从未被调用
- TTS 状态始终为初始状态，不是 `Ready`
- `playWarningOnce()` 检查 `m_tts->state() == Ready` 失败
- 输出 "❌ TTS引擎不可用"

**预期日志 vs 实际日志**：

| 预期日志（代码中有） | 实际日志（完全缺失） |
|---------------------|---------------------|
| `✅ CommonControl: TTS 语音合成器初始化成功` | ❌ 无 |
| `   模型目录: /app/models/sherpa-onnx-models` | ❌ 无 |
| `   输出模式: 网络传输（TCP 模式 → 上位机）` | ❌ 无 |

#### 原因 2：信号转发缺失（架构问题）

即使 TTS 初始化成功，也存在**信号丢失导致预警循环中断**的问题：

**音频文件播放流程（正常）**：
```
playAudio()
  → QMediaPlayer::play()  【异步】
  → playbackStateChanged(Stopped)
  → CommonControl::onPlaybackFinished() ✅ 触发第2、3次播放
```

**TTS 网络传输流程（原始实现，有问题）**：
```
m_tts->sayToNetwork()
  ├─ synthesize() 【同步阻塞 500ms】
  └─ m_tcpSender->playAudioToNetwork() 【异步】
      → playbackFinished 信号
      → SherpaOnnxTTS::onNetworkTransmissionFinished() ← 内部槽函数
      ✗ 信号丢失！CommonControl 不知道播放完成
      ✗ 预警循环中断，只播放 1 次
```

**问题**：
- `AudioNetworkTcpSender::playbackFinished` 信号被 `SherpaOnnxTTS` 捕获
- `SherpaOnnxTTS` 只清理临时文件，没有通知外部调用者
- `CommonControl` 无法知道播放完成，预警循环中断

---

## 二、解决方案

### 方案：添加信号转发机制

让 `SherpaOnnxTTS` 在内部完成清理后，向外发出 `networkTransmissionFinished` 信号。

### 修改 1：SherpaOnnxTTS.h - 添加信号声明

**位置**：第92-98行

**添加**：
```cpp
signals:
    void stateChanged(SherpaOnnxTTS::State state);

    // ✅ 2026-01-23 00:30 [信号转发] 网络传输完成信号（供 CommonControl 监听）
    // 原因：TTS 网络传输完成后需要通知 CommonControl 继续预警循环
    // 用途：playWarningOnce() → sayToNetwork() → playbackFinished → 此信号 → CommonControl::onPlaybackFinished()
    void networkTransmissionFinished();
```

**作用**：
- 提供外部接口，让 `CommonControl` 可以连接此信号
- 信号名称清晰表明用途（网络传输完成）

---

### 修改 2：SherpaOnnxTTS.cpp - 发出信号

**位置**：第511-526行

**修改**：
```cpp
void SherpaOnnxTTS::onNetworkTransmissionFinished()
{
    qDebug() << "✅ TTS网络传输完成";

    // 清理临时文件
    if (m_networkTempFile) {
        qDebug() << "   删除临时文件:" << m_networkTempFile->fileName();
        delete m_networkTempFile;
        m_networkTempFile = nullptr;
    }

    // ✅ 2026-01-23 00:30 [信号转发] 通知外部调用者（CommonControl）传输完成
    // 原因：CommonControl 需要接收此信号来继续预警循环（播放第2、3次）
    // 流程：playWarningOnce() → sayToNetwork() → [异步传输] → playbackFinished → 此槽 → emit信号 → CommonControl::onPlaybackFinished()
    emit networkTransmissionFinished();
}
```

**作用**：
- 在完成内部清理（删除临时文件）后
- 向外发出信号，通知调用者传输已完成

---

### 修改 3：CommonControl.cpp - 连接信号

**位置**：第179-184行（构造函数末尾）

**添加**：
```cpp
// ✅ 2026-01-23 00:30 [信号转发] 连接 TTS 网络传输完成信号
// 原因：TTS 网络传输完成后需要触发 onPlaybackFinished() 继续预警循环
// 流程：TTS 传输完成 → emit networkTransmissionFinished() → onPlaybackFinished() → 播放第2、3次
connect(m_tts, &SherpaOnnxTTS::networkTransmissionFinished,
        this, &CommonControl::onPlaybackFinished);
qDebug() << "✅ CommonControl: TTS 信号已连接到预警循环";
```

**作用**：
- 将 TTS 完成信号连接到 `CommonControl::onPlaybackFinished()`
- 实现与音频文件播放相同的预警循环逻辑

## 三、修复后的完整流程

### TTS 网络传输流程（修复后）

```
用户按"1号皮带启动"
    ↓
startWarningPlayback(1)
    ├─ 保存 m_currentBeltNumber = 1
    ├─ m_isWarningPlaying = true
    └─ playWarningOnce()
        ↓
构造文本: "1号皮带启动"
    ↓
m_tts->state() == Ready? → ✅ 是（TTS已初始化）
    ↓
m_tts->sayToNetwork("1号皮带启动", TCP模式)
    ├─ 1. 创建临时 WAV 文件
    ├─ 2. synthesize() 合成语音【同步 500ms】
    ├─ 3. FFmpeg 解码 + Opus 编码
    └─ 4. m_tcpSender->playAudioToNetwork()【异步】
        ↓
    独立线程发送音频帧（2-3秒）
        ↓
    AudioNetworkTcpSender::playbackFinished 信号
        ↓
    SherpaOnnxTTS::onNetworkTransmissionFinished()
        ├─ 删除临时文件
        └─ emit networkTransmissionFinished() ← 关键信号
            ↓
    CommonControl::onPlaybackFinished() ← 接收信号
        ├─ m_currentPlayCount++ (1/3)
        ├─ 播放次数未达到 → 继续
        └─ QTimer::singleShot(300, playWarningOnce) ← 播放第2次
            ↓
（重复上述流程，播放第2、3次）
    ↓
m_currentPlayCount == 3 → 预警完成
    ├─ stopWarningPlayback()
    ├─ emit warningPlaybackFinished()
    └─ startDeviceSequence() ← 自动启动设备序列
```

## 九、关键技术点

### 信号转发模式

**模式定义**：
中间层（`SherpaOnnxTTS`）接收底层信号（`AudioNetworkTcpSender::playbackFinished`），完成内部逻辑后，转发给上层（`CommonControl`）。

**优势**：
- ✅ 封装性好：`CommonControl` 不需要直接依赖 `AudioNetworkTcpSender`
- ✅ 清晰的职责分离：`SherpaOnnxTTS` 负责临时文件清理，`CommonControl` 负责预警循环
- ✅ 易于扩展：未来可以在转发前添加额外逻辑（如统计、日志）

**实现关键**：
```cpp
// 内部槽函数（private slot）
void onNetworkTransmissionFinished() {
    // 1. 完成内部清理
    delete m_networkTempFile;

    // 2. 转发信号给外部
    emit networkTransmissionFinished();
}
```
