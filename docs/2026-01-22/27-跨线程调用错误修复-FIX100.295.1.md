## 二、问题根本原因

### 错误架构（FIX 100.295 初始版本）

```cpp
// AudioNetworkTcpSender.cpp 构造函数（第78-79行）
m_senderWorker->moveToThread(m_senderThread);
m_wsClient->moveToThread(m_senderThread);  // ❌ 错误！
```

**问题流程**：
```
【主线程】UDP 服务发现
    ↓
parseDiscoveryJson()
    ↓
connectToServer(ip, port)  ← 主线程调用
    ↓
m_wsClient->connectToHost()  ← ❌ 但 m_wsClient 在独立线程！
    ↓
跨线程访问 QTcpSocket → 线程冲突
    ↓
连接失败：SocketError(19) "Trying to connect while connection is in progress"
```

### 根本原因

**WebSocketClient 被移动到独立线程后**：
1. UDP 服务发现在**主线程**触发
2. `connectToServer()` 在**主线程**调用
3. 但 `m_wsClient` 已经在**独立线程**
4. **跨线程直接访问 `QTcpSocket`** → 线程冲突
5. 连接失败，心跳超时，无法发送音频

**Qt 的 QTcpSocket 不支持跨线程直接调用**：
- QTcpSocket 必须在创建它的线程中使用
- `connectToHost()` 必须在对象所在线程调用
- 违反规则会导致未定义行为和错误

---

## 三、解决方案

### 正确架构

**WebSocketClient 应该留在主线程**：
- ✅ UDP 服务发现在主线程
- ✅ TCP 连接在主线程
- ✅ 心跳机制在主线程
- ✅ 只有 AudioSenderWorker 在独立线程

### 架构修正

```
【主线程】
├─ UDP 服务发现（监听 8600 端口）
├─ WebSocketClient（TCP 连接、WebSocket 握手、心跳）
├─ 音频编码（FFmpeg + Opus）
└─ Opus 缓存管理

【独立发送线程】
└─ AudioSenderWorker（20ms 精确定时发送）
   └─ 通过 Qt::QueuedConnection 调用 WebSocketClient::sendBinaryFrame()
```

**文件**：`src/audio_network/AudioSenderWorker.cpp`
**行数**：第 110-117 行

**修改后**（Qt::QueuedConnection）：

// ✅ 2026-01-22 21:10 [FIX 100.295.1] 跨线程调用（独立线程 → 主线程）

                          Qt::QueuedConnection,
                          Q_ARG(QByteArray, opusFrame));

## 五、技术原理

### Qt 线程安全机制

#### 方式 1：moveToThread()
```cpp
// 对象移动到独立线程
QObject* obj = new QObject();
obj->moveToThread(thread);
```
- ✅ 对象的事件循环在新线程中运行
- ✅ 信号槽在新线程中执行
- ❌ **只能在对象所在线程访问对象的方法**

#### 方式 2：Qt::QueuedConnection
```cpp
// 跨线程调用 slot
QMetaObject::invokeMethod(obj, "methodName",
                          Qt::QueuedConnection,
                          Q_ARG(Type, value));
```
- ✅ 线程安全（通过事件队列传递）
- ✅ 异步调用（立即返回）
- ✅ Qt 自动处理参数序列化

### 本次修复的原理

```
【独立线程】AudioSenderWorker::sendNextFrame()
    ↓
QMetaObject::invokeMethod(m_wsClient, "sendBinaryFrame", ...)
    ↓
Qt 事件系统（线程安全队列）
    ↓
【主线程】WebSocketClient::sendBinaryFrame()
    ↓
m_socket->write(frame)  ← 在主线程执行
```

**关键点**：
1. `QMetaObject::invokeMethod()` 将调用封装成事件
2. 事件放入主线程的事件队列
3. 主线程事件循环取出事件
4. 在主线程执行 `sendBinaryFrame()`
5. **完全避免跨线程直接访问**

## 九、经验教训

### 1. Qt 线程模型理解

**错误认知**：
- ❌ 以为把对象移动到线程就可以在任何线程调用
- ❌ 以为 QTcpSocket 是线程安全的

**正确认知**：
- ✅ **moveToThread() 只改变对象的事件循环所在线程**
- ✅ **对象的方法必须在对象所在线程调用**
- ✅ **跨线程调用必须使用信号槽或 QMetaObject::invokeMethod()**

### 2. 架构设计原则

**独立线程应该**：
- ✅ 只负责单一职责（定时发送）
- ✅ 不管理网络连接（TCP 连接、心跳）
- ✅ 通过信号槽与主线程通信

**主线程应该**：
- ✅ 管理所有 I/O 对象（Socket、文件）
- ✅ 处理系统事件（UDP 发现、用户交互）
- ✅ 协调多个模块

### 3. 调试技巧

**症状**：`QAbstractSocket::connectToHost() called when already connecting`

**诊断步骤**：
1. 检查对象所在线程：`obj->thread()`
2. 检查调用所在线程：`QThread::currentThread()`
3. 确认是否跨线程调用
4. 查看是否使用了 `moveToThread()`
5. 修改为信号槽方式
