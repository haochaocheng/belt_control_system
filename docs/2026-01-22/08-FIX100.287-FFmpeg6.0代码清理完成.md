```

```

**这是好消息！** 证明 FFmpeg 6.0 头文件已经生效。

---

## 🔍 问题分析

### FFmpeg API 演进

**旧版 API（FFmpeg 4.x/5.x）**:
```c
AVStream::codec  // AVCodecContext* 指针（已弃用）
```

**新版 API（FFmpeg 6.x）**:
```c
AVStream::codecpar  // AVCodecParameters* 指针（推荐）
AVStream::codec     // ❌ 已完全移除！
```

### 临时代码的历史

在 FIX 100.287 v1（临时修复）中，我们添加了旧版 API 回退逻辑：
1. 检测 codecpar 指针是否有效（0x200000000）
2. 如果无效 → 回退到 `streams[i]->codec`（旧版 API）
3. 如果有效 → 使用 `codecpar`（新版 API）

**这个回退逻辑现在不需要了**：
- rk3588-libs 头文件已更新为 v60
- codecpar 指针现在有效
- 旧版 API `streams[i]->codec` 已被 FFmpeg 6.0 完全移除 → 编译错误

1. **FIX 100.287 临时修复** → 添加旧版 API 回退逻辑
2. **FIX 100.287 v1** → 修复 PJSIP 环境 .pc 文件（v58 → v60）

### 技术要点

1. **头文件版本 > .pc 文件版本**
   - 头文件定义结构体布局（编译时）
   - .pc 文件只是元数据（链接时）
   - 头文件错误 → 结构体偏移量错误 → 运行时崩溃

2. **多构建环境管理**
   - PJSIP：pjsip-builder-persistent 容器
   - 应用程序：belt-control-fixed 容器
   - 每个环境需要独立检查和修复

3. **FFmpeg 6.0 迁移**
   - 完全移除了 `AVStream::codec` 字段
   - 必须使用 `AVStream::codecpar` API
   - 代码需要同步更新
