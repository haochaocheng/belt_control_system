## 二、问题原因

### 代码片段（错误代码）

```cpp
// AudioNetworkTcpSender.cpp 构造函数（第 82-83 行）
connect(m_senderWorker, &AudioSenderWorker::sendingStarted,
        this, &AudioNetworkTcpSender::playbackStarted);
```

### 信号和槽签名

**信号**（AudioSenderWorker.h）：
```cpp
void sendingStarted(int totalFrames);  // 参数：int
```

**槽**（AudioNetworkTcpSender.h）：
```cpp
void playbackStarted(const QString& fileName);  // 参数：const QString&
```

### 根本原因

Qt 的信号槽机制要求：
- **信号参数类型** 必须与 **槽参数类型** 兼容
- `int` 和 `const QString&` 不兼容
- 编译器在编译时进行静态断言检查，发现类型不匹配

### 为什么会出现这个错误？

在 FIX 100.295 实施独立发送线程时：
1. `AudioSenderWorker` 在独立线程中运行，只负责发送 Opus 帧
2. Worker 只知道发送了多少帧（`int totalFrames`），不知道文件名
3. 主线程的 `AudioNetworkTcpSender` 知道文件名（`QString fileName`）
4. 错误尝试将 worker 的 `sendingStarted(int)` 连接到主线程的 `playbackStarted(QString)`

---

## 三、解决方案

### 方案选择

**不连接 `sendingStarted` 信号**，而是在主线程的 `playAudioToNetwork()` 中直接发送 `playbackStarted` 信号。

**理由**：
- ✅ 主线程知道文件路径和文件名
- ✅ `playAudioToNetwork()` 是音频播放的入口点
- ✅ 在开始发送前就可以发送 `playbackStarted` 信号

### 修复代码

#### 1. AudioNetworkTcpSender.cpp 构造函数（第 81-94 行）

**修改前**（错误代码）：

**改进点**：

## 六、技术总结

### Qt 信号槽参数匹配规则

#### 规则 1：参数类型必须兼容

✅ **兼容示例**：
```cpp
// 信号
void sendingProgress(int framesSent, int totalFrames);

// 槽（完全匹配）
void playbackProgress(int framesSent, int totalFrames);
```

❌ **不兼容示例**：
```cpp
// 信号
void sendingStarted(int totalFrames);

// 槽（类型不兼容）
void playbackStarted(const QString& fileName);
```

#### 规则 2：槽参数可以少于信号参数

✅ **合法示例**：
```cpp
// 信号
void sendingProgress(int framesSent, int totalFrames);

// 槽（只接收第一个参数）
void updateProgress(int framesSent);
```

#### 规则 3：使用 lambda 转换参数

✅ **转换示例**：
```cpp
// 信号：int → 槽：QString
connect(m_senderWorker, &AudioSenderWorker::sendingStarted,
        this, [this](int totalFrames) {
    QString message = QString("开始发送 %1 帧").arg(totalFrames);
    emit playbackStarted(message);
});
```

### 本次修复的选择

**不使用 lambda 转换**，原因：
1. Worker 线程不知道文件名
2. 文件名只在主线程的 `playAudioToNetwork()` 中可用
3. 直接在主线程发送 `playbackStarted` 更简洁

## 八、经验教训

### 1. 信号槽设计原则

在多线程架构中设计信号槽时：
- **明确职责**：每个线程只知道自己负责的数据
- **参数传递**：信号参数应该是线程能访问的数据
- **类型匹配**：编译时会检查参数类型兼容性

### 2. 跨线程通信最佳实践

**独立线程应该**：
- ✅ 只传递自己能计算的数据（如进度、完成状态）
- ✅ 不依赖主线程的上下文信息（如文件名）

**主线程应该**：
- ✅ 负责发送包含上下文信息的信号（如文件名）
- ✅ 接收独立线程的进度和状态信号

### 3. 编译错误诊断技巧

Qt 编译错误信息通常很详细：
```
'QtPrivate::CheckCompatibleArguments<QtPrivate::List<int>, QtPrivate::List<const QString&> >::value' evaluates to false
```

**关键信息**：
- `QtPrivate::List<int>` → 信号参数类型
- `QtPrivate::List<const QString&>` → 槽参数类型
- `evaluates to false` → 类型不兼容

**诊断步骤**：
1. 找到错误行数（第 82 行）
2. 查看信号定义（`sendingStarted(int)`）
3. 查看槽定义（`playbackStarted(const QString&)`）
4. 确认类型不匹配
5. 选择修复方案
