#### FIX 100.291 - 频繁重连修复

**问题**：每 30 秒 UDP 广播触发一次重连，导致音频帧丢失

**解决方案**：
```cpp
// 缓存当前连接的服务器信息
QString m_currentConnectedIp;
quint16 m_currentConnectedPort;

// 检查是否已连接到同一服务器
if (m_wsClient->isConnected()) {
    if (m_currentConnectedIp == targetIp && m_currentConnectedPort == targetPort) {
        return;  // 忽略 UDP 广播
    }
}
```

**效果**：避免不必要的重连，音频传输稳定

**相关文档**：FIX 100.291

#### FIX 100.293 - 40ms 预缓冲机制

**问题**：前 0.6 秒正常，之后出现 11-24ms 延迟

**根本原因**：TCP 发送缓冲区积压（前期发送过快）

**解决方案**：
```cpp

m_sendStartTime = timer.elapsed() + 40;
```

**效果**：消除前期积压，延迟稳定在 20ms

### 阶段 3：独立线程架构（2026-01-22 下午）

#### FIX 100.295 - 独立发送线程

**核心思路**：将音频发送逻辑移到独立线程，完全隔离主线程干扰

**架构设计**：
```
主线程：
├─ UDP 服务发现（监听 8600）
├─ WebSocket 连接管理（TCP + 心跳）
├─ 音频编码（FFmpeg + Opus）
└─ Opus 缓存管理

独立线程（专用事件循环）：
└─ AudioSenderWorker
   ├─ Qt::PreciseTimer（精确定时）
   ├─ 40ms 预缓冲
   ├─ 绝对时间戳控制（startTime + frameIndex * 20ms）
   └─ 跨线程调用 WebSocketClient::sendBinaryFrame()
```

**核心代码**：

1. **AudioSenderWorker.h** - 独立线程工作对象
```cpp
class AudioSenderWorker : public QObject
{
    Q_OBJECT
public:
    explicit AudioSenderWorker(WebSocketClient* wsClient, QObject *parent = nullptr);

public slots:
    void startSending(const QList<QByteArray>& frames);
    void stopSending();

private slots:
    void sendNextFrame();  // 20ms 精确定时

private:
    WebSocketClient* m_wsClient;
    QTimer* m_sendTimer;  // Qt::PreciseTimer
    QElapsedTimer m_elapsedTimer;
    qint64 m_sendStartTime;
};
```

2. **绝对时间戳控制算法**
```cpp
void AudioSenderWorker::sendNextFrame()
{
    qint64 currentTime = m_elapsedTimer.elapsed();

    // 发送当前帧
    const QByteArray& opusFrame = m_frames[m_currentFrameIndex];
    QMetaObject::invokeMethod(m_wsClient, "sendBinaryFrame",
                              Qt::QueuedConnection,
                              Q_ARG(QByteArray, opusFrame));

    m_currentFrameIndex++;

    // 核心公式：下一帧应该发送的绝对时间戳
    qint64 nextFrameAbsoluteTime = m_sendStartTime + m_currentFrameIndex * 20;
    qint64 delay = nextFrameAbsoluteTime - currentTime;

    // 调度下一帧
    if (delay > 0) {
        m_sendTimer->start(delay);  // 延迟发送
    } else {
        m_sendTimer->start(0);      // 已延迟，立即发送
    }
}
```

#### FIX 100.295.1 - 跨线程调用修复

**问题**：WebSocketClient 被移动到独立线程后，跨线程调用 QTcpSocket 导致错误

**错误日志**：
```
[WARNING] QAbstractSocket::connectToHost() called when already connecting
[WARNING] ❌ TCP错误：SocketError(19) – "Trying to connect while connection is in progress"
```

**根本原因**：
- UDP 服务发现在主线程
- connectToServer() 在主线程调用
- 但 WebSocketClient 在独立线程
- **跨线程直接访问 QTcpSocket → 线程冲突**

**解决方案**：

1. **WebSocketClient 保持在主线程**
```cpp
// ❌ 错误代码
m_wsClient->moveToThread(m_senderThread);

// ✅ 正确代码（删除 moveToThread）
m_senderWorker->moveToThread(m_senderThread);
// m_wsClient 保持在主线程
```

2. **sendBinaryFrame 改为 public slot**
```cpp
// WebSocketClient.h
public slots:
    void sendBinaryFrame(const QByteArray& data);
```

3. **使用 Qt::QueuedConnection 跨线程调用**
```cpp
// AudioSenderWorker.cpp
QMetaObject::invokeMethod(m_wsClient, "sendBinaryFrame",
                          Qt::QueuedConnection,
                          Q_ARG(QByteArray, opusFrame));
```

**工作原理**：
```
【独立线程】AudioSenderWorker::sendNextFrame()
    ↓
QMetaObject::invokeMethod(..., Qt::QueuedConnection)
    ↓
Qt 事件系统（线程安全队列）
    ↓
【主线程】WebSocketClient::sendBinaryFrame()
    ↓
m_socket->write(frame)  ← 在主线程执行
```

### 关键技术点

#### 1. Qt 线程模型

**moveToThread() 的正确理解**：
- ✅ 只改变对象的事件循环所在线程
- ❌ **不改变线程安全性**（对象方法必须在所在线程调用）

**跨线程通信**：
- ✅ 信号槽（Qt::QueuedConnection）
- ✅ QMetaObject::invokeMethod()
- ❌ 直接调用对象方法

#### 2. 绝对时间戳控制算法

**核心公式**：
```cpp
nextFrameAbsoluteTime = startTime + frameIndex * 20ms
delay = nextFrameAbsoluteTime - currentTime
```

**优势**：
- ✅ 避免累积误差（每帧独立计算）
- ✅ 自动补偿延迟（delay < 0 时立即发送）
- ✅ 稳定 20ms 间隔（误差 ± 1ms）

#### 3. Qt::PreciseTimer

**精度对比**：
| 定时器类型 | 精度 | 适用场景 |
|-----------|------|---------|
| Qt::CoarseTimer | ±5% | 一般应用 |
| Qt::PreciseTimer | ±1ms | 音频/视频 |
| Qt::VeryCoarseTimer | ±500ms | 低精度任务 |

**使用方式**：
```cpp
m_sendTimer->setTimerType(Qt::PreciseTimer);
m_sendTimer->setSingleShot(true);  // 单次触发（手动调度）
```

## 六、经验教训

### 1. Qt 线程模型理解

**错误认知**：
- ❌ 以为把对象移动到线程就可以在任何线程调用
- ❌ 以为 QTcpSocket 是线程安全的

**正确认知**：
- ✅ moveToThread() 只改变对象的事件循环所在线程
- ✅ 对象的方法必须在对象所在线程调用
- ✅ 跨线程调用必须使用信号槽或 QMetaObject::invokeMethod()

### 2. 架构设计原则

**独立线程应该**：
- ✅ 只负责单一职责（定时发送）
- ✅ 不管理网络连接（TCP 连接、心跳）
- ✅ 通过信号槽与主线程通信

**主线程应该**：
- ✅ 管理所有 I/O 对象（Socket、文件）
- ✅ 处理系统事件（UDP 发现、用户交互）
- ✅ 协调多个模块

### 3. 性能优化思路

**问题分析流程**：
1. 添加日志，测量实际延迟
2. 分析延迟模式（前期/后期/随机）
3. 定位根本原因（缓冲区/定时器/线程竞争）
4. 验证修复效果（再次测量）

**优化优先级**：
1. **架构级优化**（独立线程）> 算法优化 > 参数调优
2. **测量先于优化**（没有测量就没有优化）
3. **验证修复效果**（每次修复后必须测量）

### 4. 调试技巧

**跨线程错误诊断**：
```cpp
// 检查对象所在线程
qDebug() << obj->thread();

// 检查调用所在线程
qDebug() << QThread::currentThread();

// 确认是否跨线程调用
if (obj->thread() != QThread::currentThread()) {
    qWarning() << "跨线程调用！";
}
```
