## 二、解决方案

### 删除废弃的函数

删除以下两个废弃函数（独立线程模式下已不再使用）：

1. **AudioNetworkSender.cpp** - 删除 `onFrameTimerTimeout()` 实现（第 309-325 行）
2. **AudioNetworkSender.h** - 删除 `onFrameTimerTimeout()` 声明（第 155 行）
3. **AudioNetworkSender.h** - 删除 `sendNextFrame()` 声明（第 210 行）

### 为什么可以安全删除

#### 1. onFrameTimerTimeout() 已废弃

**触发条件**：
```cpp
connect(m_frameTimer, &QTimer::timeout,
        this, &AudioNetworkSender::onFrameTimerTimeout);
```

**但是**：
```cpp
// AudioNetworkSender.cpp:126-131（构造函数）
// ❌ 2026-01-22 22:55 [已废弃] 主线程定时器精度不够,改用独立线程
/* 旧代码:
m_frameTimer = new QTimer(this);
m_frameTimer->setTimerType(Qt::PreciseTimer);
connect(m_frameTimer, &QTimer::timeout,
        this, &AudioNetworkSender::onFrameTimerTimeout);
*/
```

**结论**：`m_frameTimer` 已废弃，不会触发此回调。

#### 2. 独立线程接管发送逻辑

**新的发送流程**：
```cpp
// AudioNetworkSender.cpp:246-248
QMetaObject::invokeMethod(m_senderWorker, "startSending",
                          Qt::QueuedConnection,
                          Q_ARG(QList<QByteArray>, m_currentFrames));
```

**独立线程中的定时发送**：
```cpp
// AudioSenderWorkerUdp.cpp
void AudioSenderWorkerUdp::sendNextFrame()
{
    // 独立线程版本，使用 Qt::PreciseTimer
    // 20ms ±1ms 精度，不受主线程干扰
    qint64 nextFrameAbsoluteTime = m_sendStartTime + m_currentFrameIndex * 20;
    // ...
}
```

**结论**：发送逻辑已完全由 `AudioSenderWorkerUdp` 接管。
