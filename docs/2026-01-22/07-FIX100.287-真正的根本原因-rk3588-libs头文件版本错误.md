### 分析 4: 头文件版本验证（❌ 发现问题！）

```bash
$ grep "LIBAVFORMAT_VERSION_MAJOR" \
  docker/rk3588/rk3588-libs/include/libavformat/version.h

#define LIBAVFORMAT_VERSION_MAJOR  58  ← FFmpeg 4.x/5.x (错误！)
```

**找到根本原因！**

应用程序编译时：
- ✅ .pc 文件：v60.16.100（正确）
- ❌ 头文件：v58（错误！）
- 结果：CMake 使用 v58 的 AVStream 结构定义（没有 codecpar 字段）
- 运行时加载：FFmpeg 6.0 库（有 codecpar 字段）
- 崩溃：结构体偏移量不匹配 → codecpar 读取垃圾值 0x200000000

---

## 🔧 真正的修复

### 修复操作

```bash
# 删除旧的 FFmpeg 4.x/5.x 头文件
cd docker/rk3588/rk3588-libs/include
rm -rf libav* libsw* libpostproc

# 复制 FFmpeg 6.0 头文件
cp -r ../ffmpeg60-libs/opt/ffmpeg-rockchip/include/* .
```

### 验证修复

```bash
$ cat docker/rk3588/rk3588-libs/include/libavformat/version_major.h
#define LIBAVFORMAT_VERSION_MAJOR  60  ← 正确！
```

## 📚 技术总结

### 学到的教训

1. **多构建环境问题**
   - PJSIP 和应用程序使用不同的编译容器
   - 每个容器有独立的 sysroot 和依赖库路径
   - 修复一个环境不会影响另一个环境

2. **头文件比 .pc 文件更重要**
   - .pc 文件只是元数据（版本号、路径）
   - **头文件定义了结构体布局**
   - 头文件版本错误 → 结构体偏移量错误 → 崩溃

3. **验证方法**
   - 不能只检查 .pc 文件版本
   - 必须检查实际使用的头文件版本
   - 使用 `grep LIBAVFORMAT_VERSION_MAJOR` 验证

4. **相信用户**
   - 用户说执行了清理步骤，就应该相信
   - 问题不在用户操作，在代码逻辑
   - 应该深入分析而不是怀疑操作
