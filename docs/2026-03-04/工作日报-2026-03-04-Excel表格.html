dmix 采样率 24kHz 不被 ES8388 支持 — 全链路改为 48kHz 重要且紧急 ✅ 完成 75 分钟 ✅ Phase 7.47.91（09:32-10:07，3次提交）。恢复直接播放后设备仍完全无声，日志显示 ALSA 从启动开始持续报错：「unable to install hw params / unable to initialize slave」。关键线索：不打开程序在设备上 aplay 播放正常。根因：Phase 7.47.90 将 detect-audio-device.sh 的 dmix rate 从 48000 改为 24000（想与 TTS WAV 24kHz 一致），但 dmix 插件直接对硬件调用 snd_pcm_hw_params()，不做采样率转换——ES8388 芯片不支持 24kHz（支持列表：8k/11k/16k/22k/32k/44.1k/48k/88.2k/96k）。三步修复：① 将 dmix rate 恢复为 48000；② C++ 和 Python TTS 默认采样率改为 48000；③ QML 采样率下拉框默认改为 48000Hz。修改文件：detect-audio-device.sh、CommonControl.cpp、TTSConfigSection.qml。
TTS 模型固定输出 24kHz — 添加后处理重采样与音量归一化 重要不紧急 ✅ 完成 60 分钟 ✅ Phase 7.47.92（10:26提交）。尽管 C++ 端传 sample_rate=48000 给 Python TTS 服务端，生成的 WAV 仍为 24kHz。根因：fastspeech2_csmsc 声学模型 + hifigan_csmsc 声码器都在 24kHz 训练，PaddleSpeech 的 fs 参数对这些模型无效——模型内部固定 24kHz 输出。同时用户反馈 TTS 音量过小。方案：在 Python 端 TTS 合成后添加后处理步骤——① librosa.resample(24000→48000) 重采样；② numpy 峰值归一化到 target_peak=0.95（-0.45dB），确保音量充足且不削波。修改文件：tts_engines/paddlespeech_api.py。
音频播放卡顿根因 — 缺少 gstreamer1.0-alsa 包 重要且紧急 ✅ 完成 60 分钟 ✅ Phase 7.47.93（11:43提交）。从 3月3日 Phase 7.47.73 至今，音频播放一直存在卡顿，多种方案均失败（QSoundEffect/dmix24kHz/移除setSource/延迟play/重采样48kHz）。真正根因：Docker 容器缺少 gstreamer1.0-alsa 包，GStreamer autoaudiosink 的音频输出回退链过长——PulseAudio→Jack→OSS4→PipeWire 全部失败（每次 20-30ms），最终回退到 OpenAL 间接输出（rank=128），OpenAL 缓冲管理不如 alsasink 直接高效，导致卡顿。安装 gstreamer1.0-alsa 后，alsasink（rank=256）优先级高于 OpenAL，GStreamer 直接输出到 ALSA，卡顿彻底消除。修改文件：Dockerfile.ubuntu24-apt（添加 gstreamer1.0-alsa）。

报警播放改为"最后触发优先"逻辑 重要不紧急 ✅ 完成 25 分钟 ✅ Phase 7.48.2（15:29提交）。用户需求：每个保护触发都从最后一个触发开始从 0 计次数，旧的播放立即停止不再继续。旧逻辑（队列累积模式）：触发 A 播放中再触发 B→B 入队→A 播完→取 B 播放。新逻辑（最后触发优先）：触发 A 播放中再触发 B→立即 stopCurrentPlayback()→清空队列→从 count=0 开始播放 B。效果：同时只有一个保护在播放，始终从第 1 次开始计数，快速连续触发时只播放最后一个。修改文件：AlarmPlaybackService.cpp（onAlarmTriggered 方法替换队列逻辑）。
SQL 注释语法错误导致"播放方式"保存失败 重要且紧急 ✅ 完成 25 分钟 ✅ Phase 7.48.3（15:46提交）。切换到"按时长"模式点击保存，日志显示「Parameter count mismatch」。根因：DeviceConfigManager.cpp 的 CREATE TABLE SQL 字符串（R"(...)" 原始字符串）中使用了 // C++ 注释——SQL 只认 -- 行注释，// 被解析为语法错误→CREATE TABLE 失败→函数 return false 提前退出→后续 ALTER TABLE 迁移（添加 play_mode、protection_level 列）从不执行→表缺少新列→INSERT 包含这些列时参数数量不匹配。修复：① 将 SQL 字符串中所有 // 改为 --；② 移除 CREATE TABLE 失败后的 return false（已存在的表会报错但不影响后续 ALTER TABLE）。同时修复 device_analog_protections 表的相同问题。修改文件：DeviceConfigManager.cpp（CREATE TABLE 两处 SQL 注释 + 两处 return false 移除）。
