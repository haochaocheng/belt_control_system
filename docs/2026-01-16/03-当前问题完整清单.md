## 📌 核心问题

### 问题描述
**PJSIP 视频通话中，libx264 编码器初始化成功，但编码时失败**

### 症状表现
1. ✅ `avcodec_open2(ff->enc_ctx, ff->enc)` 返回 0（初始化成功）
2. ✅ 日志显示"Encoder opened successfully"
3. ❌ `avcodec_send_frame()` 返回 -22 (EINVAL)
4. ❌ 编码器内部状态 `x4->enc = NULL`（编码器未初始化）
5. ❌ 对方看不到本机视频

### 关键矛盾
- **初始化时**：`avcodec_open2()` 返回成功
- **编码时**：内部状态 `x4->enc` 为空，编码器实际未初始化

---

## 🔍 根本原因（已确定）⭐

### 原因分析
**FFmpeg 的帧级多线程编码器（Frame Thread Encoder）机制导致主上下文未初始化**

### 详细机制

#### 1. FFmpeg 多线程初始化流程（RK3588 设备）
```
PJSIP 调用 avcodec_open2(main_avctx)
    │
    ├─ Step 1: 分配 main_avctx->priv_data (X264Context)
    │   └─ ⚠️ 此时 x4->enc = NULL（未初始化）
    │
    ├─ Step 2: ff_encode_preinit()
    │   └─ ff_frame_thread_encoder_init()
    │       ├─ 检测 thread_count = av_cpu_count() = 9
    │       ├─ 创建 9 个子上下文（独立的 AVCodecContext）
    │       └─ 每个子上下文调用 avcodec_open2() → X264_init() ✅
    │           └─ 子上下文的 x4->enc 被正确初始化
    │
    ├─ Step 3: ff_thread_init()
    │   └─ 设置 active_thread_type = FF_THREAD_FRAME
    │
    ├─ Step 4: 条件判断（avcodec.c:452）
    │   ├─ if (!(active_thread_type & FF_THREAD_FRAME) || frame_thread_encoder)
    │   ├─     则调用 codec->init() → X264_init()
    │   ├─ ⚠️ 条件为假，跳过 codec->init()
    │   └─ ❌ 主上下文的 X264_init() 未被调用
    │
    └─ Step 5: 返回成功
        └─ ❌ 但主上下文的 x4->enc = NULL（未初始化）
```

#### 2. 关键证据
- **日志显示**：`X264_init()` 被调用 9 次（全部是子上下文）
- **源码证据**：`avcodec.c:452` 条件判断跳过主上下文的 `codec->init()`
- **FFmpeg 设计**：帧级多线程模式下，主上下文是"空壳"（仅用于任务分发）

#### 3. PJSIP 的假设冲突
- **PJSIP 假设**：`avcodec_open2()` 成功后，传入的上下文可直接编码
- **FFmpeg 实际**：多线程模式下，主上下文不包含实际编码器
- **冲突结果**：PJSIP 使用主上下文编码 → `x4->enc = NULL` → 失败

- 说明编码器状态在两次调用之间发生了变化

## ✅ 已设计的解决方案（待实施）

### FIX 100.213 - 禁用 FFmpeg 帧级多线程，使用 libx264 内部多线程 ⭐⭐⭐

#### 理论依据

1. **FFmpeg 官方推荐**：
   - `thread_type = 0`：禁用 FFmpeg 帧级多线程
   - `thread_count = 0`：让编码器自动选择线程数

2. **libx264 内部多线程**：
   - libx264 有自己的多线程实现（`x264_param_t.i_threads`）
   - 读取 `avctx->thread_count`，如果为 0，则自动设置为 `CPU × 1.5`
   - RK3588: 9 核 × 1.5 ≈ 13 线程

3. **网上推荐配置**：
   - 所有 FFmpeg libx264 教程都推荐此配置
   - 无人报告需要强制单线程
   - 质量损失在 16 线程以下几乎可忽略

#### 修改方案

**文件**: `cross-compile/src/pjproject-2.16/pjmedia/src/pjmedia-codec/ffmpeg_vid_codecs.c`
**位置**: Line 684-710（libx264 参数设置）

```c
/* ✅ 2026-01-16 11:00 [FIX 100.213 - 使用 libx264 内部多线程]
 * 根本原因（FFmpeg 源码分析）：
 *   1. FFmpeg 帧级多线程创建 9 个子上下文（每个调用 X264_init()）
 *   2. 主上下文的 X264_init() 被故意跳过（avcodec.c:452 条件判断）
 *   3. PJSIP 编码时使用主上下文 → x4->enc = NULL → 失败
 *
 * 解决方案：
 *   - thread_type = 0：禁用 FFmpeg 帧级多线程
 *   - thread_count = 0：启用 libx264 内部多线程（auto）
 *
 * 效果：
 *   ✅ 主上下文被 X264_init() 正确初始化
 *   ✅ 保持多线程编码性能（libx264 内部）
 *   ✅ 符合网上推荐的 FFmpeg libx264 配置
 *
 * 参考文档：
 *   - docs/2026-01-16/02-FFmpeg源码深度分析-主上下文未初始化根因.md
 *   - https://trac.ffmpeg.org/wiki/Encode/H.264#Threads
 */

ctx->thread_count = 0;   // libx264 auto（内部多线程）
ctx->thread_type = 0;    // 禁用 FFmpeg 帧级多线程

PJ_LOG(1, (THIS_FILE, "   ✅ GOP: gop_size=%d, keyint_min=%d, max_b_frames=%d",
           ctx->gop_size, ctx->keyint_min, ctx->max_b_frames));
PJ_LOG(1, (THIS_FILE, "   ✅ [FIX 100.213] Thread: libx264 internal (thread_count=0, thread_type=0)"));
PJ_LOG(1, (THIS_FILE, "      FFmpeg frame threading: DISABLED"));
PJ_LOG(1, (THIS_FILE, "      libx264 will auto-select thread count (CPU × 1.5)"));
```

#### 预期效果

1. **初始化时**：
   - `X264_init()` 只被调用 1 次（主上下文）
   - `x4->enc` 非 NULL
   - 编码器成功打开

2. **编码时**：
   - `avcodec_send_frame()` 返回 0（成功）
   - 视频正常编码
   - 对方可以看到视频

3. **性能**：
   - libx264 内部自动使用多线程（约 13 线程）
   - 编码性能与多线程模式相当
   - 内存占用更低（1 个编码器实例 vs 9 个）
