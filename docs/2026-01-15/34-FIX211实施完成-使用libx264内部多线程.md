## 🎯 核心修改

### 问题回顾

**根本原因**（完整分析见 [33-FFmpeg线程问题完整根因分析.md](33-FFmpeg线程问题完整根因分析.md)）：

1. **PJSIP 设置**：`thread_count=1, thread_type=0`（强制单线程）
2. **FFmpeg 覆盖**：使用默认值 `thread_type=FF_THREAD_FRAME`（Line 366 in options_table.h）
3. **libx264 不支持 FFmpeg 帧线程**：没有 `AV_CODEC_CAP_FRAME_THREADS`
4. **错误应用解码器线程**：`ff_thread_init()` 创建 9 个子上下文
5. **主上下文未初始化**：只有子上下文被 `X264_init()` 初始化
6. **编码失败**：`x4->enc = NULL` → `avcodec_send_frame()` 返回 -22

---

## ✅ FIX 100.211 解决方案

### 核心思路

**使用 libx264 的内部多线程机制**（`AV_CODEC_CAP_OTHER_THREADS`）：

- libx264 封装了 x264 库，x264 有自己的高性能多线程实现
- 不需要 FFmpeg 的帧线程（`FF_THREAD_FRAME`）
- 只需设置 `thread_count`，libx264 会传递给 x264 使用

**关键代码**（libx264.c Line 1454）：
```c
x4->params.i_threads = avctx->thread_count;
```

### validate_thread_parameters() 验证

**文件**: `pthread.c` Line 48-69

```c
static void validate_thread_parameters(AVCodecContext *avctx)
{
    int frame_threading_supported = (avctx->codec->capabilities & AV_CODEC_CAP_FRAME_THREADS)
                                && !(avctx->flags  & AV_CODEC_FLAG_LOW_DELAY)
                                && !(avctx->flags2 & AV_CODEC_FLAG2_CHUNKS);

    if (avctx->thread_count == 1) {
        avctx->active_thread_type = 0;
    } else if (frame_threading_supported && (avctx->thread_type & FF_THREAD_FRAME)) {
        avctx->active_thread_type = FF_THREAD_FRAME;
    } else if (avctx->codec->capabilities & AV_CODEC_CAP_SLICE_THREADS &&
               avctx->thread_type & FF_THREAD_SLICE) {
        avctx->active_thread_type = FF_THREAD_SLICE;
    } else if (!(ffcodec(avctx->codec)->caps_internal & FF_CODEC_CAP_AUTO_THREADS)) {
        avctx->thread_count       = 1;
        avctx->active_thread_type = 0;
    }
}
```

**预期执行路径**（thread_count=4）：

1. `thread_count == 1`？ **NO**（我们设置为 4）
2. `frame_threading_supported`？ **NO**（libx264 没有 AV_CODEC_CAP_FRAME_THREADS）
3. `AV_CODEC_CAP_SLICE_THREADS`？ **NO**（libx264 没有）
4. **进入 else 分支**：
   - 检查 `FF_CODEC_CAP_AUTO_THREADS`
   - 如果 libx264 没有这个标志，会重置 `thread_count = 1, active_thread_type = 0`

**关键问题**：需要验证 libx264 是否有 `FF_CODEC_CAP_AUTO_THREADS`！

## 🤔 潜在问题分析

### 问题 #1：libx264 可能没有 FF_CODEC_CAP_AUTO_THREADS

如果 libx264 没有 `FF_CODEC_CAP_AUTO_THREADS`，`validate_thread_parameters()` 会：
```c
avctx->thread_count       = 1;  ← 重置为 1！
avctx->active_thread_type = 0;
```

**后果**：
- ❌ `thread_count` 被重置为 1
- ✅ `active_thread_type = 0`（不会触发 FFmpeg 线程）
- ✅ 主上下文应该被初始化
- ❓ 但 libx264 只使用 1 线程（性能损失）

---

### 问题 #2：如果 libx264 有 FF_CODEC_CAP_AUTO_THREADS

如果 libx264 有这个标志，`validate_thread_parameters()` 不会重置：
```c
// 不进入 else 分支
avctx->thread_count       = 4;  ← 保持
avctx->active_thread_type = 0;  ← 默认值
```

**后果**：
- ✅ `thread_count = 4`
- ✅ libx264 使用 4 线程（`x4->params.i_threads = 4`）
- ✅ 主上下文应该被初始化
- ✅ 高性能多线程编码
