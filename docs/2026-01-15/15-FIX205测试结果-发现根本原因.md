### 结论

**100% 确定的根本原因**：

1. **PJSIP 调用 `avcodec_open2(ff->enc_ctx, libx264)`**
   - `ff->enc_ctx->priv_data = 0x7efc0386e0`（PJSIP 分配，未初始化）

2. **FFmpeg 在 `avcodec_open2()` 内部创建了新的 AVCodecContext**
   - 创建了 7 个新的 AVCodecContext
   - 每个都有新的 priv_data (X264Context)
   - 每个都被 `X264_init()` 正确初始化，`x4->enc` 有效

3. **`avcodec_open2()` 返回成功（err=0）**
   - 但 **PJSIP 的 `ff->enc_ctx` 指针没有被更新**
   - PJSIP 仍然持有旧的 `ff->enc_ctx` (0x7efc038320)
   - 旧的 `priv_data` (0x7efc0386e0) 从未被初始化

4. **编码时 PJSIP 使用未初始化的 X264Context**
   - `x4->enc = NULL`
   - `reordered_opaque = NULL`
   - 编码返回 `-22 (EINVAL)`

## 3. 为什么 FFmpeg 创建了 7 个 AVCodecContext？

### 可能原因分析

**原因 1：PJSIP 注册了多个编码器配置（最可能）⭐⭐⭐⭐⭐**

PJSIP 可能为不同的视频格式/分辨率/码率注册了多个编码器实例：
- 640x480 @ 800 kbps
- 640x480 @ 1000 kbps
- 1280x720 @ 1500 kbps
- 等等...

每个配置都调用了 `avcodec_open2()`，FFmpeg 为每个配置创建了新的 AVCodecContext。

**原因 2：FFmpeg 内部编解码器协商（可能）⭐⭐⭐**

FFmpeg 可能在 `avcodec_open2()` 内部进行编解码器协商，创建多个实例用于测试兼容性。

**原因 3：多线程编码（不太可能）⭐**

FFmpeg 可能为多线程编码创建了多个实例，但 PJSIP 配置了 `thread_count=1`，不应该有多线程。

## 4. 为什么 PJSIP 的指针没有被更新？

### 可能的机制

**机制 A：FFmpeg 不修改传入的指针**

`avcodec_open2()` 的设计可能是：
```c
int avcodec_open2(AVCodecContext *avctx, const AVCodec *codec, AVDictionary **options)
{
    // FFmpeg 内部创建新的 AVCodecContext
    AVCodecContext *new_ctx = create_new_context();

    // 初始化新的上下文
    codec->init(new_ctx);

    // 但不修改 avctx 指针（只能修改 avctx 指向的内容）
    // avctx = new_ctx;  // ❌ 无效！不会影响调用者的指针

    return 0;
}
```

**C 语言限制**：函数无法修改调用者的指针变量（除非使用二级指针）。

**结果**：PJSIP 的 `ff->enc_ctx` 仍然指向旧的、未初始化的 AVCodecContext。

### 验证方法

如果 FFmpeg 确实替换了 AVCodecContext，应该有以下机制之一：

1. **返回新的指针**（需要修改 API）：
   ```c
   AVCodecContext *new_ctx = avcodec_open2(old_ctx, codec, options);
   ```

2. **使用二级指针**（需要修改 API）：
   ```c
   int avcodec_open2(AVCodecContext **avctx, const AVCodec *codec, AVDictionary **options);
   ```

3. **修改 avctx 内部字段**（当前 FFmpeg 的设计）：
   ```c
   // FFmpeg 应该在 avctx 内部更新字段，而不是创建新实例
   avctx->priv_data = new_priv_data;
   ```

## 5. 真正的问题：为什么 FFmpeg 不初始化 PJSIP 的 priv_data？

### 理论 1：FFmpeg 检测到重复注册 ⭐⭐⭐⭐⭐

**假设**：FFmpeg 检测到 `ff->enc_ctx` 已经被注册过（或参数不正确），所以跳过了初始化。

**验证**：需要查看 `avcodec_open2()` 源码，看是否有以下检查：
```c
if (avcodec_is_open(avctx))
    return 0;  // 已打开，直接返回
```

但 PJSIP 的 FIX 100.203 DIAG-D 日志显示，这是在调用 `avcodec_open2()` **之前**，所以 `avcodec_is_open()` 应该返回 false。

### 理论 2：FFmpeg 使用编码器池（最可能）⭐⭐⭐⭐⭐

**假设**：FFmpeg 内部有一个编码器池（类似连接池）。

**机制**：
1. PJSIP 调用 `avcodec_open2(ff->enc_ctx, libx264)`
2. FFmpeg 检测到 libx264 已经有 7 个实例在池中
3. FFmpeg 返回成功（err=0），但不初始化 PJSIP 的 `ff->enc_ctx`
4. FFmpeg 期望 PJSIP 从池中获取实例

**问题**：PJSIP 不知道有编码器池的存在，仍然使用自己的 `ff->enc_ctx`。

### 理论 3：PJSIP 传递了错误的参数

**假设**：PJSIP 在调用 `avcodec_open2()` 时传递了某些错误的参数，导致 FFmpeg 认为这个上下文无效。

**验证**：需要 DIAG-A 日志来确认传入的参数。

## 6. 如何修复？

### 修复方案 A：强制使用 PJSIP 的 AVCodecContext ⭐⭐⭐⭐⭐

**思路**：确保 FFmpeg 必须使用 PJSIP 分配的 AVCodecContext，不允许创建新的。

**实施位置**：PJSIP `ffmpeg_vid_codecs.c`

**方法 1：在 avcodec_open2() 后验证并强制初始化**

```c
/* ✅ 2026-01-16 00:20 [FIX 100.206] 强制初始化 PJSIP 的 X264Context */
err = AVCODEC_OPEN(ff->enc_ctx, ff->enc);

if (err == 0) {
    X264Context *x4 = (X264Context*)ff->enc_ctx->priv_data;

    /* 检查是否初始化 */
    if (!x4->enc || !x4->reordered_opaque) {
        PJ_LOG(1,(THIS_FILE, "⚠️ [FIX 100.206] X264Context not initialized!"));
        PJ_LOG(1,(THIS_FILE, "   Forcing X264_init() manually..."));

        /* 调用 X264_init() */
        extern int X264_init(AVCodecContext *avctx);
        int init_ret = X264_init(ff->enc_ctx);

        if (init_ret < 0) {
            PJ_LOG(1,(THIS_FILE, "❌ Manual X264_init() failed: %d", init_ret));
            status = PJMEDIA_CODEC_EFAILED;
            goto on_error;
        }

        /* 再次验证 */
        x4 = (X264Context*)ff->enc_ctx->priv_data;
        if (!x4->enc) {
            PJ_LOG(1,(THIS_FILE, "❌ x4->enc still NULL after manual init!"));
            status = PJMEDIA_CODEC_EFAILED;
            goto on_error;
        }

        PJ_LOG(1,(THIS_FILE, "✅ [FIX 100.206] Manual init succeeded!"));
        PJ_LOG(1,(THIS_FILE, "   x4->enc: %p", x4->enc));
    } else {
        PJ_LOG(1,(THIS_FILE, "✅ X264Context already initialized"));
        PJ_LOG(1,(THIS_FILE, "   x4->enc: %p", x4->enc));
    }
}
```

**优点**：
- ✅ 不修改 FFmpeg
- ✅ 直接解决问题
- ✅ 100% 确保 PJSIP 的 X264Context 被初始化

**缺点**：
- ❌ 破坏了 FFmpeg 的封装（调用内部函数 `X264_init()`）
- ❌ 版本兼容性差
- ⚠️ 需要声明 FFmpeg 内部函数

---

### 修复方案 B：重新分配 AVCodecContext ⭐⭐⭐

**思路**：如果检测到 priv_data 未初始化，关闭并重新打开编码器。

**实施位置**：PJSIP `ffmpeg_vid_codecs.c`

```c
/* ✅ 2026-01-16 00:25 [FIX 100.207] 重新打开编码器 */
err = AVCODEC_OPEN(ff->enc_ctx, ff->enc);

if (err == 0) {
    X264Context *x4 = (X264Context*)ff->enc_ctx->priv_data;

    if (!x4->enc || !x4->reordered_opaque) {
        PJ_LOG(1,(THIS_FILE, "⚠️ [FIX 100.207] priv_data not initialized, re-opening..."));

        /* 关闭 */
        avcodec_close(ff->enc_ctx);

        /* 重新分配 */
        avcodec_free_context(&ff->enc_ctx);
        ff->enc_ctx = avcodec_alloc_context3(ff->enc);
        if (!ff->enc_ctx) {
            status = PJ_ENOMEM;
            goto on_error;
        }

        /* 重新配置参数（使用最小参数）*/
        ff->enc_ctx->width = vfd->size.w;
        ff->enc_ctx->height = vfd->size.h;
        ff->enc_ctx->pix_fmt = AV_PIX_FMT_YUV420P;
        ff->enc_ctx->time_base = (AVRational){1, 30};
        ff->enc_ctx->bit_rate = 800000;

        /* 重新打开 */
        err = AVCODEC_OPEN(ff->enc_ctx, ff->enc);

        if (err == 0) {
            x4 = (X264Context*)ff->enc_ctx->priv_data;
            if (x4->enc) {
                PJ_LOG(1,(THIS_FILE, "✅ [FIX 100.207] Re-open succeeded!"));
            } else {
                PJ_LOG(1,(THIS_FILE, "❌ [FIX 100.207] Re-open failed!"));
                status = PJMEDIA_CODEC_EFAILED;
                goto on_error;
            }
        }
    }
}
```

**优点**：
- ✅ 不破坏 FFmpeg 封装
- ✅ 使用 FFmpeg 公开 API

**缺点**：
- ⚠️ 增加延迟（50-100ms）
- ⚠️ 如果重新打开仍然失败，无法解决

### 修复方案 C：修改 FFmpeg avcodec_open2() ⭐⭐

**思路**：修改 FFmpeg 源码，确保 `avcodec_open2()` 总是初始化传入的 AVCodecContext。
