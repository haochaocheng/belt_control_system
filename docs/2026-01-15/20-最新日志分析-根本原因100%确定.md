## 🔍 根本原因分析

### 问题流程

1. **PJSIP 分配 AVCodecContext**：
   ```c
   ff->enc_ctx = avcodec_alloc_context3(ff->enc);
   // ff->enc_ctx: 0x7ed8036d20
   // ff->enc_ctx->priv_data: 0x7ed80370e0 (未初始化)
   ```

2. **PJSIP 调用 avcodec_open2()**：
   ```c
   err = AVCODEC_OPEN(ff->enc_ctx, ff->enc);
   // 返回 err=0 (成功)
   // ff->enc_ctx 指针没有改变
   // ff->enc_ctx->priv_data 也没有改变
   ```

3. **FFmpeg 在 avcodec_open2() 内部创建新的 AVCodecContext**：
   ```
   AVCodecContext (新): 0x7e944d1240
   priv_data (新): 0x7e944d16c0
   ```

4. **FFmpeg 调用 X264_init() 初始化新的实例**：
   ```
   X264_init(0x7e944d1240);  // 新的 AVCodecContext
   // 成功初始化 priv_data: 0x7e944d16c0
   // x4->enc: 0x7e944d1fc0 (有效)
   ```

5. **avcodec_open2() 返回成功，但没有更新 PJSIP 的指针**：
   ```c
   // PJSIP 的 ff->enc_ctx 仍然指向旧的、未初始化的实例
   // ff->enc_ctx: 0x7ed8036d20
   // ff->enc_ctx->priv_data: 0x7ed80370e0 (未初始化)
   ```

6. **编码时使用未初始化的实例**：
   ```c
   X264Context *x4 = (X264Context*)ff->enc_ctx->priv_data;
   // x4: 0x7ed80370e0 (未初始化)
   // x4->enc: NULL
   // 编码失败，返回 -22 (EINVAL)
   ```

### C 语言指针限制

**为什么 FFmpeg 不能更新 PJSIP 的指针？**

```c
int avcodec_open2(AVCodecContext *avctx, const AVCodec *codec, AVDictionary **options)
{
    // FFmpeg 内部创建新实例
    AVCodecContext *new_ctx = create_new_context();

    // 初始化新实例
    codec->init(new_ctx);  // X264_init()

    // 但无法修改调用者的指针（C 语言限制）
    // avctx = new_ctx;  // ❌ 这不会影响 PJSIP 的 ff->enc_ctx

    return 0;
}
```

**C 语言规则**：
- 函数接收的是指针的**值**（地址），不是指针本身
- 修改指针值不会影响调用者的指针变量
- 除非使用二级指针：`AVCodecContext **avctx`

## ❌ 为什么这不是 FFmpeg 的 Bug

### 1. 标准 FFmpeg 使用模式

查看 FFmpeg 官方示例（`doc/examples/encode_video.c`）：

```c
AVCodecContext *enc_ctx = avcodec_alloc_context3(codec);

// 配置参数
enc_ctx->width = 640;
enc_ctx->height = 480;
enc_ctx->pix_fmt = AV_PIX_FMT_YUV420P;

// 打开编码器
int ret = avcodec_open2(enc_ctx, codec, NULL);

// ✅ 直接使用 enc_ctx 编码
avcodec_send_frame(enc_ctx, frame);
```

**关键**：
- ✅ avcodec_open2() 应该初始化传入的 `enc_ctx`
- ✅ 不应该创建新的 AVCodecContext
- ✅ 标准用法中，priv_data 会被正确初始化

### 2. 为什么 PJSIP 的情况不同？

**可能原因 A：PJSIP 配置了特殊参数**

PJSIP 可能设置了某些参数，导致 FFmpeg 认为需要重新创建 AVCodecContext。

**可能原因 B：PJSIP 多次调用 avcodec_open2()**

PJSIP 可能在内部多次调用 `avcodec_open2()`：
- 第一次：使用 PJSIP 的 enc_ctx（未初始化）
- 后续 8 次：FFmpeg 创建新的 enc_ctx（成功初始化）

**可能原因 C：FFmpeg 版本特定问题**

FFmpeg 6.1 可能有特定的行为，导致在某些情况下重新创建 AVCodecContext。

### 3. 9 次 X264_init() 调用之谜

**日志显示**：X264_init() 被调用了 9 次

**PJSIP 配置**：
- 注册了 8 个编解码器
- 只有 H264 使用 libx264
- 那么其他 8 次从哪来？

**可能的解释**：
1. **FFmpeg 编解码器协商**：FFmpeg 测试多个配置（不同分辨率、码率）
2. **PJSIP 多编码器实例**：PJSIP 为不同场景创建多个 H264 编码器
3. **FFmpeg 线程初始化**：多线程编码时，每个线程创建一个实例（但 PJSIP 配置了 `thread_count=1`）
