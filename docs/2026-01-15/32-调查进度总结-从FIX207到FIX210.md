### 2026-01-16 08:10 - FIX 100.209 测试成功
- **关键发现**:
  - BEFORE ff_thread_init(): `thread_count=0`（不是 1！）
  - AFTER ff_thread_init(): `thread_count=9, active_thread_type=FF_THREAD_FRAME`
  - Decision: **SKIP** codec->init() 块（多线程路径）
- **结论**: FFmpeg 在某处将 thread_count 从 1 重置为 0，触发自动检测 → 9 线程

- **调查内容**:

  2. 阅读 FFmpeg encode.c 源码
  3. 理解子上下文创建机制
  4. 理解编码路径决策逻辑

- **关键发现**:
  1. **自动检测机制**（frame_thread_encoder.c Line 164-167）:
     ```c
     if(!avctx->thread_count) {
         avctx->thread_count = av_cpu_count();  // 自动检测 → 9
     }
     ```

  2. **子上下文创建**（frame_thread_encoder.c Line 196-227）:
     - FFmpeg 为每个线程创建独立的 AVCodecContext
     - 每个子上下文调用 avcodec_open2() → 触发 X264_init()
     - 主上下文设置 `active_thread_type = FF_THREAD_FRAME`

  3. **编码路径决策**（encode.c Line 346-351）:
     ```c
     if (CONFIG_FRAME_THREAD_ENCODER && avci->frame_thread_encoder)
         ret = ff_thread_video_encode_frame(...);  // 多线程
     else {
         ret = ff_encode_encode_cb(...);  // 单线程
     }
     ```
