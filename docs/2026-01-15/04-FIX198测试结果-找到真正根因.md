## 2. 真正的根本原因

### 问题：数组被清零或使用了错误的 X264Context 实例

**时间线**：
1. `X264_init()` 成功分配数组 → `x4->reordered_opaque = 0x7e8ebd53b0` ✅
2. **某个地方** `x4->reordered_opaque` 被设置为 NULL ❌
3. `setup_frame()` 读取到 `x4->reordered_opaque = NULL` ❌
4. `opaque = &NULL[0]` → `opaque = NULL` ❌
5. `opaque_uninit(NULL)` → 崩溃 ❌

---

## 3. 可能的原因分析

### 假设 1：X264Context 结构体被意外清零

**可疑位置**：
- PJSIP 的编码器暂停/恢复逻辑
- FFmpeg 内部的编码器重配置
- 多线程竞争

**证据**：
- `x4->nb_reordered_opaque = 0`（从 69 变成 0）
- `x4->reordered_opaque = NULL`（从有效地址变成 NULL）

**可能性**：60%

---

### 假设 2：使用了未初始化的 X264Context 实例

**可疑位置**：
- PJSIP 在编码器暂停/恢复时创建了新实例？
- FFmpeg 内部有多个 X264Context？

**证据**：
- DIAG-2 显示 9 个编码器实例被初始化（正常）
- DIAG-3 显示使用的实例没有初始化数组

**可能性**：30%

---

### 假设 3：X264_close() 被过早调用

**可疑位置**：
- 编码器暂停时可能调用了 `X264_close()`
- `X264_close()` 会调用 `av_freep(&x4->reordered_opaque)`

**证据**：
```c
// libx264.c Line 867-869
for (int i = 0; i < x4->nb_reordered_opaque; i++)
    opaque_uninit(&x4->reordered_opaque[i]);
av_freep(&x4->reordered_opaque);  // ← 释放数组
```

**可能性**：10%

## 6. 临时解决方案（如果调查无果）

### 方案 A：在 setup_frame() 中添加防御性检查

**修改位置**：FFmpeg `libx264.c` Line 551

```c
static int setup_frame(AVCodecContext *ctx, const AVFrame *frame,
                       x264_picture_t **ppic)
{
    X264Context *x4 = ctx->priv_data;

    /* ⚠️ 防御性检查：如果数组是 NULL，重新分配 */
    if (!x4->reordered_opaque || x4->nb_reordered_opaque == 0) {
        av_log(ctx, AV_LOG_ERROR,
               "[EMERGENCY] reordered_opaque array lost! Reallocating...\n");

        int delayed_frames = x264_encoder_maximum_delayed_frames(x4->enc);
        x4->nb_reordered_opaque = FFMAX(delayed_frames + 17, 1);
        x4->reordered_opaque = av_calloc(x4->nb_reordered_opaque,
                                        sizeof(*x4->reordered_opaque));
        if (!x4->reordered_opaque) {
            return AVERROR(ENOMEM);
        }
        x4->next_reordered_opaque = 0;
    }

    X264Opaque *opaque = &x4->reordered_opaque[x4->next_reordered_opaque];
    // ... 继续原有逻辑
}
```

**问题**：治标不治本，只是避免崩溃

## 7. 结论

✅ **FIX 100.198 诊断成功**：

1. **PJSIP 没有问题**：传递的 AVFrame 是干净的
2. **FFmpeg 初始化没有问题**：数组确实被分配了
3. **真正问题**：**数组在初始化后到第一次使用前被清零了**

❌ **不是我们之前怀疑的问题**：
- ❌ 不是 `nb_reordered_opaque = 0`（初始化时是 69）
- ❌ 不是 `av_buffer_unref(野指针)`（opaque_ref 是 NULL）
- ❌ 不是 PJSIP 传递了错误的 AVFrame

⚠️ **新问题**：
- **为什么 `x4->reordered_opaque` 从有效地址变成 NULL？**
- **谁清零了 `x4->nb_reordered_opaque`？**
