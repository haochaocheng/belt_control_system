## 2. 真正的根本原因

### 🔴 核心问题：有一个编码器实例被分配但未初始化

**证据链**：

1. **Line 1261**: PJSIP 分配 AVCodecContext，priv_data = `0x7ef00159f0`（在 `avcodec_open2()` 调用前）
2. **Line 1264-1298**: `avcodec_open2()` 成功，触发 `X264_init()`，但初始化的是**另一个实例** (`0x7ef062dba0`)
3. **Line 1831-1833**: 第一次编码时，使用的还是原始未初始化的实例 (`0x7ef00159f0`)
4. **结果**: `reordered_opaque = NULL` → 崩溃

---

## 3. 为什么会有两个不同的实例？

### 假设 1：FFmpeg 在 avcodec_open2() 中重新分配了 priv_data

**机制**：
```c
// 可能的流程
avcodec_alloc_context3()  → 分配 priv_data = 0x7ef00159f0
avcodec_open2()           → 重新分配 priv_data = 0x7ef062dba0 ✅
                          → 调用 X264_init() 初始化新实例 ✅
avcodec_send_frame()      → 使用旧的 priv_data = 0x7ef00159f0 ❌
```

**问题**：PJSIP 缓存了旧的 AVCodecContext 指针，而 FFmpeg 内部切换了 priv_data？

**可能性**：**70%**

---

### 假设 2：PJSIP 有两个 AVCodecContext 指针

**机制**：
```c
AVCodecContext *ctx1 = avcodec_alloc_context3();  // 0x7ef0015630
AVCodecContext *ctx2 = ...;                      // 0x7ef062d720

avcodec_open2(ctx2, ...);  // 初始化 ctx2 ✅
avcodec_send_frame(ctx1, ...);  // 使用 ctx1 ❌
```

**证据**：
- DIAG-5 中记录的 AVCodecContext 地址与 DIAG-6 不同
- DIAG-6 中 `ctx->priv_data` 指针是一致的（内部没有损坏）

**可能性**：**20%**

---

### 假设 3：编码器暂停/恢复导致实例切换

**时间线**：
```
01:19:17.531  avcodec_open2() → 初始化实例 A (0x7ef062dba0) ✅
01:19:17.532  Encoder stream paused
01:19:18.011  Encoder stream resumed
01:19:18.611  avcodec_send_frame() → 使用实例 B (0x7ef00159f0) ❌
```

**证据**：
- 暂停/恢复逻辑只设置标志位（vid_stream.c）
- 不调用任何可能切换实例的 FFmpeg API

**可能性**：**10%**

## 6. 临时解决方案

### 方案 A：在 setup_frame() 中检测并重新初始化（不推荐）

**修改位置**：FFmpeg `libx264.c` Line 551

```c
static int setup_frame(AVCodecContext *ctx, const AVFrame *frame,
                       x264_picture_t **ppic)
{
    X264Context *x4 = ctx->priv_data;

    /* ⚠️ 防御性检查：如果数组是 NULL，重新分配 */
    if (!x4->reordered_opaque || x4->nb_reordered_opaque == 0) {
        av_log(ctx, AV_LOG_ERROR,
               "[EMERGENCY] reordered_opaque array lost! Reinitializing...\n");

        int delayed_frames = x264_encoder_maximum_delayed_frames(x4->enc);
        x4->nb_reordered_opaque = FFMAX(delayed_frames + 17, 1);
        x4->reordered_opaque = av_calloc(x4->nb_reordered_opaque,
                                        sizeof(*x4->reordered_opaque));
        if (!x4->reordered_opaque) {
            return AVERROR(ENOMEM);
        }
        x4->next_reordered_opaque = 0;
    }

    X264Opaque *opaque = &x4->reordered_opaque[x4->next_reordered_opaque];
    // ... 继续原有逻辑
}
```

**问题**：
- 治标不治本
- 修改了 FFmpeg 官方源码
- 可能导致内存泄漏（如果 x4->enc 也是 NULL）

---

### 方案 B：在 PJSIP 中验证 AVCodecContext（推荐）⭐

**修改位置**：PJSIP `ffmpeg_vid_codecs.c`

**思路**：

**优点**：

**优点**：

**缺点**：

## 7. 结论

### ✅ FIX 100.199 诊断成功

1. **排除了错误假设**：
   - ❌ 不是数组被清零（DIAG-5 证明所有初始化实例都有数组）
   - ❌ 不是 X264_close() 过早调用（DIAG-7 证明没有被调用）
   - ❌ 不是内存损坏（DIAG-6 证明指针内部一致性）

2. **确认了真正问题**：
   - ✅ **使用了未初始化的 X264Context 实例**
   - ✅ 初始化的实例地址 != 使用的实例地址
   - ✅ 有 9 个实例被初始化，但编码时使用的是第 10 个未初始化的实例

3. **可能的根因**：
   - FFmpeg 在 `avcodec_open2()` 中切换了 priv_data？（70%）
   - PJSIP 缓存了错误的 AVCodecContext 指针？（20%）
   - 编码器暂停/恢复导致实例混乱？（10%）
