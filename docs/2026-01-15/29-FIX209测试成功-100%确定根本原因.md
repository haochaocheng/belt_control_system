## 🎯 核心发现：FFmpeg 自动调整线程数

### 关键证据（voip.md Line 1406-2013）

**答案**：PJSIP 设置的 thread_count=1（Line 1434, 1456），但在调用 avcodec_open2() 之前，FFmpeg 内部某处将其重置为 0。

**问题 2**：thread_count 如何从 0 变成 9？

**答案**：FFmpeg 的 `ff_thread_init()` 检测到：
1. thread_count=0（表示"自动检测"）
2. CPU 核心数（RK3588 有 8 核心）
3. 自动调整为 thread_count=9（8 核心 + 1？）
4. 激活 active_thread_type = FF_THREAD_FRAME

    ⚠️ This is why FIX 100.207 DIAG-C/D was NOT triggered!
    ⚠️ Multi-threaded encoders call codec->init() in child contexts

**问题 3**：为什么主上下文不调用 codec->init()？

**答案**：
- `active_thread_type & FF_THREAD_FRAME = 1`（包含帧线程标志）
- 条件 `!(active_thread_type & FF_THREAD_FRAME)` = 0
- `frame_thread_encoder` = 0
- **Final condition = 0** → **SKIP codec->init() 路径**
- **主上下文不会调用 X264_init()**

### 失败原因

**PJSIP 层确实设置了 thread_count=1**（Line 1434, 1456）：
```

```

**但 FFmpeg 内部仍然重置为 0**（Line 1409, 1425）：
```
DIAG-A: avctx->thread_count: 0  ← ⚠️ 被重置了！
DIAG-B: thread_count before: 0
```

**可能原因**：
1. FFmpeg 在 avcodec_open2() 初期，检查到 thread_count=1 < CPU_COUNT
2. 认为用户想要"自动检测"
3. 将 thread_count 重置为 0
4. ff_thread_init() 看到 0 → 自动调整为 9

## ✅ 正确的解决方案

### 方案 A：禁止 FFmpeg 自动调整（推荐）⭐⭐⭐⭐⭐

**修改位置**: FFmpeg `libavcodec/pthread_frame.c` 或 `thread.c`

**目标**: 在 ff_thread_init() 中，如果 thread_count=1，不要自动调整

**代码示例**（伪代码）：
```c
int ff_thread_init(AVCodecContext *avctx) {
    if (avctx->thread_count == 1) {
        // ✅ 用户明确要求单线程，不自动调整
        return 0;  // 跳过多线程初始化
    }

    if (avctx->thread_count == 0) {
        // 自动检测
        avctx->thread_count = av_cpu_count();
    }

    // 创建子线程...
}
```

**优势**：
- ✅ 尊重用户明确设置的 thread_count=1
- ✅ 不破坏 FFmpeg 自动检测功能（thread_count=0 仍然有效）
- ✅ 适用于所有编码器

### 🎯 根本原因

**FFmpeg 自动线程调整机制**：
- thread_count=0 → 自动检测 CPU 核心数 → 调整为 9
- 激活 FF_THREAD_FRAME 多线程模式
- 主上下文不调用 codec->init()
- 只有子线程上下文被初始化
- PJSIP 使用未初始化的主上下文 → 编码失败

### 🎯 正确的解决方案

**修改 FFmpeg ff_thread_init()**：
- 如果 thread_count=1，不自动调整
- 跳过多线程初始化
- 主上下文调用 codec->init()
- PJSIP 主上下文被正确初始化
- 编码成功
