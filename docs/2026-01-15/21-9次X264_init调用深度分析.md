## 🔍 为什么会有 9 次 X264_init() 调用？

### 假设 1：FFmpeg 为不同的 SDP 配置创建多个编码器实例 ⭐⭐⭐⭐⭐

**理论**：
H264 编解码器支持多种配置组合：
- 不同的 H.264 Profile（Baseline, Main, High）
- 不同的 H.264 Level（3.0, 3.1, 4.0, 4.1, 4.2）
- 不同的 Packetization Mode（0, 1, 2）

SIP SDP 协商时，PJSIP 可能为每种配置创建一个编码器实例。

**从日志验证**（Line 462）:
```
Codec[0]: H264
  dec_fmt_id_cnt=6  ← H264 解码器支持 6 种格式变体
```

**可能的 9 种配置**：
1. H264 Baseline Profile, Level 3.0, Mode 0
2. H264 Baseline Profile, Level 3.0, Mode 1
3. H264 Main Profile, Level 3.1, Mode 0
4. H264 Main Profile, Level 3.1, Mode 1
5. H264 High Profile, Level 4.0, Mode 0
6. H264 High Profile, Level 4.0, Mode 1
7. H264 Constrained Baseline, Level 3.0, Mode 0
8. H264 Constrained Baseline, Level 3.0, Mode 1
9. ... (其他组合)

**验证方法**：
在 X264_init() 中添加日志，打印 `avctx->profile` 和 `avctx->level`：
```c
fprintf(stderr, "  profile: %d\n", avctx->profile);

```

## ❓ 最关键的问题

### 问题 1：为什么 FFmpeg 不使用 PJSIP 传入的 AVCodecContext？

**标准行为**：
```c
AVCodecContext *ctx = avcodec_alloc_context3(codec);
avcodec_open2(ctx, codec, NULL);  // 应该初始化 ctx->priv_data
```

**PJSIP 的情况**：
```c
AVCodecContext *ctx = avcodec_alloc_context3(codec);  // 0x7ed8036d20
avcodec_open2(ctx, codec, NULL);  // ❌ 没有初始化 ctx->priv_data！
// FFmpeg 创建了新的 AVCodecContext (0x7ed864ed40, 0x7ec91d7960, ...)
```

**可能的原因**：
1. **PJSIP 传递了特殊参数**：某个标志位或选项导致 FFmpeg 重新创建 AVCodecContext
2. **FFmpeg 版本特定行为**：FFmpeg 6.1 的某个 Bug 或特性
3. **PJSIP 的调用时机不对**：在错误的时机调用 `avcodec_open2()`
4. **AVCodecContext 状态不正确**：PJSIP 分配的 `ctx` 有某些字段未设置

---

3. **PJSIP 应该获取它们**：PJSIP 应该调用某个 API 获取这些实例

**关键问题**：
- 能否让 PJSIP 使用这 9 个已初始化的编码器之一？
- FFmpeg 是否暴露了 API 来获取已打开的编码器？
