- ✅ **整个 X264Context 从未被 X264_init() 初始化**

## 2. 为什么 `x4->enc` 是 NULL？

### 根本原因确认

**FFmpeg 在 `avcodec_open2()` 内部切换了 AVCodecContext！**

**证据链**：

1. **DIAG-A（PJSIP 编码器打开后）**：
   ```
   ff->enc_ctx: 0x7ee0038130
   ff->enc_ctx->priv_data: 0x7ee00384f0
   ```

2. **DIAG-5（FFmpeg 初始化了 9 个实例）**：
   ```
   实例 1: AVCodecContext = 0x7f1462eee0, priv_data = 0x7f1462f360 ✅
   实例 2: AVCodecContext = 0x7f16d335f0, priv_data = 0x7ee5451ec0 ✅
   ... (共 9 个，都不是 0x7ee00384f0)
   ```

3. **DIAG-B + FIX 100.202（第一次编码时）**：
   ```
   ff->enc_ctx: 0x7ee0038130 (与 DIAG-A 匹配)
   ff->enc_ctx->priv_data: 0x7ee00384f0 (与 DIAG-A 匹配)
   x4->enc: (nil)  ← ❌ NULL!
   ```

**结论**：
- PJSIP 使用的 AVCodecContext (0x7ee0038130) **不在任何 DIAG-5 初始化列表中**
- 因此 priv_data (0x7ee00384f0) 从未被 X264_init() 初始化
- 导致 `x4->enc` 是 NULL，无法编码

## 3. FIX 100.202 的行为

### 检测到 `x4->enc` 是 NULL 后

**代码逻辑**（libx264.c Line 581-589）：

**结果**：
- ❌ 没有尝试分配 `reordered_opaque` 数组（因为即使分配了也无法编码）

- ❌ `avcodec_send_frame()` 失败，无视频输出

## 4. 为什么会有这个问题？

### FFmpeg 的编解码器注册机制

**可能的原因**：

#### 假设 1：PJSIP 注册了多个编码器配置（最可能）⭐

**证据**：
- 9 个 DIAG-5 实例被初始化
- PJSIP 可能注册了 9 种不同的 H.264 编码器配置（不同分辨率、码率等）
- FFmpeg 在 `avcodec_open2()` 时会对这些配置进行测试/协商
- 最终选择了一个配置，但 PJSIP 仍使用原始的 AVCodecContext

**证明**：
```
Line 1290-1615: 9 个 [FIX 100.199 DIAG-5] 日志
  - 实例 1-9 都有不同的 AVCodecContext 和 priv_data 地址
  - 这些都是 FFmpeg 内部创建的
```

**可能性**：**70%**

---

#### 假设 2：FFmpeg 的内部设计如此

**可能**：
- FFmpeg 在 `avcodec_open2()` 时会创建临时的 AVCodecContext 进行测试
- 最终确定参数后，使用不同的实例
- 但外部 API 仍返回原始的 AVCodecContext

**可能性**：**20%**

---

#### 假设 3：PJSIP 的使用方式不正确

**可能**：
- PJSIP 在调用 `avcodec_open2()` 前后，对 AVCodecContext 的使用有问题
- 导致 FFmpeg 无法正确初始化

**可能性**：**10%**

---
