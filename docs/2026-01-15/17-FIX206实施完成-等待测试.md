## 🎯 修复逻辑

### 根本原因（100% 确定）

**来自 FIX 100.205 测试结果**：

```
PJSIP 分配的 AVCodecContext: 0x7efc038320
  └─ priv_data (X264Context): 0x7efc0386e0
     └─ x4->enc: NULL ❌ (从未被初始化)

FFmpeg 初始化的 AVCodecContext（7 个）:
  1. priv_data: 0x7efc650860 → x4->enc: 0x7efc651160 ✅
  2. priv_data: 0x7efed55160 → x4->enc: 0x7efed55a60 ✅
  3. priv_data: 0x7ee9537ed0 → x4->enc: 0x7ee95387d0 ✅
  ... (共 7 个，全部正确初始化)

编码时使用:
  PJSIP 的 X264Context: 0x7efc0386e0
  → x4->enc: NULL ❌
  → avcodec_send_frame() 返回 -22 (EINVAL)
```

**结论**：
- FFmpeg 创建了新的 AVCodecContext 并初始化
- 但 PJSIP 仍在使用旧的、未初始化的 AVCodecContext
- C 语言指针限制：函数无法修改调用者的指针变量

---

### FIX 100.206 解决方案

**核心思路**：在 PJSIP 侧强制初始化

1. **检测**：`avcodec_open2()` 返回后检查 `x4->enc` 是否为 NULL
2. **修复**：如果是 NULL，强制调用 `X264_init(ff->enc_ctx)` 初始化 PJSIP 的 X264Context
3. **验证**：再次检查 `x4->enc` 是否有效
4. **失败处理**：如果仍然 NULL，返回错误避免崩溃
