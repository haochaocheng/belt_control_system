## 🔍 根本原因分析

### FIX 100.207 的代码位置

**文件**: `cross-compile/src/ffmpeg-rockchip-6.0/libavcodec/avcodec.c`
**行号**: Line 358-360

```c
if (!(avctx->active_thread_type & FF_THREAD_FRAME) ||
    avci->frame_thread_encoder) {
    if (codec2->init) {
        /* ✅ 2026-01-16 02:10 [FIX 100.207 DIAG-C] */
        fprintf(stderr, "[FIX 100.207 DIAG-C] BEFORE codec->init()\n");
        // ...
        ret = codec2->init(avctx);
        // ...
        fprintf(stderr, "[FIX 100.207 DIAG-D] AFTER codec->init()\n");
    }
}
```

### 为什么 libx264 没有触发诊断日志？

**关键条件**：
```c
if (!(avctx->active_thread_type & FF_THREAD_FRAME) ||
    avci->frame_thread_encoder)
```

**逻辑分析**：
1. **条件 A**: `!(avctx->active_thread_type & FF_THREAD_FRAME)`
   - 如果 avctx **没有** 设置 `FF_THREAD_FRAME` 标志 → 条件满足

2. **条件 B**: `avci->frame_thread_encoder`
   - 如果 avctx **使用** 帧线程编码器 → 条件满足

3. **libx264 的情况**：
   - `avctx->active_thread_type & FF_THREAD_FRAME` = **true** （设置了多线程）
   - `avci->frame_thread_encoder` = **false** （不是帧线程编码器）
   - **结果**：条件 A 和条件 B 都不满足 → **不进入 FIX 100.207 代码块**

**结论**：**libx264 使用了 `FF_THREAD_FRAME` 多线程模式，初始化走了不同的代码路径！**

---

### 多线程初始化路径

当 `avctx->active_thread_type & FF_THREAD_FRAME` 时，FFmpeg 会调用 `ff_thread_init()`（Line 346-353）：

```c
if (HAVE_THREADS && !avci->frame_thread_encoder) {
    /* Frame-threaded decoders call FFCodec.init for their child contexts. */
    lock_avcodec(codec2);
    ret = ff_thread_init(avctx);
    unlock_avcodec(codec2);
    if (ret < 0) {
        goto free_and_end;
    }
}
```

**推测**：
- `ff_thread_init()` 内部创建了多个线程上下文
- 每个线程上下文都调用 `codec2->init()`（X264_init）
- 这就是为什么有 9 次 X264_init() 调用
- 但这些调用**不经过** avcodec.c Line 360-417 的 FIX 100.207 代码

## 🚨 核心问题：100% 确定

### 问题 1：FFmpeg 为什么创建新的 AVCodecContext？

**答案**：多线程帧编码器需要为每个线程创建独立的编码器上下文。

### 问题 2：PJSIP 的 AVCodecContext (0x7ed0016890) 为什么没有被初始化？

**答案**：FFmpeg 在多线程模式下，**不会**初始化主上下文，而是创建子上下文（worker threads）。

### 问题 3：PJSIP 为什么使用未初始化的上下文编码？

**推测**：PJSIP 期望使用主上下文编码，但 FFmpeg 实际使用子上下文编码。PJSIP 直接访问主上下文的 priv_data 导致 x4->enc = NULL。
