## 一、核心问题：为什么需要 EMQX？

### 1.1 MQTT 不是点对点通讯

**错误理解** ❌：
```
主机应用 ←→ 模块1
主机应用 ←→ 模块2
主机应用 ←→ 模块3
...
```

**正确理解** ✅：
```
        ┌─────────────────┐
        │  MQTT Broker    │  ← 必须有这个中间人！
        │    (EMQX)       │
        └─────────────────┘
         ↑       ↑       ↑
         │       │       │
    ┌────┴──┐ ┌─┴──┐ ┌──┴───┐
    │主机应用│ │模块1│ │模块2 │
    └───────┘ └────┘ └──────┘
```

### 1.2 MQTT 发布-订阅模式

MQTT 是 **发布-订阅（Pub/Sub）** 模式，不是直接通讯：

1. **所有客户端** 都连接到 **MQTT Broker**（EMQX）
2. **发布者** 发送消息到 **主题（Topic）**
3. **Broker** 将消息转发给 **订阅了该主题的客户端**

**类比**：
- EMQX = 邮局（消息中转站）
- 主机应用 = 收件人A
- 8个模块 = 寄件人B1-B8
- 主题 = 邮箱地址

## 三、各组件的作用

### 3.1 EMQX（MQTT Broker）

**作用**：消息路由器/邮局

**功能**：
- ✅ 接收所有客户端的连接
- ✅ 管理主题订阅关系
- ✅ 接收发布的消息
- ✅ 将消息转发给订阅者
- ✅ 提供 Web 管理界面

**运行位置**：您的电脑 Docker 容器中

**访问地址**：
- MQTT 端口：`localhost:1883` 或 `127.0.0.1:1883`
- Web 界面：`http://localhost:18083`
- 用户名/密码：`admin` / `public`

### 3.2 主机应用（belt_control_system）

**作用**：MQTT 客户端（订阅者+发布者）

**功能**：
- ✅ 连接到 EMQX
- ✅ 订阅 8 个模块的状态主题
- ✅ 接收模块发送的数据
- ✅ 发布控制命令到模块

**运行位置**：您的电脑（QML 应用）

**连接地址**：`localhost:1883` 或 `127.0.0.1:1883`

### 3.3 MQTTX（模拟器）

**作用**：模拟 8 个模块的 MQTT 客户端

**功能**：
- ✅ 创建 8 个独立连接到 EMQX
- ✅ 模拟 8 个模块发布状态数据
- ✅ 接收主机应用的控制命令
- ✅ 可视化界面修改数据

**运行位置**：您的电脑（桌面应用）

**连接地址**：`localhost:1883` 或 `127.0.0.1:1883`

## 四、消息流转示例

### 示例 1：模块1 发送状态数据给主机

```
1. 模块1（MQTTX）发布消息
   主题: belt_control/di/module1/status
   内容: {"module": 1, "data": {...}}
   ↓
2. EMQX 接收消息
   ↓
3. EMQX 查找订阅了该主题的客户端
   ↓
4. EMQX 转发消息给主机应用
   ↓
5. 主机应用收到消息并处理
```

### 示例 2：主机发送控制命令给模块1

```
1. 主机应用发布消息
   主题: belt_control/di/module1/control
   内容: {"cmd": "read"}
   ↓
2. EMQX 接收消息
   ↓
3. EMQX 查找订阅了该主题的客户端
   ↓
4. EMQX 转发消息给模块1（MQTTX）
   ↓
5. 模块1（MQTTX）收到命令并响应
```

**症状**：`Error: connect ECONNREFUSED 192.168.10.142:1883`

**原因**：IP 地址配置错误

**错误配置**：
```
Host: 192.168.10.142  ❌ 这是另一台设备的IP

```

**正确配置**：
```
Host: localhost  ✅ 或 127.0.0.1
Port: 1883
```

**解决方案**：
1. 在 MQTTX 中修改连接配置
2. 将 Host 改为 `localhost` 或 `127.0.0.1`
3. 重新连接

## 六、正确的配置步骤

### 步骤 1：确保 EMQX 运行

```powershell
# 检查 EMQX 状态
docker ps | findstr emqx

# 如果没有运行，启动它
docker start emqx

# 等待几秒后访问 Web 界面
# http://localhost:18083
# 用户名: admin
# 密码: public
```

### 步骤 2：配置 MQTTX 连接

**创建第一个连接（开关量输入1）**：

1. 打开 MQTTX
2. 点击左上角 **"+"** 按钮
3. 填写连接信息：
   - **Name**: `开关量输入1`
   - **Client ID**: `belt_control_di1`
   - **Host**: `mqtt://`
   - **Host**: `localhost` ⭐ **重要：不是 192.168.10.142**
   - **Port**: `1883`
   - **Username**: (留空)
   - **Password**: (留空)
4. 点击右上角 **"Connect"** 连接

**预期结果**：
- 连接成功，显示绿色 "Connected"
- 在 EMQX Web 界面的 "Clients" 页面能看到 `belt_control_di1`

### 步骤 3：配置主机应用

在主机应用的 MQTT 配置中：
```cpp
// MQTTController.cpp
config.brokerHost = "localhost";  // 或 "127.0.0.1"
config.brokerPort = 1883;
```

## 七、常见误区

### 误区 1：以为模块是服务器

❌ **错误理解**：8 个模块是 MQTT 服务器，主机连接到它们

✅ **正确理解**：
- EMQX 是唯一的服务器（Broker）
- 主机和 8 个模块都是客户端
- 所有客户端都连接到 EMQX

### 误区 2：以为可以点对点通讯

❌ **错误理解**：主机直接发消息给模块1

✅ **正确理解**：
- 主机发消息到 EMQX 的某个主题
- EMQX 转发给订阅了该主题的模块

### 误区 3：IP 地址配置

❌ **错误配置**：
- EMQX 在本机 Docker，但配置 IP 为 192.168.10.142

✅ **正确配置**：
- EMQX 在本机 Docker → 使用 `localhost` 或 `127.0.0.1`
- EMQX 在远程服务器 → 使用远程 IP（如 192.168.10.142）

## 九、总结

### 核心概念

1. **EMQX 是必须的**
   - MQTT 协议需要 Broker 作为消息中转站
   - 不能省略

2. **所有客户端连接到 EMQX**
   - 主机应用 → EMQX
   - 8 个模块（MQTTX 模拟）→ EMQX

3. **IP 地址配置**
   - EMQX 在本机 Docker → `localhost` 或 `127.0.0.1`
   - EMQX 在远程服务器 → 远程 IP

4. **消息通过主题路由**
   - 不是直接发给某个客户端
   - 而是发布到主题，订阅者自动收到
