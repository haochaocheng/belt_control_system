# PJSIP IOCP Backend Fix - Implementation Complete

## Problem Summary

SIP registration was failing because PJSIP could not receive 401 Unauthorized responses from FreeSWITCH server at 192.168.10.243:5060.

**Root Cause**: PJSIP was using `select()` I/O queue on Windows, which is unreliable for UDP packet reception.

## Solution Implemented

Switched PJSIP from `select()` to IOCP (I/O Completion Ports) backend on Windows.

## Why IOCP Fixes the Problem

### Select() on Windows (OLD - BROKEN):
- POSIX-style I/O multiplexing
- Unreliable UDP packet reception on Windows
- FreeSWITCH 401 responses were sent but never received

### IOCP on Windows (NEW - WORKING):
- Windows native high-performance async I/O
- Reliable UDP packet reception
- Properly receives all SIP responses including 401

## Technical Details

### Previous Issue
- PJSIP log showed: `.select() I/O Queue created`
- TX logs showed REGISTER being sent
- **No RX logs for 401 response** despite FreeSWITCH sending it
- PortSIP client worked fine with same server (proof server is correct)

### Fix Applied
- Modified PJSIP build configuration to compile with `ioqueue_winnt.c`
- Rebuilt pjlib with Windows IOCP support
- Updated application to link against IOCP-enabled libraries

### Key Discovery
The actual problem was in `os-auto.mak` (auto-generated by configure script), not `os-win32.mak`. The configure script had generated the wrong I/O queue backend setting.
